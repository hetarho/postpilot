# 승인한 작업만 현재 브랜치에 반영

## 역할과 실제 실행 수단

호출한 세션이 끝까지 오케스트레이터다. 탐색 세션은 제안만, 구현 세션은 승인된 태스크만, 독립 리뷰 세션은 고정된 제출물만 맡는다. 작업 묶음은 배정·검증·통합 장치이며 오케스트레이터를 다른 최상위 세션으로 넘기는 기능이 아니다.

사용 가능한 하위 세션 실행 도구가 있으면 각 역할의 프롬프트와 고정 파일 포인터를 전달한다. 실제 세션 ID/owner와 배정·완료/차단을 기록한다. 서로 다른 세션은 같은 checkout에 쓰지 않는다. 권한 없는 Agent 호출을 맡김에서 강행하지 않는다. 독립 세션 실행 수단이 없으면 접속 방법과 제안 패킷을 남기고 그 역할을 가장하지 않는다.

기본 흐름은 탐색 결과 수신 → 오케스트레이터 결정 → 승인 태스크 배정 → 구현 완료 → 다른 세션의 리뷰 → CLI 통합 → 최종 검증이다. 사용자가 정한 경계 안의 제안 채택은 오케스트레이터가 결정한다. 큰 변화의 사람 판단과 실제 코드 리뷰를 대신하지 않는다. 승인 후 새 제안은 다시 이 흐름을 거친다.

## 승인 기록과 태스크

1. `work status --json`으로 다른 작업/소유권을 확인하고 호출 checkout의 브랜치·HEAD를 고정한다. 깨끗한 브랜치와 실제 실행 수단·검사 명령이 통합 전제다. 미커밋 사용자 변경은 자동 커밋/정리하지 않는다.
2. 자식 제안 artifact를 오케스트레이터가 review finding [?]와 notes로 정리한다. 승인 [o]에는 이번 로컬 실행 위임 또는 기존 정책, 제안 기준 SHA·허용 경로·계약·검증·예산을 남기고 create-task로 분해한다. 문서 표기·기획 정본은 기존 FORMAT와 cfg plan을 따른다. 다른 todo를 승인으로 간주하지 않는다.
3. 승인된 ID만 묶음 `--tasks`에 넣는다. 같은 lane은 전부 승인해야 하고, 범위 밖 선행 태스크는 승인 없이 자동 배정되지 않는다. 필요한 의존 작업을 별도로 제안/승인하거나 해당 작업을 보류한다. explore와 그 후속은 메인 세션 소유다.

## 호출 브랜치를 통합 대상으로 사용

아래 명령 앞에는 설치된 `npx haeram-spec-creator` 또는 실행기의 실제 cliCommand를 붙인다. 명령의 자리표시자는 확인한 값으로 치환한다.

```sh
work start <run> --workspace current --tasks '<approved task IDs>' --review all --push - --verify '<fast integration check>' --group-verify '<final check>'
```

ARCH의 영향 단위 검사와 빠른 검사는 `--task-verify`로 저장하고, 무거운 통합/e2e·전체 검사는 `--group-verify`에 둔다. `current`는 호출한 checkout과 **그 브랜치 그대로** 기획·통합 공간으로 채택한다. 임의로 main이나 새 work 브랜치로 전환하지 않는다. 워커는 별도 worktree를 배정받는다. 저장소 전체 todo를 소비하지 않도록 `--tasks`를 생략하지 않는다.

설치된 CLI 도움말에서 `--tasks` 지원을 확인한다. 지원하지 않으면 올바른 버전의 CLI 연결이 필요하다고 보고하고 무제한 큐로 대체하지 않는다.

기존 묶음이 이 checkout을 이미 소유하면 새 이름으로 중복 시작하지 않는다. 이 로컬 개선 묶음이고 기존 실행이 끝난 것이 확인되면 기존 승인 ID/완료 이력을 보존해 `work configure --work <run> --tasks '<old and newly approved IDs>' --review all --push -`로 확장한다. 무관한 활성 묶음이면 침범하지 않고 보고한다. 진행/통합된 ID를 범위에서 제거해 이력을 숨길 수 없다.

## 구현과 리뷰 실행

- **네이티브 하위 세션**: 오케스트레이터가 승인 ID를 `work claim <task> --work <run> --owner <worker> --workspace new`로 배정하고 실제 workspace·attempt를 전달한다. 구현 완료 프로토콜에서 커밋·submit 소유자를 한 번 정한다. 리뷰는 다른 owner의 `work review-claim` → review-task → `work review-finish`다. 승인된 제출물만 오케스트레이터의 `work integrate`로 통합한다. 자식이 다른 묶음이나 무관한 태스크를 고르지 않도록 정확한 배정을 유지한다.
- **기존 headless 실행기**: 탐색과 제안 승인까지는 호출 세션이 맡고, 확정 태스크의 구현/리뷰만 `work run --work <run> --provider <available provider> --reviewer-provider <available provider> --autopilot`로 실행한다. 대상 묶음의 승인 범위·검사·review all·push 비활성 상태를 먼저 확인한다. 조정자는 기획 결정 요청을 처리하고 실행기는 배정/커밋/제출/리뷰/통합을 맡는다. 스킬의 “오케스트레이터가 승인”은 코드 리뷰 자동 승인 옵션이 아니다.

묶음의 `--push -`는 단위별 원격 코드 반영을 끈다. 네이티브 세션에서도 push/PR은 자식에게 배정하지 않는다. 계획·런타임 정책은 워커 쓰기 범위 밖이다. 코드/범위가 변하면 새 제출·독립 리뷰를 받으며 오래된 승인을 복사하지 않는다.

## 통합 완료와 원격 반영

검사·리뷰된 단위가 실제 호출 브랜치에 들어온 것을 board/HEAD/diff로 확인한다. `work finish`의 조정자 소유 최종 관문을 통과해야 전체 완료다. 묶음 밖 todo는 그대로 남아도 승인 범위가 모두 통합되면 묶음을 마칠 수 있다. 스냅샷에는 승인 범위와 제외된 항목, 검증 커밋이 남는다. 단위 통합 뒤 최종 관문이 실패하면 로컬 브랜치에는 진행분이 있을 수 있으므로 미완료라고 보고하고 수정/되돌림을 조정한다.

현재 브랜치를 채택한 묶음의 완료 응답은 `integrationTarget`으로 실제 경로·브랜치를 알려 준다. 이 호출은 해당 브랜치의 로컬 통합까지 이미 위임했으므로 다시 묻지 않는다. 다만 다른 브랜치로의 병합·원격 push·배포는 별도 권한이다. cfg push가 사용자가 지정한 브랜치이면 최종 검증 뒤 조정자가 기존 push 절차로 한 번 반영한다. 없으면 로컬 커밋과 원격 미발행 상태를 보고한다. 원격 main을 업데이트하지 않았는데 업데이트했다고 말하지 않는다.

긴 측정 전에 생산 명령이 원시 수치·입력/출력 해시를 실행기 artifact에 저장하도록 준비한다. `work finish`의 성공 기록은 검사 명령/시각/결과의 영수증이며 원시 측정 stdout을 보존하는 저장소가 아니다. 근거를 잃었으면 그 공백을 보고하고 예산 안의 보완만 수행하며, 긴 실행을 자동으로 반복하지 않는다. 보고서만 추가된 커밋은 기존 최종 검증을 유지하므로 마감 보고 때문에 전체 검사를 다시 돌리지 않는다.

대기는 완료 이벤트나 실행기 대기 기능으로 처리한다. 모델이 sleep/상태 조회를 반복하지 않는다. 시간·시도 한도를 넘으면 로그·진행분·승인/검토 상태와 다음 재개 조건을 보존한다.
