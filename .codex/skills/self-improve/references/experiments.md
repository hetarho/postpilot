# 한 문제를 반복 실험으로 개선하기

## 목표와 증거 고정

이 절차는 [poteto-mode의 Hillclimb](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/hillclimb.md)과 [benchmark-checklist](https://github.com/cursor/plugins/blob/main/pstack/skills/benchmark-checklist/SKILL.md)를 참고해 이 패키지의 예산·검증 소유권·독립 리뷰에 맞춘 것이다. 외부 스킬이나 특정 실행 도구/모델 설치는 필요하지 않다.

하나의 문제에 지표·목표·대표 작업·행동 계약·최초 기준선·빠른 회귀 검사·최종 관문·예산을 정한다. 최초 기준선은 전체 개선의 기준이고, 지금까지 확인된 최선 후보는 다음 시도의 기준이다. 두 기준을 구별해 전체 개선과 직전 시도 개선을 따로 보고한다. 성공은 목표와 필수 검증으로 판정하며, 임의의 최소 반복 횟수를 채우려고 실험을 늘리지 않는다.

먼저 측정기가 다른 작업 규모를 구분하고 실제 작업·오류·정확성을 세는지 확인하며, 최초 기준선의 빠른 회귀 검사 통과도 기록한다. 측정 계약은 워커 쓰기 범위 밖에 두고 지문을 고정한다. [contract 템플릿](../assets/experiment-contract.json)의 숫자는 예시다. 단위·표본 수·목표 작업량·최소 개선율·환경을 이번 실험에 맞춰 수정한 다음 고정한다. 단일 입력의 반복 표본은 여러 입력/seed를 통한 행동 동등성 검증을 대신하지 않는다.

## 한 시도씩 진행

1. 최근 기록을 읽고 원인과 반증 가능한 전제를 갖춘 가설 하나를 고른다. 제거 가능한 불필요 작업·중복 계산부터 살피고, 검증/행동 범위를 보존하는 경로에서 순서·병렬화·알고리즘 개선으로 넓힌다. 측정으로 알 수 있는 사실은 작은 실험으로 확인하고, 제품 의미·정밀도 같은 위임 밖 결정은 사람에게 넘긴다.
2. 최선 후보에서 격리된 실험 변경을 만든다. 다른 가설이나 검증 기준 변경을 함께 쌓지 않는다. explore 안의 시도마다 새 태스크·전체 검증을 요구하지 않는다. 후속 구현은 create-task/implement-task로 확정한다.
3. 고정 측정과 영향 범위의 빠른 회귀 검사를 실행한다. 아래 도구로 표본을 비교해 유지/폐기/미확정을 기록한다. 목표·예산·사람 판단 경계를 확인한 뒤 다음 가설로 간다.
4. `keep`는 국소 실험의 잠정 유지다. 확인된 최선 후보를 갱신하되 최초 기준선은 보존한다. 최종 코드의 독립 리뷰·전체 관문·PR 발행 승인을 뜻하지 않는다. 구현 완료 태스크를 임의 수정하거나 실험 기록만으로 done 처리하지 않는다.
5. `discard`·`inconclusive`는 개선 코드에 누적하지 않는다. 실패한 변경과 로그는 격리 공간에 보존하고, 확인된 최선 후보에서 다음 시도를 시작한다. 사용자 변경을 reset/clean하거나 실험 기록을 삭제하지 않는다. 이미 채택 커밋에 섞였으면 소유권 확인 후 해당 변경만 명시적으로 되돌린다.

같은 전제를 공유한 실패가 두 번이면 다음 수정 전에 전제를 적고 참/거짓을 구분할 관찰을 실행한다. 단순 재시도 대신 데이터·병목·계측·환경 중 가설 범주를 바꾼다. 저비용의 새 근거가 있는 가설은 남은 예산에서 이어가되, 성과가 없다는 이유로 조건·예산을 완화하지 않는다. 목표 도달은 검증 후 완료, 예산 종료는 미완료 체크포인트, 실질적인 막힘은 근거와 재개 조건으로 구별한다.

## 비교·기록 도구

이 스킬 폴더의 `scripts/experiment.mjs`는 JSON 표본을 평가하고 선택적으로 JSONL 기록을 추가한다. Node 이외 의존성, 명령 실행, 스케줄링, Git 변경은 없다. `<skill-dir>`는 이 문서가 속한 self-improve 스킬 디렉터리(`references/`의 상위)이며 실제 경로로 치환한다(self-improve-local에서 읽어도 같다).

```sh
node <skill-dir>/scripts/experiment.mjs hash <contract.json>
node <skill-dir>/scripts/experiment.mjs evaluate <contract.json> <attempt.json> --journal <attempts.jsonl>
```

[attempt 템플릿](../assets/experiment-attempt.json)의 지문은 hash 결과로, commit·samples·evidence는 실제 실행 근거로 채운다. `contractHash`는 해당 조건으로 실행했다는 계측기의 기록이다. 도구가 실제 환경이나 코드 동등성을 인증하는 것은 아니다. `correct`와 gate `passed`는 확인됨이면 true/false, 미확인이면 null이다. 증거 파일 경로 또는 허용된 artifact 링크를 함께 남긴다.

비교는 비음수 단일 지표를 지원한다. 각 표본의 `workCount`는 고정된 논리 작업 단위이며 분모를 바꿔 처리량을 부풀리지 않는다. 중앙값의 개선율이 최소 개선율과 양쪽 범위/중앙값으로 계산한 편차를 모두 초과해야 `keep`다. 이는 보수적인 선별 규칙이며 통계적 유의성 검정은 아니다. 계약 불일치·같은 commit·기준선 작업 불완전·표본/정확성/근거 부족·비교 불가 중앙값·문턱 이하 개선은 `inconclusive`, 후보 오류·일부 작업 생략·잘못된 출력·빠른 회귀 실패·개선 없음(0% 이하)은 `discard`다. exit code는 keep=0, discard=2, inconclusive=3, 잘못된 입력/기록 충돌=1이며 JSON verdict도 확인한다.

기록은 이번 문제의 실행기 artifact 위치에 둔다. `spec/`에 새 문서 골격이나 STATE 표를 만들지 말고 기존 review notes·task result·report checks에서 기록과 원시 근거를 가리킨다. JSONL에는 시도 ID·가설·전제·계약 지문·커밋·전체 입력·판정·시각이 남는다. 같은 ID·같은 입력은 중복 기록하지 않고, 다른 입력으로 ID를 재사용하면 거절한다. 실패·미확정도 남긴다. 긴 원시 로그는 별도 artifact에 두고 포인터만 기록한다.

기록 모드에서는 새 시도의 baseline commit이 마지막 keep 후보(아직 없으면 첫 기준선)와 같아야 한다. 옛 기준선과만 비교해 현재 최선보다 느린 후보를 채택하는 것을 막는다. 재시도 응답의 `recorded:false`는 이미 처리한 과거 판정이므로 그 후보를 다시 적용하거나 같은 측정 비용을 중복 집계하지 않는다. 재시도 자체에 새로 든 비용은 누적한다. 단독 evaluate는 주어진 두 입력만 비교하므로 반복 운영에서는 journal을 함께 사용한다. 측정 계약을 바꿔 새 기록 구간을 열면 이전 최선 후보와의 관계·미비교 한계를 review notes에 연결한다.

기록 쓰기는 옆의 `.lock` 파일로 배타 처리한다. 다른 작성자가 있으면 실패 후 소유권부터 확인한다. 중단으로 잠금이 남았으면 원래 작성자 종료 확인 뒤 그 잠금만 정리한다. 손상된/부분 기록은 덮어쓰지 않고 복구 근거를 남긴다. 이 잠금은 기록 파일만 보호하며 사이클 소유권·일일 예산·장기 프로세스 관리는 기존 실행기의 책임이다.

## 검토와 다음 실행

독립 검토자는 최초 기준선·최선 후보·채택/폐기 이력·측정 계약과 최종 통합/발행 후보의 연결을 확인한다. PR 발행 모드는 한 문제의 확인된 개선을 관련 PR로 모으고, self-improve-local은 호출 브랜치에 통합한다. 실험마다 PR을 열지 않는다.

후행 관문이 잠정 keep를 기각하면 그 결과와 영향을 review notes·보고서에 기록하고 해당 후보를 발행하지 않는다. 마지막으로 행동이 확인된 후보로 돌아갈 때는 새 기록 구간에서 이전 이력과 기각 이유를 연결한다. 과거 keep 행을 지우거나 최종 승인으로 바꿔 쓰지 않는다.

반복 교정이 기계적으로 검사 가능한 원인이면 작은 실행 검사나 메타데이터로 바꾼다. 문구를 늘리는 것은 판단이 필요한 교훈일 때만 한다. 외부/설치된 공통 스킬에 대한 개선은 로컬 근거와 제안으로 인계하고 대상 프로젝트에서 직접 고치지 않는다.
