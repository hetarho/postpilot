# 비용을 줄이면서 결과를 보존하는 측정

## 먼저 있는 증거를 사용

기존 테스트/CI 타이밍·프로파일·실행 결과에서 느린 구간과 실행 빈도를 찾는다. 전체 실행이 오래 걸린다는 이유만으로 같은 실행을 한 번 더 시작하지 않는다. 최초 기록이 없으면 저비용 계측이나 짧은 진단이 첫 개선이다. 정적 의심과 측정된 병목을 구분한다.

변경 전 다음을 finding notes와 태스크 acceptance/impl notes에 기록한다.

- 비교할 base commit, 대표 입력/fixture·규모·seed 목록·실행 옵션과 환경. 생성 데이터면 생성 절차와 내용 해시도 남긴다.
- 목표 지표(전체 경과 시간, CPU, 메모리, 처리량, 재시도/재작업 비율 등)와 결과 보존 지표(출력/상태/오류/순서, 필수 계약과 검증 범위).
- 성공 기준과 중단 기준. 관측 편차보다 작은 차이는 성과로 채택하지 않는다. 수치 기준은 실험 후 유리하게 바꾸지 않는다.
- 예상 실행 비용, 반복 횟수와 warmup, 최종 관문·독립 검토에 남길 예산. 4시간짜리 전체 실행을 매 가설/리뷰마다 반복하지 않는다.

## 측정기 검증과 고정

측정 코드가 무엇을 재고 제외하는지 읽고, 증상을 재현하는 대표 작업과 더 가벼운 대조 작업을 구분하는지 확인한다. 구분하지 못하면 최적화보다 재현/계측을 먼저 고친다. 실제 처리량·오류·올바른 결과를 함께 기록한다. await/반복 소비가 빠진 지연 실행, 생략된 단계, 조기 오류, 결과를 사용하지 않는 계산은 속도 개선이 아니다.

프로파일링과 보고용 타이밍은 별도 실행으로 나눈다. 병목과 전체 시간에서의 비중을 확인해 예상 절약이 가능한 범위인지 점검한다. 한쪽만 debug 설정이거나 비현실적인 부하라면 채택 비교에 쓰지 않는다. 계측 자체의 비용도 기록한다.

입력·환경·측정 코드·검사 조건을 고정하고 내용 지문을 남긴다. 기준이 바뀌면 새 비교 구간으로 분리하며 옛 결과와 섞어 개선율을 계산하지 않는다. [실험 보조 도구](experiments.md)는 기록된 지문·작업량·오류·정확성·표본·빠른 회귀 결과의 일관성을 검사한다. 원시 근거가 실제 실행을 증명하는지는 독립 검토자가 별도로 확인한다.

## 전후 비교

동일 하드웨어·런타임·설정·입력·부하 조건에서 base와 head를 비교한다. 가능한 범위에서 번갈아 실행하고, warmup과 cold/warm cache 조건을 분리한다. 반복 가능한 짧은 벤치마크는 여러 표본의 중앙값·산포·표본 수를 보고한다. 1회만 측정했으면 1회라고 쓰며 통계적 개선을 주장하지 않는다. 검증 성공 캐시는 성능 측정 표본으로 세지 않는다.

원시 기록에는 base/head SHA, 명령, 입력·환경, 시작/끝, 표본별 수치, 성공/실패/timeout, 로그 경로를 남긴다. 요약에는 전후 값과 단위, 상대 변화, 비용과 한계를 함께 적는다. 메모리·정확성·재현성의 손해를 시간 개선 뒤에 숨기지 않는다. 프로세스 개선은 비교 기간·업무 종류·표본 수를 기록하고 추정 절약과 실측 절약을 분리한다.

보고서·태스크 상태 같은 메타데이터만 바뀌어 후보 SHA가 달라졌으면 관련 코드·설정·계약·입력·환경이 같다는 근거로 측정 재사용을 판단한다. 원시 기록의 SHA는 보존하고 새 후보에 대한 적용 근거를 별도로 남긴다. 관련 변경이나 조건 불명은 같은 측정으로 취급하지 않는다.

## 테스트가 많고 느린 경우

테스트 개수와 커버리지 퍼센트는 단독 최적화 목표가 아니다. 먼저 중복된 전체 실행·느린 setup·fixture 생성·I/O·리트라이가 비용의 어디를 차지하는지 분해한다.

| 개선 후보 | 유지해야 할 근거 |
|---|---|
| task/unit/group/CI로 실행 시점·주체 정리 | 기존 필수 검증 범위가 최종 관문에 그대로 남음; 누가 언제 실행하는지 명시 |
| fixture·초기화 재사용, 독립 테스트 병렬화 | 테스트 간 상태 누출·순서 의존·자원 경합이 생기지 않음 |
| 중복 테스트 통합/삭제 | 각 위험·계약·경계와 남는 케이스의 대응; 유일한 assertion/회귀 조건을 잃지 않음 |
| 영향 기반 선택·캐시 | 공유 모듈/설정/생성물 변경과 선택 불명 시 전체 실행 fallback, 캐시 키·무효화 확인 |
| flaky 원인 수정 | 실패 조건 재현과 원인 제거; skip·재시도 증가·실패 무시로 숨기지 않음 |

검증 실행을 옮겨 놓고 그 시간을 사라진 비용으로 계산하지 않는다. 빠른 피드백 시간과 전체 CPU/CI 비용을 따로 보고한다. 테스트를 합치는 변경도 의미 있는 회귀 검증이 필요하지만 파일마다 구현을 되풀이하는 새 테스트를 만들지 않는다. 필수 범위를 줄이거나 삭제의 동등성을 입증하지 못하면 사람 판단 대상이다.

테스트는 잘못된 관찰 가능 동작을 잡고 동작 보존 리팩터링에는 유지되는지 평가한다. 내부 호출·우연한 문구에 고정된 테스트는 계약 기준으로 고치거나 중복을 통합한다. 문서·포맷 자체가 제품 계약이면 그 구조/불변식 검사는 유지한다. 문서 문자열 검사를 에이전트의 실제 판단 검증으로 대신하지 않는다.

## 긴 엔진·시뮬레이션

작은 고정 입력으로 hot path를 프로파일하고, 반복 계산·할당·직렬화·I/O 중 측정된 한 원인만 바꾼다. 동일 seed/입력의 differential 검사, 경계·실패 입력, 불변식으로 동작 보존을 확인한다. 비결정적 시스템은 사전에 정한 seed 집합·분포/오차 기준을 사용한다. 같은 seed만으로 동등성이 증명되지는 않는다.

샘플 축소·단계 생략·정밀도/오차·확률 분포 변경은 속도 최적화와 별도 결정이다. 기존 계약을 바꾸므로 사람 판단 없이 도입하지 않는다. 작은 샘플에서 빨라도 전체 실행의 병목·성능이 같다고 외삽하지 않는다.

무거운 대표/전체 실행은 유망한 최종 후보에서 조정자 한 곳만 수행한다. 예산이 허용하면 고정된 입력/환경의 base 기록을 재사용하고 head를 비교하며, base 기록의 조건·출처가 맞지 않으면 미비교로 남긴다. 장기 관문에 필요한 예산이 없으면 승인/merge 가능한 성과로 처리하지 않고 draft에 국소 결과와 남은 검증을 명시한다. 관문은 허용된 실행기에서 이어받는다.
