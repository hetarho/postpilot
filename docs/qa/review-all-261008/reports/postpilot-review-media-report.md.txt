## Verified strengths / rejected hypotheses

- Media worker RPC identity comes from separately authenticated worker headers, never user/request actor data; lease credentials are rebound to the authenticated worker. Role-scoped routing forbids a native worker from reading analysis-verification leases and vice versa (`clip/rpc/media_worker.go`, platform media credentials parser).
- Native media claim/renew/accept paths join parent job, owning account/project, cancellation, plan revision and frozen source identities in writer transactions. Completion accepts exact receipt replay and wakes durable continuation in the same commit. Head/object I/O sits outside the single SQLite writer (`app/media_control.go`, `app/media_artifacts.go`); no concrete expired/superseded lease publication bypass was proved.
- Worker lease deadline is monotonic and conservative from request start; heartbeat failure never extends it, watchdog remains active during a pending renewal, and stage/local process cancellation is bounded (`worker/loop.go`, `workerclient/client.go`). No paid call is present in worker composition root.
- Conditional original/media output PUTs prevent re-overwriting confirmed objects. Native worker output retry correctly compares immutable bytes after412 rather than treating object existence alone as success.
- Browser outputs use position-aware seekable MP4 writes, finite pages/backpressure and an output-only OPFS spool. Web Locks protect a live page’s spool from another page’s abandoned-file sweep; dispose clears bytes and releases locks (`shared/lib/media/bounded-output.ts`, `stream-mp4.ts`, `packet-window.ts`). No original/audio/frame/credential browser persistence was found in these paths.
- Selected-range readers reject playlists, require exact206/Content-Range, stream bounded bytes instead of unbounded `arrayBuffer`, stop suspicious/unsupported inputs, and separately budget parser/decoder/presentation resources. Video/audio resources are cancelled/released by epochs and page lifetimes. Actual physical/browser GPU memory cannot be certified from these logical bounds.
- Requested speech is hash-checked and tied to immutable voice/script/profile inputs. Speech stale/readiness is independently projected; speech/source volume and hook dip are separate; narration is not contingent on source audio (`composition-audio.ts`, `browser-audio-plan.ts`, `render-audio.ts`, speech audio app).
- Browser preparation catches an uncertain/lost parent-start response by cancelling the preparation; backend `AnalysisPreparations.Cancel` finds/cancels its persisted `ParentJobID`, so the hypothesized orphan paid start is guarded. No provider replay was performed.
- Source-audio toggles update lease, saved plan snapshot and revision atomically; old render revisions remain stale. Finalization fences sources/late writes and records cleanup independently of storage availability. Deletion during speech I/O is rechecked before returning bytes.
- Possible same-revision browser completions were not reported: revision/deletion/finalization guards hold, and the spec does not impose a last-admitted winner between identical revision renders.
- Potential preview/output audio volume double application was rejected after tracing prepared PCM → preview/export buses: per-cut/source gain is applied during stretch; preview output bus only applies mute and hook dip, speech has its own gain.
- No live NVIDIA readiness, browser performance/style parity, supplier semantic accuracy, dubbing qualification or remote deployment success was asserted. T539/T550/T603/T604 already own these gates.
