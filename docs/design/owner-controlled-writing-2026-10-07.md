# 사용자가 주도하는 글 다듬기 — 확정 기획

2026-10-07. 사용자 승인에 따라 프롬프트 구조와 글 품질의 두 축을 SSOT에 반영했다. 제품 코드·응답 형식·태스크는 이번에 변경하지 않았다. 현재 코드 조사 기준은 main@95da3ad4이며 구현의 정본은 아래 SSOT다.

제품 메시지는 **“AI는 속도를, 글의 주도권은 나에게.”**다. AI가 용어·표현·구성을 도우면서 사용자가 주지 않은 의미는 알아볼 수 있게 한다. 기능이 구현되기 전에는 출시된 기능으로 홍보하지 않는다.

## 확정한 두 축

| 축 | 확정한 방향 | 정본 |
|---|---|---|
| 프롬프트 구조 | 자료·지시·고정 문구 경계, 단계별 필요한 입력, 공통 계약과 우선순위, 실제 조립 경로의 추적 | [GEN](../../spec/ssot/GEN.md), [GUIDE](../../spec/ssot/GUIDE.md), [TMPL](../../spec/ssot/TMPL.md), [MODEL](../../spec/ssot/MODEL.md), [EDIT](../../spec/ssot/EDIT.md) |
| 글 품질과 사용자 통제 | 구절별 의미 출처, 보이는 AI 표현 제안, 사진 순서로 사건을 만들지 않기, 근거 있는 최대 N개 태그 | [GEN](../../spec/ssot/GEN.md), [POST](../../spec/ssot/POST.md), [VOICE](../../spec/ssot/VOICE.md), [MEM](../../spec/ssot/MEM.md) |

긴 지침을 일괄 삭제하는 방향은 채택하지 않았다. 실제 중복, 사용하지 않는 단계의 규칙, 모순되는 출력 계약과 자료 경계를 고치고 필요한 긴 지침·예시는 보존한다. 단계별 제외는 코드가 소유한 규칙의 명시적 적용 조건을 따르며, 사용자가 작성한 지침 원문을 자동으로 분류해 삭제하지 않는다. 태그 품질은 현재와 같은 선택 가능한 tags 기본 지침에 둔다. 숫자 옵션은 ‘최대 태그 수’이며 1–10, 기본 4를 유지한다. 근거 있는 태그가 적으면 적게, 없으면 0개도 허용한다.

## 세 가지 의미 출처

| 표시 | 의미 | 예시 |
|---|---|---|
| 직접 입력 기반 | 사용자가 명시적으로 준 의미의 재서술·정리 | “12,000원이었다” → “가격은12,000원이었어요” |
| 사진에서 추론 | 사진·첨부 영상에서 읽거나 해석한 의미 | 메뉴판 글자, 붉은 토핑처럼 보이는 것; 상세에서 실제 사진/영상을 구분 |
| AI가 보탠 내용 | 입력 의미에 없던 설명·해석·감각 제안 | “맛있었다”에서 추가한 단맛·향·질감 |

타이핑 주체가 아니라 의미의 근거를 구분한다. 같은 문장도 의미가 추가되는 구절을 나눠 보여준다. 제목·요약·태그·본문·리스트·사진 설명 등 글의 모든 사람이 읽는 텍스트가 대상이다. 기본으로 표시하고 ‘출처 보기’로 전환하며 범례·범주 이름·선택한 구절의 원자료 설명을 제공한다. 색만 사용하지 않고 터치·키보드와 두 테마에서도 확인할 수 있게 한다. [POST-112–114](../../spec/ssot/POST.md), [THEME-62/63](../../spec/ssot/THEME.md)

출처는 사실 인증이나 정확도 점수가 아니다. 사진 해석도 틀릴 수 있다. 승인한 기억은 직접 사실의 근거가 될 수 있지만 매운 음식 선호에서 이번 방문의 ‘좋았다’를 추론하면 그 새 감상은 AI 추가다. 말투 예시·AI가 만든 템플릿·스토리라인은 이번 경험의 사실을 자동으로 증명하지 않는다.

문장부호 수정, 사진 이동, 스토리 선택과 글 확정은 기존 AI 의미를 직접 입력으로 바꾸지 않는다. 새로 명시한 사실은 새 입력의 근거를 가질 수 있다. 수정·재생성·비교 결과 적용 후에는 현재 원고와 표시가 맞아야 하며 증명할 수 없는 과거 출처는 ‘미확인’이다.

## 허용하는 표현 도움과 사진 순서

AI는 유용한 용어, 자연스러운 연결과 섬세한 감각 표현을 제안할 수 있다. “맛있었다”는 단맛·딸기향·바삭함을 준 정보가 아니므로 그런 추가는 AI 제안으로 보인다. 사용자가 준 감상을 뒤집거나 근거 없는 가격·실제 행동·장소 이동을 만들 권한은 아니다. [GEN-80–84](../../spec/ssot/GEN.md)

**실내3장 → 음식3장 → 실내1장**이라는 배열은 자리 이동이나 식사 완료의 근거가 아니다. 업로드·저장·파일명·촬영 순서는 사건의 선후를 만들지 않는다. 사용자가 알려준 사건 정보가 없으면 주제와 사진 내용으로 글을 구성한다. AI 추가 색을 붙여도 이동을 지어낼 수 없다. 영상 안에서 실제로 관찰되는 시간 순서는 별개의 근거다.

## 표시가 불완전한 경우

본문과 출처 정보를 별도로 검증한다. 정상 본문은 보존하고 출처를 확인하지 못한 구절은 ‘미확인’으로 설명한다. 임의로 세 범주 중 하나를 칠하거나 과거 기록을 현재 자료로 복원하지 않는다. 출처 실패만으로 새 확정·내보내기 차단이나 추가 유료 분류/복구 호출을 만들지 않는다.

현재 글도 블록 JSON으로 받고 있다. 새 출처 계약의 구체 응답 구조·구절 대응·저장 방식은 태스크에서 정한다. 형식·범주·참조 존재·본문 대응 검사는 가능하지만 의미적 근거의 정확성까지 보장하지 않는다. 저렴한 모델의 성공률도 실제 모델/endpoint로 검증할 사항이다. [현재 schema](../../backend/internal/generation/schemas/write_answer.schema.json), [provider 처리](../../backend/internal/llm/openaicompat/client.go)

검토용 색·범주·원자료·기술 정보는 복사·내보내기 원고에 들어가지 않는다. 최신 canonical 글만 출력한다. [EXPORT-27](../../spec/ssot/EXPORT.md)

## 프롬프트 조회와 언어

개발자·운영자는 전체 단계의 실제 소스·조립 함수·적용 조건·자료 역할·우선순위·schema/parser/consumer·버전을 한곳에서 추적한다. 글 소유자는 별도의 기술 조회에서 자신의 적용/제외 규칙과 요청을 확인한다. 현재 설정, 준비된 미리보기와 실제 실행 기록을 구분한다. 과거 기록이 없으면 없다고 표시한다. 비밀값·SDK 전송 원문·signed URL·타 계정 자료를 노출하지 않으며 비교 중에는 후보 정체를 숨기는 기존 규칙을 지킨다. 조회 자체는 유료 호출이나 원고 변경을 만들지 않는다. [MODEL-93–95](../../spec/ssot/MODEL.md)

한국어 글의 기준은 한국어 지시로 유지한다. 영어 공통 지시를 비교할 때는 한국어 재료·이름·말투·예시·응답과 모델 조건을 고정한다. 영어가 더 좋다는 결론은 실험 전에는 내리지 않는다. 새 언어 선택기·번역 파이프라인·사용자 비교 요인은 만들지 않는다. [LANG-29](../../spec/ssot/LANG.md)
