# 맛집 클립 템플릿 v2 (`맛집 테스트` 교체본)

`a3d32f4f…` 클립(해미 연풍 우가)에서 드러난 4가지 문제를 템플릿 수준에서 고친 판본이다.
`/admin` → 영상 템플릿 → **맛집 테스트** → 템플릿 본문(XML) 전체를 아래 XML로 교체하고 저장하면 된다.
`backend/internal/clip/composition` 파서로 검증했다 — 필드 10/10(상한), 씬 5개, 본문 7,998자(상한 16,000).

## 요청 → 변경 대응표

| 요청 | 변경 | 근거 |
|---|---|---|
| ① 한 메뉴라도 클립 여러 개 쓰기, 굽는 장면은 1~2초로 짧게 | 메인 `<guide>`의 **"전체 6~10개 안에서 고르고 나머지는 버리세요"** 삭제 → "상한 없음 + 반복 동작은 1~2초, 정보가 바뀌는 컷만 3~5초" | 이 한 문장이 20개 중 7개만 쓰인 직접 원인이었다 |
| ② 원본 상한 없음 | `dish` 씬 guide에 "이 메뉴의 클립이 여러 개면 아끼지 말고 여러 컷으로 나눠 쓰세요" | 씬당 컷 수에 코드 제한은 없다(상한은 100컷) |
| ③ 상호를 우측 상단에 | `arrival_place` → `position="top" align="right"` | `PlaceCopy`가 y=80, x=(888−너비)로 배치 |
| ④ 자막이 화면 요소를 가리지 않게 | 모든 `role="caption"` → `position="auto"` | 위치를 고정하면 피사체 회피 로직(`design.SelectAnchor`)이 통째로 꺼진다 |
| 겹침 방지 켜기 | `<clip pace="rapid">` → `pace="steady"` | 겹침 스케줄러가 `Pace != "rapid"`일 때만 돈다 |

## 이 교체만으로 바로 고쳐지는 것

- **된장찌개 자막 겹침** — `steady`로 바꾸면 `scheduleDeclaredCaptions`가 살아나 같은 컷의 두 자막을 시간 분할한다. 추가로 guide가 "소개 문장과 감상 문장은 서로 다른 컷에" 라고 지시해 애초에 한 컷에 몰리지 않는다.
- **"연결이 안 되는 짧은 단어들"** — `rapid`는 문장을 14자 이하 조각으로 쪼개 순차 노출한다(`강릉` / `여행 갔다가 기념일을` / `맞이해서 들렀어요.`). `steady`는 문장을 통째로 띄운다.
- **자막이 음식을 가리는 문제** — `position="auto"`면 간판·메뉴판이 보이는 장면에서 자막이 자동으로 위/아래로만 가고, 피사체를 15% 넘게 덮는 위치는 후보에서 빠진다.
- **상호 위치** — 기존 `upper_mid`는 세로 1920px 중 y=700, 즉 위에서 36% 지점이라 어정쩡했다. `top`은 y=80.

## 같이 바꾼 것 (부작용 방지)

- **광고 표시 뱃지**: `position="header"` → `position="top" align="left"`. header는 우측 상단(x = 984−너비)에 배치되어 새 상호 위치와 겹친다. 좌상단으로 옮겨 분리했다.
- **가격 칩**: `<value field="menu.name"/> · <value field="menu.price"/>` → 가운뎃점 제거하고 `top/right`로. 가격 필드 안내도 "숫자만 적지 말고 단위까지"로 고쳤다(입력이 `3000`이라 `된장찌개 · 3000`으로 나왔다).
- **점수 필드**: 입력이 `4점 `이라 `제 기준 4점 /5점`으로 나왔다. 안내문에 "숫자만, 예: 4"를 명시했다.
- **참고 정보 줄**: `lower_mid` → `bottom`. 우측 상단 칩들과 분리한다.
- **메뉴 이름 필드**: "메뉴 하나마다 항목을 따로, 가장 짧은 형태로(예: 살치살)". `살치살 갈비살`처럼 한 칸에 몰아 적으면 장면-메뉴 연결이 문자열 단위로 일치해야 해서 실패한다.
- **감상 다듬기 지시**: "입력한 문장의 낱말을 최대한 그대로 살려라. 입력에 없는 감각 표현으로 바꿔 말하면 그 자막은 통째로 버려진다"를 추가했다. 서버 검증(`GroundScopedText`)이 `맛있`·`고소`·`먹어` 같은 낱말이 들어간 문장은 입력값과 **완전히 동일할 때만** 통과시키기 때문이다 — 이번에 마무리 문구가 사라지고 된장찌개 감상이 축약본으로 바뀐 이유다.
- **분량**: 20~40초 → 25~45초, "같은 시간이면 짧은 컷을 여러 개".

## 템플릿으로는 못 고치는 것 (태스크화 완료)

update-ssot로 CLIP r20 / CDS r14에 반영하고 create-task로 쪼갰다.

| 태스크 | 내용 | 근거 |
|---|---|---|
| T159 | 같은 컷의 자막 두 개를 페이스와 무관하게 시간 분할 + `simple`에 TOP 대안 앵커 | CDS-43 CDS-52 CDS-58 |
| T160 | 관찰을 프로젝트 언어로 고정하고 재사용 키에 포함 | CLIP-104 CLIP-93 CLIP-62 |
| T161 | 장면별 자막 가능 영역(caption-safe region) 관찰·저장 | CLIP-105 |
| T162 | 관찰된 영역으로 자동 앵커 순위를 매김 (dep T161) | CDS-38 |
| T163 | 정보 알약을 전용 SVG 프레임 가족으로 교체 | CDS-69 CDS-30 CDS-16 CDS-44 |

폐기된 항목: 세로 위치 자유화(앵커를 스타일에서 완전히 분리). 오너 판단으로 네 앵커 모델을 유지하고, 그 안에서 T159·T162가 회피 여지를 만든다.

## 교체용 XML

```xml
<clip accent="coral" pace="steady" styles="simple" version="1">
  <field id="place" label="상호명·지역" required="false">상호명과 동네 또는 지역을 적어주세요. 예: 성수동 ○○식당. 지점이 있으면 함께 적고, 상세 주소는 넣지 마세요.</field>
  <field id="visit" label="방문 계기·시간·대기" required="false">가게에 들른 이유와 실제 방문 요일·시간, 기다린 시간을 아는 만큼 적어주세요. 예: 근처에서 약속이 끝나 들름. 토요일 오후 1시, 20분 대기. 모르는 내용은 빼주세요.</field>
  <field id="downside" label="가게에서 아쉬웠던 점" required="false">좌석, 소음, 대기, 이용 방식 등 직접 겪은 아쉬움을 적어주세요. 없으면 비워두세요. 특정 음식의 아쉬움은 해당 메뉴의 감상에 적어주세요.</field>
  <field id="tips" label="가기 전 참고할 점" required="false">직접 확인한 주차, 예약, 웨이팅 방식, 브레이크타임, 휴무일, 아이 동반 등 필요한 정보만 적어주세요. 유료 여부, 이용 시간, 적용 조건도 함께 적고 상세 주소는 빼주세요.</field>
  <field id="score" label="개인 점수·5점 만점" required="false">1부터 5까지의 정수 하나만 적어주세요. 예: 4. "점"이나 "/5" 같은 말은 화면에 자동으로 붙으니 숫자만 입력하고, 표시하지 않으려면 비워두세요.</field>
  <field id="verdict" label="재방문 의사·이유" required="false">다시 갈 것 같은지와 이유를 솔직하게 적어주세요. 기다리는 시간이나 방문 목적에 따른 조건, 누구에게 맞을지도 직접 판단한 내용만 적어주세요. 다음에 먹고 싶은 메뉴는 실제로 생각한 경우만 적어주세요.</field>
  <field id="disclosure" label="광고·협찬 등 표시 문구" required="false">화면에 그대로 표시할 문장을 적어주세요. 광고·협찬이 있으면 제공받은 내용을 명확하게 적어주세요. 직접 결제했다는 표시는 사실인 경우만 입력하고, 표시할 내용이 없으면 비워두세요.</field>

  <group id="menu">
    <field id="name" label="메뉴 이름" required="true">메뉴 하나마다 항목을 따로 추가하고, 먹은 순서대로 넣어주세요. 영상에 보이는 이름을 그대로, 가장 짧은 형태로 적어주세요. 예: 살치살. 여러 부위나 메뉴를 한 칸에 몰아 적지 마세요.</field>
    <field id="price" label="이 메뉴의 가격" required="false">이 메뉴의 가격을 단위까지 적어주세요. 예: 1인분 18,000원, 2인 세트 45,000원. 숫자만 적지 말고 통화와 수량 기준을 함께 적고, 다른 메뉴의 가격이나 전체 결제액은 섞지 마세요.</field>
    <field id="review" label="먹어본 감상·가격에 대한 생각" required="false">맛, 식감, 양, 좋았던 점과 그냥 그랬던 점을 평소 말투로 적어주세요. 예: 겉은 바삭한데 제 입에는 조금 짰어요. 가격이 부담됐는지도 실제로 느꼈다면 적어주세요. 먹어보지 않았다면 맛 평가는 비워두세요.</field>
  </group>

  <guide>
    장면 배열이 이 템플릿에서 가장 중요합니다. 아래 순서를 반드시 지키세요.
    먼저 선택할 수 있는 모든 클립을 실제 촬영 시각 순서대로 늘어놓으세요. 그다음 앞에서부터 차례로 구간에 배정하세요. 뒤 구간에는 앞 구간보다 이른 시점의 클립을 쓰지 마세요. 도착·외관·입구·실내 장면이 음식 장면 뒤에 오면 안 됩니다. 계산이나 나가는 장면이 먹는 장면 앞에 오면 안 됩니다.

    쓸 수 있는 클립 수에는 상한이 없습니다. 한 구간에 여러 컷을 두어도 되고, 한 메뉴에 클립이 여러 개면 여러 컷으로 나눠 쓰세요. 다만 같은 동작이 이어지는 클립(굽기, 뒤집기, 끓기, 덜기)은 1~2초로 짧게 끊어 리듬을 만들고, 정보가 바뀌는 클립(처음 나온 모습, 자르거나 집는 순간, 완성된 모습)에만 3~5초를 주세요. 화면이 거의 같은 클립이 세 번을 넘겨 이어지면 나머지는 버리세요. 같은 메뉴에 속한 클립은 반드시 붙여서 배치하고 다른 메뉴 사이에 끼워 넣지 마세요.
    각 메뉴 안에서도 나온 모습, 자르거나 집는 모습, 이후 모습의 실제 순서를 지키세요. 없는 장면을 만들거나, 장면을 복제하거나, 정지 화면을 늘려 분량을 채우지 마세요.

    자막은 컷마다 달지 마세요. 1~2초짜리 짧은 컷은 자막 없이 화면만 지나가게 두고, 3초 이상인 컷에만 문장 하나를 얹으세요. 한 컷에 문장 두 개를 겹쳐 넣지 말고, 소개 문장과 감상 문장은 반드시 서로 다른 컷에 나눠 담으세요.
    자막은 컷마다 따로 설명하지 말고 앞 문장에서 이어지는 하나의 이야기로 쓰세요. 화면에 무엇이 보이는지 해설하는 문장으로 시작하지 마세요. 앞 자막에서 이미 말한 것을 다시 설명하지 말고 그다음 이야기를 하세요. 자막만 순서대로 읽었을 때 한 번의 방문 기록으로 읽혀야 합니다.

    평범한 일반인 남성이 친구에게 이번 식사를 이야기하는 짧은 방문 기록을 만드세요. 전문가의 평가나 가게 홍보처럼 쓰지 마세요.
    예쁜 가게면 좋지만 일부러 찾아다니지는 않고, 웨이팅은 30분 정도가 마지노선이며, 평소 비싼 음식은 자주 먹지 않지만 가끔 4~5만원도 쓰는 사람입니다. 무조건 싼 것만 찾지는 않지만 저렴하면 기분이 좋습니다. 이 설정은 말투의 기준이지 실제 방문 계기, 대기시간, 지출이나 감정을 만들어내는 근거가 아닙니다.
    문장은 친구에게 카톡으로 말하듯 자연스러운 존댓말로 쓰세요. 모든 문장을 같은 어미로 끝내거나 일부러 남성적인 말투를 만들지 마세요.
    "풍미", "감칠맛의 밸런스", "인생", "미쳤다", "역대급", "무조건 가세요", "안 가면 손해"는 쓰지 마세요. 감탄사, 최상급, 이모지, 광고성 수식어를 남발하지 마세요.

    사실의 근거는 사용자가 입력한 정보와 선택한 실제 영상입니다. 맛, 향, 온도, 식감, 배부름, 가격 만족도, 직원의 친절함은 입력이 있을 때만 쓰세요. 윤기가 난다고 촉촉하다고 하거나 김이 난다고 갓 만들었다고 단정하지 마세요.
    감상을 다듬을 때는 입력한 문장의 낱말을 최대한 그대로 살려 이어 쓰세요. 입력에 없는 감각 표현으로 바꿔 말하면 그 자막은 통째로 버려집니다.
    가격과 대기시간, 수량, 영업시간, 점수는 입력값을 유지하세요. 가격을 반올림하거나 인당 금액, 할인율, 총액을 계산하지 마세요. 한 번의 대기 경험으로 한산한 시간대를 추천하지 마세요. 30분 넘게 기다린 일을 미화하지 마세요.
    좋았던 점과 아쉬웠던 점은 입력된 만큼만 반영하세요. 균형을 맞춘다는 이유로 단점을 만들거나, 전부 맛있었다고 통일하지 마세요.
    비어 있는 선택 정보와 연결된 문구는 통째로 생략하세요. 빈 제목, 구분점, 가격 단위, 점수 틀, "정보 없음"을 남기지 마세요. 입력 안내와 예시는 사실 자료로 사용하지 마세요.

    전체는 25~45초 안에서 구성하되 원본 길이와 메뉴 수에 맞추세요. 짧은 자료를 목표 시간까지 늘리지 말고, 최대 90초를 넘기지 마세요. 도착과 마무리는 각각 한 컷으로 짧게 두고 남은 시간 대부분을 음식 컷에 쓰세요. 컷 수를 줄여 컷 하나를 길게 만들지 말고, 같은 시간이면 짧은 컷을 여러 개 쓰세요.

    소리 없이 보아도 메뉴와 감상을 이해할 수 있게 쓰세요. 자막 하나에는 정보 하나만 담고, 한 줄 18자 안팎으로, 필요할 때만 두 줄로 구성하세요. 짧게 줄이느라 메뉴명, 가격 기준, 대기 요일·시간, 이용 조건을 훼손하지 마세요.
```
