# Test entitlement reset (pricing transition)

This runbook applies only to an environment whose subscription, credit, voucher and payment rows have been classified as **test data**. It is a separate recorded maintenance action. The database migration creates replay guards but does not reset data at boot. Never run this command as a deployment step.

1. Boot the new application version once so schema migration 0121 is applied, then stop the API, billing worker and media worker for the target environment. Confirm no AI or render job and no payment or refund outcome is unresolved. Record the environment, operator, time, database path and reason in the maintenance log. The reset command itself does not migrate or boot the application.
2. From `backend/`, set `DB_PATH` to the existing SQLite database. Run `DB_PATH=/absolute/path/to/postpilot.db go run ./cmd/api reset-test-entitlements --dry-run` and retain its JSON report. Review `affected`, `preserved` and every `blockers` count. A nonzero blocker prevents apply.
3. Create a private backup directory **outside** the database directory, for example `install -d -m 700 /absolute/private/backups`. Choose a new filename there. Run `DB_PATH=/absolute/path/to/postpilot.db go run ./cmd/api reset-test-entitlements --apply --test-only --backup=/absolute/private/backups/pricing-before.db` once. Keep its JSON report and the SHA-256 checksum. The command refuses an existing backup filename, a shared directory or a path in the database directory.
4. Check that the report shows the expected accounts, verified identities, posts, voices, videos, clip results and usage history preserved; check the master login, a previously authored post and a completed clip. Check that subscription, purchase, voucher and credit balances are cleared and paid users show Free. Start the processes only after these checks. A repeat apply reports `already_applied` and does not clear new entitlements.

The reset also clears test payment method keys, intents, notifications, events, quotes and refund records. It performs no provider call and sends no charge, refund or email. Old provider order IDs remain in `test_entitlement_reset_orders`; triggers reject inserting or changing an intent or purchase to one of them. Keep the completion and order tables with the database. Schema rollback refuses to drop them after a completed reset.

To restore, stop all processes again. Verify the backup checksum against the recorded `backup_sha256`. Move the current database and any `-wal`/`-shm` companions into a private quarantine directory, then copy the backup to the original `DB_PATH` with mode `0600`. Restart only after opening the restored database and checking the account and content counts. Restoring the backup also restores the prior test entitlements, so resolve the reason for rollback before processing provider notifications.

This procedure does not authorize running a reset on production data. A real-environment execution needs its own recorded maintenance action and deployment authorization.
