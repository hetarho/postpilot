# recomend-models: 내보내기 → 고친 붙여넣기 문서

**역할: 모델 큐레이터.** 사용자는 모델 관리에서 등록을 관리하는 운영자다. 기본 사용법은 하나다.

1. 사용자가 모델 관리 `일괄 편집`의 내보내기(MODEL-55)로 지금 상태를 복사해 이 스킬과 함께 붙인다.
2. 이 스킬은 **오늘 OpenRouter가 실제로 파는 모델**만 근거로 그 문서를 고쳐, 그대로 붙여넣을 문서를 돌려준다.
3. 사용자가 그 문서를 `일괄 편집`에 붙여 미리보기로 확인하고 적용한다.

응답의 주인공은 2의 문서다. 추천 표나 긴 설명을 문서보다 앞에 두지 않는다. 학습 기억 속 모델명은 쓰지
않는다: 스크립트 출력에 있는 id만 쓰고, 가격도 출력 그대로 인용한다.

## 0. 입력 판별
- 메시지(스킬 인자 포함)에 `# postpilot models v1`로 시작하는 문서가 있으면 그것이 **기준 문서**다. 1~6절을 따른다.
- 기준 문서가 없으면 붙여넣기 문서를 만들지 않는다. 적힌 섹션은 그 탭의 최종 상태라(MODEL-52), 지금
  등록을 모르고 만든 문서는 사용자가 모르는 해제를 일으킨다. 질문(예: "무료 모델 뭐 있어")에는 1~3절
  기준으로 짧게 답하고, 끝에 한 줄로 "붙여넣을 문서가 필요하면 `일괄 편집` 내보내기를 붙여 다시 호출해
  달라"고 안내한다.
- 사용자가 내보내기 없이 문서를 달라고 명시하면 그때만 3절 기준으로 새로 짠다. 응답 첫 줄에 "적힌 탭의
  기존 등록과 기존 추천 조합은 전부 해제된다"고 적는다.

## 1. 데이터 받기
```bash
S=<작업용 임시 디렉터리: Claude는 scratchpad, Codex는 mktemp -d>
python3 .claude/skills/recomend-models/scripts/openrouter_models.py --json $S/raw.json > $S/catalog.txt
python3 .claude/skills/recomend-models/scripts/openrouter_models.py --purpose writing --days 90   # 범위 좁히기
python3 .claude/skills/recomend-models/scripts/openrouter_models.py --all-providers               # 비주류 제공사까지
```
- 붙여진 기준 문서는 손대지 않고 `$S/baseline.txt`로 저장한다. 5절 검증의 기준이다.
- 앱과 같은 엔드포인트·모달리티 쿼리(MODEL-17)를 쓰고 `:batch` 변형은 뺀다(MODEL-50, 동기 호출만 있어 쓸 수 없음).
- 출력 flags: `V` 이미지 입력 · `M` 영상 입력 · `R` reasoning 파라미터 · `S` structured_outputs. 가격은 USD / 1M 토큰.
- 지금 등록·등급·추천 조합은 DB에 있고(MODEL-10·69) 스크립트는 모른다. 붙여진 내보내기가 유일한 사실이다.
- fetch가 실패하면 추천을 지어내지 말고 실패를 보고한다.

## 2. 용도(탭)별 조건
사용자 스테이지를 먹이는 세 탭을 다룬다. 이미지·영상 생성 탭은 아직 스테이지가 없으니(MODEL-14) 요청이
있을 때만 다룬다.

| 탭 (purpose) | 스테이지 | 필수 | 선호 | 비용 성격 |
|---|---|---|---|---|
| 사진 분석 `photo-analysis` | observe | `V` (게이트, MODEL-15) | `M`(영상 글이면), `S` | 사진 수만큼 호출·입력 토큰 위주 → 입력 단가 |
| 스타일 분석 `style-analysis` | analyze | 없음 | `S`, 긴 컨텍스트 | 샘플 글 여러 편 입력 → 입력 단가 |
| 글쓰기 `writing` | write / revise | 없음 | `S`, 한국어 자연스러움 | 출력 토큰이 지배 → 출력 단가 (MODEL-28) |

- `S`가 없어도 앱은 텍스트 폴백으로 동작한다(MODEL-5). 다만 파싱 실패(`MODEL_OUTPUT_INVALID`) 위험이 커지니 같은 급이면 `S` 있는 쪽을 고른다.
- `R`만 있고 effort를 못 낮추는 모델은 writing에서 reasoning이 완료 예산을 먹어 빈 응답으로 잘리는 일이 있었다(MODEL-3·48).

## 3. 등급 기준
등급은 제품이 실제로 쓰는 말이다(MODEL-57). 사용자는 모델 선택 화면에서 이 배지를 그대로 보고 고른다.

| 등급 | 토큰 | 정의 | 고르는 법 |
|---|---|---|---|
| 무료 | `free` | `:free` 변형 | 게이트 통과 + 활성 파라미터 큰 순. `exp=`가 있으면 만료일을 적는다. |
| 가성비 | `value` | 출력 ≤ ~$1.5/M | 그 가격대에서 가장 최신 세대. 주요 제공사의 flash/mini/luna급. |
| 밸런스 | `balanced` | 출력 ~$2–12/M | 품질과 비용 중간. 각 제공사의 중간 티어(sonnet/terra/max/glm 정규) + 최신 flash 상위. |
| 고급 | `premium` | 플래그십 아래 최상위 | 플래그십과 같은 급이지만 입력·출력이 확연히 싼 것(예: 플래그십 $10/$50 대비 $3/$15). |
| 최고 | `top` | 가격 무관 | 각 제공사 플래그십 최신 세대. `-pro` 변형은 같은 모델의 고강도 reasoning이니 하나로 묶는다. |

- `free`는 유료 등급과 따로 관리되는 분류다. 서버는 적용 경로의 무료 가격을 검증하므로(MODEL-68)
  `:free` 변형에만 `free`를 적는다. 다른 모델에 적으면 `free_path_ineligible`로 거절된다(MODEL-53).
- 고급과 최고는 이름이 아니라 **가격대**로 나눈다. 카탈로그가 실제로 두 무리로 갈릴 때만 나누고, 한 무리뿐이면 최고만 쓴다.
- 등급마다 3~5개, 서로 다른 제공사가 최소 3곳 섞이게 한다(한 제공사 장애가 세트를 못 죽이도록).
- `preview`·`exp` 모델은 무료 외엔 피한다. 등록일이 며칠 안 된 모델은 "출시 직후"로 표시한다.

## 4. 기준 문서를 고치는 법
**기준 문서에서 출발해, 이유가 있는 줄만 바꾼다.** 이 스킬이 처음부터 짰다면 다르게 골랐을 모델이라도
아래 이유에 해당하지 않으면 그대로 둔다. 운영자가 고른 등록을 취향 차이로 해제하지 않는다.

바꾸는 이유는 다음 다섯 가지뿐이고, 위에서부터 본다.
1. **카탈로그에 없는 id**: 해제한다. 남겨 두면 `unknown_model`·`unlisted_model`로 문서 전체가 거절된다.
2. **게이트 위반**(사진 분석에 `V` 없음, 생성 탭에 출력 모달리티 없음): 해제한다(MODEL-15·53).
3. **등급이 비었거나 3절과 어긋남**: 등급을 바꾼다. `:free` 변형이 유료 등급이면 `free`로, 유료 모델은 가격대에 맞는 등급으로.
4. **같은 계열의 새 세대·새 스냅샷이 같은 가격대 이하로 나옴**: 교체한다(옛 것 해제 + 새 것 추가, 등급은 새 가격 기준).
5. **등급이 비었거나 1~2개뿐, 또는 등급 안 제공사가 1곳뿐**: 3절 기준으로 골라 채운다.

- 5개를 넘는 등급이 있어도 줄이지 않는다. 그것도 운영자의 선택이다.
- 사용자가 "새로 짜줘", "처음부터"라고 하면 위 제한 없이 3절로 다시 고른다. 응답 형식은 6절 그대로다.
- 사용자가 범위를 좁히면(예: "무료만 손봐", "글쓰기 탭만") 그 범위만 고치고 나머지 줄은 기준 문서 그대로 둔다.

### 4-1. 문서 문법 (MODEL-51·59)
- 첫 줄은 `# postpilot models v1` 그대로다. 등급이 붙어도 버전은 `v1`이다.
- **세 탭 섹션(`[photo-analysis]` `[style-analysis]` `[writing]`)은 항상 전부 적는다.** 기준 문서의 줄을 옮겨
  적고 4절에서 바꾼 줄만 다르게 둔다. 바꾸지 않은 탭을 그대로 옮기면 그 탭은 아무 변화가 없다.
- 생성 탭(`[image-generation]` `[video-generation]`) 섹션은 사용자가 요청할 때만 적는다. 섹션이 없는 탭은 그대로 남는다.
- 섹션 아래 한 줄에 `<모델 id> <등급>` 하나씩, id 알파벳순(내보내기와 같은 순서)으로 둔다. 적용 뒤 다시 내보내면 같은 문서가 나온다.
- id는 카탈로그 그대로 복사한다. 백틱·따옴표·쉼표·순위 번호·가격을 붙이지 않는다.
- 등급은 `free` `value` `balanced` `premium` `top` 다섯 토큰뿐이다. 한글이나 다른 값, 세 번째 토큰은 `unknown_level`·`malformed_line`으로 거절된다.
- **모든 id 줄에 등급을 적는다.** 등급을 비운 줄은 "등급 없음"이라는 지시라서 기존 등급이 지워진다(MODEL-59).
- 문서 안에 `#` 주석 줄이나 설명을 넣지 않는다. 설명은 문서 밖에 쓴다.
- effort는 문서가 다루지 않는다(MODEL-52). 기본 정책이 observe·write를 low로 보낸다.

### 4-2. 추천 조합 (`[recommendations]`, MODEL-72·73)
- 이 섹션은 **조합의 전체 목록**이다. 적용하면 섹션에 없는 기존 조합은 지워지고, 이름이 같은 조합은
  교체된다. 그래서 기준 문서의 조합을 이름·순서 그대로 옮겨 적고 출발한다.
- 조합 하나는 `set <이름>` 줄 다음 세 줄이다: `observe <활성> <A> <B>` · `analyze <활성>` · `write <활성> <A> <B>`.
- 조합의 모든 id는 **같은 문서의 해당 탭 섹션에 등급과 함께** 있어야 한다. 아니면 `slot_unregistered`·
  `slot_unclassified`로 문서 전체가 거절된다. 기준 문서의 조합이 이미 그런 상태일 수 있다(해제된 모델을
  가리킴). 그러면 같은 등급의 교체 모델로 슬롯을 바꾸고, 대체할 모델이 없으면 그 조합을 빼고 이유를 적는다.
- 이 스킬이 관리하는 조합은 등급별 다섯 개다: `무료 추천` `가성비 추천` `밸런스 추천` `고급 추천` `최고 추천`.
  기준 문서에 있으면 4절 결과에 맞게 갱신하고, 없으면 새로 만든다. 다른 이름의 조합은 운영자 것이라
  고장 난 슬롯만 고친다. 조합에 쓴 모델의 등급을 받을 수 있는 플랜만 그 조합을 적용할 수 있으므로(MODEL-58),
  등급별 조합에는 그 등급의 모델만 쓴다.
- 등급별 조합은 그 등급에 사진 분석 2개, 스타일 분석 1개, 글쓰기 2개가 있을 때만 만든다. 없으면 만들지 않고
  이유를 한 줄로 적는다. 활성은 그 등급에서 가장 무난한 모델(출시 1주 넘음, `S` 있음 우선)이고, A는 활성과
  같게, B는 다른 제공사의 대안으로 둔다. A와 B는 서로 달라야 한다(`slot_duplicate`). 출시 직후 모델은 B에 둔다.
- 이름은 60자 이하이고 서로 달라야 하며, 조합은 10개까지다. 넘으면 등급별 조합을 덜 만들고 무엇을 뺐는지 적는다.

## 5. 검증 (응답 전에 반드시)
고친 문서를 `$S/proposed.txt`로 저장하고 돌린다.
```bash
python3 .claude/skills/recomend-models/scripts/check_document.py $S/proposed.txt --baseline $S/baseline.txt --catalog $S/raw.json
```
- 일괄 편집 미리보기가 거절하는 것(문법, 카탈로그 존재, 사진 분석 `V`, `free` 경로, 등급 누락, 조합 슬롯)을
  흉내 낸다. `OK`가 나올 때까지 고친다. 거절될 줄이 남은 문서는 내지 않는다.
- 출력의 변경 목록(추가·해제·등급 변경·조합)이 6절 "바뀌는 점"의 원본이다. 손으로 다시 세지 않는다.
- 최종 판정은 서버 미리보기다. 이 스크립트는 붙여넣기 전에 걸러내는 장치다.

## 6. 응답 형식
cfg.lang이 있으면 그 언어로, 없으면 한국어로 쓴다. 다음 순서와 분량을 지킨다.

1. **한 줄 요약**: 무엇을 기준으로 고쳤는지(붙여진 내보내기, 카탈로그 조회 날짜)와 검증 결과.
2. **붙여넣기 문서**: 언어 태그 없는 코드펜스 하나. 첫 줄 `# postpilot models v1`부터 마지막 줄까지 문서만 담는다.
3. **바뀌는 점**: 탭별로 교체·해제·추가·등급 변경을 한 줄씩 적고, 줄마다 가격·플래그·등록일에 근거한
   짧은 이유를 붙인다. 교체는 "옛 id → 새 id (이유)" 한 줄로 묶는다. 바뀐 게 없는 탭은 "변화 없음"이라고만
   적는다. 조합은 추가·교체·삭제를 적는다.
4. **적용 안내** 한 줄: `일괄 편집`에 붙여넣고, 미리보기에서 해제 목록·`등급 변경` 목록·조합 변경을 확인한 뒤 적용하라.
5. **주의**: 꼭 필요한 것만 세 줄 이하로 적는다(무료 모델의 레이트리밋 `MODEL_RATE_LIMITED`·프롬프트 학습 가능성, 출시 직후 모델).

- 탭별 추천 표(등급·id·입력/출력 $/M·flags·이유)는 사용자가 "이유 자세히", "표로", "후보 다 보여줘"처럼
  요청할 때만 문서 아래에 붙인다.
- 바꿀 게 하나도 없으면 문서를 내지 않는다. "지금 상태 그대로 두면 된다"와 근거 한두 줄만 적는다.
- 파일로 저장하지 않는다. 코드펜스가 결과물이다. 사용자가 파일을 요청할 때만 문서만 담은 `.txt`로 쓴다.

## 7. 하지 않는 것
- **적용하지 않는다.** 모델 관리 RPC 호출, 세션 발급, 로컬·운영 DB 읽기·쓰기, SSH 접속을 하지 않는다.
  응답 뒤에 사용자가 "해줘", "적용해"라고 해도 마찬가지다. 붙여넣는 방법을 한 줄로 다시 알려주고, 필요하면
  문서를 다시 준다. 적용과 되돌리기는 사용자가 모델 관리에서 한다.
- 붙여진 내보내기를 DB와 대조하지 않는다. 사용자가 붙인 문서가 사실이다.
- DB·providers.yaml·프론트 설정·코드를 고치지 않는다.
- 벤치마크 점수를 인용하지 않는다. 출력에 없는 수치는 근거가 아니다. 근거는 가격·플래그·등록일·설명문뿐이다.
