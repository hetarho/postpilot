# 지속 개선 운영 정책

## 한 번 정하고 이어받을 것

지속 개선 요청을 받았으면 사용자가 이미 준 범위·권한을 정책 초안에 반영하고 빠진 것은 보수적인 기본값으로 정한다. 반복 승인 절차를 만들지 않는다. 범위를 넓히거나 필수 권한이 없는 경우에만 해당 항목을 보류한다. 정책은 update-ssot/ARCH 개정 절차로 평범한 결정 블록에 기록한다. 새 cfg 키나 자체 정책 파일 파서는 필요하지 않다.

기존 프로젝트의 FORMAT에 자율 채택·실행 규칙이 없으면 배포된 FORMAT 템플릿의 Autonomous improvement·self-improve 규칙을 필요한 부분만 이관한다. 기존 표기·골격은 유지하며 FORMAT 전체를 덮어쓰지 않는다. 정책이 위임하는 범위와 분리해 기록하고, 사용자 요청 밖의 채택 권한을 새로 만들지 않는다.

| 항목 | 기본값 또는 기록할 내용 |
|---|---|
| 활성화 | 명시적인 지속 개선 위임이 있을 때 활성; 설치만 했으면 비활성 |
| 목표·범위 | 동작 보존을 전제로 실행 비용·실패·반복 작업 개선; 허용 경로와 제외 경로 명시 |
| 계기 | 새 문제 발견은 사용자 작업 완료/유휴 세션 시작 시, 마지막 발견 사이클 종료 후 24시간 이상 지났을 때 한 번; 기존 문제의 재개는 저장된 다음 실행 조건을 따름 |
| 예산 | 한 사이클 wall-clock 60분, 하루 누적 120분, 단일 명령 15분; 사람의 본 작업이 우선 |
| 비용 | 유료 서비스/추가 과금 작업은 별도 허용 상한 없으면 시작하지 않음; 모델 비용을 조회할 수 없으면 금액 상한을 지켰다고 주장하지 않음 |
| 실행량 | 문제 1개/사이클, 그 안에서는 고정 지표·예산으로 가설을 순차 실험; 무거운 명령 동시 1개, 수정 후 재검토 최대 2회, 열린 개선 PR 최대 2개 |
| 발행 | 사용자가 허용한 remote·base·개선 브랜치 접두사·PR 작성 범위; merge는 기본 미허용 |
| 검토자 | 작성자와 다른 새 세션, 도구/모델 지정은 있는 설정을 따름; 도구 없으면 review pending |
| 큰 변화 | 의미·정확도·공개 계약·저장 방식·필수 검증 범위 변경과 광범위/영향 불명 변경은 사람 판단 |
| 종료·회수 | 예산 소진·검토 재시도 소진·대표성 부족·동일 실패 반복·일시중지 요청 시 중단; 되돌림 방법과 재개 조건 |

기존 요청에 더 긴 실험 예산이 있으면 그 값을 사용한다. 실행 전에 예상 남은 측정·검토·최종 검증 비용까지 예약한다. 단일 명령이 상한보다 길 것으로 보이면 시작하지 말고 짧은 진단을 택하거나 장기 관문을 주차한다. 기본 상한은 필수 검증을 생략할 근거가 아니다.

문제 발견 주기와 실험 반복 횟수는 다르다. 한 문제의 고정 항목과 시도 규칙은 [실험 루프](experiments.md)를 따른다. 처음에는 한 문제를 발견부터 PR·후속 관찰까지 운영해 배정과 증거 흐름을 확인한 뒤 동시 운영을 늘린다.

## 실제 자동 진입 연결

스킬은 실행 중인 에이전트의 절차이며 백그라운드 프로세스가 아니다. 정책을 문서에 쓴 것과 실행기를 연결한 것을 구분한다.

1. **세션 중 자동 진입**: 대상 프로젝트의 기존 AGENTS.md/CLAUDE.md 구조에 다음 취지의 짧은 지침을 통합한다. 기존 지침을 덮어쓰지 않는다. 정책의 실제 결정 참조로 치환하고 프로젝트가 쓰는 에이전트 지침만 수정한다.

   ```text
   After explicit user work is complete, or when starting an idle session, consult
   the standing autonomous-improvement decision in spec/ssot/ARCH.md.
   If enabled and due, run one bounded /self-improve cycle within that policy.
   Resume existing evidence and open PRs first; do not interrupt foreground work.
   ```

2. **세션 밖 정기 실행**: 사용자가 쓰는 스케줄러/CI/에이전트 자동화가 있으면 그 기능과 권한을 실제로 확인하고, 저장소·실행 시각/시간대·한 사이클 프롬프트·세션 timeout·로그 위치를 연결한다. 연속 개선 위임이 실행 설정 쓰기까지 포함하는 범위에서 진행한다. 호스트 전역 서비스 설치나 유료 실행 권한을 추측하지 않는다. 실행기가 없거나 연결이 불가능하면 세션 지침까지 완료하고, 정기 실행은 미연결이라고 보고한다. 미지원 CLI 옵션이나 가상의 스케줄 등록 성공을 만들지 않는다.
3. **진입 프롬프트**: “이 저장소의 /self-improve를 사용해 저장된 정책에 따라 한 사이클만 실행하라. 먼저 활성화·기한·실행 중 사이클·남은 누적 예산을 확인하고, 진행 중인 PR/후속 관찰부터 재개하라. 사람이 없으므로 위임 내 작업만 수행하고 주차 사항을 보고서에 남겨라.” 실제 실행 명령은 설치된 실행기의 기능으로 정한다.

`vibe loop`에는 개선 발견/정기 실행 기능이 없고, 단위 세션은 부하 에이전트와 자체 push를 금지한다. 이를 무한 실행기로 쓰거나 그 안에서 독립 리뷰를 흉내 내지 않는다. 발견은 탐색 세션(`work scout` 또는 네이티브 하위 세션), 실험 운영은 개선 조정자, 확정 태스크 처리는 기존 실행기, 별도 검토 배정·PR은 개선 조정자 소유로 구분한다. 작업 묶음을 쓰면 `--review all`로 모든 개선을 검토하고 대상 기본 브랜치로 직접 push하는 묶음을 만들지 않는다.

## 중복·예산·복구

- 같은 clone은 실행기의 배타 실행 기능 또는 저장소 범위 원자적 잠금으로 사이클 하나만 소유한다. 다른 clone은 CI concurrency나 공유된 실행기 소유권으로 직렬화한다. STATE·브랜치 이름·열린 PR 조회만으로 원자적 선점이 됐다고 보지 않는다. 직렬화 수단이 없으면 무인 다중 실행을 켜지 않는다.
- 보고서와 실행기 로그에 사이클의 시작/끝·정책·후보·사용 예산·명령/검토 시도·PR·다음 시점을 남긴다. 일일 합계는 실패·중단·CI/검토 비용도 포함하며 새 세션/새 후보가 초기화하지 않는다. 일자의 기준 시간대도 정책에 둔다. 조회 불가 비용은 unknown으로 남긴다.
- 명령은 timeout과 자식 프로세스 회수를 지원하는 실행기에 맡긴다. heartbeat가 늦다는 이유로 다른 세션을 중단하지 않는다. 회수 확인 전에는 다음 무거운 명령을 시작하지 않는다. 에이전트는 긴 명령/CI를 반복 폴링하지 않는다.
- 중단 뒤에는 진행 중 프로세스·소유권·HEAD·미커밋 변경·검토 대상·PR head부터 확인하고 기존 사이클을 재개한다. 불명확한 종료는 성공이나 예산 0으로 처리하지 않는다. 사용자 변경·실패 결과를 삭제하거나 자동 정리하지 않는다.
- 사용자의 중지/비활성화 요청은 새 사이클·새 원격 변경을 멈춘다. 실행 중인 자기 작업은 실행기의 정상 취소·체크포인트 절차로 보존하고, 정책·진입 지침·스케줄을 일치시킨다. 자동 권한·상한·검토 기준을 스스로 완화하지 않는다. 다른 프로젝트나 설치된 공통 스킬을 이 루프가 직접 고치지 않는다.
