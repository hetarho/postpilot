# 독립 검토와 발행

## 검토자가 실제로 별도 세션인지 확인

작성자 세션 ID/역할과 검토자 세션 ID/도구·모델을 기록한다. 다른 모델은 필수가 아니며, 작성자가 같은 대화에서 “리뷰어로서 승인”하는 것은 독립 검토가 아니다. 모델/세션 확인이 불가능하면 독립성 미확인이다.

사용 가능한 세션 실행 도구나 사전에 허용된 headless 실행기를 사용한다. 권한 확인을 유발하는 부하 에이전트를 맡김에서 새로 띄우지 않는다. 기존 work runner를 쓰면 `--review all`과 reviewer 설정을 명시하고 review-task의 고정 snapshot·runtime 결과를 사용한다. runner가 없다면 [독립 검토 프롬프트](../assets/reviewer-prompt.md)에 고정 commit과 증거를 채워 별도 세션에 전달한다. 실행 도구/권한이 없으면 패킷만 완성하고 review pending으로 남긴다.

검토는 읽기 전용의 고정 checkout에서 한다. 작성자의 가변 worktree를 공유해서 검토하지 않는다. 세션 간 모델의 내부 사고나 “승인이 필요하다”는 결론을 넘기지 않는다. 반대 증거를 포함한 원시 자료와 실제 제약을 제공한다.

## 단계별 승인 조건

코드 검토 승인과 최종 발행 준비 완료를 구분한다. work runner는 제출 리뷰 → 통합 → group 최종 관문 순서다. 제출 리뷰가 아직 실행할 수 없는 후행 전체 관문을 요구해 순환하지 않게 한다.

- base/head·계약·정책 버전과 검토 범위가 일치한다.
- 개선이 관측된 원인과 연결되며 비교 조건·표본·한계가 정직하다.
- 반복 실험이면 최초 기준선·최선 후보·고정 측정 계약·전체 시도 기록을 읽는다. 작업량/오류/정확성이 실제 artifact와 일치하는지 확인하고, 도구의 keep 판정을 독립 승인으로 취급하지 않는다. 폐기한 변경이 최종 diff에 남거나 기준 변경 전후 수치를 섞지 않았는지도 본다.
- 정확성·공개 계약·재현성·테스트의 위험 대응 범위를 보존한다.
- P1/P2 결함·검증 공백이 없고 사람 판단 대상이 아니다. 성능 차이가 불확실하면 승인 근거가 아니다.
- 제출 단계의 영향 검사·측정은 실제 실행 증거가 있다. 조정자 소유 통합/전체 관문은 명령·대상·소유자를 정해 후행 검사로 인계할 수 있다. 제출 단계에 필요한 검증 공백과 정상적인 후행 관문을 구분한다. 리뷰어는 코드·기록과 필요한 빠른 재현만 확인하고 무거운 검증을 중복하지 않는다.

후행 관문만 남았으면 코드 검토는 approved일 수 있으나 summary에 final verification pending을 적는다. 조정자는 통합/전체 관문 뒤 실제 PR 후보의 base/head·최종 증거를 독립 검토자에게 마감 확인시킨다. 같은 코드의 검증 증거 확인은 전체 검사를 다시 실행하는 절차가 아니다. 통합·sync로 관련 코드/계약이 달라졌으면 변경 범위를 다시 검토한다. 실패·미실행 관문이나 마감 확인 부재로 발행 준비 완료/자동 merge를 선언하지 않는다. draft PR은 그 공백을 명시할 수 있다.

결과는 review-task의 verdict/summary/findings 형식을 재사용하고 세션·base/head·증거 링크를 보고서 checks에 함께 보존한다. 런타임 배정이 없으면 가짜 review ID나 review-finish 호출을 만들지 않는다. 수정 요청은 구체적인 재현과 요구 증거를 담는다. 작성자가 고치면 새 head 전체와 변경분을 같은 독립 검토자에게 재제출하되 횟수 상한을 지킨다. target·정책·검사 입력이 달라져 근거가 무효화되면 재검증/재검토한다.

## PR 발행과 사람 판단

remote/base/개선 브랜치 권한을 확인한다. 허용된 경로이면 현재 사용 가능한 저장소 연결 도구나 인증된 CLI로 PR을 만든다. PR 작성은 스킬의 업무 범위지만, 토큰 발급·권한 확대·보호 규칙 해제는 포함하지 않는다. 같은 원인의 PR이 이미 있으면 그것을 갱신한다.

발행 직전에 실제 PR base/head를 고정하고 모든 증거가 그 후보에 유효한지 확인한다. 메타데이터만 바뀐 커밋 등에서 이전 측정/검증을 재사용하려면 관련 코드·설정·계약·입력·환경의 동일성과 캐시 유효성을 기록하고 독립 마감 확인이 실제 PR head를 가리키게 한다. 원시 증거의 원래 SHA를 새 SHA로 바꿔 쓰지 않는다. 기본 브랜치의 최신 코드와 충돌·관련 변경이 있으면 최종 후보를 다시 확정하고 필요한 측정/검사/리뷰를 수행한다. 자동 rebase나 수정 뒤 오래된 승인으로 발행/merge하지 않는다. 검증·검토된 후보 브랜치를 한 번 push하고, 새 실제 push에 CI가 있으면 그 결과를 한 번 기다린다. 검토 코멘트만 바뀌었다고 다시 push해 CI를 켜지 않는다.

[PR 본문](../assets/pr-body.md)은 문제·전후 근거·결과 보존·검토자·위험·한계·되돌림·사람이 판단할 구체적 선택을 담는다. 원시 로그는 허용된 artifact 위치에 보존하고 비밀값/개인 데이터는 PR에 싣지 않는다. 로컬 경로만 있는 증거는 외부에서 접근 불가임을 표시한다.

큰 변화는 사람이 보기 전에 검토 가능한 설계·작은 실험·대안·영향 분석을 완성한다. 기존 계약을 바꾸는 update-ssot를 사전 확정하거나 본선에 적용하지 않는다. draft PR 권한이 있으면 미승인임을 드러낸 draft, 없으면 로컬 제안으로 남긴다. 사람 결정이 없는 동안 해당 건은 parked이며 다른 허용 작업만 진행한다.

기본 종료점은 PR이다. 작은 변경 자동 merge를 사용자가 별도로 허용했다면 허용 경로/종류·정확한 head·독립 검토 통과·필수 로컬 관문/CI·보호 규칙·열린 사람 판단 유무를 모두 확인한다. LLM 검토 결과를 플랫폼의 사람/독립 계정 승인으로 가장하거나 관리자 우회로 합치지 않는다. merge 뒤 관측 때 회귀면 신규 개선을 멈추고 허용된 되돌림 경로로 인계한다.
