# 04. Model Provider Registry

> A vendor-neutral LLM port, providers registered in `backend/config/providers.yaml`, capability-aware per-stage
> model dropdowns, and per-account memory of the last choice | Scope: FS | Status: done (job 06). The dropdown is
> built but mounted on a page by jobs 09 and 11.

## Purpose

Generation is two calls with different needs (cheap vision for observation, a good writer for the draft — [I3]),
free models vanish without notice, and the two users may want different price/quality trade-offs. The app therefore
does **not** pick models: it exposes what is registered, marks what each model can do, greys out what cannot run
(no API key, model gone), and remembers each person's last choice per stage (PRD §3.3, §6.4, §6.5, F-4).

The Go side needs a hard boundary so that nothing above `internal/llm` ever learns which vendor answered
(ARCHITECTURE §2.1). Adding a provider must be a config edit, not a code change.

## Scope / Non-goals

**In scope**

- The `internal/llm` port (`Provider`, `Request`, `Response`) exactly as the PRD frames it, plus the registry that
  loads `config/providers.yaml`, resolves API keys from env, and exposes model capabilities.
- Adapters: `openai_compatible` first (covers OpenRouter, Together, Groq, Fireworks, DeepInfra, OpenAI, Ollama, vLLM,
  LM Studio, Google's compatible endpoint); `anthropic` via the official Go SDK **when a registered provider needs
  it**. The PRD deliberately does not fix how many adapters ship in 1.0.
- `ListModels` with per-model `vision` / `structured_output` flags and `disabled` + reason.
- Per-user, per-stage (`observe`, `write`, `analyze`) last-selection persistence and RPCs.
- Stage timeout (5 min per provider call) and adapter-internal streaming to survive long outputs.
- FE: per-stage dropdowns (observe shows vision-only), disabled/greyed rendering with reasons, vanished-model handling.

**Non-goals**

- Any app-chosen default model or default pairing (PRD §3.3: 앱이 기본값을 정해 주지 않는다).
- In-app routing/fallback between models (use router models such as `openrouter/free` in the yaml instead).
- Cost or token accounting, budgets, usage dashboards.
- Streaming tokens to the client — streams stay inside the server; the client sees job progress (PRD §6.6).
- Storing API keys anywhere but process env; exposing keys or provider SDK types to the frontend.
- Prompt text, JSON schemas, and structured-output *fallback parsing* — those belong to the callers (plans 03, 06,
  07); this plan only signals whether a model supports structured output and passes a schema through.

## Design

### The port — `backend/internal/llm`

```go
type Provider interface {
    Name() string
    Complete(ctx context.Context, req Request) (Response, error)
}
type Request struct {
    Model      string      // filled in by the registry from the ref
    System     string
    Messages   []Message   // Text and Image parts (image = bytes + mime); roles user/assistant
    JSONSchema []byte      // non-nil → the adapter requests structured output; ErrUnsupported if the model lacks it
    MaxTokens  int         // 0 → LLM_MAX_TOKENS_DEFAULT
}
type Response struct {
    Text   string          // raw text, or the JSON document when JSONSchema was set
    Usage  Usage           // prompt/completion tokens when the provider reports them
}

// What the contexts above actually call:
func (r *Registry) Complete(ctx, ref ModelRef, req Request) (Response, error)   // resolve → checks → timeout → adapter
func (r *Registry) Resolve(ref ModelRef, req Request) (Provider, ModelInfo, error)
func (r *Registry) Models() []ModelInfo · Lookup(ref) (ModelInfo, bool)
type AdapterFactory func(AdapterConfig{ProviderID, BaseURL, APIKey}) (Provider, error)
```

- Callers pass the **model** explicitly (per stage); the port reads no global default.
- Errors are normalized into a small set the callers can act on: `ErrModelUnavailable` (unknown/vanished model),
  `ErrProviderDisabled` (no key), `ErrRateLimited` (quota — the free-tier daily limit case), `ErrUnsupported`
  (image or schema on a model that lacks it), `ErrBadOutput`, plus `ProviderError{Provider, Status, Message, Kind}`
  which keeps the provider's message and *wraps* the sentinel (`errors.Is` still works). The job layer surfaces the
  message verbatim to the user (PRD §7: 오류 메시지에 원인 노출).
- Capability checks (`Resolve`) run before any network call.
- Each call runs under `LLM_STAGE_TIMEOUT` (5 min). The `openai_compatible` adapter requests a stream and joins it
  server-side to avoid idle HTTP timeouts on long outputs; the stream never leaves the process (PRD §6.6).
- Adapters are **injected**: `Load(path, getenv, adapters, opts)` takes a map of adapter name → factory, and
  `cmd/api` is the one place that builds that map (`openai_compatible` → `openaicompat.Factory`). The boundary test
  exempts `cmd/…` and `internal/llm/…` and checks everything else's dependency closure.

### Registry — `config/providers.yaml`

```yaml
providers:
  - id: openrouter
    adapter: openai_compatible          # base_url differs, protocol is the same
    base_url: https://openrouter.ai/api/v1
    api_key_env: OPENROUTER_API_KEY
    models:
      - id: openrouter/free             # auto-routing entry: survives individual free models disappearing (PRD §6.5)
        label: OpenRouter free (auto)
        vision: true
        structured_output: false
      - id: anthropic/claude-sonnet-4.5
        vision: true
        structured_output: true
  - id: anthropic
    adapter: anthropic                  # one of the few genuinely different schemas → official Go SDK
    api_key_env: ANTHROPIC_API_KEY
    models: [...]
```

- The file lives at `backend/config/providers.yaml` and is **baked into the image** at `/config/providers.yaml`
  (`Dockerfile`: `COPY config /config`, `ENV PROVIDERS_CONFIG=/config/providers.yaml`); a stack may mount an override.
  The dev container sees it through the bind mount. Parsed with `github.com/goccy/go-yaml` in strict mode (unknown
  fields are an error — a `vison: true` typo cannot silently drop a capability).
- Loaded and validated at boot (unknown adapter, duplicate provider/model id, missing `api_key_env`, no models, or
  an adapter's own check — `openai_compatible` needs an http(s) `base_url` → the process exits, same posture as a
  bad migration: a broken config must be loud). The entry is validated **even when its key is unset**.
- `api_key_env` names an env var; the key is read from the process environment at boot. Missing → every model of
  that provider is `disabled` with reason `API key not configured` (PRD §6.4, §7), the boot logs a warning per
  model, and the process still serves. The registry never stores the key in yaml. The field is optional: an entry
  without it is a keyless local endpoint (Ollama, vLLM, LM Studio), enabled as is. In dev, `docker-compose.yml`
  passes the whole repo-root `.env` through, so any `api_key_env` name works without a compose edit; the dev
  container's air also restarts on a yaml edit.
- `vision` and `structured_output` are declared per model in the yaml (the registry cannot probe them reliably).
  `label` defaults to the id.
- Adding a model or provider = edit yaml + restart. No code change (PRD §6.4). The shipped file registers
  `openrouter` (`openai_compatible`, `OPENROUTER_API_KEY`) with `openrouter/free` (vision, no structured output),
  `anthropic/claude-sonnet-4.5` and `google/gemini-2.5-flash` (both vision + structured output). `cmd/api` has a test
  that the shipped file loads with the wired adapters.

### Adapters — `backend/internal/llm/<adapter>`

- `openai_compatible`: `POST {base_url}/chat/completions`; a text-only message is sent as a plain string, one with
  images as a part list with `image_url` data URLs (base64, the part's MIME); `response_format: {type: json_schema,
  json_schema: {name, schema}}` when `JSONSchema` is set (no `strict` — the callers own their schemas); `stream:
  true` + `stream_options.include_usage`, the SSE `data:` lines joined server-side (a provider that ignores the flag
  and answers one JSON document is accepted too); an `error` object inside the stream is a failure; an empty
  completion is `ErrBadOutput`. Error bodies map to the normalized errors: HTTP 429 → `ErrRateLimited`, 404 or a 400
  whose message says the model is unknown → `ErrModelUnavailable`, anything else a generic `ProviderError` with the
  message kept.
- `anthropic`: added when a provider entry needs it, via `github.com/anthropics/anthropic-sdk-go` — never hand-rolled
  HTTP (PRD §6.4). Structured output through the SDK's tool/JSON mechanism; images as base64 blocks.
- No adapter type, SDK type, or provider error type crosses above `internal/llm` (ARCHITECTURE §2.1).

### Contract — `proto/postpilot/v1/provider.proto`

```
service ProviderService {
  rpc ListModels    (ListModelsRequest)    returns (ListModelsResponse);    // registry snapshot + per-model flags
  rpc GetSelections (GetSelectionsRequest) returns (GetSelectionsResponse); // acting user's per-stage choices
  rpc SaveSelection (SaveSelectionRequest) returns (SaveSelectionResponse);
}
message ModelRef  { string provider_id = 1; string model_id = 2; }          // reused by Start* RPCs in plans 03, 06, 07
message ModelInfo { ModelRef ref = 1; string label = 2; bool vision = 3; bool structured_output = 4;
                    bool disabled = 5; string disabled_reason = 6; }
enum Stage { STAGE_UNSPECIFIED = 0; STAGE_OBSERVE = 1; STAGE_WRITE = 2; STAGE_ANALYZE = 3; }  // buf lint prefixes
message Selection { Stage stage = 1; ModelRef ref = 2; bool missing = 3; }  // missing: saved ref no longer registered
message SaveSelectionRequest  { Stage stage = 1; ModelRef ref = 2; }
message SaveSelectionResponse { Selection selection = 1; }
```

### Selection memory (PRD F-4, addition to §5)

```sql
model_selections (user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
                  stage TEXT NOT NULL,             -- observe | write | analyze
                  provider_id TEXT NOT NULL, model_id TEXT NOT NULL,
                  updated_at TEXT NOT NULL, PRIMARY KEY (user_id, stage))
```

- The FE calls `SaveSelection` whenever a dropdown changes. `Start*` RPCs (plans 03/06/07) receive the `ModelRef`s
  explicitly in their requests and record them on the job row; they do not read this table — the table exists only
  to refill the dropdowns.
- `GetSelections` marks a selection `missing` when its ref is no longer in the registry, or no longer suits the
  stage (observe needs vision), **and clears the row in the same call** (PRD §7: 마지막 선택 초기화) — conditionally
  on the row still holding that ref, so a save made in between is not taken with it. The FE renders the old entry
  greyed with the reason "등록된 모델 목록에서 사라졌어요" once; the next answer no longer carries it, and the user
  must pick again. A saved ref whose provider has lost its key, or that the stage cannot use, is resolved
  client-side the same way: greyed with the reason, `selected = null`. A catalog that is loading or failed does not
  make a valid choice "vanished".
- `SaveSelection` refuses an unknown stage (`InvalidArgument`), an unregistered model (`NotFound`), and a disabled
  or stage-unsuitable one (`FailedPrecondition`). The FE patches its cached selections from the answer rather than
  refetching.
- Migration `0003_model_selections.sql` (build order, not the illustrative `0004` below).

### Dropdown rules (FE)

- `observe` stage: only `vision: true` models are listed (PRD §6.4). `write` and `analyze`: all models.
- `disabled` models stay in the list, greyed and unselectable, with `disabled_reason` appended to the option text.
- Each model shows badges: 👁 vision, `{}` structured output (plain text — an `<option>` renders no markup).
- No pre-selection: until the user picks, the stage is empty ("모델을 선택하세요") and
  `useStageSelection(stage).selected` is `null`, which is what the `Start*` callers block on (acceptance criterion 7
  — the "no default pairing" invariant is visible here). `StageModelSelect` is the component; pages mount it (jobs
  09 and 11), features never import it.
- `StageModelSelect` composes the shared native `Select`, `FieldLabel`, and `FieldMessage`. Loading or save-pending
  disables the control; catalog/save failures set `aria-invalid`, point `aria-describedby` at the explanatory
  alert, and a polite status announces an in-flight save without changing selection semantics.
- Free-model advice (PRD §6.5) is expressed in yaml content (router entries), not in UI logic.
- The catalog is cached for `MODEL_CATALOG_STALE_MS` (5 min): it only changes on an API restart.

## Acceptance Criteria

1. Adding a provider or model by editing `config/providers.yaml` and restarting makes it appear in the dropdowns with
   no code change; an invalid yaml stops the api from starting with a clear error.
2. A provider whose `api_key_env` is unset shows all its models greyed with reason "API key not configured"; they
   cannot be selected.
3. The `observe` dropdown lists only `vision: true` models; `write` and `analyze` list all.
4. A selection made on one device is restored on another device for the same account and stage.
5. When a saved model is removed from the yaml, the dropdown shows it greyed with the "vanished" reason and the saved
   selection is cleared; the user must choose again.
6. The frontend never receives an API key or a provider SDK payload — only ids, labels, and flags (asserted by the
   proto shape; keys exist only in server env).
7. A fresh account has no selection in any stage; the generation and analysis actions are blocked with an inline
   message until both required stages are chosen — the app ships no default pairing ([I3]).
8. A provider 429 surfaces as `ErrRateLimited` with the provider's message intact, so the job error the user sees
   names the cause (PRD §7: 무료 모델 한도 초과).
9. Requesting an image part or a JSON schema on a model that lacks the capability fails fast with `ErrUnsupported`
   before any network call.
10. No package above `internal/llm` imports an adapter or SDK package (enforced by a build-tag/lint check in the job).

## Policy / Config Impact

**The rules now live in [`spec/policy/providers.md`](../policy/providers.md)** (landed by job 06). In summary:

- Providers and models are declared only in `backend/config/providers.yaml`; keys only in env; the app ships no
  default model.
- Observation may run only on vision-capable models; structured output is requested whenever the model supports it.
- Missing key ⇒ disabled model with reason (and the process still boots); vanished model ⇒ greyed with reason and the
  saved selection is cleared by the server on read.
- Nothing above `internal/llm` learns which provider answered; the composition root is the one place adapters are
  imported.

**Config**

| Value | Owner | Supplied as | Default |
|---|---|---|---|
| `PROVIDERS_CONFIG` | BE `platform/config` | env | `config/providers.yaml` (cwd-relative); the image sets `/config/providers.yaml` |
| `<api_key_env>` per provider (`OPENROUTER_API_KEY` in the shipped file) | BE process env, named by yaml | env | — (repo-root `.env` / stack `.env`; `.env.example`, `.env.production.example`; passed through by `docker-compose.yml`) |
| `LLM_STAGE_TIMEOUT` | BE `platform/config` | typed constant | `5m` (PRD §6.6) |
| `LLM_MAX_TOKENS_DEFAULT` | BE `platform/config` | typed constant | `4096`; callers may override per request |
| `MODEL_CATALOG_STALE_MS` | FE `shared/config` | typed constant | `300000` |
| `backend/config/providers.yaml` | repo, baked into the image | file | model ids, labels, capability flags |

The yaml is config; the model ids inside it are data, never literals in Go or TS.
