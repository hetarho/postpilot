# Job 27: Throttle the publishing agent heartbeat write (refactor)

> Implementation work doc. Source spec: [code-review/01.full-repo-audit-after-twelve-plans](../code-review/01.full-repo-audit-after-twelve-plans.md).
> /implement-job 27 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/tech) and set status: done. Write it in English.

Finding covered: **R002** — every paired Mac's 5-second poll takes the single SQLite writer to refresh a value read
only as a 30-second freshness hint, and a failure of that write is reported as an authentication failure.

## Acceptance Criteria (from code-review/01)

- [ ] A1 A sequence of agent-authenticated calls arriving faster than the heartbeat interval produces **one**
      `TouchAgent` write, not one per call. Proven with a fake clock and a counting store, not by inspection.
- [ ] A2 A call arriving after the interval has elapsed does write, so `last_seen_at` never falls further behind
      than the interval.
- [ ] A3 The heartbeat interval flows through `backend/internal/platform/config` — it is not a literal in the
      publishing service (ARCHITECTURE §4) — and its documented relationship to the frontend's
      `PUBLISH_AGENT_STALE_MS` (30 s) is stated where a reader will find it: the interval must stay **shorter** than
      the staleness window, or an online agent renders as offline.
- [ ] A4 A failed `TouchAgent` no longer fails authentication. The call proceeds, and the failure is logged. Proven
      by a test whose store returns an error from `TouchAgent` and whose `AuthenticateAgent` still returns the agent.
- [ ] A5 A revoked agent is still refused before any touch is attempted, and an unknown or empty token still returns
      `ErrAgentRevoked` — the existing refusal order is unchanged.
- [ ] A6 No behavior change visible to the Mac agent or the user: claim, lease renewal, progress, complete, fail and
      cancel all behave exactly as before; `ListAgents` still reports a `last_seen_at` that moves.
- [ ] A7 The existing publishing test suite passes unchanged except where a test asserted the per-call write it is
      this job's purpose to remove.

## Implementation Checklist

- [ ] T001 `backend/internal/platform/config/config.go` — add the heartbeat interval beside the other publishing
      values (`PublishPairingTTL`, `PublishLeaseTTL`, `PublishAssetURLTTL`, …). Use the existing
      `positiveDuration("PUBLISH_AGENT_HEARTBEAT_INTERVAL", "15s")` helper so a non-positive or malformed value
      stops boot like its neighbours. **15 s is chosen, not arbitrary:** the frontend renders an agent stale after
      `PUBLISH_AGENT_STALE_MS = 30_000`, so a heartbeat at half that window keeps a live agent always inside it
      while cutting the writes from the agent's 5 s poll by two thirds. Comment that constraint at the field — the
      two values live in different config seams and nothing else will connect them.
- [ ] T002 `.env.example` and `.env.production.example` — add `PUBLISH_AGENT_HEARTBEAT_INTERVAL=15s` next to the
      other `PUBLISH_*` entries (ARCHITECTURE §4: a new env var is added to both in the same job).
- [ ] T003 `backend/internal/publishing/service.go` — add the interval to `Config` and carry it into `NewService`.
      Add a small last-touch registry to `Service`: a `map[string]time.Time` keyed by agent id, guarded by a
      `sync.Mutex`, because `WrapUnary` runs concurrently. Keep it unexported and internal to the service — it is a
      write-suppression cache, not state anyone else may read.
- [ ] T004 `service.go:104` — replace the unconditional `s.store.TouchAgent(...)` with: read the agent's last
      recorded touch; if `now.Sub(last) < s.config.AgentHeartbeatInterval`, skip the write; otherwise write and
      record `now`. Record the timestamp **only after** a successful write, so a failed write is retried on the next
      call instead of being suppressed for a full interval.
- [ ] T005 Same site — stop returning the touch error (A4). A storage failure must not present as the Mac being
      unable to authenticate: the token was valid and the agent is legitimate. Log it (`slog.Warn`, with the agent
      id) and continue. Then revisit `rpc/agent_interceptor.go:60-66`: its comment explains mapping non-revocation
      errors to `CodeUnavailable` so the supervisor backs off rather than stopping — that mapping stays correct for
      `AgentByTokenHash` failures, but the comment should no longer imply the touch is among them.
- [ ] T006 Keep `agent.LastSeenAt = &now` on the returned value even when the write was skipped. The agent *was*
      just seen; the returned struct is per-request context, and `ListAgents` reads the database independently
      (`rpc/mapping.go:18`), so the displayed value stays honest either way.
- [ ] T007 Consider whether the process-lifetime map needs eviction. Entries are bounded by the number of enrolled
      agents per deployment (a handful — `PUBLISH_MAX_PENDING_PAIRINGS` defaults to 8), and a revoked agent never
      reaches the touch, so its entry simply goes cold. Decide explicitly and write the reason down; do not add a
      sweeper without one.
- [ ] T008 `backend/internal/publishing/service_test.go` — tests: (a) three authenticated calls one second apart
      with a fake clock produce exactly one `TouchAgent` (A1); (b) a call past the interval writes again (A2);
      (c) a store whose `TouchAgent` returns an error still yields a successful `AuthenticateAgent` (A4);
      (d) a revoked agent and an unknown token are still refused, with no touch attempted (A5). The suite already
      swaps `service.clock = fakeClock{...}` (see `service_test.go:228`), so the clock seam is in place.
- [ ] T009 `backend/internal/platform/config/config_test.go` — assert the new value's default and that a
      non-positive or malformed override refuses boot, matching how the sibling `PUBLISH_*` values are tested.
- [ ] T010 Re-read `agent/internal/config/config.go:16` (`PollInterval = 5 * time.Second`) and
      `agent/internal/publishing/supervisor.go:34` (the same value again, as a fallback default). This job does
      **not** change the poll — throttling the write fixes the cost — but the duplicated constant is worth one line
      of comment pointing each at the other, so a future change to one is not silently half-applied.
- [ ] T011 Verify the full backend gate and confirm the agent is unaffected:
      `go vet ./... && go build ./... && go test ./...` in `backend/`, then the same in `agent/` (A6, A7).

## Grounding

- Constitution ([I1]–[I7]): [00.overview](../plan/00.overview.md) §3. **[I1]** is the one to watch — this job must
  not weaken the lease, the outbound-claim model, or the commit fence. It touches only the freshness stamp taken
  during authentication; claim, renewal, progress and completion are untouched. **[I5]** is unaffected.
- Architecture (placement): [ARCHITECTURE.md](../ARCHITECTURE.md) §2.4 is the rule being honoured — *one serialized
  writer connection*, which this job stops spending on a display hint — and §4 owns T001's config placement. Invoke
  `/be-architecture` before editing `internal/publishing`; the write-suppression map belongs to the publishing
  context's service, not to `platform/`.
- PRD / policy / tech touched: [policy/publishing](../policy/publishing.md) (agent liveness/`last_seen_at`
  semantics) and [tech/paired-local-publishing-agent](../tech/paired-local-publishing-agent.md) — both need the new
  interval and its relationship to the staleness window recorded in the reflect step.
