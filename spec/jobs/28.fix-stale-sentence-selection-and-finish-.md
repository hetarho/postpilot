# Job 28: Fix stale sentence selection and finish the FE config seam (refactor)

> Implementation work doc. Source spec: [code-review/01.full-repo-audit-after-twelve-plans](../code-review/01.full-repo-audit-after-twelve-plans.md).
> /implement-job 28 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/tech) and set status: done. Write it in English.

Findings covered: **R004** (the voice-feedback control submits the sentence it was mounted with), **R013** (its
long-press timer outlives the component), **R006** (two timing values are literals in components) and **R010** (the
transport segment in three query keys distinguishes nothing).

R004 is the only one with a user-visible failure; the rest are hygiene in the same slice of the frontend.

## Acceptance Criteria (from code-review/01)

- [ ] A1 Editing a block's text and then opening 문장 의견 without touching the dropdown submits a sentence that
      exists in the **current** text. The old behavior — submitting a sentence from the pre-edit text, which the
      server refuses at `backend/internal/voice/feedback.go:60` — no longer occurs.
- [ ] A2 A sentence the user explicitly picked is **kept** while it remains present in the text. The fix must not
      reset the selection on every keystroke; only a selection that has disappeared from the text is replaced.
- [ ] A3 The reason dropdown and the open/closed state of the dialog survive an edit to the surrounding text — the
      fix does not remount the component.
- [ ] A4 Unmounting the component between pointer-down and pointer-up leaves no scheduled timeout.
- [ ] A5 The long-press threshold, the app-wide query `staleTime`, and the app-wide query `retry` count all live in
      `frontend/src/shared/config` with a comment giving their rationale, matching how every neighbouring value there
      is written (ARCHITECTURE §4).
- [ ] A6 `staleTime`'s relationship to `SESSION_STALE_MS` is stated where a reader of either will see it — today the
      global default (60 s) is twice the session window (30 s) and nothing records that.
- [ ] A7 The three publishing query keys no longer carry the transport object, and every call site that built or
      invalidated one still matches the query it means to. Cache behavior is unchanged.
- [ ] A8 No behavior change anywhere else: `pnpm --filter ./frontend test` passes, `pnpm build:web` passes,
      `pnpm --filter ./frontend lint:fsd` reports no FSD violation.

## Implementation Checklist

- [ ] T001 `frontend/src/features/give-voice-feedback/ui/SentenceFeedback.tsx` — the defect is at line 20:
      `useState(sentences[0] ?? '')` is an **initializer**, read once on mount, while `sentences` (line 15) is
      recomputed from the `text` prop on every render. The prop is live editable block content
      (`features/edit-post-content/ui/BlockEditor.tsx:131` passes `block.content`), so after an edit the state names
      a sentence the text no longer contains. Fix by **reconciling during render** rather than storing the resolved
      value: keep the state as the user's *choice*, and derive what is actually used —
      `const selected = sentences.includes(sentence) ? sentence : (sentences[0] ?? '')`. Submit `selected`
      (line 27) and feed it to the `Select`'s `value`.
- [ ] T002 Do **not** solve this with a `key` on the call site. Remounting would satisfy A1 and break A3: the reason
      dropdown and an open dialog would be discarded on every keystroke in the block. Write that trade-off down at
      the fix — it is the obvious wrong turn.
- [ ] T003 Same file — add the missing cleanup for the long-press timer (A4):
      `useEffect(() => () => window.clearTimeout(timer.current), [])`. The timer is set at line 37 and cleared on
      `onPointerUp`/`onPointerCancel` (lines 39–40), but a component unmounted mid-press keeps it. React silently
      ignores the resulting `setOpen`, which is exactly why nobody would find this later.
- [ ] T004 `frontend/src/shared/config/index.ts` — add `LONG_PRESS_MS = 600`, with the rationale its neighbours all
      carry (why 600 and not 300 or 1000 for a touch target). Consume it at `SentenceFeedback.tsx:37`.
- [ ] T005 `frontend/src/shared/config/index.ts` — add `QUERY_STALE_MS` (60 s today) and `QUERY_RETRY_COUNT` (1
      today), and consume both in `frontend/src/app/providers/query-client.ts:9-10`. In the comment, state the
      relationship to `SESSION_STALE_MS` explicitly (A6): the global default is deliberately twice the session
      window. Note that `retry` is load-bearing policy, not incidental — two call sites already document themselves
      as overriding it (`entities/session/api/session-queries.ts:73`, `entities/post/api/usePost.ts:34`), which is
      why it belongs in the seam where those readers can find it.
- [ ] T006 Leave `refetchOnWindowFocus: false` where it is. It is a behavioral choice, not a tunable number, and
      moving it into the config seam would misrepresent what that file holds.
- [ ] T007 Remove the `transport` segment from the three key builders (A7):
      `entities/publish-job/api/usePublishJob.ts:9-10`, `entities/publish-job/api/useRetryablePublishJobs.ts:8-9`,
      `entities/publishing-agent/api/queries.ts:9-10`. It partitions nothing: TanStack Query hashes keys with
      `JSON.stringify`, and a Connect transport is a plain object of functions, so every transport serialises to
      `{}`. Drop the parameter from each signature rather than passing an ignored argument.
- [ ] T008 Update the seven consumers so the compiler proves the change is complete:
      `features/publish-post/model/usePublishPost.ts:29`, `features/retry-publish/ui/RetryPublishJobButton.tsx:21`,
      `features/cancel-publish/ui/CancelRetainedPublishJobButton.tsx:28`,
      `features/pair-publishing-agent/ui/PairPublishingAgent.tsx:16`,
      `features/revoke-publishing-agent/ui/RevokePublishingAgent.tsx:26`,
      `features/configure-publishing-agent/ui/ConfigurePublishingAgent.tsx:30`, and
      `entities/publishing-agent/api/queries.ts:32`. Several then no longer need `useTransport()` or `transport` in
      a dependency array — remove what becomes unused rather than leaving it.
- [ ] T009 `pages/publishing-agents/ui/PublishingAgentsPage.test.tsx:65-67` and `:124-126` currently cast `{}` to
      the transport parameter type. What those assertions actually prove is that **ownerId** separates two users'
      caches, which stays true and stays worth testing — rewrite them against the new signature; do not delete them.
- [ ] T010 Add a test for A1/A2/A3 in `features/give-voice-feedback/` (the slice has none today): render with one
      text, change the `text` prop to a different set of sentences, and assert the submitted `sentenceRef` belongs
      to the new text; then assert that an explicitly chosen sentence that is still present survives a prop change.
- [ ] T011 Verify: `pnpm --filter ./frontend test`, `pnpm build:web`, `pnpm lint`,
      `pnpm --filter ./frontend lint:fsd`, `pnpm lint:style` (A8).

## Grounding

- Constitution ([I1]–[I7]): [00.overview](../plan/00.overview.md) §3. **[I4]** is the relevant one: sentence
  feedback is per-voice learning evidence. This job does not change what is learned — the server already refuses
  feedback that does not reference the finalized text (`feedback.go:60`), which is why R004 is a UX defect rather
  than data corruption. The fix stops the client from constructing a request it should never be able to send.
- Architecture (placement): [ARCHITECTURE.md](../ARCHITECTURE.md) §3 (FSD) — every edit stays inside the slice that
  owns it: the control in `features/give-voice-feedback/ui`, the constants in `shared/config`, the query keys in
  their `entities/*/api` segments. §4 owns T004/T005. Invoke `/fe-architecture` before editing; no file moves layer.
- PRD / policy / tech touched: [policy/voice](../policy/voice.md) (sentence feedback as learning evidence) — read to
  confirm nothing there describes the stale-selection behavior as intended. No policy change is expected.
