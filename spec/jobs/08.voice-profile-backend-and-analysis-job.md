## Acceptance Criteria (from plan/03.voice-profile-learning)

<!-- Plan 03 criteria owned by this job (plan AC numbers in parentheses). AC 1 and the UI halves of 4, 6, 7, 8 belong to job 09. -->

- [ ] A1 (plan AC2) Two accounts hold different styleguides and rules; no RPC can return one account's profile to the other (no request carries a user id; queries are interceptor-scoped).
- [ ] A2 (plan AC3) Pasting a single sample of ≥ 200 characters yields a styleguide whose first section is the 종결어미 distribution and which contains a "never uses" section — the handler fails the job if the 종결어미 section is absent.
- [ ] A3 (plan AC4) A sample under 200 characters is refused with `InvalidArgument` and the character count.
- [ ] A4 (plan AC5) Adding a second sample runs the analysis over both samples (the job's input contains both bodies — asserted by a unit test on corpus assembly).
- [ ] A5 (plan AC6, server half) `UpdateVoiceProfile` persists edited `styleguide` and `rules`; `GetVoiceProfile` returns them.
- [ ] A6 (plan AC7, server half) `DeleteVoiceSample` removes the sample and re-enqueues the analysis when at least one sample remains; with none left the styleguide is untouched.
- [ ] A7 (plan AC8, server half) `AddVoiceSample` returns immediately with a `job_id` (or the active job's id when one is already running); `GetVoiceProfile.active_job_id` exposes the in-flight analysis.
- [ ] A8 (plan AC9) `ProfileForPrompt` returns styleguide, ≤ 3 excerpts (most recent, each ≤ 1500 chars), rules, in that order, plus `empty` when there is neither a styleguide nor a sample.
- [ ] A9 (derived) `AppendRule` appends a de-duplicated line to `rules` and never touches `styleguide`; the analysis overwrites `styleguide` wholesale and never writes `rules`.
- [ ] A10 (derived) `AddVoiceSample` without an enabled analyze model is refused with `FailedPrecondition` before anything is stored or enqueued.
