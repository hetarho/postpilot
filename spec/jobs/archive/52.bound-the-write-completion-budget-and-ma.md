## Review

- [x] `/code-review` (high) · `codex exec -m gpt-5.5` (background, read-only) — merged and deduped.
      **Six defects found and fixed.** Both reviewers independently reached the first two.
  1. **The spend signal never joined in production** (both reviewers, P1). The ledger records a
     model as the REGISTRY ref (`openrouter/z-ai/glm-5.3-flash`) while a catalog row is the
     provider-local id (`z-ai/glm-5.3-flash`), so `reasoningSpend` was always absent however
     many calls had been recorded — A11 silently unmet. The translation now happens in the
     composition root's adapter, the one place that knows both vocabularies, stripping only the
     registry's own first segment (a provider-local id contains slashes of its own).
     `cmd/api/reasoning_spend_test.go` asserts it directly, because the port-level test sees
     already-translated rows and could not have caught this.
  2. **The 2026-09-03 failure shape carried no split** (both reviewers, P2). `TruncatedError`
     was only built in `responseParseError`, which handles a body cut off mid-JSON — but the
     actual failure was an EMPTY completion after the model reasoned through its budget, which
     the adapter raises. The adapter has the usage in hand there and now attaches the split, so
     A12 fires where it matters.
  3. **The writing floor walked back job 23** (`/code-review`). `writeBudgetFloor = 4096` halved
     the budget for every post with a target under ~2,048 characters — reverting the 4096→8192
     raise job 23 made to stop write-stage truncation. The floor IS the configured fallback now,
     so a post that requests no length is sent exactly what every call was sent before this
     policy existed, and the ceiling became a bounded multiple of it so a longer draft can
     genuinely rise (A6) without a mistyped target asking for an unbounded completion.
  4. **A revision was budgeted by the target it may not have** (`/code-review`). `revise` must
     re-emit the WHOLE `PostContent`, so a long post with no `TargetLength` got the floor and
     truncated deterministically. The policy gained `Revise(contentChars, targetLength)`, sized
     by the larger of the two.
  5. **The observation budget ignored `OBSERVE_BATCH_SIZE`** (`/code-review`). It was a fixed
     2,048 while the batch size is deployment-tunable and `.env.example` invites raising it, so
     a raised batch would have truncated. It is per-photo × batch size now, with a floor.
  6. **The aggregate had no index** (`/code-review`). `ReasoningSpendByStage` filters on
     `(stage, created_at)` and the only index was `(user_id, created_at)`, so every operator tab
     load full-scanned a table that grows one row per provider call. Migration 0021 adds it.
- [x] **Rejected:** "`MODEL_PURPOSE_NOT_REGISTERED` is not in the frontend's reason allowlist, so
      the UI shows the generic failure" (codex, P2). Correct about the mechanism, and declined on
      scope: change 24 names **the normalized error set and every user-facing error string** as an
      explicit non-goal, and the existing `MODEL_PURPOSE_INELIGIBLE` — the same class of
      operator-only server refusal, unreachable through the UI because the control appears only
      once registered — already behaves this way. Adding copy for one and not the other would be
      worse than adding neither. A follow-up should add BOTH reasons together with their ko/en
      strings; codex's cross-tab race (one tab deregisters while another edits the effort) is a
      real way to reach it.
- [x] Verified by both reviewers and left alone: no production `llm.Request` boundary is missing
      `Stage`; `errors.Is(err, ErrOutputTruncated)` and `MODEL_OUTPUT_TRUNCATED` survive
      `TruncatedError.Unwrap`; purpose→stage is 1:1 so `stageReasoningOf` cannot collide;
      migration 0021's number is free and its `DROP COLUMN` runs (the store tests apply it);
      `unset` still emits no wire key; the FE's input-less `createConnectQueryKey` really does
      prefix-match every purpose's listing.
- [x] Design pass (design-language §10) — the spend signal sits BESIDE the control it argues
      about (§4.3), its tone reinforces words that carry the whole meaning (§2.6), it renders
