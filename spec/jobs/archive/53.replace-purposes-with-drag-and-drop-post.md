## Acceptance Criteria (from changes/archive/25.replace-purposes-with-drag-and-drop-post)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 An account creates a template whose body is the interview example, assigns it to a post with three attached photos, and generates. The result contains the intro prose, both `=========================` literal lines byte-exactly, a rating line, one unfilled 장소 slot, then **exactly three** photo-plus-description pairs in attachment order, then the closing verdict — with no leftover grammar text (`<write>`, `<repeat>`, `<note>`, a note's instruction, or a slot's `label`) anywhere in the post.
- [x] A2 The same post with **zero** photos generates with the entire repeat block absent, including its literals, and still produces the intro, the rating line, the 장소 slot and the closing verdict.
- [x] A3 A `<note>` never appears in the post, and its text is present in the frozen prompt.
- [x] A4 A post with **no** template produces a write prompt byte-identical to the fixed no-template golden under `internal/generation/testdata`, and the voice-profile prefix is byte-identical across posts with different templates and with/without guidelines.
- [x] A5 `[글 템플릿]` occupies the position `[글의 용도]` held — after the complete voice profile, before the per-post material — with `[작문 지침]` after it; a guideline still overrides the template on content and the voice still overrides both on register. The word 지침 appears in the prompt only in the guideline section and its precedence sentence.
- [x] A6 Editing or deleting a template after `StartGeneration` / `StartRevision` returns changes neither the running run nor a restart-resume nor an explicit retry; attaching more photos after the start does not change the expansion. Both write A/B candidates receive byte-identical prompts, a different template yields a different input hash, and the comparison detail still reads correctly after the template is renamed or deleted.
- [x] A7 A template body that fails to parse cannot be saved; the failure names the offending line and the reason (unknown tag, unclosed tag, unknown `kind`, unknown `each`, nested `repeat`), and no partial template is stored. A body over `TEMPLATE_BODY_MAX_CHARS` is refused with the same allowlisted `field`/`max`/`actual` detail contract the purpose bounds used.
- [x] A8 Builder → stored body → builder round-trips byte-identically for every template the builder produced. A pasted body that parses opens in the builder; one that does not opens in 원문 mode with its error and cannot be saved.
- [x] A9 A `place` or `link` slot survives generation, an AI revision that does not mention it, finalization, and export: it holds its position, is counted in the editor and the export panel, blocks neither finalization nor export, and appears in the Naver output as a bracketed placeholder line in marker order without disturbing the `[사진 …]` markers or the photo copy controls.
- [x] A10 A model result that omits a declared slot has it re-inserted at its template position; a result that drifts on literal text or section order is still accepted, and no run fails or retries because of template deviation.
- [x] A11 A photo count whose expansion would exceed `TEMPLATE_MAX_REPEAT_EXPANSION` refuses at start with an actionable failure and enqueues nothing.
- [x] A12 Deleting a template detaches it from its posts (returning the count), cascades its `guideline_templates` links, and deletes no post, content, photo, guideline or history. A guideline left with no links lists as 적용 대상 없음 and reaches no prompt until it is rescoped. Frozen payloads and experiment snapshots keep their text and stay readable.
- [x] A13 A foreign or unknown template id is `NotFound` and is indistinguishable from the other; naming one in a draft save leaves the post exactly as it was, title and memo included, and mints no post on a create. A foreign template id in a guideline scope applies nothing.
- [x] A14 `catalog_model_purposes` and `purpose_reasoning_effort` are unchanged: every 모델 관리 purpose tab, its per-purpose reasoning effort, and every stage dropdown behave exactly as before.
- [x] A15 After migration `0022`, `/purposes` is gone, no `purposes` or `guideline_purposes` table remains, an account with no templates sees the empty state, and every existing post reads and generates with no template.

## Review

- [x] Codex (`gpt-5.5`, read-only) reviewed the whole diff. **Four real defects found and fixed**, each pinned by a
      regression test using codex's own failing input:
  1. **The two parsers disagreed on blank text.** Go's `strings.TrimSpace` has `U+0085` and not `U+FEFF`;
     JavaScript's `.trim()` has `U+FEFF` and not `U+0085` — so `<write>\uFEFF</write>` was accepted by the server and
     refused by the browser. Both now share one explicit `blankRunes` set (the union, plus zero-width characters),
     and the shared fixtures pin four blank-character cases.
  2. **A slot could be inserted out of template order.** When the model echoed only a later token, the earlier
     missing slot was inserted *after* it, because insertion was relative to "the last slot seen". It now inserts
     after the nearest preceding resolved slot, else before the nearest following one, else at the end, and the
     recorded positions shift with each insertion.
  3. **A block holding two different tokens left one behind.** `slotTokenIn` returned only the lowest-numbered
     match, so the second raw token survived in the prose and the pass was not idempotent. `slotTokensIn` now
     resolves every slot a block names, in the order the tokens appear, and strips all of them.
  4. **A slot label containing `"` produced a body the builder's own parser refused**, dropping the editor into
     source mode on a valid keystroke. `&quot;` joined the grammar's entity set on both sides and the builder
     escapes it.
  Codex found **no** issue with the migration (it diffed the schema through 0021, after 0022 and after 0022's down)
  and no non-terminating or out-of-range path in either parser.
- [x] Own review pass: a 600-body generated corpus is now committed with the Go parser's verdict per body, and the
      TypeScript suite is held to the same verdicts — the differential check the two-parser design needs. The corpus
      alphabet includes the characters codex's findings turned up.
- [x] Design pass (design-language §10): the palette was rebuilt from `Menu` to a labelled button group, because a
      menu is a radio group over a current value and picking the option that already equals the value emitted no
      event at all — the bug a menu would have hidden. `font-mono` went through `Typography`/`typographyStyles`
      rather than as an ad-hoc utility. The reorderable list became `shared/ui/sortable-list` rather than one
      slice's private control (§1.1), and it offers move buttons alongside pointer drag because HTML5 drag events do
      not fire on touch and the base breakpoint is a 360px phone (§1.5).
- [x] Accessibility fix found while testing: the body field's `sr-only` label pointed at a `<textarea>` the structure
      mode does not render, and the tabpanel's `aria-label` duplicated the field's accessible name. The label is now
      rendered only with the field it names, and the panel is unnamed (its tablist carries the name).
