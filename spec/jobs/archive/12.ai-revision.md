# Job 12: AI Revision (new)

> Implementation work doc. Source spec: [plan/07.ai-revision](../plan/07.ai-revision.md).
> /implement-job 12 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/tech) and set status: done. Write it in English.
>
> Whole of plan 07 in one full-stack job: `StartRevision`, the `revise` job handler (full profile re-injection,
> minimal change, image constraints), "save as rule" through `voice.AppendRule`, and the revision box in the editor.
> Requires jobs 08 (`ProfileForPrompt`, `AppendRule`), 10 (content, validation, filter) and 11 (editor composition).

## Acceptance Criteria (from plan/07.ai-revision)

- [x] A1 Saving "존댓말로" as a rule and then generating a **new** post yields a write prompt whose rules section contains that line, placed after the excerpts (prompt assembly test), and the generated draft uses 존댓말 (manual QA).
- [x] A2 Five consecutive revisions each re-inject the complete profile (styleguide, excerpts, rules) — asserted on the prompt for each of the five jobs; the draft's voice is unchanged after the fifth (manual QA).
- [x] A3 A revision result never introduces an IMAGE `file` outside the attached set (crafted-output unit test); reordering IMAGE blocks is preserved.
- [x] A4 With `save_as_rule = false`, `voice_profiles.rules` is unchanged after the revision; with `true`, the instruction appears as a new line in the profile immediately after `StartRevision` returns and is shown on `/voice`.
- [x] A5 `StartRevision` returns a `job_id` immediately; progress is visible; closing and reopening the editor mid-revision resumes polling (plan 05 mechanics).
- [x] A6 An empty instruction, a post without content, or another user's post is refused before a job is created.
- [x] A7 Submitting the same rule twice does not duplicate the line in `rules`.
- [x] A8 Revision output passes the same validation function and attachment filter as generation (shared code path, asserted by test).
- [x] A9 (derived) An instruction longer than `REVISION_INSTRUCTION_MAX_CHARS` is refused with `InvalidArgument`; the revision box enforces the same limit.
