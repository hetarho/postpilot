## Implementation Checklist

- [x] T001 `frontend/src/features/give-voice-feedback/ui/SentenceFeedback.tsx` — the defect is at line 20:
      `useState(sentences[0] ?? '')` is an **initializer**, read once on mount, while `sentences` (line 15) is
      recomputed from the `text` prop on every render. The prop is live editable block content
      (`features/edit-post-content/ui/BlockEditor.tsx:131` passes `block.content`), so after an edit the state names
      a sentence the text no longer contains. Fix by **reconciling during render** rather than storing the resolved
      value: keep the state as the user's *choice*, and derive what is actually used —
      `const selected = sentences.includes(sentence) ? sentence : (sentences[0] ?? '')`. Submit `selected`
      (line 27) and feed it to the `Select`'s `value`.
- [x] T002 Do **not** solve this with a `key` on the call site. Remounting would satisfy A1 and break A3: the reason
      dropdown and an open dialog would be discarded on every keystroke in the block. Write that trade-off down at
      the fix — it is the obvious wrong turn.
- [x] T003 Same file — add the missing cleanup for the long-press timer (A4):
      `useEffect(() => () => window.clearTimeout(timer.current), [])`. The timer is set at line 37 and cleared on
      `onPointerUp`/`onPointerCancel` (lines 39–40), but a component unmounted mid-press keeps it. React silently
      ignores the resulting `setOpen`, which is exactly why nobody would find this later.
- [x] T004 `frontend/src/shared/config/index.ts` — add `LONG_PRESS_MS = 600`, with the rationale its neighbours all
      carry (why 600 and not 300 or 1000 for a touch target). Consume it at `SentenceFeedback.tsx:37`.
- [x] T005 `frontend/src/shared/config/index.ts` — add `QUERY_STALE_MS` (60 s today) and `QUERY_RETRY_COUNT` (1
      today), and consume both in `frontend/src/app/providers/query-client.ts:9-10`. In the comment, state the
      relationship to `SESSION_STALE_MS` explicitly (A6): the global default is deliberately twice the session
      window. Note that `retry` is load-bearing policy, not incidental — two call sites already document themselves
      as overriding it (`entities/session/api/session-queries.ts:73`, `entities/post/api/usePost.ts:34`), which is
      why it belongs in the seam where those readers can find it.
- [x] T006 Leave `refetchOnWindowFocus: false` where it is. It is a behavioral choice, not a tunable number, and
      moving it into the config seam would misrepresent what that file holds.
- [x] T007 Remove the `transport` segment from the three key builders (A7):
