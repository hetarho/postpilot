# Job 31: Split the frontend bundle by route (refactor)

> Implementation work doc. Source spec: [code-review/01.full-repo-audit-after-twelve-plans](../../code-review/01.full-repo-audit-after-twelve-plans.md).

Finding covered: **R011** — the eager bundle is 731.42 kB (gzip 216.67 kB) and every one of the eleven screens loads
on first paint, on a product whose design language was deliberately reworked to be mobile-first.

      `dist/assets/index-*.js`, and the after-figures are recorded beside it. A split with no measurement is not a

- [x] A2 The screens outside the editor/posts core no longer appear in the entry chunk. Verified by inspecting the
      build output's chunk list, not by assuming the import removal worked.

## Measurement (A1)

**Before** — one eager chunk, every screen in it, and a standing size warning:

| chunk | raw | gzip |
|---|---|---|
| `index-*.js` | 731.67 kB | 216.77 kB |
| `heif-worker-*.js` (already lazy) | 1,459.06 kB | — |

**After** — nine screens moved behind their routes. The entry chunk alone is not the honest
figure: `index.html` also `modulepreload`s six shared chunks, and all seven load on first paint.

| eagerly loaded on first paint | raw | gzip |
|---|---|---|
| `index-*.js` | 352.49 kB | 110.39 kB |
| `session-*.js` | 279.83 kB | 84.51 kB |
| `post-*.js` | 7.61 kB | 2.98 kB |
| `voice-queries-*.js` | 5.46 kB | 2.15 kB |
| `model-catalog-*.js` | 4.41 kB | 1.80 kB |
| `voice-*.js` (entity) | 3.81 kB | 1.48 kB |
| `config-*.js` | 0.37 kB | 0.25 kB |
| **total** | **653.98 kB** | **203.56 kB** |

**So the real saving is ~78 kB raw / ~13 kB gzip (−10.6% / −6.1%), not the −52% the entry chunk
alone suggests.** Stating it the other way would be the misleading version of this result, and A2
exists to prevent exactly that.

Fetched only when its route is first entered (10 chunks, 87.2 kB raw / 29.5 kB gzip in total):
`voice` 23.43 · `ai-models` 13.31 · `purposes` 9.86 · `voices` 9.55 · `publishing-agents` 9.38 ·
`model-experiment` 6.82 · `candidate-comparison` 5.76 · `voice-validation` 3.59 ·
`voice-rule-comparison` 3.24 · `VoiceLayout` 2.22 kB.

`heif-worker-*.js` keeps its byte-identical hash (`D9Ws7trK`) before and after, so **[I6]** is
untouched: HEIC work is still its own lazily fetched chunk.

**The remaining eager weight is not route code.** `session-*.js` (279.83 kB) is the protobuf/Connect
/react-query runtime reachable from the auth guard, which every route needs before it can render
anything. Reducing it is a vendor-splitting question, not a routing one, and is left as a named
follow-up rather than smuggled into this job.

## Implementation Checklist

- [x] T001 Record the baseline (A1): run `pnpm build:web` and copy the chunk table into this job. Note that
      `heif-worker-*.js` (1,459 kB) is **already** correctly split and lazily fetched — `shared/lib/image/heif.ts:20`
      constructs the worker only when the first HEIC is selected. It is the proof the pattern is understood here,
      and it must stay as it is.
- [x] T002 (**core kept eager, as proposed:** `LoginPage`, `AuthenticatedLayout`, `PostsPage`,
      `NewDraftPage`, `PostEditorPage`. A session's first paint is the post list or the editor, so
      putting either behind a chunk would pay a real cost to save one.) Decide the core, and write the reason down. Proposed: `LoginPage`, the authenticated layout, `PostsPage`,
      `NewDraftPage` and `PostEditorPage` stay eager — a session's first paint is the post list or the editor, and
      making either wait on a chunk trades a real cost for the saving. Everything else is a candidate:
      `PublishingAgentsPage`, `VoicesPage`, `PurposesPage`, the five voice tabs behind `VoiceLayout`,
      `AIModelsPage`, `ModelExperimentPage`, `VoiceRuleComparisonPage`, `VoiceValidationPage`.
- [x] T003 `frontend/src/app/routes/router.tsx` — convert the chosen routes with TanStack Router's
      `lazyRouteComponent(() => import('@/pages/…'), 'ExportName')`, replacing the static `component:` and its
      top-of-file import. The pages are **named** exports (`import { AIModelsPage } from '@/pages/ai-models'`), so
      pass the export name as the second argument; the default-export form will silently render nothing.
- [x] T004 Keep every `beforeLoad`, `loader` and `context` exactly where it is (A4). Only the `component` moves into
      the lazy boundary — the session guard on `authenticatedRoute` and the voice loader must keep running before
      the chunk is requested, or a signed-out user fetches a screen's code before being redirected.
- [x] T005 (**one chunk, not five.** All five tabs name the same specifier `import('@/pages/voice')`,
      so the bundler emits a single 23.43 kB tab chunk — they are one screen and are always reached
      together. `VoiceLayout` is lazy too but stays its **own** 2.22 kB chunk: it lives in
      `app/routes/`, not in the `pages/voice` slice, and sharing their specifier would mean moving it
      across FSD layers for two kilobytes. An earlier version of this job's comment claimed they
      shared one chunk; codex caught that it did not, and the comment now states what the build does.)
      The five voice tabs share `VoiceLayout` and are always reached together. Decide whether they are five
      chunks or one, and say which and why — five chunks for one screen's tabs is a worse trade than a single
      voice-area chunk. Whatever is chosen, `VoiceLayout` itself follows the tabs.
- [x] T006 (**a pending state was added.** The first answer was "the chunks are small enough" — the
      largest is 7.16 kB gzip — but that measures the wrong thing: TanStack *awaits* the chunk before
      committing the navigation, so a slow fetch does not show a blank frame, it leaves the previous
      screen sitting there with no sign the tap was heard. On the mobile-first product this finding
      exists for, that is the regression. `RoutePending` (`app/routes/RoutePending.tsx`) reuses the
      established page-loading pattern — `role="status"`, `text-content-tertiary`, registered tokens
      only — and TanStack's 1 s `defaultPendingMs` means a fast connection never sees it.
      `defaultPreload: 'intent'` was considered and **not** taken: it would also fire loaders on
      hover, a broader behavior change than this job's scope.) Check what a lazy route shows while its chunk loads. TanStack Router renders the nearest `pendingComponent`
      (or nothing). A blank frame on a slow phone connection is a regression against R011's own motivation — if the
      app has no pending state for this, either add a minimal one consistent with
      [tech/design-language](../../tech/design-language.md) or note explicitly that the chunks are small enough not to
      need one, with the measurement to back it.
- [x] T007 (**no change was needed to keep the existing tests passing** — they already `await`
      `findBy*`, which absorbs the lazy boundary, and all 16 passed unmodified against the real tree.
      Five tests were *added* instead: `renderAppAt` starts at a path via `createMemoryHistory`, which
      is exactly a deep link, so they prove A3's direct-load half for `/publishing-agents`, `/voices`,
      `/purposes`, `/ai-models` and a voice tab. Verified they bite: replacing one `lazyRouteComponent`
      export name with a wrong one fails both the new test and the pre-existing `/purposes` test.)
      `frontend/src/app/routes/router.test.tsx` — the tree is exported specifically so a test can mount it
      against a fake transport. Update it to await the lazy boundaries rather than narrowing what it mounts (A5).
- [x] T008 Re-run `pnpm build:web` and record the after-figures next to T001's baseline (A1, A2). Confirm the entry
      chunk shrank and that the new chunks correspond to the screens in T002 — a split that merely renamed chunks is

- [x] T009 (**left at the 500 kB default, and now stated explicitly in the config** so the decision is
      visible: nothing trips it, the build carries no warning, and raising the number would only hide
      the next regression.) `frontend/vite.config.ts` — set `build.chunkSizeWarningLimit` to the number chosen in T008 (A6). This is
      the step that closes the finding: the build must stop carrying a warning nobody reads. If the entry chunk is

- [x] T010 (**partially — stated plainly rather than claimed.** The *direct-load* half of A3 is proven

## Review

- [x] `/code-review` applied (rejections noted with reason) · for non-trivial logic, `/codex:review --background`

**`/code-review` — one finding, applied.** Nine routes went lazy with neither `defaultPreload` nor a
pending component, so a slow chunk fetch leaves the previous screen unchanged with no feedback —
previously instant. `RoutePending` closes it (see T006). It also confirmed by grep that `router.tsx`
is the only importer of `@/pages/*`, so nothing pulls a split chunk back into the entry bundle.

**codex (`gpt-5.5`, read-only) — one finding, applied.** The comment claimed the five tabs *and their
layout* shared one chunk; the build emits two, because `VoiceLayout` names a different specifier. Both
the router comment and the test comment now say what actually happens (see T005). codex separately
verified the two things most worth verifying: that `beforeLoad` runs before `loadRouteChunk` in the
installed router — so a signed-out visitor is redirected before any screen code is imported (A4) —
and that `lazyRouteComponent`'s `exportName` is constrained to `keyof` the imported module, so a wrong
name fails loudly rather than silently rendering nothing. It also independently recomputed the
first-paint arithmetic above and agreed the entry-only figure overstates the result.
