## Review

- [x] `/code-review` applied (rejections noted with reason) · for non-trivial logic, `/codex:review --background`

`/code-review` at `high` raised five findings; all five were applied.

1. The seed `job_id` had nowhere to show. `VoiceRunStatus` was extracted from `VoiceImportPage` and mounted on the
   `말투` tab too, so the tab a described create lands on reports the run and its failure (A7, A11).
2. The seeded snapshot published zeros for measurements it never took, and the prompt renderers guard only on
   `Empty || Version == 0`. `renderChars` / `renderParagraphSentences` now render a non-positive measurement as
   `unknown`, the way an unanswered axis already does, in all three projections.
3. The plan/quota gate lives inside `Queue.Enqueue`, so a refused seed leaves the voice created. That is the intended
   "creation and seeding are separable" contract, but the client dropped the row: `useCreateVoice` now invalidates
   the directory `onError` too, so the voice is never invisible while its name is genuinely taken.
4. `versions.reason.seed` was missing, so the version history rendered the raw `seed`. Added in both locales.
5. `seed_voice` was absent from `SweepQueuedPersonalization`. Added (plus sqlc regeneration and the job test): a seed
   is explicit intent carrying a model ref, so boot must not drain it — the deliberate cost is that a seed lost to a
   restart is not re-run, which the jobs policy now states.

`/codex:review` was NOT run: this session is configured not to call the Agent tool, which is how that skill
dispatches. Nothing here is presented as a Codex review.

Beyond the findings, `frontend/vite.config.ts` gained an explicit `testTimeout` (20s). The suite mounts the real route
tree in almost every file and had begun expiring vitest's 5s default on a loaded machine, in whichever files happened
to be scheduled together — including files this change never touched.
