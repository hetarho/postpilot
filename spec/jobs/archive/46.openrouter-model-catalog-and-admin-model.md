## Acceptance Criteria (from plan/18.openrouter-model-catalog-and-admin-model)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 A master-plan user reaches 계정 관리 and 모델 관리 as tabs of `/admin`; a non-master is redirected by the route guard, and every `ModelCatalogService` procedure is refused server-side with `MASTER_ONLY` regardless of client.
- [x] A2 The 모델 관리 tab shows the live OpenRouter catalog merged with DB state: featured providers first in the configured order, then the rest alphabetically, newest models first within a provider; search and the provider/capability/enabled filters narrow the list client-side.
- [x] A3 Enabling a model (floor prefilled `free`, admin-changeable to `basic`/`max`) makes it appear in every user's stage dropdowns — observe only when it has vision — **without a process restart**; disabling removes it and the existing vanished machinery greys it once and clears saved selections per current policy.
- [x] A4 The user-facing catalog (`ListModels`, `SaveSelection`, plan-floor admission, `Registry.Complete`) is served entirely from `catalog_models`; no user-path request contacts OpenRouter, and an OpenRouter outage changes nothing for users.
- [x] A5 `min_plan` behaves exactly as plan 17 shipped it: locked models render with the unlocking tier, every RPC refuses a locked ref, and a kept-but-locked selection returns on upgrade.
- [x] A6 An admin refresh re-snapshots label/context/pricing (`pricing_checked_at` updated) for enabled rows and marks rows absent from the live list `listed = false`: they badge as 제공 종료 in admin, serve as disabled-with-reason to users, and are never auto-disabled.
- [x] A7 When the OpenRouter fetch fails or the cache is stale, `ListCatalog` degrades to DB rows plus a visible fetch error, and no `listed`/metadata bookkeeping is written.
- [x] A8 The migration seeds the twelve shipped models with their current labels, flags, metadata, floors, and the `claude-sonnet-5` `unset` override; an existing account's saved selections survive the cutover with no clearing and identical generation behavior.
- [x] A9 `providers.yaml` carries only provider connection config and recommendation sets; a `models:` key fails boot via strict parsing; an empty `catalog_models` boots fine and renders an empty user catalog; boot never calls OpenRouter.
- [x] A10 `ApplyRecommendationSet` validates all nine refs against the DB registry at apply time and refuses with every offending ref named (unknown / disabled / unsuitable / plan-locked) in one answer.
- [x] A11 The per-model reasoning override round-trips through admin edit: `NULL` defers to stage policy, `unset` omits the wire key, an explicit value is sent — verified at the adapter seam.
- [x] A12 Boundary intact: no package above `internal/llm` imports an adapter/SDK; the OpenRouter catalog client is plain HTTP inside `internal/modelcatalog`; no API key or base URL reaches the frontend.

      against in-flight job 25 before landing): create `catalog_models` exactly as plan 18 §Design (PK `model_id`,

      `input/output_usd_per_million` + `pricing_checked_at`, `min_plan` CHECK `free|basic|max`, nullable
      `reasoning_effort` CHECK over the strict effort set incl `unset`, `enabled`, `listed`, `last_seen_at`,

      parsed yaml slice. Provider-key-missing still disables every model of the provider with
      `DisabledReasonNoKey`; add the new disabled reason constant for a source-delisted model (`listed = false`).
      An empty source is valid (no boot failure).
- [x] T003 `backend/internal/llm/registry.go`: drop the per-provider `models:` list from the yaml schema (strict
      parse now fails a leftover key with a clear error); keep provider connection fields + `recommendation_sets`,

**Backend — the new `modelcatalog` context**

- [x] T005 `backend/internal/modelcatalog/openrouter`: catalog HTTP client — `GET {base_url}/models` (no auth
      header), plain `net/http` under `OPENROUTER_CATALOG_FETCH_TIMEOUT`, parse per
      [tech/openrouter-catalog](../../tech/openrouter-catalog.md) (id→model_id, slug before first `/`, name→label,
      `"image" ∈ input_modalities`→vision, `"structured_outputs" ∈ supported_parameters`→structured_output,
      USD-per-token decimal strings ×10⁶ without float round-trip, `created`→source_created_at; skip entries
      missing id/name with a warning; ignore unknown fields), in-memory TTL cache (`OPENROUTER_CATALOG_TTL`) with
      an explicit bypass for refresh. Unit-test against `httptest` fixtures incl. a malformed entry and a fetch
      failure.
- [x] T006 `backend/internal/modelcatalog/store`: `catalog_models` queries (list all, list enabled, get, insert
      from snapshot, partial update enabled/min_plan/reasoning, bulk availability/metadata refresh) + store
      mapping rows → domain; new `sqlc.yaml` entry; `pnpm gen:sql`.
- [x] T007 `backend/internal/modelcatalog` (`service.go`, `ports.go`): domain rules — `EnableModel(model_id,
      min_plan)` snapshots the live entry (or re-enables an existing row offline; unknown both ways → NotFound);
      `UpdateModel` partial update with strict `reasoning_effort` validation; merge logic for the admin view
      (every live candidate annotated with DB state **plus** DB rows absent from the live list as `listed=false`);
      availability bookkeeping written **only on a successful fetch** (set `listed`, `last_seen_at`, refresh
      label/context/pricing + `pricing_checked_at` for enabled rows); a failed fetch degrades to DB rows + error,
      writes nothing.
- [x] T008 `backend/internal/modelcatalog`: the DB-backed `llm.ModelSource` implementation — reads enabled rows
      into `ModelInfo` (flags, metadata, `min_plan`, reasoning override, unlisted→disabled-with-reason), in-process
      cache invalidated by every admin write so the next RPC sees the change without a restart.
