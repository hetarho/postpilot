## Review

- [x] `/code-review` applied (rejections noted with reason) · for non-trivial logic, `/codex:review --background`

Review notes — `/code-review` (7 findings) + codex `gpt-5.5` (2 findings), merged:

- **Applied:** the stale-success guard (a text copy's confirmation now stores the value it copied and renders only
  while that value is still the current output — the Naver copy carries no fallback element whose value `isCurrent`
  could compare; found by both reviewers); focus handed back to the copy button when a content change unmounts the
  focused fallback field; the fallback field kept mounted through a retry (`manualCopy` is no longer cleared up
  front, and the copy button always passes `outputRef.current`); `imageByFile` reused instead of a re-derived map;
  dead `block.type` conditionals under `renderMissingImage` removed (proto `Block` is one flat message, not a
  union); the ceremony `useCallback` dropped; a dismissed fallback can no longer resurrect when an edit is undone
  (`manualCopy` stores the content identity beside the value; codex).
- **Rejected:** "PreviewPhoto should reuse the `rendered` node instead of re-rendering the image" — the preview's
  `img` needs `onError`-keyed failure state and a `relative` overlay plane, neither of which can be attached to the
  opaque node `renderBlock` receives; extracting a shared image atom for two ~15-line call sites was judged
  premature. The duplication is confined to `PreviewPhoto` and noted here for the next touch.
