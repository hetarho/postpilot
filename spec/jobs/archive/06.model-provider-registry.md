## Acceptance Criteria (from plan/04.model-provider-registry)

- [x] A1 Adding a provider or model by editing `providers.yaml` and restarting makes it appear in the dropdowns with no code change; an invalid yaml stops the api from starting with a clear error. — `registry_test.go` (`TestParse_RejectsBrokenConfigs`: unknown adapter, duplicate ids, bad `base_url`, field typo, no providers, not yaml; `TestLoad_UnreadableFile`), `cmd/api/providers_test.go` (the shipped file loads with the wired adapters), `main.go` exits 1 on a load error before the DB is touched. The dropdown reads `ListModels`, which is the registry.
- [x] A2 A provider whose `api_key_env` is unset shows all its models greyed with reason "API key not configured"; they cannot be selected. — `TestParse_MissingKeyDisablesProviderWithReason` (exact string), `service_test.go` (`SaveSelection` refuses a disabled model), `StageModelSelect.test.tsx` ("greys a model whose provider has no key").
- [x] A3 The `observe` dropdown lists only `vision: true` models; `write` and `analyze` list all. — `filterForStage` + `types.test.ts`, `StageModelSelect.test.tsx` ("lists only vision models for observe"); server side, `SaveSelection` refuses a non-vision model for observe (`ErrModelUnsuitable`).
- [x] A4 A selection made on one device is restored on another device for the same account and stage. — `store_test.go` (`TestSelectionsRoundTrip`, scoped by user), `StageModelSelect.test.tsx` ("restores a saved choice").
- [x] A5 When a saved model is removed from the yaml, the dropdown shows it greyed with the "vanished" reason and the saved selection is cleared; the user must choose again. — `service_test.go` (`TestGetSelections_MarksAndClearsVanishedModels`: reported `missing` once, row cleared conditionally on the ref), `StageModelSelect.test.tsx` ("shows a vanished saved model greyed…").
- [x] A6 The frontend never receives an API key or a provider SDK payload — only ids, labels, and flags. — `provider.proto` has no such field; `ModelInfo`/`Selection` are the only shapes.
- [x] A7 A fresh account has no row in `model_selections` and `StageModelSelect` renders "모델을 선택하세요" for every stage, exposing `selected = null`. — `useStageSelection` returns `selected: null` until a usable choice exists; `StageModelSelect.test.tsx` ("starts empty for a fresh account", no `SaveSelection` call).
- [x] A8 A provider 429 surfaces as `ErrRateLimited` with the provider's message intact. — `client_test.go` (`TestComplete_RateLimitKeepsTheProviderMessage`, also mid-stream).
- [x] A9 Requesting an image part or a JSON schema on a model that lacks the capability fails fast with `ErrUnsupported` before any network call. — `registry_test.go` (`TestResolve_RefusesUnsupportedBeforeCalling`: provider call count stays 0).
- [x] A10 No package above `internal/llm` imports an adapter or SDK package. — `internal/llm/boundary_test.go` (one `go list -f '{{.ImportPath}} {{join .Deps " "}}' ./...`; exempts `internal/llm/…` and `cmd/…`, the composition root that injects adapters by design).

- [x] `/code-review` (high) applied · `/codex:review` (gpt-5.5, background) merged. Applied: catalog load error shown as "model vanished"; over-broad model-not-found regex swallowing ordinary 400s and every 404; empty message serialized as `[]`; negative `MaxTokens` sent to the provider; `Resolve` exposing the raw `Provider` (timeout bypass) → unexported; `api_key_env` mandatory (blocked keyless local providers) → optional, no `Authorization` header when keyless; registry validation moved before the DB is opened; dev compose forwarded one key by name → root `.env` passed through; air not watching the yaml; N+1 `go list` in the boundary test; `readStream`/`readJSON` duplication; unreadable `updated_at` zeroed in silence → RFC3339Nano + warn; stage-unsuitable saved model (observe without vision) treated as selected → refused on save, reported missing on read, greyed on the client; **race**: clearing a vanished selection could delete a concurrent new save → `DeleteSelectionIfRef`; **truncation**: a stream cut before `[DONE]`/`finish_reason` was accepted as complete → `ErrBadOutput`; unknown non-zero stage reported as "required".
  Rejected: clear-on-read being destructive when a *valid* but trimmed yaml is deployed (it is the spec'd behaviour — PRD §7 마지막 선택 초기화 — and a registry that does not validate refuses to boot; noted as an operator caveat); `Provider.Name()` unused (PRD §6.4's port shape); cwd-relative default `PROVIDERS_CONFIG` (same convention as `DB_PATH`, documented in `.env.example`); the stage set existing in proto/Go/TS forms (the FE string union is the app vocabulary; the mapping table is the one seam); deploy preflight for the key (a missing key is non-fatal by design; `DEPLOY.md` documents it); `UpdatedAt` plumbing and `providerClient` (cheap, spec'd); hoisting the SQLite timestamp helpers / test DB fixture / `actingUser` across contexts (worthwhile, but a cross-context refactor for a code-review job, not this one).
