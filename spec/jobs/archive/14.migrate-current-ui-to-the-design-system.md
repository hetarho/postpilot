## Acceptance Criteria (from changes/01.migrate-current-ui-to-the-design-system)

- [x] A1 The login, authenticated shell, post list, draft editor, photo workflow, and `StageModelSelect` all render and retain the plan 01/02/04 behavior described above; their existing feature tests pass without weakening assertions around routing, mutation ordering, autosave, upload, deletion, retry, or selection persistence.
- [x] A2 No generic button, button-like link/file trigger, text input, textarea, or select is visually hand-rolled in `app`, `pages`, `widgets`, `features`, or `entities`; it uses or composes the current-need primitive in `shared/ui`, while domain-named UI remains in its owning slice.
- [x] A3 The resulting `shared/ui` inventory contains no primitive, variant, or state that has no production call site in the in-scope UI. Each primitive has focused tests for the semantics and interaction states it actually exposes.
- [x] A4 Every in-scope colour utility uses the new surface/content foundation or the narrow functional role appropriate to the element. There are no call sites using the retired `bg`, `surface`, `text`, `primary`, bare status, `border`, `overlay`, or `depth` vocabulary.
- [x] A5 The temporary migration-alias block is absent from `frontend/src/app/styles/index.css`, and `pnpm lint:style` fails on a probe containing any retired colour utility while passing the migrated frontend.
- [x] A6 Each in-scope view has at most one CTA treatment. Every other existing action uses the quietest current-needed functional button treatment, including hover and active feedback; outlined is used only when an actual secondary action needs a visible rim, and a solid danger treatment appears only in a confirmation context.
- [x] A7 Generic controls that a user presses have a minimum 44 px touch target in their normal mobile presentation; icon-only actions have accessible names; every control is keyboard reachable and has a visible `focus-visible` indicator.
- [x] A8 Labels remain visible or programmatically associated, field errors use `aria-invalid` plus an explanatory message, and logout/save/upload/model-selection asynchronous feedback retains the appropriate `role="status"` or `role="alert"` behavior.
- [x] A9 The UI is reviewed with both `data-theme="night"` and `data-theme="day"`; primary, secondary, and tertiary content meet WCAG AA on every surface used, functional foreground/background pairs meet AA, and information is never communicated by colour alone.
- [x] A10 Cards, borders, surface jumps, type roles, spacing, radius, shadow, and motion across all in-scope screens satisfy the design-language review checklist; no card is nested and every remaining border matches an allowed exception.
- [x] A11 `pnpm build:web`, frontend lint, FSD lint, frontend tests, `pnpm lint:style`, and `pnpm lint:spec` pass after the migration.
- [x] A12 No backend/proto/schema/config value or product policy changes as a result of this refactor, and invariants [I1]–[I7] remain true.

## Implementation Checklist

- [x] T001 [P] `frontend/src/shared/ui/button/`: add the named-export `Button` primitive and a
      `buttonStyles` recipe for semantic elements that cannot render as `<button>` (the router's
      `Link` and the file-input `<label>`). Support only combinations with current production call
      sites: CTA, secondary, neutral ghost, and quiet danger; add no solid-danger or outlined variant
      unless an in-scope call site proves it needs one. Use the `button-*` functional roles for
      default/hover/active/foreground, keep pressed controls at least 44 px high, default a rendered
      button to `type="button"`, preserve caller-supplied `type`, `disabled`, native props, ref, and
      accessible name. Add focused tests for the exposed variants and semantics; do not add a slot or
      component-library dependency.
- [x] T002 [P] `frontend/src/shared/ui/field/`: add the current-needed field primitives
      (`TextField`, `Textarea`, and the shared label/message presentation they actually consume).
      Support the recessed well and editor-bare variants only, using `field-*`, `content-*`, and the
      global focus role. Forward native props and refs so login autocomplete/required behavior and the
      editor's focus, selection range, and caret handoff remain intact; preserve `aria-invalid` and
      label association. Add focused tests for ref/native-prop forwarding, well/bare styling contract,
      disabled state, and invalid messaging.
- [x] T003 [P] `frontend/src/shared/ui/select/` and `shared/ui/badge/`: add a native `Select` and a
      neutral `Badge`, with only the states used by `StageModelSelect` and post status rows. `Select`
      forwards native select props/ref and keeps placeholder, disabled option, disabled control, and
      `aria-invalid` semantics; it does not introduce a custom menu. `Badge` is a non-interactive
      label using `badge-neutral-*`. Add focused tests and no speculative tone/size variants.
- [x] T004 `frontend/src/shared/ui/index.ts`: expose the four current primitive groups through the
      shared public surface (named exports only). Audit production imports and tests so every exported
      primitive/variant has at least one in-scope production call site; remove anything unused rather
      than keeping it for a future screen.
- [x] T005 `app/routes/AuthenticatedLayout.tsx` + `pages/login/ui/LoginPage.tsx`: migrate the
      authenticated shell, logout action/error, and login form to `shared/ui` and the functional

      a neutral ghost action, retain pending labels/disabled states, generic login failure text,
      session-end ordering, and redirect behavior, and apply the mobile `px-4` → `sm:px-6` gutter.
      Extend the existing real-router tests only where needed to assert semantic element types,
      disabled/pending state, labels, and alert behavior without class-name snapshots.
- [x] T006 `pages/posts/ui/PostsPage.tsx`: use `buttonStyles` for the new-post router link, `Button`
      for retry, `Badge` for post status, `row-*` for interactive rows, `divider` for the allowed
      hairline, and content hierarchy tokens for loading/empty/time metadata. Keep one CTA, make every
      row and action a 44 px target on mobile, preserve server order and navigation, and keep the list
      flat (no per-row cards). Extend `PostsPage.test.tsx` for retry and accessible row/action
      semantics while retaining its plan 02 routing assertions.
- [x] T007 `pages/editor/ui/{DraftEditor,EditorPage,EditorPhotos}.tsx` and
      `features/save-draft/ui/SaveStatus.tsx`: compose the shared bare field and button/link contracts,

      autosave, first-save minting, ref-based caret restoration, load-failure retry rules, photo
      orchestration, or live-region behavior. Preserve the editor's paper-like transparent fields and
      exactly the current title/memo accessible names.
- [x] T008 `features/upload-photos/ui/{PhotoPicker,PhotoStrip,SkippedList,UploadProgress}.tsx` and
      `entities/image/ui/Thumbnail.tsx`: use the shared button recipe for the label-backed file trigger,

- [x] T009 `features/select-model/ui/StageModelSelect.tsx`: compose the shared native `Select` and

      `StageModelSelect.test.tsx` around native combobox semantics rather than presentation classes.
