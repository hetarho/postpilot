## Acceptance Criteria (from changes/20.purpose-scoped-model-enablement-with-adm)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 The 모델 관리 tab of `/admin` presents five purpose tabs — 사진 해석 · 문체 분석 · 글 작성 · 이미지 생성 · 비디오 생성 — and registering a model in one tab does not register it in any other; one model can be registered to several purposes simultaneously.

- [x] A3 Each user-facing stage picker (observe / write / analyze, wherever mounted: generation options, A/B candidate slots, model lab, voice analysis) lists exactly the models registered to its purpose (`photo-analysis` / `writing` / `style-analysis`); `SaveSelection` and `Registry.Complete` refuse any other model server-side.
- [x] A4 `image-generation` and `video-generation` registrations persist, survive reload, and are editable in admin, while no generation path, job type, or user-facing surface reads them.
- [x] A5 The migration seeds no purpose registrations: after cutover all five tabs are empty, stage dropdowns are empty, and previously saved selections flow into the existing unavailable-selection machinery (greyed with a reason, cleared per current policy) with no crash and no auto-selection.
- [x] A6 `ApplyRecommendationSet` validates every ref against its purpose's registration at apply time and refuses with all offending refs named, grouped by cause, in one answer.
- [x] A7 Per-model reasoning override, pricing/metadata snapshots, refresh bookkeeping, and 제공 종료 badging behave exactly as before, shared across the model's purposes.

## Implementation Checklist

<!-- How to build it, top to bottom. [P] = parallel (different files, no dependency). Flag (gen)/(migrate).

- [x] T001 (migrate) Migration `0020_catalog_model_purposes.sql`: add `catalog_model_purposes(model_id REFERENCES
      catalog_models, purpose TEXT CHECK (purpose IN ('photo-analysis','style-analysis','writing',
      'image-generation','video-generation')), PRIMARY KEY(model_id, purpose), created_at)` and add
      `image_output` / `video_output` INTEGER NOT NULL DEFAULT 0 columns to `catalog_models`. **Seed no purpose
      rows** (interview decision — every purpose starts empty). Embed and run at boot like 0018/0019.
- [x] T002 BE purpose vocabulary in `backend/internal/modelcatalog` (`types.go`): a `Purpose` type with the five
      slugs, the display order, the per-purpose capability gate (photo-analysis → vision; image/video-generation →
      the matching output flag; style-analysis/writing → none), and the mapping to the three `provider.Stage`
      values. Purposes are domain constants, not env config.
- [x] T003 [P] OpenRouter client (`backend/internal/modelcatalog/openrouter/client.go`): parse
      `architecture.output_modalities` and surface `ImageOutput` / `VideoOutput` on the candidate model; keep the
      existing input-modality → vision mapping untouched.
- [x] T004 Store (`backend/internal/modelcatalog/store`, `queries/catalog_models.sql` + sqlc regen): persist the
      new columns, list rows with their purposes (join), and add register/deregister purpose writes. Snapshot
      refresh keeps updating the shared per-model metadata only.
- [x] T005 `modelcatalog.Service`: purpose-aware curation — `RegisterPurpose(modelID, purpose)` /
      `DeregisterPurpose(...)` semantics replacing global enable as the user-visibility gate (a model row is
      created on first registration, kept on last deregistration so the reasoning override survives, mirroring
      the shipped enable/disable behavior); enforce the T002 capability gate server-side (refuse with
      `InvalidArgument`-shaped domain error); merged `ListCatalog` entries carry `purposes`, `image_output`,
      `video_output`; in-memory `ModelSource` cache invalidates on every purpose write.
- [x] T006 (gen) `proto/postpilot/v1/model_catalog.proto`: `CatalogEntry` gains `repeated string purposes`,
      `bool image_output`, `bool video_output`; curation RPC surface becomes purpose-aware (e.g.
      `UpdateModel` gains per-purpose registration edits or a dedicated `SetModelPurpose`; absent fields stay
      non-edits so concurrent operators don't clobber each other). `pnpm gen:proto`; adapt
      `backend/internal/modelcatalog/rpc/handler.go` (still master-only via the interceptor list).
- [x] T007 `internal/llm` registry: `SourceModel`/`ModelInfo` carry the purpose set (opaque strings from the
      source — llm learns no product vocabulary beyond passing them through); a model with zero registered
      purposes is unavailable to `Resolve`/`Complete` (`ErrModelUnavailable`), keeping the no-key and delisted
      disabled-reasons precedence as shipped.
- [x] T008 `backend/internal/provider`: replace the vision-only `Suitable(stage, info)` gate with purpose
      membership (stage → purpose via the T002 mapping; observe's vision requirement is subsumed because the
      photo-analysis gate already forces vision at registration). `ListModels` conveys per-stage availability,
      `SaveSelection` and the pair/experiment paths refuse an unregistered model, and the existing
      unavailable-selection machinery (grey with reason, clear per policy) is reused unchanged for selections
      stranded by the empty cutover (A5 — no bespoke clearing).
- [x] T009 `ApplyRecommendationSet` (`backend/internal/provider/service.go`): apply-time validation checks each
      ref against **its stage's purpose registration**, still collecting every offender into one `SetRefusal`
      grouped by cause. Update `backend/cmd/api/providers_test.go`: the shipped-recommendation assertion drops
      "seed enables the refs" (purposes now start empty) and asserts refs name seeded `catalog_models` rows +
      that apply refuses cleanly on the empty registration state.
- [x] T010 (gen) `proto/postpilot/v1/provider.proto`: carry purpose membership to the client (per-model purposes
      on `ModelInfo`, so `StageModelSelect` filters by membership instead of re-deriving from capability flags).
      `pnpm gen:proto`; adapt `backend/internal/provider/rpc/handler.go`.
- [x] T011 [P] FE config + i18n: `MODEL_PURPOSES` ordered tuple (slug + i18n label key) in
      `frontend/src/shared/config/index.ts`; tab labels, empty-state copy (incl. the video tab's
      "OpenRouter has no video-output models yet" explanation), and refusal reasons in
      `frontend/src/app/providers/i18n/resources/{ko,en}` (plan 13).
- [x] T012 FE entity (`frontend/src/entities/model-catalog`): mappers/types gain `purposes` /
      `imageOutput` / `videoOutput`; `useAdminCatalog` gains the purpose-registration mutation;
      `useModels`/`useSelections` expose per-stage (purpose-filtered) views for the pickers.
- [x] T013 FE admin (`frontend/src/features/manage-model-catalog` + `frontend/src/pages/admin/AdminModelsPage` +
      `frontend/src/app/routes`): 모델 관리 renders five purpose tabs in the `MODEL_PURPOSES` order (app-drawn
      tabs per the `/voice` routed-tab or segmented pattern — no native select); each tab applies the
      capability-forced candidate filter *before* search/provider/filters, keeps the virtualized window list,
      featured ordering, 새로고침 status line, and shows the explanatory empty state; the row checkbox registers

- [x] T014 FE pickers (`frontend/src/features/select-model/ui/StageModelSelect.tsx` and its mounts — generation
