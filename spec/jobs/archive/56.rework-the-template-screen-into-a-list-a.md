## Review

- [x] `/code-review` applied (rejections noted with reason) · for non-trivial logic, `/codex:review --background`

Both reviews ran (`/code-review` at `high`, and Codex `gpt-5.5` on the same diff) and converged on
the same root cause: **the draft's clean baseline came from the directory query, which lags a save
by a refetch.** Six findings applied, one rejected with reason.

| Finding | Fix |
|---|---|
| **The screen stayed dirty after its own save.** The baseline was `stored`, so until `ListTemplates` refetched, 저장 re-enabled and the leave guard warned about a template that had just been written. On the create path it was worse: the guard intercepted the screen's OWN post-save redirect, and cancelling stranded the user on `/templates/new`, where saving again produced `TEMPLATE_NAME_TAKEN`. | A `savedBaseline` taken from the mutation's own response, plus a `leavingAfterSave` **ref** — the redirect runs in the same tick as the state update, and the blocker reads its render-time closure, so state alone could not have fixed it. Two tests pin both paths. |
| After the create's redirect the new id was not in the directory yet, so the screen flashed "이 템플릿을 찾을 수 없어요". | Not-found renders only once the query is settled AND not fetching; the loading state covers the refetch window. |
| `useBlocker` omitted `enableBeforeUnload`, which defaults to `true` and does **not** consult `shouldBlockFn` — so the browser prompted on reloading a clean screen. | `enableBeforeUnload` is now the same guard function. A tab close warns only when something is unsaved, which is also better than the "not guarded at all" the first comment claimed. |
| The body was trimmed for both the dirty check and the write, so a stored body with significant outer bytes opened as dirty and was silently rewritten — a direct **A11** violation. | The body is compared and sent verbatim; only the name and description are trimmed. Test: a stored `'\n인트로\n'` is not dirty on open and survives a save of another field. |
| **Deleting the aimed row left `aimedAt` holding a dead id**, so no insertion marker rendered anywhere while the toolbar silently aimed at the end — exactly the failure a single toolbar cannot afford (**A7**). | The aim is resolved against the live blocks every render; an unresolvable aim IS the end position, and the end marker renders. Test included. |
| `density="compact"` used `items-center`, so a repeat row's grip and move buttons floated down level with its children's identical controls. | `items-start` in both densities, with the compact controls centring inside the row's own 44px first line. |
| *(pre-existing, fixed in passing)* `SortableList`'s drag handle was labelled `moveUp`, so its tooltip read "위로". | A `builder.block.drag` key in both locales. |

**Found and fixed while writing the tests, before either review:** `SortableList` did not stop
drag events propagating, so a nested list's drag also started one in its parent — dragging a
repeat's child moved the entire repeat. The old editor nested these lists too, so this was
pre-existing; it now has a regression test.

### Rejected

- Codex: *"adding an empty block does not mark the page dirty, so navigating away loses the row
  with no warning."* True, and **intended**. An incomplete block contributes no bytes by design
  (an empty `<write></write>` does not parse), so what would be lost is a row with nothing in it.
  Warning about it would train the user to dismiss the guard that protects real work. The moment
  anything is typed, the body changes and the guard applies.

### As built — deviations from the checklist

- **T004's flat rendering did not survive contact.** The plan was one flat list of rows; the
  editor renders a repeat's children as a **nested** `SortableList` instead, because a single flat
  list would let a drag carry a block out of its repeat — which the grammar cannot express (A8).
  `outline()` remains as the addressing projection `positionAfter` is built on.
- **`SortableList` gained a `density` prop** (`shared/ui`). Its `comfortable` rows stack the two
  move buttons, which made every collapsed row 88px — a list that could not read as an outline.
  Adding the variant to the primitive was the §1.1-correct move; hand-rolling drag in the slice
  was not.
- **The delete moved into the expanded panel.** A destructive control on every collapsed row took
  the width the one-line summary needs at 360px.
- **Two sticky elements share the page scroller**: the add toolbar (`top`) and the save dock
  (`bottom`). §4.3's "one docked bar per scroller" is about two bars pinning to the *same* offset
  and painting over each other; these pin to opposite edges and never meet.
