## Review

- [x] `/code-review` applied (rejections noted with reason) · for non-trivial logic, `/codex:review --background`

**Applied (4).**
- Codex, high: an expired presigned read was going to be classified `blocked`, not `unreadable`. R2 answers it with
  a 403 carrying no CORS headers, so the browser withholds it and `fetch` rejects exactly as for a missing `GET`
  allow — the response cannot separate the two. Verified against Cloudflare's *R2 → CORS → Use CORS with a presigned
  URL*, then re-based the split on the lifetime SigV4 states in the URL query. Without this the change would have
  traded one dead-end message for another.
- Both reviews: the deploy gate probed `R2_ENDPOINT`, but presigned URLs are signed against `R2_PUBLIC_ENDPOINT`
  when set — a split-network stack would have gone green with its browser-facing host unchecked. Now mirrors
  `storage.New`'s precedence.
- `/code-review`: the exact-origin ACAO grep failed a bucket whose rule allows `*`. Now accepts either, and both
  assertions print why they failed plus the response headers instead of exiting on a silent `grep`.
- `/code-review`: DEPLOY.md §5 cited §2 for the new gate while §2 still described only the API CORS check. §2's
  pipeline block and its rationale now carry both.

**Rejected (2).**
- `/code-review`: decode/encode failures still map to `unreadable`, whose message promises a remint that cannot fix
  a dead canvas. True, but a fifth kind for an unreachable-in-practice case is a new change, and change 23 records
  this mapping as a deliberate scope decision.
- Codex, low: `deploy/r2-cors.json` ships an unusable placeholder origin. Intentional — an obviously invalid
  `https://postpilot.<domain>` fails loudly if applied unedited, where a plausible `example.com` would install a
  silently wrong rule. DEPLOY.md §5 says to replace it, and the deploy gate catches a bucket that never got a real
  origin.
