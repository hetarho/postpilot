## Review

- [x] `/code-review` (two rounds, `high`) and codex (`gpt-5.5`, two rounds) — every finding applied, none rejected.
  - Round 1 (6 + 4 findings) all pointed at the same root: the save state lived in the component. Fixed by moving it
    into a per-post queue (T004). Individually: the unmount flush could never be retried; typing during an outage
    restarted the debounce and defeated the backoff; reverting the text stranded the status; a 200 with no post was
    taken as a create; `liveRef` was never reset, so React StrictMode disabled retries in dev; a passive effect could
    be deferred past `pagehide` and lose the last keystroke (now a layout effect).
  - Round 2 on the new queue found four more, all applied: **a queue outliving a logout would save one account's
    draft into the next account** (`discardDraftQueues()`, proven by a test that fails without it); an undo made
    while a save was in flight was compared against the pre-save text and never sent; every `/posts/new` editor
    shared one queue key, so a second draft could erase the first; and keying the attach on the `post` object rebuilt
    the queue on every save, since each save reseeds the cache with a new `updated_at`.
  - `pagehide` still uses a normal request — `keepalive` is not reachable through the Connect transport and
    `sendBeacon` cannot carry the JSON content type cross-origin. Recorded as a known bound in
    [spec/tech/draft-autosave.md](../tech/draft-autosave.md); the mitigation is the added
    `visibilitychange`(hidden) flush plus the short debounce.
  - **Out of scope, not fixed, worth their own job:** round 2 also reported four backend issues in job 03's code —
    a TOCTOU between `ImageKeyInUse` and `blobs.Delete` in `internal/post/sweep.go` (a late `ConfirmUpload` can leave
    an images row whose object the sweep then deletes); the sweeper skipping its boot pass with a 24 h interval, so
    deploy-on-merge means it effectively never runs; a blank-filename guard surfacing as `CodeInternal`; and
    `SaveDraft` re-reading the post and re-minting a presigned GET per photo on a ~1 req/s endpoint.
