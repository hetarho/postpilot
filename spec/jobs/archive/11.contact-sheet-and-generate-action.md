## Acceptance Criteria (from plan/06.two-stage-generation-and-contact-sheet)

<!-- Plan 06 criteria owned by this job (plan AC numbers in parentheses). -->

- [x] A1 (plan AC3, UI half) The contact sheet shows each photo's persisted observation (`scene`, `mood`, `visible_text`, `objects`) under its thumbnail, keyed by filename.
- [x] A2 (plan AC9) Closing and reopening the browser mid-generation shows the in-flight progress and, on completion, the rendered draft and the `review` status.
- [x] A3 (plan AC10) Thumbnails load via the presigned GET `view_url` from `GetPost` and from nowhere else; the R2 object is not readable without one.
- [x] A4 (plan AC12, UI half) The generate button is disabled with an inline message when the write model is missing, or when photos are attached and the observe model is missing or not vision-capable; it is also disabled while a job is active on the post.
- [x] A5 (derived) `BlockList` renders every `BlockType` — TEXT paragraph, HEADING h2/h3, IMAGE thumbnail by filename with caption, QUOTE, LIST — plus title, summary and tags.
- [x] A6 (derived) During `observe`, photos already observed show their text and the rest show "관찰 대기"; the strip refreshes on each poll because observations are persisted per batch.
- [x] A7 (derived) The empty-profile banner (job 09) is visible but does not block generation.
- [x] A8 (derived) A 0-photo post can be generated with only the write model selected; the observe select is shown as not required.
