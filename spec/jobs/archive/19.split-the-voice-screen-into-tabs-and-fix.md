## Implementation Checklist

<!-- How to build it, top to bottom. [P] = parallel (different files, no dependency). Flag (gen)/(migrate).

**Config: none.** This delta introduces no tunable value. The analysis prompt and the JSON schema are code
(ARCHITECTURE §4); `DiffMinPatternEdits`, `RuleActivationEvidence`, and `ValidationPostCount` already live in
`backend/internal/platform/config` and are not touched. No migration: profile snapshots are JSON blobs in an
existing column and old rows stay byte-valid (an absent pointer field decodes from a stored `0` as present-0).

### Gate 1 — Axis presence through the contract (A10, A11)

- [x] T001 (gen) `proto/postpilot/v1/voice.proto`: make the six `VoiceAxes` fields `optional int32` so the wire
      carries presence. Field numbers are unchanged, so this is binary-compatible. Run `pnpm gen:proto` and commit
      both generated trees.
- [x] T002 `backend/internal/voice/types.go`: `AxesProfile` fields become `*int`. `encodeProfile`/`decodeProfile` are
      untouched — `json.Marshal` on a nil pointer writes `null`, and an existing snapshot's explicit `0` still
      decodes as present-0, which is what keeps historical versions showing what they published.
- [x] T003 `backend/internal/voice/learning.go`: `qualitativeAxesJSON` fields become `*int` so a key the model did
      not answer stays nil instead of decoding to 0. `validateAxes` skips nil and still rejects a present value
      outside `-3..3`.
- [x] T004 `backend/internal/voice/learning.go`: rewrite `structuredAnalysisPrompt` to name the `axes` object and all
      six keys (`involvement`, `narrativity`, `persuasion_overtness`, `abstractness`, `addressee_focus`, `humor`)
      the same way it already names the eight string keys. This asymmetry is the root cause; the prompt is the only
      channel a model without `structured_output` has.
- [x] T005 `backend/internal/voice/schemas.go` + `schemas/voice_analysis.schema.json`: embed a schema for the whole
      `qualitativeJSON` response — the eight string fields plus a required `axes` object with the six integer keys
      bounded to `-3..3`. Mirror `generation/schemas.go`'s `//go:embed` + defensive-copy accessor exactly.
- [x] T006 `backend/internal/voice/ports.go` + `backend/cmd/api/main.go`: add `Resolve(ref llm.ModelRef)
      (llm.ModelInfo, bool)` to the `Models` port and implement it on `voiceModels` by delegating to
      `registry.Lookup`. The voice port does not have it today; `generation/ports.go` already declares the same
      method, so this is the established shape, not a new one.
- [x] T007 `backend/internal/voice/learning.go`: attach the schema on the `learn_voice` completion call when
      `s.models.Resolve(ref)` reports `StructuredOutput`, exactly as `generation/write.go:29` does. A model without
      the capability keeps the prompt-only path — do not fail it.
- [x] T008 `backend/internal/voice/profile.go`: `applyOverride`'s `LayerAxes` branch assigns through the pointer, so
      a manual axis override marks the axis present.
- [x] T009 `backend/internal/voice/retrieval.go:106`: the `[Axes]` line must not print `involvement=0` for an axis
      that was never measured — an unknown axis renders as `unknown`, or is omitted. Printing a fabricated 0 into
      the generation prompt is the same bug one layer down.
- [x] T010 `backend/internal/voice/rpc/handler.go`: map `*int` → the optional proto field in `toProto…`, and read
      presence back in the override direction.
- [x] T011 [P] `frontend/src/entities/voice-profile`: `axes` becomes presence-carrying in `model/types.ts`, and
      `api/voice-queries.ts:18` stops collapsing absence with `?? 0`. `emptyStructuredVoiceProfile()` returns all six
      as absent, not as 0.
