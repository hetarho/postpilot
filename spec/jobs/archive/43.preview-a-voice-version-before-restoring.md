### A. The per-version generation snapshot

- [x] T001 (migrate) The new migration's FIRST half: `voice_version_samples` —
      `(voice_id, version)` as the primary key so one version holds **at most one** snapshot and a
      later generation REPLACES it; a `content` text column; a `created_at`.
      `FOREIGN KEY (voice_id, user_id) REFERENCES voices(id, user_id)` and a `user_id` column
      following the shape 0016 gave `voice_profile_versions`, so a soft-deleted voice's samples go
      with the voice and no cross-voice or cross-account read is expressible ([I4]).
      Follow the 0016 precedent, not `ALTER TABLE`: table creation inside goose's transaction,
      leaving `PRAGMA foreign_keys` alone. Write the `Down` half.
- [x] T002 `internal/voice` domain — a `VersionSample` type and the service method that records one:
      it resolves the voice's CURRENT head version and upserts the sample against it. The snapshot's
      content is stored and returned as **opaque text the voice domain never parses** — voice does
      not learn the post's content shape (ARCHITECTURE §2, the anti-corruption boundary).
      Recording is idempotent per `(voice_id, version)`. A voice with no published version yet
      records nothing rather than inventing version 0.
- [x] T003 `internal/voice/ports.go` + `store` + `store/queries/voice.sql` + (gen) `pnpm gen:sql` —
      the upsert, the per-version read, and a presence read for the list.
- [x] T004 `internal/generation/ports.go` — a NEW consumer-declared port beside `Profiles` and
      `RuleWriter`, e.g. `VersionSampleWriter.RecordVersionSample(ctx, userID, voiceID, content)`.
      **Direction matters:** the machine baseline is written by `post.Service.SetGeneratedContent`,
      and `post` must stay unaware of voice profiles. `generation` already depends on both, so it is
      the only context that may join them. Call it from the three places that write a baseline —
      `generate_handler.go:70`, `revise_handler.go:78`, `experiment_surface.go:176` — AFTER the
      baseline write succeeds. A failure to record a snapshot must NOT fail the generation: the post
      is the product, the snapshot is a record of it.
- [x] T005 `backend/cmd/api/main.go` — wire the new port to the voice service in the composition
      root, adapting types at the boundary the way the existing `Profiles` adapter does.

      `VoiceProfileVersion` (line ~139) gains a presence flag so a row can say whether a preview
      exists **without** the list carrying every post body; a new
      `GetVoiceProfileVersionSample` RPC returns the one version's snapshot on open. Type the
      snapshot as `post.proto`'s existing `PostContent` (import it — the snapshot *is* a post
      content, and the FE already decodes that message) while the voice domain keeps treating the
      stored value as opaque text.
- [x] T007 `internal/voice/rpc/handler.go` — the new RPC: ownership-checked against the owned voice,
      returns absent for a version with no sample, and refuses another account's voice.

      one version's sample with its own query key.

- **T013 — `ApplyStyleguideWinner` measures rather than clones.** The first attempt replaced only the lexical
  description on the current head, which carried that head's measurements onto a version the winner never described
  and published a v1 with every metric unset for a voice with no head. It now mirrors `analyze_handler` exactly:

- **T002 — the snapshot's version is the head AT COMPLETION**, which is what A1 asks for and is not the same thing
  as the version the prompt was built from. A profile published during the provider call moves the head and the run's
  output is filed under the newer version; the window is one provider call. Closing it would mean freezing the
  profile version into the generation payload and carrying it back out through the write path — a contract this
  change did not open. Both review passes raised it; the criterion's own wording settles it, and the code says so.
- **T006 — the snapshot's wire format is `PostContent`'s own protojson.** The alternative was a second JSON shape
  maintained independently at the two ends (the composition root and the voice RPC edge), which would drift the
  moment the block message gains a field. Encoding happens in `cmd/api` (the only place that sees both contexts) and
  decoding at `internal/voice/rpc`; `internal/voice` itself never parses the value, which is the anti-corruption
  boundary the job asked for. A snapshot that cannot be decoded is reported as "no preview" and LOGGED, since the
  list said the version had one.
- **`VoiceProfile.legacy_manual_guidance` (field 7) was removed too**, beyond T015's list. It was derived purely
  from `styleguide` + `rules`, so it would have become permanently empty — dead contract. Its number is reserved.
- **T009 — the preview does not trust a cached `has_sample`.** A generation records a snapshot without invalidating
  the version-list query, so the flag can be stale; the per-version snapshot query runs whenever a row is opened and
  the RESPONSE decides whether a preview exists. `has_sample` stays a hint that keeps the closed list free of RPCs.
- **T009 — a snapshot is read as text, not re-rendered as an article.** `BlockList` resolves image blocks against
  the post's `images` rows, and a snapshot has file references with no rows behind them, so mounting it would render
  broken images and a heading that competes with the page outline. The preview shows the title plus the block bodies
  joined, bounded by `VOICE_VERSION_PREVIEW_CHARS`.
- **T022 — the sentence picker is a `radiogroup`, not a set of toggles.** It replaced a `Listbox` (a combobox), so
  select-one semantics and the single tab stop had to survive the shape change: only the chosen row is tabbable and
  the arrows move between rows, with focus following selection. Sentences are also DEDUPLICATED now that the source
  is the whole finalized post, so a repeated sentence is one row rather than two identical choices.
- **T020 — `sentenceSource` mirrors the server's own body projection.** `parseAuthoredContent` takes
  TEXT/HEADING/QUOTE content and LIST items; a projection that read only `block.content` would make the control
  vanish on a list-only post and could offer a sentence the server cannot find.
