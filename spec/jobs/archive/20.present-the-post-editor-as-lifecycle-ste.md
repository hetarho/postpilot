## Implementation Checklist

<!-- How to build it, top to bottom. [P] = parallel (different files, no dependency). Flag (gen)/(migrate).
     Config values are never magic literals — FE via shared/config, BE via internal/platform/config. -->

**Frontend only.** No proto change, no migration, no new RPC, no config value. Nothing under `backend/` is touched.

**Two primitives already exist — use them, do not build a third.** The step bar is `SegmentedControl`: its own
doc-comment calls it "the primitive for a bounded switch or a **tab row**", it already carries `role="tablist"`,
arrow-key roving focus, a `controls` prop for the panel id, and horizontal scrolling. The read-first shape is
`Editable`, created by job 19. Adding a new stepper control here would be the §1.1 bug this job exists to avoid.

### Gate 1 — Derive the step from the post's status (A1, A4, A5, A6)

- [x] T001 `frontend/src/pages/editor/model/steps.ts` (new): the pure mapping — the three step ids with their Korean
      labels (글 생성 · 글 다듬기 · 글 완성) and `stepForStatus(status)` (`draft`→①, `review`→②, `finalized`→③, and a
      defined fallback for a status a later plan adds). Pure and unit-testable; no React.
- [x] T002 `frontend/src/pages/editor/ui/DraftEditor.tsx`: hold the selected step in state seeded from
      `stepForStatus(post.status)`. **A status transition moves the step; a manual selection holds until the next
      transition.** This is what makes generation completing carry the user into 글 다듬기 instead of leaving them
      on the screen they just finished with — track the last status the step followed so a re-render cannot undo a
      deliberate selection.
- [x] T003 Render the step bar with `SegmentedControl` (`ariaLabel`, `controls` pointing at the panel's id) and give
      the panel `role="tabpanel"` with that id. No new primitive.
- [x] T004 `/posts/new` (no `post`) renders step ①'s content with **no** step bar — there is no lifecycle yet. Keep
      the existing `EditorDock saveState` branch for that state untouched.
- [x] T005 Every step is selectable regardless of status (A4). A step whose work has not happened yet renders an
      empty state that says what it is waiting for and offers the way to the step that produces it — never a
      disabled tab. Selecting a step must not mutate `post.status`, enqueue a job, or make a provider call.

### Gate 2 — Split the column into step panels (A2, A3, A11)

- [x] T006 `DraftEditor` keeps title, memo, and the mint/caret plumbing **outside** the panels — they are the post's
      identity, not a step. Do not move `useAutosave`, `peekPendingDraft`, `stashCaret`, or the `onMinted`
      navigation; A6 exists because moving them would strand a queued save.
- [x] T007 Step ① panel: `EditorPhotos`, `EditorVoiceWarning`, the two `StageModelSelect`s, the A/B link, the
      pending-experiment link, and `ContactSheet`. This is where `GenerationSection`'s current head moves.
- [x] T008 Step ② panel: the block editing surface and `ReviseForm`, with `SentenceFeedback` still supplied through
      `BlockEditor`'s existing `renderSentenceAction` prop. With no content yet, the T005 empty state.
- [x] T009 Step ③ panel: `FinalizePost` and `ExportPanel`. Export stays reachable while the post is still `review`
      (A4 makes step ③ selectable), and it still only derives copy-ready output — never publishes ([I1]).
- [x] T010 `EditorDock` renders per step: save state always; `GenerationActions` and the job progress/failure/success
      block only on ①; the finalize action only on ③; step ② docks the save state and revision control. Keep it the
      LAST child of `main` — a `sticky bottom` box is only pinned while its containing block extends below it, which
      is why it is placed there today. Never two committing actions in the bar at once (A11).
- [x] T011 The `job.status === 'done'` announcement and the `scrollIntoView` handoff currently jump the user to the
      result a screen and a half down. With steps that jump becomes the step move from T002 — reconcile the two so
      the user is taken to 글 다듬기 once, not scrolled inside ① and then moved.

- [x] T015 Generated title, summary, and tags follow the same read-first rule through `Editable`. `BlockList`'s

- **Deliberate deviation from T010.** T010's "step ② docks … the revision control" conflicts with T008 ("step ②

  step ② and forbid a second committing action in the bar. `ReviseForm` is a form, not a single action, so it stays
  in the panel and the dock carries the save state alone on step ②.
- **Deliberate widening of T010's dock rule.** A running or failed job is reported on *every* step, not only its
  own: a failure the user cannot see is precisely the bug the dock exists to prevent. Only the retry is scoped to
  the owning step, because that is where the control it calls is mounted.

## Review

- [x] `/code-review` applied (rejections noted with reason) · for non-trivial logic, `/codex:review --background`

`/code-review` and a read-only Codex pass (gpt-5.5) ran in parallel; four findings inside this job's blast radius
were applied, each with a regression test:

- **`beforeFinalize` was permanently null.** The block editor renders on 글 다듬기 and 확정 on 글 완성, so the ref
  finalize used to flush the content through no longer exists — 확정 would have taken the fallback revision and
  finalized content that omitted the user's last edit while reporting success. The content queue is keyed by slug
  and outlives the editor, so `flushContentQueue(slug)` now waits on it and returns its revision.
- **취소 after moving a block wrote the snapshot into another block's slot** ([A,B,C], open B, ↑, 취소 → [B,B,C]).
  Moving now closes the editor, as deleting already did.
- **The header editor snapshotted the whole `PostContent`,** so 취소 reverted block edits made while it was open.
  It now snapshots and restores only the title, summary and tags it owns.
- **Export could freeze on stale content** (Codex): a revision completing while the user sat on 글 완성 left
  `liveContent` holding the pre-revision draft. The edited content is now tagged with the revision it was edited
  from and expires when the server's revision moves past it.

Left alone as out of scope: `entities/model-catalog/api/useModelSetup.ts`'s pair-save pending window belongs to the
write-comparison job running in another session.
