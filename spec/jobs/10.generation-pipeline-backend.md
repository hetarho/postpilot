>
> **Split:** plan 06 is built as two jobs. This is the backend: the `Block` / `PostContent` contract ([I2]), the
> `generation` context (observe → write, batching, matching, the single validation function, the attachment filter,
> the fallback parser), `StartGeneration`, and the `generate` job handler. The contact sheet, reading view and generate

## Acceptance Criteria (from plan/06.two-stage-generation-and-contact-sheet)

<!-- Plan 06 criteria owned by this job (plan AC numbers in parentheses). AC 9, 10 and the UI half of 3 belong to job 11. -->

- [ ] A1 (plan AC1) Generating a post with 0 photos succeeds: no observation call is made, the write stage runs from the memo alone, and a `PostContent` with blocks is persisted.
- [ ] A2 (plan AC2) The persisted content contains no IMAGE block whose `file` is not an attached filename — a model output that references `IMG_999.jpg` is filtered and logged (unit test with a crafted payload).
- [ ] A3 (plan AC3, server half) Observation precedes writing; after the job `posts.observations` holds one entry per attached photo keyed by filename, and entries are persisted incrementally per batch (visible through `GetPost` mid-job).
- [ ] A4 (plan AC4) With N photos and `OBSERVE_BATCH_SIZE = 4`, the handler makes `ceil(N/4)` observation calls and progress advances by batch (stubbed provider test).
- [ ] A5 (plan AC5) A model output with a bad field combination (`TEXT` with `items`) or unknown type drops exactly that block, logs it, and persists the rest (unit test).
- [ ] A6 (plan AC6) The write prompt contains the voice profile in the order styleguide → excerpts → rules, with rules after all excerpts and before the per-post material (snapshot test on prompt assembly).
- [ ] A7 (plan AC7) The write prompt includes the one-paragraph-per-TEXT-block rule, the exact attached filenames, and the no-invented-images rule (prompt snapshot).
- [ ] A8 (plan AC8) When the write model declares `structured_output`, the request carries the `PostContent` JSON schema; when it does not, a fenced ```` ```json ```` response is parsed successfully and an unparseable response fails the job with an error that begins with the fixed Korean prefix and includes the raw head.
- [ ] A9 (plan AC11) Observation results naming files that are not attached are discarded and photos without a result get an empty observation — the observation count always equals the photo count.
- [ ] A10 (plan AC12) `StartGeneration` without a write model, or with photos attached and a non-vision observe model, is refused before any job is created.
- [ ] A11 (derived) A successful generation replaces `posts.content` wholesale and sets `status = review`; `StartGeneration` returns a `job_id` before any provider call (plan 05 AC1, now verifiable).
- [ ] A12 (derived) `BlockType` values serialize in protojson as `TEXT`, `HEADING`, `IMAGE`, `QUOTE`, `LIST` (the names the model emits, PRD §3.2).
