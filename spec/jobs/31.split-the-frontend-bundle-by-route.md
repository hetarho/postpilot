# Job 31: Split the frontend bundle by route (refactor)

> Implementation work doc. Source spec: [code-review/01.full-repo-audit-after-twelve-plans](../code-review/01.full-repo-audit-after-twelve-plans.md).
> /implement-job 31 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/tech) and set status: done. Write it in English.

Finding covered: **R011** — the eager bundle is 731.42 kB (gzip 216.67 kB) and every one of the eleven screens loads
on first paint, on a product whose design language was deliberately reworked to be mobile-first.

## Acceptance Criteria (from code-review/01)

- [ ] A1 The measured baseline is recorded in this job before any change: `731.42 kB` raw / `216.67 kB` gzip for
      `dist/assets/index-*.js`, and the after-figures are recorded beside it. A split with no measurement is not a
      finished job.
- [ ] A2 The screens outside the editor/posts core no longer appear in the entry chunk. Verified by inspecting the
      build output's chunk list, not by assuming the import removal worked.
- [ ] A3 Navigating to every lazily-loaded route still renders it, including a direct page load (deep link) and a
      browser refresh on that route — a lazy route that only works via in-app navigation is broken.
- [ ] A4 `beforeLoad` guards and loaders still run in the same order relative to rendering. The authenticated
      layout's session guard and the voice loader must not be deferred into the lazy chunk.
- [ ] A5 `frontend/src/app/routes/router.test.tsx` still mounts the real `routeTree` and passes. If lazy components
      require the test to await a chunk, the test is updated to await it — not to stop mounting the real tree.
- [ ] A6 `build.chunkSizeWarningLimit` is set to a number this job chose deliberately, and the build emits **no**
      standing size warning. Either the chunks are under the default or the limit states the accepted size.
- [ ] A7 No behavior change: `pnpm --filter ./frontend test` and the full FE gate pass, and no route's URL,
      guard behavior or data loading changes.

## Implementation Checklist

- [ ] T001 Record the baseline (A1): run `pnpm build:web` and copy the chunk table into this job. Note that
      `heif-worker-*.js` (1,459 kB) is **already** correctly split and lazily fetched — `shared/lib/image/heif.ts:20`
      constructs the worker only when the first HEIC is selected. It is the proof the pattern is understood here,
      and it must stay as it is.
- [ ] T002 Decide the core, and write the reason down. Proposed: `LoginPage`, the authenticated layout, `PostsPage`,
      `NewDraftPage` and `PostEditorPage` stay eager — a session's first paint is the post list or the editor, and
      making either wait on a chunk trades a real cost for the saving. Everything else is a candidate:
      `PublishingAgentsPage`, `VoicesPage`, `PurposesPage`, the five voice tabs behind `VoiceLayout`,
      `AIModelsPage`, `ModelExperimentPage`, `VoiceRuleComparisonPage`, `VoiceValidationPage`.
- [ ] T003 `frontend/src/app/routes/router.tsx` — convert the chosen routes with TanStack Router's
      `lazyRouteComponent(() => import('@/pages/…'), 'ExportName')`, replacing the static `component:` and its
      top-of-file import. The pages are **named** exports (`import { AIModelsPage } from '@/pages/ai-models'`), so
      pass the export name as the second argument; the default-export form will silently render nothing.
- [ ] T004 Keep every `beforeLoad`, `loader` and `context` exactly where it is (A4). Only the `component` moves into
      the lazy boundary — the session guard on `authenticatedRoute` and the voice loader must keep running before
      the chunk is requested, or a signed-out user fetches a screen's code before being redirected.
- [ ] T005 The five voice tabs share `VoiceLayout` and are always reached together. Decide whether they are five
      chunks or one, and say which and why — five chunks for one screen's tabs is a worse trade than a single
      voice-area chunk. Whatever is chosen, `VoiceLayout` itself follows the tabs.
- [ ] T006 Check what a lazy route shows while its chunk loads. TanStack Router renders the nearest `pendingComponent`
      (or nothing). A blank frame on a slow phone connection is a regression against R011's own motivation — if the
      app has no pending state for this, either add a minimal one consistent with
      [tech/design-language](../tech/design-language.md) or note explicitly that the chunks are small enough not to
      need one, with the measurement to back it.
- [ ] T007 `frontend/src/app/routes/router.test.tsx` — the tree is exported specifically so a test can mount it
      against a fake transport. Update it to await the lazy boundaries rather than narrowing what it mounts (A5).
- [ ] T008 Re-run `pnpm build:web` and record the after-figures next to T001's baseline (A1, A2). Confirm the entry
      chunk shrank and that the new chunks correspond to the screens in T002 — a split that merely renamed chunks is
      not a split.
- [ ] T009 `frontend/vite.config.ts` — set `build.chunkSizeWarningLimit` to the number chosen in T008 (A6). This is
      the step that closes the finding: the build must stop carrying a warning nobody reads. If the entry chunk is
      now under the 500 kB default, leave the default and say so.
- [ ] T010 Walk every lazily-loaded route in a running app (`pnpm dev:web`), including a hard refresh on each deep
      link (A3). Route-level lazy loading is exactly the change whose failure mode does not appear in unit tests.
- [ ] T011 Verify the full FE gate: `pnpm --filter ./frontend test`, `pnpm build:web`, `pnpm lint`,
      `pnpm --filter ./frontend lint:fsd`, `pnpm lint:style` (A7).

## Grounding

- Constitution ([I1]–[I7]): [00.overview](../plan/00.overview.md) §3. **[I6]** is the one to protect: image work
  stays in the browser, and the already-lazy `heif-worker` chunk is part of how that is delivered — this job must
  not disturb it.
- Architecture (placement): [ARCHITECTURE.md](../ARCHITECTURE.md) §3.2 — `app/routes/` is where the router lives and
  the only place this job edits in the FSD tree. No page moves layer, no slice changes its public surface: the
  change is *how* `app` imports pages, not *what* it imports. §1 also constrains the outcome — the frontend stays
  purely static (PRD §3.1), so this is code splitting, never SSR or a server-rendered route. Invoke
  `/fe-architecture` before editing.
- PRD / policy / tech touched: [PRD.md](../../PRD.md) §6.2 (browser image pipeline — the chunk that must stay lazy)
  and [tech/design-language](../tech/design-language.md) (T006's pending state, and the mobile-first commitment that
  motivates the whole job).

## Affected files (blast radius)

| Path | FE layer / slice / segment | What changes |
|---|---|---|
| `frontend/src/app/routes/router.tsx` | app / routes | static page imports → `lazyRouteComponent` for the non-core routes (T003–T005) |
| `frontend/src/app/routes/router.test.tsx` | app / routes | awaits the lazy boundaries (T007) |
| `frontend/vite.config.ts` | build config | `build.chunkSizeWarningLimit` set deliberately (T009) |
| possibly one small pending component | shared / ui or app / routes | only if T006 concludes one is needed |

Deliberately **not** touched: every page component's own code (this job changes how they are *loaded*, never what
they do), `shared/lib/image/heif.ts` and its worker chunk (already correctly split), all `beforeLoad`/`loader`
logic, and every route path — no URL changes, so no link anywhere in the app or in the specs breaks.
