## Acceptance Criteria (from plan/01.accounts-and-login)

<!-- Plan 01 criteria owned by this job (plan AC numbers in parentheses); the rest are job 01's. -->

- [ ] A1 (plan AC4, browser half) In browser devtools, `document.cookie` never contains `pp_session`; the session cookie is sent on every RPC as a `Cookie` header (network tab) and no `Authorization` header is used.
- [ ] A2 (plan AC9) An unauthenticated visit to any route redirects to `/login`; after login the originally requested route loads.
- [ ] A3 (derived) The Connect transport is created with `credentials: 'include'`; without it the same call is rejected with 401 (asserted by a unit test on the transport options).
- [ ] A4 (derived) A 401 on any RPC other than `Login` clears the cached session and navigates to `/login`, from anywhere in the app.
- [ ] A5 (derived) Logout calls `AuthService.Logout`, clears the session cache, and lands on `/login`; the back button does not show authenticated content.
- [ ] A6 (derived) The login form shows one generic message for any failure ("아이디 또는 비밀번호가 맞지 않아요") and never reveals whether the id exists.
- [ ] A7 (derived) `app/` root holds only `App.tsx` and `index.ts`; the router lives in `app/routes/`, the query client in `app/providers/` (ARCHITECTURE §3.2).

## Implementation Checklist

<!-- How to build it, top to bottom. [P] = parallel (different files, no dependency). Flag (gen)/(migrate).
     Config values are never magic literals — FE via shared/config, BE via internal/platform/config. -->

- [ ] T001 Re-segment `app/` (ARCHITECTURE §3.2): move `frontend/src/app/query-client.ts` → `app/providers/query-client.ts`, `app/router.tsx` → `app/routes/router.tsx`, `app/RootLayout.tsx` → `app/routes/RootLayout.tsx`; fix imports in `app/App.tsx`. Only `App.tsx` and `index.ts` stay at the `app/` root.
- [ ] T002 `frontend/src/shared/api/transport.ts`: `createConnectTransport({ baseUrl, credentials: 'include', interceptors: [unauthenticated] })`; `shared/api/auth-events.ts`: a framework-free `onUnauthenticated(cb)` registry (shared/api is a *pure* layer — no react); the interceptor catches `ConnectError` with `Code.Unauthenticated` on any procedure except `AuthService.Login` and notifies. Export `authClient = createClient(AuthService, transport)`; `shared/api/index.ts` re-exports `AuthService` and its types.
- [ ] T003 `frontend/src/entities/session`: `model/types.ts` (`User`), `api/useSession.ts` (connect-query `useQuery(AuthService.method.getMe, {}, { retry: false })`), `api/useLogin.ts` and `api/useLogout.ts` (mutations that set / remove the `getMe` cache entry), `index.ts`. Hooks live in `api/` — `entities/*/model` may not import react (eslint boundaries).
- [ ] T004 `frontend/src/pages/login`: `ui/LoginPage.tsx` — id + password form, submit via `useLogin`, generic error text on failure, on success navigate to the validated `redirect` search param (in-app path only) or `/`; `index.ts`.
- [ ] T005 `frontend/src/app/routes/router.tsx`: a pathless `authenticated` layout route whose `beforeLoad` runs `queryClient.ensureQueryData(getMe)` and on `Unauthenticated` throws `redirect({ to: '/login', search: { redirect: location.href } })`; `/login` `beforeLoad` redirects to `/` when a session exists; the existing `/` (HomePage) moves under the guard until job 04 replaces it.
- [ ] T006 `frontend/src/app/providers/auth-redirect.ts` (wired in `App.tsx`): register `onUnauthenticated` → `queryClient.removeQueries(getMe)` + `router.navigate({ to: '/login' })`.
- [ ] T007 `frontend/src/app/routes/RootLayout.tsx`: minimal header showing the current user id and a logout button (via `entities/session`), rendered only when a session exists; routes without a session render bare.
- [ ] T008 Tests (vitest + testing-library): `LoginPage.test.tsx` (submits credentials; generic error on failure; redirect param honored), `transport.test.ts` (options include `credentials: 'include'`), `useLogout` clears the cache; a router test for the guard redirect with a mocked `getMe` rejection.
- [ ] T009 Manual: log in on the dev stack; devtools `document.cookie` is empty of `pp_session`; refresh keeps the session; open `/` in a private window → `/login?redirect=…` → login → lands on `/`.
