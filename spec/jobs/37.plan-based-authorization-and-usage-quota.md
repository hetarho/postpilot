## Acceptance Criteria (from plan/17.plan-based-authorization-and-usage-quota)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [ ] A1 Every account has a plan in `{free, basic, max, master}`; the migration backfills pre-existing accounts to `master`; `adduser` defaults to `free` and accepts `--plan`; `setplan` changes an existing account.
- [ ] A2 When an account at its daily start count (free 10 / basic 30 / max 100) starts any LLM-consuming job (generation, revision, voice analysis/learning, profile validation, A/B comparison), the server refuses with `resource_exhausted` and a `daily_count` detail carrying limit, used, and the next Asia/Seoul midnight; the job record is not created.
- [ ] A3 When an account's ledger cost for the current Asia/Seoul day ≥ its daily budget (free $0.10 / basic $0.50 / max $1.00), or for the current month ≥ its monthly budget (free $2 / basic $12 / max $25), new LLM-job admissions are refused with the matching `daily_cost` / `monthly_cost` detail; in-flight jobs are not killed (bounded overshoot).
- [ ] A4 Every server-side LLM call (success or failure with reported usage) writes one `usage_events` row with token counts, `cost_microusd`, and `cost_source` resolved reported → estimated → unavailable; A/B candidate calls appear in both the experiment table and the ledger; one A/B comparison consumes exactly one daily-count admission.
- [ ] A5 `master` accounts are never refused on any numeric axis, yet their admissions and usage events are still recorded.
- [ ] A6 A request that references a model whose `min_plan` exceeds the caller's plan — starting a job, saving a selection or comparison pair, or applying a recommendation set — is refused `permission_denied` with a `model_locked` detail naming the ref and required plan; `ListModels` marks such models `locked` for the caller, and the FE pickers show them disabled with the required plan.
- [ ] A7 A saved model selection that becomes plan-locked (downgrade) is reported to the client as missing/locked but its row is preserved, and it works again after an upgrade with no re-selection.
- [ ] A8 Every human `PublishingService` procedure refuses non-master callers with `permission_denied` (`master_only`), so a non-master account can neither pair an agent nor start/retry/cancel a publish; the FE shows no publishing UI to non-master plans.
- [ ] A9 `GetMyPlan` returns the caller's plan, all three limits (0 = unlimited), live usage, and both reset instants; the FE surfaces plan + usage in the app shell and shows axis-specific copy with the reset time when an action is refused.
- [ ] A10 `ListUsers` / `SetUserPlan` and `/admin` work for `master` and are refused `permission_denied` for every other plan; demoting the last remaining master is refused (RPC and CLI).
- [ ] A11 `providers.yaml` requires a valid `min_plan` on every model; an unknown or missing value fails boot.
- [ ] A12 `GetMe` (session probe) includes the plan, and the FE role-gates publishing/admin surfaces from it without an extra round-trip.

### Contracts

- [ ] T001 (gen) New `proto/postpilot/v1/plan.proto`: `enum Plan { PLAN_UNSPECIFIED, PLAN_FREE, PLAN_BASIC,
      PLAN_MAX, PLAN_MASTER }`; `PlanService.GetMyPlan → { Plan plan, PlanLimits limits, PlanUsage usage }`
      (`PlanLimits{ int32 daily_job_starts, int64 daily_budget_microusd, int64 monthly_budget_microusd }`,
      0 = unlimited; `PlanUsage{ int32 jobs_started_today, int64 cost_today_microusd, int64 cost_month_microusd,
      string day_resets_at, string month_resets_at }` RFC3339); `AdminService.ListUsers` (id, plan, created_at) ·
      `AdminService.SetUserPlan(user_id, plan)`. Extend `provider.proto` `ModelInfo` with `Plan min_plan` +
      `bool locked`; extend `auth.proto` `GetMeResponse` with `Plan plan`. Quota/gate refusals ride the existing
      `AppErrorDetail{reason, params}` contract (`error.proto`) with new reasons `daily_count | daily_cost |
      monthly_cost | model_locked | master_only` (params: limit, used, resets_at, model ref, required plan).
      Run `pnpm gen:proto`.

### Backend

- [ ] T002 (migrate) Migration `0013_plans_and_usage.sql` (renumber to the next free slot if taken by the time
      this lands): `ALTER TABLE users ADD COLUMN plan TEXT NOT NULL DEFAULT 'free' CHECK (plan IN
      ('free','basic','max','master'))` + one-time backfill `UPDATE users SET plan = 'master'` for pre-existing
      rows; `usage_admissions(id INTEGER PK, user_id REFERENCES users ON DELETE CASCADE, kind, job_id,
      created_at)` with index `(user_id, created_at)`; `usage_events(id INTEGER PK, user_id REFERENCES users ON
      DELETE CASCADE, kind, job_id, stage, model, prompt_tokens, completion_tokens, cost_microusd, cost_source
      CHECK IN ('reported','estimated','unavailable'), created_at)` with index `(user_id, created_at)`.
- [ ] T003 [P] New leaf domain package `backend/internal/plan`: `Plan` string type, ordered ladder
      `free < basic < max < master`, `ParsePlan`, `Allows(min Plan) bool`, and the code-owned limits table
      (free 10/$0.10/$2.00 · basic 30/$0.50/$12 · max 100/$1.00/$25 · master unlimited; budgets as micro-USD
      `int64` constants). The quota timezone `Asia/Seoul` is an unexported product-rule constant here. No
      imports besides stdlib.
- [ ] T004 [P] `backend/internal/llm/registry.go`: `modelEntry`/`ModelInfo` gain required `min_plan`
      (string, validated against the known plan names at load — unknown/missing fails boot, same posture as any
      bad registry entry; registry stays user-ignorant). Assign floors in `backend/config/providers.yaml`:
      free → `openrouter/free`, `deepseek/deepseek-v4-flash-0731`, `z-ai/glm-5.3-flash`, `qwen/qwen3.8-flash`;
      basic → `openai/gpt-5.6-luna`, `google/gemini-3.7-flash`, `deepseek/deepseek-v4-pro-0813`, `z-ai/glm-5.3`;
      max → `x-ai/grok-4.6`, `anthropic/claude-sonnet-5`, `openai/gpt-5.6-sol`, `anthropic/claude-opus-5`.
- [ ] T005 `backend/internal/auth`: `User.Plan` in `types.go`, `store/queries/auth.sql` (`GetUser` selects
      plan; `SetUserPlan`, `ListUsers`, `CountMasters` queries), plan loaded with the session and carried on
      the request context beside the user id (`context.go`); `GetMe` handler returns the plan.
- [ ] T006 `backend/internal/auth/rpc/interceptor.go`: a closed-by-default **master-only procedure set** — the
      nine human `PublishingService` procedures (`CreateAgentPairing`, `ListPublishingAgents`,
      `UpdatePublishingAgent`, `RevokePublishingAgent`, `StartPublish`, `GetPublishJob`,
      `ListRetryablePublishJobs`, `RetryPublish`, `CancelPublish`) + the two `AdminService` procedures —
      refused `permission_denied` with reason `master_only`, same pattern as `publicProcedures` /
      `agentProcedures`. The `PublishingAgentService` bearer path is untouched.
- [ ] T007 New context `backend/internal/usage`: store + queries over both tables;
      `Admit(ctx, userID, plan, kind, jobID) error` checking the three axes inside the caller's enqueue
      transaction and inserting the admission row (master skips the numeric checks but still records);
      `Record(ctx, event)`; `Summary(ctx, userID)` (today's count, today/month cost, reset instants from the
      Asia/Seoul calendar windows). Move the reported → estimated → unavailable resolver out of
      `backend/internal/experiment/cost.go` into a home both contexts share (placement per `/be-architecture`;
      `experiment` keeps its behavior through the shared resolver).
- [ ] T008 Enforce admission at the shared enqueue seam in `backend/internal/job` via a small injected
      `Admitter` port (wired in `backend/cmd/api/main.go`), so all seven LLM job kinds (`generate`, `revise`,
      `analyze_voice`, `model_experiment`, `learn_voice`, `compare_voice_rule`, `validate_voice_profile`) are
      gated in one place; a refusal surfaces as `resource_exhausted` + `AppErrorDetail` and creates no job row.
      One `model_experiment` comparison = one admission ([I3] fan-out).
- [ ] T009 Persist usage where `llm.Usage` surfaces instead of discarding it: `generation/observe.go`,
      `generation/write.go` (generate + revise), the voice analyze/learn/compare/validate handlers, and
      `experiment/handler.go` (experiments keep their candidate columns **and** write ledger rows). Failed
      calls with reported usage are recorded (job 23 already preserves them). Model-gate check at job start:
      every explicit ref in a start request must satisfy `plan.Allows(min_plan)` or the request is refused
      `permission_denied`/`model_locked`.
- [ ] T010 `backend/internal/provider/service.go` + `rpc/handler.go`: `ListModels` computes `locked` per model
      for the calling plan; `SaveSelection` / `SaveComparisonPair` / `ApplyRecommendationSet` refuse locked
      refs with `model_locked` details (apply names every offending selection); `GetSelections` reports a
      plan-locked saved row as missing/locked **without deleting it** (vanished/unsuitable rows keep today's
      delete behavior).
- [ ] T011 New RPC handlers: `PlanService.GetMyPlan` (plan from context + `plan` limits table +
      `usage.Summary`) and `AdminService.ListUsers` / `SetUserPlan` with the **last-master guard** (refuse
      demoting the only remaining master). Register both in `backend/cmd/api/main.go`.
- [ ] T012 CLI: `api adduser` gains `--plan=<free|basic|max|master>` (default `free`); new `api setplan
      <user-id> <plan>` subcommand in `backend/cmd/api/main.go` (+ `auth/provision`), enforcing the same
      last-master guard.
