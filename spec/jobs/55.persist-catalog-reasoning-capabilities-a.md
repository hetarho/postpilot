## Acceptance Criteria (from changes/27.persist-catalog-reasoning-capabilities-a)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [ ] A1 A catalog refresh persists `reasons`, `reasoning_efforts`, `reasoning_default_effort`, `reasoning_mandatory`, `reasoning_native_effort` and `reasoning_max_tokens` for every model in the response, and a model whose entry carries no `reasoning` object is recorded as not reasoning rather than skipped or failed.
- [ ] A2 For `deepseek/deepseek-v4-pro-0813` the stored list is exactly `max·high·low`, the default effort is `high`, mandatory is false, and native effort is true.
- [ ] A3 The 글 작성 tab's effort control for that model offers `max·high·low` and `unset`, and does **not** offer `medium`, `xhigh`, `minimal` or `none`.
- [ ] A4 The control for `google/gemini-3.8-flash` (mandatory) offers no `none`; the control for a model with no stored list still offers all eight values.
- [ ] A5 `unset` is labelled with the model's default effort where one is known.
- [ ] A6 `SetModelReasoning` refuses `medium` for `deepseek/deepseek-v4-pro-0813` with `ErrInvalidReasoning`, and accepts any value for a model whose list is empty.
- [ ] A7 An override that is no longer in its model's list survives a refresh unchanged, is still sent on a call, and is shown with a warning in the admin row.
- [ ] A8 A model that does not reason shows no effort control at all.
- [ ] A9 No generation path changes: an unchanged registration produces a byte-identical provider request body before and after this change.

## Implementation Checklist

<!-- How to build it, top to bottom. [P] = parallel (different files, no dependency). Flag (gen)/(migrate).
     Config values are never magic literals — FE via shared/config, BE via internal/platform/config. -->

**Contract and schema first**, then the source client, then the store, then the service, then the wire, then the
screen. Everything below is the delta only: the fetch, the pricing rules, the availability bookkeeping and the
per-purpose registration model are untouched.

- [ ] T001 (migrate) `0023_catalog_reasoning_capabilities.sql` adds six columns to `catalog_models`:
      `reasons`, `reasoning_mandatory`, `reasoning_native_effort`, `reasoning_max_tokens` (INTEGER NOT NULL
      DEFAULT 0, the table's existing boolean convention), `reasoning_efforts` (TEXT NOT NULL DEFAULT '' — the
      source's descending order is meaningful, so store the list as the source ordered it) and
      `reasoning_default_effort` (TEXT NOT NULL DEFAULT ''). Defaults make every existing row read as "unknown",
      which is what it is until the next refresh — no backfill, no boot-time fetch. Comment the file the way
      `0021` is commented: why absence is not "supports nothing".
      ⚠ `0022` is held by in-flight job 53; confirm the next free number before writing the file, and remember an
      already-applied goose migration never re-runs — a local DB that ran an earlier draft needs a fresh apply.
- [ ] T002 [P] `openrouter/client.go`: `modelDocument` gains the `reasoning` object
      (`mandatory`, `supported_efforts`, `default_effort`, `default_enabled`, `supports_max_tokens`) as a
      **pointer** so "absent" and "present and false" stay distinguishable, and the mapper fills the six fields
      beside the existing `contains(item.SupportedParameters, "structured_outputs")` line — with
      `reasoning_native_effort` from `contains(item.SupportedParameters, "reasoning_effort")`. An entry with no
      `reasoning` object maps to "does not reason"; an unknown extra key stays ignored (the doc's rule).
      `default_enabled` is read but not persisted in this job — it is display context change 27 does not scope.
- [ ] T003 `types.go`: `Model` and the browse entry gain the six fields, next to `Vision` / `StructuredOutput` /
      `ImageOutput` / `VideoOutput`. Do **not** add them to what `types.go:214` builds for `llm.SourceModel` —
      the generation path is out of scope (A9), and change 29 is what carries the native-effort signal across
      that boundary.
- [ ] T004 (gen) `store/queries/catalog_models.sql`: the six columns join the SELECT lists, the UPDATE snapshot
      and the upsert's `excluded.*` set — every place `structured_output` already appears. Then `pnpm gen:sql`,
      and map the columns in `store/store.go` at all three sites (`boolToInt` on write ×2, `== 1` on scan).
- [ ] T005 `service.go`: the candidate → row snapshot copy at the register path (beside
      `row.StructuredOutput = candidate.StructuredOutput`) and the refresh path both carry the six fields, so a
      successful fetch refreshes them exactly as it refreshes label, context and pricing. A failed fetch still
      writes nothing.
- [ ] T006 `service.go`: `SetModelReasoning`'s patch validation gains the model rule — an effort outside a
      non-empty `reasoning_efforts` is `ErrInvalidReasoning`, `none` is refused when `reasoning_mandatory` or
      when a non-empty list lacks it, and a model with an empty list keeps accepting all eight values. The
      existing enum check stays as the first gate.
- [ ] T007 `service.go`: the browse entry reports **drift** — a stored override that is no longer in its model's
      non-empty list. Derived at read time from the two fields, not stored: it must follow the catalog, and it
      must not change what `stageReasoningOf` projects onto the stage keys (A7 — the override is still sent).
- [ ] T008 (gen) `proto/postpilot/v1/model_catalog.proto`: `CatalogEntry` gains the six fields plus the drift
      flag, and `SetModelPurpose`'s `reasoning_effort` doc comment is corrected — the comment at L76–77 asserts
      `supported_parameters` "never [says] which VALUES it honors", which the `reasoning` object now does. Then
      `pnpm gen:proto` (regenerates BE, agent and FE stubs).
- [ ] T009 `rpc/handler.go`: map the new entry fields beside `StructuredOutput: e.StructuredOutput`.
- [ ] T010 [P] `entities/model-catalog`: the entry type in `model/types.ts` gains the fields;
      `api/catalog-mappers.ts` maps them with the same defensive shape as `isReasoningEffort` today.
      `REASONING_EFFORTS` stays exactly where it is and keeps its eight values — it becomes the **fallback** for
      a model with no stored list, not the whole truth. No new config value: change 27 adds none.
- [ ] T011 `features/manage-model-catalog/ui/CatalogModelRow.tsx`: the `Listbox` options come from the model's
      stored list when non-empty and from `REASONING_EFFORTS` otherwise; `none` is withheld under the T006 rule;
      the `unset` option is labelled with the model's `reasoning_default_effort` when known; the whole control is
      absent for a model that does not reason; a drifted override renders a warning naming the mismatch. Put any
      list-derivation logic in `model/catalog-view.ts` beside the existing view logic, not in the component.
- [ ] T012 [P] i18n `ko` + `en` `models.ts`: the `unset`-with-default label and the drift warning, beside the
      existing `reasoning*` keys. Korean is the product's voice; keep the existing tone.
- [ ] T013 Tests for the delta: `openrouter/client_test.go` (all six fields from a fixture, plus an entry with no
      `reasoning` object), `store_test.go` (round-trip and the refresh snapshot), `service_test.go` (T006's
      refusals and acceptances, T007's drift, and that `stageReasoningOf` is unchanged by drift), FE
      `types.test.ts` / a row test for the option filtering and the absent control. A9 is a regression assertion,
      not a new test surface: the existing `openaicompat` body tests must pass untouched.
