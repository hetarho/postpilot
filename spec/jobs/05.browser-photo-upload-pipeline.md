# Job 05: Browser Photo Upload Pipeline (new)

> Implementation work doc. Source spec: [plan/02.post-drafting-and-list](../plan/02.post-drafting-and-list.md).
> /implement-job 05 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/tech) and set status: done. Write it in English.
>
> **Split:** the browser image pipeline third of plan 02 — file filter, HEIC/HEIF WASM decode, 1024 px downscale,
> JPEG q0.85, direct PUT to R2, confirm, retry, skip list, photo strip with delete. Requires
> [job 03](03.posts-uploads-and-r2-backend.md) (upload RPCs) and [job 04](04.post-list-and-editor-autosave.md)
> (editor slot). This is where **[I6]** becomes code.

## Acceptance Criteria (from plan/02.post-drafting-and-list)

<!-- Plan 02 criteria owned by this job (plan AC numbers in parentheses). -->

- [ ] A1 (plan AC2) Selecting an executable (or any non-listed extension) stores nothing and lists the file under "건너뜀" with a reason.
- [ ] A2 (plan AC3, browser half) Eight iPhone HEIC photos all upload; each arrives in R2 as a JPEG with long edge ≤ 1024 px and appears in the editor's photo strip.
- [ ] A3 (plan AC4) A file over 25 MB at selection is skipped with a reason; a 20 MB HEIC is accepted and uploads as a ~200 KB JPEG.
- [ ] A4 (plan AC5, browser half) The PUT targets the R2 host, not `api.postpilot.*` (network tab); the API only sees `CreateUpload` / `ConfirmUpload`.
- [ ] A5 (plan AC6, browser half) Deleting a photo from the strip calls `DeleteImage` and the photo disappears from the strip and from `GetPost`.
- [ ] A6 (plan AC11, photos half) Opening a post from the list restores its photos in the strip via `view_url`.
- [ ] A7 (derived) Conversion progress is visible ("변환 중 n/m") and the UI stays responsive while eight files convert.
- [ ] A8 (derived) A failed PUT or an expired presigned URL leaves that photo in a `failed` state with a retry that restarts from `CreateUpload` with a fresh `upload_id`; other photos are unaffected.
- [ ] A9 (derived) A HEIC the device cannot decode lands on the skipped list with the reason; the rest proceed.
- [ ] A10 (derived) The WASM decoder is loaded lazily — the main bundle does not include it, and no WASM request happens unless a HEIC/HEIF file is selected.

## Implementation Checklist

<!-- How to build it, top to bottom. [P] = parallel (different files, no dependency). Flag (gen)/(migrate).
     Config values are never magic literals — FE via shared/config, BE via internal/platform/config. -->

- [ ] T001 `frontend/src/shared/config/index.ts`: `UPLOAD_MAX_FILE_MB = 25`, `UPLOAD_ALLOWED_EXTENSIONS = ['jpg','jpeg','png','webp','heic','heif']`, `IMAGE_MAX_LONG_EDGE_PX = 1024`, `IMAGE_JPEG_QUALITY = 0.85`.
- [ ] T002 `/library-setup`: pick the libheif WASM package (current, maintained, browser-targeted); wire it behind a dynamic `import()` so the WASM chunk loads only for HEIC/HEIF; record the bundle-size delta from `vite build`.
- [ ] T003 `frontend/src/shared/lib/image/`: `decode.ts` (`decodeImage(file): Promise<ImageBitmap>` — native `createImageBitmap(file, { imageOrientation: 'from-image' })` for jpg/png/webp; HEIC/HEIF → WASM → `ImageData` → bitmap; a typed `DecodeError(reason)`), `resize.ts` (`resizeToJpeg(bitmap, maxEdge, quality): Promise<{ blob, width, height }>` — canvas/OffscreenCanvas, never upscale, re-encode drops metadata), `filename.ts` (`dedupeFilename(name, taken)` → `IMG_1 (2).jpg`), `index.ts`. Pure — no react (eslint boundaries).
- [ ] T004 `frontend/src/entities/image`: `model/types.ts`, `api/useDeleteImage.ts` (mutation; invalidates the post), `ui/Thumbnail.tsx`, `index.ts`.
- [ ] T005 `frontend/src/features/upload-photos`: `model/filter.ts` (extension + size → `accepted | skipped(reason)`), `model/uploadMachine.ts` (per-file `selected → converting → uploading → confirming → done | skipped | failed(retryable)`; batch progress counters), `api/upload.ts` (`CreateUpload` → `fetch(put_url, { method: 'PUT', body: blob, headers: { 'Content-Type': 'image/jpeg' } })` → `ConfirmUpload(upload_id, width, height)`), `ui/PhotoPicker.tsx` (`<input type="file" multiple accept=".jpg,.jpeg,.png,.webp,.heic,.heif,image/*">`), `ui/UploadProgress.tsx`, `ui/SkippedList.tsx`, `ui/PhotoStrip.tsx` (thumbnails, delete, per-photo retry), `index.ts`.
- [ ] T006 `frontend/src/pages/editor/ui/EditorPage.tsx`: fill the photo slot with `PhotoPicker` + `PhotoStrip`; in `/posts/new` mode create the post (empty-slug `SavePostDraft`) before the first `CreateUpload`; invalidate `usePost` after confirm/delete.
- [ ] T007 Tests: `filter` (each allowed ext; `.exe` skipped; > 25 MB skipped with reason), `uploadMachine` with a fake api (PUT failure → `failed` + retry issues a new `CreateUpload`; confirm → `done`), `dedupeFilename`, `resizeToJpeg` dimension math with a mocked canvas (long edge 4032 → 1024, portrait/landscape, small image not upscaled), `decodeImage` routes HEIC to the lazy decoder (mocked import).
- [ ] T008 `DEPLOY.md`: confirm the R2 CORS prerequisite (job 03) lists the dev origin `http://localhost:2564` and the methods `PUT, GET, HEAD`.
- [ ] T009 Manual: eight HEIC from an iPhone on the dev stack; network tab shows PUTs to the R2 host; one `.exe` skipped; a 30 MB file skipped; delete one photo → gone from strip and R2 (HEAD 404).
