# 06. Change: Start Write Comparisons from the Model Lab

> A **change proposal** (a WHAT delta) that modifies the already-shipped behavior of [plan/09.stage-model-experiments-and-leaderboards](../plan/09.stage-model-experiments-and-leaderboards.md).
> Filled by /create-change through a user interview — a reviewable doc, not a one-line prompt.
> The STEPS live in the job that /create-change-job creates. Write it in English.

## As-is

The AI model page has stage tabs for observe, analyze, and write. Observe and analyze expose a model-lab start action,
but the write tab deliberately replaces that action with a notice directing the user to the post editor. The start
handler also returns before a write request, even though the backend already exposes `StartWriteExperiment` and the
editor already uses it for explicit A/B generation.

Consequently, users can configure and inspect the write pair and leaderboard in the model lab, but cannot start a
write comparison there. They must leave the model page, find a post in the editor, and start the same experiment from
that separate screen.

## To-be

The write tab starts the existing post-backed write experiment directly from the model lab. The user selects an
existing owned post, then presses the same `비교 시작` action used by the other model-lab stages. The client loads the
selected post before enabling the action so it can preserve the existing write-experiment contract:

- it sends the configured, distinct write A/B refs explicitly;
- when the post has photos, it also sends the explicitly active, usable observe ref; with no photos it sends no
  observe ref and causes no observation call;
- it forwards the post's persisted optional target length unchanged;
- it blocks a post with an active generation job or an unresolved write experiment and explains the blocking reason;
  and
- on success it navigates to the existing durable blind experiment route.

The experiment remains post-backed and uses the existing immutable snapshot, queue, blindness, application,
adoption, ranking, retry, and ownership behavior. Starting it from the model lab never mutates canonical content,
selects a model, applies a recommendation, or calls a provider on page load.

## Scope / Non-goals (regression boundary)

**In scope**

- Add a post selector and start action to the AI model page's write tab.
- Reuse the existing post projection, saved active observe selection, saved write comparison pair, optional target
  length, and `StartWriteExperiment` RPC.
- Show accurate loading/precondition/pending/error feedback and cover the flow with focused frontend tests.

**Non-goals**

- No new RPC, backend behavior, schema, migration, provider, dependency, or configuration value.
- No standalone free-form writing benchmark: every write comparison remains attached to an existing post so a
  selected winner can follow the shipped post application contract.
- No change to ordinary editor generation, editor-started A/B generation, observe/analyze model-lab starts,
  experiment review/application/adoption, leaderboards, or recommendation behavior.

## Acceptance Criteria

1. Selecting the `글 작성` tab shows an existing-post selector and a `비교 시작` action instead of the editor-only
   notice; observe and analyze tabs retain their current controls.
2. A write comparison cannot start until a post and two configured write candidates are available. A selected post
   is loaded before enablement, and an active job, unresolved experiment, unavailable required observe model, or
   request failure is represented with an accurate visible state.
3. Starting from a no-photo post sends its slug, the exact configured write A/B refs, no observe ref, and the post's
   optional target length to `StartWriteExperiment`, then navigates to the returned blind experiment.
4. Starting from a post with photos additionally requires and sends the account's explicit active vision-capable
   observe ref; the page never infers or silently saves any model selection.
5. Mounting or switching tabs starts no experiment or provider work. The existing editor write-comparison path,
   ordinary generation, observe/analyze starts, blind review, winner application/adoption, ranking, and post
   canonical-content behavior do not regress.
6. Focused frontend tests plus lint, FSD/style gates, and the production frontend build pass without a backend or
   generated-contract change.
