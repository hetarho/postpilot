# 16. Change: Preview A Voice Version Before Restoring It And Retire Legacy Manual Guidance

> A **change proposal** (a WHAT delta) that modifies the already-shipped behavior of [plan/03.voice-profile-learning](../../plan/03.voice-profile-learning.md).
> Filled by /create-change through a user interview — a reviewable doc, not a one-line prompt.
> The STEPS live in the job that /create-change-job creates. Write it in English.

## As-is

### A version is a number you cannot read

말투 → 버전 lists every published profile head as one row: `v3 · 분석`, optionally
`(v1에서 복원)`, with a 복원 button that opens a confirmation dialog and publishes that snapshot as a new head. The
row names the version's **origin** and nothing about its **content**. Restoring is therefore a blind choice: the user
can undo it afterwards, since restore publishes a new head and old snapshots survive, but nothing on the screen says
what any version would actually make the AI write.

The material for that answer already exists and is thrown away for this purpose. `posts.machine_baseline` holds each
post's raw AI output exactly as generated, before any human edit, alongside `machine_baseline_voice_id`. What is
missing is the link from that output to the **profile version** that produced it: nothing records which head was
current when a generation ran, and a post's baseline is cleared when the post is reassigned to another voice.

### 기존 글 가져오기's first field does not say what it is

The paste form's first field is labelled 라벨 (선택) with the placeholder `예: 제주 여행기`. It is the imported
piece's name — and when left blank the server fills it with the first 20 characters of the body — but "라벨" names
the mechanism rather than the thing.

### "이전 수동 안내" is a migration carry-over whose write paths were never cut

The bottom of 기존 글 가져오기 renders a section headed 이전 수동 안내 holding two free-text editors:

- **문체 규칙** (`voice_profiles.styleguide`) — the analysis model's output verbatim, hand-editable.
- **추가 규칙** (`voice_profiles.rules`) — rules the user types, which take effect immediately without waiting for
  the three independent pieces of evidence an earned rule needs.

Those two fields were the **entirety** of plan 03's voice profile. Change 02 replaced them with the structured
profile (ending distribution, sentence metrics, six tendency axes) and required the old text to survive migration
byte-for-byte **as manual guidance**, still affecting prompts until the user changed it — which is why the section
was renamed 이전 수동 안내 and pushed to the bottom of the screen.

The reads were kept and the **writes were not cut**, so the section is not a residue of old data — it is refilled by
today's behavior:

- every 학습 run writes the fresh analysis text into `styleguide` under a `corpus_version` guard, and that guarded
  write is also what decides whether the run may publish a structured version at all;
- a voice seeded from a description writes it the same way;
- plan 09's analyze-stage A/B winner is applied by writing it;
- `UpdateVoiceProfile` patches both fields for the two editors.

And because the analysis text is *also* copied into the structured profile's lexical description, and the prompt
renders the structured profile and then appends `styleguide` under a `[Legacy manual guidance]` header, **the same
analysis text reaches the model twice in one prompt** — double the tokens for zero new information.

### 문장 의견 is offered where the server always refuses it

The 문장 의견 control is rendered by the block editor, which is mounted on **글 다듬기** only. The server requires a
**completed voice-learning event** for that post before it will accept feedback, and a post on 글 다듬기 is in
`review` — never finalized, never learned. On the ordinary path the control therefore always fails, with
현재 말투 상태에서는 이 작업을 할 수 없어요 and no statement of what state would work.

Its dialog compounds this:

- The 문장 picker is a `Listbox` whose option labels are **whole sentences**. Its trigger is `whitespace-nowrap`, so
  the grid item's automatic minimum resolves to the full sentence's width and the sheet gains a long horizontal
  scroll.
- The 이유 picker's panel is clipped and unreadable for the reasons change 15 fixes in `Listbox` itself.
- A help line reads 이 반응만으로 새 규칙이 생기거나 활성화되지는 않습니다 — a true statement of what the feature does
  *not* do, standing where a statement of what it *does* should be.
- There is no free-text field, and no statement that the post is not going to be edited, so leaving feedback reads as
  a revision request that silently did nothing.

## To-be

### A version shows what it wrote before you take it

Every voice profile version carries at most one **generation snapshot**: a copy of the raw AI output of the last post
generated under that version, taken as the machine baseline is written and stored as a copy rather than a reference.
Replacing a version's snapshot replaces the previous one; a version never accumulates more than one.

- The copy is per voice and per version and is never shared with or inherited by another voice or account ([I4]).
- Because it is a copy, deleting the source post, regenerating it, editing it by hand, or reassigning it to another
  voice leaves the snapshot intact. A snapshot is a record of what a profile version produced, not a view of a post.
- A soft-deleted voice's snapshots go with the voice, like the rest of its private learning data.

The version list becomes a list of **openable** rows. Opening a version shows its number, origin, date, and its
snapshot — the title and body as the model wrote them. A version with no snapshot yet says so plainly instead of
showing an empty box. The way to adopt it, 이 버전으로 변경, lives inside that surface and publishes the version as a
new head exactly as 복원 does today. The preview **is** the confirmation, so the separate confirm dialog is gone: the
user is looking at what they are choosing. The current head is openable and offers no change action.

### The imported piece's field says 제목

기존 글 가져오기's first field is 제목 (선택), keeping its optional status, its placeholder, and the server's
existing fallback to the body's opening characters.

### 이전 수동 안내 is gone, and so are the fields behind it

The section, both editors, the two columns, their RPC surface, and their prompt injection are removed. The voice's
profile is the structured profile, its earned rules, and its sample excerpts — one representation, injected once.

- The `[Legacy manual guidance]` append disappears; the analysis text reaches the model once, through the structured
  profile's lexical description.
- The free-text 추가 규칙 path disappears entirely — column, RPC field, editor, and its position ahead of the earned
  rules in the prompt. Rules are earned through evidence or set through the structured profile's own fields;
  plan 16's 지침 is the planned home for standing instructions.
- 학습 and voice seeding keep their `corpus_version` guard: the guard is what decides whether a finished analysis is
  still the newest and may publish a structured version, and it survives without a text column to write into.
- Plan 09's analyze-stage A/B winner is applied by publishing a structured profile version whose lexical description
  is the winning analysis, so applying a winner keeps its confirmation and its effect on the voice.
- No migration preserves the old text. The product is not open, and the analysis text a live voice depends on is
  already in its structured profile.

### 문장 의견 is offered where it works, and says what it is

- It appears on **글 완성**, and only for a post whose voice-learning run has completed — the exact condition the
  server enforces. It is not rendered on 글 다듬기.
- Its surface states its purpose: this teaches the **voice** and does not change this post. Wanting the post changed
  is 글 다듬기's AI 수정, which the surface names as the way there.
- It keeps its four reasons (단어 선택 · 종결어미 · 문장 길이 · 구조) and stays a single, retry-idempotent record
  carrying no free text.
- The sentence is chosen from a **vertical list of the finalized text's sentences**, each a full-width row that wraps
  onto as many lines as it needs. The sheet does not scroll horizontally.
- The 이 반응만으로… line is replaced by the statement of purpose above. That one piece of feedback does not by
  itself create or activate a rule remains true and remains the contract; it is no longer the only thing the surface
  says.

## Scope / Non-goals (regression boundary)

**In scope**

- A per-version generation snapshot: its storage, the point at which it is copied, its one-per-version retention, its
  cascade with the voice, and the RPC that returns it with the version list.
- `pages/voice` (versions, import) and `features/edit-voice-profile` (version history, removal of the two editors).
- The 문장 의견 surface: where it is mounted, what it says, and how a sentence is chosen.
- Removal of `voice_profiles.styleguide` and `voice_profiles.rules`, their proto fields, their `UpdateVoiceProfile`
  patch, the `[Legacy manual guidance]` prompt append, and the free-text rules position in the prompt.
- The `corpus_version` guard's rework in the analyze and seed handlers.
- Plan 09's analyze-winner application, rerouted to publish a structured profile version.
- An embedded migration dropping the two columns ([I7]).

**Non-goals — these must NOT change**

- `SampleMinChars` stays **200**. The paste field's minimum is deliberately unchanged.
- Voice isolation ([I4]): profiles, samples, sources, rules, evidence, comparisons, validations and now snapshots
  stay private to one voice and one account, never shared, never inherited.
- 종결어미 as the primary Korean style signal, and the mandated analysis dimensions.
- The structured profile's own shape, its editor, its manual overrides, and `clearManual`.
- Earned-rule mechanics: `candidate/1 → candidate/2 → active/3`, three independent pieces of evidence from different
  posts, contradiction confirmation, 180-day retirement during a later explicit request, and the fact that only
  active rules reach generation.
- The prompt **injection order** for what remains: profile → sample excerpts → rules.
- The content/source-language equality gate on feedback, save-as-rule, comparison and validation, and the
  one-immutable-source-language-per-voice rule.
- Restore's own semantics: adopting a version publishes a **new head** and destroys no history.
- Sample add/delete and the re-analysis confirmation before overwriting an existing analysis.
- Rule comparison and profile validation screens.
- Page load, copy/export, polling, time and boot still never enqueue or call a personalization model.
- No change to how the editor reports status (change 15) or to the export panel (change 17).

**Dependency** — the 문장 의견 sheet's reason picker relies on change 15's portalled, elevated `Listbox`.

## Acceptance Criteria

1. After a generation completes for a post, the voice's current head version carries a snapshot equal to that post's
   raw AI output; generating again under the same head replaces it rather than adding a second.
2. Deleting the source post, editing its text by hand, or reassigning it to another voice leaves the snapshot's
   content unchanged.
3. Two voices in one account, and two accounts, never see each other's snapshots through any RPC.
4. Opening a version row shows that version's number, origin, date, and its snapshot's title and body; a version with
   no snapshot says so and shows no empty preview.
5. Pressing 이 버전으로 변경 inside the preview publishes that version as a new head with `origin = restore` and the
   restored-from version recorded, with no separate confirmation dialog in between; the previous head remains in the
   list.
6. The current head version is openable and offers no change action; a deleted voice's versions are read-only.
7. 기존 글 가져오기's first field is labelled 제목, is still optional, and a blank one still yields the server's
   body-derived fallback.
8. A body of 200 characters is still accepted and a body of 199 is still refused.
9. The 이전 수동 안내 section and both of its editors are absent from every voice screen, and no RPC accepts or
   returns a styleguide or rules string.
10. After a 학습 run, the analysis text appears exactly once in the constructed write prompt, and the string
    `[Legacy manual guidance]` appears nowhere.
11. A 학습 run whose corpus changed while the provider was working still declines to publish and re-analyzes the
    newest corpus, exactly as before.
12. A voice seeded from a description still produces a structured profile and a watchable run.
13. Applying an analyze-stage A/B winner still requires its confirmation and results in a structured profile version
    whose lexical description is the winning analysis.
14. 문장 의견 is not rendered on 글 다듬기; it is rendered on 글 완성 for a post whose learning run has completed, and
    submitting from there succeeds.
15. The 문장 의견 surface states that it teaches the voice and does not change the post, and names AI 수정 as the way
    to change the post; the string 이 반응만으로 새 규칙이 생기거나 활성화되지는 않습니다 is not rendered.
16. The 문장 의견 sheet does not scroll horizontally with sentences of any length, and each sentence row wraps.
17. Submitting the same sentence and reason twice yields one stored record.
18. Earned-rule behavior is unchanged: one piece of sentence feedback creates no rule and activates none, and a rule
    still needs three independent pieces of evidence from different posts of that voice.
19. The migration dropping both columns runs at boot and a failed migration kills the process ([I7]).
