# 11. Change: Header icon menus, profile popover, tab icons, and a typography primitive

> A **change proposal** (a WHAT delta) that modifies the already-shipped behavior of [plan/14.theme-preferences](../../plan/14.theme-preferences.md).
> Filled by /create-change through a user interview — a reviewable doc, not a one-line prompt.
> The STEPS live in the job that /create-change-job creates. Write it in English.
>
> Owner request (2026-09-01), four items in one interface revision: (1) the header exposes theme and
> locale as two icon-triggered dropdown menus, (2) the header's far right becomes a profile control
> whose popover holds the name, the plan/permission material, and logout, (3) the voice tab row stops
> horizontally scrolling on narrow screens by becoming icon-compact (owner delegated the exact
> pattern: "혹시 다른 UX가 더 좋으면 그렇게"), and (4) a repo-wide typography audit: document when
> each text size/weight is used, componentize it, and stop per-element CSS composition. The primary
> surface being dissolved (`widgets/interface-preferences`) belongs to plan 14, so the change targets
> plan 14 and lists the other touched plans under Grounding.

## As-is

- **Interface preferences.** `widgets/interface-preferences` is the only locale/theme composition,
  mounted on all three shells (login page, authenticated header, `/about` header). It is a single
  `Popover` triggered by one sliders-icon secondary button (icon-only on phone, icon + "환경설정"
  label from `sm:`), and its panel stacks two labelled `SegmentedControl`s — `LocaleSelect`
  (한국어/English, plan 13) and `ThemeSelector` (System/Light/Dark, plan 14). The current value of
  either preference is invisible until the popover is opened.
- **Session controls.** The authenticated header's right side renders three more independent
  controls beside the preferences popover: the raw account id as `font-mono text-xs` text (hidden on
  phone), the plan-17 `PlanUsage` popover (accent plan badge on `sm:`, gauge icon on phone; its panel
  holds the plan badge, the three usage meters, and the master-only `/admin` link), and an
  always-visible secondary logout `Button` (plan 01). A failed logout renders a danger `Notice`
  under the header.
- **Voice tabs.** `VoiceLayout` (plan 03, shaped by archived change 04) renders five text-only
  `TabLinks` (프로필 · 버전 기록 · 기존 글 가져오기 · 대조 규칙 · 프로필 검증). The row deliberately
  scrolls horizontally when the Korean labels outgrow the container, which on a 320–390px phone it
  always does — the later tabs are off-screen until swiped to.
- **Typography.** [design-language §3](../../tech/design-language.md) documents seven type roles as
  *class recipes* (display/title/body/input/label/meta/eyebrow), and every call site hand-composes
  them: ~79 non-test `.tsx` files repeat `text-*`/`font-*`/`tracking-*`/`text-content-*` per
  element. Drift exists (`text-xl` and prose `text-base` appear in no role; heading levels pick
  sizes locally), and nothing mechanical stops the next ad-hoc combination.

## To-be

1. **Two icon-triggered preference menus.** The preferences area becomes two adjacent icon-only
   dropdown controls, both app-drawn (no native `<select>`, per the §7 owner decision):
   - a **theme menu** whose trigger icon reflects the current preference (monitor = System,
     sun = Light, moon = Dark) and whose panel lists the three options,
   - a **locale menu** with a languages trigger icon and the two autonym options.
   Each option row shows a check on the active choice; choosing applies immediately with plan 13/14
   semantics unchanged (persistence, System override removal, live-region announcement), closes the
   menu, and returns focus to the trigger. The triggers carry translated `aria-label`s and 44px
   targets. `widgets/interface-preferences` keeps being the one composition mounted by all three
   shells, so login and `/about` gain the same two menus with no session control.
2. **Profile popover at the header's far right.** The authenticated header's session controls
   collapse into one avatar control (the account id's first character in a `rounded-full` trigger,
   since no profile image exists in the session model). Its popover holds, top to bottom: the
   account id (the "name"), the plan badge + the three usage meters + the master-only `/admin` link
   (the exact `PlanUsage` panel material, still fetched only while open), and the logout action.
   The standalone header id text, plan badge/gauge trigger, and logout button disappear. Logout
   keeps plan 01 semantics — navigate to `/login` only on success; on failure the popover stays
   open and shows the localized failure inline where the user is looking (§4.3), instead of a
   notice under the header.
3. **Icon-compact voice tabs.** `TabLinks` accepts an optional icon per item, and `VoiceLayout`
   provides one for each of the five tabs. When every item has an icon and the row's *container* is
   too narrow for the full text labels, the row switches (via `@container` query, §1.5) to evenly
   divided icon-above-compact-label tabs — all five visible at 320px with no horizontal scroll.
   Wide containers keep today's text-only row. Icon-only tabs (labels dropped entirely) are
   rejected: these five destinations are not conventional enough for an icon to carry alone, the
   same judgement the shell's bottom bar already records. This is the "better UX" the owner
   delegated.
4. **Typography as a primitive.** A `Typography` primitive joins `shared/ui`, owning the §3 role
   recipes (`display` · `title` · `body` · `label` · `meta` · `eyebrow`; `input` stays owned by the
   field primitives) with an element override (`as`) so a heading role can render any `<h*>`
   level. design-language §3 is rewritten to (a) state for each role when it is used — which
   size/weight belongs to which hierarchy level, (b) mandate the primitive: slice code renders text
   through `Typography` (or a primitive built on it) and never composes raw size/weight/tracking
   utilities, and (c) record the mechanical gate. All non-test call sites across
   `pages/ widgets/ features/ entities/ app/` migrate; off-role drift (`text-xl`, prose
   `text-base`) is normalized to the nearest role during the sweep, and hierarchy inconsistencies
   (e.g. two sizes for the same heading level) are resolved to one role per level.
   `pnpm lint:style` gains the gate: outside `shared/ui`, a raw text-size/weight/tracking utility
   in `.tsx` fails the scan (same pragma escape hatch as colour for the rare genuinely-not-type
   case, e.g. `font-mono` code rendering that a primitive exposes deliberately).

## Scope / Non-goals (regression boundary)

**In scope**

- `widgets/interface-preferences` recomposition; new app-drawn menu primitive in `shared/ui`;
  `features/change-locale` / `features/change-theme` presentation (their models are untouched).
- The authenticated header's right-side composition and the profile popover; `PlanUsage` panel
  content reuse; logout failure presentation.
- `TabLinks` compact mode + the five voice tab icons.
- `Typography` primitive, design-language §3 rewrite, the style-lint typography gate, and the
  repo-wide call-site migration (the 전수조사).
- i18n: the handful of new labels (profile/account popover, menu aria-labels) in both `ko` and `en`
  resources; updated tests for every touched surface.

**Non-goals (must NOT change)**

- No proto/RPC/backend/migration change; no new persisted state anywhere. Locale and theme remain
  independent browser-local preferences with plan 13/14 bootstrap, persistence, OS-change and
  cross-tab contracts intact.
- Logout still navigates only on success and drops the session cache first ([plan 01]); the
  master-only gating of `/publishing-agents`, `/admin`, and the plan material stays server-decided
  (plan 17) — this change only moves where it is rendered.
- Navigation destinations, routes, and the phone bottom tab bar are untouched. `SegmentedControl`
  keeps serving non-header surfaces; the legacy native `Select` surfaces stay as they are (their
  migration to the app-drawn listbox remains a later, separate concern).
- No design-token, palette, or theme-mapping change; both themes keep WCAG AA.
- The `input` type role stays inside the field primitives (§3.1 16px floor unchanged).

## Acceptance Criteria

1. The authenticated header renders, right of the brand/nav: the theme icon menu, the locale icon
   menu, and the avatar profile control — and no standalone logout button, plan badge/gauge, or
   account-id text in the header row.
2. The theme menu trigger's icon reflects the stored preference (monitor/sun/moon) at first paint
   and after every change; its panel marks the active option; selecting Light/Dark/System applies
   immediately with plan 14 persistence semantics (System removes the override) and closes the
   menu, focus returning to the trigger.
3. The locale menu lists 한국어/English as autonyms with the active one marked; selection switches
   the interface language immediately, announces politely (existing live region), and never changes
   the URL or theme.
4. Both menus are app-drawn (no native select option list), fully keyboard operable (open, arrow
   between options, Enter selects, Escape closes and restores focus), have translated trigger
   `aria-label`s, ≥44px targets, and no horizontal overflow at 320px, in both themes.
5. The login page and `/about` mount the same two icon menus through the shared composition, with
   no profile control there.
6. The avatar popover shows the account id, the plan badge and three usage meters (fetched only
   while open, exactly as before), the `/admin` link only for `master`, and a logout action;
   successful logout lands on `/login` with the session cache dropped; a failed logout keeps the
   popover open and shows the localized failure inline.
7. The five voice tabs each carry an icon; below the container width where the full labels fit, the
   row shows all five tabs icon-first with compact labels and no horizontal scrolling at 320–390px
   viewports; at wide widths the row renders text labels as today; the current tab stays
   `aria-current="page"` in both modes.
8. A `Typography` primitive exists in `shared/ui` covering the documented roles with semantic
   element control; design-language §3 states when each role/size/weight is used, mandates the
   primitive for slice text, and documents the lint gate.
9. Outside `shared/ui`, no non-test `.tsx` composes raw text-size/weight/tracking utilities for
   text; every migrated surface renders through `Typography` (or a primitive), `pnpm lint:style`
   enforces the rule and fails on a violation, and the full sweep leaves no off-role size in slice
   code.
10. Per-surface hierarchy is normalized: each page has one `display` title, section headings share
    one `title` role, metadata uses `meta` — no screen renders two different ad-hoc recipes for the
    same hierarchical level.
11. All existing behavior contracts hold: plan 13/14 acceptance criteria (locale/theme persistence,
    bootstrap order, cross-tab, System following), plan 01 logout, plan 17 gating — verified by the
    updated test suites; `pnpm test`, `pnpm lint`, `pnpm lint:fsd`, `pnpm lint:style`,
    `pnpm lint:style:probe`, and `pnpm build:web` all pass.
