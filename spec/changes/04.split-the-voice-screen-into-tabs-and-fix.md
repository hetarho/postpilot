# 04. Change: Split the Voice Screen into Tabs and Fix Unset Axes

> A **change proposal** (a WHAT delta) that modifies the already-shipped behavior of [plan/03.voice-profile-learning](../plan/03.voice-profile-learning.md).
> Filled by /create-change through a user interview — a reviewable doc, not a one-line prompt.
> The STEPS live in the job that /create-change-job creates. Write it in English.

## As-is

**One route, one column.** `/voice` is a single screen that stacks every voice surface the account owns, in this
order: the typed profile editor, contrast rules, validation start, the validation record list, a `<details>` holding
historical import, and a `<details>` holding legacy manual guidance. Six unrelated concerns share one scroll. Version
history and restore are buried at the bottom of the profile section, ~4 screens below the fold on a phone.

- The current-profile section renders the five overridable fields, the measured ending distribution, sentence and
  paragraph measurements, the six axes, banned expressions, **and** the whole version list with a restore button.
- Contrast rules, the pending-confirmation notices, and the blind-comparison dialog are one section below it.
- Profile validation and its record list are two more sections below that.
- Historical import (analyze-stage model select, the paste form, the sample list, and the shared analysis progress
  line) is a collapsed `<details>`, as is the legacy styleguide/rules pair.

**Every profile field is permanently in edit mode.** `EditableValue` renders a single-line `TextField` seeded from a
`draft` state, plus a 적용 button and a 직접 설정 해제 button, whether or not the owner intends to change anything.
Reading the profile means reading five form inputs. The control is a `TextField`, so a description longer than the
input's width is only ever visible one line at a time.

**All detail queries load on every mount.** `useVoiceDetails` issues `ListVoiceProfileVersions`,
`ListRuleConfirmations`, and `ListVoiceProfileValidations` whenever `/voice` mounts, regardless of which of the six
concerns the owner actually came for.

**There is no sub-navigation primitive.** `AuthenticatedLayout`'s three-destination `DESTINATIONS` list is the app's
only navigation. `SegmentedControl` is the design system's tab row, but it is a state control driven by `onChange`,
not a set of links, so it cannot express "these five tabs are five addresses".

**The six axes publish as zeros regardless of what the model measured.** The prompt is asymmetric: it names all
eight string keys the decoder expects (`lexical_description`, `base_register`, `connective_style`, `intro_pattern`,
`closing_pattern`, `heading_habit`, `list_habit`, `emoji_use`) but describes the axes only as
"six integer axes (-3..3)" — never naming the `axes` wrapper object or the six keys under it (`involvement`,
`narrativity`, `persuasion_overtness`, `abstractness`, `addressee_focus`, `humor`). The
`learn_voice` completion call passes no `JSONSchema` — unlike write, revise, and observe, which each attach one when
the resolved model declares `structured_output`. A model that answers with the six values flat, or under different
key names, decodes into the zero value of `qualitativeAxesJSON` with no error. `validateAxes` then accepts 0 because
0 is inside `-3..3`, and the profile publishes six zeros that are indistinguishable from a genuine neutral
measurement. The typed profile represents weak evidence as explicit `unknown` everywhere else; the axes are the one
place where "the model did not answer" is silently rendered as a real value.

This is observed, not hypothetical. On a live account after a successful learn, every field the prompt names by key
holds an analyzed value, the deterministic measurements (ending distribution, average sentence length, paragraph
sentence range) hold measured values, and the six axes are all exactly 0 — the one group the prompt does not name.

## To-be

### Five addresses, one tab row

`/voice` becomes five sibling routes, each owning exactly one concern, each rendering the same tab row:

| Route | Tab | Owns |
|---|---|---|
| `/voice` | 말투 | The current typed profile: the five overridable fields, ending distribution, sentence/paragraph measurements, six axes, banned expressions, and the empty-profile copy |
| `/voice/versions` | 버전 기록 | The version list and the restore confirmation |
| `/voice/import` | 기존 글 가져오기 | Analyze-stage model select, the paste form, the sample list, the analysis progress line, and the legacy manual guidance |
| `/voice/rules` | 대조 규칙 | The rule list with status actions, pending confirmations, and the blind-comparison start |
| `/voice/validations` | 프로필 검증 | The validation start control and the validation record list |

The two existing detail routes nest under their owning tab rather than under the profile: `/voice/rules/$id/compare`
returns to `/voice/rules`, and `/voice/validations/$id` returns to `/voice/validations`. Both keep their current URLs.

The tab row is a new `shared/ui` primitive built from `<Link>`, not from `<button>`: each tab is a real address, so
the browser's back button, a bookmark, a copied link, and a modifier-click all work. It scrolls horizontally rather
than wrapping or crushing its five Korean labels — the shape `SegmentedControl` already establishes for a tab row
that outgrows a 360px content column (design-language §1.1 corollary, §4.4's horizontal-strip exception).

Each tab loads only the queries its own panel reads. The profile query stays shared; the versions, confirmations, and
validations queries move behind the tab that displays them.

### Read first, edit on request

A profile field's default state is **text**, not a form control: its label, its provenance badge (측정 / 분석 /
직접 설정 / 알 수 없음), and its value as prose that wraps to as many lines as it needs.

Each field carries one edit control — a pencil icon with an accessible name naming its field. Pressing it puts that
one field into edit mode: a growing `Textarea` (capped per §4.4's in-form rule) seeded with the published value, a
저장 action, a 취소 action, and 직접 설정 해제 when the field's source is `manual`. Fields are independent; opening
one does not close another.

취소 discards the draft and restores the published value. A successful 저장 leaves edit mode; a failed one stays in
edit mode with the draft intact, so a rejected save never costs the owner their text.

### An unanswered axis is unknown, not zero

The `learn_voice` analysis stops being able to publish a fabricated neutral:

- `structuredAnalysisPrompt` names the `axes` object and all six keys explicitly.
- The completion call attaches a JSON schema when the resolved model declares `structured_output`, mirroring
  `generation/write.go`'s existing capability check. A model without the capability keeps the prompt-only path.
- The six axes carry presence. An axis the model did not answer publishes as **unknown** and renders as 알 수 없음
  next to the other unknown-capable fields, rather than as 0. A value outside `-3..3` still fails the job.

Existing profile snapshots are immutable and are not rewritten: a version that already stored six explicit zeros
keeps showing zeros. The next successful learn publishes a new version with real values or explicit unknowns.

## Scope / Non-goals (regression boundary)

**In scope**

- The `/voice` route split, the tab row primitive, and per-tab query loading.
- Read-first field display with per-field edit mode.
- The back-link targets of `/voice/rules/$id/compare` and `/voice/validations/$id`.
- The analysis prompt's axis keys, the structured-output attachment on the `learn_voice` completion call, and axis
  presence through the contract, the store, and the profile UI.

**Must NOT change**

- **Navigation above 말투.** `글 / 말투 / AI 모델` stays three destinations in both the phone tab bar and the desktop
  header. The five tabs are sub-navigation inside 말투, not a fourth top-level destination.
- **When learning runs.** `learn_voice` still fires only from an explicit **Finalize and learn** with a confirmed
  analyze model. No page load, mount, tab switch, poll, or navigation enqueues or calls a personalization model.
- **What the axes mean**, and their `-3..3` bound.
- **Rule lifecycle.** Three independent evidence rows still activate a rule; only active rules reach generation;
  contradictions still wait for owner confirmation; the 180-day retirement still happens only during a later explicit
  generation or revision.
- **Validation semantics.** Still three finalized sources, still topic-only neutral summaries, still opt-in judge,
  still no write to the profile and no model Elo.
- **`ProfileForPrompt` injection order** (styleguide → excerpts → rules) and the excerpt counts.
- **Legacy styleguide and rules** stay byte-preserved and keep applying to generation and revision.
- The post editor, generation, revision, export, and model-experiment surfaces.
- **Account-singleton scoping.** These routes stay one-profile-per-account; job 18 adds the voice dimension on top of
  this structure later ([I4]).

## Acceptance Criteria

1. `/voice` renders the current typed profile and the tab row, and renders none of: the version list, the rule list,
   the validation start, the paste form, the sample list, or the legacy manual guidance.
2. `/voice/versions`, `/voice/import`, `/voice/rules`, and `/voice/validations` each render the tab row and only
   their own panel. The tab matching the current address is marked current for assistive technology.
3. Every tab is a link with an `href`. Navigating to a tab and pressing the browser's back button returns to the
   previous tab, and reloading a tab's address renders that tab — not `/voice`.
4. Mounting `/voice` issues no `ListVoiceProfileVersions`, `ListRuleConfirmations`, or `ListVoiceProfileValidations`
   request; each of those is issued by the tab that displays its result, on that tab's mount.
5. At a 360px viewport the tab row scrolls horizontally, no tab label is clipped or wrapped, every tab meets the
   44px target minimum, and the page itself does not scroll horizontally.
6. A profile field renders its value as wrapping text with no form control until its edit control is pressed. The
   value is fully readable without scrolling a control.
7. Pressing a field's edit control puts that field — and only that field — into edit mode with the published value
   seeded. 취소 restores the published value and discards the draft. A successful save exits edit mode and shows the
   saved value; a rejected save stays in edit mode with the draft intact.
8. 직접 설정 해제 appears only for a field whose source is `manual`, and clearing it republishes the analyzed value.
9. `/voice/rules/$id/compare` returns to `/voice/rules` and `/voice/validations/$id` returns to `/voice/validations`.
   Both addresses are unchanged and still render their existing content.
10. A `learn_voice` completion against a model declaring `structured_output` sends a JSON schema that requires the
    `axes` object and its six keys; a model without the capability sends the prompt naming those same six keys.
11. A model response that omits an axis publishes that axis as unknown, and the profile screen shows 알 수 없음 for
    it. A response with a value outside `-3..3` still fails the job. A response with all six answered publishes all
    six values unchanged.
12. No regression: the empty-profile state, the empty-profile editor warning, the finalize-and-learn trigger, rule
    activation at three evidence rows, validation eligibility at three finalized sources, and the
    styleguide → excerpts → rules injection order all behave exactly as before.
