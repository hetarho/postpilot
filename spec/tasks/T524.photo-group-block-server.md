# T524 photo group block on the server

## goal
`PostContent` can carry a GALLERY block (2 … 10 photos, one layout, one alt, one caption) that the post context validates, stores, serves, finalizes and measures.

## acceptance
- [ ] proto `BlockType.GALLERY`, `GalleryLayout` and `Block.files` / `Block.layout` exist and `pnpm gen:proto` output is committed (only the post files change)
- [ ] SavePostContent accepts a valid GALLERY block and refuses: fewer than 2 or more than `PhotoGroupMax` photos, a photo named twice, a name not attached (a video named → the "belongs in a VIDEO block" reason), a missing layout, and `content`/`level`/`items`/`file` on a GALLERY; any other block type carrying `files` or `layout` is refused as fields for another block type
- [ ] a stored GALLERY round-trips through the DB JSON and GetPost; content stored before this change decodes unchanged
- [ ] FinalizePost counts every missing photo of an IMAGE block or a GALLERY as one remaining place
- [ ] QUAL M4 photo count counts every non-blank photo of a GALLERY, and a GALLERY counts as one distinct block type
- [ ] memory extraction text includes a GALLERY's caption; the template-request sample renders a GALLERY as `[사진 n장 묶음]` with n capped at the template photo-row ceiling
- [ ] Go tests pin each case above (post content validation, store round trip, rpc mapping, finalize count, quality composition, memory text, template sample)
- [ ] ARCH-26 and ARCH-28 pass; `pnpm build:web` still passes with the regenerated TS

## impl notes
- proto (`post.proto`): `GALLERY = 7` in `BlockType`, commented as a photo group carrying `files`, `layout`, `alt`, `caption` (GEN-77); new `enum GalleryLayout { GALLERY_LAYOUT_UNSPECIFIED = 0; GALLERY_LAYOUT_COLLAGE = 1; GALLERY_LAYOUT_SLIDE = 2; }` — prefixed values because enum values are package-scope siblings (the AttachmentKind comment); `Block` gains `repeated string files = 9; GalleryLayout layout = 10;` documented as GALLERY-only. Field 8 stays reserved. The FE gets the TS through the generator only (ARCH-3). Regenerating rewrites every generated file from the current protos; stage only the post files (a peer's clip proto edits may be in the tree).
- domain (`internal/post/types.go`): `BlockGallery BlockType = "GALLERY"`; `type GalleryLayout string` with `GalleryCollage = "COLLAGE"`, `GallerySlide = "SLIDE"`; `Block` gains `Files []string` and `Layout GalleryLayout`; exported typed constant `PhotoGroupMax = 10` beside the other post limits (POST constraints; FE mirrors it in T526).
- `ValidateContent` (`content_edit.go`): a GALLERY case with the refusals above (reasons in the existing English `block %d: …` style, e.g. "a photo group holds 2 to 10 photos", "photo appears twice in one group", "photo group layout is required"); every other case additionally rejects non-empty `Files` or `Layout` with the existing "contains fields for another block type". `alt` and `caption` are allowed on GALLERY like IMAGE.
- finalize (`service.go` FinalizePost): count IMAGE `File` and each GALLERY file that is non-empty and not attached; the error stays `PhotoMissingError{Count}` (POST-13 "places" = photo positions).
- store (`post/store/content.go`): `blockJSON` gains `Files []string json:"files,omitempty"` and `Layout string json:"layout,omitempty"` so every stored row decodes unchanged; no migration (the column is a JSON document the post context owns).
- rpc (`post/rpc/handler.go`): map `GALLERY` both ways, `files` copied, layout `UNSPECIFIED ↔ ""`, `COLLAGE ↔ GalleryCollage`, `SLIDE ↔ GallerySlide`.
- quality: `quality.BlockGallery`, `quality.Block.Files`; `cmd/api/adapters_quality.go` maps the type and copies files; `MeasureComposition` marks GALLERY used when it has at least one non-blank file and adds each non-blank file to `PhotoCount`; update the "six block types" comments to seven.
- `cmd/api/adapters_memory.go`: GALLERY writes its caption like IMAGE/VIDEO.
- `cmd/api/adapters_template.go` sample: GALLERY → `[사진 n장 묶음]`, n = min(len(files), the configured template photo-row max that the template limits already carry); IMAGE stays `[사진]` (TMPL-64).
- out of scope here: generation (T525), every FE rendering (T526–T528). Until T526 the FE renders nothing for a GALLERY; no server path produces one before T525, and nothing is pushed between tasks.
