# T531 observed photo rotation on the server
> st:todo | ssot:GEN-79 POST-107 GEN-77 | base:GEN@23 POST@31 | dep:T530 | touches:proto/postpilot/v1/post.proto backend/internal/generation backend/internal/post backend/internal/platform/db/migrations backend/cmd/api

## goal
The observe stage reports each photo's upright rotation, the post stores a rotation per photo that follows the observation until the owner turns it, GetPost serves it, a RotateImage RPC lets the owner turn a photo, and orientation for grouping reads the turned dimensions.

## acceptance
- [ ] the photo observe schema requires `rotation` (integer, no enum) and the prompt asks for it; the parser keeps 0/90/180/270 and reads anything else as 0; video observations carry none
- [ ] `Observation.Rotation` travels through generation, the post store JSON (omitempty) and the experiment snapshot; old stored observations decode with 0
- [ ] migration adds `images.rotation INTEGER NOT NULL DEFAULT 0` and `images.rotation_by_owner INTEGER NOT NULL DEFAULT 0`; existing rows read 0/false
- [ ] SetObservations sets each observed photo's rotation from its entry unless the photo is owner-rotated, in the same transaction as the observations
- [ ] `RotateImage(image_id, rotation)` is owner-scoped, refuses a published post (→POST-74) and a value other than 0/90/180/270 (InvalidArgument), sets `rotation_by_owner`, returns the Image; `Image.rotation` rides GetPost
- [ ] the write and revise prompts' orientation reads the turned dimensions: the owner's rotation when owner-rotated, else the merged observation's rotation
- [ ] Go tests for each of the above (parse, store round trip, migration, SetObservations rule, RotateImage refusals, orientation with rotation); ARCH-26 and ARCH-28 pass
