## goal
The voice's third tab, 검증, lets the owner pick an answered prompt (or answer one there) and start one durable `check_voice` job on the active write model that writes a 10~15 sentence piece in this voice with that answer withheld; each result shows the piece beside the owner's answer with the fingerprint comparison, stays listed, and retries as a new job.

## acceptance
- [ ] a migration creates `voice_checks` and adds `check_voice` to the voice-kind index and the duplicate-work trigger (one queued or running 검증 per voice); DeleteVoice refuses while one runs through the existing job clause
- [ ] `StartVoiceCheck(voice_id, prompt_key, write_model)` refuses a tombstone, a voice not made (`VOICE_NOT_MADE`), an unanswered prompt (`VOICE_CHECK_PROMPT_UNANSWERED`), a model not registered to the write stage, and a photo prompt on a write model without `vision` (`VOICE_CHECK_PHOTO_UNSUPPORTED`); it freezes the projection with that answer withheld, the prompt and the analysis time on the check, holds one write call, and returns the check and the job id
- [ ] the handler makes one write call with the prompt of impl notes (the answer's photo attached for a photo prompt), stores the trimmed piece or a structured failure, and never calls a second time
- [ ] `ListVoiceChecks(voice_id)` returns the voice's checks newest first, each with its prompt, the answer's current text (or that it was deleted), the piece, `VOICE-62`'s comparison of `MeasureText(piece)` against the current analysis, and whether it predates the current analysis; `RetryVoiceCheck(check_id, write_model)` starts a new check against the same prompt and the current analysis

## impl notes
- Schema: `voice_checks(id PK, user_id FK cascade, voice_id, prompt_key, material_id, analysis_created_at, projection TEXT NOT NULL, write_model, status CHECK (status IN ('queued','running','done','failed')), piece TEXT, error_reason, error_params, technical_detail, created_at, updated_at, FOREIGN KEY (voice_id, user_id) REFERENCES voices(id, user_id))`, index `(voice_id, created_at DESC, id DESC)`; the failure columns reuse `voice/store/failure.go`'s codec
- Migration: drop and recreate `generation_jobs_active_voice_kind_idx` and `generation_jobs_refuse_duplicate_voice_work` with `'analyze_voice', 'check_voice'`
- Kind `check_voice` in `job/job.go` and `voice/types.go`, registered in `cmd/api/jobs.go`, listed in `voiceOwnedKind` (`cmd/api/job_subjects.go`), with a `jobs.sql` stage-map entry of `write`; planned calls: one write call on the given model
- Projection: `PromptProfileForTopic(ctx, userID, voiceID, {prompt text}, LanguageKorean, {answer material id})` at start, frozen as text on the check
- Prompt (Korean, code), after the frozen projection:
  ```
  [문항]
  {prompt text}
  [요청]
  위 말투로, 이 문항의 주제에 대해 블로그 글의 한 부분을 10~15문장으로 써 주세요. 첫인사로 시작해서 끝인사로 마무리하세요. 사진이 있으면 사진에 보이는 것을 소재로 쓰되, 사진에 없는 사실은 지어내지 마세요. 제목·목록·설명 없이 본문만 쓰세요.
  ```
  - the photo is read from private storage by a `Read(ctx, key)` method added to the voice context's `ObjectStore` port, capped at `MAX_IMAGE_BYTES`, and sent as an image part — the registry refuses an image to a model without `vision`, so the start check mirrors it
  - the answer is plain text; empty output is `MODEL_OUTPUT_INVALID`; the completion budget is the write stage's floor
- `VOICE_CHECK_SENTENCES` (10~15) is the requested range, not a validation — a shorter piece is stored and its comparison marks what it cannot show as 알 수 없음
- New reasons `VOICE_CHECK_PROMPT_UNANSWERED`, `VOICE_CHECK_PHOTO_UNSUPPORTED`, `VOICE_CHECK_NOT_FOUND` in both FE catalogs
- FE: `pages/voice/ui/VoiceChecksPage.tsx`, `features/check-voice` (start sheet, retry), `entities/voice` `useVoiceChecks` keyed `['voice-checks', transport, owner, voiceId]` and invalidated when a check's job finishes; the start sheet reads the active write selection and its `vision` flag from `ListModels`; `VOICE_TABS` = 말투 분석 · 학습 글 · 검증 (`ClipboardCheck` icon)
- Do not run concurrently with another task in this tree that regenerates proto or adds a migration
