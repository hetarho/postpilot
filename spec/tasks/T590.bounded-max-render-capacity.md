## goal
Protect the existing CPU deployment with atomic finite server-render capacity and truthful cancellable waiting.

## acceptance
- [ ] The initial native render configuration admits one active server render, at most two waiting server renders globally and one queued/running render per account, with validated finite overrides.
- [ ] Capacity and export-slot admission cannot overrun under concurrent starts; duplicate requests do not occupy another slot and refusals spend neither AI credits nor successful export counts.
- [ ] Waiting uses the existing finite media wait deadline, shows actual waiting/running/expiry/overload states, supports cancellation and preserves the previous successful result.
- [ ] Completion, cancellation, admission failure, restart, expired leases and worker loss release or reconcile capacity exactly once without reviving expired commercial allowance.
- [ ] Bounded analysis verification is accounted independently from native render capacity; a Max queue cannot reserve browser-render execution or silently cause browser exports to wait.
- [ ] Same-host deployment documents enforceable API/worker CPU, memory and disk reservations and needs no second rented worker or GPU; local configuration/race/recovery tests and matching CPU smoke pass.

## impl notes
- Implement a clip-owned capacity admission port composed with existing export reservation and job admission transaction ports; generic job/usage contexts gain no product-specific SQL.
- Use named clip limits merged with validated platform env settings under ARCH-21; default active=1, waiting=2, per-account=1. Retain the existing 30-minute media wait default rather than inventing a completion-time guarantee.
- Count durable queued/running render identities, including work awaiting worker claim, so a process-local semaphore is not the admission authority.
- Keep master subject to execution bounds. Preserve already admitted work when tuning capacity downward; reject only new starts until capacity returns below the bound.
- Work with existing lease/recovery/cancellation machinery and typed product failures. Report bounded stage metrics without media, text or signed URLs.
- Update reference Compose/runbook and tests only; do not provision hosts, change the production database, alter backup policy or modify live environment values.
