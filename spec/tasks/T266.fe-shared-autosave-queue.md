# T266 one autosave queue behind three save features
> st:todo | ssot:ARCH-14 ARCH-18 ARCH-24 | base:ARCH@5 | dep:-

## goal
Replace the three hand-rolled autosave machines with a generic keyed queue in `shared/lib/autosave` and turn `save-draft`, `edit-clip-project` and `edit-post-content` into thin adapters that supply `merge` and `send`.

## acceptance
- [ ] `shared/lib/autosave/` exports `createAutosaveQueue<TDraft, TResult>({ debounceMs, retry, merge, send })` returning `{ queue(key, draft), flush(key, failFast?), peek(key), state(key), failure(key), subscribe(key, fn), discard(key), discardAll() }`; it imports no react (ARCH-18) and reads `AUTOSAVE_*` from `shared/config`
- [ ] `features/save-draft/model/draft-queue.ts`, `features/edit-clip-project/model/clip-draft-queue.ts`, `features/edit-post-content/model/content-queue.ts` each shrink to their `merge`/`send`/state-mapping (≤120 lines) and keep their exported names so `useAutosave` and consumers are untouched
- [ ] the `conflict` state of `content-queue` is a first-class queue outcome (`send` may return `{ kind: 'conflict', ... }`), not a special case inside one adapter
- [ ] the generic queue has its own unit tests (debounce, merge of two queued drafts, retry backoff schedule, flush waiters, failFast, discard while in flight) and the existing 685-line `draft-queue.test.ts` plus the other two suites pass unchanged
- [ ] behaviour unchanged: the editor and clip autosave render tests pass; ARCH-25 passes

## impl notes
- from review/arch-260919 F8
- the three machines share: module `Map` of queues keyed by slug/projectId, `stateOf`, `publish`, retry with backoff, flush waiters, `discard*` — that is the generic core; what differs is the payload merge and the send/revision contract, which become the two callbacks
- revision handling: `SendDraft` returns nothing, `SendContent` returns the next `bigint` revision — model it as `send(draft, ctx) => Promise<TResult>` and let the adapter store the result in its own state
- keep `SaveState` as the shared union (`shared/api` or `shared/lib`) and map `ContentSaveState`'s `conflict` onto it so the union is one
