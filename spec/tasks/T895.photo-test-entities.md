## goal
The writing-test entity can build an observation plan, read observation tests with their photos and blind observations, upload test photos through the same pipeline posts use, and its fixture refuses what the server refuses.

## acceptance
- [ ] Deterministic, unit (`api/mappers.test.ts`): `planToProto` sends output OBSERVATION, the photo ids, stage OBSERVE and model entrants for an observation plan and refuses one with material text, attachments, a source post, setting fields, writer/observer models or no photo; a post plan sends output POST and no photo ids; `mapWritingTest` reads output (unspecified → post), photos and candidate observations, refuses observations on a post test and drops a candidate observation `model` before reveal.
- [ ] Deterministic, unit: `createTestPhotoHandshake(transport)` calls CreateTestPhotoUpload/ConfirmTestPhotoUpload and returns the same shapes as `createUploadHandshake`; the studio fixture serves both RPCs, applies T893's observation shape rules in estimate/start and echoes observation tests with photos and blind observations.
- [ ] Deterministic, unit: affected `pnpm --filter ./frontend exec vitest run src/entities/writing-test src/widgets/writing-test` plus changed-file ESLint/Prettier and the ARCH-24 task lint pass.

Export it from the entity's public index.
- Fixture (`api/studio-fixture.ts`): reuse `refuseServerShape` and add the observation rules from T893's ValidateTestShape note; keep host tests deterministic.
- Unit receipt: every `agentChecks` entry's `candidate` is the full 40-character commit SHA (`git rev-parse HEAD`) or null; an abbreviated SHA makes the runner record the unit as failed.
