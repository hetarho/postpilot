# T559 Take a server render's ground frames from its own lossless cut, and trim before scaling
> st:todo | ssot:ARCH-37 ARCH-24 | base:ARCH@15 | dep:T558 | touches:backend/internal/clip/media/composition_render.go backend/internal/clip/media/ground_sampler.go

## goal
A server render reads each cut's ground frames from the lossless `bare-%04d.mp4` it just encoded instead of decoding the original a second time, and the browser sampler scales only the frames it reads, in one output per cut.

## acceptance
- [ ] server render: after `renderBareFootage`, the cut's needed frames are read from `bare-%04d.mp4` (canvas-sized, `-crf 0`, yuv444p, same chain) by one ffmpeg call selecting the needed local frame indexes; no second decode of the original
- [ ] browser sampling (`sampleCut` on an original): the chain is trim → rate → select the needed frames → cover scale → setsar, with one output for the cut instead of up to `SampleBatch` outputs
- [ ] grounds are pixel-identical to today's for the same plan: a media smoke compares the sampled grounds (scrim, accent, contrast notices) of a fixture plan before and after, and the identity smoke digest is unchanged on this host
- [ ] ARCH-37: `production` target media smokes and the identity smoke pass (grep `did not complete successfully` → 0); record `render_footage` substage time for one fixture before and after in the result
- [ ] behaviour unchanged otherwise: ARCH-26 green
