## goal
An author sees the selected template's concrete questions and must answer its required fields before starting a new write.

## acceptance
- [v] Go and TypeScript parse `<ask required="true">`, preserve it through the builder, treat absence as optional and refuse any other value; shared grammar cases and both parser tests agree.
- [v] The editor shows each question's topic as help, marks required fields, keeps them editable without an off switch and points to the first missing field before a new writing action.
- [v] The server refuses a new generation, storyline start or rewrite, and write comparison with the first missing required label before a job, snapshot or credit hold; an ordinary revision of existing content stays available.
- [v] Optional blanks still disappear from the frozen template and existing templates without required fields keep their behavior.
- [v] The template format guide, request path, stable error reason and localized error copy describe the new field rule; focused tests and ARCH-25/26/28 verification pass.

## impl notes
- The sole required syntax is `required="true"`; unknown or false values are `malformed_tag`. The same field label remains the answer key.
- Return `FailedPrecondition` with `TEMPLATE_REQUIRED_ANSWER_MISSING` and `params.label` holding the first missing label in template order. This is a pre-enqueue check over saved answers; the frontend check is immediate guidance.
- Do not apply the new gate to StartRevision. Preserve old optional answers and existing answer rows without migration.
- Shared Go/TypeScript fixture is `backend/internal/template/testdata/grammar/cases.json`; proto error code is 290.
