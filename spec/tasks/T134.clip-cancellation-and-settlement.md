# T134 Cancel clip attempts and settle the unused reservation

## goal
Provide durable owner cancellation for clip jobs with one result outcome and an auditable reservation-based credit settlement.

## acceptance
- [ ] CancelClipJob accepts only the owner's queued/running generate_clip or render_clip job; accepted cancellation persists across navigation/restart, stops later AI work and result replacement, and terminates as cancelled after the handler exits.
- [ ] Cancellation racing dispatch, reservation, result commit, normal failure or repeated requests has one durable winner, one terminal settlement and no replacement of the previous result after cancellation wins.
- [ ] Settlement is C + ceil((R - C) / 2), capped by reservation/approval, with C zero without confirmed billable usage; fixtures include R=100/C=20 → 60 charged/40 refunded and R=5/C=0 → 3 charged/2 refunded.
- [ ] Before reservation and for manual rerender cancellation, debit is zero; ordinary no-usage failure remains zero, master has a separate shadow calculation and no lot debit, and historical settled attempts stay unchanged.
- [ ] API accounting exposes the cancellation policy and separate confirmed-use, cancellation-addition, total and refund values; unknown usage remains unknown and no synthetic usage event represents the addition.
- [ ] Real SQLite concurrency/fault tests cover cancellation before/during reservation and provider calls, after upload/before result commit, completion winning first, save failure, shutdown/restart, multiple settlement callers, expired/refunded lots, zero/full/over-ceiling confirmed cost and missing provider usage.
- [ ] Existing post/voice/experiment workers and settlement behavior pass regression tests; cancellation is not exposed for those job kinds.
- [ ] Run applicable ARCH-25 through ARCH-29 local gates, deterministic proto/SQL generation and spec lint; preserve unrelated generated changes using a before/after snapshot.

## impl notes
- Add CancelClipJob(project_id, job_id) → current GenerationJob and ClipAccounting to ClipService. Resolve the actor from auth, reject a foreign/mismatched job as not found, return terminal jobs unchanged, and make repeated requests for the same owned attempt idempotent. Distinguish an accepted request from terminal cancellation in the response.
- Add nullable cancel_requested_at to generation_jobs and the terminal status cancelled, updating SQLite CHECK constraints/indexes, domain/proto adapters and all terminal predicates. Keep status queued/running while cancellation is pending so existing active-job exclusion remains authoritative; project/list projections show 취소 중. Dispatch skips cancelled requests, while queued cancellation may finish immediately when no handler owns the job.
- Install per-job cancel functions inside job.Queue; persist the request before invoking the in-process signal. Immediately re-read the durable flag when a handler registers, covering cancellation before registration; parent shutdown remains distinct from owner cancellation. Context cancellation reaches provider HTTP requests, media preparation, ffmpeg/resvg process trees and storage operations; detached bounded cleanup/metering must finish before settlement.
- Serialize cancellation acceptance and reservation through a short BEGIN IMMEDIATE unit of work. Extend the current cmd/api clip/jobs/usage adapters to use transaction-bound context stores: check the pending flag and acquire the usage hold in that same transaction, so a cancellation that wins before reservation cannot acquire a later hold. Domains expose consumer-owned behavior ports and receive no SQL transaction/proto types; no transaction spans network/media work.
- At the metered clip call allowance seam, atomically authorize dispatch only while the attempt is active without accepted cancellation, consuming its existing bounded call allowance. A dispatch authorized before cancellation is in-flight work and receives the job's cancelled context; no subsequent observation or writer may acquire permission. This preserves QUOTA's frozen refs/budgets without adding retries or calls.
- Remove the current SaveGeneration/SaveRender → later worker Finish gap for clip success. Stage the candidate analysis/plan/result in a clip-owned clip_attempt_results row keyed by job ID, then commit the candidate and job done outcome in one write transaction through a cmd/api ClipFinisher adapter using each context's transaction-bound store operations. The transaction checks cancellation, project ownership/deletion/finalization and expected revision; a losing/uncommitted candidate is queued for object cleanup and never becomes project.result.
- The clip completion adapter is the only successful result commit path; worker Finish treats its already-terminal outcome idempotently. Ordinary failure and accepted cancellation also use conditional terminal writes; settlement is authorized by the persisted outcome, never a transient context error. Unknown transaction outcomes are resolved by rereading before cleanup or retry.
- Recover accepted pending cancellations to cancelled before the general startup SweepRunning failure pass; release T133 source bindings using their durable terminal timestamp, then settle open holds. Other interrupted running jobs still become failed under ARCH-11. Maintain startup order so settlement never treats an unresolved cancellation as success/failure.
- Add usage.OutcomeCancelled and immutable settlement breakdown columns on usage_admissions: settlement_reason, confirmed_charge_credits and cancellation_fee_credits, populated only when settling an open hold. R uses admission.HoldCredits (bounded by approved ceiling), never aggregate account balance; C uses confirmed micro-USD through existing pricing and charge code, capped at R, with zero override when no billable cost is confirmed. Compute the rounded half using integer division/remainder to avoid overflow.
- Keep provider usage_events append-only and unchanged. Hold refund follows existing original-lot allocation and settled_at guard; absence of an admission gives zero without inventing a hold. For master use the nominal hold for shadow C/fee/total and retain actual debit/refund zero, rather than incorrectly using its zero debited-lot sum as the shadow reservation.
- Extend QuoteClipGenerationResponse with policy version and cancellation rate/rounding semantics, bind policy version into the quote/approval digest and freeze it at start; invalidate old unconsumed quotes on this policy upgrade. Add presence-aware accounting fields for confirmed use, fee, settlement reason and nominal reservation, keeping existing final/refund fields compatible and historical unknown breakdowns absent.
- Policy activation follows T136: advertise cancellation availability and accept the new cancellation policy only for clients that echo its supported version after rendering its disclosure. Freeze legacy in-flight jobs to their prior settlement contract and offer no fee-bearing cancellation for them; older clients must refresh before starting a new AI attempt instead of silently approving a fee they never saw.
