## impl notes
- Paperlogy's official channel is the designer's release page (freesentation.blog/paperlogyfont) with the fonts-archive GitHub mirror; read both at implementation (ARCH-33), take the TTF from the official archive, record its SHA-256 and the OFL text in the assets directory, and note the source in `RENDER.md`; only 8 ExtraBold is bundled because CDS uses no other Paperlogy weight
- the Noto Sans KR fallback of CDS-17 never fires in the renderer: resvg runs with system fonts off and the coverage check refuses an unsupported glyph (T074), so the fallback is a FE preview concern; say so in `RENDER.md`
- cards are separate PNG plates on the overlay chain like copies, so their timing reuses the fade filters from T103; their contents come from the answers by reserved label (T104), never from model text except `hook`
- the sampler decodes PNG frames in Go (`image/png`) rather than parsing `signalstats`, so the luminance formula is one tested function and no FFmpeg text output is parsed
- three frames per unplated copy is the CDS-44 rule; a clip with ten `bold`/`mark` copies costs thirty single-frame extractions, well inside the media timeout, and the sampler runs during the same source callback that renders the cut so no second download happens (CLIP-33)

- V3's effective background for an UNPLATED style is the `stroke.dark` α0.85 outline composited over the scrim-washed footage, not the footage itself. Measured: white on bare footage is 1.00:1 over a white frame and already fails 4.5:1 above L ≈ 0.18, so crediting only the footage would replace 크게 강조 and 형광펜 with 깔끔하게 on ALL daylight footage — CDS-26 states the opposite intent outright ("the text stays white so contrast never depends on the accent"), and the 6/4 px outline CDS-25 and CDS-26 specify is what does the work (13.2:1 over a white frame). Consequence: with today's CDS-14 tokens CDS-44's "final pairing under 4.5:1 falls back to 깔끔하게" is unreachable for a correctly stroked style; the clause is implemented and fires for a style with neither plate nor stroke, and its own test uses such a style. **update-ssot CDS**: say which surface V3 measures an unplated style against, and if it really is the bare footage, then either the scrim rectangles have to cover the mid-frame anchors CDS-25 uses or the floor has to be WCAG's 3:1 for large text (every clip text is ≥ 44 px, far past WCAG's 24 px threshold)
- CDS-16 exempts a plated element from sampling, so V3's "plate composited at its α over the sampled mean" branch has no sample to read: a plated element is verified against its own token pairing instead, which CDS-16 already certified and `TestContrastArithmeticAndTheTokenPromises` now asserts for every plated style over a WHITE frame (13.58:1 and 14.89:1, both well past the floor). Sampling stays exactly where CDS-44 puts it — `bold` and `mark` only
- CDS-28's 9:16 card is x 144–936, sixteen pixels past CDS-9's x ≤ 920 on each side. The plate sits there and its TEXT does not: V1 exempts only the `card` kind, `measureCard` checks the padded band the lines are set in against the safe area and the plate against the frame, and the 40 px padding is what makes both true (text spans x 184–896). **update-ssot CDS**: either state the exemption in CDS-9/CDS-28 or narrow the card to 792 → 776
- CDS-44's accent-to-white applies to 크게 강조's word only. 형광펜's accent is the marker stroke BEHIND white text, so whitening it would paint white on white; the highlight keeps the accent on every ground and the goldens pin both behaviours
- CDS-28's category chip is `#111` ink as written, i.e. `ink_900`'s hex — not the `text.ink` token (#1A1A1A), which is 4.40:1 on the violet accent and would fail V3. Every accent clears the floor against #111 (worst: violet 4.77:1)
- the SVG asks for `font-family="Paperlogy 8 ExtraBold"`, the family name the file itself declares, not the bare `Paperlogy` of the acceptance line: resvg matches the declared family and system discovery is off, so the bare name would find nothing.
