# T183 A group holding a required field admits at least one item
> st:todo | ssot:CLIP-119 CLIP-61 CLIP-102 | base:CLIP@27 ARCH@2 | dep:-

## goal
Give every repeated item group an effective minimum — its declared one, or one when it holds a required field — and refuse an empty group at generation admission by the group's own name.

## acceptance
- [ ] the effective minimum is computed once in the composition grammar: the declared `min`, else 1 when any field of that group is `required`, else 0
- [ ] the TypeScript grammar owner returns the same number for the same template, pinned by the shared corpus the way T179 pinned the maxima
- [ ] the owner's group controls open at the effective minimum rather than the declared one, and a group that admits any number still admits any number above it (→CLIP-61)
- [ ] generation admission refuses a group below its effective minimum with the group's owner-visible name, the limit and the actual count, through the existing `items_required` shape rather than a new failure code (→CLIP-102)
- [ ] a template saved before this rule still loads and is refused only at admission, never at template load (→CLIP-119)
- [ ] tests: the effective number per group shape in both grammars, the admission refusal naming the group, and a legacy template that loads and then fails admission
- [ ] verify BE (ARCH-26) and FE (ARCH-25) pass

## impl notes
- `composition_state.go:230` already raises `items_required` against `Group.Min`; this task changes what that comparison reads, not where it lives, so the quote path and the save path inherit it
- the number belongs beside `Document.Maxima` (T179): one derivation the input control, the admission check and the writer all read, never three
- carry the group's owner-visible name into the refusal parameters the way T181 carried a field label; `formatAppFailure` already special-cases `items_required`
- no migration — this is a read-time rule over stored template text, and no stored project is rewritten
