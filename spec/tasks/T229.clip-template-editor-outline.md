## goal
Make the video-template editor name, description and one body draft shared by a block builder and 원문, with the outline's entries added, reordered and deleted in order and no design selection anywhere on the screen.

## acceptance
- [ ] `CompositionDesignStep` and the `designReady` save gate are gone from `ClipTemplateEditor`; a template saves with no design chosen
- [ ] the builder lists the outline in document order and adds, reorders and deletes entries across kinds — stage, intro/caption/outro text, badge, field, group, guide
- [ ] `composition-skeleton.ts` retires with the preset rebuild: no `CompositionDesign`, `compositionSkeleton`, `compositionDesign` or `rebuildCompositionSkeleton`, and no caller left behind
- [ ] ①'s own preset and caption-style previews still render (`ClipDesignSelection` imports `CompositionDesignThumbnail` today)
- [ ] the editor preview draws the regions in the shared default presets and says in one line that the clip's own design decides the real shape
- [ ] switching builder ↔ 원문 stays lossless over the one draft (TMPL-26's rule, unchanged)
- [ ] ①'s answer control folds the project's own preset back into a field's maximum where that answer reaches a region slot (CLIP-117; T227 left the parser unable to know the preset)
- [ ] tests: saving a body with no design attributes, adding and reordering entries, an outline round-tripping through both modes, and ①'s previews still rendering
- [ ] ARCH-25 verify clean, FE self-audit per ARCH constraints

## impl notes
- `CompositionDesignThumbnail` must survive T227's retirement of `compositionSkeleton`: give it its own small preset-sample builder inside `entities/clip-template/lib` that takes the preset id directly, since ① is now its only caller and ① knows the preset.
- the preview's default presets are the shared defaults (intro b, outro e) — the same fallback `ProjectDesign.RegionPresets()` uses — so a template author and a project owner never see two different "defaults".
- the builder's row order IS the outline order: reordering writes the body through the existing `patchCompositionSource`/`ReplaceNode` path, never a second representation (TMPL-2's rule, which CLIP-42 inherits).
- parallel sessions share this tree: `frontend/src/app/providers/i18n/resources/{ko,en}/clips.ts` is also edited by T230 and T232 — stage explicit paths and expect to rebase that one file.
