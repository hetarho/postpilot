# T379 Media bytes cross stages through authorized private artifacts
> st:todo | ssot:ARCH-6 ARCH-7 ARCH-46 ARCH-47 ARCH-48 ARCH-49 CLIP-21 CLIP-29 CLIP-32 CLIP-33 | base:ARCH@11 CLIP@44 | dep:T376 T378

## goal
Give a leased worker bounded access to its inputs and reserved outputs without passing media through RPC or distributing storage credentials.

## acceptance
- [ ] An input read is signed only for an object bound to the current stage and authorized owning attempt; a caller cannot substitute another user's key, an expired original or an unrelated source.
- [ ] Output slots are reserved durably before URLs are returned, under an attempt-specific immutable key; the reservation is idempotent and upload credentials expire and can be refreshed only by an active lease.
- [ ] Completion verifies every required uploaded artifact's existence, declared size, type, ordinal and current attempt binding; incomplete, oversized, overwritten or foreign outputs cannot wake the parent.
- [ ] Analysis artifacts preserve the existing chunk-duration, dimension, per-copy and aggregate-byte limits; render artifacts obey the existing final-output limits and never reuse an analysis copy as footage.
- [ ] Accepted artifacts survive an API restart and stay protected while the owning job uses them; unaccepted/stale uploads can be identified for T383 cleanup even if the worker never reports.
- [ ] MinIO integration and fake-storage tests cover direct PUT/GET, missing/expired access, reservation/response loss, conditional-write collision, size/type mismatch, cross-owner/attempt references and no secret-bearing logs; ARCH-26 and generated-code checks pass.

## impl notes
- Add clip-owned `clip_media_artifacts`: id, stage_id, attempt_id, logical slot/source/chunk ordinal, object_key, kind, expected/actual bytes, content_type, worker-computed digest, state and timestamps; unique(attempt_id, slot). Persist a deletion request before losing the row that identifies an uploaded object.
- Use a new private analysis prefix `clip-media/` and the existing clip.ResultPrefix for delivered-file candidates so ordinary result signing and deletion remain valid. All keys are API-generated and attempt-specific; the worker never supplies an arbitrary key.
- Extend the existing storage.Bucket adapter behind narrow clip-owned access/head/delete ports. Use short-lived presigned GET and conditional PUT, retaining the existing If-None-Match protection; return all required signed headers explicitly.
- Set access TTL to the lesser of 10 minutes and the remaining stage deadline; current-lease authorization controls refresh, not merely knowing an artifact id. Expiry of an already issued URL is not cancellation revocation, so all subsequent acceptance still checks the durable fence.
- Use a worker-reachable storage endpoint, independent of the browser endpoint and API-local MinIO name. Add MEDIA_STORAGE_ENDPOINT defaulting to R2_ENDPOINT; in dev it is http://minio:9000, while R2 uses its normal external endpoint. Never rewrite a host inside an already signed URL.
- An output reservation includes exact byte length and content type after encoding; completion HEAD checks storage metadata, while the worker supplies measured media properties and SHA-256. Do not treat an S3 ETag or an unverified custom metadata field as a content hash.
- Preparation results are an ordered manifest of all verified source metadata and missing-observation chunk artifacts; chunk ordinals and offsets are checked against the frozen source manifest before credit reservation.
- Allocate/read/check storage outside SQLite transactions, then atomically recheck current lease, parent eligibility and artifact reservations before accepting the result. T381/T382 will wake the parent in the same transaction; until then return the immutable accepted receipt only.
- Official reference checked 2026-09-25: https://developers.cloudflare.com/r2/api/s3/presigned-urls/ . Keep production validation against R2 as well as local S3-compatible tests.
