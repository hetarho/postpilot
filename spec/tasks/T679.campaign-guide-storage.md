## goal
A post persists its 체험단 글 switch, advertiser guide and checklist ticks through presence-aware draft saves, new posts starting with the switch on.

## impl notes
- Bounds (typed constants in `internal/campaign`): `ADVERTISER_GUIDE_MAX_CHARS` 3000 Unicode scalar values after trim; `ADVERTISER_KEYWORD_MAX` 10 keywords, each trimmed, non-empty, ≤ 40, duplicates (case-insensitive, spaces ignored) collapsed to the first; hashtags ≤ `POST_TAG_OUTPUT_MAX` (30), each with a leading `#` stripped, ≤ 40, same dedupe; `MinChars` within `POST_TARGET_LENGTH_MIN`…`MAX` (100…10,000); `MinPhotos` 1…`UPLOAD_MAX_PHOTOS_PER_POST` (30). The package imports nothing from `post` or `clip` so the clip context can reuse it (T690).
- Proto (`post.proto`, next free field numbers): `message AdvertiserGuide { string text = 1; repeated string keywords = 2; optional int32 min_chars = 3; optional int32 min_photos = 4; repeated string hashtags = 5; }`, `message ChecklistTicks { repeated string lines = 1; }`; `Post` gains `bool campaign`, `AdvertiserGuide advertiser_guide`, `repeated string checklist_ticks`; `SavePostDraftRequest` gains the three optional fields. Ticks are stored as given (trimmed, distinct, ≤ 200 lines, each ≤ 500).
- Service: extend `DraftSave` (service.go:294) and `SaveDraft` (:152) with presence handling like `voice_id`; store adds the columns to `UpdatePostDraft`/read queries (`store/queries/posts.sql`) and `InsertPost` sets `campaign = 1`. JSON columns are encoded/decoded in the store.
- Failure reasons join the shared failure catalogue on both sides; the FE catalogue keys land in T680.
