# T089 Guideline candidate disclosure with bulk review

## goal
Move the 후보 queue below the saved list as a closed, counted disclosure and let the whole queue be accepted or dismissed at once.

## acceptance
- [ ] the queue renders below the saved list as a `<details>` closed by default whose summary carries the pending count, and renders nothing when nothing waits and the queue has room, and nothing on a failed candidate read
- [ ] a full pending queue says so from the server's `queue_full`, with no client copy of the bound, and the disclosure appears for that reason even with no rows
- [ ] rows keep the server's review order, their text, the occurrence count above one, the source link or its plain-text fallback, and the per-row 승인 / 무시 pair
- [ ] `전부 수락` and `전부 거절` sit once at the head of the open disclosure, are absent when there are no rows, and hold their box while running
- [ ] `전부 수락` creates one guideline per listed pending candidate with 전역 scope and `from_candidate_id`, in order, keeping every one that passes
- [ ] a refused candidate (over 300 characters, duplicate, account cap) stays in the queue with its catalogue reason shown on its own row, the run continues past it, and a single 승인 on that row still works
- [ ] `전부 거절` asks once through `Dialog` naming the count and then dismisses every listed candidate; a single 무시 stays dialog-free
- [ ] both bulk actions re-read the candidate list when they finish and `전부 수락` also invalidates the saved list
- [ ] a finished run reports itself in a live region at the head of the disclosure, stating how many were saved and how many were left behind
- [ ] tests cover the closed default with its count, the empty and queue-full states, a bulk approve that is entirely accepted, one that is partly refused (reason on the right row, the rest saved, the run not aborted), the bulk dismiss confirmation and its cancel path
- [ ] ARCH-25 passes

## impl notes
- no proto or backend change: bulk approve is `useCreateGuidelineCall` per row (`from_candidate_id`, `globalScope()`) and bulk dismiss is `useDismissGuidelineCandidateCall` per row, both already exported from `entities/guideline`
- run the calls sequentially, never in parallel: the pending-count, dedupe and cap checks all run inside one transaction per create, and concurrent creates race the cap
- the two new triggers live in `features/review-guideline-candidate` beside the existing per-row buttons; the failure map (`candidateId → message`) is page state in `pages/guidelines` — the bulk trigger reports failures through a callback and each row is handed its own message, so a feature never owns another row's state
- reuse `guidelineErrorMessage` for every refusal; predict nothing client-side (GUIDE-24)
- the candidate list the bulk action iterates is the one currently rendered; a candidate that has since become terminal answers `NotFound`, which is an ordinary per-row refusal and must not abort the run
- model the disclosure on the closed 삭제된 말투 `<details>` in `VoicesPage` — a `min-h-11` summary with the pointer cursor and `select-none`, so it clears the coarse floor
- `Dialog` for the bulk dismissal only; keep the existing `DismissGuidelineCandidateButton` unchanged
- new `guidelines` i18n keys in ko and en: the two trigger labels, the summary with its count, the dismissal dialog's title and explanation, and a bulk result line stating how many were saved and how many were left
