# T912 Fold post guide hashtags into the guide text and drop their storage
> st:doing@261119.advg1119 | ssot:POST-118 POST-117 GEN-88 | base:POST@57 GEN@35 | dep:- | touches:backend/internal/platform/db/migrations backend/internal/post/store backend/internal/post/rpc/handler.go proto/postpilot/v1/post.proto | lane:- | explore:- | run:claude/opus@high

## goal
A post's advertiser guide stores no hashtag list: every stored `advertiser_hashtags` entry moves into the guide text as a `#tag` token, the column goes, and the post API carries no post hashtags.

## acceptance
- [v] a new goose migration appends each stored post hashtag its `advertiser_guide` text does not already hold to that text as a `#tag` token (space-separated, on a new last line), then drops `posts.advertiser_hashtags`; a post with `[]` or with every hashtag already in its text keeps its text byte-for-byte — unit test on a small fixture DB (owner: implementer, stage: unit)
- [v] the post store reads and writes no hashtags; sqlc output regenerated from ASCII-only `.sql`; `migration_creation_lineage_test.go` and the affected store tests updated — `go test -count=1 ./internal/post/... ./internal/platform/db/...` (unit)
- [v] a post draft/option save whose `AdvertiserGuide.hashtags` is non-empty is refused with the existing advertiser-guide invalid-argument refusal naming the hashtags field; a GetPost returns an empty `hashtags`; a clip save still accepts and returns its hashtags (CLIP-210) — existing `post/rpc/campaign_test.go` and `clip/rpc/campaign_test.go` extended (unit)
- [v] `go vet` and the backend task-tier commands of ARCH pass for the touched packages (unit)

## impl notes
- migration: next free number after `0170_photo_observation_tests.sql`; keep the file ASCII-only (sqlc reads migrations; a Hangul byte breaks codegen). Shape: `UPDATE posts SET advertiser_guide = advertiser_guide || CASE WHEN advertiser_guide = '' THEN '' ELSE char(10) END || (SELECT group_concat('#' || value, ' ') FROM json_each(posts.advertiser_hashtags) WHERE instr(posts.advertiser_guide, '#' || value) = 0) WHERE EXISTS (SELECT 1 FROM json_each(posts.advertiser_hashtags) WHERE instr(posts.advertiser_guide, '#' || value) = 0);` then `ALTER TABLE posts DROP COLUMN advertiser_hashtags;`. Stored hashtags have no leading `#` (`campaign.Normalize` strips it). Before the DROP, `rg -n advertiser_hashtags backend/internal/platform/db/migrations` for an index, trigger or view naming the column (SQLite refuses the drop then). Down re-adds the column `TEXT NOT NULL DEFAULT '[]'` (data not restored).
- the appended text may exceed `ADVERTISER_GUIDE_MAX_CHARS` (3000) on a long guide: do not truncate in the migration (no data lost); the owner's next text edit meets the existing save limit. Pre-alpha data (prod post 20261119-untitled measured with `advertiser_hashtags = []`).
- `backend/internal/post/store/queries/posts.sql`: drop the column from every SELECT/INSERT/UPDATE; regenerate sqlc (the repo's sqlc command; see `backend/` Makefile or ARCH). `store.go` around lines 160–175 (write) and 1410–1420 (read) stop marshalling/unmarshalling hashtags.
- `post/rpc/handler.go` ~860–895: the post guide conversion refuses a non-empty `GetHashtags()` before `Normalize` (reuse the guide's existing field error with `campaign.FieldHashtags`), and the outbound message never sets `Hashtags`. `campaign.Guide` keeps its `Hashtags` member — clips use it (CLIP-210, `backend/internal/clip/...` untouched).
- `proto/postpilot/v1/post.proto` `AdvertiserGuide.hashtags` stays (shared with clips; field 5 not removed): update its comment to say a post never carries it (POST-118) and only a clip's guide does (CLIP-210); regenerate with the repo's proto gen (gen.mjs normalizes EOF — never hand-edit generated files).
- the frontend stops sending post hashtags in T913; T913 and this task land in the same batch, so the refusal never meets a released client that sends them.
- generation still reads `campaign.Guide.Hashtags` until T914 removes the post-side rendering; after this task it is always empty for posts.
- no paid AI call is needed or allowed for verification.
