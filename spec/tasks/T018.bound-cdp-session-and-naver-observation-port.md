# T018 The bound CDP session and the deterministic Naver observation port
> st:todo | ssot:PUBLISH-20 PUBLISH-24 PUBLISH-16 PUBLISH-17 PUBLISH-19 | base:PUBLISH@2 ARCH@1 | dep:T005

## goal
Implement the read-only half of `naver.Port` — a full `Snapshot` observed from the live SmartEditor over one bound CDP target — and correct the versioned locator set against the real editor, so the deterministic publisher can finally see the page T005 was written against.

## acceptance
- [ ] `browser` exports a bound single-page CDP session (attach, page URL, one reviewed-script evaluation, full accessibility snapshot, page-scoped DOM query, recheck) and carries no SmartEditor knowledge; no exported method accepts a selector, script, coordinate or key sequence originating outside the agent module
- [ ] `Observe` binds every call to the one dedicated page: the target id, its `/json/list` entry and the page URL are rechecked immediately before and after the observation, and a target switch, an added or removed page, or a URL outside the Naver host allowlist returns a poisoned run rather than a snapshot
- [ ] the snapshot reports `TargetID`, `URL` (exact `https://blog.naver.com/PostWriteForm.naver…` form the publisher requires), `AccountID` read from the page's own blog identity, and `SignatureID` from the versioned manifest
- [ ] `Title`, `Body` (the exact ordered TEXT/HEADING/QUOTE/LIST/IMAGE sequence with level, items, ordinal, caption and uploaded state), `ImageCount`, ordered `Tags`, and `Category`/`Visibility` as `{ID, Name, Selected}` are read from DOM plus full accessibility evidence, identifying category, visibility and tags by role and state rather than label text alone, so a body paragraph equal to a setting label is neither truncated nor mistaken for a control
- [ ] `LocatorMatches` holds the true match count per `MutationKind` — 1 exactly when one reviewed control resolves, and the real count when a control is missing, renamed or duplicated — and `UnversionedPublishLikeControls` counts publish-like controls outside the versioned allowlist, `NativeDialogOpen` reflects an open native dialog
- [ ] `Auth` distinguishes `ready`, `login`, `captcha` and `two_factor` from page evidence and never attempts a bypass
- [ ] `Token` is a deterministic digest of the observed projection, so two observations of an unchanged editor are equal and any observed change differs — the property `mutate` relies on to reject a mutation that changed nothing
- [ ] every locator in `naver/compatibility.json` resolves exactly once against the owner's real signed-in SmartEditor; the known-wrong `visibility` locator is corrected, `signature_id` is bumped, and setup's probe still arms the existing connection against the corrected manifest
- [ ] table-driven tests against a fake CDP server cover: each locator missing, renamed and duplicated; a second page appearing mid-observation; a target id change; a URL leaving the allowlist; each auth state; an open native dialog; an unversioned publish-like control; a body paragraph equal to a category or visibility label; token equality across an unchanged editor and inequality across every changed field
- [ ] ARCH-27 passes

## impl notes
- placement: the port implementation lives in `agent/internal/naver` (new `port.go`), NOT in `agent/internal/browser`. `naver` already imports `browser` for the probe and `Port` returns `naver.Snapshot`, so putting it in `browser` would be an import cycle. This also matches `Port`'s own contract comment — "its implementation owns the reviewed SmartEditor locator set" — and the locator set already ships as `naver/compatibility.json`. `browser` stays the narrow, editor-agnostic CDP boundary PUBLISH-20 describes
- `browser` gains one exported type wrapping the existing unexported `cdpClient`, `discoverSinglePage` and `noProxyHTTPClient`; reuse them rather than opening a second connection per observation. `InspectCompatibility` should end up sharing that type instead of keeping its own copy of the attach sequence
- one observation = one `Runtime.evaluate` of a package-level const script plus one `Accessibility.getFullAXTree`, fenced by a recheck on both sides. Do not read the DOM control by control: a partial read across a mutating page is exactly the stale evidence PUBLISH-20 forbids
- `Token`: hex SHA-256 over a canonical serialization of the whole projection (target id, URL, account, signature, auth, title, the body sequence, image count, tags, category, visibility, locator matches, unversioned count, dialog flag). A monotonic counter is wrong here — `Publisher.mutate` fails closed when `before.Token == after.Token`, so the token must be content-derived or that check stops catching a no-op mutation
- the snapshot must satisfy `Publisher.observe`'s invariants or every run fails closed: `SignatureID` equal to the manifest's, non-empty `TargetID` and `Token`, `URL` prefixed `https://blog.naver.com/PostWriteForm.naver`, `UnversionedPublishLikeControls == 0` and `NativeDialogOpen == false` on a healthy editor
- the corrected visibility locator: the live editor renders visibility as `label[class^="radio_label__…"]` wrapping `전체공개 · 이웃공개 · 서로이웃공개 · 비공개`, not `[role=radio]` as the manifest still claims (`compatibility.go`'s probe was already corrected the same way). Verify all eleven against the real editor in one pass rather than trusting the file
- the reviewed observation script may read only the editor surface. It never reads cookies, storage or credentials, and its output is data — no returned string is ever evaluated or used as a selector
- the account identity is the blog id Naver itself selected (T004's `resolveAccountWriter` already establishes it); never parse it from user input or page prose
- live verification is read-only and needs no publish: PUBLISH-8 already permits opening the account's own writer without typing, uploading or publishing. Use the owner's existing armed connection `5fd6571…`, and do not type into or submit the editor in this task
