# T067 The list dock stays at every width
> st:todo | ssot:THEME-24 POST-64 | base:THEME@8 POST@5 ARCH@2 | dep:-

## goal
A list's add action stays docked at every width, right-aligned at its natural width from `sm:`.

## acceptance
- [ ] `ActionBarDock` drops `'phone'` and gains `'list'`: sticky at every width, full-bleed on a phone, right-aligned at its natural width from `sm:`; `'always'` is unchanged
- [ ] `/posts`, `/voices` and `/templates` pass `dock="list"` and their CTA is `w-full sm:w-auto`
- [ ] no call site or type mentions `'phone'` any more
- [ ] the bar still clears the phone tab bar and the safe area, still floats a step clear of what is under it, and stays one element per action
- [ ] the primitive's doc comment states the new rule (the current text argues for the phone-only dock and would contradict THEME-24)
- [ ] `ActionBar` test: the `list` dock keeps its sticky, plane, radius and shadow classes at every width and resets none of them from `sm:`
- [ ] each of the three page tests still finds exactly one add action, inside the bar
- [ ] ARCH-25 gates green

## impl notes
- THEME-24✎ (r8) is design language, so this lands on all three list pages, not only `/posts`; `/voices` (VOICE-52) and `/templates` (TEMPLATE-24) need no SSOT revision — "one docked CTA" stays true of both
- `list` = today's `always` classes plus `sm:ml-auto sm:w-fit`; that is what keeps a natural-width bar from being the full-width card the retired rule objected to
- `'phone'` is deleted rather than kept as an alias ← THEME-10 forbids an unused variant, and a second name for the same treatment is what the next reader has to disambiguate
- `mt-auto` stays on the caller, so a short list still pushes the bar to the bottom of the viewport rather than leaving it under the last row
- `frontend/src/shared/ui/action-bar/ActionBar.tsx` is the only primitive touched; nothing in `features/review-model-experiment` or the editor uses `'phone'`
