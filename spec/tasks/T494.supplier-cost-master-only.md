# T494 Supplier cost and the credit conversion never reach a non-master

## goal
No non-master RPC response, screen, error or mail carries supplier cost (USD prices, provider cost, model-named rates, provider prose) or the credit↔KRW conversion (FX rates, temporary-rate status); master keeps them, and a descriptor-walking test keeps it that way.

## acceptance
- [ ] `ModelInfo` has no `input_usd_per_million`, `output_usd_per_million` or `pricing_checked_at` (numbers and names reserved); `ListModels` returns no price for any caller; the /ai-models selector and comparison candidate meta line shows context only
- [ ] `ClipPricedCall` has no USD price fields (reserved); the four clip quote RPCs send label and call count only
- [ ] `CandidateUsage.cost_microusd`/`cost_source` and `LeaderboardEntry.total_cost_microusd`/`cost_quality` are populated only when the acting plan is master; the comparison reveal and the leaderboard render cost only for a master session (a non-master sees tokens and latency, no cost and no "비용 미제공")
- [ ] `GetMyPlan` omits `fx_rate` and leaves every `EstimatorCombo.observe_label`/`write_label` empty for a non-master; quote `rate` and `ClipAccounting.rate` are omitted for a non-master on the four clip quote RPCs, `GetClipProject` and `CancelClipJob`; /plans, the billing screen, the clip approval panel and the settlement panel show their FX line only when a rate is present (master)
- [ ] `Failure.technical_detail` is empty for a non-master caller on `GetGeneration`, the post projection, experiment candidates and voice checks; the reason's product copy still renders
- [ ] user copy names no exchange rate or AI-cost denomination: `AI_FX_RATE_UNAVAILABLE` ko/en, the billing `fxUnavailable` notice and the plans `estimator.fxUnavailable` notice are rewritten; purchase and charge mails carry no USD amount or rate
- [ ] `backend/internal/auth/rpc` gains a descriptor-walking test: for every procedure outside `masterProcedures` it walks the response message graph and fails on any field whose name matches the cost pattern unless the field is in an explicit allowlist with a one-line reason; every allowlisted master-populated field has a handler test proving a non-master gets it empty
- [ ] tests: provider/clip/experiment/plan/job/post/voice handler tests for non-master emptiness and master presence; FE tests that a non-master sees no price, cost or FX line on /ai-models, /ai-models/compare, the leaderboard, a revealed comparison, /plans, /billing and the clip panels, and a master still sees cost and FX
- [ ] ARCH-25, ARCH-26 and ARCH-28 pass

- proto removals use `reserved <n>; reserved "<name>";` in `provider.proto` (ModelInfo 8, 9, 10) and `clip.proto` (ClipPricedCall 7, 8). Re-read the files before editing: another session may have touched them. Regenerate with `pnpm gen:proto`.
