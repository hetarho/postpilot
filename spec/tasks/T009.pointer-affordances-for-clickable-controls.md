# T009 Pointer affordances for clickable controls
> st:done@260905 | ssot:THEME-36 | base:THEME@2 ARCH@1 | dep:-

## goal
Make every enabled pointer-activated surface use the pointer cursor without feature-local opt-ins, while disabled controls, text inputs and drag handles keep truthful cursor feedback.

## acceptance
- [v] destination links, enabled native buttons and selects, disclosure summaries, enabled checkbox/radio/file inputs and their labels, and enabled ARIA button/tab/menuitem/menuitemradio/option/radio/checkbox controls compute to `cursor: pointer`
- [v] disabled native controls and every `aria-disabled="true"` interactive surface compute to a non-pointer cursor and remain behaviorally disabled
- [v] text inputs and textareas retain the text cursor; the template sortable-list drag handle retains `grab` and its active drag feedback
- [v] the rule is owned once by the global app stylesheet; feature and primitive code need no new cursor opt-ins, while a specialized cursor utility may override the zero-specificity global default
- [v] a focused test imports the production stylesheet and asserts representative enabled, disabled, text and specialized-cursor elements through `getComputedStyle`
- [v] `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` pass on Node 24.18.0

## impl notes
- add the interactive cursor selectors in `frontend/src/app/styles/index.css` beside the existing touch-action and focus-visible base rules; wrap selector groups in `:where(...)` so Tailwind utilities such as `cursor-grab` can override the default without specificity tricks
- cover `a[href]`, `button`, `select`, activation-oriented input types and labels, `summary`, and the ARIA roles used by the design system; exclude disabled native controls and `[aria-disabled='true']` from the pointer group, then give disabled controls the ordinary default cursor without removing their existing event guards or native disabled semantics
- do not apply pointer to generic labels, text inputs, textareas, containers with `onClick`, or elements merely carrying `tabIndex`; semantics, not an event handler alone, define the interactive set
- place the stylesheet test beside the app styles; add no dependency, design token, config value or new frontend slice

## result
- `frontend/src/app/styles/index.css` now owns zero-specificity semantic cursor defaults for enabled pointer controls, file-picker labels, text editing and disabled controls; the upload feature's two local pointer opt-ins were removed.
- The sortable-list handle now exposes `grab` and `active:grabbing`; its specialized utility continues to override the global default.
- `frontend/src/app/styles/interaction-cursors.test.ts` exercises ten computed-style cases against the production stylesheet.
- Verified on Node 24.18.0: focused cursor test (10), full frontend suite (129 files / 988 tests), ESLint, Prettier, FSD, style probe (61 cases), style lint and the production web build all pass. Vite reports only its existing advisory that the main chunk exceeds 500 kB.
