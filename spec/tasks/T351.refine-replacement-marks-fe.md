# T351 ② marks replacement spans over the title, tags and body, and taking one is a manual edit
> st:todo | ssot:POST-79 POST-80 GEN-53 GEN-54 QUAL-19 QUAL-21 ARCH-3 ARCH-18 ARCH-20 ARCH-24 THEME-23 | base:POST@11 GEN@10 QUAL@3 ARCH@9 THEME@17 | dep:T349

## goal
- A stored replacement candidate renders on ② as a pressable mark while its source still stands at its surface and index. A press lists up to 3 phrases, and taking one is an ordinary content save that records no provenance. A published post shows no marks.

## acceptance
- [ ] In ②'s read view, each candidate whose source still stands marks the first occurrence of that source.
  - The places are `content.title` (TITLE), `tags[index]` (TAG), and at BODY `blocks[index]` when that is a TEXT block without a slot, a HEADING or a QUOTE, or a LIST, where the mark goes in the lowest-numbered item that contains the source.
  - Any other candidate renders nothing and says nothing (GEN-53).
- [ ] Two candidates overlapping at one place keep the first in answer order.
- [ ] A candidate shows at most 3 phrases (GEN-54).
- [ ] A TAG phrase whose result would canonically duplicate another tag is not offered. A candidate left with no phrase is not marked.
- [ ] A press, Enter or Space on a mark opens its panel (T328 `InlinePopover`). Hover opens it too, but only under a fine pointer.
  - The panel names the source and lists each phrase as a button.
  - It carries one line that states only what was observed about the phrases, never what they improve, and never implies a whole post was read (QUAL-19, QUAL-21).
- [ ] Taking a phrase is exactly a manual edit (POST-80).
  - It replaces that occurrence in the editor's content and goes out through the existing content queue as `SavePostContent { slug, content, expectedRevision }`, with the revision the editor holds and nothing else.
  - The revision moves once, and a finalized post returns to 검토.
  - No member, field or row records that the text came from a suggestion.
- [ ] After a take:
  - the taken mark is gone, because its source no longer stands there;
  - a neighbouring candidate whose source still stands stays marked;
  - focus moves to the 수정 pencil of the header or block that held the text.
- [ ] Opening and closing a mark, or never pressing one, sends nothing (POST-79).
- [ ] A block or header editor that is open shows plain fields with no marks.
- [ ] Editing a source away drops its mark. The stored candidates are left as they are; the drop happens at render.
- [ ] No mark renders on a published post, on a post with no candidates, or in any `BlockList` given no `renderText`, which includes the export preview (R39).
- [ ] Under `pointer-coarse:` a mark on a tag chip keeps a hit area of at least 44 × 44 px (THEME-23, R37).
  - A mark inside a sentence takes WCAG 2.5.8's inline exception, and `ReplacementMark`'s doc comment says so.
- [ ] Tests:

  - new `entities/post/api/replacement-mappers.test.ts`: every generated `ProtoReplacementSurface` other than UNSPECIFIED maps both ways, and UNSPECIFIED and `9_999` give undefined (the `verdict-badges.test.ts` shape).
  - `entities/post/api/post-queries.test.ts` (created by T349): 'maps replacement candidates and drops one with an unknown surface'.
  - `entities/post/ui/BlockList.test.tsx`:
    - new 'renders every text through renderText with its place';

    - new 'never passes a slot TEXT block'.
  - `pages/editor/ui/EditorPage.test.tsx`: new describe 'the replacement marks':
    - 'marks the title, a tag and a TEXT block';
    - 'offers at most three phrases and no duplicate tag';
    - 'saves a take with the expected revision and returns 확정 to 검토';

## impl notes
- Wire and storage:
  - From T322: `Post.replacement_candidates = 30`, `ReplacementCandidate { surface; index; source; phrases }` and `ReplacementSurface { UNSPECIFIED, TITLE, TAG, BODY }` (TS `ProtoReplacementSurface.TITLE` and so on). `index` is the tag index for TAG, the block index for BODY and 0 for TITLE.
  - T341 stores the candidates from a write answer. A revision and a manual `SavePostContent` keep them, so after a take the stored list still holds the taken candidate, and this task drops it at render.
  - The containment rules are T330's `ValidateReplacements` contract (exact substring, title index 0, a slot is never a surface, a LIST matches on any item), and `visibleSpans` mirrors them.
- `shared/api/index.ts` adds to its `post_pb` exports `ReplacementSurface as ProtoReplacementSurface` and `ReplacementCandidateSchema`, which the fake needs, plus the type `ReplacementCandidate as ProtoReplacementCandidate`.
- New `entities/post/model/replacements.ts`. It is pure (ARCH-18): no React, only `shared/api` types, `BlockType` and `./content` helpers.
  - `type ReplacementSurface = 'title' | 'tag' | 'body'`.
  - `interface ReplacementCandidate { surface: ReplacementSurface; index: number; source: string; phrases: string[] }`.
  - `type TextAt = { surface: 'title' } | { surface: 'tag'; index: number } | { surface: 'body'; index: number; item?: number }`, where `item` is set only for a LIST.
  - `interface ReplacementSpan { at: TextAt; start: number; end: number; source: string; phrases: string[] }`.
  - `visibleSpans(content, candidates): ReplacementSpan[]`, `spansAt(spans, at)` (sorted by `start`), `applyReplacement(content, span, phrase): PostContent` and `canonicalTag(tag)`.
- `visibleSpans` walks the candidates in answer order:
  1. It resolves the text at the candidate's place by the placement rules in acceptance, and an out-of-range index drops the candidate.
  2. A blank source drops it. `start = text.indexOf(source)` is the first occurrence, case-sensitive, like Go's `strings.Contains`, and `-1` drops it.
  3. Phrases are deduplicated, with a blank one or one equal to the source dropped.
  4. For TAG, a phrase is dropped when `canonicalTag(tag.slice(0, start) + phrase + tag.slice(end))` equals `canonicalTag` of any other tag.
  5. The phrases are sliced to 3, and a candidate with none left is dropped.
  6. A span overlapping one already accepted at the same place is dropped. The same place means equal `surface`, `index` and `item`.
- `canonicalTag` mirrors `backend/internal/post/content_edit.go` `ValidateContent` exactly: `tag.split(/\s+/).filter(Boolean).join(' ').replace(/^#+/, '').trim()`, case kept. A take that duplicated a tag would be refused as `POST_CONTENT_INVALID`.
- `applyReplacement` splices `phrase` over `[start, end)` at `span.at`. It rebuilds through `postContentWith` and `blockWith`, with `items[item]` for a LIST, and never mutates its input.
- New `entities/post/api/replacement-mappers.ts`:
  - `replacementSurfaceFromProto(value): ReplacementSurface | undefined` and `replacementSurfaceToProto(surface)` over a `Record` plus the reverse `Map`, with no `default` branch (ARCH-3);
  - `toReplacementCandidate(candidate): ReplacementCandidate | undefined`.
- `PostDraft.replacementCandidates: ReplacementCandidate[]`. `toPostDraft` drops a candidate with an unknown surface, because a dropped offer changes nothing (GEN-53), which is a drop rather than a fallback value.
- `entities/post/index.ts` exports:
  - `visibleSpans`, `spansAt` and `applyReplacement`;
  - the types `ReplacementCandidate`, `ReplacementSpan` and `TextAt`.
- `entities/post/ui/BlockList.tsx` gains `renderText?: (text: string, at: TextAt) => ReactNode`, defaulting to the identity.
  - It wraps `content.title` as `{ surface: 'title' }` and each tag chip's text after the `#` as `{ surface: 'tag', index }`.
  - It wraps the content of a TEXT block without a slot, a HEADING or a QUOTE as `{ surface: 'body', index }`.
  - It wraps each LIST `<li>` as `{ surface: 'body', index, item }`.
  - `SlotRow`, captions, alt text and the summary never go through it. The export preview and T339's published view pass none, so they render exactly as today.
