## goal
Give the operator a separate speech-profile catalog and give owners an eligible, explicit voice-creation model choice.

## acceptance
- [ ] Master can curate a profile with explicit design/speech refs, immutable compatible binding/settings, revision, classification, Korean/custom-voice capabilities and applicable unit-price evidence; non-master writes are refused.
- [ ] The creation picker projection shows model labels, grade, required plan, availability and limits, with no default selection or supplier prices; contract tests assert price/key/account-state absence for both master and ordinary owners.
- [ ] Existing five-purpose models-v1 export/preview/apply, recommendation sets, selection memory and completion catalog refresh behave unchanged; speech curation never delists or attributes completion rows.
- [ ] Backend tests cover capability/price drift, profile revisions, key omission and free classification; UI tests cover the admin tab, unavailable and locked profiles, and ko/en parity.

## impl notes
- Own separate speech_profiles and speech_profile_revisions tables in modelcatalog/store with composite provider/model identity and versioned binding JSON mapped at the store edge. Historical binding revisions remain readable to confirmed voices. Grade/pricing/capability changes invalidate quotes; a revised binding creates a new revision without rebinding existing voices.
- Add a small speech_profile.proto service family for master CRUD/qualification state and an ordinary read projection; explicitly add admin RPCs to the closed master set. Do not extend Stage or SelectionSlot for profiles. Use ModelRef inside the profile pair and server-issued profile id/revision for creation requests.
- Add a 목소리 tab to existing model management outside its five-purpose paste contract. Operator chooses both compatible refs and a classification; display the associated synthesis model in the owner creation picker. No installed account default or assumed provider/model pairing.
- Use authenticated GET /v1/models for synthesis candidates, language/input limits and cost factors, and the documented design endpoint model vocabulary for design candidates. An account-specific documented price schedule is curated as decimal USD/unit with source, checked-at, unit, multipliers, request charges and confirmation charges; evidence lacking an enforceable ceiling leaves that operation unavailable. Reference: https://elevenlabs.io/docs/api-reference/models/list .
- The initial qualification harness may exercise a provisional profile only through a master-only explicit test action while retaining price bounds; ordinary availability requires T539 evidence. Its admin entry creates an owner-scoped qualification session for the same creation UI; a query flag alone authorizes nothing. Distinguish voice-ready from narrated-export-ready so later export qualification does not prevent the first voice milestone.
