# T109 Two sequential copies on a long cut
> st:doing@260911.trs | ssot:CDS-43 CDS-41 CDS-45 CDS-52 CLIP-17 ARCH-24 | base:CDS@1 CLIP@6 ARCH@2 | dep:T108

## goal
Let a cut of four seconds or more carry a descriptive copy followed by a numeric one, never both at once, in the compiler and in the correction step.

## acceptance
- [ ] `clip.Cut.Copies []Caption` (1 or 2) replaces the single `Copy` in the domain and JSON with a read-time upgrade of legacy single-copy plans; the proto `ClipEditCut.copies` (repeated, 10) is added and `copy` (6) is kept populated with the first copy for one release
- [ ] validation: a second copy only when the cut is ≥ 4000 ms, the first is `DESC` and the second `NUM` (T105's classifier), the windows are disjoint with a 120 ms gap, each meets its own exposure minimum, and the style guards count both
- [ ] the compiler produces a second copy only when the model's `short_text` or a `NUM` clause of the caption can stand alone as ≤ 16 characters; otherwise one copy as today
- [ ] `Layout`, the verifier (V4 for both, V7 across both windows) and the overlay chain handle two plates per cut; the manifest lists both
- [ ] step ②: a 자막 추가 control on a cut ≥ 4 s adds the second copy with its own fields and window, and the validator mirrors the rules; ko/en copy
- [ ] tests: legacy upgrade · every rule of the second copy · a plan with two copies through `Layout` and `Verify` · FE add/remove and window disjointness
- [ ] ARCH-26, ARCH-28 and ARCH-25 pass

## impl notes
- a list with the single-copy case as length 1 is simpler than a nullable second field and keeps the overlay chain uniform; the legacy `copy` field is mirrored so a stale client still sees the first copy
- the compiler never asks the model for a second sentence; it splits what it already has, which keeps the credit plan unchanged
