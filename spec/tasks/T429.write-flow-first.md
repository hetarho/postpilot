# T429 The write sets the day's flow first and places every photo along it
> st:todo | ssot:GEN-14 GEN-47 GEN-67 | base:GEN@16 | dep:T428

## goal
In the one write call, the answer opens with `flow`, the visit told in order, and the post is written along it, every attached photo placed once where its moment is, so the post reads as one story rather than as captions of the observations.

## acceptance
- [ ] `schemas/write_answer.schema.json` gains a required string `flow` as the FIRST key of `properties` and of `required`; a test decodes the embedded schema with a `json.Decoder` token walk and asserts `flow` is the first property
- [ ] the structured-output request carries the schema bytes unchanged. Check how `internal/llm/openaicompat` sends `JSONSchema`; if it round-trips through a Go map (which loses key order), send it as `json.RawMessage`, with a test
- [ ] `ParseWriteAnswer` accepts an answer with `flow` and drops it (no `WriteAnswer` or `PostContent` member carries it), and an answer without `flow` still parses; tests for both
- [ ] Korean and English static rules: the altitude constants carry the positive flow rule; the IMAGE placement line becomes the every-photo-once line; the output-shape line lists `flow` first with its own rule line; the output-language sentence names flow too (wording in impl notes)
- [ ] `WriteExperimentPromptVersion` moves from `write-v3-language-ab` to `write-v4-flow`, because the write prompt changed
- [ ] prompt-assembly snapshots and write-rule tests are updated; a test pins that both languages' static rules carry the flow rule and the every-photo-once line; the revise prompt and its schema are unchanged
- [ ] verify BE: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test -timeout 30m ./...`

## impl notes
- Keep the meaning of this wording; small phrasing tunes are fine.
  - `koreanAltitude`: `글을 쓰기 전에 메모, 템플릿 입력란, 모든 사진 관찰을 함께 보고 오늘 무슨 일이 어떤 순서로 있었는지 먼저 정해 flow에 적으세요. 그다음 그 흐름을 따라 한 편의 글을 쓰고, 각 사진은 흐름에서 그 사진의 순간이 나오는 자리에 놓으세요. 사진 관찰은 글의 근거이자 사진을 놓을 자리를 알려주는 자료이지, 하나씩 묘사해야 할 목록이 아닙니다. 어떤 문단도 사진을 가리키며 설명할 필요가 없습니다. 조명, 벽, 천장, 집기, 공간 배치처럼 글에 아무것도 더하지 않는 시각적 묘사는 쓰지 마세요.`
  - `englishAltitude`: `Before writing, read the memo, the template's fields and every photo observation together, decide what happened today and in what order, and write it in flow. Then write one post along that flow, placing each photo where its moment comes. The photo observations are grounding and placement material, not a list to describe one by one. No paragraph has to point at a photo. Do not write visual detail that carries nothing for the post: lighting, walls, ceilings, fixtures, the arrangement of a room.`
  - IMAGE line (`WritePrompt`, replacing `IMAGE 블록은 사진이 글의 흐름상 가장 자연스러운 위치에 오도록 배치하세요.`): `첨부 사진은 모두 정확히 한 번씩, 흐름에서 그 사진의 순간이 나오는 자리에 IMAGE 블록으로 놓으세요. 템플릿의 사진 자리에는 그 자리 앞뒤 내용이 요구하는 사진을 놓으세요.` English: `Place every attached photo exactly once, as an IMAGE block where its moment comes in the flow; at a template's photo place, put the photos the section around it asks for.`
  - Output shape: `{"flow":"...","title":"...","summary":"...","tags":[],"blocks":[],"nouns":[]}`, followed by `flow에는 오늘 있었던 일을 순서대로 3~6줄로 짧게 적고, 메모·입력란·사진 관찰에 없는 사실은 쓰지 마세요.` English: `In flow, tell what happened today in order in 3 to 6 short lines, stating nothing the memo, the template's fields and the photo observations do not carry.`
  - Output-language sentence: `flow, title, summary, tags, 모든 본문, IMAGE alt와 caption을 한국어로 작성하세요` and the English counterpart.
- `flow` is grounded like everything else (GEN-16). It reaches no store, no annotation and no revision (GEN-67). `WriteAnswer` gains no member.
