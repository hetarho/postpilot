# T377 A job can wait durably without occupying the API worker
> st:todo | ssot:ARCH-6 ARCH-7 ARCH-11 ARCH-50 GEN-28 GEN-32 GEN-33 GEN-35 | base:ARCH@11 GEN@12 | dep:-

## goal
Let an owning workflow park and resume the same active job around external work without blocking the single API consumer or replaying an interrupted model call.

## acceptance
- [ ] A handler can persist an external wait and yield without finishing, settling, releasing its sources or recording a failure; the public job remains running and retains its identity and active-subject guard.
- [ ] Another queued model job runs while the first job waits; waking the wait makes the same parent runnable exactly once, including a wake committed before its handler returns the yield signal.
- [ ] Boot preserves waiting/ready continuations and their cancellation requests, re-readies a claimed replay-safe continuation, and still fails interrupted local/model executions with JOB_INTERRUPTED.
- [ ] Cancellation of a parked job remains pending until its owning workflow acknowledges stopped external work; existing queued/local cancellation and terminal hooks retain their behavior.
- [ ] Atomic suspend/wake ports can join an owning-context transaction, and duplicate wakes or terminal-job wakes neither reopen a job nor settle twice.
- [ ] Queue/store tests cover park-before-yield crash, wake-before-yield, competing wake/claim, restart in waiting/ready/claimed states under both resume policies, cancellation at each boundary and continued processing of unrelated jobs; ARCH-26 and SQL generation checks pass.

## impl notes
- Add job-owned `job_continuations(job_id PK, wait_key, state, resume_policy, ready_at, created_at, updated_at)` with states waiting, ready and claimed and resume_policy fail_on_interrupt|replay_safe (default fail_on_interrupt); use a job FK with cleanup on deletion. The key is opaque to job, and clip data remains in clip/store.
- Expose generic tx-scoped `Park(jobID, waitKey, resumePolicy)` and `Wake(jobID, waitKey)` behaviors through job/store and the existing app transaction binder. Park only a currently running authorized job, and require an exact key match for Wake.
- Keep existing public status values. The runnable picker handles initial queued jobs and running jobs with ready continuations; claim a ready continuation atomically before calling its handler and order runnable work by ready_at/created_at with id as tie-breaker.
- Introduce a dedicated queue yield sentinel recognized with errors.Is before the normal terminal path. A missing durable wait is an error, not permission to leave an untracked running row. The clip boundary maps its own pending outcome to this sentinel; no generic queue code names clip operations.
- Extend SweepRunning and RecoverCancellations to exclude waiting/ready external continuations. A claimed fail_on_interrupt continuation receives the existing interrupted failure after restart; a claimed replay_safe continuation is atomically re-readied. Only workflows containing no paid or non-idempotent side effect may opt into replay_safe; T382 uses it for idempotent result publication, while T381 preparation-to-model work uses fail_on_interrupt.
- Check cancellation before dispatching a ready continuation; never resume paid work to finish a cancellation. Expose a generic terminal acknowledgement for the owning reconciler to call once remote work is stopped or its lease has expired.
- Keep dispatch_ready's existing initial-activation meaning and retain old payloads unchanged. No second credit admission occurs on a resume; settlement/notifyTerminal still follow a persisted terminal outcome.
- T354 and T372 modify registration/drain tests in cmd/api, not this state machine; preserve their generation payload ownership and shared registration harness rather than duplicating either.
- New primitives remain unused by production media work until T381/T382 wire them.
