## goal
Produce coherent template-directed clip narration with traceable scene/item facts and no cross-item price leakage.

## acceptance
- [ ] One writer call receives the frozen template narrative, grouped answers and source analyses, selects real footage and returns section/cut IDs, text and supporting observation/fact references.
- [ ] Each item-specific claim resolves to that item and overlapping source observations; identical numbers elsewhere, a generic food scene or a model-asserted item ID alone cannot establish a match.
- [ ] Unknown matches remain unassigned and use observed descriptive copy or no generated copy with a recorded reason; the run does not invent a price, require a new approval stage or make an extra AI call.
- [ ] The template controls narration order, viewpoint and repeated sections; output includes no undeclared badge, CTA, card or fixed-vocabulary chip, and exact authored text never passes through model rewriting.
- [ ] Tests cover two similar items with different prices/currencies/bases, shared numbers, menu reorder, missing facts, unsupported first-person experience, source gaps, valid context sections and explicit owner associations.
- [ ] Run the applicable local ARCH-25 through ARCH-29 checks, deterministic proto/SQL regeneration when changed, and spec lint; use a before/after generation snapshot when unrelated generated changes already exist.

## impl notes
- Extend the existing plan schema, strict parser and BuildPlanPrompt rather than creating another model stage. Each planned cut names template_section_id, optional item_id, observation references and fact references; the server binds source fingerprints from the frozen source inventory, never from model text.
- Keep observation independent of template instructions and answers. Match evidence against existing event/subject/speech fields; owner range bindings are authoritative, and an automatic match needs a unique supplied item name/alias explicitly supported in the observed range. Merely visual/model-proposed matches without checkable identity remain unassigned; provide no fuzzy threshold that silently turns uncertainty into certainty.
- Implement scoped fact lookup by field/group/item and exact number/unit/currency/basis comparison, replacing project-wide concatenated digit-substring grounding. An explicit context scene may use global facts but may not label a depicted item with an unrelated global price. Retain full source range/fact references on generated text for correction inspection.
- Plan ordered sections before writing their scene copy within the same response. Repetition expands only over selected scenes or matched items with footage, does not invent cuts to satisfy an item count, and does not repeat the same promotional sentence to fill duration.
- Use only alternatives already present in the single writer response for semantic shortening; deterministic removal records a typed reason. No automatic semantic repair calls, analysis replay or composition-only AI regeneration is introduced. Preserve completion budgets, provider admission and credit ceilings.
- Freeze resolved fixed/answer-bound text on the server, then attach the writer-selected cuts and generated text. T128 owns final placement and timing resolution; explicit content authority is carried through untouched.
