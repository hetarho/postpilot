# T355 The writing brief saves its run options together
> st:todo | ssot:POST-51 POST-54 POST-71 POST-81 POST-82 POST-89 MEM-18 MEM-26 | base:POST@14 MEM@3 ARCH@9 | dep:-

## goal
목표 분량, 태그 수, the 발행 글 점검 ticks, 분야 and 기억 사용 become one form in the writing brief, seeded from the post each time it opens and saved by its 저장 as one whole-set `SavePostGenerationOptions` that the server writes in one statement; ①'s panel and `/posts/new` carry neither 분야 nor 기억 사용.

## acceptance
- [ ] Wire (`proto/postpilot/v1/post.proto`):
  - `SavePostGenerationOptionsRequest` gains `optional BlogField field = 6`.
  - The request is a whole set. `tag_count`, `use_memory`, `quality_rules` and `field` must be present. An absent `target_length` is natural length.
  - A request missing any of the four is refused `InvalidArgument` / `POST_CONTENT_INVALID`, and nothing is written.
  - `field` UNSPECIFIED is 없음. A number this build does not name, or a 분야 the product does not list, is `NotFound` / `POST_FIELD_NOT_FOUND`.
  - The message and field comments say so (text in impl notes). No FailureReason is added.
  - `SavePostDraftRequest.field` (8) is still accepted and applied, and its comment says the editor no longer sends it.
- [ ] BE `post.Service.SaveGenerationOptions(ctx, userID, slug string, set GenerationOptionsSet) (Post, error)`:
  - It validates every member before anything is written: a present length > 0, the tag range, known ticks, and a known 분야 or "".
  - A published post is refused with `ErrPostPublished`.
  - A set equal to the stored one writes nothing.
  - Otherwise all five land in ONE `ContentStore.SaveGenerationOptions` call. Its one `SavePostGenerationOptions` statement also writes `field`. It never calls `AssignField`.
- [ ] FE entity:
  - `useGenerationOptions()` returns the mutation plus one `save(slug, set: GenerationOptionsSet)`.

  - 저장 sends one request and closes the brief once it lands. It is disabled while the form is unchanged or invalid. It is also disabled while its request is out, and every control of the form holds still then too.

  - On a published post the whole form and 저장 are disabled. While a job runs, the numbers and the ticks are held, and 분야 and 기억 사용 stay usable.
