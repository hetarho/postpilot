## goal
Build the clip directory and setup flow through a confirmed transient source batch, keeping every selected File local to the current browser session.

## acceptance
- [ ] `entities/clip-project` owns project mappers, cache keys, query/mutation hooks and core types; `features/upload-clip-sources` owns metadata reading, fingerprinting, the batch handshake and upload progress
- [ ] authenticated lazy routes `/clips`, `/clips/new` and `/clips/$clipId` render directory, setup and project states; the directory lists title, ratio, target duration, template and updated time and docks one `새 클립` action
- [ ] setup requires title, one owned video template, answers for its current information fields, one of 세로 9:16 · 가로 16:9 · 정방형 1:1, and a target duration from 15 to 90 seconds; ratio has no edit control after create
- [ ] the external-analysis disclosure is visible before the file input and says originals are temporary, sent to an outside video-analysis provider and may need reselection after refresh
- [ ] the picker accepts the T071 containers, reads duration/dimensions with a browser `<video>`, computes the versioned first/last-chunk fingerprint with Web Crypto, and rejects count, combined duration and byte ceilings before any reservation
- [ ] one manifest call reserves the batch, each File PUTs directly to its signed URL with per-file progress, and each success is confirmed; no Connect request, query cache, localStorage or IndexedDB contains video bytes or object URLs
- [ ] page memory keeps `File` and object URL entries by fingerprint only until unmount/attempt completion, revoking every object URL; refresh presents a clear `원본 영상을 다시 선택해 주세요` state instead of pretending the files survived
- [ ] replacing or cancelling a selection calls discard, while unload relies on the server TTL and never starts an unreliable asynchronous delete request
- [ ] project and template mutations preserve unsaved values after server failures and display stable localized reasons; upload-network classification remains local as LANG-22 allows
- [ ] tests cover metadata/fingerprint determinism, every client gate, direct PUT headers/progress, partial failure, cancellation/discard, no byte-bearing Connect call, ratio immutability and ko/en copy parity
- [ ] ARCH-25 passes

## impl notes
- keep the new project draft local until the required setup fields validate, then call `CreateClipProject` once before reserving sources; a failed upload leaves the project and its answers available for another selection
- implement PUT with the same XHR progress adapter used by post video upload; do not route large bodies through TanStack Query or `shared/api`
- fingerprint only bounded slices of the File so a 2 GiB source does not need a full browser read; include the media metadata in the digest input so same-named phone exports do not collide accidentally
- the page ends in a typed `readyBatch` state consumed by T077; until then it may say 업로드 준비 완료 but must not expose a generation action that has no endpoint
- primary navigation remains unchanged here; T080 installs the grouped 글/영상 shell after both video pages exist
