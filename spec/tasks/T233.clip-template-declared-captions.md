# T233 The template's caption entries reach the narration in outline order
> st:todo | ssot:CLIP-65 CLIP-112 CLIP-121 CLIP-134 | base:CLIP@33 ARCH@3 | dep:T228

## goal
Hand the narration call the outline's caption entries in order and keep a fixed entry's text exact by substituting the server's own resolved text.

## acceptance
- [ ] the narration request carries the outline's caption entries in order, each with its id, its position among the outline's entries, and either its resolved exact text or its writer instruction and character bound
- [ ] the response supplies an interval for each declared caption; the writer decides where in the resolved flow it sits
- [ ] a fixed entry's text in the saved plan is the server's resolved text byte-for-byte even when the response returns something else (CLIP-65)
- [ ] a generated entry is grounded and repaired exactly as a written caption is today
- [ ] a declared caption the response omits records one CLIP-108 notice with action `removal` and refuses nothing
- [ ] the outline order is guidance, not a check: a response that orders two declared captions differently is delivered as written
- [ ] the request stays byte-identical for a template that declares no caption entry (the section is omitted whole, as `template_guide` already is)
- [ ] tests: fixed text survives a rewriting response, an omitted entry notices, no-caption templates leave the request unchanged, and the plan's captions still hold disjoint windows (CDS-62)
- [ ] ARCH-26 verify clean

## impl notes
- model it on the existing `generated_region_slots` payload in `ai/narration_prompt.go`: one entry per declared caption, and a matching response array the schema requires — the pattern for "the template declared it, the writer places it" already exists for region rows.
- substitution follows `ai/composition_copy.go:attachRegionRows`: resolve the entry through the composition resolver, then overwrite the response's text for fixed entries rather than validating it — a check would leave the owner reading a diff the product can simply not produce.
- a declared caption is a caption like any other afterwards: CLIP-66's non-overlap, CDS-62's windows and CLIP-137's grounding all apply, and the repair ladder needs no new rung.
- this is the one new capability in CLIP r33 (a template could not declare a caption before, `unsupported_role`); keep it behind the same admission the other declared elements pass so a malformed entry fails before any paid call (CLIP-92).
