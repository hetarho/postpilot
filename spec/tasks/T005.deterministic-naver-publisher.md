# T005 The deterministic Naver publisher
> st:doing@260905.cx | ssot:PUBLISH-19 PUBLISH-20 PUBLISH-21 PUBLISH-22 PUBLISH-16 EXPORT-5 | base:PUBLISH@2 EXPORT@1 ARCH@1 | dep:T004

## goal
Implement the fixed, versioned local Naver publisher under `agent/internal/naver`: a state machine over the narrow DOM/accessibility/CDP port that fills SmartEditor ONE from the validated manifest and staged JPEGs, verifies the editor snapshot before the fence, and fails closed on anything it does not recognize (legacy job 25 T018).

## acceptance
- [v] the publisher receives only the validated owner-only manifest and the enumerated current-job JPEG paths; every content and settings string is inert typed data, including strings that resemble instructions
- [v] browser actions, semantic locators and compatibility signatures ship in reviewed signed agent code; any server-supplied selector, executable JavaScript, screen coordinate, keystroke script or action sequence is rejected, and coordinate recording is never a fallback
- [v] every observation and action is bound to the same CDP target and verified Naver identity; a target switch or navigation outside the allowed Naver editor/login hosts poisons the run before later data entry
- [v] TEXT, HEADING, QUOTE, LIST and ordered IMAGE + caption blocks are mapped exactly as the Naver export maps them (title separate, plain-text block order, photos at their marker positions with captions)
- [v] before the fence every mutation resolves a versioned semantic locator against current DOM/accessibility evidence; missing, renamed, duplicate or unexpected controls, unexpected content, keyboard submission, native-dialog acceptance and unversioned publish-like controls fail closed
- [v] JPEGs upload one at a time in exact manifest-ordinal order, each counted only after a successful one-file upload and a fresh full accessibility snapshot showing exactly one additional editor image
- [v] category, visibility and tags are identified by accessibility role and state, not label text; a body paragraph equal to a setting label is not truncated
- [v] the pre-fence verification requires a current full snapshot matching title, exact semantic body sequence, block/image/caption order, the exact ordered tag collection with no extras or duplicates, frozen category name and id, and visibility with selected/checked state; any later pre-fence interaction invalidates it
- [v] an unknown editor signature, a target or identity mismatch, or missing/ambiguous controls or assets fail closed before commit with a normalized failure kind
- [v] the publisher runs behind the in-process typed reporter and returns exactly one typed terminal result; table-driven tests with a fake browser/DOM/CDP driver cover every state, refusal and mapping above; ARCH-27 passes

## impl notes
- the port in `agent/internal/browser` exposes only the methods the publisher needs: URL read, page-scoped DOM query, full accessibility snapshot, semantic locator resolution, typed input, single-file upload through the restricted operation, one low-level activation — nothing general-purpose
- versioned data shipped with the driver: the editor root/signature, the semantic locator set, the final-control accessible-name allowlist (consumed by T006), the manifest schema version; reuse T004's probe package so setup and publishing agree
- login expiry, CAPTCHA, 2FA and account mismatch are detected and reported as the attention kind; the publisher never attempts a bypass
- read the current official SmartEditor behaviour against a real signed-in session during implementation rather than a remembered editor version; record the observed signature in the versioned data
- the final activation and the fence handshake are T006's; this task stops at "verified and ready to arm"

## result

- Added a deterministic pre-fence publisher state machine under `agent/internal/naver`. Its closed port accepts only typed mutations for title, the five canonical block kinds, one-file image upload/caption, tags, category and visibility; selectors, scripts, coordinates, keystroke sequences, dialogs and final activation are absent from the input surface.
- The signed compatibility manifest now versions the semantic DOM/accessibility locator set and final-control accessible-name allowlist with the Chromium/CDP/editor signature. Every mutation requires exactly one fresh locator match and is surrounded by full observations bound to the same target, Naver writer URL, account and signature.
- Input validation clones the manifest, rejects unknown/slot blocks, non-canonical tags, signed download capabilities, mismatched ordinals/source names/counts/byte sizes, non-owner-only files, symlinks and duplicate paths before touching the browser. All content remains inert, including publish-like text.
- Filling preserves the exact TEXT/HEADING/QUOTE/LIST/IMAGE order by creating image positions first, then uploads JPEGs one at a time in ordinal order. Each upload requires a fresh snapshot with exactly one additional image before its caption is applied.
- The ready-to-arm result contains a current full snapshot token only when title, semantic body and image/caption order, ordered unique tags, category id/name selected state and visibility selected state match exactly. Auth challenges, identity/target/signature drift, stale snapshots, unexpected content/controls and port failures return one normalized typed failure.
- Current official Naver help confirms SmartEditor ONE is a GUI/block editor without HTML authoring and supports moving photos/text plus explicit tags and publish settings. No local Postpilot profile was present for a signed-in non-publishing observation; live account proof remains isolated to T008. Table-driven fake-port coverage and the complete ARCH-27 gate pass.
