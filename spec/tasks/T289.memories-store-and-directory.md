# T289 memories are a table, a context and a directory RPC family

## goal
Create the memory aggregate end to end on the backend: schema, domain context, field rules, deduplication, cap, source links and the four directory procedures.

## acceptance
- [ ] a goose migration creates `memories`, `memory_tags` and `memory_sources`: the five-value `kind` CHECK, `memories(user_id, text)` UNIQUE, `memories(id, user_id)` as the composite target, an index on `memory_tags(user_id, tag)`, and `memory_sources` cascading on its memory; `PRAGMA integrity_check` and the existing migration test pass on a migrated temp DB
- [ ] `internal/memory` holds the domain types, service, consumer-owned ports and store; `kind` is a typed enum whose zero value is invalid and whose parser refuses an unknown string
- [ ] `proto/postpilot/v1/memory.proto` carries one `MemoryService` with `CreateMemory` `ListMemories` `UpdateMemory` `DeleteMemory`; generated code is committed and `pnpm gen:proto` leaves no diff
- [ ] create: trimmed non-empty `text` of at most `MemoryTextMaxChars`, at most `MemoryTagsMax` distinct trimmed tags (duplicates within one request collapse), an explicitly present supported `kind` refused otherwise as `InvalidArgument`
- [ ] an exact duplicate text after trim inserts nothing: it adds the source link, advances `last_seen_at` and answers the existing memory; no similarity, fuzzy or semantic matching exists anywhere
- [ ] the cap is read inside the insert transaction and a create beyond `MemoryMaxPerAccount` is `FailedPrecondition` naming the cap; nothing is evicted
- [ ] deleting a post drops its source links and deletes only the memories whose last link it was, after the post row is gone; a failure is logged and never fails the post delete
- [ ] every query is scoped by the authenticated user; a foreign id is indistinguishable from an unknown one (`NotFound`)
- [ ] the memory queries file is ASCII-only and `pnpm gen:sql` leaves no diff
- [ ] store and service tests over a migrated temp SQLite pin: a duplicate adds a link instead of a row, the cap refuses, a foreign id is `NotFound`, a post delete removes a single-linked memory and leaves a multi-linked one
- [ ] ARCH-26 and ARCH-28 pass

## impl notes
- bounds mirror the guideline ceilings exactly — `MEMORY_TEXT_MAX_CHARS` (120), `MEMORY_TAGS_MAX` (5), `MEMORY_MAX_PER_ACCOUNT` (300), `MEMORY_INJECT_MAX` (8) read in `platform/config` with those defaults and mirrored as `VITE_*` in the FE's `shared/config`; the frontend hardcodes none
- tags are their own table rather than a JSON column: retrieval (T290) matches on them and the index is the entire reason
- `memory_sources` holds the post slug, never a post row id, and its FK cascades so a deleted post cannot leave a dangling link; the orphan deletion is still an explicit statement because CASCADE cannot express "only when it was the last link" (MEM-17)
- the post-delete hook is a consumer-declared port on the post context, wired in `cmd/api`, following GUIDE-13's candidate detach: it runs after the post row is gone and its failure is logged
- a dedupe hit advances `last_seen_at` and does NOT touch `updated_at`: ordering reads the former, and the latter belongs to an authored edit
- `CreateMemory` is also the hand-authoring path (MEM-25); there is no separate procedure for it
