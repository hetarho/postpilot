# T291 extract_memory is a job that proposes candidates and stores none
> st:todo | ssot:MEM-13 MEM-14 MEM-15 QUOTA-13 ARCH-11 ARCH-24 | base:MEM@1 QUOTA@13 | dep:T289

## goal
Turn a finished post into memory candidates through one durable credit-gated job that writes no memory.

## acceptance
- [ ] job kind `extract_memory` addressed by the post dimension, guarded so it is refused while other work is active on that post
- [ ] it passes the shared enqueue credit gate like every other LLM job; an insufficient balance answers `resource_exhausted` / `INSUFFICIENT_CREDITS` and leaves no job row
- [ ] exactly one provider call against the account's current enabled analyze-stage selection, attaching the embedded JSON schema when the resolved model declares `structured_output` and falling back to the prompt alone otherwise
- [ ] each candidate carries text, a proposed kind from the five and proposed tags, all inside the bounds a create enforces
- [ ] nothing is written to `memories`, `memory_tags` or `memory_sources` by this job, and the post's content, status, revision and baseline are untouched on success and on every failure
- [ ] `GetMemoryExtraction(job_id)` answers the candidates for a done job the caller owns and refuses anything else
- [ ] approving a candidate is the ordinary `CreateMemory`; unchecked candidates are discarded with the job and never reappear
- [ ] tests: the credit refusal before the job row, the active-work guard, a stubbed provider driven through completion, the ownership refusal, and an assertion that a completed extraction left the memory tables empty
- [ ] ARCH-26 and ARCH-28 pass

## impl notes
- the analyze stage is the model class for reading finished prose; `seed_voice` and `analyze_voice` already select it, so no new per-account setting appears
- the candidates ride the job row's kind-specific payload (GEN-30) and live nowhere else. MEM-15 forbids a durable review queue, and a job row is transient work state nothing re-surfaces — state this in the code comment so it is not turned into a table later
- the extraction prompt is a code constant beside the other prompt constants: it receives the post's canonical content and its memo, and asks for atomic one-sentence facts about the author's world, each with one of the five kinds — never opinions about the writing, never a summary of the post
- schema file `internal/memory/schemas/memory_candidates.schema.json`, `//go:embed`-ed, following VOICE-27's attach-or-fall-back rule
- the schema must contain NO integer enum: a numeric enum in a response schema makes Gemini answer `{}` for the whole object, measured on this codebase. Kinds are string values
- the job freezes the post slug and the content it read at enqueue, so an edit during the call cannot change what was extracted
