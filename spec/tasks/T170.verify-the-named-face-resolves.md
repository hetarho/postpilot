# T170 Fail when a text renders in a face it did not ask for
> st:todo | ssot:CDS-52 CDS-17 | base:CDS@16 ARCH@2 | dep:T166

## goal
A font family the renderer cannot resolve stops the render instead of silently substituting another face.

## acceptance
- [ ] the renderer validates at construction that every `faces` value in `design.json` matches a family the bundled font file actually declares, reading the TTF `name` table (IDs 1 and 16)
- [ ] a value that does not match, or that is not a parsable CSS font-family (any component beginning with a digit), fails `NewRenderer` with a named error rather than starting
- [ ] V19 is recorded in the verifier's check list so the contract is visible beside the others
- [ ] test: `"Paperlogy 8 ExtraBold"` is rejected and `"Paperlogy"` accepted against the bundled file
- [ ] test: `NewRenderer` fails with the unparsable value and succeeds with the corrected one
- [ ] `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...`

## impl notes
- the defect this closes: `faces.paperlogy` was `"Paperlogy 8 ExtraBold"`, which resvg cannot parse as a CSS font-family, so it fell back to Pretendard and every hook, title and 크게 강조 has rendered in the wrong face since the face was bundled — silently, because resvg only warns on stderr
- validate at construction, not per render: the set of faces is fixed at boot, and a startup failure is the cheapest place to catch a constant that is wrong
- do not parse resvg's stderr for the warning — it is not a contract, and a warning that changes wording between versions would make the check unreliable
- T166 fixes the value itself; this task makes the class of mistake impossible to ship again
