# T436 ②'s storyline space: reading it and editing it by hand (frontend)
> st:todo | ssot:POST-54 POST-86 POST-95 POST-96 POST-99 | base:POST@21 | dep:T435

## goal
② shows the post's storyline in a space that opens and closes above the draft: paragraphs with their photo and video thumbnails, text edited in place, attachments moved, taken out and put back, every edit autosaving, and a notice when attachments were added after it was made.

## acceptance
- [ ] `shared/ui/disclosure` (new primitive): a heading button with `aria-expanded`/`aria-controls` over a region, controlled or uncontrolled; unit tests
- [ ] `widgets/storyline-space`, mounted by `pages/editor/ui/EditorRefinePanel.tsx` above the draft when `post.storyline` is present (nothing otherwise): open while the post has no content — the draft area then saying it waits for 이 스토리로 글 쓰기 — and closed when ② first shows content during this mount; opening or closing changes nothing else
- [ ] each paragraph: its number, its text edited in place (read view → autogrow textarea), and its attachments as small thumbnails (`entities/image` Thumbnail, `entities/video` VideoTile)
- [ ] moves: each thumbnail has a move control (the single-choice `Menu` with `n번째 문단` options and `빼기`); from `sm:` an HTML5 drag onto another paragraph's drop zone does the same; `빠진 사진` under the paragraphs lists `taken_out_files`, each with a `넣기` menu choosing the paragraph; `added_files` are never offered
- [ ] `features/edit-storyline`: every change goes through the draft queue as `storyline` (the whole paragraph list; `features/save-draft/model/draft-queue.ts` gains the field with its newest-wins rules; `useAutosave` sends it only when changed) and the cached GetPost is patched from the answer (`applyingSavedDraft` owns the field)
- [ ] read-only (no field, no move control) while a job targets the post, on a published post (POST-86) and while the queue reports a refusal
- [ ] the notice when `added_files` is not empty (copy below); its 다시 만들기 is T437's
- [ ] tests: Disclosure unit; widget tests (open/closed rules, a text edit queues a save, move, take out, put back, added files never offered, the read-only states); draft-queue test for the field; page test in `EditorPage.refine.test.tsx`
- [ ] verify FE: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- Copy (namespace `posts`): heading `스토리라인` / `Storyline`; waiting draft `이 스토리로 글을 쓰면 여기에 글이 나와요` / `Write from this storyline to see the post here`; `{{n}}번째 문단` / `Paragraph {{n}}`; `빼기` / `Take out`; `빠진 사진` / `Taken out`; `넣기` / `Put back`; notice `이 스토리라인을 만든 뒤 사진이 추가됐어요. 다시 만들면 새 사진도 들어가요.` / `Photos were added after this storyline was made. Make it again to include them.`
- The server validates every save (T434); the client never adds or removes a paragraph.
- Thumbnails use `viewUrl` (a `blob:` URL right after an upload is fine; a missing URL shows the filename).
- The widget composes `features/edit-storyline` now and the storyline actions in T437; `pages/editor` only mounts it.
- A post with content and no storyline (written before storylines existed) shows no space.
