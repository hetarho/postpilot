# T359 The write prompt builder and template Create each take one named input
> st:todo | ssot:- | base:ARCH@9 | dep:T354

## goal
`generation.BuildWritePromptForLanguage` and `template.Service.Create` take one named struct instead of long positional lists. A new frozen input then edits one struct and its one reader, and two same-typed values can no longer trade places silently.

## acceptance
- [ ] `BuildWritePromptForLanguage(input WritePromptInput) (string, string)` is the only form. `write.go`'s call and every test call pass a `WritePromptInput{…}` literal with named members, and no call passes a trailing run of `nil`s.
- [ ] Prompt output is byte-identical. Every existing prompt golden passes unchanged: `write_prompt_no_template.golden`, `write_prompt_memories.golden`, `write_prompt_pre_naturalness.golden`, and the revise goldens, which this task does not touch.
- [ ] `template.Service.Create(ctx, userID string, authored Authored) (Template, error)`. Every caller is updated: `template/rpc/handler.go`, the `cmd/seed` adapter, `template/service_test.go`, `template/numbers_test.go` and `cmd/api/bootstrap_test.go`. Validation order and errors are unchanged.
- [ ] Behavior unchanged: existing tests still pass.
- [ ] New test `internal/generation/write_prompt_input_test.go` `TestEveryWritePromptInputMemberReachesThePrompt` fails for a `WritePromptInput` member that has no fixture or that the builder never reads.
- [ ] BE gate passes: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test -timeout 30m ./...`

  - `tag_count_test.go`, `template_test.go`, `video_test.go`, `write_rules_test.go`
- Struct choice: a dedicated `WritePromptInput` in `internal/generation/prompts.go`, not `PostInput`. Reasons:
  - The builder reads the run's merged observations (the set the run holds eyesight for, `generate_handler.go`), while `PostInput.Observations` is the stored snapshot read at enqueue. Handing it `PostInput` puts two observation lists in reach, and the wrong one looks right.
  - It needs the profile and the resolved tag count, which `PostInput` does not carry.
  - It needs filenames split by kind (`AttachmentNames`), not `[]Image` with storage keys.
  - `PostInput` carries Slug, UserID, TemplateID, Field, Published and more that must never shape prompt bytes. A struct holding only what the prompt reads keeps the domain type free of prompt concerns and makes "what reaches the prompt" one type.
- Definition, members in the old parameter order:
  ```go
  type WritePromptInput struct {
      Language     Language
      Profile      Profile
      Observations []Observation // the run's merged observations, never the stored snapshot
      Memo         string
      Title        string        // the 가제 (title hint)
      Photos       []string      // attached photo filenames, post order
      Videos       []string      // attached video filenames, post order

      Memories     []string
      QualityRules []string
      FieldPhrases []string

  ```
  Move the per-parameter doc comments from the current function comment onto these members.

- The body is unchanged, with each parameter read replaced by `input.X`: `filenames`→`input.Photos`, `videoFilenames`→`input.Videos`, `template`→`input.Template`, and so on.
