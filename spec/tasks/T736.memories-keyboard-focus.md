## goal
On /memories, closing a row's edit form or deleting a memory from the keyboard leaves focus in the list instead of dropping it to `<body>`, with no change for pointer users.

## acceptance
- [ ] `MemoryRow` (`frontend/src/pages/memories/ui/MemoriesPage.tsx`): when the edit form's `onDone` closes the form, focus returns to the row's 수정 pencil with `preventScroll: true`, only while focus is lost (`document.activeElement` is null or `document.body`)
- [ ] `DeleteMemoryButton` takes an optional `onDeleted?: () => void` called after a successful delete (the shape `DeletePostButton` uses); a failed delete does not call it and keeps today's message
- [ ] `MemoriesPage`: after a successful delete it waits until the deleted id has left the rendered list (the refetch is not awaited by the mutation), then — only while focus is lost — focuses the 이 기억 삭제 button of the row now at `min(deletedIndex, length - 1)`, or the 새 기억 trigger when the list is empty
- [ ] `frontend/src/pages/memories/ui/MemoriesPage.test.tsx` new cases "returns focus to 수정 when the row's form closes from the keyboard", "keeps keyboard focus in the list after a memory is deleted", "moves focus to 새 기억 when the last memory is deleted" — each fails at the base commit
