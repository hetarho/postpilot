## goal
Enable only evidenced browser rendering and ship a reviewable static deployment with complete notices and independent analysis gates.

## acceptance
- [ ] Real-browser outputs cover all ratios, styles/paces, transitions/rates, source-only and qualified narrated cases with exact text/geometry/timing/audio checks and reviewed blur/neon/glitch/ember extremes.
- [ ] Identified integrated-GPU Windows Chrome/Edge, macOS Chrome and a lower-resource case are measured when available; unsupported/unavailable combinations are not marketed as qualified.
- [ ] Cold/warm phase timings, peak resources and output quality compare optimized Canvas 2D and PixiJS on identical fixtures; a slower or incorrect default is not enabled without resolving the comparison.
- [ ] Static deployment exercises HTTPS, private-storage CORS, bundled module Workers, versioned fonts/WASM, seekable/temporary output cleanup and local-ready versus saved-result behavior.
- [ ] MIT/OFL notices and exact-version MPL covered-source access accompany the shipped JS/WASM; transitive/native components and any optional SDK conditions are checked for the actual lockfile.
- [ ] Browser final-render readiness and browser analysis preparation readiness are independent; T603 evidence is required only to open the latter, and T539/T550/provider voice gates remain closed where unqualified.
- [ ] Load/queue/cancellation/restart checks preserve API capacity and bounded Max/native verification behavior; full local CI and applicable real-binary/browser qualification checks pass.
- [ ] Missing real hardware, human review or output evidence leaves release acceptance open rather than substituting mocks; no live deployment, host purchase or desktop packaging occurs without its separately authorized scope.

## impl notes
- Parallel group execution uses isolated worktrees; exact final cross-slice edits remain uncertain (touches:-). Coordinate shared public exports and adapter seams explicitly; review and integration are serial and resolve overlap without shared-checkout writes.
- Use a versioned readiness record/configuration for independently qualified renderer and analysis profiles; exact public env names/defaults belong to their owning config and example files.
- Keep the existing Cloudflare static frontend, Go API, private R2/S3-compatible transfer and CPU worker deployment; do not introduce a Node SSR service, GPU rental or PostgreSQL migration.
- Publish bounded fixture/report artifacts under docs/design with actual run/device/tool/source provenance, not runtime secrets, signed links or private user footage.
- Ship a notices page/source-access manifest and source archives or exact-version source paths for bundled MPL portions, including modifications. Do not claim the whole proprietary app must be disclosed.
- Retain finite queue/operation limits and same-host API CPU/memory headroom; deployment configuration is prepared and verified locally, with live rollout left as a concrete later operator action.
- The dependency on T601/T602 verifies packaging/integration of the disabled analysis path; T603 may remain blocked while a fully qualified final renderer is independently released.
