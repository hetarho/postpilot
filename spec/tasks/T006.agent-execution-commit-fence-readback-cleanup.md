# T006 Agent execution, the commit fence, readback and cleanup
> st:todo | ssot:PUBLISH-12 PUBLISH-13 PUBLISH-14 PUBLISH-15 PUBLISH-16 PUBLISH-22 PUBLISH-23 PUBLISH-26 | base:PUBLISH@2 ARCH@1 | dep:T005

## goal
Wire the publisher into the companion's job execution: download and verify the staged JPEGs, supervise the publisher, enter the durable commit fence synchronously before exactly one final activation, require exact readback before completion, and delete local job data on every terminal path (legacy job 25 T019).

## acceptance
- [ ] every signed JPEG is downloaded to a random owner-only per-job directory without forwarding auth; redirects and hosts outside the signed storage target are rejected; filenames, byte counts and count are verified against the manifest; the signed GET URLs are stripped from `manifest.json` before the publisher can read it
- [ ] the supervisor forwards only legal typed progress transitions through the typed reporter; skipped, duplicate or late progress is rejected; a transient lease-renewal failure cancels the local run and sends no competing terminal failure report
- [ ] immediately before exactly one low-level activation of the exact verified final control, the agent synchronously enters the durable commit fence (server acknowledgement that `committing` is persisted) and disables automatic activation retry; from photo verification onward every other activation is blocked
- [ ] after activation, completion requires the expected numeric Naver URL on the same bound target plus exact frozen title/block/image/caption/tag/category/visibility readback; otherwise the agent reports `outcome_unknown` and never republishes
- [ ] the fence accepts exactly one button whose accessible name is in the versioned final-control allowlist; scheduled, generic, renamed or duplicate publish-like controls cannot arm it
- [ ] local job data is deleted on every terminal and abort path; abandoned job directories are removed at startup only after the process lock is held
- [ ] raw browser or driver failure detail never enters an agent RPC — only a redacted diagnostic marker locally and a constrained failure kind to the server
- [ ] the pre-commit and post-commit process-death cases, lease expiry, stale progress and duplicate-completion races are covered by agent tests with fake Postpilot, storage, browser and clock adapters; ARCH-27 passes

## impl notes
- placement: `agent/internal/publishing` (supervisor, downloader, reporter, fence handshake), `agent/internal/workdir` (per-job directories, cleanup), `agent/internal/naver` (T005), `agent/internal/singleton` (the process lock already exists)
- the server contract is already built: claim/lease/progress/commit/complete/fail on `PublishingAgentService`; `committing` must be acknowledged by the server before the click — treat a rejected or timed-out fence call as fail-closed (no activation)
- the 15-minute job timeout yields `outcome_unknown` after the fence and a normal failure before it
- keep the agent's HTTP client redirect-refusal and origin-bound bearer injection (PUBLISH-7)
