# T006 Agent execution, the commit fence, readback and cleanup
> st:doing@260905.cx | ssot:PUBLISH-12 PUBLISH-13 PUBLISH-14 PUBLISH-15 PUBLISH-16 PUBLISH-22 PUBLISH-23 PUBLISH-26 | base:PUBLISH@2 ARCH@1 | dep:T005

## goal
Wire the publisher into the companion's job execution: download and verify the staged JPEGs, supervise the publisher, enter the durable commit fence synchronously before exactly one final activation, require exact readback before completion, and delete local job data on every terminal path (legacy job 25 T019).

## acceptance
- [v] every signed JPEG is downloaded to a random owner-only per-job directory without forwarding auth; redirects and hosts outside the signed storage target are rejected; filenames, byte counts and count are verified against the manifest; the signed GET URLs are stripped from `manifest.json` before the publisher can read it
- [v] the supervisor forwards only legal typed progress transitions through the typed reporter; skipped, duplicate or late progress is rejected; a transient lease-renewal failure cancels the local run and sends no competing terminal failure report
- [v] immediately before exactly one low-level activation of the exact verified final control, the agent synchronously enters the durable commit fence (server acknowledgement that `committing` is persisted) and disables automatic activation retry; from photo verification onward every other activation is blocked
- [v] after activation, completion requires the expected numeric Naver URL on the same bound target plus exact frozen title/block/image/caption/tag/category/visibility readback; otherwise the agent reports `outcome_unknown` and never republishes
- [v] the fence accepts exactly one button whose accessible name is in the versioned final-control allowlist; scheduled, generic, renamed or duplicate publish-like controls cannot arm it
- [v] local job data is deleted on every terminal and abort path; abandoned job directories are removed at startup only after the process lock is held
- [v] raw browser or driver failure detail never enters an agent RPC — only a redacted diagnostic marker locally and a constrained failure kind to the server
- [v] the pre-commit and post-commit process-death cases, lease expiry, stale progress and duplicate-completion races are covered by agent tests with fake Postpilot, storage, browser and clock adapters; ARCH-27 passes

## impl notes
- placement: `agent/internal/publishing` (supervisor, downloader, reporter, fence handshake), `agent/internal/workdir` (per-job directories, cleanup), `agent/internal/naver` (T005), `agent/internal/singleton` (the process lock already exists)
- the server contract is already built: claim/lease/progress/commit/complete/fail on `PublishingAgentService`; `committing` must be acknowledged by the server before the click — treat a rejected or timed-out fence call as fail-closed (no activation)
- the 15-minute job timeout yields `outcome_unknown` after the fence and a normal failure before it
- keep the agent's HTTP client redirect-refusal and origin-bound bearer injection (PUBLISH-7)

## result

- `naver.Publisher` now implements the companion's typed `publishing.Publisher` contract. It loads only an absolute owner-only `manifest.json`, rejects unknown proto fields, derives the exact current-job asset paths, and returns constrained terminal results without raw browser detail.
- Asset download uses a random mode-0700 job directory, sends no agent authorization, refuses every redirect and mixed storage origins, verifies ordinal/filename/count/byte contracts, writes a URL-stripped mode-0600 manifest, and removes the whole random directory on every return. Startup crash cleanup remains after the process lock.
- The prepared full snapshot arms only one opaque final control whose accessible name is in the signed release allowlist. The synchronous `committing` progress acknowledgement occurs immediately before activation; rejection sends no activation, while authorization is consumed before one non-retrying low-level call.
- After activation the executor enters `verifying` and accepts only a fresh same-target snapshot plus `https://blog.naver.com/<paired-account>/<numeric-id>` whose exact title, body/image/caption sequence, ordered tags, category and visibility match the frozen pre-fence evidence. Any error after the durable fence follows the existing browser-lost → `outcome_unknown` server classification and cannot invoke the publisher again automatically.
- Tests cover same- and cross-origin redirect refusal, storage-origin isolation, bearer non-forwarding, random-directory cleanup, legal/stale progress, fence refusal, missing/duplicate/renamed/scheduled final controls, one-shot ambiguous activation, exact readback mismatch classes, lease-renewal cancellation and simulated process loss on both sides of the fence. ARCH-27 passes.
