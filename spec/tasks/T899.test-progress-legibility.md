## goal
While a test runs or partly fails, the owner sees which blind contestant is working, done or failed and why; the failed-only retry of a photo observation test talks about observations, not posts; and match progress shows only once matches are ready.

## acceptance
- [ ] Deterministic, unit: a partial observation test with two succeeded and six failed contestants lists 후보 A–H, each as 관찰 완료 or 실패 with its normalized reason (요청 한도 초과, 응답이 잘림, …), and no model names; a running writing test lists each as 작성 중/완료.
- [ ] Deterministic, unit: the failed-only retry estimate of a photo observation test reads in observations (관찰 N개를 다시 할까요? … 관찰 N회 다시 시작) and never says 글 or 글 N편; a writing test keeps its post wording.
- [ ] Deterministic, unit: `0 / 7번 선택 완료` (and any decisions counter) is absent while the test is queued, running or partial, and shows as 대결 progress once matches are ready.
- [ ] Deterministic, unit: affected `pnpm --filter ./frontend exec vitest run src/widgets/writing-test src/pages/writing-tests src/features/writing-test` plus changed-file ESLint/Prettier and the ARCH-24 task lint pass.

## impl notes
- The blind wire already carries each candidate's normalized `failure` (reason only, identity-safe) and status; `mapWritingTest` maps it to `candidate.failure` (`AppFailure`). Render reasons through the existing `AppFailureMessage` (shared/ui) or the failure catalog's short labels; never show `params` or identity before reveal.
- New `WritingTestContestantStatus.tsx` in the widget renders the list (letter from the candidate's blind `displayLabel` or its index, status, reason). Mount it in the work/partial views of `WritingTestStudio.tsx` (search the `observation.partial`, `observation.progress`, `work` view and the retry estimate). Use `test.output === 'observation'` for wording.
- Retry estimate: find where the estimate view renders the retry title/body/CTA for `flow.context.retryEstimate` (keys around `retry`, `onceOnly`, `start`) and branch on observation output with new keys (`observation.retryTitle` `관찰 {{count}}개를 다시 할까요?`, `observation.retryHelp` `실패한 AI만 같은 사진을 다시 관찰해요. 성공한 관찰은 그대로 두고 다시 만들지 않아요.`, `observation.retryStart` `관찰 {{count}}회 다시 시작`).
- Match progress: the `n / N-1번 선택 완료` line (grep `선택 완료` in i18n) renders only when `test.status` is review or completed (matches ready); reword it as `대결 {{done}} / {{total}} 완료`.
- Unit receipt: every `agentChecks` entry's `candidate` is the full 40-character commit SHA (`git rev-parse HEAD`) or null.
