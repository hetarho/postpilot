# T155 Call an item group by its name and open it at its minimum
> st:todo | ssot:CLIP-61 | base:CLIP@19 | dep:T154

## goal
Make the group's declared name and minimum what the owner sees: the controls say 메뉴 추가, and a template that needs one item opens with one.

## acceptance
- [ ] the owner's composition form titles each group and labels its add and remove controls with the declared name, falling back to today's generic wording when the template declares none
- [ ] a group with a minimum opens with that many items already present, including on a project saved before with fewer, and removing below the minimum is not offered
- [ ] the add control stops at the declared maximum rather than only at the shared item limit
- [ ] the template editor can set a group's name and minimum, and the source view round-trips both
- [ ] vitest covers the named controls, the opened minimum and the fallback for an undeclared group
- [ ] verify FE `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- The owner's form is [ClipCompositionInputs.tsx](frontend/src/entities/clip-project/ui/ClipCompositionInputs.tsx): `composition.groupNumber` / `composition.addItem` / `composition.removeItem` become name-carrying variants, with the current keys kept for the undeclared case. Both locales need the new keys in the same order — the parity test compares key sequences.
- Opening at the minimum is a render-time concern, not a stored one: derive the items shown from `max(declared min, stored count)` rather than writing items into the project on load, or a project the owner never touched would be dirtied by merely opening it and the autosave would fire (CLIP-39).
- The template editor's group node is built by `newCompositionNode` ([composition-author.ts:83](frontend/src/entities/clip-template/lib/composition-author.ts#L83)), which emits `{ id }` only. Add the name and minimum there and in the row editor beside it. The 원문 view already round-trips whatever the parser accepts once T154 lands, so nothing extra is needed for it.
- Purely presentational: no admission rule moves here. T154 owns the refusal; this task owns what the owner reads and can do about it.
