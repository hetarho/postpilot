# T547 Play synchronized narration in the editable draft preview

## goal
Hear the exact ready narration assets on the draft output clock with independent source and narration gain.

## acceptance
- [ ] Narration-only preview is audible with all original sources off; mixed preview honors source/per-cut and narration gains independently and plays each speech segment at natural rate.
- [ ] Seeking, pause/resume, cut transitions, playhead scrub, changed selection and explicitly opened details keep the shared output clock synchronized without duplicate sound.
- [ ] Missing/stale/undecodable speech is named, prior audio is identified and no preview fetch/replay creates synthesis or usage; autoplay refusal offers user-gesture playback.
- [ ] Scheduler tests with an injected clock/audio context cover mid-segment seeks, cross-cut narration, speech gaps, gain zero, visibility suspension and cleanup; browser review verifies audible behavior on supported desktop and phone.

## impl notes
- Extend entities/clip-preview model/browser-audio-plan with source and speech schedules from the same transformed output clock. Keep source rate/pitch rules; narration is not tied to the current cut or its source-audio flag.
- Use Web Audio buffers for narration, the existing source-audio playback adapter, independent gains and a bounded in-memory decode cache keyed by immutable asset hash. Cancel prior scheduled nodes on seek/revision; never persist audio/signed URLs in localStorage.
- Authorized speech asset retrieval uses short-lived storage access from T540/544; refresh expired access without changing the asset identity. Cap total decoded memory through owning slice config and explicitly refuse unsupported decode/memory capability.
- Use measured sample duration and a monotonic output transport clock, not timeupdate callbacks as scheduling authority. Real-time preview need not promise exact export loudness on every device, but it must preserve intended assets, order, placement and relative mix; state existing CDS preview limits.
