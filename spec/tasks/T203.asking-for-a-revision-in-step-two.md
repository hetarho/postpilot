# T203 ② asks for a revision in its own panel
> st:todo | ssot:CLIP-131 CLIP-132 CLIP-40 CLIP-53 | base:CLIP@31 ARCH@3 | dep:T202

## goal
Let the owner write a revision request in ②, approve its credits and watch it run without leaving the correction screen.

## acceptance
- [ ] ② carries a request field bounded at the same 1000 characters the instruction uses, with the count and its bound visible while typing, and a target SegmentedControl 영상 흐름 | 자막 | 둘 다 defaulting to 자막
- [ ] the approval shows the priced writing calls for the chosen target (one for 자막, two otherwise) and changing the target re-quotes before approval
- [ ] the request shows its maximum credits and is sent only after the owner approves that ceiling, with the CLIP-81 cancellation rule stated beside it
- [ ] the request and its approval sit in ②'s panel; ②'s dock keeps exactly 확정하기, 다시 렌더 and download, and gains nothing
- [ ] while the request runs the owner stays in ②: the preview and timeline remain visible as read-only, the panel shows progress and 취소, and no focused job view opens
- [ ] a completed request shows the rewritten plan in the draft preview, marks the existing result stale and leaves rendering to 다시 렌더
- [ ] unsaved direct edits are flushed before the request is sent, so the plan the writer receives is the one the owner sees
- [ ] a failed or cancelled request explains itself in the panel and leaves the timeline and the existing result as they were
- [ ] tests: the dock is unchanged while the panel holds the request; a running request keeps ② mounted with the timeline read-only; approval is required before the request is sent
- [ ] verify FE (ARCH-25) passes

## impl notes
- CLIP-40 puts the request in the panel because THEME-39 allows exactly one ActionBar per step and ②'s is already full; treat the request as a panel control with its own approval, the way ①'s model selectors sit outside the dock
- reuse `ClipApprovalAction` (features/generate-clip) for the ceiling and the approval copy rather than writing a second approval surface — it already renders the cancellation rule, the refusal reasons and the insufficient-credit state
- the request lives beside `ClipCorrectionWorkspace` (features/correct-clip); the owner's answer to the progress question was to stay in ②, so this path deliberately does NOT reuse the focused job view CLIP-78 gives generation and rerender
- flushing: ClipPage.tsx already chains `save.flush()` then `correction.flush()` before a generation starts — the request must do the same, because T201 feeds the writer the saved plan and an unflushed edit would be silently dropped from it
- the timeline goes read-only while the request runs for the same reason the job view hides correction controls: an edit made against a plan that is being replaced has nowhere to land
- the polling lifecycle is the mounted page's (CLIP-36); do not add a second poll — reuse the job hook ①'s generation already runs so a step change cannot remount it
- copy goes in `resources/ko/clips.ts` and `resources/en/clips.ts` under a new key group beside `correction`, matching the existing 다시 출력 · 크레딧 사용 없음 wording so the charged action reads as the exception it is
