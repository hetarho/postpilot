## goal
A model list, GetMyPlan and every estimate no longer queue behind one FX fetch or take the writer when nothing needs granting, and settled jobs stop leaving eligible-lot rows behind.

## acceptance
- [ ] `RateSelector.Select` serves an already-selected rate for the current day from memory under a read lock; a fetch from the official source runs outside the mutex with single-flight (concurrent callers share one fetch); the one-minute failure memo is kept
- [ ] `BalanceFor` first asks the read pool whether `renew` would write anything for (user, acting plan, now); only when it would does it open the write transaction; the answer it returns is the same either way
- [ ] `Settle` deletes the job's `usage_admission_eligible_lots` rows in its transaction, as `Release` does
- [ ] tests: 50 concurrent Select calls with a slow source make one fetch and none of them waits on the mutex for a cached day; two BalanceFor calls in the same daily window open one write transaction between them; a settled job has no eligible-lot rows
- [ ] behaviour unchanged otherwise: ARCH-26 green
