# T308 the server serves a sequence caption's own frames
> st:done@260922 | ssot:CLIP-159 CDS-85 CDS-81 CLIP-154 | base:CLIP@43 CDS@25 | dep:-

## goal
A browser render can obtain the server's own drawing of every output frame of a sequence-rendered caption, as bounded sprite sheets over the plan it is rendering.

## acceptance
- [v] one RPC returns, for one caption instance of a validated plan, the style's own drawing for a requested run of output frames as a sprite sheet: one PNG holding the frames in order, with the cell size, the cell count, the first output frame and the layer's canvas origin
- [v] the frames are the ones a server render would draw for that caption — same crop, same progress per frame, same painter
- [v] a request is owner-scoped and pinned to the plan's draft hash: a foreign or unknown project is not found, a stale hash is refused, and a finalized project is refused
- [v] a static style is refused by name: its one raster is what the preview already serves
- [v] the response respects a stated ceiling on cell count and bytes, and a run larger than the ceiling is answered with what fits plus the next frame to ask for
- [v] serving frames changes no project state, starts no job, consumes no credits and never renders a video
- [v] go test: the sheet's cells match the frames the render's own sequence writes for the same caption, a stale hash and a static style are refused, and the ceiling pages a long caption
- [v] the media image stage is built and run locally (ARCH-37): `docker buildx build --target media-smoke -f backend/Dockerfile .`
- [v] verify: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...` · `pnpm gen:proto && git diff --exit-code -- backend/internal/gen frontend/src/shared/api/gen agent/internal/gen`

## impl notes
- the drawing already exists whole: `media/sequence.go` `captionSequence` writes one PNG per output frame for a server render, from `captionFrame(canvas, copy, layout, duration, progress)` + `design.DrawCaptionFrame`, cropped by `sequenceCrop`. This task exposes the same frames without a workspace or a render
- sheet over single frames (owner decision 2026-09-22): a 2 s caption is 60 frames, and one request and one decode per sheet beats sixty of each. Cells are the crop box, laid left-to-right in rows; the browser blits a sub-rect
- one resvg run per sheet, not per cell: tile the frames into ONE document by repeating each frame's body inside `<g transform="translate(col*w, row*h)">` against a sheet-sized viewBox. The painters use fixed filter and clip ids (`cbi`, `cneon`, `cgs%d-%d`), so each cell's body and defs go through `prefixIDs` with the cell index, exactly as `captionFragment` prefixes a fragment with its instance id — two cells sharing an id would draw one cell's filter over the other
- bounds belong with the preview's, in `clip.PreviewConfig`'s neighbourhood: a cell-count ceiling and a byte ceiling per response, checked before rasterising rather than after, and `ErrPreviewTooLarge` when one sheet's own cell cannot fit
- the request carries the project id, the draft hash, the caption's `instance_id` and the first output frame; the response carries the sheet, the cell box, the count, the first frame and the next frame (-1 at the end), mirroring `ClipPreviewAsset`'s paging shape
- reuse the preview's admission path (`app/preview.go`): same ownership, same finalized refusal, same plan validation and draft-hash check, so a browser render cannot ask for frames of a plan the server has not validated (CLIP-154)
- this is the cost the owner accepted: the server rasterises the same frames it would for its own render, but no encode, no merge and no footage pass

## result
- `PrepareClipCaptionFrames` (clip_render.proto) returns one run of a caption's frames as ONE PNG sheet with its cell size, column count, cell count, canvas origin, the caption's first output frame, this run's offset and the next offset (-1 at the end). The request carries the project, the revision, the plan and its draft hash, exactly as the preview's does.
- `media/caption_frames.go` draws the run from the render's own parts — `captionFrame` + `design.DrawCaptionFrame` at the same progress per frame, cropped by `sequenceCrop` — and tiles the cells into ONE document so a run costs one resvg invocation rather than one per frame. Each cell's filter and clip ids carry its frame index through the existing `prefixIDs`, because two cells of one document cannot share an id.
- the run is bounded twice: `MaxFrameCells` (30) and `MaxSheetPixels` (4096 in either direction, so a browser can decode the sheet whole), and the rasterised sheet is refused if it passes the response ceiling. What does not fit is answered with the next frame to ask for.
- admission is the preview's, extracted rather than copied: `admitPreview` (owner, unfinalized, exact revision — run before the work and again after it) and `correctedPlan` (the owner's correction with the project's own design and its sources) are now shared by both reads. Serving frames starts no job, writes nothing and spends no credits.
- a static style is refused by name — its one raster is what the draft preview already serves — as is an unknown caption and a frame past the caption's own run.
- go test: the sheet's cells are the frames `captionSequence` writes for the same caption (compared after normalising the per-cell id prefixes), the origin matches the render's crop, a static style and an unknown caption are refused, paging delivers exactly the caption's output frames in several runs, and the RPC is owner-scoped, hash-pinned, revision-pinned and refused on a finalized project.
- real binaries: the whole `media-smoke` image stage was rebuilt and run — MediaSmoke, MediaProfileSmoke and RenderSmoke all PASS. `TestRenderSmokeCaptionFrames` runs inside the image with the bundled fonts and the real resvg — 30 cells in 174 ms, 232 KB, decoding to the expected sheet size with distinct per-frame ink. Its first assertion was wrong and the smoke caught it: a style with an entrance fade draws its FIRST frame transparent, and the render's own first frame is transparent too, so the check now holds the settled cell and the per-cell difference rather than demanding ink in every cell.
- verification: backend gofmt/vet/build/test green; `pnpm gen:proto` regenerated Go, Connect and TS clients and is byte-stable on a repeat; `pnpm gen:sql` showed no drift; frontend gates pass with the regenerated client.
