## goal
A 지침 / 영상 지침 carries an optional `title` (≤ 40 chars) that every create surface offers and that never reaches a prompt.

## acceptance
- [v] migration `guidelines.title TEXT NOT NULL DEFAULT ''`; existing rows read with no title
- [v] CreateGuideline takes `title`, UpdateGuideline takes `optional title` (presence: absent leaves it, present replaces it, `""` clears it); both trim it; over `GUIDELINE_TITLE_MAX_CHARS` (default 40, Unicode scalar values) is `InvalidArgument` with the new reason `GUIDELINE_TITLE_TOO_LONG` carrying `max`, and nothing is written; no uniqueness on the title
- [v] `Guideline.title` is returned by List / Create / Update; a text-only or scope-only update leaves the title untouched, and a title + text + scope update applies in one transaction (a refused text rolls the title back)
- [v] the title never reaches a prompt: `ForPrompt`, the generation payload, the write-experiment snapshot and the clip attempt freeze carry texts only — a Go test asserts a post's write prompt and a clip's frozen 영상 지침 are byte-identical with and without titles on the same guidelines
- [v] candidates stay title-less: `전부 수락` creates every guideline with an empty title
- [v] `GUIDELINE_TITLE_MAX_CHARS` is BE env with a typed default in `platform/config` (non-positive or malformed is boot-fatal, like its siblings) and in `.env.example`; FE mirrors it as `VITE_GUIDELINE_TITLE_MAX_CHARS` beside `VITE_GUIDELINE_TEXT_MAX_CHARS` (`entities/guideline/config`, `shared/config`)
- [v] every create surface shows one `제목` field above the text, empty, not required: `새 지침` / `새 영상 지침` sheet, the 승인 dialog, `지침으로 저장` (post revision) and `영상 지침으로 저장` (clip revision); over the bound it says `count.exceeded` under the field and the save is disabled; the create sends the trimmed title
- [v] the ko / en failure catalogue says `GUIDELINE_TITLE_TOO_LONG` ("제목은 {{max}}자까지 쓸 수 있어요" / "A title can be at most {{max}} characters")
- [v] tests: Go service (trim, bound, clear, presence, rollback with a refused text), store (round trip, text-only update keeps the title), rpc mapping of the reason, config default/refusal, prompt byte-identity; FE: each create surface sends the title, the exceeded state blocks the save, the fake server (`src/test/guidelines.ts`) stores and returns titles and refuses over-long ones

## impl notes
- migration: next free number under `backend/internal/platform/db/migrations` at implement time (0104 when this was written; `ls` first — a peer session may take a number). `NOT NULL DEFAULT ''`, never `TEXT NULL` (sqlc types an explicit NULL as `interface{}`); no backfill ← pre-alpha data is disposable and an empty title is the defined "none"
- `guidelines.sql` stays ASCII-only: add `title` to `InsertGuideline`, `ListGuidelines`, `GetGuideline`, and a new `UpdateGuidelineTitle :execrows`; never add it to `ListApplicableGuidelineTexts` / `ListApplicableClipGuidelineTexts` ← that is how the title stays out of every prompt
- domain: `Guideline.Title string`; `Patch.Title *string`; `Service.validTitle` (trim; empty is fine; `utf8.RuneCountInString` > limit ⇒ `&TitleTooLongError{Chars, Max}`); `Limits.TitleMaxChars` wired from `cfg.GuidelineTitleMaxChars` in `cmd/api/contexts.go`; `Create` gains a `title` parameter; `Store.Update` runs the title statement inside the existing transaction, and `patch.empty()` counts it; the "first statement answers existence" rule must hold whichever part runs first
- proto: `Guideline.title = 9`, `CreateGuidelineRequest.title = 7`, `UpdateGuidelineRequest optional string title = 4`; `ErrorReason GUIDELINE_TITLE_TOO_LONG` = the next free number in `error.proto` (257 is the highest when written; check a peer's uncommitted edits with `git diff proto/` first); regenerate with `pnpm gen` (never hand-edit generated files — gen.mjs normalizes EOF)
