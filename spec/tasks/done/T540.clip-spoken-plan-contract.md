## goal
Represent narration separately from captions while keeping existing projects and audio-free clips readable.

## acceptance
- [v] Old plans with narration-caption flags load as ordinary captioned clips with no synthesized audio, voice default or implicit billing; migration and old-proto fixture tests pass.
- [v] Narration config, stable spoken segment ids, script revisions, independent caption links/edit flags, immutable speech references and measured timing survive save/reload and proto/store mapping.
- [v] Only changed spoken segments become stale; voice change stales all required speech, visual/caption edits retain compatible audio, and newer revisions reject late speech publication.
- [v] Plan validation allows stale/missing speech during editing while render/finalize readiness identifies the exact unresolved segment; foreign asset/voice ids and unsupported schema versions are refused.

## impl notes
- Under DUB-27, implement and automatically verify this task with deterministic fixtures before live supplier qualification; do not promote production readiness from fixtures.
- Extend clip.proto/clip_plan.proto additively and version the stored plan mapper; leave all existing field numbers and the narration-caption bool intact. Add optional narration enabled/confirmed_voice_id/volume, source-track master gain, ordered spoken segments and independent derived-caption metadata. Both gains default to 1 and accept 0..1 independently of source retention and existing per-cut gain. Use explicit milliseconds on the output clock, converted through existing pure timeline helpers.
- Keep spoken script and caption wording in separate fields. Each segment holds stable id, text revision/hash, owner placement and optional ready speech asset ref; each derived caption holds origin segment id, origin text version and separate text_edited/timing_edited flags. Existing owner-corrected captions are conservatively protected on import; do not infer a new script from them.
- Own clip_speech_assets and generation segment records in clip/store; account voices are references resolved through the voice context port. The plan may name only owner/project-authorized asset ids; never trust a client URL, provider voice id, duration or ready flag.
- Voice and speech provenance includes immutable confirmed binding plus input/settings/audio hash. Editing back to an exact compatible input may reuse an existing retained asset. Unsupported old/new versions refuse paid work before a call, while retained results remain downloadable.
- Use named clip limits: at most 32 spoken segments, each at most 500 code points and at most 2000 in one script. Provider-specific billable counting comes from its qualified adapter, not those validation counts. Declared segment duration/fit must use measured audio; no subtitle field is a speech input.
