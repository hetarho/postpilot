# T065 일괄 편집: the paste box, the diff preview and the export
> st:done@260909 | ssot:MODEL-54 MODEL-55 MODEL-56 MODEL-52 | base:MODEL@8 ARCH@2 | dep:T064

## goal
Give 모델 관리 one 일괄 편집 surface that exports the current document, previews a pasted one as a per-purpose diff, and applies it on confirmation.

## acceptance
- [v] 모델 관리 carries exactly one 일괄 편집 entry shared by the five tabs — not a control per tab — and it opens over the catalog without losing the tab underneath
- [v] the surface shows the current document (from `ExportCatalogDocument`) in a copyable form and a paste box for the operator's own
- [v] 미리보기 calls `PreviewCatalogDocument` and renders, per purpose, what would be registered, what would be deregistered and what already holds; nothing is written until 확정
- [v] the deregistration list is visually the loud half of the diff, and a purpose absent from the document is shown as untouched rather than as an empty diff
- [v] rejected lines render with their line number, the offending text and the cause, and 확정 is unavailable while any rejection stands
- [v] a failed live read renders the fetch error and no diff
- [v] 확정 sends the same document text to `ApplyCatalogDocument`, then invalidates the catalog query so every tab reflects the new registrations
- [v] the paste box keeps its text across a failed preview so the operator can fix one line without re-pasting
- [v] placement: UI in `frontend/src/features/manage-model-catalog/ui`, pure diff shaping in that slice's `model`, the three calls in `entities/model-catalog/api` beside the existing hooks (ARCH-14, ARCH-15)
- [v] every generic control is a `shared/ui` primitive and classes resolve to registered tokens (ARCH-20)
- [v] a vitest beside the code covers: a diff with adds and removes, a document with rejected lines keeping 확정 unavailable, an untouched purpose, and 확정 issuing the apply call with the pasted text
- [v] `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` (ARCH-25)

## impl notes
- the entry belongs to `ModelCatalogManager` rather than to a tab: one document names any purpose (MODEL-56), so a per-tab control would misrepresent what a paste changes
- diff shaping is pure and lives in the slice's `model` segment beside `catalog-view.ts`; the server already returns the three per-purpose lists, so the client sorts and groups them and invents no comparison of its own
- the preview response is display state only — 확정 re-sends the document text, never a preview id (MODEL-54), so the component keeps the text as the source of truth
- copy is Korean admin copy local to this surface; the rejection causes are rendered from the server's cause strings through a local map, not through the FE reason catalog (see T064)
- no new dependency: the textarea, buttons and the diff list are existing `shared/ui` primitives and the calls reuse the Connect client `entities/model-catalog/api` already holds

## result
- files: `entities/model-catalog/api/useCatalogDocument.ts` (new) · `model/types.ts` `api/catalog-mappers.ts` `index.ts` (+the plan/issue types and their mapper) · `features/manage-model-catalog/model/document-view.ts` + test (new) · `ui/CatalogDocumentPanel.tsx` + test (new) · `ui/ModelCatalogManager.tsx` (the one 일괄 편집 entry) · `shared/api/index.ts` (three response schemas + two response types) · `test/model-catalog.ts` (the fake now models the document path) · ko/en `models.ts` (the `document` block)
- the panel resets by REMOUNT, not by an effect: the parent bumps a session key on open. An effect that cleared the previous paste tripped `react-hooks/set-state-in-effect`, and the key expresses the same rule better — the state is the session
- editing the paste box drops the plan on screen, so 확정 can never commit a diff computed for text that has since changed; the text itself survives, which is the point of the acceptance
- the apply's answer replaces the preview's when both exist, so a rejection the catalog moved into between the two calls renders through the same list as one caught at preview
- an unknown cause slug renders through a fallback string rather than another cause's copy — a newer server must not be able to mislabel a line here
- copy went into the ko/en `models` namespace rather than staying Korean-only as the impl notes assumed: the locale parity test requires both, and ARCH-1 has the product bilingual. The note was written before reading the i18n setup
- the fake ModelCatalogService now parses and applies the document the same way the server does, so the page tests drive the real contract (whole-purpose sync, all-or-nothing rejection, fetch failure refusing) rather than a stub's idea of it
