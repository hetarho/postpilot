## goal
Persist authored compositions, grouped answers and project snapshots while converting legacy recipes without changing retained results.

## acceptance
- [v] Owned template/project CRUD round-trips raw body, stable field/item IDs and exact values; only declared required fields block generation and no category/disclosure/minimum-fact gate survives for the new contract.
- [v] Additive migrations preserve existing answers, template identities, results, analysis and plan revisions; legacy campaign/CTA/preset defaults become explicit editable content without leaking project-specific choices into a shared template.
- [v] Generation quotes bind the exact composition, answers, item associations and settings; any changed input invalidates approval before a model call, and the accepted job freezes those values.
- [v] Deleting or editing a reusable template leaves the retained project composition and prior output readable; manual correction/rerender can use the retained snapshot after template deletion.
- [v] Owner isolation, migration/restart idempotence, detached templates, duplicate field labels with distinct IDs, legacy empty presets and distinct disclosure choices on two projects sharing a template are covered by store/RPC tests.
- [v] Run the applicable local ARCH-25 through ARCH-29 checks, deterministic proto/SQL regeneration when changed, and spec lint; use a before/after generation snapshot when unrelated generated changes already exist.

## impl notes
- Add nullable composition_body to video_templates and versioned composition_inputs_json/composition_snapshot_json to clip_projects in the next embedded goose migration. Keep domain structs free of storage/JSON tags and keep serialization in store adapters. Existing fields stay as legacy read inputs until migration coverage is verified; do not reuse proto field numbers.
- Composition inputs contain global answers keyed by field ID, ordered group items with stable item IDs and field values, and owner-authored source-range associations keyed by source ID plus fingerprint. A source range association carries start/end and cannot outlive a mismatched fingerprint. Labels are presentation, never the new identity key.
- Extend template/project protobuf messages additively with body and typed input/snapshot projections, presence-based patches and stable field/element validation errors. Backend parsing is authoritative. Generate all three proto targets and sqlc outputs.
- Convert old recipes deterministically to explicit fields, guide, scene repetition and optional role elements; convert each project snapshot from its own disclosure/hide flag/CTA/answers and retained plan. Preserve absence of legacy cards and empty text. A deleted-template project uses the retained plan/styles/analysis; conversion never fabricates missing facts. Conversion on legacy read is pure and idempotent, with the editable form persisted on the next accepted write.
- Introduce stored plan version 5 with a template snapshot, source cuts, resolved text elements, authored/automatic placement and timing authority, item/evidence references, and copy-fallback reasons; retain version 1–4 readers and upgrade into explicit element records. Keep the existing successful MP4 key and its revision unchanged until an explicit rerender.
- Include the canonical resolved composition and input values in quote digest and job freeze. Remove preset-based RequiredAnswers/ApprovalGate assumptions for version 5, while legacy compatibility uses only its explicitly converted content. Reserve obsolete SeedPresetFields and campaign IDs as read compatibility, never as new-authoring defaults.
- Expose a workflow capability version so intermediate deployments do not offer generation for an unsupported composition version; version-5 authoring may store drafts, but generation/render capability becomes available only when T127/T128 handlers are present. No partially supported template may silently run through the legacy renderer.
