# T312 Export retirement outcomes and purge publishing-owned data
> st:done@260922 | ssot:PUB-40 PUB-41 PUB-42 PUB-45 PUB-46 PUB-48 ARCH-6 ARCH-10 ARCH-43 | base:PUB@6 ARCH@7 | dep:T282

## goal
Extend the temporary operator command to safely remove publishing copies and records after verified shutdown, retaining a private outcome report.

## acceptance
- [v] Inspection is read-only by default. Apply requires the T310 cutoff, verified original report/digest, matching environment/database identity and a recorded companion-shutdown inventory; unresolved devices or a missing/stale report refuse destructive work.
- [v] Cleanup removes only objects whose exact key is under publishing/, including unreferenced orphan copies, after fully paginated listing; it never touches source post photos/videos, clip objects, other prefixes or other buckets. Any referenced key outside the permitted prefix fails closed.
- [v] Object failures or listing failures produce a nonzero result and retain bookkeeping needed for retry; successful deletions are idempotent, and no database transaction spans object-storage I/O.
- [v] After referenced assets and a final full-prefix sweep are verified absent, delete publish_assets, publish_jobs, publish_job_ids, publishing_agents and publishing_pairings rows in foreign-key order; retain the tables and retirement guards for T283. Original reported URLs and unknown results remain in the private report, never fabricated as successful/failed publications.
- [v] A machine-readable verification receipt records cutoff/report digest, environment identity, zero publishing rows and zero listed publishing objects plus the reconciled shutdown inventory; empty installations and repeated cleanup succeed without overwriting the original outcome report.
- [v] Fixture/MinIO tests cover every terminal classification, deleted source posts, two owners, empty data, pagination, orphans, failed individual deletion, failed final listing, interrupted retry and malicious out-of-prefix keys; unrelated records and source object checksums remain identical.
- [v] Backend tests/build and temporary-command tests pass; DEPLOY.md describes the bridge rollout, report custody, idempotent cleanup, verification and the final-removal precondition separately from code completion.

## impl notes
- Extend backend/cmd/retirepublishing from T310 with explicit apply and verify modes; keep use cases in the publishing context and reuse the existing object-store List/Delete ports. No new dependency, public endpoint, scheduled cleaner or permanent retention service.
- Load all safe metadata before deleting anything and atomically persist the report. File/digest validation must verify the record inventory and cutoff, not merely trust a boolean flag. Shutdown receipts are operator evidence, not a claim that the server can remotely inspect a Mac.
- For object deletion use only validated exact keys from a complete listing/asset inventory. Confirm cleanup with a fresh full listing; leave original media checksums unchanged. A retry after row deletion can still find any orphan by the fixed prefix, and failure never deletes its original report.
- T310 has stopped sweeps and producers; do not keep the former 24-hour orphan age delay, because the retirement prerequisite is a stopped producer set. Do not clear rows first and hope that an ordinary sweeper will later find their objects.
- This command operates across the deployment's publishing records as an operator tool and needs no Naver cookies. Its report is owner-only and never committed to Git; only a redacted verification receipt/counts belong in task results or deployment notes.
- The initial and bridge application versions must have fully stopped producing objects; an already-issued external final click is outside recall and remains unknown. Do not use Naver network calls to settle it.
- Implementation acceptance uses seeded disposable DB/object-store fixtures. Real deployment cleanup is an explicit operator rollout action; never claim production data was purged merely because fixtures passed. Keep the bridge build available until every deployed environment has passed this checkpoint.

## result
- Added inspect, apply and verify cleanup modes to the private retirement command. The command authenticates the immutable T310 report and digest, database/environment identity and an owner-only, evidence-digested companion shutdown inventory before permitting mutation.
- Cleanup inventories the complete `publishing/` namespace, rejects unsafe keys, persists retry state before object deletion, verifies the prefix empty and only then deletes publishing rows in one short foreign-key-ordered transaction. The original outcome report is never rewritten.
- Added disposable SQLite and object-store fixtures for terminal outcomes, multiple owners, deleted source posts, empty/repeated cleanup, pagination, orphan objects, interrupted failures and malicious keys. The optional real MinIO test is gated by `CLIP_SOURCE_TEST_ENDPOINT` and was skipped when that environment was absent.
- Focused retirement packages pass. On the staged snapshot, formatting, vet and build passed and all backend packages except the existing long-running `internal/clip/store` whole-suite contention completed successfully; the regression at the timeout site passed alone in 46.8 seconds after concurrent backend gates ended. No production cleanup was executed: operators must retain the bridge build and follow `DEPLOY.md` per environment before T283 final removal.
- SSOT deviation: none.
