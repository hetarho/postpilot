# T027 The estimate becomes a calculator on /plans
> st:done@260907 | ssot:QUOTA-41 QUOTA-36 QUOTA-40 QUOTA-24 QUOTA-28 | base:QUOTA@5 THEME@4 LANG@1 ARCH@2 | dep:T025

## goal
Put an adjustable characters / photos / videos control above the rungs with a combo picker, and recompute every rung's post count from the published rates as the reader moves them, with no request per change.

## acceptance
- [v] a new `shared/ui/slider` primitive wraps a native `<input type="range">`: a visible label, the current value as text beside it, `min`/`max`/`step`, a 44 px thumb and track drawn from two new registered roles, `aria-valuetext` carrying the localized value, and keyboard operation left to the native element
- [v] the calculator sits above the rung list with three sliders — 글자 수 200–5,000 step 100 (default 1,000) · 사진 0–30 step 1 (default 5, the ceiling being QUOTA-24's `UPLOAD_MAX_PHOTOS_PER_POST`) · 영상 0–3 step 1 (default 0, the ceiling being VIDEO-3's `UPLOAD_MAX_VIDEOS_PER_POST`) — and a `SegmentedControl` over the assigned combos
- [v] each rung shows `매달 약 {{count}}편` recomputed from the selected combo's rates: `credits = PerPostBase + photos × PerPhoto + videos × PerVideo + ceil(chars / 1000) × Per1000Chars` in milli-credits, then `floor(monthlyCredits × 1000 / credits)`; the client does that arithmetic and nothing else (QUOTA-40)
- [v] a rung whose grant cannot cover one post says so instead of `약 0편`, and `master` shows the unlimited label rather than a count
- [v] one caveat line under the list states the assumption and that the real charge depends on the actual work (ko: 실제 사용량은 사진과 글 길이, 모델에 따라 달라져요)
- [v] with no combo assigned the rungs still render their grant and price, and the calculator area says the estimate is not set up yet — no error, no empty picker
- [v] moving a slider issues no RPC: a test asserts the call list is unchanged across several changes while the counts change
- [v] the three values persist for the session in `localStorage` under one key so returning to `/plans` keeps the reader's own case, and a throwing or missing store falls back to the defaults without breaking the page (THEME-2's storage discipline)
- [v] i18n ko/en at full parity: the three slider labels and value formats, the four combo labels, the estimate line, the too-small line, the caveat, the unset line (LANG-7)
- [v] `PlansPage.test.tsx` grows cases for: the default figures per rung, a slider change moving every count with no request, the zero-video default, the too-small line, the unset-combo state, and the combo switch changing the counts
- [v] `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` pass

## impl notes
- the estimator arithmetic lives in `entities/plan/model` as a pure function over the published rates plus the three inputs, unit-tested there rather than inside the page ← the page composes, and a figure this visible deserves its own test without a DOM
- milli-credits keep the client integer-only: rates arrive as milli, the sum stays milli, and only the final division floors (`Math.floor(grant * 1000 / milliPerPost)`)
- `ceil(chars / 1000)` rather than a proportional part ← the write budget is derived per post from the requested length and a partial thousand still costs a whole call's output ceiling; it also keeps the arithmetic monotonic as the slider moves
- the combo `SegmentedControl` is the existing primitive at exactly its bounded four options (THEME-29); the sliders are new because nothing in `shared/ui` adjusts a bounded number, and the native range element brings keyboard and pointer behaviour with it
- two new functional roles for the slider (`--slider-track` on `surface-recessed`, `--slider-thumb` on `intent-accent`) rather than borrowing `--meter-track` ← a meter reports and a slider is operated; sharing one role would make either component's change move the other
- `pageStyles('board')` is the right column width now that the page holds a control strip plus four columns (THEME-26)
- the storage key follows the theme's shape: one namespaced key, every read and write in try/catch, a malformed value read as absent
- removal check before finishing: no `estimatedPosts` reference survives on the offer, and the T023 caveat key is gone (T025 removed the copy keys)

## result
- new `shared/ui/slider`: a native range input with its value as text, `aria-valuetext`, a 44 px control height and two new registered roles (`--slider-track`, `--slider-thumb`) kept separate from the meter's
- `pages/plans/ui/PlanEstimator.tsx` (the three sliders + the combo `SegmentedControl`) and `pages/plans/model/estimate-input.ts` (`useEstimateInput`, `firstCombo`, the clamped storage read)
- `PlansPage` derives each rung's count from the selected combo's rates through `postsPerGrant`, states the too-small case in words, drops the count entirely when no combo is assigned, and carries one caveat line under the list
- `shared/config`: `PLAN_ESTIMATE_BOUNDS` (chars 200–5 000/100 · photos 0–`UPLOAD_MAX_PHOTOS_PER_POST` · videos 0–`UPLOAD_MAX_VIDEOS_PER_POST`), `PLAN_ESTIMATE_DEFAULTS` (1 000 자 · 5 photos · 0 videos), `PLAN_ESTIMATE_STORAGE_KEY`
- i18n ko/en: the whole `plans.estimator` block
- tests: the default counts per rung (4 / 19 / 52 / 108 at 11.015 credits a post), sliders moving every count with the call list unchanged, a combo switch repricing, the case surviving a remount, the too-small wording, and the unassigned state
- the estimator's own state is deliberately in the page, not the entity: `useEstimateInput` and `firstCombo` moved to `pages/plans/model` because ESLint's react-refresh rule forbids a component file exporting non-components, and `model` is where ARCH-15 puts state anyway
- a stored case is clamped to the same bounds the sliders offer, so a value from an older build cannot price a post the product would refuse to accept
- `beforeEach` in the page test clears the storage key ← the first case's sliders would otherwise become the next case's defaults, which is exactly the pollution the persistence introduces
- verified: FE 1106 tests · lint · lint:fsd · lint:style(+probe) · build:web · BE untouched and green
