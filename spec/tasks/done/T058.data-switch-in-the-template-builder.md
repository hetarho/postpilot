# T058 데이터 받기: the switch on the builder's two text rows
> st:done@260909 | ssot:TMPL-44 TMPL-26 TMPL-36 TMPL-41 | base:TMPL@4 THEME@6 ARCH@2 | dep:T055

## goal
Let a template author say "ask the post's author for this" on an AI가 쓰는 글 or 고정 문구 row, and teach the copyable 형식 안내 the construct that says it.

## acceptance
- [v] `shared/ui/switch`: a `Switch` primitive — `role="switch"` with `aria-checked`, its own 44 px hit area over a drawn track the way `Checkbox` does it, tokens only, disabled state at 50%, labelled by the caller
- [v] the expanded AI가 쓰는 글 and 고정 문구 rows carry a `데이터 받기` switch; the 사진, 사진마다 반복 and AI에게만 하는 말 rows do not
- [v] turning it on reveals a `제목` field seeded from the row's own text with a live counter against `TEMPLATE_ASK_LABEL_MAX_CHARS`; turning it off restores the row's authored text and drops the title
- [v] a 고정 문구 row with the switch on shows the 제목 field in place of its text field (the title IS that row's authored content); an AI가 쓰는 글 row keeps its instruction field beside the title
- [v] on a row nested in 사진마다 반복 the switch renders disabled with its reason stated in place, never hidden
- [v] the collapsed row keeps its kind badge and adds the 데이터 받기 mark plus the title in its one-line summary
- [v] flipping the switch makes the draft dirty by itself, and 저장 refuses a duplicate title with the same in-place message the parser's `duplicate_ask_label` produces
- [v] `entities/template/model/guide.ts` teaches `<ask>` — both flavors, `label` required and unique, not inside a repeat, the ceiling, and that a field the post's author leaves off disappears from the post — with no retired construct and the tags left as they are
- [v] tests: the switch appears on exactly two kinds · on → 제목 → body carries `<ask label="…">`, off → back to `<write>`/literal · the nested row's switch is disabled and says why · a duplicate title is refused · the collapsed summary · the guide text names `ask` and the guide snapshot test still passes
- [v] verify: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- the switch is a NEW `shared/ui` primitive, not a reused `Checkbox` (owner's call): a checkbox says "this row is selected" and this control says "this position's data comes from outside", and ARCH-20 forbids a slice hand-rolling either. THEME-29's roster owes a `Switch` line — see STATE next; nothing else in the design language changes
- the composition editor stays in `entities/template/ui` (→TMPL-33): this is a controlled input over the entity's own `body` field and performs no mutation
- the row is the same block edited in place (→TMPL-44), so the switch writes through the existing complete-block contribution path in `blocks.ts` (T055 already round-trips `ask`) — do not introduce a second representation of a row's state
- seeding the title from the row's text is what makes the flip cheap for the body the owner already wrote (a 고정 문구 line reading `총평 별점` becomes the question); the seed happens once, on the flip, and the two fields are independent afterwards
- duplicate titles are caught in the editor rather than only at save because the parser refuses the body outright — showing it on the offending row is the only way the author can tell WHICH two collided
- the guide and the grammar rule ship together (→TMPL-41): a construct added to TMPL-18 lands in the guide in the same change, so the guide edit is part of this task and not a follow-up

## result
- files: new `shared/ui/switch/Switch.tsx` + test + `shared/ui/index.ts` · `entities/template/model/{blocks,guide}.ts` + their tests · `entities/template/ui/TemplateComposition.tsx` + test · `pages/template/ui/TemplatePage.tsx` + test · i18n ko/en `templates.ts`
- `ask` distinguishes ABSENT from EMPTY: `undefined` is a row that does not ask, `''` is one that asks with no title typed yet. The first cut derived the switch from "the title says something" and a test caught it — clearing the title to retype it collapsed the field under the caret. An empty title keeps the row out of the body the way an empty `<write>` already does
- the 제목 field shows the RAW title, not the trimmed one: trimming the input's own value ate a space the moment it was typed, so `총평 별점` could not be written at all. Trimming belongs to serialization and to the duplicate check
- TMPL-44's "저장 refuses a duplicate title" is implemented as: `toValidBody` leaves the colliding row OUT of the body, and the composition reports the collision upward through a new `onAskConflict` prop which the page adds to its `blocked`. Emitting the duplicate instead would have made the builder produce a body its own parser refuses — and the composition would then have flipped to its UNREADABLE state (TMPL-30) and taken the outline the author was editing with it, which is how the test found this. The row stays on screen with the in-place message, and 저장 is refused rather than silently saving a template missing that row
- turning the switch on seeds the title from the row's own text, but skips the seed when that text would exceed `TEMPLATE_ASK_LABEL_MAX_CHARS`: a title the server refuses would leave a draft nobody can save, which is worse than an empty field with a counter beside it
- `guide.test.ts`'s retired-construct check was `label=` as a bare substring, which `ask` now trips. TMPL-18 fixes what TMPL-41's parenthetical means — the retired SLOT label, alongside the retired place and link KINDS — so the check is now scoped to `<slot … label=` and the guide teaching `<ask label="…">` breaks no decision. No SSOT change was needed; if the owner wants TMPL-41's text to spell that out, it is a one-line update-ssot
- THEME@6 (not @5) is the base: the parallel session that revised THEME put `Switch` on THEME-29's roster while this task was queued, so the primitive this task builds is the one that decision describes
