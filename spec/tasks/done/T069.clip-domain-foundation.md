## goal
Create the owned clip-project and video-template aggregates, their storage and their authenticated Connect contract, without uploads, model calls or rendering yet.

## acceptance
- [v] migration `0035_clips.sql` creates `video_templates`, `clip_projects` and `clip_project_answers`; every row is account-scoped and cascades from `users`, a project has a composite owner-safe reference to its template, and a template-delete trigger clears only `video_template_id`
- [v] `video_templates` stores `id`, `user_id`, trimmed unique `name`, ordered `information_fields` JSON, `cut_guidance`, ordered `copy_styles` JSON, optional approved `accent`, `created_at` and `updated_at`; malformed stored JSON fails the read rather than becoming an empty recipe
- [v] `clip_projects` stores immutable `id`, `user_id` and `ratio`, mutable `title`, `video_template_id` and `target_duration_ms`, nullable `analysis_json`, `edit_plan_json`, `result_key`, `result_content_type`, `result_bytes`, `result_duration_ms`, `result_created_at`, integer `edit_plan_revision` and `rendered_plan_revision`, plus timestamps; no source object key or source bytes column exists
- [v] `clip_project_answers(project_id, label, answer, updated_at)` keeps one answer per label, cascades only with the project and survives template reassignment or deletion
- [v] `backend/internal/clip` owns pure types, validation, consumer-declared ports and services; ids are random 16-byte hex, ratios are exactly `vertical|horizontal|square`, and target duration is 15–90 seconds
- [v] video-template validation: name 1–40 scalars, cut guidance at most 4,000, at most 10 information fields with unique trimmed labels of 1–40 and prompts of 1–200, and a non-empty subset of `clean|diary|emphasis`; project title is 1–100 and each answer at most 500 scalars
- [v] `proto/postpilot/v1/clip.proto` adds authenticated `ClipService` procedures to list/create/update/delete video templates and list/create/get/update/delete clip projects; update fields are presence-aware and no update request exposes ratio
- [v] creating or assigning a project resolves an owned template; incomplete answers may be saved, while the later generation gate remains responsible for requiring every current information field
- [v] deleting a video template atomically reports and detaches its projects while preserving their answers, analysis, plan and result columns; a detached project must choose another template before generation
- [v] unknown and foreign ids are indistinguishable `NotFound`; validation and duplicate-name failures use registered stable reasons with ko/en catalog entries, and no handler accepts a user id
- [v] store, service, RPC and migration tests cover owner isolation, ratio immutability, presence updates, answer preservation, malformed JSON, detach counts and cascades
- [v] ARCH-26 and ARCH-28 pass with generated Go, agent and TypeScript contracts committed

## impl notes
- keep both aggregates in `internal/clip`: a video template exists only to drive clip projects and splitting a second context would add ports before any independent lifecycle needs them
- store ordered fields and style ids as JSON because the template is replaced and validated as one recipe; keep project answers relational because a single field save must not read-modify-write or erase an answer from another tab
- use the existing TMPL detach-trigger pattern instead of `ON DELETE SET NULL` on the composite key; SQLite would otherwise null `user_id` together with the template id
- `ClipProject` read models may carry result metadata but never a persisted URL; T076 mints short-lived view and download URLs after the result store exists
- put every bound in `platform/config` as code-owned exported values consumed by the clip service; the frontend mirrors them through the generated/handwritten clip entity in T070/T072, not through new environment variables
- add one `clips` i18n namespace for both project and video-template surfaces and register every new failure in the existing LANG-21 boundary; record that LANG-7's namespace inventory needs an `update-ssot LANG` follow-up
