# T219 The approved caption style set, its faces and its glyph fallback
> st:done@260917 | ssot:CDS-80 CDS-17 CDS-18 CDS-25 CDS-66 CDS-84 | base:CDS@21 CLIP@32 | dep:-

## goal
Introduce the caption style registry — each style fixing its face, type role, colour treatment and motion — with the static styles rendering and a face that cannot set a syllable falling back with a notice.

## acceptance
- [v] a style registry in `internal/clip/design` names every approved style with its face, type role, colour treatment, motion and whether it is static or sequence-rendered, and `크게 강조` is the default
- [v] Jua and NanumMyeongjo ship beside Pretendard and Paperlogy, each pinned by exact size and SHA-256 at construction as the existing two are, with the licence notices in the image
- [v] the renderer passes every bundled face to resvg with system fonts off and sets a caption in the face its style names
- [v] a caption whose style's face lacks one of its syllables renders in the default style instead and records a CLIP-108 notice naming that caption; no glyph is ever substituted from another family
- [v] a style id outside the project's allowed set is refused before rendering as an authoring error
- [v] the static styles render in a golden test per style and per ratio, and the glyph-coverage check has a test using a syllable Jua lacks
- [v] the ffmpeg/resvg name check (ARCH-39) still passes and the media image stage builds and runs locally (ARCH-37)
- [v] ARCH-26 passes

## impl notes
- the registry is Go code, not JSON in `design.json` ← a style carries filter graphs and generated geometry that a constants file cannot express, while `design.json` keeps the numbers both sides mirror
- glyph coverage is read once per face at construction from its cmap and cached, so the per-caption check is a set lookup
- every filter in a style declares `color-interpolation-filters="sRGB"` ← resvg computes filters in linearRGB by default and the colour then differs from what a browser draws (→CDS-83)
- `feDisplacementMap` is not admitted to any style ← resvg 0.48.1 places its result at the wrong offset, so a style using it cannot satisfy CDS-83

## result
- `internal/clip/design/caption_style.go` is the registry: sixteen approved styles, each fixing its face, weight, tracking, colour treatment and motion and declaring itself static or sequence-rendered, with `크게 강조` first and default. The numbers the preview and the renderer must agree on to the pixel stay in `design.json`'s `regions.caption`, which gained the fifteen new entries and which the registry refuses to start without (→CDS-83). The fifteen come from the rendered exploration in `tmp/caption-styles/`, made with the production resvg and ffmpeg.
- `design.CaptionStyle(id)` became `CaptionRule(id)` and the type took the name; `CaptionMotion` now takes the style as well as the pace, because the motion is the style's own (CDS-4). The manifest keeps the style the copy carries rather than the one the layout resolved it to, so a stored plan's retired name stays its own history and V13's per-style anchor step still reads what it read.
- Jua and NanumMyeongjo 400/800 ship beside Pretendard and Paperlogy, each pinned by size and SHA-256, each with its OFL notice and a README recording its checksums and its family name. `RenderConfig.FontPath`/`DisplayFontPath` became `FontPaths`, keyed by face and weight; five `CLIP_FONT_*` settings feed it and the image already copies `assets/fonts/` whole.
- Glyph coverage is read from each file once at construction over the ranges Korean captions use, so the per-caption check is a set lookup. A caption whose style's face lacks a syllable is drawn in the default style instead and records a `composition_caption_glyph` / `style_fallback` notice naming it (CDS-84); the swap is one caption's, never the project's.
- Contrast is measured against `stroke.dark` only where a style actually strokes in it: a coloured outline is decoration, not a backing, so such a style is measured against its sampled ground instead (CDS-44).
- The caption overlay template now declares `color-interpolation-filters="sRGB"`, which added that one attribute to all six `bold` goldens and changed nothing else in them; the default treatment is otherwise byte-identical to what it rendered before.
- Verified: ARCH-26 green, ARCH-25 green, `docker buildx build --target media-tooling` (ARCH-39) and `--target media-smoke` (ARCH-37) both green.
- Out of scope, found here: `TestDeclaredRegionsUseDocumentSelection` and `TestAuthoredAdmissionUsesSelectedRegionLimits` were left red by T217's commit — they still expected the frozen document to choose the region preset. Both were retargeted at the project's selection, which is what CLIP-139 now says.
- Not changed, worth an update-ssot: CDS's `constraints` still lists `face_family` with two faces. CDS-17 already names four, so the constraint line is behind its own decision.
