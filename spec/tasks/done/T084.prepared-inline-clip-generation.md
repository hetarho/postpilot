## goal
Run approved clips through prepare-all bounded analysis copies, one protected AI sequence and original-quality rendering within bounded shared-service resources.

## acceptance
- [v] each original is downloaded once during preparation to a bounded temporary file, verified and converted from that same file, then removed before the next original; every source and every proxy is verified before any hold or AI call
- [v] prepared copies retain the existing ordered source/chunk coverage and timing, each at most 60 seconds, long edge 720 pixels and 8 MiB; one bounded preparation-only recompression may retry the same interval, but no extra chunks, omitted footage, stretched timing or AI retry is permitted
- [v] all prepared copies stay in the job workspace as file descriptors/metadata, not accumulated byte buffers or R2 uploads; paths are unique across sources and remain valid until their own analysis finishes
- [v] exact prepared call counts and frozen budgets are reserved once within the approved maximum; malformed media, remaining oversize, insufficient disk, incompatible models, ceiling excess or admission failure before analysis causes zero provider calls and zero credit debit
- [v] every analysis call uses T083's inline/static input and every analysis/plan call carries the admitted price policy; the metered allowance rejects changed refs, raised budgets, missing constraints and extra calls before network I/O
- [v] the plan call receives only bounded structured analysis, recipe and answers; final rendering uses the selected originals and original audio, preserving current ratio, caption, correction and free-rerender behavior
- [v] workspace/source cleanup succeeds on success, preparation failure, partial paid failure, cancellation, panic and boot recovery; old persisted proxy objects remain sweepable but no new proxy object is uploaded or presigned
- [v] one clip media job at a time runs on the shared service; fixed worker/process bounds and temporary-disk limits prevent concurrent originals/encoders or accumulated encoded request bodies, and workspace cleanup never removes active work
- [v] previous successful result/analysis/plan survive all failed attempts; terminal accounting follows T081/T082, unknown usage does not produce a fabricated zero supplier bill and no failed attempt restarts automatically
- [v] service/media/job/metering/store tests assert the full prepare-before-hold-before-AI order, actual chunk counts, last-source failure, second compression failure, cleanup ownership, guard enforcement and original rather than proxy rendering
- [v] real-media tests cover rotation, variable frame rate, speech/audio continuity, no audio, high-motion/noisy 60-second input and all three result ratios; the production image passes a nonroot smoke with bounded memory/CPU, with no live AI request
- [v] ARCH-25 through ARCH-28 and ARCH-31 local gates pass; version 2 is enabled only after the complete guarded runner replaces the old path, and version 1 remains refused

## impl notes
- replace the current separate `probeBatch` and analysis redownload loops in `clip/generation.go` with a preparation pass yielding an ordered runtime manifest of original metadata plus verified proxy paths; change the media callback lifetime to workspace-owned outputs instead of deleting them immediately
- retain the existing 60,000 ms chunk partition and source-relative coordinates; use source id plus chunk index for filenames, normalize rotation/SAR, and verify decode, full intended coverage, A/V continuity, dimensions and final bytes after encoding
- initial analysis profile: MP4/H.264 yuv420p, 15 fps, long edge at most 720 without upscaling, CRF 28, maximum video rate 900 kbit/s with 1,800 kbit buffer, mono AAC 48 kHz at 64 kbit/s when audio exists; one retry uses 650 kbit/s with 1,300 kbit buffer and the same timing/resolution/audio; do not reduce original-render settings
- use one decoder/encoder/filter thread for analysis, sequential subprocesses and the existing bounded timeout/stderr handling; codec options must be checked against current [FFmpeg codecs](https://ffmpeg.org/ffmpeg-codecs.html) and [filters](https://ffmpeg.org/ffmpeg-filters.html), then pinned by real-media quality tests, not assumed to improve model token billing
- an output-size flag alone is not proof of a complete video: do not accept a truncated container to meet 8 MiB; stop an over-limit encoder safely, recompress the full same interval once in preparation and fail if it still cannot satisfy every bound
- add typed limits of 512 MiB for prepared proxies and 8 GiB for the entire job workspace, including originals, render intermediates and any encoded request scratch; keep at most one 2 GiB original locally, account bytes/free-space before allocations and enforce limits while subprocesses write, rather than discovering disk exhaustion after AI
- the current source limits imply at most 49 actual chunks and 392 MiB of valid proxies; reject overflowing calculations and enforce source/batch limits independently of metadata; temporary-storage checks do not alter browser-to-private-storage uploads
- keep the current single global worker (`WorkerConcurrency=1`) and pin that invariant with config/wiring tests; no extra queue, process, instance or background media pool is introduced; analysis and free rerender use the same serialized execution path
- release each proxy after its analysis and all remaining proxies on exit; rendering continues to load only needed original files sequentially through the existing renderer source loader, and all paths/readers are absent from durable snapshots and logs
- validate compatibility and price-policy enforceability again after preparation, then call the exact-count reservation; install its allowance in the worker context and require that policy at `meteredRegistry.Complete`, so a custom caller cannot bypass it by omitting request fields
- compare the complete T083 versioned modality/endpoint policy at reservation and metering, not only model refs or the two catalog token prices; refuse old token-only pricing snapshots. Pass only verified at-most-60-second proxies into the static profile and use the shared per-call quote calculator with actual counts; never estimate final usage from its conservative envelope
- transition the version-2 runner guard from T082 to this complete implementation; old version-1 queued work fails without paid calls, interrupted work remains failed on restart and previous source/proxy cleanup records are retained for recovery rather than migrated into new paid attempts
- preserve the existing atomic result replacement/outbox and T081 terminal settlement ordering; safe technical details may name stage, source id, measured limits and normalized cause, never raw provider bodies or media
- use backend-owned reasons `CLIP_ANALYSIS_TOO_LARGE`, `CLIP_WORKSPACE_LIMIT` and `CLIP_MODEL_INPUT_UNSUPPORTED` with typed metadata and ko/en reason entries; no error path offers an automatic paid repair
- CLIP-35 remains deferred: do not add cached-analysis composition-only generation; manual correction and its original-source credit-free rerender remain the only separate edit action
