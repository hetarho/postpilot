# T153 Admit the empty legacy disclosure a composition project saves with
> st:done@260914 | ssot:- | base:ARCH@2 | dep:-

## goal
Let an owner save edits to a composition-template clip project, which update admission refuses today over the empty legacy disclosure creation already allows.

## acceptance
- [v] `UpdateProject` accepts an empty disclosure on a project whose composition is authored, still refuses one on a legacy project (CDS-5), and still refuses any unsupported non-empty value
- [v] behaviour otherwise unchanged — the existing clip suites still pass
- [v] a Go test drives the client's real patch shape: a composition project whose stored disclosure is `""`, updated with `Disclosure` set to `""` alongside its composition inputs, saves; the same patch with `"nope"` is refused with `clip.ErrInvalid`
- [v] verify BE `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...`

## impl notes
- from review/clip-project-update-260914 F1
- The whole fix is the guard at [service.go:283](backend/internal/clip/service.go#L283): make it read `p.Disclosure != nil && *p.Disclosure != "" && !ValidDisclosure(*p.Disclosure)`, which is exactly what [service.go:235](backend/internal/clip/service.go#L235) already does on creation. Do not change the frontend to stop sending the field: the empty value is a real state a composition project holds, and admission has to accept writing it.
- `design.Disclosure` holds only `ad`, `sponsored`, `provided`, `paid`, `self`, so `ValidDisclosure("")` is false and always will be; the emptiness test belongs at the call site, beside creation's.
- Existing composition coverage misses this because every `UpdateProject` call in `store/composition_test.go` leaves `Disclosure` nil, while the browser sends the whole draft on every save. The new test must set the pointer, or it reproduces nothing.
- Put it in `backend/internal/clip/store/` beside [disclosure_test.go](backend/internal/clip/store/disclosure_test.go), which already owns disclosure behaviour and has the `setup(t)` harness; build the project with a `CompositionBody` template and no `Disclosure`, as `composition_test.go:142` does.

## result
- changed: the disclosure guard in [service.go:283](backend/internal/clip/service.go#L283); regression added to [store/disclosure_test.go](backend/internal/clip/store/disclosure_test.go).
- the planned fix was wrong and was narrowed during implementation. Admitting an empty disclosure unconditionally, as the impl notes said, broke `TestPresetDisclosureAndCTARoundTrip`, which deliberately refuses clearing it: on a legacy project that value IS the campaign identity (CDS-5). The guard now admits the empty value only where `old.Composition` is present and not legacy — exactly the case the frontend already exempts — so a legacy project keeps its rule.
- the regression was confirmed to reproduce: it fails against the unpatched guard and passes with it.
- BE verify ran in an isolated worktree at HEAD plus this task's files, because the working tree does not compile while T145 is mid-implementation. gofmt, vet, build and two consecutive full `go test ./...` runs pass.
- out of scope, observed twice under full-suite load and reported in the STATE log: `ClipCorrection.test.tsx > saves exact milliseconds…` fails intermittently at ~8 s while passing 5/5 in isolation, and `store.TestRecoveryRenderRestartSkipsCompletedWork` failed once the same way. Both belong to the assembly work in flight.
