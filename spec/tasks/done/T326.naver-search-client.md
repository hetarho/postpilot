# T326 The 네이버 검색 API blog client and its optional credentials
> st:done@260924 | ssot:QUAL-17 QUAL-18 QUAL-25 QUAL-33 QUAL-34 QUAL-42 ARCH-6 ARCH-21 ARCH-33 ARCH-42 ARCH-24 | base:QUAL@3 ARCH@9 | dep:-

## goal
- A tested `internal/naversearch` wrapper returns plain titles and descriptions for one page of `/v1/search/blog.json`, and boot config carries the two optional Naver keys and an optional refresh-interval override, so a box without keys boots and simply has no batch.

## acceptance
- [v] `naversearch.New(clientID, clientSecret, httpClient).SearchBlog(ctx, query, start)` sends exactly one `GET https://openapi.naver.com/v1/search/blog.json` with `query`, `display=100`, `start` and `sort=sim`, and the headers `X-Naver-Client-Id` and `X-Naver-Client-Secret`.
- [v] A 200 answer returns one `Item{Title, Description}` per element of `items`, in answer order, with every `<b>` and `</b>` removed and HTML entities decoded; an empty `items` array returns an empty slice and no error.
- [v] A non-200 answer returns a `*naversearch.StatusError` carrying the HTTP status and Naver's `errorCode` (empty when the body is not the documented JSON); no returned error string contains the client id or the secret.
- [v] A `start` outside 1…1000 or a blank query is refused before any request is sent.
- [v] Each request is bounded by the wrapper's own timeout even when the caller's context has none, and the caller's cancellation still ends it.
- [v] `config.Load` trims `NAVER_SEARCH_CLIENT_ID` and `NAVER_SEARCH_CLIENT_SECRET`; `NaverSearchEnabled` is true only when both are non-empty; neither or only one set is a legal disabled mode and never a boot error.
- [v] `QUALITY_PHRASE_REFRESH_INTERVAL` unset leaves `QualityPhraseRefreshInterval` zero (the quality context's own default applies, T338); a set value must parse as a positive Go duration, and a malformed, zero or negative value fails `Load` with an error naming the key.
- [v] The three keys are declared in `.env.example`, `.env.production.example` and DEPLOY.md §3; none has a `VITE_` mirror; `docker-compose.yml` and `docker-compose.prod.yml` stay unchanged (both pass `.env` through `env_file`).
- [v] Tests: `backend/internal/naversearch/client_test.go` — `TestSearchBlogRequestContract`, `TestSearchBlogReturnsPlainText`, `TestSearchBlogEmptyItems`, `TestSearchBlogStatusErrors` (401, 429, 500), `TestSearchBlogRefusesAnInvalidRequest`, `TestSearchBlogTimesOut`; `backend/internal/platform/config/config_test.go` — `TestLoadNaverSearchCredentials`, `TestLoadQualityPhraseRefreshInterval`.
- [v] Verify: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test -timeout 30m ./...`

## impl notes
- ARCH-33: re-read the official docs before coding and copy names verbatim — https://developers.naver.com/docs/serviceapi/search/blog/blog.md (request, parameters, item fields, SE01–SE99) and https://developers.naver.com/docs/common/openapiguide/errorcode.md (401/403/429/500 and the error body). Read at task creation (260923): JSON URL `https://openapi.naver.com/v1/search/blog.json`, GET, `query` (UTF-8, required), `display` (default 10, max 100), `start` (default 1, max 1000), `sort` (`sim` default | `date`); `title` and `description` wrap query matches in `<b>`; the error body is `{"errorMessage": "...", "errorCode": "..."}`; 403 means 검색 API is not enabled on the application; the daily limit is 25,000 calls.
- New wrapper context `backend/internal/naversearch` (ARCH-6 wrapper, like `internal/fxrate`); stdlib only (`net/http`, `net/url`, `encoding/json`, `html`, `strings`), so no `go get` and no go.mod change. It imports no other `internal/` package.
- `client.go`: `const baseURL = "https://openapi.naver.com"`, `const blogPath = "/v1/search/blog.json"`, `const pageSize = 100` (QUAL-17's three pages of 100), `const maxStart = 1000`, `const requestTimeout = 10 * time.Second`, `const maxBodyBytes int64 = 1 << 20`, `const maxErrorBodyBytes int64 = 4 << 10`.
- `type Client struct { clientID, clientSecret string; http *http.Client; baseURL string; timeout time.Duration }`; `func New(clientID, clientSecret string, client *http.Client) *Client` — nil client means `http.DefaultClient` (fxrate shape). `baseURL` and `timeout` are unexported fields so the test can point them at httptest and shorten the wait, as `eximbank_test.go` does with `endpoint`.
- `type Item struct { Title, Description string }`; `func (c *Client) SearchBlog(ctx context.Context, query string, start int) ([]Item, error)`. The consumer port and its own item type belong to T338 (`quality.BlogSearch`); cmd/api maps `Item` to it, so this package never imports `quality`.
- Request: `strings.TrimSpace(query) == ""` or `start < 1 || start > maxStart` → a plain error, no request. The query is built with `url.Values{"query", "display"="100", "start", "sort"="sim"}.Encode()`, which sorts keys and encodes a space as `+` (the same form as the docs' Java sample `URLEncoder.encode`). `context.WithTimeout(ctx, c.timeout)` wraps each request.
- The credentials travel only in the two headers, never in the URL, so a transport error (`*url.Error` quotes the URL) cannot leak them.
- 200: decode `struct{ Items []struct{ Title string \`json:"title"\`; Description string \`json:"description"\` } \`json:"items"\` }` through `io.LimitReader(body, maxBodyBytes)`; other members (`lastBuildDate`, `total`, `link`, `bloggername`, `postdate`) are ignored — the corpus is title and description only (QUAL-18).
- Plain text per field: `strings.ReplaceAll` `<b>` and `</b>` to "" FIRST, then `html.UnescapeString`, then `strings.TrimSpace` — in that order an escaped `&lt;b&gt;` in the author's own text survives as a literal `<b>` instead of being stripped.
- Non-200: `type StatusError struct { Status int; Code string }`, `Error()` = `fmt.Sprintf("naver blog search: status %d, errorCode %q", e.Status, e.Code)`. The body is read through `io.LimitReader(body, maxErrorBodyBytes)` and decoded as `{"errorCode"}`; a decode failure leaves `Code` empty. `errorMessage` is not carried.
- No retry, no rate limiting and no logging in the wrapper: the batch (T338) owns scheduling and what a failure means.
- Test `TestSearchBlogRequestContract`: query `패션 미용`, start 101 → method GET, `r.URL.Path == "/v1/search/blog.json"`, `r.URL.RawQuery == "display=100&query=%ED%8C%A8%EC%85%98+%EB%AF%B8%EC%9A%A9&sort=sim&start=101"`, both headers equal the constructor's values; a second case `맛집`, start 1 → `display=100&query=%EB%A7%9B%EC%A7%91&sort=sim&start=1`; also pin `baseURL`'s value.
- Test `TestSearchBlogReturnsPlainText`: `"title":"<b>성수</b> 카페 &quot;추천&quot;"` → `성수 카페 "추천"`; `&amp;`, `&#39;` decode; `&lt;b&gt;` in a description comes back as `<b>`; item order kept.
- Test `TestSearchBlogStatusErrors`: 401 `{"errorMessage":"Authentication failed (인증에 실패하였습니다.)","errorCode":"024"}` (the guide's example), 429 with a JSON code, 500 `{"errorCode":"SE99"}` and a non-JSON 500 body → `errors.As` a `*StatusError` with the right `Status` and `Code`; `strings.Contains(err.Error(), id|secret)` is false for every case.
- Test `TestSearchBlogTimesOut`: the handler blocks until the request context ends; with `client.timeout = 50 * time.Millisecond` and `context.Background()`, the call returns an error well within a second.
- `internal/platform/config/config.go`: `Config` gains `NaverSearchClientID`, `NaverSearchClientSecret string`, `NaverSearchEnabled bool`, `QualityPhraseRefreshInterval time.Duration`, each with a field comment in the file's style. The keys read `strings.TrimSpace(os.Getenv(...))` as `GOOGLE_CLIENT_ID` does, and `NaverSearchEnabled = id != "" && secret != ""`.
- A half-configured pair is disabled, not boot-fatal — deliberately unlike the Google pair — because R24 and QUAL-42 make "no batch" a legal product mode rather than a misconfiguration that could charge or sign in wrongly.
- The interval default is NOT in config: R21 and ARCH-21 make the batch interval default a Go constant in `internal/quality/limits.go` (T338 adds `PhraseRefreshInterval = 24 * time.Hour`), and config may not import quality (`TestConfigImportsNoDomainPackage`). Config therefore parses only an override: a new helper `optionalPositiveDuration(name string) (time.Duration, error)` beside `positiveDuration` returns 0 for an unset or empty value, and otherwise `time.ParseDuration` plus the `must be positive` check with the key in the message.
- Config tests set both keys explicitly with `t.Setenv` in every case (a developer's shell or repo `.env` may carry real ones): neither → disabled; id only and secret only → disabled with no error; `"  id  "`/`"  secret  "` → enabled with trimmed values; whitespace-only counts as unset. Interval: unset → 0; `36h` → 36h; `nonsense`, `0s`, `-1h` → error containing `QUALITY_PHRASE_REFRESH_INTERVAL`.
- `.env.example`, after the billing block: a `# --- 분야 phrase batch (optional; set both or leave both empty) ---` block explaining that the Naver Search API keys are backend-only, never baked into the web bundle, and that without them the batch does not run and every phrase list stays empty; `NAVER_SEARCH_CLIENT_ID=`, `NAVER_SEARCH_CLIENT_SECRET=`, and a commented `# QUALITY_PHRASE_REFRESH_INTERVAL=24h` (commented so the product default stays owned in one place). `.env.production.example`: the same three lines after its billing block.
- DEPLOY.md §3 table, after the `EXIM_API_KEY` row, in the table's Korean: `NAVER_SEARCH_CLIENT_ID` / `NAVER_SEARCH_CLIENT_SECRET` | 스택 `.env` | the operator registers an application at 네이버 개발자센터 with 사용 API 검색 enabled (a 403 means it is not); used only by the daily 분야 phrase batch; either one empty → the batch does not run, every list stays empty, and the API still boots. Then `QUALITY_PHRASE_REFRESH_INTERVAL` | 스택 `.env` (선택) | refresh period per 분야; empty = the product default 24h; a malformed, zero or negative value stops the boot.
- Out of scope: phrase extraction, the refresh pass and its wiring in cmd/api (T338); any search-demand or 검색광고 API (QUAL-34); reading blog.naver.com pages (QUAL-18, QUAL-33); any owner-facing screen naming the keys (QUAL-42).
