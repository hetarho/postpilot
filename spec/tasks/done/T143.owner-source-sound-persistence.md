# T143 Persist owner-controlled source sound atomically

## goal
Persist the default-off per-source original-sound choice and make each semantic change stale only the render while preserving compatible AI work.

## acceptance
- [v] Embedded migration 0052 adds a constrained source-lease original-audio flag, backfills legacy sources from their saved plan and leaves malformed, empty or unmatched plans safely off; migration upgrade, rollback and idempotent-start tests preserve existing project results.
- [v] New source identities default off, while a matching canonical source reselected by fingerprint inherits its resolved prior choice; source list, retained-source and editing projections expose the owner setting without exposing it as a model decision.
- [v] `SetClipSourceOriginalSound` is owner-scoped and atomically validates project, current batch, source id, fingerprint and expected edit-plan revision, returning the updated source batch and project.
- [v] A no-op request is idempotent and changes neither revision nor retention; a real change with a saved plan updates the lease and complete v6 plan snapshot in one transaction, increments `edit_plan_revision` once, preserves `rendered_plan_revision` and renews retention once.
- [v] A pre-plan change accepts expected revision zero; active generation/rerender, stale revision or fingerprint, foreign ownership, replacement batch, finalization, deletion and revoked source access are refused through the existing typed boundaries.
- [v] Changing source sound leaves analysis, template composition, observed evidence and candidate assembly intact; quote and plan-recovery identity exclude this owner setting, and the next continuation is render-only with the latest setting frozen into its job payload.
- [v] Per-cut volume never grants source-audio permission: it remains an independent gain applied only after an enabled source, and changing either value cannot silently change the other.
- [v] Migration, source store/service, correction transaction, recovery/quote and Connect RPC tests cover default off, v0 nil-volume on, mixed legacy cuts, canonical reselection, races, retry idempotence, stale-result projection and zero provider calls.
- [v] Run the applicable ARCH-25 through ARCH-29 checks, including deterministic protobuf and SQL generation and generated-file snapshot protection for the dirty workspace.

## impl notes
- Add `backend/internal/platform/db/migrations/0052_clip_source_audio.sql` with `retain_original_audio INTEGER NOT NULL DEFAULT 0 CHECK(retain_original_audio IN (0,1))`; use SQLite JSON extraction only for valid recognized v0-v5 envelopes and never rewrite stored plan JSON in the migration.
- Backfill v0 from `Cuts` with `COALESCE(Volume,1) != 0`, and v1-v5 from `Plan.Cuts` with `VolumePermille != 0`, grouped by canonical source/fingerprint. The T142 decoder remains the compatibility authority when a row cannot be safely matched.
- Define `SetClipSourceOriginalSoundRequest { project_id, batch_id, source_id, expected_fingerprint, retain_original_audio, expected_revision }` and return both `ClipSourceBatch` and `ClipProject`; authentication comes only from request context.
- Perform the lease write, semantic v6 plan rewrite, optimistic project revision update and retention renewal on the serialized writer transaction. Do not hold a transaction across media or provider work.
- Exclude audio settings from observation and writer inputs and from the planning recovery digest. Freeze them only when constructing the validated assembly/render payload, so an owner toggle never spends credits or invalidates completed model output.

## result
Files: `proto/postpilot/v1/clip.proto` · `backend/internal/platform/db/migrations/0052_clip_source_audio.sql` (new) and `migration_0052_test.go` (new) · `backend/internal/clip/source_audio.go` (new) `sources.go` `rate.go` `portable_plan.go` `generation.go` `rerender.go` `source_manifest.go` `rate_test.go` `correction_test.go` · `clip/store/source_audio.go` (new) `source_audio_test.go` (new) `sources.go` `store.go` `queries/sources.sql` and generated sqlc · `clip/rpc/sources.go` `source_audio_test.go` (new) · `frontend/src/entities/clip-project/{model/types.ts,api/clip-project.ts,api/sources.ts,api/source-audio.test.ts}` and the affected fixtures.

- The LEASE is the owner-facing authority and the plan carries a snapshot of it. `SetSourceOriginalAudio` performs the lease write, the v6 plan rewrite, the single revision bump and the retention renewal on one writer transaction, with no media or provider work inside it.
- Migration 0052 backfills from each recognized envelope: version 0 by `COALESCE(Volume,1) != 0`, versions 1-5 by `VolumePermille != 0` grouped by canonical source and fingerprint, and — beyond the task's note — version 6 from its explicit `SourceAudio`, since T142 can reach production first. Malformed, absent, unmatched and fingerprint-changed rows stay off, and no stored plan JSON is rewritten.
- A correction was needed in T142's encoder: it read an absent snapshot as the legacy per-cut-volume meaning, which made a plan built TODAY audible by default. That reading now belongs to `upgradeLegacyAssembly` on decode alone; `EncodeEditPlan` writes off, and generation freezes the snapshot from the live leases so a reselected source inherits its resolved choice. The two tests that relied on the old behaviour now build a genuine version-4 row instead.
- Exclusion is structural rather than asserted: the setting sits on `SourceLease` outside `SourceMetadata`, so `SourceManifest`, `QuoteInputDigest` and `planRecoveryDigest` cannot see it; a test pins all three. `StartRender` re-freezes from the leases, so the next continuation is render-only with the current setting in its payload.
- `matchOwnerAudio` refuses a plan save that contradicts a saved per-source choice but tolerates a stale projection after a delete or undo, because the snapshot follows the cut set and the server rebuilds it.
- ARCH-25 through ARCH-29 pass. `pnpm gen:proto` and `pnpm gen:sql` were run through locally installed `buf` and `sqlc` because Docker is unavailable here; both reproduced byte-identical output on a before/after snapshot, and `sqlc` regenerated the whole committed tree unchanged before the new query was added.
