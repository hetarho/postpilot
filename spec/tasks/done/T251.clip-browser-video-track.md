# T251 the browser composites and encodes the video track
> st:done@260918 | ssot:CLIP-159 CLIP-157 CLIP-153 CLIP-155 CLIP-23 CLIP-12 CLIP-13 CLIP-98 CLIP-125 | base:CLIP@38 | dep:T250

## goal
The browser draws the plan's cuts, transforms and typeset text onto the output canvas and encodes them as an H.264 video track meeting CDS-52's V12.

## acceptance
- [v] every cut is drawn over its source range at its fixed rate, with its crop, at the ratio's canvas size and 30 fps, in plan order
- [v] a fade transition renders as a fade and a hard cut as none, matching what the plan declares
- [v] every caption, intro line, outro line and disclosure badge is drawn from the server-typeset PNG at the position and interval its manifest states, never redrawn as browser text
- [v] a sequence-rendered caption style is drawn every output frame of its interval with the motion its style declares, applied by the browser to the server's one representative raster; a static style is the same raster held for its whole interval
- [v] every original the plan cites is available to the draw, an unheld one fetched under CLIP-23 before the frames it supplies rather than refusing the render
- [v] the encoded track is H.264 High at the ratio's resolution and 30 fps, and its frame count matches the edited output timeline within one frame
- [v] vitest: a two-cut plan with a rate change, a fade and a caption produces the expected frame count, the caption is drawn only inside its interval, a sequence-rendered style draws a frame per output frame while a static one reuses its raster, an unheld original is fetched once before its cut, and the encoder is configured from the ratio and CDS-52's V12
- [v] verify: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- the typeset text is ALREADY server-rendered: `entities/clip-project/model/preview-assets.ts` caches the PNGs the draft preview draws, with their placement manifest. The browser render reuses exactly those, so CLIP-12's "exact typeset text through approved templates" and CLIP-13's bundled fonts hold with no browser typesetting at all
- source frames: an `HTMLVideoElement` seeked per output frame and drawn with `drawImage` onto an `OffscreenCanvas`, rather than a raw `VideoDecoder` — the originals are ordinary MP4 files the element already decodes, and the element handles container parsing the decoder would need a demuxer for
- encode with `VideoEncoder` fed `VideoFrame`s built from the canvas, `avc` `High`, the ratio's canvas, 30 fps; the config comes from `CLIP_DESIGN.ratios` and CDS-52's V12, never a literal
- the work runs in a Worker so the page stays interactive; T254 owns its progress and cancellation, so expose the render as an async iterator of completed frames rather than wiring UI here
- CLIP-159 (r37) fixes what the browser owns: the words, the face, the size and the position are the server's raster, and only the motion is the browser's. `ClipCaptionFragment.representativeFrame` already marks a sequence-rendered style's raster as one frame OF the motion rather than the motion — that flag is the switch between holding the raster and animating it
- the motion table is the one the draft preview already animates from (CDS-83 makes the preview state the motion the render produces), so this task reads that table rather than writing a second one; CLIP-157 (r37) settles that a per-frame appearance differing from the server's is not a defect, so no test compares the two kinds' frames
- fetching an unheld original is the authorized playback access CLIP-34 already grants over unexpired retained originals — the same URL the source strip plays — fetched once per source into the element that supplies its cuts, never persisted in browser storage
- CLIP-125 binds this: a browser render that moved a frame or a millisecond against the same plan would be a product change, so the timeline arithmetic is the plan's own resolved output intervals, not a re-derivation

## result
- `entities/clip-project/model/composite-video.ts` reads the existing resolved cut intervals, source-time conversion, crop and fade calculations. The worker encodes ratio-sized H.264 High frames at 30 fps with bounded encoder input; its public handle reports completed frames and closes source decoders, bitmaps and the worker on completion, failure or cancellation. DOM video handles MP4 parsing and supplies transferable snapshots; no container demuxer or browser text rasterizer was added.
- `features/render-clip-browser` loads the same paged, hash-checked PNG manifests as draft preview, resolves a retained original only when first needed, and reuses that decoded source across its cuts. Static caption rasters remain cached throughout their interval; representative sequence rasters use the existing manifest motion each frame. Text, raster placement and half-open visibility intervals remain server-owned.
- `ClipPreviewAsset.representative_frame` now carries the sequence/static distinction through both edge mappers and generated clients. Media preview uses the existing caption representative-frame renderer for sequence styles, with a real-font PNG smoke proving the raster is visible. No SSOT decision changed; r38's per-caption selection is already resolved into these assets.
- Real Chromium encoded and decoded a two-cut rate/fade fixture on all three canvases: 84 frames each, H.264 High, 30 fps, 2.8 seconds, one retained-source access, caption pixels present at 1 second and absent at 2 seconds. Cancellation rejects with AbortError. Unit tests cover rate, crop, fade/hard cut, frame timestamps, static reuse, sequence motion, source reuse and failure/cancellation cleanup.
- Official references consulted: [WebCodecs](https://www.w3.org/TR/webcodecs/), [HTML media seeking](https://html.spec.whatwg.org/multipage/media.html#dom-media-seeking), [OffscreenCanvas](https://html.spec.whatwg.org/multipage/canvas.html#the-offscreencanvas-interface).
- Verification passed: frontend 260 files / 2,121 tests plus focused 8 renderer cases, lint, FSD, style probe/style, formatter, production build; backend and agent format/vet/build/test plus agent shell syntax; 8 deploy tests; skill sync; real Docker `media-smoke` including the new representative PNG case. Existing DraftEditor dependency and bundle-size warnings remain.
