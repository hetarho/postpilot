# T561 Take job-kind lists out of generation_jobs' CHECKs and the dispatcher SQL
> st:done@261004 | ssot:ARCH-10 ARCH-43 ARCH-24 | base:ARCH@15 | dep:T551 | touches:backend/internal/platform/db/migrations/ backend/internal/job/ backend/cmd/api/job_subjects.go

## goal
Adding a cancellable or staged job kind becomes a Go change only: generation_jobs is rebuilt one last time without kind-naming CHECKs, and the dispatcher's first stage per kind comes from Go like the queue's other kind lists.

## acceptance
- [v] migration `0129_job_kind_checks_out_of_schema.sql` rebuilds `generation_jobs` following 0126's pattern (NO TRANSACTION, `foreign_keys=OFF`, explicit transaction, every trigger and index written back — including T551's `generation_jobs_project_latest_idx` and `generation_jobs_post_idx`), replacing the two cancellation CHECKs with kind-free ones: `CHECK (status!='cancelled' OR cancel_requested_at IS NOT NULL)`; the FK guard checks only the rebuilt table and its children (`pragma_foreign_key_check('generation_jobs')` plus the tables that reference it) and aborts on any row
- [v] `PickNextQueued` reads each kind's first stage from a JSON object argument (`jobstore.Kinds.FirstStages`, wired in `cmd/api/job_subjects.go` from the owning contexts' constants) with `'observe'` as the default, and names no kind
- [v] which kinds may be cancelled stays Go's `Kinds.Cancellable` / `jobCancellation`, now the only place it lives; a job test cancels each cancellable kind through the store against a migrated DB (this is what caught nothing before: `clip/store/subjects_helper_test.go` lacked `template_request`)
- [v] tests: migrated schema has no `kind IN (` inside generation_jobs' CREATE statement; index and trigger sets of generation_jobs equal the set before the migration (diff `sqlite_master`); dispatch picks the right first stage for every kind in `FirstStages` and `observe` for others
- [v] behaviour unchanged otherwise: ARCH-26 green; `pnpm gen:sql` leaves no diff (ARCH-28)

## impl notes
- from review/perf-cost-261004 F13
- one more rebuild is the price of never needing another for a kind; the boot cost is one table copy (measured 0.29 s at 30k jobs)
- `cancellation_policy_version IN (0,1)` and the status/value CHECKs stay — they name no product
- the `clip_quote_job_owner` trigger keeps its clip kinds: it guards clip quotes, a clip-owned rule
- the tier enum CHECK repeated in seven tables is out of scope (no tier is being added)
- write the migration's Down as 0126 does (rebuild back with the old CHECKs)
