## goal
Mint a clip project from the title, template and ratio alone, and move the answers, the instruction and the target duration into ① beside the sources they describe.

## acceptance
- [v] `/clips/new` shows the title, the video template and the ratio and nothing else, keeping its single 클립 만들기 dock action
- [v] ① shows the full settings form — answers, instruction, target duration, disclosure, CTA — above the source picker it already carries

- [v] generation admission refuses a project whose target duration is unset, with the same owner-facing shape the missing-disclosure refusal already has, and never starts preparation or a paid call
- [v] an existing project keeps its stored target duration and opens ① with it filled
- [v] tests: BE — creation without a duration succeeds and generation admission refuses it; FE — `/clips/new` renders only the three fields and ① renders the rest
- [v] verify FE (ARCH-25) and BE (ARCH-26) pass

## impl notes
- r31 adds the caption pace and the accent to ①'s settings (CLIP-130✎); T209 builds those two controls, so this task moves only the fields that exist today and leaves room for them in the form
- unset duration follows the disclosure precedent already in `CreateProject` (clip/service.go): "Empty disclosure is allowed at creation — the owner chooses it before starting, and the generation gate is what refuses a clip without one". Store 0 as unset; `target_duration_ms` is NOT NULL, so no migration is needed
- drop `!s.duration(input.TargetDurationMS)` from `CreateProject`'s creation check and keep `s.duration` enforcement in `UpdateProject` (a written value must still be 15–90 s) and in the generation gate. CLIP-7 asks for the choice before generation, not before the project exists
- the refusal belongs with the CLIP-102 admission refusals so it names the field the way a group or answer refusal does; find the existing missing-disclosure refusal and place it beside that one
- FE: `ClipProjectForm` (features/edit-clip-project) is mounted twice — by `NewClip` and by `ExistingClip`'s `generatePanel` in pages/clip/ui/ClipPage.tsx. Give it a mode that renders the creation subset, rather than building a second form: one form keeps the autosave, the draft shape and the validation in one place
- `CLIP_PROJECT_LIMITS` and `validClipProject` (entities/clip-project) currently require a valid duration on the draft; the creation draft must pass without one while ①'s draft still validates it
- the step bar is unchanged: CLIP-36 keeps `/clips/new` without one, and this task moves fields between two existing surfaces rather than adding a step
- unchanged: the ratio stays creation-only and immutable (CLIP-8, CLIP-9), and 클립 만들기 stays the single committing action CLIP-39 requires
