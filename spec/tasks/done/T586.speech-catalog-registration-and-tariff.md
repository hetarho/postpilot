## goal
Register supported speech combinations with server-owned defaults and immutable shared account pricing snapshots.

## acceptance
- [v] Master-only catalog registration accepts an explicit supported pair, offered state, optional grade and three optional synthesis values; all other binding and pricing fields are server-resolved.
- [v] Registration without classification, prices or qualification remains possible and unavailable for ordinary paid work; existing account voices, revisions and audio remain intact.
- [v] One registration owns each pair; concurrent or stale writes cannot create duplicates or overwrite current revisions, and saved registrations remain manageable during supplier outages.
- [v] One versioned account tariff accepts only monetary terms and their complete account evidence, resolves documented provider billing rules and finite input bounds, and refuses unknown factors/units rather than inferring free costs.
- [v] Updating the common tariff refreshes registered price snapshots atomically, preserves prior revisions, clears affected readiness and prevents stale quotes from admitting new work.
- [v] Domain, SQLite migration/store and RPC tests cover registration, defaults, unknown pricing, classification, duplicate/stale writes, tariff/account drift and master-only access; required local CI checks pass.

## impl notes
- Extend SpeechProfileService additively with lean registration and common-tariff mutations; retain existing wire fields/history without accepting manual binding/pricing through the new path.
- Derive compatible pairs from catalog design and Korean reusable synthesis capabilities. Keep explicit refs in every profile and approved request.
- Add catalog metadata alongside existing profile revisions instead of rebuilding tables referenced by owned voices. Preserve original level for legacy revisions and represent unclassified catalog registrations explicitly.
- Persist a singleton current account tariff and its revisions in modelcatalog-owned tables. Store pair uniqueness in a separate catalog registration key; claim new pairs transactionally.
- Resolve billing-unit bounds behind the llm provider boundary, from documented Voice Design preview-character rules and unambiguous model rate metadata. Ambiguous or missing billing evidence leaves operation prices unavailable. Never multiply already reported charged quantities a second time or guess a confirmation fee.
- Common terms are design/speech USD per reported supplier billing unit, confirmation USD per request and complete account evidence; decimal strings and explicit zero remain authoritative. The server records verification time after explicit evidence acknowledgement.
- A common tariff write advances affected current profile price snapshots in one writer transaction with optimistic revision checks; provider metadata reads happen before the transaction. Immutable confirmed voice bindings remain unchanged.
