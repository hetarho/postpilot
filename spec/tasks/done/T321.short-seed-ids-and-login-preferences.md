## goal
Make local accounts quick to enter and offer independent automatic login and saved login ids.

## acceptance
- [v] Seed creates free/base/pro/max/master without email, retaining plans, seed-only password, credits and post spread; real temporary-database login and fixture tests pass.
- [v] Password and Google login default to session cookies; explicit remember_me issues a fixed 30-day persistent cookie with unchanged security attributes and revocation; HTTP tests cover both modes and configured TTL.
- [v] Accessible localized login checkboxes default off; successful password login optionally saves only the id, reload prefills it, unchecking removes it immediately, failures do not overwrite it and blocked storage cannot break login; frontend tests cover these cases.
- [v] Google authorization carries the automatic-login choice to its exchange, absent choice defaults false, and safe redirects/session cache/logout behavior still pass regression tests.
- [v] ARCH frontend/backend gates, generated output reproducibility, CI support checks and spec lint pass.

## impl notes
- Add bool remember_me=3 to LoginRequest and bool remember_me=4 to SignInWithGoogleRequest; omitted fields mean false, and regenerate Go/TS with the existing Docker generator.
- Keep database session expiry at SessionTTL; cookie MaxAge is zero (omit persistence attributes) unless remember_me, and logout continues using negative MaxAge to emit deletion; no migration or dependency is needed.
- Use localStorage only for postpilot.saved-login-id; read/write/remove inside try/catch, save only in password-login success, leave automatic login as per-visit state and preserve saved id on logout.
- Extract the password form into features/log-in with slice-owned translations/storage logic; LoginPage composes it with the Google button and shares the automatic-login checkbox state; carry the boolean inside the existing sessionStorage PKCE attempt and read absent/invalid values as false.
- Remove devseed email data/port/adapter, shorten fixture ids, update README and prove the real seed on a temporary SQLite database without resetting the working installation.
- Run Node 24.18.0 for frontend verification; regenerate twice and compare file hashes because intended uncommitted generated changes prevent a clean git diff gate.
