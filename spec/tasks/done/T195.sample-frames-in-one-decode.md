# T195 A plate's sample frames come from one decode
> st:done@260916 | ssot:CLIP-124 CLIP-125 | base:CLIP@30 ARCH@2 | dep:T191

## goal
Extract the frames the contrast sampler needs in one read of the composed footage instead of one seek and decode per frame.

## acceptance
- [v] the frames CDS-44 names are extracted for every element in one pass over the composed footage, and each element is measured on exactly the frames it is measured on today (→CDS-44)
- [v] the measured luminance, the scrim decision, the accent decision and any recorded contrast notice are unchanged for a plan whose ground is near the thresholds
- [v] the delivered clip is unchanged (→T191)
- [v] tests: a fixture asserting the same sampled values before and after for a bright, a dark and a high-variance ground, plus the identity regression from T191
- [v] verify BE (ARCH-26) passes

## impl notes
- `sample` (`media/luminance.go:182`) runs one ffmpeg per frame and each one seeks into the lossless intermediate; on prod a single seek-and-extract measured 3.8 s against real footage, so six elements cost about 68 s while one sequential decode of a 30-second lossless clip measured 45 s
- the PNG frames are decoded in Go already, so batching changes only how many invocations produce them; keep the decode-and-measure code as the one place the luminance formula lives
- shortening the intermediate's GOP was considered and rejected: it would make each seek cheap but multiplies the intermediate's size, and a 90-second clip already reaches about 4.2 GB against the 8 GiB workspace bound
- `declaredPlate` (`media/composition_plates.go:24`) calls the sampler per element while building each plate, so the batch has to be collected before the plate loop rather than inside it

## result
- `media/luminance.go`: `sample` split into `sampleOffsets` (the three timestamps, unchanged), `sampleFrames` (one read of the footage producing every requested frame) and `measureFrames` (CDS-44's measurement over frames already in memory, one region per frame). The luminance formula still lives in `regionLuminance`/`summarize` only
- one read instead of one per frame: the command opens the footage once and gives each frame its own OUTPUT-side `-ss` with the same cover chain. Verified against the real binaries that an output seek selects the very same frame an input seek does — the extracted PNGs are byte-identical — which is what lets the batch keep CDS-44's frames exactly
- `media/composition_plates.go`: new `sampleDeclaredGrounds` collects every element's window and region BEFORE any plate is built and measures them from that one read; `declaredPlate` now only draws. `composition_render.go` calls it before the plate loop, so `recordContrastNotices` still reads the same grounds
- `clip.RenderConfig.SampleBatch` (new, default 24, bounded 3..48 by `NewRenderer`): each output carries its own scale/crop chain, so the frames are taken in as few reads as that allows rather than one read per frame. Six elements (18 frames) are one read, where prod measured 3.8 s per seek-and-extract against 45 s for a sequential decode
- tests: `TestSampledGroundsSurviveTheBatchedRead` (real binaries) measures a bright, a dark and a high-variance ground both ways — a seek and decode per frame, as before this task, and the batched read — and requires the mean, σ, colour, per-frame values, scrim decision and accent decision to match; `TestSamplerTakesThreeFramesThroughTheRenderChain` now also asserts the three frames come from ONE read
- identity held: `TestDeliveredClipIdentity` passes against T191's baseline (96.6 s)
- no SSOT difference; verify BE (ARCH-26) passes (`go test ./...` with `-p 2`: the full-parallel run is OOM-killed on this box)
