# T059 The template's data fields in ①, under the memo
> st:done@260909 | ssot:POST-62 POST-54 TEMPLATE-43 | base:POST@3 TEMPLATE@4 THEME@6 ARCH@2 | dep:T055 T056

## goal
Render the selected template's data fields under ①'s memo as titled textareas with their own switches, autosaved through the same draft queue as the memo.

## acceptance
- [v] `features/fill-template-answers`: one field per `askFields(body)` entry, in body order, under the memo — the title as the textarea's visible `<label>`, an `autoGrow` `Textarea` in the memo's `well` appearance, a `Switch` on the row, and a live counter against `TEMPLATE_ASK_VALUE_MAX_CHARS`
- [v] the switch off leaves the field visible, greyed and its text kept and readable; the textarea is disabled and the section says in one line what an off field means for the post
- [v] no template selected, a template with no data fields, or a body that does not parse renders nothing at all — no empty section, no error
- [v] the answers ride the existing draft queue: `Draft` gains them, dirty comparison is per label over both text and switch, one debounce covers a memo and an answer edited together, and `flush()` awaits them before 생성 · A/B 비교 · 확정
- [v] a reload seeds the fields from `Post.template_answers`; switching the template re-renders the field list while the stored answers of the other template stay untouched and reappear on a swap back
- [v] typing an answer on `/posts/new` before the post exists is local until the first save mints the slug, exactly as the title and memo are
- [v] an answer save never changes the step, the revision or the finalize state, and a failed save shows the same status as any other draft save with the typed text intact
- [v] tests: fields render in body order for the selected template · off greys and disables while keeping the text · nothing renders for 없음 / no fields / unparsable body · a queued answer + memo land in one save with per-label presence · `flush()` waits for a pending answer before 생성 · seeding from the server value · a template swap keeps both sets · the counter bound
- [v] verify: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- a `features/` slice, mirroring `features/select-post-template`: the panel is a user action over the post that commits through the draft queue rather than a mutation of its own, and `pages/editor` composes it into ① next to the memo (→POST-54)
- the labels come from the template DIRECTORY query the editor already holds — it returns `body` — so no new RPC and no second fetch; `askFields` (T055) is the only parse and it never throws
- the queue keeps answers as a map keyed by label with the same dirty/waiter shape `voiceId` and `templateId` use, and sends the full current answer set whenever it is dirty. Every entry is an upsert, so sending all of them cannot disturb another template's stored answers and one in-flight save can never revert a newer keystroke
- an answer with no stored row renders switched ON with empty text (matching T056's default): the field exists because the template requires that data, and a blank one is dropped at the freeze anyway
- do NOT gate 생성 on a blank field (TEMPLATE-34): the switch and the blank field mean the same thing to the freeze, and blocking the run was explicitly rejected
- ② and ③ render none of this — the answers are ①'s input and the frozen brief is what ② is looking at

## result
- files: new `features/fill-template-answers` (`model/answers.ts`, `ui/TemplateAnswerFields.tsx`, both tested) · `features/save-draft/model/{draft-queue,useAutosave}.ts` + new `answers-queue.test.ts` · `entities/post/{model/types,api/post-queries,api/useSavePostDraft,index}` · `pages/editor/ui/DraftEditor.tsx` · `shared/api/index.ts` · `test/posts.ts` (the fake now upserts answers per label like the server) · i18n ko/en `posts.ts` · assertion updates in `useAutosave.test.tsx` and `EditorPage.test.tsx` where `FakeDraftSave`'s shape grew
- the answers live in `Draft`, so the whole existing debounce·retry·waiter machinery carries them with no second pipeline: the memo and an answer edited together are ONE save, and `flush()` already waits for them
- `sameDraft` is now DIRECTIONAL, which a bug forced: the patch is upsert-only, so a draft carries only the fields on screen. Comparing whole sets made every post that held answers under another template — or under none, with the picker on 없음 — read as dirty and fire a save on mount. A field with no saved row is settled while it holds the default the screen renders (empty, switched on), which is what keeps a mount from being an edit
- the saved baseline MERGES what a save carried instead of replacing it: replacing dropped the labels a save did not carry, and the editor then re-sent them the next time its template made them visible. Pinned by a test that switches templates and comes back
- `answerFields` presents an unanswered field switched ON: the field exists because the template requires that data, and a blank one is dropped at the freeze anyway, so off-by-default would silently mean "never ask"
- `toPostDraft` does NOT filter the answers against the current template: which labels are shown is the write screen's business, and dropping the rest would lose an answer typed under a template the post is about to be assigned again
