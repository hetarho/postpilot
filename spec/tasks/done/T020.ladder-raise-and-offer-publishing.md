## impl notes
- the reference constants live in `plan.go` beside the ladder as unexported constants with the derivation in a comment, and they are deliberately NOT read from `internal/platform/config` ← `OBSERVE_BATCH_SIZE` and `LLM_MAX_TOKENS_DEFAULT` are per-installation env values and a comparison figure that moved with an operator's environment would make two deploys quote different post counts (QUOTA-8, QUOTA-36); the comment records that they mirror the shipped defaults (batch 4, `observeBudgetPerPhoto` 512, fallback 8 192) and must be revisited when those defaults move
- pricing is worst-case on purpose: 30 000 input tokens is `holdInputTokens`, the same assumption the admission gate holds against, so the estimate can never promise a post the gate would then refuse ← an over-promise on a comparison screen is a claim violation, an under-promise is only conservative
- arithmetic to reproduce: observe call = 30 000/1e6 × 300 000 + 2 048/1e6 × 2 500 000 = 9 000 + 5 120 = 14 120 µ$ → `Charge` = 2 + ceil(42 360/10 000) = 7; write call = 9 000 + 20 480 = 29 480 µ$ → 2 + ceil(88 440/10 000) = 11; total 3×7 + 11 = 32
- `Recommended` is a function over the ladder rather than a field on a rung so `Offers()` stays the only assembler; the rung it names is a product decision (QUOTA-28) and belongs beside the grants it compares
- proto field numbers 4 and 5 are new and additive, so an older client reading the response is unaffected; `estimated_posts` is `int32` like every other count in the file
- the existing `plan.SignupBonusCredits` and the provisioning bonus are untouched — BILL-10 replaces them, and that needs update-ssot QUOTA first
- grep for the old grant figures before finishing: `backend/internal/usage/service_test.go` and `backend/internal/plan/plan_test.go` assert against 200 / 500 / 1000 and must move with the ladder
