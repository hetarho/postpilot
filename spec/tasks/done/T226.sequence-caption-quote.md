# T226 The approval surface quotes sequence-rendered captions separately
> st:done@260917 | ssot:CDS-81 CLIP-19 | base:CDS@21 CLIP@32 | dep:T220

## goal
Count and show the sequence-rendered captions and their added render time before the owner approves a generation or a rerender.

## acceptance
- [v] the quote carries the number of sequence-rendered captions the current plan or selection implies and the render time they add, measured from the style registry rather than guessed
- [v] ① and ② show both numbers on the approval surface beside the existing credit ceiling
- [v] no ceiling is enforced and nothing is refused for the count alone (→CLIP-145)
- [v] a project using only static styles shows the count as zero and the added time as none
- [v] backend tests pin the count for a mixed plan and the frontend renders both numbers
- [v] ARCH-25 and ARCH-26 pass

## impl notes
- the added time is stated as a measured per-frame cost from the style registry times the frames each caption covers ← CLIP-145 is open precisely because a ceiling needs real numbers first, and this surface is where they accumulate
- the count is not a credit line: sequence rendering consumes no AI call and CLIP-20 keeps rendering credit-free

## result
- `backend/internal/clip/sequence_cost.go` — `SequenceCostOf` counts the plan's captions whose style is sequence-rendered (the owner's style where they chose one, the project's first allowed style otherwise — the layout's own resolution), their output frames (rapid phrases counted one by one) and what those frames add; before a plan exists it counts the sequence styles the SELECTION allows and says so with `FromPlan`
- `ClipSequenceCaptionCost` rides both approval quotes (proto + `clip/rpc/quotes.go`); nothing reads it to refuse anything — a project whose numbers cannot be read is quoted without them
- `ClipSequenceFrameCostMS = 30` is measured, not assumed: the bundled resvg over the real frames five sequence styles produce, 6 ms (word-pop) to 37 ms (neon) per frame on this Mac, the spread coming from the painted crop. The render box is slower, so the number a CEILING would need is still prod's — CLIP-145 stays open and this surface is where its numbers accumulate
- `frontend/src/entities/clip-project` — the quote carries the line and `ClipQuoteApproval`, the ONE approval surface ① and ② share, states it above the cancellation rule: the captions and the seconds with a plan, the selected styles without one, and plainly none where every style is static
- tests: `clip/sequence_cost_test.go` (mixed plan, rapid phrases, static-only, no plan, empty selection), `ClipQuoteApproval.test.tsx` (all three readings, approval still enabled) and one page-level assertion that the server's numbers reach ①
- no SSOT divergence
