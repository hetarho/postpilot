# T307 a browser render applies every caption's declared motion
> st:done@260922 | ssot:CDS-4 CDS-85 CLIP-157 CLIP-159 | base:CDS@25 CLIP@43 | dep:-

## goal
A browser render moves every caption the way its style declares, so a static style fades in, settles and fades out in the file the browser produces exactly as it does in the server's.

## acceptance
- [v] in a browser render a static-style caption fades in over its declared in-ms, settles its declared upward offset and fades out over its declared out-ms
- [v] a rapid phrase appears and disappears with no fade and no movement
- [v] the browser render and the draft preview read the same motion from the same manifest fields, with no second motion table
- [v] a caption is drawn only inside its half-open interval, unchanged
- [v] vitest: a static raster and a sequence raster both animate from the manifest's in/out/dy; a rapid asset holds still; the existing case that asserted a held static raster is rewritten rather than deleted
- [v] verify: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- the defect: `entities/clip-preview/model/composite-video.ts` applies `previewMotion` only when `asset.representativeFrame`, and draws every other asset at `{opacity: 1, dy: 0}`. `representativeFrame` marks a SEQUENCE style (`media/preview.go`: `m.Role == "caption" && !Static()`), so the styles that do declare a fade-and-settle — every static one, the default 크게 강조 among them — are the ones held still
- the server does apply it: `media/composition_batches.go` loops the static plate and adds `fade=t=in`, `fade=t=out` and the cubic dy expression from the same manifest in/out/dy. The draft preview applies `previewMotion` to every asset (`ui/ClipDraftPreview.tsx`). The browser render is the only surface that does not
- fix: call `previewMotion(asset, timeMs)` for every asset. Nothing special-cases rapid — `design.CaptionMotion` returns zero tokens at rapid pace, so in/out/dy arrive as 0 and `previewMotion` holds the phrase steady and opaque
- `representativeFrame` keeps its meaning and its one remaining use: it says this raster is one frame OF a motion rather than the whole of it, which T309 reads
- `composite-video.test.ts` case "holds a static raster and animates the representative raster" asserts today's behaviour; it becomes both rasters animating, plus a rapid-motion case
- every generated caption is `bold` today (`clip/compose.go` hardcodes the style), so this single change is what the owner sees in a browser-rendered file

## result
- `entities/clip-preview/model/composite-video.ts`: the compositor applied `previewMotion` only to a `representativeFrame` asset and drew every other one at opacity 1 with dy 0. That flag marks a SEQUENCE style, so the styles that actually declare a fade-and-settle — every static one, 크게 강조 among them — were the ones held still, while the server chain faded, settled and faded them out from the same manifest numbers. One call now covers every asset; a rapid phrase carries 0/0/0 and the same call holds it steady, so nothing special-cases the pace.
- the draft preview already animated from `previewMotion`, so preview, browser render and server render now read one motion table (CDS-83).
- `composite-video.test.ts` asserted the old rule by name ("holds a static raster"). It now runs three rasters — static, sequence and rapid — and pins the fade-in, the 20 px settle and the rapid phrase's stillness. Reverting the one line fails exactly that case and nothing else.
- verification: frontend 290 files / 2,295 tests, lint, format:check, FSD, style probe + style, production build. No backend, proto or generated file changed.
