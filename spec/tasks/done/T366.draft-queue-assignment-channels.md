# T366 The draft queue's assignments are one record per channel
> st:done@260925 | ssot:- | base:ARCH@11 | dep:T355

## goal
`draft-queue.ts` keeps its three assignments — the voice, the 템플릿 and the target language, which T355 leaves once it has removed the 분야 channel — as one typed `Assignment<T>` record per channel, walked by a single channel list. A new channel is then one table row rather than about 12 hand-kept sites. `SendDraft` takes one named request.

## acceptance
- [v] `features/save-draft/model/draft-queue.ts` holds every assignment in `Queue.assignments: AssignmentRecords`. The channels are the voice, the 템플릿 and the target language.
  - One `CHANNELS` list drives `run`, the handle's `queue`, the settles, the take-backs, the locked-refusal path, `attachDraftQueue`'s init and `discardQueue`. None of them names a channel.
  - This `grep` over `frontend/src` returns nothing: `grep -rnE "savedVoiceId|savedTemplateId|savedTargetLanguage|voiceWaiters|templateWaiters|targetLanguageWaiters|voiceDirty|templateDirty|targetLanguageDirty|ToSend\(|settle(Voice|Template|TargetLanguage)Waiters|reject(Voice|Template|TargetLanguage)Waiters"`.
- [v] `SendDraft` is `(request: DraftRequest) => Promise<string>`, with `DraftRequest = { slug: string; draft: Draft } & Partial<Assignments>`. No positional assignment argument is left.
- [v] The handle has one `assign(channel, value)` in place of `assignVoice` / `assignTemplate` / `assignTargetLanguage`. `useAutosave`'s returned API keeps the same signatures: `reassign`, `assignTemplate` and `assignTargetLanguage`.
- [v] Every channel's baseline is required by construction: `attachDraftQueue` takes `DraftQueueOptions extends Assignments`. `expectTypeOf` cases in the new suite pin this (impl notes). They fail `pnpm build:web` (`tsc -b`) if a member is made optional.
- [v] `describe('the post template')` in `draft-queue.test.ts` (six cases) is replaced by `features/save-draft/model/assignment-queue.test.ts`.
  - The new suite runs, for the 템플릿 channel, the 16 generic cases that `field-queue.test.ts` held at 4ea56946. T355 deleted that file together with the 분야 channel. The titles are listed in impl notes.
  - Each of the six template cases is one of these, so nothing is lost. "treats 없음 on a post that holds one as a clear" is among them.
- [v] Behavior unchanged. The existing tests still pass, with no expectation changed. They are rewritten only for the `DraftRequest` object and `assign(channel, …)`: `draft-queue.test.ts`, `draft-queue.mint.test.ts`, `answers-queue.test.ts`, `useAutosave.test.tsx`, `useSaveStatus.test.tsx` and `pages/editor/ui/EditorPage.test.tsx`.

- **Which channels share the shape: all three.** The voice, the 템플릿 and the target language each have the same five parts:
  - a wanted value and a server-held baseline;
  - dirty = `slug && wanted !== saved`;
  - toSend: dirty-only on an existing post, a create-time rule otherwise;
  - waiters settled by "landed / superseded / still waiting";
  - a take-back on refusal.

  Only three things differ. They become data in one table:

  | channel key | error noun | create sends | baseline before the post exists |
  |---|---|---|---|
  | `voiceId` | `voice` | always (`v => v`) | `''` |
  | `templateId` | `template` | only when chosen (`v => v \|\| undefined`) | `''` |
  | `targetLanguage` | `target language` | always | `undefined` |

  The take-back `wanted = saved ?? wanted` is today's rule for all three. For the voice and the 템플릿, `saved` is always set once `slug` is, so `?? wanted` only matters for the language.
- **New types in `draft-queue.ts`.** Export the three that the tests and `useAutosave` need.
  - `export interface Assignments { voiceId: string; templateId: string; targetLanguage: ContentLanguage }`. The keys are the request's and the options' member names, so a request is `{ slug, draft, ...carried }` and the init reads `options[channel]`.
  - `export type AssignmentChannel = keyof Assignments`
  - `export interface DraftRequest extends Partial<Assignments> { slug: string; draft: Draft }`. Move SendDraft's doc comment onto the members. An undefined member leaves the post's value alone, and `''` clears a 템플릿.
  - `interface AssignmentWaiter<T> extends FlushWaiter { value: T }`. It replaces the three `*Waiter` interfaces.
  - `interface Assignment<T> { wanted: T; saved: T | undefined; waiters: AssignmentWaiter<T>[] }`. `saved` is "what the server is known to hold". Keep the voice and template field comments of `Queue` on the table rows.
  - `type AssignmentRecords = { [K in AssignmentChannel]: Assignment<Assignments[K]> }`
  - `const RULES: { [K in AssignmentChannel]: { noun: string; onCreate: (wanted: Assignments[K]) => Assignments[K] | undefined; unsaved: Assignments[K] | undefined } }`, filled from the table above.
  - `const CHANNELS = ['voiceId', 'templateId', 'targetLanguage'] as const satisfies readonly AssignmentChannel[]`. Add a `satisfies` check that it covers every key: either a `Record<AssignmentChannel, true>` built from it, or a test.
  - `export interface DraftQueueOptions extends Assignments { slug; saved; send: SendDraft; retry?; onState; onMinted }`. This is `attachDraftQueue`'s parameter.
- **Generic helpers** replace the per-channel `xDirty`, `xToSend`, `settleXWaiters` and `rejectXWaiters`:
  - `dirty(queue, channel)`
  - `toSend(queue, channel)`
  - `anyDirty(queue)`
  - `carried(queue): Partial<Assignments>` (only the members this save carries)
  - `settleAssignments(queue)`
  - `takeBack(queue, channel, cause)`: sets `wanted = saved ?? wanted`, then rejects that channel's waiters with `cause instanceof Error ? cause : new Error(`${noun} assignment failed`)`
- **Error strings and typing.**
  - Superseded waiters reject with `new Error(`${noun} assignment superseded`)`, which keeps today's exact strings. The new suite asserts `'template assignment superseded'`.
  - With `Assignment<ContentLanguage>` in the union, write the per-record helpers generically over `<T>` and call them inside the `CHANNELS` loop.
  - Where TypeScript cannot correlate `RULES[channel]` with `queue.assignments[channel]`, use one typed accessor, such as `function each(queue, fn: <K extends AssignmentChannel>(channel: K, a: Assignment<Assignments[K]>) => void)`. Do not use per-site casts.

## result
- `draft-queue.ts`:
  - `Assignments`, `AssignmentChannel`, `DraftRequest` and `DraftQueueOptions extends Assignments` are exported.
  - Each channel is one `Assignment<T>` record (`wanted`, `saved`, `waiters`) in `Queue.assignments`, walked by one `CHANNELS` list. A type-only check fails if a key of `Assignments` is missing from it. `RULES` holds each channel's noun, its create rule and its baseline before the post exists.
  - Generic helpers replace the per-channel copies: `dirty`, `anyDirty`, `toSend`, `carried`, `settleAssignments` and `takeBack`. `run`, the handle's `queue`, the settles, the take-backs, the locked-refusal path, the init and `discardQueue` no longer name a channel.
  - `SendDraft` is `(request: DraftRequest) => Promise<string>`, and the handle has one `assign(channel, value)`.
  - Casts: one in the `each` accessor that correlates a channel with its record, and one when building the records.
  - Error strings are unchanged (`${noun} assignment superseded/failed`), and the header comment is kept with one added sentence.
- `useAutosave.ts`: `send` destructures the request, and the follow effects and returned functions call `assign`. Its API (`reassign`, `assignTemplate`, `assignTargetLanguage`) and the SavePostDraft mapping are unchanged.
- Tests:
  - New `assignment-queue.test.ts` has the 16 generic cases from 4ea56946's field-queue suite, one `describe.each` row for the 템플릿, plus the `expectTypeOf` baseline pins. Making `voiceId` optional fails `tsc`.
  - `describe('the post template')` is deleted from `draft-queue.test.ts`, since each of its six cases is one of the 16.
  - `draft-queue.test.ts`, `draft-queue.mint.test.ts` and `answers-queue.test.ts` are rewritten mechanically for the request object and `assign`, with no expectation changed.
  - `useAutosave.test.tsx`, `useSaveStatus.test.tsx` and `EditorPage.test.tsx` needed no change: they never call the queue's send or assign directly.
