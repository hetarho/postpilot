# T145 Record complete clip scenes with explicit uncertainty

## goal
Make observation a complete factual scene record for every prepared source timeline, including explicit uncertainty and unusable spans, without making edit decisions.

## acceptance
- [v] Every observation response covers local `0..chunk_duration_ms` exactly in order, with the first scene at zero, each next start equal to the previous end and the last end equal to the chunk duration; merged chunks therefore cover the complete source timeline.
- [v] Each scene carries bounded event, action, motion, subjects, audible speech, quality, focal/subject geometry, `certainty` in `certain|uncertain|unknown` and `usability` in `usable|unusable`; black, obscured, static and unknowable spans are recorded instead of omitted.
- [v] The observe prompt and closed schema prohibit narrative, cut, copy, rate, transition and effect choices; source original-sound settings do not alter the audible analysis copy or its speech observation.
- [v] Parsing rejects rather than clamps negative, overflowing or out-of-order model times and reports distinct safe categories for missing start, internal gap, missing end, invalid status and invalid geometry without storing or logging response text.
- [v] Writer payloads and owner read projections preserve action, motion, certainty, usability and original verified cadence; UI inspection labels legacy records as unspecified rather than inventing certainty.
- [v] Automatic item association consumes structured certainty/usability for v2 observations and retains the old keyword heuristic only for read-compatible legacy successful content; unknown or unusable v2 scenes cannot authorize item facts.
- [v] `AnalysisContractVersion` advances to `clip-observation-v2`; v1 recovery/checkpoint data is never relabelled or reused for new generation, while existing successful v1 observations remain readable and their existing result remains unchanged.
- [v] Coverage/schema failures use the already reserved same-model response-correction allowance and stop on success, cancellation or exhaustion; non-response failures and source insufficiency do not create extra calls.
- [v] Analysis, parser, diagnostics, evidence, response-correction, recovery, schema-budget, RPC mapping and observation UI tests cover first/middle/end gaps, unknown/unusable footage, legacy display and v1-to-v2 non-promotion.
- [v] Run applicable ARCH-25 through ARCH-29 checks, including deterministic protobuf generation and generated-file snapshot protection.

## impl notes
- Add explicit `Action`, `Motion`, `Certainty` and `Usability` fields to the domain, JSON schema and `ClipObservedSegment`; keep `Quality` descriptive. Unknown content may use empty factual descriptions but must still carry a bounded quality/reason, valid geometry and its exact time span.
- Change validation from `previous.end <= next.start` to equality at every boundary and require exact chunk endpoints. Remove parser min/max clamping before validation so correction feedback describes the model response that actually failed.
- Keep chunk-local time in the model response and add the frozen source offset exactly once after successful validation. Merge only the exact frozen source/chunk sequence and never sort, fill or drop scenes.
- Version recovery compatibility separately from display compatibility. `upgradeRecovery` must not stamp v1 data with the v2 contract; canonical old analysis may be projected read-only with explicit legacy status but cannot enter a v2 writer input.
- Update prompt/schema budget fixtures for the added bounded fields rather than reducing source coverage, dropping speech or increasing provider calls silently.

## result
- domain: `clip/analysis.go` Segment+`Action Motion Certainty Usability` with `Observed/Confident/Unknowable`; `ValidateSegments` now demands exact coverage (first=start, next=previous end, last=end) and a valid status pair, while `ValidateLegacySegments` keeps the v1 rule for stored records only.
- parser: `clip/ai/parse.go` keeps the model's chunk-local times, refuses instead of clamping, and adds the frozen offset once after validation; `schemas/chunk.schema.json` and the observe prompt carry action/motion/certainty/usability and forbid every editing decision.
- diagnostics: new `observe_coverage_start|observe_coverage_gap|observe_coverage_end|observe_status` checks plus `action_runes`/`motion_runes`, allowlisted in `attempt_diagnostics.go` and mapped in the FE inspection vocabulary.
- contract: `AnalysisContractVersion` is `clip-observation-v2` beside a `LegacyAnalysisContractVersion` constant. `upgradeRecovery` no longer converts v1 attempt evidence at all — it refuses it, so a successor re-observes rather than planning on gapped, status-less scenes (the old conversion could only produce a state `selectRecovery` would discard).
- readers: writer payload, proto `ClipObservedSegment` (fields 7-10), the RPC projection and the FE model/mapper/viewer carry the four fields; a legacy record shows `unspecified` in ko/en instead of an invented certainty. `uncertainObservation` consumes the recorded status for v2 and keeps the keyword heuristic only for status-less legacy content.
- budget: the writer fixture `testPolicy("write")` now freezes `llm.ClipPlanInputUnits`, which is what `FreezeExecution` actually grants a text-only write stage; the 49-observation ceiling test measures against that same allowance. The observe prompt was compressed (no rule dropped) and a new `TestObservePromptFitsTheInlineInputAllowance` pins it at 7417 of its 7952 reserved bytes.
- fixtures: `testdata/live-observation.json` and `testdata/multi-source.json` were mechanically migrated (empty action/motion, `certain`/`usable` as their own recorded quality text states); no time changed and no paid call was made. README records it.
- tests removed as unreachable rather than weakened: the writer's "observation gap" and truncated-segment timeline cases, because a v2 record can no longer be gapped at the writer input. Their rules are pinned instead by `TestObservationGapIsRefusedBeforeTheWriterIsPaid` and the existing direct `composeTimeline` gap/scene test.
