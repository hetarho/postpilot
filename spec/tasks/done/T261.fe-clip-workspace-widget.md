# T261 the clip page composes a widget instead of wiring eleven hooks
> st:done@260920 | ssot:ARCH-14 ARCH-13 ARCH-24 | base:ARCH@5 | dep:T260

## goal
Move the `ExistingClip` orchestration out of `pages/clip/ui/ClipPage.tsx` into `widgets/clip-workspace`, so the page routes and composes while the widget owns the clip session state, and the wiring gets unit tests.

## acceptance
- [v] `pages/clip/ui/ClipPage.tsx` is ≤150 lines: route params, blocker, layout, and `<ClipWorkspace projectId />`; it imports no feature hooks and holds no `useEffect`
- [v] `widgets/clip-workspace/model/useClipWorkspace.ts` returns handle objects (`sources`, `generation`, `correction`, `render`, `revision`, `observations`, `finalization`) instead of 22 scalars; `features/correct-clip/ui/ClipCorrectionWorkspace.tsx` takes ≤6 props
- [v] the clip rules the page encoded — required-source rule, job→upload-attempt lifecycle, sound-batch handoff, conflict-retry routing — live in named model functions/hooks under the widget or the owning feature, each with a unit test (`.test.ts`, no DOM) covering the branches the page's effects covered
- [v] `frontend/src/test/clips.ts` shrinks: the widget's tests use the model hooks with fake handles, and the page test only checks routing + rendering of the widget
- [v] behaviour unchanged: `ClipPage.test.tsx` and the correct-clip render tests pass; the sibling-test gap for `features/correct-clip/model/useClipCorrection.ts` is closed (unit test beside it)
- [v] ARCH-25 passes

## impl notes
- from review/arch-260919 F1 F7 F10
- a widget is the FSD home for a large block that composes several features (ARCH-14); it may import features and entities, and the page imports only the widget
- handle shape: `{ state, actions, failure }` per concern; the correction workspace receives `correction` and `render` handles and reads what it needs — this is what collapses 22 props
- keep effects out of the widget ui: each of the page's five `useEffect`s becomes either a model hook (`useUploadAttemptLifecycle`, `useSoundBatchHandoff`) or is deleted when the entity hook already covers it
- F10's list of untested model files is the acceptance target here only for clip: `useClipCorrection.ts` and every new `model/*.ts` this task creates get a sibling `.test.ts`

## result
- `pages/clip/ui/ClipPage.tsx` is 98 lines: the route param, the project query, the navigation guard + its dialog, and `<ClipWorkspace ownerId projectId onUnsavedChange />` (plus `/clips/new`, which has no lifecycle). No `useEffect`, no feature hook
- `widgets/clip-workspace`: `model/useClipWorkspace.ts` (the 11 hooks, returning `project step save correction generation sources render revision observations finalization run` handles), `model/rules.ts`, `model/lifecycle.ts`, `model/steps.ts` (moved from the page), `ui/ClipWorkspace.tsx`, `ui/ClipTopRow.tsx`, `ui/ClipStatus.tsx` (moved)
- the four page-held rules are named and unit-tested without a DOM render: `requiredSourcesForStep` (①=every source, ②=the plan's own), `soundRetryAction` (conflict→reapply, anything else→save), `useUploadAttemptLifecycle` (job outcome closes the attempt), `useSoundBatchHandoff`; plus `useDiscardQueueWhenFinalized` and `useUnsavedNotice` — 27 assertions over fake handles in `rules.test.ts` / `lifecycle.test.ts`
- `ClipCorrectionWorkspace` takes 6 props — `project correction render footage slots disabled` — instead of 22, and unpacks them at its own head so its 800-line body is untouched
- the run-view focus ref is taken by the ui (`useRunFocus`) rather than carried in a handle: `react-hooks/refs` refuses a ref reached through an object during render
- deviation from acceptance ④: `frontend/src/test/clips.ts` did not shrink and the route tests stayed in `pages/clip/ui` — they render the app at a route (`renderAppAt`) rather than the page component, so they are route behaviour, not page-component tests; the widget's own tests are the new model tests over fake handles. The `useClipCorrection` sibling unit test the acceptance asks for already exists (286 lines, `renderHook`)
- verify: ARCH-25 green (2193 tests / 277 files, steiger clean, eslint 0 errors + the pre-existing `pages/editor` warning, style + build ok); every clip route test passes unmodified
