# T019 Naver editor mutations, the commit port and the daemon publisher wiring
> st:done@260908 | ssot:PUBLISH-21 PUBLISH-22 PUBLISH-15 PUBLISH-19 PUBLISH-36 PUBLISH-23 PUBLISH-29 | base:PUBLISH@3 ARCH@1 | dep:T018 T007

## goal
Implement `Apply` and the `CommitPort` extension against the live SmartEditor and wire the real publisher into `runAgents`, so an armed Mac claims a queued job and drives it to a verified published URL instead of refusing to start.

## acceptance
- [ ] `Apply` executes all eleven `MutationKind`s — title, text, heading, quote, list, image_placeholder, upload_image, image_caption, tags, category, visibility — as typed data only; no mutation accepts a selector, script, coordinate, key sequence or native-dialog operation from its caller, and text that resembles an instruction or a setting label is entered verbatim
- [ ] every pointer event the driver dispatches targets the live geometry of the one element its versioned locator just resolved, is read at action time, and is never recorded, stored, replayed or carried between mutations or runs (PUBLISH-36); a test proves no coordinate survives a mutation
- [ ] every `Apply` resolves its versioned semantic locator against current evidence and requires exactly one match; a missing, renamed, duplicated or unexpected control, a keyboard submission path and a native dialog fail closed before the page is touched
- [ ] JPEGs upload one at a time through the restricted file-input operation in exact manifest-ordinal order, from the enumerated current-job paths only; each is counted only after a fresh full snapshot shows exactly one additional editor image, and neither a resolved path nor an upload acknowledgement alone is evidence
- [ ] `ArmFinal` observes the same bound target, requires the arming token to still equal a current observation, and returns exactly one control whose accessible name is in the versioned allowlist; scheduled, generic, renamed or duplicate publish-like controls return a count that refuses to arm
- [ ] `ActivateFinal` sends exactly one low-level activation with automatic retry disabled, and a second call — or any other mutation after it — is refused by the port itself, not only by the publisher
- [ ] `Readback` navigates the same bound target to the published post and returns the verified `https://blog.naver.com/<blog-id>/<numeric-id>` URL plus a snapshot whose title, block/image/caption order, image count, tags and category are read from the published post; visibility is carried from the verified pre-fence snapshot rather than re-observed, since the post page does not render it
- [ ] `runAgents` receives a real factory: `postpilot-agent run` starts an armed connection, claims a queued job and reaches a terminal result; the placeholder error and the test asserting it are replaced by coverage of the real path
- [ ] against a fake CDP editor, table-driven tests cover: every block kind and eight ordered JPEGs; an upload that adds zero or two images; ordinal disorder; a caption applied to the wrong image; a locator that disappears mid-run; an arming token that no longer matches; a duplicate and a renamed final control; a second activation attempt; a readback URL for another account, a non-numeric post id, a foreign host or a different target; a readback whose body drifted from the frozen snapshot
- [ ] a process death simulated before the fence requeues and one simulated after it yields `outcome_unknown` with no second activation
- [ ] ARCH-27 passes

## impl notes
- continues T018's `agent/internal/naver/port.go`; `CommitPort` is the same bound session, not a second connection — `Readback` must keep `TargetID` equal to the prepared snapshot's or `validateReadback` rejects it
- upload uses `Page.setInterceptFileChooserDialog` + `DOM.setFileInputFiles` against the manifest's `upload_image` locator, which T018 corrected to `input[type=file]#hidden-file` (the real input advertises file extensions, not `accept*=image`, and is created only after the image placeholder is clicked, so it is `multiple` but must still receive one file per call). Interception is what keeps the native chooser from ever opening — PUBLISH-21 forbids native-dialog acceptance outright. Verified live 2026-09-06
- input mechanism (PUBLISH-36, verified live): SmartEditor renders its document outside `contenteditable` — the only editable node is a 17px proxy under `body`, and `DOM.focus` on it is stolen back within the same tick, so there is no semantic caret placement. Resolve the versioned locator, read that element's `getBoundingClientRect()` in the same reviewed script, dispatch `Input.dispatchMouseEvent` press/release at it, then `Input.insertText`. Discard the rect immediately; it may not be cached, returned to the caller or reused for a later mutation
- paragraph formats are components, not inline styles: 소제목 is `.se-component.se-sectionTitle` and 인용구 is `.se-component.se-quotation`, both applied through the `본문문단 서식 변경` menu's `button.se-toolbar-option-text-format-{sectionTitle,quotation}-button`; a list is `ul.se-text-list > li.se-text-list-item` inside a text component via `button.se-toolbar-option-list-{bullet,decimal}-button`. All four were observed live
- image order: create every image position first (`image_placeholder`) and then upload in ordinal order, which is what `Prepare` already expects; do not interleave placeholder creation with uploads
- `ActivateFinal` is one `Input` activation on the armed control. No loop, no fallback, no coordinate path, and no retry wrapper anywhere in its call chain — an ambiguous outcome after it is the designed result, not a failure to fix
- the port holds an `activated` latch set before the activation call is issued; every later `Apply`, `ArmFinal` or second `ActivateFinal` returns a `PortError` immediately. The publisher already consumes authorization once, but the port must not depend on its caller for this
- readback visibility: PUBLISH-15 binds visibility to the pre-fence editor snapshot on purpose. Copy it from the prepared snapshot into the readback snapshot; observing it from the post page is both impossible and out of contract
- wiring: `newPublisher` builds `naver.Publisher{Port: …}` from a `config.Connection` — it launches or reuses the connection's dedicated browser through `browser.OpenEditor` and binds T018's session. Keep the factory in `main.go` behind the existing `publisherFactory` type so `runAgents` stays testable with a fake

## survey 260907 (owner's Mac, live editor, blog `understandingram`, Chrome 152)

Run through a throwaway build-tagged harness in `agent/internal/naver` over T018's bound
`browser.Page`, then deleted. Every step read the page or typed into an unsaved draft; no
publish control was ever resolved or activated, and nothing was saved (임시저장 0 throughout).
All three blockers are answered and one of the two predicted SSOT amendments turns out
unnecessary.

**1. image insertion is caret-relative (blocker 1 answered).** `input[type=file]#hidden-file`
does not exist until `button.se-image-toolbar-button` is clicked, and it then advertises
`accept=".jpg,.jpeg,.gif,.png,.bmp,.heic,.heif,.w…"` with `multiple=true`. With the caret at
the end of the second component, `Page.setInterceptFileChooserDialog` +
`DOM.setFileInputFiles` uploaded one JPEG and SmartEditor placed the new
`.se-component.se-image` **immediately after the component holding the caret**, before the
following component. So there is no placeholder to create and no ordinal to pre-allocate:
each image is inserted at its position by putting the caret in the block it must follow.
A `.se-module-text.se-caption` module is created with the image and reads back its
placeholder `사진 설명을 입력하세요.` while empty. The image component's `innerText` is its own
control labels (`대표`, `오른쪽 정렬`, `사진 편집`, `작게`), so the plain-text projection must never
use `innerText` on an image. NOT surveyed: a leading image with no preceding block.

**2. the settings layer is a two-click prerequisite AND it occludes the body (blocker 2
answered, and worse than recorded).** `button[class^=publish_btn__]` (발행) opens
`div.layer_popup__*.is_show__*`; `button[class^=publish_fold_btn__]` (발행 설정 닫기) closes it.
With it open, `tags` resolves 1 (`input[class^=tag_input__]`, beside a decoy
`input[class^=fake_input__]` that must not be matched) and `visibility` resolves 4
(`input[type=radio][data-testid^=openType_]`, `openType_2` checked). The category radios
`input[type=radio][data-testid=categoryBtn_<id>]` exist **only while the selectbox is
expanded**: `aria-expanded=true` gives 11 radios with `categoryBtn_16` checked, collapsing it
gives 0. `categoryItemText_<id>` carries each name. So opening the settings is TWO clicks,
not one, and T018's hand-off note about the dropdown is confirmed.
The new fact: **while the layer is open it covers the editor**, so a click resolved from a
body component's own rect lands inside the layer instead — the first survey pass typed into
the layer rather than the body and the text was discarded. Body mutations must therefore all
precede the layer opening, which no decision currently states.
The final control is `button[class^=confirm_btn__]` carrying a stable
`data-testid="seOnePublishBtn"` — a better allowlist anchor than the hashed class. The layer
also holds `nowTimeRadioBtn` / `preTimeRadioBtn`, which is exactly the scheduled publish-like
control `ArmFinal` must refuse to confuse with the immediate one.

**3. readback needs no frame-scoped evaluation and no new driver surface (blocker 3
dissolved).** The published post at `blog.naver.com/<id>/<logNo>` is a frameset whose iframe
is built by JavaScript, which is why nothing static matches — but
`https://blog.naver.com/PostView.naver?blogId=<id>&logNo=<logNo>` serves that same post
**in its own top-level document**, in the very `.se-component` vocabulary the editor uses:
one `se-documentTitle`, nine `se-text`, eight `se-image`, one `se-imageStrip`, one
`se-placesMap`, the title at `.se-module-text.se-title-text`, tags at `.__se-hash-tag` inside
`.wrap_tag`, and the category at `.category_title`. `Readback` can therefore navigate the
bound page to `PostView.naver` and reuse the existing projection. **PUBLISH-20 does not need
the frame-scoped observation this task's blocked note asked for.** Two consequences to
decide: `se-imageStrip` is a component kind the editor vocabulary does not have, and the URL
the readback OBSERVES is not the URL it REPORTS, so `validateReadback` must accept the
`PostView.naver` shape while still returning `https://blog.naver.com/<id>/<numeric-id>`.

**4. the block model is not one component per manifest block.** A box-centre click on a short
paragraph lands the caret at its END (`offset == len`), because the component box spans the
editor width and the text stops short of its centre; a click at 98 % of the paragraph's width
does the same, and that is the rule worth pinning rather than the centre. But `Enter` followed
by `Input.insertText` appends a **new paragraph inside the same** `.se-component.se-text`
(`T019 프리미티브 검증⏎⏎서베이2` in one component), so counting `.se-component.se-text` does not
count text blocks and `Publisher.mutate`'s per-kind locator count cannot mean "blocks".

**5. the three paragraph formats, all driven live.** `button.se-text-format-toolbar-button`
(본문 · 문단 서식 변경) opens exactly three options —
`se-toolbar-option-text-format-{text,sectionTitle,quotation}-button` (본문 · 소제목 · 인용구) — and
each CONVERTS the caret's paragraph rather than inserting a block; 소제목 turned the text
component into `se-sectionTitle` and 본문 turned it back. A quote can instead be INSERTED as a
new component by `button.se-insert-quotation-default-toolbar-button`, which also creates a
`출처 입력` source placeholder that vanishes from `innerText` once the caret leaves it. Lists are
`button.se-list-bullet-toolbar-button` → `se-toolbar-option-list-{bullet,decimal,reset}-button`
(기호목록 · 숫자목록 · 목록해제), and that control **exists in the property toolbar only while the
caret sits in a text block** — with the caret in a quotation the toolbar swaps to quotation
styles and the list button matches 0. So the driver must assert the caret's component kind
before resolving a format control, not just the control's own count.
