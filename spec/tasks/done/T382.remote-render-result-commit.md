# T382 A worker render becomes the result through one durable API commit
> st:done@260925 | ssot:ARCH-6 ARCH-11 ARCH-45 ARCH-46 ARCH-49 ARCH-50 ARCH-55 CLIP-20 CLIP-31 CLIP-79 CLIP-80 CLIP-87 CLIP-93 CLIP-125 CLIP-153 CLIP-154 CLIP-161 | base:ARCH@11 CLIP@44 | dep:T381

## goal
Replace server-render execution with a frozen remote stage while preserving the project's existing atomic completion and cancellation semantics.

## acceptance
- [v] StartRender keeps all ownership, plan-revision, original-sound, layout, quote-free and retained-source admission checks; browser rendering and its upload/verdict path do not acquire media-stage jobs.
- [v] In worker execution mode RunRender creates a frozen render stage and yields without downloading originals or launching FFmpeg in the API; worker failures cannot invoke an embedded render fallback.
- [v] Worker completion accepts only the current stage, original identities, plan revision, expected artifact slot, compatible profile and passing measurements; a failed or stale candidate never replaces the previous result.
- [v] The stage result and parent wake survive a restart, and safe result-commit continuations can retry after a crash without another render or provider call.
- [v] The existing finisher atomically publishes the accepted candidate and finishes the same owning job once; repeated reports, response loss and cancellation/completion races leave one authoritative outcome and one retained object.
- [v] API integration tests with real stores and two independent worker clients cover no-duplicate render, accepted-result recovery, source replacement, revision conflict, cancellation races and preserved browser rendering; ARCH-26 and render/release smokes pass.

## impl notes
- Keep renderPayload compatibility, including old queued version-1 payloads. Resolve legacy recipe/design inputs once through the current plan validation path, then freeze a complete portable execution snapshot before creating the remote stage.
- Transfer the actual-original rebind logic from RunRender to the common executor used by T380: compare fingerprint, duration, dimensions and audio/cadence evidence before executing the validated plan. Final rendering always loads originals.
- Use the temporary CLIP_MEDIA_EXECUTION switch introduced in T381 only for rollout. The shared service still provides in-process layout/preview/caption-frame methods; the final-encode path is the part moved here.
- CompleteMediaStage validates the immutable accepted receipt and wakes its parent in the same writer transaction through clip/app ports. It does not write project.Result or settle credits directly.
- Mark the render-result continuation as replay-safe in the generic continuation contract: it performs only validation, idempotent storage metadata reads and the atomic finisher, never a model call. API boot may re-ready a claimed safe continuation; preparation-to-AI continuations remain fail-on-interruption.
- Extend Finisher's transaction-scoped ports to prove that the staged candidate is the accepted media output for this parent and revision and mark it consumed in the same commit as ApplyAttemptResult and Finish. Reuse existing StageAttemptResult/DiscardAttemptResult and deletion intents rather than adding a second terminal authority.
- Preserve Result.Kind=server and all download/finalization behavior. Store execution profile/provenance on the media attempt, not as another user-facing render kind.
- After a lost Complete reply the worker reuses the same attempt/output receipt; once accepted it must not rerender or reupload under a new key merely to get an acknowledgement.
- Test API restart after object upload, after receipt acceptance, after continuation claim and after canonical commit; only the pre-acceptance lease-loss case may spend a new media attempt.

## result
- StartRender freezes complete version-2 execution snapshots after existing admission/layout checks; queued version-1 jobs resolve once into an immutable stage. Browser rendering stays outside the media queue, and compatible re-upload identities retain the owner's source-audio selection and disclosure setting.
- RunRender parks the same parent with a replay-safe continuation and publishes only its accepted worker artifact; API execution downloads no originals, performs no encode or provider call, and has no worker-error fallback.
- Source grants and receipts recheck the current retained batch; original dimensions, duration, audio/cadence evidence and frozen composition must agree. Execution-only contrast/glyph notices do not change the assembly or invalidate an otherwise identical render.
- Finisher consumes the accepted result reservation, applies the canonical project result and finishes its parent in one SQLite transaction; lost responses and replay are idempotent and cancellation has one authoritative winner.
- Real SQLite/private HTTP tests race two worker clients and cover upload/acceptance/claim/publication crashes, rollback at every commit write, revision/source conflicts, cancellation races, legacy jobs, browser isolation and no API fallback. Focused race checks pass.
