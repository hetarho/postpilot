## goal
The five plans read at a glance (tier, price, one button, four benefits) and one compact section below them compares post and clip counts, with no post/clip basis switch.

## acceptance
- [v] Each `/plans` card holds only, in order: tier with at most one state label (current, else pro's recommended), the selected-term price, its button, then daily credits, monthly bonus, highest eligible model grade and monthly server exports. Annual adds one approximate monthly-equivalent line under the price; the ten-for-twelve saving appears once, beside the period selector while annual is selected, never on a card. The free card shows free-model access and its provider-limited caveat instead of the four lines, with no zero-valued benefit. No estimate, per-post figure, basis label or clip cap is inside a card; the 60-second cap is stated once below the cards.
- [v] Every card has exactly one full-width button in the same slot under the price, chosen per QUOTA-28's table: Subscribe (no active subscription, paid card, term carried into checkout), Upgrade (higher tier), the scheduled-change button (lower paid tier), cancel on Billing (free under a subscription), 구독 관리 → Billing (the active paid tier), a disabled 이용 중 (free as the current plan); for master, a disabled Subscribe on each paid card and a disabled 무료 플랜 on free. Only pro's Subscribe is the filled CTA, and only when it is enabled; no master card links to checkout or opens a change dialog. Master sees no operator notice anywhere on the page.
- [v] `/plans` has no post/clip basis selector, basis label/summary, per-card production grid, floating condition button or estimate sheet, and the header's three-check benefit row and above-card monthly-assumption paragraph are gone. Below the cards, one comparison lists every tier with a post count and a separate AI-clip count, naming each paid tier's highest eligible model level, labelling the post figure 최근 사용량 기준 or 예상, and stating the assumed 30 daily grants plus the monthly bonus; free shows provider-limited availability. A missing/unpriced/incompatible assigned pair or an unavailable rate shows an explanation, never a fabricated count or another level's count.
- [v] Clip estimates start at three 60-second originals and a 30-second finished clip. A collapsed inline control in the comparison (a button with `aria-expanded`) edits only original count and finished duration within QUOTA-57 bounds, persists valid values in the browser, and updates the counts and the stated conditions immediately with no network request; the post count has no input.
- [v] Price, button, benefit lines and the comparison keep AA contrast and clear spacing in both themes; pro's recommendation has a text label; THEME promotional primitives, reduced motion, keyboard access, a single vertical scroller and no horizontal overflow at 320 px are retained.
- [v] `/about` still shows MKT-5's complete static offer (both list prices, benefits, the 60-second cap once below its cards) with no session request, estimator, selector or button. FE tests cover card content and order for free/paid and both terms, every button state in the table including master and the current free plan, the comparison's counts and unavailable/free cases, the clip disclosure and its persistence, `/about` regression and both languages; run ARCH-25 verification.

## impl notes
- Card composition: PlanLadder renders the card frame and contents; `/plans` passes `term` and the `action` slot. Render the action slot directly under the price block (before the benefit lines) and always reserve it on `/plans` so the buttons align across the five cards on the desk grid. `/about` passes no `action` and no `term`, so its slot is absent and its card keeps the annual list price and saving copy, since it has no selector (MKT-5). Drop `estimates` and `ModelEstimate` from PlanLadder and move the 60-second cap (`compare.clipCap`) below the ladder on both pages.
- Button mapping lives in `PlansPage.action` and uses the existing billing state (`myPlan.plan`, `useMyBilling` subscription status/plan/term). Order of checks: master → the Subscribe control disabled on paid cards and a disabled `compare.freePlan` on free; current free → disabled `compare.inUse`; current paid tier → `Link` to `/billing` with `compare.manage`; lower paid tier under an active subscription → `ScheduledChangeButton` (add an optional `className` prop so it can be `w-full`); free under an active subscription → the existing `compare.cancelFromBilling` link; otherwise → the existing checkout `Link` (Subscribe/Upgrade, `cta` only for the recommended rung when it is actionable). New copy: ko `구독 관리` / `이용 중` / `무료 플랜`, en `Manage subscription` / `In use` / `Free plan`. Disabled buttons use `Button disabled variant="secondary"` (a disabled checkout control is a `Button`, never a `Link`). Remove the `operatorCoverage` notice from `/plans`, and delete the key if T514 has already removed its billing use (QUOTA-68).
- Saving copy: keep the annual option label `compare.yearly`; while annual is selected, render one meta line under the selector with `compare.annualSaving` reworded to state ten monthly payments for twelve months (ko `12개월을 10개월 요금으로 결제해요`, en `Pay 10 months for 12`), and remove it from `/plans` cards. `compare.monthlyEquivalent` is the card's only extra price line.
- Comparison data: reuse GetMyPlan's estimator combos. Map each paid tier to its `modelCeiling` (`value`, `balanced`, `premium`, `top`), take only that level's assigned combo, and use the existing `postsPerFigure`, `clipsPerGrant` and `illustrativeMonthlyCredits` helpers; no locked state is needed, so `requiredPlanForLevel` and `canEstimate` go if nothing else uses them. Lay it out as one row per tier (tier and level name; posts with basis label; clips) that fits 320 px without horizontal scroll; keep `useCountUp` for the counts. The assumption sentence (`benefits.baseline` meaning) heads the comparison, and the post caveat plus the clip caveat sit beneath it, shortened if needed but still saying the counts are estimates, that actual use varies, and that clip estimates are separate from server exports.
- Clip control: keep bounds/defaults and guarded browser persistence from `pages/plans/model/estimate-input` and the `PlanEstimator` sliders; replace the Sheet/ActionBar with an inline disclosure whose toggle shows the current condition summary (`estimator.clipSummary`) and the 60-second-original assumption. Remove `EstimateKind` and the basis state.
- Delete only UI code and strings made obsolete by the removed basis switch, header check row, per-card estimates, floating action and sheet; the backend estimator contract and the other per-post displays (`/ai-models`, post creation) stay. Use existing semantic tokens and `shared/ui` primitives; add a token only if AA contrast requires it in either theme.
