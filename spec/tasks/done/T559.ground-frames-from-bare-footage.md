# T559 Take a server render's ground frames from its own lossless cut, and trim before scaling
> st:done@261005 | ssot:ARCH-37 ARCH-24 | base:ARCH@15 | dep:T558 | touches:backend/internal/clip/media/composition_render.go backend/internal/clip/media/ground_sampler.go

## goal
A server render reads each cut's ground frames from the lossless `bare-%04d.mp4` it just encoded instead of decoding the original a second time, and the browser sampler scales only the frames it reads, in one output per cut.

## acceptance
- [v] server render: after `renderBareFootage`, the cut's needed frames are read from `bare-%04d.mp4` (canvas-sized, `-crf 0`, yuv444p, same chain) by one ffmpeg call selecting the needed local frame indexes; no second decode of the original
- [v] browser sampling (`sampleCut` on an original): the chain is trim → rate → select the needed frames → cover scale → setsar, with one output for the cut instead of up to `SampleBatch` outputs
- [v] grounds are pixel-identical to today's for the same plan: a media smoke compares the sampled grounds (scrim, accent, contrast notices) of a fixture plan before and after, and the identity smoke digest is unchanged on this host
- [v] ARCH-37: `production` target media smokes and the identity smoke pass (grep `did not complete successfully` → 0); record `render_footage` substage time for one fixture before and after in the result
- [v] behaviour unchanged otherwise: ARCH-26 green

## impl notes
- from review/perf-cost-261004 F8
- cover is a per-frame spatial filter, so moving the frame selection before it cannot change a selected frame's pixels; the bare file is the composition's own footage, so reading it is reading what the viewer sees under the text
- keep `readFrame`'s PNG decode; cropping inside ffmpeg would need one output per region again
- the fade-to-black mean (`fadeBlackMean`) path is untouched
- ffmpeg filters used must be on the `media-tools.sh` allowlist (`select` is; check before relying on any other)
