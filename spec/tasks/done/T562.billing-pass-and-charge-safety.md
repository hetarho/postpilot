# T562 Keep the billing pass running, charge each order once and never revert a cancel
> st:done@261004 | ssot:ARCH-10 ARCH-24 | base:ARCH@15 | dep:- | touches:backend/internal/billing/ backend/internal/tosspay/client.go backend/cmd/api/contexts.go

## goal
One unapplicable order no longer stops every renewal, a billing-key charge cannot run twice for one order or be marked failed after it was captured, and the annual benefit step never overwrites a subscription with a stale copy (BILL-7, BILL constraint "repeated notifications and unresolved outcomes must not duplicate charges, grants or refunds").

## acceptance
- [v] `ReconcilePending` handles each intent independently: a captured payment that cannot be applied (`ErrInvalidPack`, a quote mismatch, any apply refusal that is not transient) moves the intent to `review` with an error log, as `ErrStaleQuote` does; other per-intent errors are logged and collected; `RunDue` logs a ReconcilePending error and still runs `DueSubscriptions` and `ReconcilePendingRefunds`
- [v] `tosspay.Client.Charge` sends `Idempotency-Key: <orderID>`
- [v] `DueIntents` skips intents created less than `pendingSettleGrace` (2 minutes, a named constant in billing) ago, so the worker does not race the request path that just created them
- [v] a charge answered with 429, 5xx, a transport error or Toss's duplicate-order code leaves the intent pending (read the order again next pass); only a definitive card refusal runs `failFixedIntent`
- [v] `grantAnnualWindow` advances `next_grant_at` with a conditional update (`UPDATE subscriptions SET next_grant_at=? WHERE user_id=? AND next_grant_at=?`) that touches no other column and not `updated_at`; zero rows means another writer moved the row, and the loop re-reads the subscription before continuing
- [v] the Toss client gets an `http.Client` with a 30 s timeout in `cmd/api/contexts.go`
- [v] tests: an intent failing with ErrInvalidPack goes to review and the same pass still renews a due subscription; a 429 charge leaves the intent pending; a fresh intent is not picked by DueIntents; a cancel written between DueSubscriptions and an annual row's step survives the step; the charge request carries the idempotency header (httptest)
- [v] behaviour unchanged otherwise: ARCH-26 green
