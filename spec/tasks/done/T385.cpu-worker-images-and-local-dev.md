# T385 Local development and CPU images run API and worker separately
> st:done@260925 | ssot:ARCH-2 ARCH-6 ARCH-21 ARCH-32 ARCH-36 ARCH-37 ARCH-39 ARCH-40 ARCH-42 ARCH-45 ARCH-52 ARCH-54 | base:ARCH@11 | dep:T383

## goal
Package the CPU executor independently and make the ordinary development command start a complete two-process media environment.

## acceptance
- [v] A reproducible nonroot CPU worker image contains only the worker and its required media assets/runtime, advertises the contract/profile manifest and needs no application DB or provider configuration.
- [v] The API and worker use the same pinned media/font/overlay sources without relying on identical host paths, a shared workspace or a database volume in the worker.
- [v] `pnpm dev` and `pnpm dev:api` start/rebuild the API and CPU worker with MinIO; a first install, changed compiled-in asset and API hot reload cannot leave a seemingly healthy stack with a missing worker.
- [v] `pnpm dev --seed` stops both API and worker before changing installation data, and restarts them only after a successful seed; bucket purging still requires its existing explicit flag.
- [v] Worker startup validates its own bounded env overrides, performs a real CPU tooling check and exposes a shell-free health command; bad config identifies its cause and fails that worker.
- [v] Build/compose/dev-launcher tests cover service selection, private credentials, separate volumes, no NVIDIA requirement and failed-seed behavior; both execution-image smokes and relevant ARCH-26 gates pass.

## impl notes
- Add named `media-worker-deployable` and `media-worker-smoke` targets in backend/Dockerfile, sharing the existing pinned media/resvg/font build stages. Preserve the current deployable API target name and its default behavior while the rollout switch is still present.
- Build cmd/media-worker independently and add OCI labels for media protocol, renderer profile/asset digest, supported architecture and source revision. Protocol compatibility does not require every API and worker to have the same git SHA.
- Retain API media assets needed by existing plan checks, preview/caption frames and the temporary embedded execution. Removing them blindly breaks the browser render path.
- Add a media-worker dev service with its own work volume and worker-specific air/build command; source/go-module mounts may be shared, but backend_data and API secrets may not. Render/profile asset changes rebuild both participating images so hot reload cannot create a silent asset mismatch. Both services communicate through the internal Compose network.
- Generate a random local-only worker credential into an ignored restrictive env file read by the dev API and worker, using a worker-reachable MinIO signing endpoint. Set the temporary execution switch to worker in dev after the full backend lifecycle is available; never copy a real VPS credential into the fixture.
- Change the dev command's explicit service list as well as its profiles: `up backend` does not start an unrelated worker just because both declare the same profile.
- Keep existing local encode/decode overrides within clip.MediaThreadMax and put documented overrides through the same owning-context validation. Production CPU defaults remain 1 encode / 2 decode and one job per worker.
- Add a pure command-planning seam to scripts/dev.mjs if needed so tests inspect stop/seed/start order without actually wiping a developer database.
- Do not copy obsolete explicit font paths from an env example into the worker image. Use the current renderer defaults/asset manifest and keep deployed override compatibility visible in the later preflight.
- Official Compose profile behavior checked 2026-09-25: https://docs.docker.com/compose/how-tos/profiles/ .

## result
- Added execution-only nonroot CPU targets, pinned runtime/build bases, contract/asset/revision OCI labels and an offline manifest command. The build executes a tiny H.264 encode/decode check using the existing pinned PNG capability; no codec/profile changed.
- Added separate worker Air/build/work volumes and generated local-only credentials. Both dev entry points explicitly rebuild/watch API and worker; seed planning stops both before replacement and leaves them stopped on failure.
- Health checks require CPU capabilities, a compatible authenticated API and the live worker's workspace lock. Command checks use a separate directory beneath that worker's identity; startup locks before probing/collecting its own workspaces.
- Verified the disposable development stack from empty named volumes, API Go hot reload, a compiled asset edit rebuilding/replacing both images, worker-child exit detection beneath Air, and explicit restart recovery. The fixture used no real env, published no ports, and was removed with its own volumes afterward.
- Native full backend gates and frontend 314 files / 2711 tests plus lint/format/FSD/style/build pass in an isolated checkout. Dev launcher tests (5), deployment tests (11), generated-code consistency and spec checks pass; the spec tool reports only 22 unrelated existing freshness warnings.
- Both execution images pass: API `media-smoke` (580.6 s) and CPU `media-worker-smoke` (361.28 s parity, 2 CPU / 1 GiB), including identical preparation measurements and delivered footage/sequence hashes (`93ec1006…`, `b863cc97…`) with 16 sampled frames each. Final command-directory isolation changes were rebuilt and verified with the real nonroot health/isolation/reaping checks; rendering code/assets were unchanged.
- Main files: `backend/Dockerfile`, `backend/cmd/media-worker/main.go`, `backend/internal/clip/media/runtime.go`, `backend/internal/clip/worker/workspace_unix.go`, worker config/smoke tests, `docker-compose.yml`, both Air configs, `scripts/dev.mjs`, `scripts/dev.test.mjs`, `scripts/media-assets.mjs`, `deploy/media_dev_test.py`, CI, package scripts and README. No live deployment, physical host setup or SSOT deviation.
