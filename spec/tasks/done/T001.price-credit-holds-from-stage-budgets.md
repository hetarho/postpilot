# T001 Price credit holds from each call's own completion budget
> st:done@260905 | ssot:QUOTA-14 QUOTA-32 QUOTA-33 GEN-22 GEN-29 | base:QUOTA@2 GEN@1 ARCH@1 | dep:-

## goal
Make the credit hold price every planned call at the completion budget that call is actually sent, instead of one process-wide `LLM_MAX_TOKENS_DEFAULT`, so observation stops over-holding and long writes stop under-holding (legacy change 28).

## acceptance
- [v] a generation job's hold prices its observation call at the observation budget and its write call at the write budget for that job's requested target length, not both at `LLM_MAX_TOKENS_DEFAULT`
- [v] holding for a job whose observation and write use the same model produces two priced entries when the two stages have different budgets, and the model is not charged for more calls than it makes
- [v] a job with a long requested target holds strictly more than the same job with no target, and the difference tracks the write budget's own derivation
- [v] an observation-only job whose every observation is reused (no observe call) still holds nothing for observation — the zero-count rule is unaffected
- [v] `CreditsFor` and the admission hold return the same figure for the same planned work; a surface pricing a model without a stage names the stage it quotes for
- [v] balance-floor regression: a user whose lots cannot cover the hold is refused before any row is written, and a job whose actual cost exceeds its hold drains the lots to zero and no further
- [v] settlement refunds `held − actual` to the originating lots, and a terminal transition that runs twice settles once
- [v] no provider request body changes as a result of this task (golden or byte-equality test on the request builders)
- [v] unit tests cover every item above in `backend/internal/usage` and `backend/internal/job`; ARCH-26 and ARCH-28 pass

## impl notes
- `PlannedCall` (`backend/internal/job/job.go`) gains the completion-token figure beside `Ref` and `Count`; `job.PlannedCalls` keeps collapsing a ref used twice into one entry only when the budgets agree, otherwise emits one entry per budget
- `worstCaseMicrousd` (`backend/internal/usage/service.go`) prices each entry at its own figure; the service keeps a completion fallback for an entry that declares no budget so a new caller cannot price a call at zero; `holdInputTokens` stays 30 000
- the admission seam already knows kind, photo count and requested target length: the `jobAdmission` bridge in `backend/cmd/api/main.go` asks the same `LLMCompletionBudget` (`backend/internal/platform/config`) the stage will ask — observe from `OBSERVE_BATCH_SIZE`, write from target length, revise from the larger of target and existing content — so the two halves cannot drift; do not let a context reach into another's configuration (ARCH-7): expose the budget through the seam the composition root already owns
- `CreditsFor` behind the catalog's per-model `RequiredCredits` and `EstimatePostCredits` (`backend/internal/provider/service.go`) prices with the same per-call budgets
- must not change: the floor guarantee (`spend` refuses before writing, `spendUpTo` clamps at each lot), settlement, the `len(debits) > 0` exempt-tier guard, the ladder, the charge formula, lot order, renewal, the 30-photo ceiling, `LLM_MAX_TOKENS_DEFAULT`, and every budget a stage is sent
- sequencing: T002 (MODEL-46) raises the write budget and must land after this task so no window exists where the budget is raised but still held at 8 192

## result
- `job.PlannedCall` and `usage.PlannedCall` carry each call's completion budget; exact pricing calls collapse only for equal model-and-budget pairs, while callers still using the registry default retain the non-zero fallback.
- The composition-root generation enqueue prices observation, write and revision from the same `LLMCompletionBudget` used by execution; a reuse-everything run emits no observation pricing call, and revision freezes its target/content length before enqueue.
- Catalog and post estimates name observe/write stages and resolve through the same usage estimator; no provider request builder or wire body changed.
- Added focused coverage in `backend/internal/job`, `backend/internal/usage`, `backend/internal/provider`, `backend/internal/generation` and `backend/cmd/api`; the existing floor, overrun, refund, idempotence and exact request-shape regressions remain green.
- ARCH-26 and ARCH-28 pass: gofmt, vet, build, the complete backend test suite, proto generation and SQL generation.
