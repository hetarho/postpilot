# T565 Send each clip autosave through its own project's sender and queue the clip storyline
> st:done@261004 | ssot:ARCH-14 ARCH-24 | base:ARCH@15 | dep:- | touches:frontend/src/features/edit-clip-regions/model/ frontend/src/features/edit-clip-project/model/ frontend/src/features/edit-clip-storyline/ frontend/src/widgets/clip-workspace/

## goal
A pending clip settings or region save can only ever reach its own project, and the clip storyline saves through the same autosave machine — flushed before a paid build or request, retried on transient failure, and never discarding the owner's text on an error.

## acceptance
- [v] `region-queue.ts` and `clip-draft-queue.ts` keep senders in a `Map<projectId, sender>` and their `send` looks the sender up by the key the queue passes; `queueX(projectId, …, send)` registers that project's sender
- [v] the clip storyline gets a module-level `createAutosaveQueue` keyed by project (`features/edit-clip-storyline/model/storyline-queue.ts`), sending inside `serialClipWrite(projectId, …)`, retrying `retriableTransportFailure`, with `flushClipStoryline(projectId, failFast)` and `peekClipStoryline(projectId)` like the other queues
- [v] `ClipStorylineSpace` queues edits instead of its own timer; it replaces its draft from the server only when nothing is queued or in flight for the project, so a failed save keeps the typed text and shows the save state
- [v] the workspace's `flushAll` (before 이 스토리로 만들기) and the storyline request's flush include the storyline queue
- [v] tests: A's debounced settings save fires after B registers a sender and still saves A's draft to A; region edits of A survive editing B; a storyline save failing with a transient error retries and keeps the draft; a non-retriable failure keeps the draft and reports it; flushAll waits for a pending storyline save before the build starts
- [v] behaviour unchanged otherwise: FE suite, `pnpm lint`, `pnpm lint:fsd`, `pnpm build:web` green

## impl notes

- a sender map entry is replaced on every queue call, so it always closes over the newest mutation and transport, which is what `latest` was protecting
