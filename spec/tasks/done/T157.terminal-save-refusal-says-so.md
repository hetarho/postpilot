# T157 Say a save was refused rather than promising a retry that was abandoned
> st:done@260915 | ssot:- | base:ARCH@2 | dep:-

## goal
Tell the owner when a draft will never be saved as it stands, instead of reporting a retry the queue already gave up on.

## acceptance
- [v] the status line distinguishes a save that is being retried from one the server refused outright, and says so in ko and en
- [v] a refused save names what to fix, reaching the owner from the page rather than only from the settings panel
- [v] a retryable failure keeps today's wording and today's backoff
- [v] behaviour otherwise unchanged — the existing queue and status tests still pass
- [v] vitest covers both shapes: an `invalid_argument` refusal and an `unavailable` one, asserting the two different lines
- [v] verify FE `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- from review/clip-failure-visibility-260914 F2
- The queue already knows the difference: `terminal(error)` ([clip-draft-queue.ts:84](frontend/src/features/edit-clip-project/model/clip-draft-queue.ts#L84)) decides whether to schedule another attempt, and returns without one for an `invalid_argument`. What is lost is only that the state machine collapses both into `failed`, and `SAVE_STATUS_LABEL_KEYS.error` is the single key `state.saveRetrying` ([save-state.ts:27](frontend/src/shared/lib/save-state.ts#L27)). Split the failed state into refused and retrying, keep the existing key for retrying, and add a refused one.
- Carry the refusal itself, not just the fact of it: keep the `AppFailure` on the queue so the page can render the same `AppFailureMessage` the settings panel shows. `ClipStatus` already gives a failing save precedence on the one line and already colours it (`text-notice-danger-fg`), so the line is the right place; it is mounted by the page and outlives the settings panel (CLIP-36, CLIP-39), which is exactly why the panel's own message is not enough.
- `save-state.ts` is FE-pure and must stay react- and i18next-free (ARCH-18) — keys, not copy.
- Scope note: this task does not change which drafts are refused. T153 already fixed the refusal that exposed this; what is left is that the owner could not tell a permanent refusal from a transient one.
