# T044 The settings layer, and tags, category and visibility inside it
> st:done@260908 | ssot:PUB-37 PUB-21 PUB-22 PUB-19 | base:PUB@4 ARCH@2 | dep:T042

## goal
Open the publish settings layer as a versioned step and enter the three settings that exist only inside it, without ever letting a body mutation follow it.

## acceptance
- [v] `Apply(open_settings)` resolves `button[class^=publish_btn__]` to exactly one match, clicks its live geometry, and requires that `div[class^=layer_popup__][class*=is_show__]` then resolves to exactly one; a layer that does not appear, or two shown layers, fails closed
- [v] the `tags`, `category` and `visibility` locator counts are read inside the shown layer only, and are expected to be 0 before `open_settings` and 1 / 1 / 4 after it; `Publisher.mutate`'s pre-check for those three kinds runs against the post-`open_settings` snapshot, and a test proves each of them fails closed if attempted before it
- [v] `Apply(tags)` enters each manifest tag into `input[class^=tag_input__]` inside the shown layer and never into the `input[class^=fake_input__]` beside it; the resulting tag collection equals the manifest's order with no extra or duplicate tag
- [v] `Apply(category)` first opens the selectbox (`button[class^=selectbox_button__]`, whose `aria-expanded` must become `true`) because the category radios do not exist while it is collapsed, then selects `input[type=radio][data-testid="categoryBtn_<id>"]` for the manifest's frozen id and verifies it is checked; an id with no radio, or a name that does not match `categoryItemText_<id>`, fails closed
- [v] `Apply(visibility)` selects `input[type=radio][data-testid="openType_<n>"]` for the manifest's visibility and verifies it is checked, over the four radios the layer exposes
- [v] no body mutation is accepted after `open_settings`: the port holds a latch set when the layer opens, and a later `title`, `text`, `heading`, `quote`, `list`, `upload_image` or `image_caption` returns a `PortError` from the port itself rather than relying on `Prepare`'s ordering
- [v] the fence's full snapshot is taken with the layer open and reports the title, the exact body sequence, block/image/caption order, image count, the ordered tags, the category name and id, and visibility, each with its selected or checked state (PUB-22)
- [v] against a fake CDP editor, table-driven tests cover: the layer opening and its locator transition from 0 to 1/1/4; a tag typed into the decoy input being refused; three tags in order; a duplicate tag; a category id with no radio; a category whose name disagrees with its id; each of the four visibility values; a body mutation attempted after the layer opened; and a layer that closes again mid-sequence
- [v] ARCH-27 passes

## impl notes
- T019's `## survey` item 2 holds every verified fact: the layer is `div.layer_popup__*.is_show__*`, opened by `button[class^=publish_btn__]` (발행) and closed by `button[class^=publish_fold_btn__]` (발행 설정 닫기); the category radios exist only while `aria-expanded` is `true` (11 radios with `categoryBtn_16` checked on the owner's blog, 0 when collapsed); `categoryItemText_<id>` carries each name; visibility is `openType_{2,1,3,0}` = public / neighbor / both_neighbor / private
- the decoy `input[class^=fake_input__]` sits beside the real tag input; matching it would type a tag nowhere. Scope every settings locator to the shown layer, never to the document
- the occlusion latch is the important half of PUB-37: while the layer is open it covers the editor, so a body mutation resolved from its own geometry would click whatever the layer put over it. The survey hit exactly that — text typed after the layer opened went into the layer and was discarded
- do NOT resolve or touch `button[class^=confirm_btn__]` in this task. It is the live final control (`data-testid="seOnePublishBtn"`) and it belongs to T045
- the layer also holds `nowTimeRadioBtn` / `preTimeRadioBtn` (즉시/예약) and a `searchYn` checkbox; none is a manifest setting and none may be touched
