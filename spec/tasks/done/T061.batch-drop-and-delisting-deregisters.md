# T061 Batch variants dropped at mapping, delisting deregisters and hides
> st:done@260909 | ssot:MODEL-20 MODEL-22 MODEL-50 | base:MODEL@6 | dep:-

## goal
A successful catalog read never offers a `:batch` variant, and a curated model the source stopped offering loses every registration and leaves the operator's list in that same read.

## acceptance
- [v] `openrouter.Client.Fetch` returns no candidate whose id carries the `:batch` variant suffix; `:free` and unsuffixed ids are unchanged; the drop is not counted in the "skipped unusable" warning
- [v] `Store.RefreshAvailability` deletes every `catalog_model_purposes` row of a model left `listed = 0` and stamps its `updated_at`, in the same transaction as the unlist/mark-seen pair; the `catalog_models` row is untouched (the per-purpose effort is a registration column and goes with it, →MODEL-7)
- [v] `Service.Browse` omits curated rows with `listed = 0` from `Entries`, on a live read and on the degraded (fetch failed / cached) path alike; a row that comes back into the source is offered again as an unregistered candidate carrying its stored effort
- [v] the registry view (`setCache`) shows no delisted model because it has no registrations — `Models()` / `Lookup` return nothing for it after the read
- [v] `ListCatalog` still carries `listed` in the proto (unchanged contract, always true for what is now sent); no proto or migration change
- [v] tests: `openrouter/client_test.go` — a `:batch` entry is dropped and its unsuffixed twin kept; `store/store_test.go` — RefreshAvailability with a registered row absent from `seen` leaves the row, no purposes, no effort, `listed = 0`, `updated_at` stamped; `service_test.go` — Browse hides a `listed = 0` row on the live and the degraded path, and a re-seen row reappears unregistered; the existing `TestBrowse_MergesLiveCatalogWithCuratedRows` expectation for the "curated but unoffered" entry is replaced, not deleted
- [v] verify BE (ARCH-26) and the sqlc gate (ARCH-28: `pnpm gen:sql && git diff --exit-code -- backend`) are green

## impl notes
- MODEL-50: filter in `openrouter/client.go get()` before `toCandidate`, on the id's variant suffix (`strings.Cut(id, ":")` → suffix `== "batch"`); a separate counter logged once at debug level, not the `skipped` warning ← that warning means "upstream shape changed", this is expected on every read (72 of 502 on 2026-09-09)
- MODEL-20: add a sqlc query `DeregisterUnlistedCatalogModels :exec` — `DELETE FROM catalog_model_purposes WHERE model_id IN (SELECT model_id FROM catalog_models WHERE listed = 0)` — plus an `UPDATE catalog_models SET updated_at = ? WHERE listed = 0 AND EXISTS (...)` stamp (or stamp the affected ids read back before the delete); call both after the mark-seen loop inside `RefreshAvailability`'s transaction so a reader never sees a hidden-but-registered row
- an already-curated `:batch` row (none in prod on 2026-09-09) needs no migration: it is absent from `seen` on the next successful read and falls under the same deregister-and-hide path
- Browse: in the "curated but unoffered" loop skip `!row.Listed`; the pre-existing `curated` map / `EntryOf` path stays for rows the source offers but the operator curated (unchanged), so the only rows the loop still emits are `listed = 1` rows the snapshot lacks — which cannot happen after a live read, and on the degraded path means "the stored rows"
- `SetPurpose` is left as is: the UI can no longer reach a delisted row, and a registration written from a stale tab in the window between two reads is cleared by the next successful read (MODEL-20's rule, not a new refusal)
- `llm.SourceModel.Delisted` and the `priceable` check on `Listed` (estimator combos) stay ← a combo may still name a delisted model; that surface is QUOTA's and unchanged here
- update the comment on `Store.DeregisterPurpose` / `RefreshAvailability` in `ports.go` and the plan-18 "never retired" comments in `service.go` to the r4 rule — the code's prose must not contradict the SSOT
