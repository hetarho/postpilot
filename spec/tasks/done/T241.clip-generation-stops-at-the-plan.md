# T241 a generation stops at the validated plan and renders nothing
> st:done@260918 | ssot:CLIP-151 CLIP-56 CLIP-152 CLIP-26 CLIP-93 CLIP-97 CLIP-132 | base:CLIP@37 | dep:-

## goal
A clip generation succeeds with a validated plan and no result file, and a project holding a plan with no render is a normal state everywhere that reads one.

## acceptance
- [v] a generation job ends after the plan is validated and saved; no media execution runs and no result is written
- [v] the attempt settles as a successful generation under QUOTA-46 with its notices, exactly as a rendering generation did
- [v] a project with a plan and no result opens ② and is presented as a plan to review, never as a missing or failed result
- [v] an existing project keeps its stored result and its revision unchanged
- [v] a revision request already stops at the plan; its path is unchanged by this task
- [v] go test: a generation completes with `editing.plan` set and `result` empty; the previous result of a regenerated project survives; the job's terminal state is success
- [v] vitest: ② mounted on a project with a plan and no result shows the draft preview and no result-missing failure
- [v] verify: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...` (`-timeout 30m` for `clip/store`) · `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- the generate worker's stages end at the saved, validated plan; the execute stage moves to the ALREADY EXISTING render path — `job.KindRenderClip` and the `StartClipRender` RPC, cancellation and sweep included — which T242 only adds the kind to, so this task REMOVES a stage rather than adding a branch
- `internal/job/worker.go`'s generate_clip case and the clip service's post-plan steps are where the cut lands; keep the recovery-plan save, the notice recomputation and the retention renewal
- the quote and the reservation are unchanged: the render is credit-free either way (CLIP-20), so nothing about the ceiling moves
- `clip/store` tests run ~759 s, past `go test`'s default; run that package with `-timeout 30m` rather than reading the default timeout as a failure
- FE: every place that treats "no result" as a failure state — the step router's `ClipStepWaiting`, the download and the finalization refusals — reads it as the first state instead; the copy for it belongs to T246 and this task only stops the false failure

## result
- backend: `clip/generation.go` ends the attempt on the validated, laid-out plan — the render stage, the result upload and the `Result` it built are gone, and `finisher.Complete` is called with the plan alone. `clip/store/queries/generation.sql` adds `SaveGeneratedPlan` (analysis + plan + `edit_plan_revision`+1, leaving `result_*`, `result_id` and `rendered_plan_revision` alone) with its store method in `clip/store/generation.go`; `ApplyAttemptResult` routes a result-less completion to it. `cmd/api/clip_finisher.go` skips the staging row for such a completion (the table's result columns are NOT NULL and there is no file to sweep), applies the plan inside the job's own terminal transaction, and reads "already committed" off the saved plan instead of the result key.
- frontend: no surface change was needed — `clipState` already reads `editPlanRevision > 0` as ②, `editing` needs only a saved plan, and the status line already says 다시 출력 필요 through `renderedPlanRevision`. The `generation.stage.save` copy dropped its "result" (결과 저장 → 저장 중 / Save result → Saving), since a generation's save is now the plan's.
- tests: `TestGenerationSucceedsWithAPlanAndNoResult` pins the plan-only success, the surviving previous result and the stale `rendered_plan_revision`; `ClipLifecycle.test.tsx` pins ② on a plan with no result. 17 store tests assumed a rendering generation and were re-pointed at the render job: a new `h.startRender`/`h.render` harness pair renders the saved plan where a stored result is the premise, and the tests that injected `renderer.fail` to interrupt an attempt now inject `media.cleanupErr`, which fails the attempt after its candidate plan is durable — the same interruption CLIP-93 resumes from.
- SSOT-adjacent notes, no divergence: (1) `ownedPlanRenderer`'s refinement moved from `Render` to `LayoutComposition`, because the plan the executor shapes now has to be shaped before any render; production's `media.Rendering` already layouts there, and `RenderedVideo.Plan` was never adopted by the render job. (2) a legacy project's frozen composition is now frozen by the generation rather than inside `Render`; both freezes take the same `HideDisclosure`/facts, so the executed document is unchanged, and `TestDisclosureChoiceReachesApprovedGeneration` asserts on that document instead of on a plan field the composition path never reads.
- ARCH-37: not run. The media packages, the render admission and `rerender.go` are untouched — this task removes a call site from the generation and adds no media behavior.
