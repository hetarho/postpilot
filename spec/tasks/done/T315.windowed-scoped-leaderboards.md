# T315 Leaderboards keyed by scope, stage and window
> st:done@260922 | ssot:MODEL-38 MODEL-41 MODEL-44 LANG-18 ARCH-3 ARCH-6 ARCH-10 ARCH-16 ARCH-21 ARCH-24 | base:MODEL@14 LANG@5 ARCH@7 | dep:-

## goal
- Replace the all-time private leaderboard with boards keyed by `(scope, stage, window)`: 일간·주간·월간 rolling windows, `me` or `all` scope, chosen in the URL with 주간 · 나 as the default.

## acceptance
- [v] GetLeaderboard takes `window` (day/week/month) and `scope` (me/all); unspecified values resolve to week/me; the Elo replay uses only winner verdicts whose `decided_at` lies in `[now − window, now]`, in decision order from 1500 with K 32; the provisional threshold stays 3.
- [v] `all` aggregates every account's verdicts and returns only per-model rating, matches, wins, losses, win rate, call metrics and flags; nothing in the response names an account, experiment, output or note; `me` stays scoped from the authenticated account; no request carries an account id.
- [v] Call metrics (calls, latency, tokens, cost) come from the experiments decided or dismissed inside the same window and scope; a deleted account's rows leave `all` through the existing cascade.
- [v] No RPC path returns an all-time board.
- [v] `/ai-models/leaderboard` carries `stage`, `window` and `scope` in the URL (defaults 주간 · 나 when absent or invalid); changing any one keeps the other two; reload, back/forward and links restore all three; the stage tabs preserve window and scope.
- [v] The page shows window and scope switches as `SegmentedControl`s (일간·주간·월간 / 나·전체), a heading and description naming the scope and the window's span (최근 24시간 / 7일 / 30일), and a window-specific empty state; loading/error states are unchanged; ko/en.
- [v] Every cached leaderboard, whatever its window or scope, is invalidated after a verdict; the RPC test helper records window and scope.
- [v] Tests: BE domain (window boundary, order kept), store (`me` vs `all`, since filter, metrics window, two target languages share one board), handler (defaults, no account fields); FE (search defaults/validation, switch navigation, stage tabs keep window/scope, query inputs, heading/empty copy); ARCH-25/26/28 gates pass.

## impl notes
- Proto: `enum LeaderboardWindow { LEADERBOARD_WINDOW_UNSPECIFIED = 0; LEADERBOARD_WINDOW_DAY = 1; LEADERBOARD_WINDOW_WEEK = 2; LEADERBOARD_WINDOW_MONTH = 3; }`, `enum LeaderboardScope { LEADERBOARD_SCOPE_UNSPECIFIED = 0; LEADERBOARD_SCOPE_ME = 1; LEADERBOARD_SCOPE_ALL = 2; }`; `GetLeaderboardRequest { Stage stage = 1; LeaderboardWindow window = 2; LeaderboardScope scope = 3; }`. Defaults resolve in the handler (`week`, `me`) so an explicit client and an old one agree. `pnpm gen:proto`.
- Domain: `Window` and `Scope` types in `experiment/types.go`; window lengths are code-owned constants in `experiment/config.go` (`LeaderboardWindowDay = 24h`, `Week = 168h`, `Month = 720h`), not env (MODEL constraints). `Service.Leaderboard(ctx, userID, stage, window, scope)` computes `since = s.now().Add(-length)`.
- Port: `OutcomeLedger.LeaderboardData(ctx, userID string, stage Stage, since time.Time, scope Scope)`. Queries: `ListDecidedForLeaderboard` / `ListCandidatesForLeaderboard` gain `AND e.decided_at >= ?` and the candidates query restricts to `e.status IN ('decided','dismissed')`; `all` variants (`ListDecidedForLeaderboardAll`, `ListCandidatesForLeaderboardAll`) drop the `user_id` predicate. `decided_at` is stored as text through the store's `nullTime` formatting (RFC 3339 UTC), so pass `since` through the same formatter for a lexicographically safe comparison. Query files stay ASCII-only; `pnpm gen:sql`.
- Migration (next free number): `CREATE INDEX model_experiments_stage_decided ON model_experiments(stage, decided_at) WHERE decided_at IS NOT NULL` for the `all` scan.
- `BuildLeaderboard` is unchanged; `Active` / `Recommended` / `Disappeared` stay the viewer's own flags in both scopes.
- FE: `pages/ai-models/model/search.ts` validates `window: 'day' | 'week' | 'month'` and `scope: 'me' | 'all'` (undefined when invalid); a sibling of `useModelStage` returns the resolved filters with defaults `week` / `me`; `ModelStageTabs` and the two new switches navigate with `search: (prev) => ({ ...prev, <changed key> })`. `useLeaderboard(stage, window, scope)`; `leaderboardQueryKey` takes window and scope, and a `leaderboardQueriesKey(transport)` (no input) replaces the per-stage invalidation in `useExperimentActions.refresh`. Name↔enum mirrors (`LeaderboardWindowName`, `LeaderboardScopeName`) live in `entities/model-experiment/api/experiment-mappers.ts` beside the existing stage mirror.
- Copy: `pages/ai-models/config/i18n.ts` — `page.myLeaderboard` splits into `page.leaderboardMe` '내 {{stage}} 리더보드' / `page.leaderboardAll` '전체 {{stage}} 리더보드', `page.leaderboardDescription` names the scope; `widgets/model-leaderboard/config/i18n.ts` — `leaderboard.window.day` '최근 24시간' · `week` '최근 7일' · `month` '최근 30일', switch labels 일간·주간·월간 / 나·전체 (en Daily·Weekly·Monthly / Me·Everyone), empty state '이 기간에는 비교 결과가 없어요.' / 'No comparison results in this period.'
- LANG-18 is consumed here: the key is `(scope, stage, window)` and target language partitions nothing — the store test asserts two targets share one board.
- `test/experiments.ts`: `getLeaderboard` records `{ stage, window, scope }`.

## result
- Proto: `LeaderboardWindow` and `LeaderboardScope` on `GetLeaderboardRequest`. Both resolve their defaults in the handler, so a client that states nothing and one that states week/me ask for the same board.
- Domain: `Window` and `Scope` with parsers that refuse anything outside the vocabulary; the three lengths are code-owned constants in `experiment/config.go`, not env, because they are the product's own vocabulary and changing one would silently rewrite what every rating means. `Service.Leaderboard` measures the window at the moment of the request.
- Store: `LeaderboardData` takes `since` and a scope; the four queries are the per-account and all-account halves of the verdict list and the call accounting. `decided_at` is compared as text through the same fixed-width UTC formatter that writes it. Migration 0074 adds `model_experiments_stage_decided` for the all-account scan.
- The call accounting is now restricted to comparisons that were resolved, so one still awaiting its verdict contributes nothing to a board.
- Frontend: `window` and `scope` join `stage` in the model group's search schema, each dropped rather than corrected when unreadable. `useLeaderboardFilters` supplies 주간 · 나. The stage tabs and the two new switches all navigate with a search updater, so changing one filter keeps the other two. The heading names the scope, a line under it names the span, and the empty state names the period that produced nothing.
- `leaderboardQueryKey(transport, stage)` became `leaderboardQueriesKey(transport)`: a verdict lands in its own window and in every wider one, on the account's board and on the shared one, so all of them go stale at once.
- LANG-18 is consumed: the key is `(scope, stage, window)` and a store test asserts two comparisons frozen to different targets share one board.
- Validation on Linux, Go 1.26.4, Node 24.18.0: every backend package passes on its own, including the migration package (166s) and `internal/clip/store` (828s, past Go's default 10-minute package limit). Frontend `tsc -b`, `pnpm lint`, `lint:fsd`, `lint:style` and `build:web` pass, as do the model, leaderboard and experiment suites.
- Run all at once the backend reports migration-rollback failures and `internal/clip/store` times out; run alone each passes. The same is true of the clip and plans frontend files. Both are load, not this work.
- This task and T316 were implemented in the same session and share every backend file they touch, so they are committed together rather than as two commits that would not compile apart. The overlap is stated in the commit message.
