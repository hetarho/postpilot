## goal
A shared `FloatingActionMenu` primitive gives channels THEME-67's one-button menu: a closed extended button in the list add-action dock that opens a scrim and grouped link menu above itself.

## acceptance
- [v] `frontend/src/shared/ui/floating-action-menu/FloatingActionMenu.tsx` is exported from `@/shared/ui`; closed, it renders one extended button (plus icon + `label`) with `aria-haspopup="menu"` and `aria-expanded="false"` inside `ActionBar dock="list"`
- [v] open: a scrim covers the page, the same button shows × with `closeLabel` as its accessible name and `aria-expanded="true"`, and the groups stand above it in the given order, the last group nearest the button; each group is one raised menu surface (`role="menu"` named by `menuLabel`), each item a `role="menuitem"` link with an icon and a label at the 44 px pointer floor
- [v] the × button, a scrim click, Escape and choosing an item close the menu; focus moves to the first item on open and back to the button on close; ↑/↓ move across items of every group, Home/End jump to the first/last
- [v] items render through the `NavigationContext` Link (plain `<a>` fallback) and an item's `onSelect` runs before its navigation
- [v] movement uses `motion-safe:` only; colours, scrim, surface and shadow use semantic tokens in both themes; `pnpm lint:style` passes
- [v] `FloatingActionMenu.test.tsx`: closed attributes; open renders groups in order with focus on the first item; Escape, scrim, × and item selection each close and restore focus; arrow/Home/End cross groups; `onSelect` called on item activation

## impl notes
- API: `FloatingActionMenu({ label, closeLabel, menuLabel, groups })`, `groups: readonly (readonly FloatingActionItem[])[]`, `FloatingActionItem = { id: string; label: string; icon: ComponentType<{ className?: string }>; href: string; onSelect?: () => void }`. Links, not buttons: every item is an address (new tabs and modifier-clicks work).
- Key handling follows `shared/ui/action-menu/ActionMenu.tsx` (WAI-APG menu button: trigger is the only tab stop, rows take programmatic focus), but there is no phone bottom sheet: THEME-67 stands the menu above the button at every width.
- Placement: the root is `ActionBar dock="list"` (THEME-24 list dock: sticky lower band, right-aligned, no plane, the control on its own shadow). The menu is absolutely positioned `bottom-full right-0` with a gap above the button and takes its content width; groups are separated by the same gap.
- Scrim: reuse the backdrop token/classes `shared/ui/sheet/Sheet.tsx` uses for its overlay so both overlays dim alike; the scrim and the open menu sit above page content and the sticky header (the header's z-30), the button stays above the scrim so × remains reachable.
- No numbers to configure; sizes come from existing spacing/button tokens.
- Icons are passed in by the consumer (lucide components); the primitive owns only the plus and × glyphs.

## result

Items are links through the NavigationContext Link; `NavigationLinkProps` now passes anchor attributes through and `AuthenticatedLayout`'s NavigationLink runs a supplied onClick before routing.
