# T346 ② shows this post's own M2, M3 and M4 above the article
> st:done@260924 | ssot:POST-83 POST-85 QUAL-3 QUAL-6 QUAL-12 QUAL-19 QUAL-27 QUAL-36 QUAL-37 QUAL-40 ARCH-3 ARCH-13 ARCH-16 ARCH-17 ARCH-18 ARCH-24 THEME-29 | base:POST@11 QUAL@3 ARCH@9 THEME@17 | dep:T335 T343

## goal
- A new `entities/quality` over QualityService puts one measurement row above ②'s article. It shows the current revision's own M2, M3 and M4 against the server's bands whether or not one is crossed, never shows an absent value as zero, names M2's minimum while the account is under it, is hidden on a published post, and refreshes after content saves, URL saves and deletes.

## acceptance
- [v] On ② of a post with content that is not published, one section headed 이 글의 측정값 sits directly above the article. It holds exactly three groups, 글 간 고정 문구 (M2), 글 안 반복과 제목 관련성 (M3) and 분량·구성 (M4), stacked on a phone and in three columns from `sm:`. There is no M1 and no composite score (QUAL-27, QUAL-36).
- [v] The values are M2's fixed-phrase share; M3's repetition share and title relevance; and M4's character count, photo count, distinct block types and average sentence length. The sentence length is in characters for Korean and in words for English, following `contentLanguage`, and a post with none reads as Korean (QUAL-26).
- [v] Each banded value (M2 share, both M3 values, M4 distinct block types) shows the band edge the server sent beside it. M4's other three values are context lines with no band (QUAL-10).
- [v] A metric whose verdict is `over_band` carries a `Badge` `tone="warning"` reading 주의, and one whose verdict is `within_band` carries `tone="success"` reading 양호. Colour is never the only signal. Numbers show whether or not a band is crossed (QUAL-37).
- [v] A value the server left unset reads 측정할 수 없어요, and a metric whose verdict is `absent` carries no badge. A stored `0` renders as 0 (for example `0%`) and is never read as absent (QUAL-40).
- [v] An M2 reading with verdict `below_minimum` replaces its value line with the minimum line: '발행한 글이 {{minimum}}편 이상이면 비교해요. 지금은 {{count}}편이에요.' The copy comes from one helper, which T349's brief reuses verbatim (QUAL-12, QUAL-36).
- [v] One line under the groups says the badge thresholds are PostPilot's own (QUAL-6). No copy promises exposure, and none implies that a Naver post was read (QUAL-19).
- [v] While loading, the section says 측정하는 중이에요. On failure it says 측정값을 불러오지 못했어요 with a 다시 시도 button. It never renders nothing.
- [v] The row is absent on an empty ② (no content) and on a published post (R39, POST-86).
- [v] The measurement is read per content revision. A block save, a generation or an applied result moves the revision, and the row refetches. After a `useSavePostContent` success, a `useSavePublishedUrl` success (paste, replace or clear) and a `useDeletePost` success, every cached quality query is invalidated (QUAL-3, POST-85, R15).
- [v] Only `shared/api` and `entities/quality/api` name QualityService or its schemas (ARCH-17), and `entities/quality/model` imports no React (ARCH-18).
- [v] Tests:
  - new `entities/quality/api/quality-mappers.test.ts`, in the `entities/model-experiment/api/verdict-badges.test.ts` shape:

  - `entities/post/api/useSavePublishedUrl.test.tsx` (T343's): new 'marks every quality query stale after a paste, a replace and a clear'.

## impl notes
- Wire, from T322 (`quality.proto`):
  - `GetPostMeasurementResponse { content_revision; repeated QualityReading readings }` carries M2, M3 and M4, in that order.
  - `QualityReading { metric; verdict; minimum; published_count; rule_text; oneof values }`, whose oneof holds `QualityCrossPostPhrases { optional share; share_warn_above }`, `QualityInPostRepetition { optional repetition_share; optional title_relevance; repetition_share_warn_above; title_relevance_warn_below }` and `QualityComposition { optional char_count; optional photo_count; optional distinct_block_types; optional average_sentence_length; distinct_block_types_warn_at_or_below }`.
  - Shares are fractions in [0,1], and every value is an optional double.
  - T335 serves it, and an unknown or foreign slug answers `POST_NOT_FOUND`.
- `shared/api/index.ts` re-exports from `./gen/postpilot/v1/quality_pb`:
  - `QualityService`;
  - `QualityMetric as ProtoQualityMetric` and `QualityVerdict as ProtoQualityVerdict`;
  - `GetPostMeasurementResponseSchema`, `GetAccountQualityResponseSchema`, `QualityReadingSchema`, `QualityTitleSaturationSchema`, `QualityCrossPostPhrasesSchema`, `QualityInPostRepetitionSchema` and `QualityCompositionSchema`;
  - the types `QualityReading as ProtoQualityReading`, `GetPostMeasurementResponse as ProtoPostMeasurement` and `GetAccountQualityResponse as ProtoAccountQuality`.
  - T349 needs no further `shared/api` edit.
- New slice `entities/quality`. It depends on no other entity, so `entities/post` → `entities/quality/@x/post` creates no cycle.
- `model/types.ts` (React-free):
  - `type QualityMetricId = 'title_saturation' | 'cross_post_phrases' | 'in_post_repetition' | 'composition'`, which are R3's ASCII ids.
  - `QUALITY_METRICS` holds them in R3 order, `as const`.
  - `type QualityVerdict = 'over_band' | 'within_band' | 'below_minimum' | 'absent'`.
  - `type QualityValues` is a union discriminated by `metric`, one member per value message, with each optional double as `number | undefined` and each band edge as `number`.
  - `interface QualityReading { metric; verdict; minimum: number; publishedCount: number; ruleText: string; values: QualityValues | undefined }`.
  - `interface PostMeasurement { contentRevision: bigint; readings: QualityReading[] }`.
- `model/format.ts` is React-free and uses `i18next.t`, the `entities/post/model/types.ts` `postStatusLabel` precedent. It is shared with T349.
  - `qualityMetricName(id)`.
  - `formatShare(value)` is `formatPercent` from `shared/lib`.
  - `formatMeasure(value)` is `formatNumber` with `maximumFractionDigits: 1`.
  - `belowMinimumLine(minimum, publishedCount)`.
  - `bandsAreOwnLine()`.
  - `absentValueLabel()` returns 측정할 수 없어요.
- `api/quality-mappers.ts` follows the `shared/api/language.ts` shape:
  - `qualityMetricFromProto(value): QualityMetricId | undefined` and `requireQualityMetric(value)`, which throws `Error('unsupported quality metric enum: …')`;
  - `qualityMetricToProto(id)` over a `Record<QualityMetricId, ProtoQualityMetric>` with the reverse `Map`;
  - the same three for the verdict;
  - `toQualityReading(reading)`, which switches on `reading.values.case` over the four generated cases plus `undefined` and throws when the case is not the one `metric` names;
  - `toPostMeasurement(response)`.
  - There is no `default` branch that yields a value (ARCH-3). An unknown enum fails the query, and the row shows its error state.
- Keys live in `api/quality-queries.ts`. They follow the per-account `[noun, transport, ownerId]` convention (`memoriesQueryKey`, `clipProjectsKey`); the plan's "accountId" is this repo's `ownerId`.
  - `qualityQueriesKey(transport, ownerId) = ['quality', transport, ownerId] as const`.
  - `postMeasurementQueryKey(transport, ownerId, slug, revision) = [...qualityQueriesKey(transport, ownerId), 'measurement', slug, String(revision)]`.
  - The revision is a string because a bigint breaks the JSON key hash.
  - Keying by revision is what makes a generation result, which calls no content-save hook, refetch too (QUAL-3).
- `api/usePostMeasurement.ts`, in the `useMemories` shape:
  - `usePostMeasurement(ownerId, slug, revision)` runs `useQuery({ queryKey, queryFn: () => createClient(QualityService, transport).getPostMeasurement({ slug }).then(toPostMeasurement), enabled: ownerId !== '' && slug !== '', placeholderData: keepPreviousData })`.
  - It returns `{ measurement, isPending, isError, isFetching, refetch }`.
  - `keepPreviousData` holds the last row while the next revision loads, so an autosave does not flash the row back to its loading text.
- `api/quality-cache.ts`: `invalidateQuality(queryClient, transport): Promise<void>` invalidates `{ queryKey: ['quality', transport] }`. The prefix covers every owner and slug, because the three post hooks hold no ownerId, and a stale neighbour costs one refetch.
- `@x/post.ts` exports `invalidateQuality` (the `entities/post/@x/model-experiment.ts` precedent).
- `index.ts` exports:
  - the model types and `QUALITY_METRICS`;
  - the `format.ts` helpers;
  - `usePostMeasurement`;
  - `PostMeasurementRow`.
- `entities/post` calls `void invalidateQuality(queryClient, transport)` in three `onSuccess` handlers: `api/useSavePostContent.ts`, `api/useDeletePost.ts` and T343's `api/useSavePublishedUrl.ts`.
- `ui/PostMeasurementRow.tsx`:

  - It renders `<section aria-labelledby>` with a `Typography variant="label" as="h3"` heading and a `<dl className="mt-2 grid grid-cols-1 gap-4 sm:grid-cols-3">`, one `<div>` per reading in response order.
  - Each group has a `<dt>` holding the name and the verdict `Badge`, then `<dd>` lines of the form `<name of value> <value> · 기준 <edge> 이하|이상|초과`.

  - The bands line and the loading and error lines are `Typography variant="meta"` with `text-content-secondary`. Retry is `Button variant="ghost"` running `refetch`, with the `action.retry` label from the `common` namespace.
- `entities/quality/config/i18n.ts`, posts namespace, key `quality` (free). ko is given below; en carries the same keys.

The block-save case also asserts a reading cached for the new revision, and the placement case uses an English-content post counted in words.
  - The full FE suite (304 files, 2546 tests) and every FE gate pass.
- Behaviour notes:
  - The row shows a reading whenever it has one, and the failure line only when nothing has been read. A failed background refetch therefore keeps the last reading.
  - `formatShare` gives one fraction digit, where `formatPercent` defaults to a whole percent. Otherwise a share just past its edge (8.4% against 8%) would print as the edge itself beside 주의.
  - A reading of M1, which a post measurement never carries, is filtered out rather than drawn.
  - The slice index also exports the two `ToProto` mappers, which the test fake builds its readings with.
- Mutation check: 45 mutations over the mappers, the keys, the hook, the cache helper, the format helpers, the row, the three post hooks and the mount.
  - Before the run I closed four gaps in the tests:
    - the verdict names, since a swapped pair round-trips;
    - the revision in the key and the kept previous reading, which a content save would refetch anyway through the invalidation;
    - the key's place under the invalidation prefix;
    - the mount's revision and content language.
  - One mutation survives and is equivalent: the `!isPublished` guard at the mount, which the notes asked for. The editor branch never renders for a published post.
  - All others are caught.
- No SSOT deviation.
