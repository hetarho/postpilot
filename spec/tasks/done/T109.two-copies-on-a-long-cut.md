# T109 Two sequential copies on a long cut
> st:done@260912.trs | ssot:CDS-43 CDS-41 CDS-45 CDS-52 CLIP-17 ARCH-24 | base:CDS@1 CLIP@6 ARCH@2 | dep:T108

## goal
Let a cut of four seconds or more carry a descriptive copy followed by a numeric one, never both at once, in the compiler and in the correction step.

## acceptance
- [v] `clip.Cut.Copies []Caption` (1 or 2) replaces the single `Copy` in the domain and JSON with a read-time upgrade of legacy single-copy plans; the proto `ClipEditCut.copies` (repeated, 10) is added and `copy` (6) is kept populated with the first copy for one release
- [v] validation: a second copy only when the cut is ≥ 4000 ms, the first is `DESC` and the second `NUM` (T105's classifier), the windows are disjoint with a 120 ms gap, each meets its own exposure minimum, and the style guards count both
- [v] the compiler produces a second copy only when the model's `short_text` or a `NUM` clause of the caption can stand alone as ≤ 16 characters; otherwise one copy as today
- [v] `Layout`, the verifier (V4 for both, V7 across both windows) and the overlay chain handle two plates per cut; the manifest lists both
- [v] step ②: a 자막 추가 control on a cut ≥ 4 s adds the second copy with its own fields and window, and the validator mirrors the rules; ko/en copy
- [v] tests: legacy upgrade · every rule of the second copy · a plan with two copies through `Layout` and `Verify` · FE add/remove and window disjointness
- [v] ARCH-26, ARCH-28 and ARCH-25 pass

## impl notes
- a list with the single-copy case as length 1 is simpler than a nullable second field and keeps the overlay chain uniform; the legacy `copy` field is mirrored so a stale client still sees the first copy
- the compiler never asks the model for a second sentence; it splits what it already has, which keeps the credit plan unchanged

Three readings recorded rather than decided quietly:

1. **A `NUM` clause of the caption can almost never be the second copy.** CDS-39 reads a number FIRST, so any sentence stating one is classified `NUM` and is therefore never the `DESC` first copy CDS-43 splits. In practice the second copy is the `short_text` the model wrote beside the description. The clause walk is implemented as the acceptance asks and answers for a sentence the classifier reads as a description anyway — but it is not the path that fires.
2. **V4's "≥ 60 % of the cut" is not enforced, and cannot be as written.** The minimum exposure IS checked for every copy (`plan_copy_exposure`). The occupancy half needs the cut's own length, which the manifest does not carry — and it contradicts CDS-45 outright: the render smoke's own last cut ends its copy at 2400 ms of 5200 (44 %) precisely so nothing shows under the ending card. **update-ssot CDS**: either say the occupancy is of the cut MINUS the card windows, or drop it for a cut that carries a card or two copies (two copies can never each occupy 60 %).
3. **CDS-40's guards now count copies, not cuts.** A cut carrying two copies contributes two entries to the 크게 강조 count and to the run, and CDS-38's one-step walk goes from a cut's second copy to the next cut's first. That is the only reading that keeps V13 and V14 meaningful when a cut can show two sentences, and it is what both the verifier and the FE mirror do.

Also worth knowing:
- **A plan stored before this deploy reads back as the one copy it was.** `EncodeEditPlan` writes version 3; versions 0, 1 and 2 are decoded through typed legacy structs rather than a token rewrite, because a caption's own text may contain a brace and a rewrite could not tell them apart.
- `ClipEditCut.copy` (6) stays populated with the first copy for one release, and the FE reads `copies` when the server sends them and falls back to `copy` when it does not — so neither side has to deploy first.
- The release-smoke fixtures were two contracts behind T108, not T109: its default plan was ONE 15 s take and its multi-source plan had a 1000 ms cut, both of which CDS-37 now refuses. Both are migrated here (three contiguous 5 s cuts of the one source, so the speech comparison still maps one-to-one).
- The manifest element carries the copy it belongs to, so two captions of one cut are two elements to V7 and two slots to V13/V14. Their windows never meet, so V7 never compares them — but it would if a plan ever put them together.
