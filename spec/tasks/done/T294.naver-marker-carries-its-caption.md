# T294 the Naver photo marker carries its caption as one double-clickable token
> st:done@260921 | ssot:EXPORT-5 EXPORT-4 EXPORT-9 EXPORT-24 ARCH-24 | base:EXPORT@4 | dep:-

## goal
Fold each photo's caption into its Naver marker so one double-click selects the whole marker.

## acceptance
- [v] `toNaver` emits `사진_<n>_<folded caption>_사진` (`photo_<n>_<folded caption>_photo` for English content), the number still counted from 1 in marker order
- [v] the fold turns every run of whitespace, punctuation and symbols inside the caption into one `_`, with no leading or trailing `_`, and keeps every other character as written
- [v] a block with no caption — or one whose caption folds to nothing — emits the bare `사진_<n>_사진`, byte-identical to today
- [v] the marker carries no filename, and an `IMAGE` block with an empty `file` still spends its number
- [v] video markers, the Tistory, site and Markdown outputs and `naverPhotoOrder` are all unchanged (their snapshots do not move)
- [v] an unfilled template slot still renders bracketed and is still unreadable as a photo marker (EXPORT-4)
- [v] the Naver tab's guidance names the new marker shape and still says the captions are not pasted with the body; the caption's own copy control is untouched (EXPORT-24)
- [v] vitest covers the fold table (spaces, punctuation, symbols, a caption that folds to nothing, a caption already snake-cased), the captionless bare form, the numbering with a caption present, and the English marker
- [v] ARCH-25 passes

## impl notes
- the fold is a local helper in `features/export-naver/model/convert.ts`; nothing else needs it and `shared/lib` is for what two slices share (ARCH-14)
- the rule is one regex over Unicode classes: `value.trim().replace(/[\s\p{P}\p{S}]+/gu, '_')` then strip leading/trailing `_`. `\p{P}\p{S}` is what makes `맥북(M4)` fold to `맥북_M4` — and it is why an emoji-only caption folds to nothing and falls back to the bare marker
- `\p{...}` needs the `u` flag; the FE targets modern browsers only (ARCH-12's Vite build), so no polyfill and no allowlist of punctuation characters
- do NOT touch `naverPhotoOrder`: the strip pairs by POSITION, and the caption changes no position
- the marker is still one line and still replaced whole by the photo — the caption in it is a label, not body text, which is why EXPORT-24's caption copy stays exactly as it is
- the tests currently match markers with `/사진_\d+_사진/`; that pattern no longer matches a captioned marker, so update every one of them to `/사진_\d+_.*?사진/` or an explicit expected string rather than loosening the assertion
- both Naver goldens (`convert.test.ts.snap`) move; regenerate them and check the diff is only the two photo marker lines
- the i18n guidance strings live in `widgets/export-panel/config/i18n.ts` (`guidance.naverPhotos`, ko and en) and `ExportPanel.test.tsx` asserts the Korean one verbatim

## result
- `features/export-naver/model/convert.ts`: two local helpers — `photoMarker` builds `<word>_<n>_<folded>_<word>` and falls back to the bare `<word>_<n>_<word>` when the fold is empty, and `foldCaption` is `trim()` → `replace(/[\s\p{P}\p{S}]+/gu, '_')` → strip the edge underscores. The counter was renamed `markerNumber` so the helper could keep the name that says what it builds.
- `naverPhotoOrder`, the video markers and the other three converters are untouched; both Naver snapshots moved by exactly the two photo-marker lines (`사진_1_사진` → `사진_1_비_뒤의_바다_사진`).
- tests: a fold table (spaces, parentheses, a comma with a double space, leading/trailing blanks, an already-snake-cased caption, an emoji-only caption and an empty one), the captionless bare form, the English marker carrying the same folded caption, the numbering read through a caption-tolerant pattern, and the empty-file hole now asserting that the captioned photo moved from 1 to 2. Every `/사진_\d+_사진/` matcher was replaced with an explicit string or a caption-tolerant pattern rather than a looser one.
- the panel's Naver guidance (ko and en) names the new shape, says a double-click selects the whole marker, and says the marker goes with the photo so the caption still needs its own copy; `ExportPanel.test.tsx` asserts the Korean line verbatim and its preview check now refuses any `사진_<n>_` text.
- ARCH-25 green: 2239 vitest tests in 286 files, `pnpm lint`, `lint:fsd`, `lint:style`, `build:web`. No backend, proto or sql file changed, so ARCH-26/27/28 are unaffected.
- No SSOT deviation. EXPORT-24 needed no code change: the caption copy control is exactly as it was.
