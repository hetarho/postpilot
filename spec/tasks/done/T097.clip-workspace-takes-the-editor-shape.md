## impl notes
- `clipState` lives in the ENTITY, not in `pages/clip`, because `/clips` needs the same vocabulary for its badge (T100) and a page-local copy would let the badge and the status line disagree; it uses `i18next.t` directly the way `entities/model-catalog`'s `levelPrefix` does, which ARCH-18 permits (that rule bars react, not i18next)
- `editPlanRevision === 0` IS "no `editing` state": the server rejects `revision <= 0` everywhere (`clip/rerender.go`, `clip/store/correction.go`) and only a successful generation writes the first plan. That matters because `ClipProject.editing` is detail-only by the proto's own comment, so the list can derive the identical state from the revisions and the result
- the status precedence puts a failing save above the running job for the same reason POST-45 does: a clip generation lasts minutes and this screen has no save button, so a save that is losing the user's answers must not sit behind a stage label for all of them
- the progress-bar box is taken verbatim from `EditorProgressBar` rather than re-derived. It paints out of flow, so the sticky box is zero pixels tall whether the bar is there or not, and `-mx-*` is what makes it full-bleed past the page's gutters
- 보정 종료 goes because the step bar is now the way out and the draft survives the change; a route guard still covers a real navigation away, which is what the exit confirm was actually protecting — see the result for why that guard had to move up to the page
- delete becomes its own slice because it is rendered by the page on the top row, and a feature cannot be reached from inside another feature's markup (ARCH-13); `features/delete-post` is the shape to copy, dialog and all
- `ClipStatusLine` takes its save state as a prop rather than reading a hook, so T098 can swap the source without touching the precedence; until then the page passes the settings form's existing saved flag
- one panel element, not three mounted ones: `STEP_PANEL_ID`'s single `role="tabpanel"` with a changing `aria-label` is what the editor does, and it is why the bar's `controls` can name one id
