# T227 The template body becomes an ordered outline in both parsers
> st:done@260918 | ssot:CLIP-4 CLIP-59 CLIP-66 CLIP-112 CLIP-113 CLIP-116 CLIP-141 | base:CLIP@33 ARCH@3 | dep:-

## goal
Parse a template body as an ordered outline whose entries declare only their order — no design attributes, no preset conformance, no interval — in the Go and TypeScript parsers against the shared corpus.

## acceptance
- [v] `ParseTemplate` accepts a body with no `intro`/`caption`/`outro` root attributes, and ignores them when an older body still carries them
- [v] a template may declare any number of `hook`, `ending` and `caption` entries, zero included, and their document order is readable as one outline across stages and texts
- [v] `role="caption"` is admitted in a template body (it was `unsupported_role`)
- [v] `basis`, `start` and `end` on any template entry are refused with that entry's id and line; frozen snapshots keep reading them through `Parse`/`ReadStored`
- [v] `invalid_skeleton` is gone from the template path: no "exactly one hook and one ending" rule and no row-count check against a preset's slots
- [v] an authored `chars` is refused only when it exceeds the grammar's own bound — never for being larger than a preset slot's count (`invalid_max` no longer consults `design.Region`)
- [v] `Document.Design` is gone and no caller reads it — `DesignSelection` survives as the PROJECT's carrier only (see result)
- [v] every frozen-snapshot corpus case resolves byte-identically to before this task
- [v] corpus: new cases for the outline order, the caption entry, the refused interval and the ignored legacy attributes, all shared — `corpus_test.go` (Go) and `composition.test.ts` (TS) run the same file
- [v] ARCH-26 and ARCH-25 verify clean

## impl notes
- `Document` gains `Outline []Entry` where `Entry{Kind string; Index int}` points into `Stages` or `Elements` in document order — the outline is the only position an entry declares (CLIP-112), and the existing per-kind slices stay so nothing downstream is rewritten to walk the outline it does not need.
- keep the stored tag vocabulary: an entry is still `<text role="hook|caption|ending|badge">` with `<row>` children. Renaming roles would churn every frozen snapshot for no product gain; intro/outro/caption in the SSOT map onto hook/caption/ending as they already do.
- rows per entry lose their preset-derived cap and take no new limit of their own: `Nodes` already bounds the body, and a surplus line is a render-time notice under CLIP-147 (T228), not a parse refusal.
- `regionSlotChars` (parse.go:35) and its `design.Region` import go away with the row cap; an undeclared `chars` resolves at render under CDS-77 instead of at parse.
- `Parse` and `ReadStored` change in one way only — they stop surfacing `Design` — because CLIP-140 holds every frozen snapshot to the behaviour it was frozen with.
- the template path keeps refusing `scene`, `repeat` (`unsupported_section`) and `role="info"` (`unsupported_role`); only `caption` moves from refused to admitted.
- README.md in `composition/` documents the three entries and must be rewritten with the same delta — it is the first thing an implementing session reads.
- corpus.json is the oracle both sides read; write the expected results by hand, never by generating one implementation's output (README rule).
- parallel sessions share this tree: stage `backend/internal/clip/composition/**` and `frontend/src/entities/clip-template/{lib,model}/**` explicitly.

## result
- grammar (Go `composition/parse.go`, `types.go`, `convert.go`; TS `composition-parse.ts`, `model/composition.ts`): the root's `intro`/`caption`/`outro` are accepted and read by nobody; `Document.Outline`/`ClipComposition.outline` carries the root's stages and texts in document order; the "exactly one hook and one ending" rule, the preset row cap and the preset-derived `chars` ceiling are gone; a template admits `role="caption"` and refuses any `basis`/`start`/`end` as `unsupported_basis`; an entry with no basis takes its role's span (hook output-start, ending output-end, else whole).
- `composition.DesignSelection` survives, against the acceptance line as written: `clip.ProjectDesign.RegionPresets()` returns it and the render, admission and AI sides all read it. What CLIP-14 required was removing it from the DOCUMENT, which is done — the type is now the project's carrier and the package reads it as an argument.
- the compiler pulled two neighbours in: the AI readers (`ai/composition_copy.go`, `composition_prompt.go`, `narration_prompt.go`, `narration_parse.go`, `composition_parse.go`) now take the project's presets from `PlanningInput.Design` (T228's first acceptance line, already met), and `TemplateDesign` plus the mint seeding are deleted so a project starts at the shared defaults (T231's first two lines). `ValidIntroPreset`/`ValidOutroPreset` now admit `""`, which is what an unset selection stores.
- `ConvertLegacyTemplate` drops the root design attributes and every entry interval, so a stored body still opens and its next save writes the r33 form; without this every saved template would have been unsavable until T231.
- the editor kept compiling but could no longer author what it wrote: the badge/region timing controls, `compositionSkeleton`'s `basis`/`start`/`end` and its root design attributes, and the builder's excess-row error are gone. The design step, its preset rebuild and the outline editing stay for T229.
- corpus: 20 summaries lose `design` and gain `outline`; the retired refusals (`missing design`, `missing intro`, `duplicate intro`, `third intro row`, `fourth outro E row`, the preset `invalid_max`) become accepted cases; the two legacy bodies now refuse at their badge's interval; one new case pins an outline of stages, three intro lines and two captions with its resolution. The outline oracle was derived with a stock XML reader, not from either parser.
- CLIP-117 narrows where a field's answer reaches only region slots: the parser can no longer fold in a slot's count because the preset is the project's, so the answer keeps the grammar's bound and the drawn position holds the text under CDS-77. ①'s control could fold the project's own preset back in — added to T229 as an acceptance line.
- ARCH-25 and ARCH-26 green (2073 FE tests, full `go test ./...`, gofmt, vet, lint, fsd, style, build:web).
