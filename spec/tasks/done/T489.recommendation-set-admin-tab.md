## goal
The operator adds, edits, deletes and reorders recommendation sets on a fifth /admin tab, and /ai-models lists every set in that order.

## acceptance
- [v] `/admin/recommendations` is the fourth of five tabs (계정 관리 · 모델 관리 · 편수 기준 조합 · 추천 조합 · 이용권) with a short caption and icon; the route tree test lists it
- [v] the tab lists the sets in order, each with its label and its seven slots as model label + classification, and flags a slot whose ref is no longer registered to the stage's purpose (등록 해제됨) or has no classification (미분류), derived from the current catalog reads
- [v] 추가 opens an empty editor; 수정 opens one seeded from the set; the editor has a label field and seven app-drawn `Listbox` pickers grouped 사진 관찰 (활성 · A · B), 문체 분석 (활성), 글 작성 (활성 · A · B), each offering the models registered to that purpose with their classification in the option text
- [v] 저장 sends the whole set; a `MODEL_SET_INVALID` refusal shows each cause beside its own field and keeps the draft; `MODEL_SET_LIMIT` and other failures show as a notice; 추가 is disabled with a note at 10 sets
- [v] 삭제 asks for confirmation first; 위로 · 아래로 move a set one place and are disabled at the ends
- [v] every write refreshes both the admin list and the /ai-models recommendations read
- [v] `/ai-models` renders one `ApplyRecommendation` per set in order, shows loading only while the read is pending, a failure notice on error, and an explicit empty message with no set; the set id is no longer displayed
- [v] vitest: the admin feature (create, edit with per-field refusal, delete confirm, move, flags), the admin route/tab, the /ai-models list and empty state, and the updated `ApplyRecommendation` test
- [v] ARCH-25 passes

## impl notes
- entity `entities/model-catalog/api/useRecommendationSets.ts`: `useRecommendationSets()` reads `ProviderService.listRecommendationSets` (same query key `useModelSetup` already uses, so both views share one cache entry) and mutations `useSaveRecommendationSet` `useDeleteRecommendationSet` `useMoveRecommendationSet`, each invalidating that key on settle and exposing `failure` via `appFailureFromConnect`; the save mapper builds `RecommendationStageSelection`s with no candidates on analyze
- feature `features/manage-recommendation-set` (verb slice, ARCH-14): `RecommendationSetManager` (list + controls) and `RecommendationSetEditor` (draft form)
  - slot options come from `filterForStage(useModels().models, stage)`: for the operator that is exactly the registered and classified models of the stage (the server's save rule), with the full `ModelRef` a draft needs — `ListCatalog` entries carry no registry provider id; option text `<label> · <등급>` from `access[stage].grade`; a slot value not among the options stays visible as a disabled option naming the id, as `ComboPicker` does
  - slot flags come from `useAdminCatalog('photo-analysis' | 'style-analysis' | 'writing')`: the ref's entry not registered to the purpose ⇒ 등록 해제됨, registered with `level === ''` ⇒ 미분류; nothing is flagged while those reads are pending
- per-field copy reads `failure.params[<field key>]` (`required` `duplicate` `unregistered` `unclassified` `too_long`) and renders feature i18n; the notice for the refusal as a whole uses `AppFailureMessage`
- delete confirmation uses `Dialog` from `shared/ui` as `DeleteTemplateButton` does (never `window.confirm`, THEME-29; no hand-rolled overlay, ARCH-20)
- page `pages/admin/ui/AdminRecommendationsPage.tsx` is composition only; route `adminRecommendationsRoute` at `/recommendations` in `app/routes/admin.ts`; `ADMIN_TABS` gains `recommendations` with a lucide icon; tab and caption copy in the `plans` namespace beside the other tab keys
- `/ai-models`: map over `setup.recommendations`; the section heading copy stays; empty copy 아직 추천 조합이 없어요 / No recommended sets yet
- `frontend/src/test/providers.ts`: the fake ProviderService keeps an in-memory ordered list behind list/apply/save/delete/move so page tests exercise the real hooks
