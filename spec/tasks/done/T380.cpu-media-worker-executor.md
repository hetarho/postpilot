# T380 A standalone CPU worker prepares and renders frozen media jobs

## goal
Run the existing deterministic preparation and rendering algorithms in a standalone process that consumes leases and never opens the application database.

## acceptance
- [v] `backend/cmd/media-worker` boots with worker/media settings alone: no DB, account/provider keys, migrations, billing sweep or public user listener is required or initialized.
- [v] Prepare downloads originals sequentially, verifies the same actual media identity/cadence rules and produces only the missing bounded analysis chunks requested by the manifest; it uploads them and reports the ordered measured result.
- [v] Render binds downloaded originals to the frozen plan/source identities, executes the existing renderer and its delivered-output checks, uploads its immutable candidate and reports measurements/profile without publishing a project result itself.
- [v] Lease renewal continues through downloads, FFmpeg/resvg execution and uploads; cancellation, shutdown or missed renewal stops work by the conservative local lease deadline and prevents a success report.
- [v] CPU operation works with no NVIDIA tools or device present. Only a validated CPU profile is advertised in this task; requested nvenc fails readiness explicitly, and auto resolves to CPU until an approved GPU profile exists.
- [v] Real-binary parity smokes compare embedded versus worker execution on the same host/profile for representative footage, audio, transitions and sequence captions; byte/frame fingerprints and CDS output measurements remain unchanged.
- [v] Tests cover corrupted/mismatched originals, bounded streaming, failed/expired uploads, heartbeat loss during a child process, stale completion and cleanup on every local exit; ARCH-26 and matching media image smokes pass.

## impl notes
- Keep cmd/media-worker as a composition root. Put the execution loop in `internal/clip/worker` over consumer-owned control, artifact transfer, media and rendering ports; wire clip/media and the workerclient HTTP adapter in the command.
- Reuse clip/media.Adapter, Renderer, source validators and existing plan codecs; extract reusable original verification/render orchestration from clip/app rather than maintaining two separately evolving renderer algorithms. Local paths and callbacks remain inside the executor.
- Load a dedicated typed WorkerConfig, not config.Load for the whole API. MEDIA_ACCEL accepts cpu, auto and nvenc; default cpu. Worker identity/runtime version and the effective profile fingerprint are mandatory claim metadata; a rejected/unknown contract cannot be silently downgraded.
- MEDIA_WORKER_CONCURRENCY defaults to 1 and is initially validated as exactly 1; retain CLIP_ENCODE_THREADS/CLIP_DECODE_THREADS defaults 1/2 and existing MediaThreadMax bounds, work-root ownership, file/workspace budgets and operation timeout. Further concurrency requires the later tuning wave.
- Use monotonic lease deadlines derived from Renew responses with a safety margin; no successful renewal means no continued subprocess past expiry. The existing cancellation-aware process runner must reap the process and descendants, not merely abandon its goroutine.
- Verify input length/fingerprint while streaming to the dedicated workspace, and fetch renewed access on expiry without rerunning completed encoding. Bound transport retries inside the active lease/stage deadline; never retry invalid media or output verification as a network failure.
- Persist no worker-local cache as authoritative state. Record the selected CPU profile, binary versions, font/overlay digests and resource settings for each attempt; output compatibility is based on these values, not on hostname.
- Add bounded health/status commands using GetMediaRuntimeStatus and local capability results, suitable for distroless Docker HEALTHCHECK and deployment drain checks, and a SIGTERM drain: stop claiming, renew/finish the current job during a finite drain interval, otherwise cancel and relinquish it for fenced recovery.
- Add an execution smoke target using the existing pinned media build/runtime. Full dev/prod image packaging is T385; do not strip API fonts/resvg or preview support, which remain necessary for plan validation and browser caption assets.
- CPU separation only: do not change codec, intermediate pixel format, compression, filter graph, typography or motion to obtain a faster benchmark.

## result
- Added the standalone `cmd/media-worker` composition root and typed worker settings. CPU defaults remain one job, one encode thread and two decode threads; `auto` stays CPU and `nvenc` refuses readiness while CLIP-163 is open.
- Added execution/control/transfer ports in `clip/worker`, bounded monotonic lease renewal, finite SIGTERM drain and authenticated health/status commands. Process groups are killed on cancellation; Linux adopts and reaps orphaned descendants.
- Extracted shared original download and single-held-source loading into `clip/localmedia`. Worker downloads verify the existing browser v1 identity (metadata plus first/last 64 KiB), exact streaming length and existing decode/cadence rules. Artifact SHA-256 remains a separate whole-file measurement.
- Preparation uploads only missing copies; rendering reuses the current renderer and its output validation. Project-owned render inputs omitted from the persisted editing plan are explicitly frozen in the media task. Worker execution never publishes a project result.
- Added bounded artifact transfer with refreshed access and conditional upload retries. A response-lost PUT is verified by downloading only the current attempt's reserved candidate and comparing the full digest; foreign or stale candidate reads remain fenced.
- Added bounded CPU runtime manifests covering actual tool versions/digests, pinned fonts, overlay snapshots and resource settings. Added the pinned `worker-execution-smoke` target and same-host preparation/render identity comparisons, including source audio, transitions and sequence captions.
- Validation passed: isolated ARCH-26 plus final affected-package checks; native race tests; 314 frontend files / 2,695 tests, lint/format/FSD/style checks and web build; deployment 8 tests; retirement/skill checks; regenerated protobuf/SQL equality; spec lint (pre-existing unrelated warnings only). The pinned nonroot image passes Linux descendant reaping, standalone CPU/auto readiness with no DB/provider settings, nvenc refusal, tooling coverage, media/profile smokes and preparation/render parity. The two render cases each match all bytes, 16 sampled frames and output measurements (584,397 and 732,346 bytes). Test-only fixture path and protocol mismatches were corrected before the final successful runs.
- No production deployment or host migration. No GPU profile is activated; hardware validation and the CLIP-163 equivalence decision remain later gates. No SSOT change.
