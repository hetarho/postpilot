# T037 Register a payment method through the hosted card window and grant the 100-credit bonus once
> st:done@260908 | ssot:BILLING-1 BILLING-10 BILLING-14 BILLING-16 QUOTA-9 QUOTA-12 AUTH-40 | base:BILLING@2 QUOTA@5 AUTH@2 ARCH@2 | dep:T036 T030

## goal
Let a signed-in account with a verified email register a card through the provider's hosted window, store only the provider's token and a label, and grant the one non-expiring 100-credit bonus the first time it does.

## impl notes
- the card is registered through the provider's hosted window (BILLING-16): the browser only ever sees `authKey` — a one-time handle — and the server exchanges it for the billing key; card numbers never reach the product
- `customer_key` is server-derived and checked ← the browser posts it to Toss, so a client could bind a card under another account's key; equality with `CustomerKey(actor)` closes that
- the bonus id is derived from the account (`payment-method-bonus:<user>`) so a repeat registration, a card change or a retry can never mint a second one — the same shape T034 gave the cycle lot
- the email gate is AUTH-40's rule for legacy operator accounts and BILLING-12's precondition for later mails; a self-signed account always passes it
- removing the card while subscribed is refused rather than silently switching auto-renew off ← the owner's intent is unknown; cancelling (T039) is the explicit path
- the Toss SDK is a third-party script on an AUTHENTICATED page; MARKETING-6's same-origin rule binds `/about` only. Load it lazily from the feature, never in `index.html`
- `successUrl`/`failUrl` are absolute and built from `window.location.origin` so staging and prod resolve to themselves; both must be registered nowhere (Toss accepts any URL on the merchant's domain) — confirm in the docs
