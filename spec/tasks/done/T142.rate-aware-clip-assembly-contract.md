# T142 Version the rate-aware clip assembly contract

## goal
Make one versioned edit-plan contract authoritative for fixed playback rates, transformed time and server-owned source-audio snapshots without changing legacy results.

## acceptance
- [v] Protobuf, Go domain, portable composition and frontend API mappings carry an optional `playback_rate_permille` whose only explicit values are 500, 750, 1000, 1250, 1500 and 2000; absence is accepted only through a legacy compatibility path as 1000.
- [v] A plan-level `ClipSourceAudioSettings` wrapper distinguishes an absent legacy value from an explicit complete source set; present settings contain each retained source identity and fingerprint exactly once and cannot conflict with cuts or owner data.
- [v] New plans use a strict v6 assembly envelope, while dedicated v0, v1-v4 and portable-v5 readers remain unmodified in shape; every old plan reads at 1x, preserves its original audio meaning and rewrites to v6 without changing the existing result.
- [v] One shared checked-integer helper computes each pre-transition cut duration from source span and rate, and cut order, transitions, captions, rapid phrases and composition elements all resolve on that transformed output timeline while evidence remains in original source milliseconds.
- [v] Plain and portable cuts agree on id, source, range, transition and rate; unknown fields, explicit zero, unsupported rates, duplicate source-audio settings, foreign fingerprints and contradictory per-source state are rejected before save or render.
- [v] New v6 plans reject overlapping ranges for the same source identity and fingerprint; unchanged overlap in a legacy saved plan remains readable and renderable, but a correction cannot create or enlarge it.
- [v] Slow-rate admission uses verified original-source cadence and requires `source_fps × rate >= 30 fps`; missing, variable or insufficient cadence refuses the slow rate instead of substituting 1x, and the 15 fps analysis proxy is never used as evidence.
- [v] Domain, correction-history, portable-plan, composition-resolution and RPC tests cover six-rate round trips, transformed duration boundaries, source/output-time separation, v0-v5 fixtures, malformed settings and legacy-overlap preservation.
- [v] Run the applicable ARCH-25 through ARCH-29 checks, including deterministic protobuf generation and a before/after generated-file snapshot when unrelated workspace changes exist.

## impl notes
- Represent rates as integer permille end to end; use `(span_ms*1000 + rate_permille/2) / rate_permille` with checked multiplication for the canonical nearest-millisecond duration. Subtract transitions only after transforming each cut; final 30 fps frame quantization belongs to T147 and must use cumulative rounding rather than per-filter drift.
- Add `optional int32 playback_rate_permille` to `ClipEditCut` and `composition.Cut`. Add `ClipSourceAudioSetting { source_id, fingerprint, retain_original_audio }` plus an optional wrapper on `ClipEditPlan`; the writer response never owns the audio field, and the server constructs the complete snapshot.
- Set `CompositionPlanVersion` to 6 and dispatch decoding by explicit envelope type. A numeric comparison between `storedPlanVersion` and `CompositionPlanVersion` is forbidden because version 5 already identifies the current portable envelope.
- Legacy audio upgrade groups cuts by source identity and fingerprint: any cut with nonzero original volume enables that source, including v0 `Volume == nil`; per-cut volume remains unchanged. An absent rate becomes 1000 only while decoding an old stored plan or an old-client request whose optional field is absent.
- Preserve verified original cadence in the retained analysis metadata and expose the server-computed allowed-rate set needed by later writer and editor tasks. Treat non-CFR or unverified cadence conservatively as ineligible for 0.5x and 0.75x.
- Keep the plan as declarative state; do not add speed ramps, reverse, freeze, frame generation, BGM or executable filter expressions to the wire contract.

- `composition.TransformedDurationMS` is the ONE checked helper; `clip.TransformedDuration` only narrows its rate set to CLIP-98's six. Validation, correction, portable resolution, caption windows, chip exposure and the composition resolver all measure cut length through `OutputDurationMS()`.
- Storage: `CompositionPlanVersion` is 6 and decoding dispatches on the exact stored version. Version 6 carries `Rates` beside `Focals` and a complete `SourceAudio` list, and its composition is a POINTER, so EVERY new plan is written as v6 — a project with no composition included. The v0, v1-v2, v3-v4 and v5 readers are unchanged in shape; `upgradeLegacyAssembly` is the single compatibility path that reads an absent rate as 1x and derives the audio snapshot from saved per-cut volume.
- The audio snapshot is server-owned: the correction projection carries it and `matchOwnerAudio` refuses a per-source contradiction, while a source only one side names (a delete, an undo, new footage) is reconciled rather than refused. `ReconcileSourceAudio` keeps every existing choice and starts a new source off; the snapshot is in canonical identity order so a reorder never changes its bytes.
- Slow-rate admission uses `VerifiedCadence`, which cross-checks the declared average rate against the frame count the ORIGINAL-source decode produced (`MediaInfo.DecodedFrames`, landed by T152 in parallel). Unmeasured or disagreeing cadence is ineligible for 0.5x and 0.75x rather than substituted with 1x; the 15 fps analysis chunk is a separate type and is never read here.
- `clip.RefuseUnsupportedRates` identifies a non-1x cut at the media adapter, because this executor still materializes footage at 1x. T147 removes that guard when the renderer performs the transform; until then an unsupported transform is identified rather than simulated (CLIP-99).
- Deviations worth recording: the plan-level `ClipSourceAudioSettings` completeness rule is defined against the sources the plan's CUTS draw on, which is the set that governs output and is checkable at render; T143's lease remains the owner-facing authority. The one-line sqlc half of ARCH-28 was not run — no SQL changed and Docker is unavailable on this machine, so `buf` was installed locally and the same remote pinned plugins produced byte-identical output twice (before/after snapshot compared).
