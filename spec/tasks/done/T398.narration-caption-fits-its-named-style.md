# T398 a narration caption fits the style it names
> st:done@260926 | ssot:- | base:ARCH@11 | dep:-

## goal
A narration caption is admitted against the line and character bound of the style it names, the writer is told each style's bound, and a caption none of whose sentences fit is omitted with a notice rather than failing the clip; a refusal naming a narration caption says which caption.

Test in `backend/internal/clip/ai/narration_service_test.go`
- [v] the same caption with no short_text that fits is omitted with a `composition_generated_bounds` fallback, the other captions are still admitted, and Narrate returns no error

- [v] a fixed declared caption whose template text the named style cannot hold keeps its text and takes the selection's first style when that style holds it, with the `composition_caption_style` / `style_fallback` notice; it is never omitted over the writer's style choice
- [v] `allowed_caption_styles` entries carry `max_lines` and `max_line_chars` from `design.json`, the prompt states that a caption's bound is its named style's, `caption_max_chars` is gone, and `testdata/narration-prompt-prefix.txt` matches

## impl notes
- from review/clip-narrate-failure-260926 F1 F2
- `design.StyleRule.Holds(text string) bool` beside `Chars` in `design/verify.go`: a blank line or more lines than `Lines` → false; explicit `\n` lines each ≤ `Chars`; one unbroken line ≤ `Lines × Chars`. It mirrors `media/copy.go`: `copyCandidates` tries only the writer's own break when there is one, and an unbroken sentence may split at any grapheme, so a split within `Chars` exists whenever the total is within `Lines × Chars`
- `admitNarration` resolves the style before `check` (absent or out-of-set → the selection's first, unchanged), and the style notice is still added after the identity is minted, so it names the admitted caption. At steady pace, `check` bounds a value by `rule.Holds`. Rapid pace keeps `design.Chars(value) > maxChars`, because its phrases carry `Rapid.MaxChars` and not the style's line bound
- a generated caption keeps CDS-55's ladder: full text → grounded short_text → omit (`composition_generated_bounds`). Its style is never changed ← CDS-55 names no style step, and the named style is the mix CLIP-142 asked for
- an authored caption was only styled by the writer, and its template text is never dropped or rewritten for that choice. It falls back to the selection's first style when that style holds the text (CDS-84's precedent, the existing `style_fallback` notice); otherwise it is bounded as today
- `Alternatives` go through the same `check`, so a short text the style cannot hold is never offered in ②
- prompt: `narrationStyles` returns `[]map[string]any` adding `max_lines` and `max_line_chars`. The numbers stay request data, so the cached prefix does not vary with the selection. Line 18 becomes "A caption holds at most max_lines lines of max_line_chars characters each for the style it names (spaces and punctuation excluded), so choose its style and its words together; a rapid phrase is at most 14."
- FE: `formatAppFailure` adds a branch ahead of the generic one. An `element_id` matching `^narration-([1-9][0-9]*)$` renders `clips:composition.errors.caption` `{n}`. Otherwise `params.line === '0'` renders `clips:composition.errors.element` `{element}`. The ko and en strings go in `entities/clip-template/config/i18n.ts` beside `items_required_count`

## result

- `ai/narration_parse.go` `admitNarration`: the style is resolved before `check`, and a steady written caption is bounded by `rule.Holds` for its named style. The prod case now takes `원목 테이블 배치` under `iridescent`, and with no fitting short text it is omitted as `composition_generated_bounds` while the clip still generates. Rapid pace and authored captions keep the default total bound. An authored caption the named style cannot hold takes the selection's first style when that style holds it, with the existing `style_fallback` notice, which is still added only after the caption is minted
