# T231 A saved template reads as an outline and seeds no design
> st:done@260918 | ssot:CLIP-14 CLIP-114 CLIP-139 CLIP-140 CLIP-144 | base:CLIP@33 ARCH@3 | dep:T227

## goal
Open every template saved with preset-bound skeletons as an outline, ignoring its stored design attributes and authored intervals, and stop seeding a project's design from the template it was made from.

## acceptance
- [v] a stored template body with `intro`/`caption`/`outro` attributes, one hook and one ending loads without a refusal and shows as an outline with those two entries in declared order
- [v] its authored intervals are ignored rather than refused, and the next save writes the body without the design attributes or the intervals
- [v] a legacy (pre-composition) template still converts through `ConvertLegacyTemplate` and carries its sections' guides into the root guide as before
- [v] `TemplateDesign` is gone: minting a project from any template leaves the intro preset, the outro preset, the allowed caption styles, the accent and the caption pace at the shared defaults
- [v] `/clips/new` no longer fills those five from the chosen template, and clearing the template changes nothing about them
- [v] a project frozen before this task renders byte-identically — its snapshot is untouched (CLIP-69)
- [v] tests: a r23-era template body fixture loads → saves → reparses; minting from it leaves the defaults; an existing project's frozen snapshot resolves unchanged
- [v] ARCH-26 and ARCH-25 verify clean

## impl notes
- the read projection is `composition_state.go:authoredRecipe` plus `ConvertLegacyTemplate`; neither may refuse a stored body — CLIP-114's whole point is that nothing already saved becomes unopenable.
- deleting `TemplateDesign` (`design_selection.go:78`) removes the last consumer of the template body's design attributes; `service.go:266` then mints with `ProjectDesign{}` and lets `RegionPresets()`/`ResolvedCaptionStyles` resolve the defaults.
- CLIP-144's one-time carry already ran for existing projects, so nothing re-reads a template's attributes onto a project here; this task only stops the seeding path for new ones.
- the FE side is the template-selection handler in `features/edit-clip-project` that T224 added ("choosing one fills all five"); it stops writing design fields and keeps writing the template id and its answers.

## result
- T227 had already deleted `TemplateDesign` and the preset/style seeding at the mint (the compiler required it when `Document.Design` went), and taught `ConvertLegacyTemplate` to drop the root design attributes and every entry interval. What was left here is the rest of the same rule and its proof.
- `service.go`: the caption pace and the accent stop being seeded from the template too — every project starts unset, which IS the shared default (CLIP-14, CLIP-139). All five now behave identically.
- `features/edit-clip-project/ui/ClipProjectForm.tsx`: choosing a template no longer writes the five design values onto the draft, and `templateDesign` is gone with its `compositionDesign` import. Choosing or clearing a template still resets the answers and the composition inputs, which is what a template does decide.
- tests: `store/legacy_template_test.go` gains the r23-era design-first body — stored as it was, read back converted without `intro`/`caption`/`outro`, without any `basis`/`start`/`end`, with its entries in declared order and its two intro lines intact, savable as-is, and a project minted from it taking none of the five; `store/project_captions_test.go` now pins the unset pace and accent; `pages/clip/ui/ClipDesignSelection.test.tsx` pins that the project's own selection survives both choosing and clearing a template.
- a frozen snapshot is untouched: the existing legacy test still shows a project freezing the STORED body, and the new test shows the next save writing the converted one.
- ARCH-25 and ARCH-26 green.
