# T343 ③ records, replaces and clears the post's Naver address
> st:done@260924 | ssot:POST-54 POST-73 POST-75 POST-77 POST-84 POST-87 ARCH-13 ARCH-16 ARCH-17 ARCH-20 ARCH-21 ARCH-24 THEME-20 | base:POST@11 ARCH@9 THEME@17 | dep:T339

## goal
- The 발행 URL field sits at the foot of ③. It pastes, replaces or clears the post's Naver address, refuses a non-Naver address in place before sending, and stays disabled with its reason until the post is 확정.

## acceptance
- [v] On a finalized post, ③ ends with a 발행 section holding a visible `FieldLabel`, a `TextField` and 저장. Pasting a Naver post address and pressing 저장 (or Enter) sends one `SavePostPublishedUrl` with the trimmed input. The status line then reads 발행됨, the step stays ③, and the field shows the stored address.
- [v] A mobile share address (`https://m.blog.naver.com/…`) is accepted and the field then shows it normalized to `https://blog.naver.com/…`.
- [v] An address that fails POST-77 is refused in place and sends no request:
  - a `FieldMessage` under the field says why, and the field is `aria-invalid`;
  - the status and any stored address are unchanged (POST-84).
  - This covers another host, another scheme, userinfo, a port, an empty path and over-length input.
- [v] On a published post the field holds the stored address. Saving a different valid address replaces it, and the status stays 발행됨 (POST-75).
- [v] On a published post, 지우기 or an emptied field plus 저장 clears the address without a confirmation. The status line then reads 확정, and ② is editable again (POST-75).
- [v] An empty 저장 on a finalized post that has no address sends nothing.
- [v] On a draft or review post the field and 저장 are disabled, with one line saying the field opens once the post is 확정 (POST-87), and nothing is sent.
- [v] Server refusals render in place under the field, and the status and address stay as they were: `POST_PUBLISHED_URL_INVALID`, `POST_BUSY`, and `POST_NOT_FINALIZED` for a post that changed meanwhile.
- [v] The field is the `input` role at the 16 px floor (the `TextField` well, THEME-20). It states `type="url"`, `inputMode="url"`, `autoComplete="url"`, `autoCapitalize="none"`, `autoCorrect="off"` and `enterKeyHint="done"` (THEME-29).
- [v] Tests:
  - new `entities/post/model/published-url.test.ts` runs every case of the shared fixture;
  - new `entities/post/api/useSavePublishedUrl.test.tsx`: a success replaces the GetPost entry and invalidates the list, and a refusal is exposed as an `AppFailure`;
  - `pages/editor/ui/EditorPage.test.tsx`, new `describe('the 발행 URL field')`: paste → 발행됨 on the status line while staying on ③; the mobile host accepted and shown normalized; an invalid address refused with no `SavePostPublishedUrl` in `calls`; replace; clear by 지우기 and by an empty 저장 → 확정 with ② editable again; disabled before 확정 on a review post; the busy refusal.
- [v] Verify: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` · `pnpm lint:retirement`

## impl notes
- Slice is `frontend/src/features/record-published-url` (R6). `features/publish-post` is on `scripts/check-publishing-retirement.mjs`'s forbidden-path list, and no name here matches its retired-contract patterns.
- Wire (T322): `PostService.method.savePostPublishedUrl` with `{ slug, url }`, answering `{ post }`. An empty `url` clears. Add `SavePostPublishedUrlResponseSchema` to `shared/api/index.ts`'s explicit `post_pb` re-export list for the test fake.
- `entities/post/config/index.ts` gains `POST_PUBLISHED_URL_MAX_CHARS = 2048`, mirroring T329's `PublishedURLMaxChars` in `internal/post/limits.go` (ARCH-21).
- `entities/post/model/published-url.ts` (pure, no React, ARCH-18) exports `parseNaverBlogUrl(raw: string): string | undefined`, mirroring R9 and returning the stored form or `undefined`:
  - Trim. Refuse `''` and anything longer than `POST_PUBLISHED_URL_MAX_CHARS` code points (`Array.from(value).length`).
  - Match `/^([a-z][a-z0-9+.-]*):\/\/([^/?#]*)([^?#]*)(?:\?([^#]*))?(?:#.*)?$/i`. Do NOT use `new URL()`: it silently drops a default port (`:443`), which the server refuses.
  - The scheme, lowercased, is `http` or `https`.
  - The authority holds no `@` (userinfo) and no `:` (a port, even an empty one).
  - The host, lowercased, is `blog.naver.com` or `m.blog.naver.com`.
  - The path is neither `''` nor `/`.
  - Return `'https://blog.naver.com' + path + (query ? '?' + query : '')`. The fragment is dropped.
  - Export it from `entities/post/index.ts`.
- Shared case table: T329's `backend/internal/post/testdata/published_url/cases.json`, `{ "_comment": [...], "cases": [{ "name", "input", "stored": string | null }] }` (`null` = refused), which the Go `TestParseNaverBlogURL` already reads.
  - `published-url.test.ts` reads it with `readFileSync`, as `entities/template/lib/grammar.test.ts` does.
  - The TS harness builds the at-limit and over-limit cases from `POST_PUBLISHED_URL_MAX_CHARS`, as the Go harness does from `PublishedURLMaxChars`.
  - The fixture is the contract. Where it and this note disagree, the fixture wins and the FE follows it; a new case goes into the fixture, so both parsers see it.
- The FE sends the trimmed input, not its own normalization, and renders the server's answer. `parseNaverBlogUrl` only gates the request and must pass every fixture case.
- `entities/post/api/useSavePublishedUrl.ts` (R6, in `useFinalizePost`'s shape) returns `{ save(slug, url): Promise<PostDraft>, pending: boolean, failure: AppFailure | undefined, reset(): void }`.
  - On success, `setQueryData(getPostQueryKey(transport, post.slug), create(GetPostResponseSchema, { post }))`, then invalidate `listPostsQueryKey(transport)`. The answer IS the post, so the detail entry is replaced.
  - A 200 with no post throws.
  - `failure` is `appFailureFromConnect(mutation.error)` while there is an error.
  - Export it from `entities/post/index.ts`. Quality-query invalidation is T346's.
- `features/record-published-url/ui/PublishedUrlField.tsx` takes `{ post: PostDraft; className?: string }` and renders `<section aria-labelledby>`:
  - a `Typography variant="title"` heading;
  - `FieldLabel` + `TextField` + a help line (`Typography variant="meta"`);
  - then `FieldMessage` for an error, and a row with 저장 (`Button variant="secondary" type="submit"`, `w-full sm:w-auto`, `pending`) and, only when `isPublished(post)`, 지우기 (`Button variant="ghost"`).
  - Rhythm matches ③'s other sections (`mt-10`).
- Field state:
  - The inner form is keyed on `post.publishedUrl`, so each server answer reseeds the draft: `''` on a finalized post, the stored address on a published one.
  - A change clears the local error and calls `reset()`.
  - `aria-describedby` lists the help id, plus the reason id when disabled and the error id when there is one.
- Submit rules:
  - A trimmed empty draft sends `''` only when `isPublished(post)`; otherwise it does nothing.
  - A non-empty draft with `parseNaverBlogUrl(draft) === undefined` shows the `POST_PUBLISHED_URL_INVALID` message locally and sends nothing.
  - Otherwise it calls `save(post.slug, draft.trim())`.
  - 지우기 calls `save(post.slug, '')`. There is no `Dialog`: clearing is undone by pasting again.
  - Both buttons hold still while `pending`: 저장 shows its spinner and 지우기 is disabled.
- Messages: the local refusal renders `formatAppFailure({ reason: 'POST_PUBLISHED_URL_INVALID', params: {} })` (`formatAppFailure` from `@/shared/lib`) and a server refusal renders `formatAppFailure(failure)`, both inside `FieldMessage`. The pre-check and the server therefore say one sentence (T322's copy states POST-77's rule). `AppFailureMessage` renders a `<div>` and cannot sit inside the `<p>`, which is why `formatAppFailure` is used, as `PostVoiceSelect` does.
- Disabled when `post.status` is `draft` or `review`. The reason is a `Typography variant="label" as="p" role="status"` line above the field (POST-87). A finalized or published post is enabled, and a busy post is left to the server's `POST_BUSY` (R8).
