# T161 Observe and store caption-safe regions per scene
> st:done@260915 | ssot:CLIP-105 | base:CLIP@21 ARCH@2 | dep:-

## goal
Each observed scene reports where on-screen text can sit without covering the principal subject or readable footage text.

## acceptance
- [v] the observe response schema under `backend/internal/clip/ai/schemas` adds a bounded `caption_safe` array of normalized boxes per segment (at most 4), described as factual empty space and explicitly not an anchor, style or placement choice
- [v] `observePrompt` in `backend/internal/clip/ai/prompts.go` defines the field and keeps the existing "make NO editing decision" rule intact
- [v] the domain segment type carries the regions and `ValidateSegments` rejects a box outside 0..1 or extending past the frame, the way `subject` is already checked
- [v] the field is OPTIONAL and additive: `AnalysisContractVersion` stays `clip-observation-v2`, an observation without regions stays valid and reusable, and nothing downstream requires one
- [v] regions survive the analysis JSON round trip and appear in the attempt checkpoint and recovery state without a schema bump
- [v] test that a response omitting `caption_safe` still validates and reuses
- [v] test that an out-of-frame or inverted box is rejected with the existing segment-validation reason
- [v] test pinning the observe schema so the new field is present exactly once and the prompt still forbids editorial output
- [v] `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...`

## impl notes
- CLIP-105 deliberately asks for regions, not an anchor name: naming an anchor would be a layout decision and break CLIP-10
- keeping the field optional avoids invalidating every stored v2 observation, which would make owners pay for re-observation; the v1→v2 bump in `recovery.go` is the precedent for when a bump IS warranted (shape change), and this is not one
- T162 consumes these; nothing else reads them, so this task ships inert and safe
