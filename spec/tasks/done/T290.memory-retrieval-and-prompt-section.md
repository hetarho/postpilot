# T290 retrieval, the frozen [기억] section and the draft's opt-in
> st:done@260920 | ssot:MEM-6 MEM-7 MEM-8 MEM-18 MEM-19 MEM-20 MEM-21 MEM-22 GEN-5 GEN-14 GEN-15 GEN-30 GUIDE-28 POST-71 ARCH-24 | base:MEM@1 GEN@7 GUIDE@3 POST@8 | dep:T289

## goal
Retrieve a post's memories by tag, freeze them at enqueue and render them as one `[기억]` section in the per-post half of the write prompt.

## acceptance
- [v] posts carry `use_memory`, default false, saved through `SavePostGenerationOptions` presence-aware, changing no status, revision, baseline or learning eligibility
- [v] retrieval: `preference` and `persona` are candidates for every post, `place` `person` and `history` only when a tag matches; score is the count of distinct matching tags; ties break by `last_seen_at` then `created_at` descending; at most `MemoryInjectMax` are returned
- [v] a tag matches when it occurs as a substring of the folded key text; the key is the memo, the 가제, the template answers and the observation `objects` and `visible_text` of the post's photos and videos
- [v] folding is Unicode lower-casing plus whitespace and punctuation collapse, using the Go standard library alone — no morphology, stemming, vector or similarity dependency
- [v] `MemoriesForPrompt` is a consumer-owned port in `generation/ports.go` with its adapter in `cmd/api`, mirroring `GuidelinesForPrompt`; the generation context receives texts and never a memory row
- [v] StartGeneration resolves and freezes the selected texts into the payload; the handler reads only the payload; editing or deleting a memory after the start changes nothing in flight, across restart-resume and retry
- [v] the write prompt renders one `[기억]` section in the PER-POST half beside the memo and the observations, never in the stable prefix, closed by a line naming the memories as material for this post and stating that a guideline outranks them
- [v] a post with `use_memory` off produces a write prompt byte-identical to T287's goldens, asserted directly
- [v] the revise prompt carries no memories in any case
- [v] a payload without the member decodes as no memories
- [v] tests: a retrieval table covering both halves of the enum, the tie-break and the cap; a golden for the section; the byte-identity assertion; the pinned payload wire shape
- [v] ARCH-26 and ARCH-28 pass

## impl notes
- retrieval lives in `internal/memory` and answers texts only, so `internal/generation` never learns the row shape (ARCH-7)
- substring matching is the deliberate choice over token equality: Korean agglutination means `연남동` has to match `연남동에서`, and VOICE-51 rules out a morphological analyser. A short tag can over-match; that is the accepted cost and the reason `MemoryTagsMax` is small
- the `[기억]` section goes into the per-post string, NOT into the stable builder where the template brief and the guideline section sit. This is the one place the pattern differs from GUIDE-15, and the reason is that the selected set differs per post while the stable prefix is what the provider cache and every golden rest on (MEM-20)
- the closing line carries the grounding permission too, appended only when the section exists, the way `templateFactLegend` is appended only when the brief carries a fact — a post with the option off must not read a word about a source it has none of
- `use_memory` is a generation option, so it rides `SavePostGenerationOptions` rather than the draft save; the column defaults false so every existing row decodes as off

## result
- the opt-in: migration `0070_post_use_memory.sql` adds `posts.use_memory` NOT NULL DEFAULT 0; `SavePostGenerationOptions` writes it beside the two numbers, `SaveGenerationOptions` takes a presence-aware `*bool` (absent keeps the stored flag), and the save still touches no status, revision or baseline. `post.proto` carries it on `Post` and on the save request. Tests: `TestSaveGenerationOptionsUseMemory` (presence + nothing else moved) and `TestStoreRoundTripsTheMemoryOptIn`.
- retrieval: `internal/memory/retrieval.go` — `Select` is a pure function over the list order (which IS the tie-break: last use, then creation), `preference`/`persona` always candidates and the other three on tag overlap, score = distinct matching tags, cap = `InjectMax`. `fold` is Unicode lower-casing plus whitespace/punctuation collapse, stdlib only; a tag matches as a SUBSTRING of the folded key, which is what makes `연남동` match `연남동에서`. `retrieval_test.go` states both halves of the enum, the tie-break, the cap, the folding table — including the accepted over-match of a short tag — and that a punctuation-only tag matches nothing.
- the seam: `MemoriesForPrompt` in `generation/ports.go` takes the post's own words and answers TEXTS; `generationMemories` in `cmd/api` is its only implementation. `freezeMemories` runs at enqueue and only when the post opted in; `memoryKeyParts` builds the key from the memo, the 가제, the ENABLED template answers and each observation's `objects` and `visible_text` (the observer's `scene`/`mood` prose is deliberately excluded — it would match a tag on a word nobody in the post wrote). `TestOnlyAPostThatOptedInReachesTheMemoryPort` pins both the inclusion and the exclusions.
- the payload: `memories,omitempty` beside `guidelines`; the option-off case and a pre-memory payload are the same absent member. The wire-shape golden now pins it, and `TestMemoriesAreFrozenIntoThePayload` covers the round trip, the legacy decode and the absent member.
- the prompt: `memorySection` renders `[기억]` in the PER-POST half between the memo and the attachments (GEN-14), closed by `memoryPrecedence` — which names the memories as material for this post AND states that a guideline outranks them (MEM-21, GUIDE-28). `write_prompt_memories.golden` pins the whole prompt; its diff against `write_prompt_no_template.golden` is exactly the four section lines. `TestAPostWithoutMemoriesIsByteIdenticalToTheBaseline` asserts the nil and empty cases against T287's goldens in both halves, and `TestTheRevisePromptCarriesNoMemories` pins MEM-22.
- `MemoryInjectMax` joined `memory.Limits` (the service owns the bound; no caller passes one).
- gates: ARCH-25, ARCH-26, ARCH-27 and ARCH-28 all green (both generators re-run with no change; 2218 vitest tests; full `go test ./...`).
- No SSOT deviation. T293 can read `Post.use_memory` and save it through `SavePostGenerationOptions`.
