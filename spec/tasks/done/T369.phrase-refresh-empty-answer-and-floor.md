## impl notes
- from review/published-quality-260924 F12. QUAL-46 is the SSOT delta the review's notes asked for; it is QUAL r4.
- QUAL-46 in `RunOnce` (batch.go:92-108): right after `items, fetchErr := b.fetch(...)` and the ctx check, turn an empty answer into a failure:
  ```go
  if fetchErr == nil && len(items) == 0 && found && len(stored.Phrases) > 0 {
      fetchErr = ErrEmptySearchAnswer
  }
  ```
  - Then the existing failure path keeps the stored row, restamps `NextRefreshAt` and joins `refresh <id>: <err>` into the pass error, which `Run` logs. No second code path.
  - `ErrEmptySearchAnswer = errors.New("quality: the search answered no results")` is exported, beside `ErrPostNotFound` in types.go or at the top of batch.go.
  - "Holds a list" means `len(stored.Phrases) > 0`. A row with empty phrases (a first-failure row, or an earlier empty store) is "no list yet", which QUAL-46 leaves empty ← the SSOT's "a field with no list yet stays empty".
  - "No results" means zero items. Items whose titles and descriptions are all blank are still an answer.
- Retry delay: both failure-path lines use `min(b.interval, PhraseRetryDelay)` (:102). Replace them with `PhraseRetryDelay`. With the floor at `PhraseRetryDelay` the `min` can only ever pick `PhraseRetryDelay`, and the quota test pins that relation.
- Floor value: `PhraseRefreshMinInterval = time.Hour`. Its doc comment carries the reason:
  - one pass is 9 fields × 3 pages = 27 calls;
  - at 1h that is 648 calls a day, and failed fields retry within the same hourly cadence, so the batch cannot exceed that;
  - 648 is ~2.6% of the 25,000/day quota of the Naver application that every stack using the keys shares (staging, prod, dev);
  - `=1m` would be 38,880 a day, over the quota.
  - It equals `PhraseRetryDelay`, so a failing field never retries faster than the floor either.
- `NewPhraseBatch(store, search, interval, now) (*PhraseBatch, error)`. Keep panicking on a nil store or clock, as today and as the other constructors do for a missing collaborator.
  - `interval == 0` → `PhraseRefreshInterval`.
  - `interval < PhraseRefreshMinInterval` (negatives included) → `fmt.Errorf("%w: %s is below the %s floor", ErrPhraseRefreshTooFrequent, interval, PhraseRefreshMinInterval)`.
  - Validate the resolved value, so the product default passes the same check (ARCH-42 "the same bounded owning-context validation as its production default").
  - Precedent for a context constructor refusing an env-fed setting: `clipmedia.New` (internal/clip/media/workspace.go:43-55, thread bounds) wrapped at contexts.go:213-216.
- Composition root:
  - New `newPhraseBatch(cfg *config.Config, store quality.PhraseLists) (*quality.PhraseBatch, error)` in cmd/api/adapters_quality.go, next to `phraseSearch`. It returns `fmt.Errorf("QUALITY_PHRASE_REFRESH_INTERVAL: %w", err)` so the log names the key; quality does not know env names.
  - contexts.go:209 becomes `c.phraseBatch, err = newPhraseBatch(cfg, qualityStore); if err != nil { return nil, err }`.
  - platform/config keeps only format and positivity (`optionalPositiveDuration`, config.go:443-447) ← platform/config may not import quality (ARCH-21, imports_test.go). Update the field doc (:230-232) to "the quality context validates its floor".
- Test seam: `PhraseBatch` gains an unexported `check time.Duration`, set to `PhraseRefreshCheck` by the constructor. `Run` ticks every `b.check` (:52) instead of `min(b.interval, PhraseRefreshCheck)`, which the floor makes always `PhraseRefreshCheck`.
