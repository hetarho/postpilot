## goal
Render the requested narration through the separate media worker without requiring original source audio.

## acceptance
- [v] Narration-only, mixed and source-only renders encode the correct AAC stream, exact asset order/placement and independent gain; all-source-off narration never yields a silent/source-only result.
- [v] Server readiness validates current speech/voice/script provenance before export reservation; missing/corrupt/stale/foreign assets refuse without publishing or consuming a successful export count.
- [v] Worker lease/retry/restart/cancellation and asset-access expiry preserve authorization and once-only output/count settlement; new worker contract versions explicitly refuse incompatible peers.
- [v] Real-binary CPU-image smokes decode narration-only and mixed MP4s, measure audible placement/content/duration and final loudness/peak, and exercise regions, cross-cut speech and all ratios under ARCH-37.

## impl notes
- Under DUB-27, implement and automatically verify this task with deterministic fixtures before live supplier qualification; do not promote production readiness from fixtures.
- Extend the versioned media artifact/job contract with bounded private speech refs, content hashes, measured duration, output start and independent gains. API validates project ownership and readiness; workers have no provider/credit authority and download only authorized immutable inputs.
- Keep original per-cut pitch/fade processing, construct narration on the output clock without cut-rate transforms, apply the source-only hook dip and gains, sum tracks then final loudnorm to CDS-35. Generate an audio stream when ready requested speech contributes, regardless of source HasAudio.
- Validate complete speech before rendering; amix/trims may remove silence outside the plan but must not truncate requested spoken content. Intentional gain zero follows the saved owner state; absent bytes/readiness cannot masquerade as mute.
- Extend renderer/verifier manifest audio provenance and CDS V10/V12/V17 checks, plus the API render fingerprint. Fixture audio has distinct voiced/frequency markers so decoded output proves presence/order rather than just an AAC container.
- Run the existing CPU image smoke harness with narration fixtures and matching font/codec image; record new contract compatibility. No GPU implementation/activation, host migration or production deployment is part of this task.
