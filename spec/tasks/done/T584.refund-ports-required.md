# T584 Make the reviewed-refund ports required and name a failed refund
> st:done@261005 | ssot:ARCH-40 BILL-11 ARCH-24 | base:ARCH@15 BILL@9 | dep:- | touches:backend/internal/billing/ backend/internal/tosspay/ backend/cmd/api/ frontend/src/

## goal
The reviewed-refund store and provider behaviour are part of billing's required ports instead of type-asserted optional extensions (ARCH-40), and a reviewed refund the provider fails is answered with the typed `REFUND_FAILED` reason instead of `UNKNOWN_FAILURE`, so the operator reviewing it sees why.

## acceptance
- [v] `RefundStore`'s methods join the billing `Store` port and `RefundProvider`'s join the `Provider` port; no `.(RefundStore)` / `.(RefundProvider)` type assertion and no `refundStore()`-style lookup remains; `ErrUnavailable` returned only for a refund surface that is genuinely unwired in a legal, tested mode, or not at all
- [v] the reviewed-refund RPCs (request, review, reconcile, list) map `ErrRefundFailed` to `REFUND_FAILED`; the FE app-failure spec and the ko/en copy for it exist and read as an operator-facing message (the copy already exists for the retired purchase path — reuse its keys if they fit)
- [v] test fakes implement the full ports (shared no-op journal/refund stubs as T583 did for intents); the typed-reason coverage test passes with `REFUND_FAILED` emitted by the reviewed path
- [v] behaviour unchanged otherwise: ARCH-26 green; FE gates green; `pnpm gen:proto` / `pnpm gen:sql` clean
- [v] nothing "still open" of this kind is left; a product decision, if any, is recorded in limits
