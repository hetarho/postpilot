## result
- F55: `FinalizePost` refuses `POST_PHOTO_MISSING` (FailedPrecondition, `count`) while IMAGE blocks name photos the post no longer has — deleting a photo scrubs no block, so this is the case (`TestFinalizeRefusesImageBlocksNamingDetachedPhotos`, failing first; rpc params test). The editor already refuses to save such content, so it now says the same thing where it is fixed — 글에 사진이 없는 자리가 N곳 … 지우거나 다시 올린 뒤 완성 — instead of 빈 블록을 채워 주세요, and a finalize never reaches the server with it (`EditorPage.refine.test.tsx`); the server refusal renders the same count through the failure catalog (`post-failure.test.ts`, ko/en)
- F125: `post.TargetLengthMin`/`TargetLengthMax` are 100/10,000 (the frontend's `POST_TARGET_LENGTH_MIN`/`MAX`); an option save outside them is `POST_TARGET_LENGTH_INVALID` (InvalidArgument, `min`/`max`). The template's floor reads the same constant, so it rises to 100 with it; its ceiling is T425's (TMPL-6)
