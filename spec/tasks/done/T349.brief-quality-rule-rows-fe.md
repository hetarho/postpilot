# T349 The writing brief offers one quality row per metric, with a toggletip when over band
> st:done@260924 | ssot:POST-51 POST-81 QUAL-5 QUAL-6 QUAL-12 QUAL-13 QUAL-14 QUAL-19 QUAL-21 QUAL-27 QUAL-30 QUAL-36 QUAL-40 ARCH-3 ARCH-13 ARCH-20 ARCH-24 THEME-23 THEME-32 | base:POST@11 QUAL@3 ARCH@9 THEME@17 | dep:T328 T344 T345 T346

## goal
- ①'s writing brief renders M1–M4 in their four states from the server's account aggregate. An over-band row is a checkbox with a press-operable toggletip quoting the exact rule text that ticking adds, and ticks autosave per post, where the next run's enqueue reads them.

## acceptance
- [v] On a saved post, the brief shows a section headed 발행 글 점검 after the 목표 분량 block.
  - It holds one row per metric in `QUALITY_METRICS` order (M1 제목 도배율, M2 글 간 고정 문구, M3 글 안 반복과 제목 관련성, M4 분량·구성), always.
  - A metric missing from the answer renders as absent, so no row is ever simply missing (POST-81).
- [v] An `over_band` row is a `Checkbox` whose `<label>` reads the metric name and its value(s).
  - A `Toggletip` named `<metric> 설명` sits as a sibling of that label (T328).
  - Its text says what the metric is and why the row appeared: the value(s), the band edge the server sent and the published count.
  - It then quotes the server's `ruleText` verbatim as the sentence ticking adds. M1 and M2 name the measured phrase through that text (QUAL-13, QUAL-14).
- [v] A `within_band` row shows the name, the value(s) and a `Badge` `tone="success"` reading 양호.
- [v] A `below_minimum` row shows the name and T346's `belowMinimumLine(minimum, publishedCount)`, the same words ② uses (QUAL-12, QUAL-36).
- [v] An `absent` row shows the name and 측정할 수 없어요, with no control (QUAL-40).
- [v] One line under the rows reads T346's `bandsAreOwnLine()`, plus that the values come from the published posts PostPilot holds (QUAL-6).
  - No composite score and no number input anywhere (QUAL-27, QUAL-30).
  - The copy states only what was counted, never an exposure gain and never a read of a whole post (QUAL-19, QUAL-21).
- [v] Ticking or unticking sends one `SavePostGenerationOptions` at once.
  - It carries `qualityRules.metrics` = the whole new tick set in `QUALITY_METRICS` order, plus the brief's current `targetLength`, and no `tagCount` and no `useMemory`.
  - The box answers immediately. A refusal puts it back and shows a `FieldMessage`.
- [v] Ticks survive a reload. A stored tick for a metric that is not over band now has no checkbox and is kept in the set the next toggle sends; the server's `RulesFor` ignores it (R23).
- [v] Pressing the toggletip leaves the checkbox as it was. Escape with the tip open closes only the tip, and the brief stays open (THEME-32).
- [v] The checkboxes are disabled while a job runs and on a published post (POST-86). The toggletips stay operable.
- [v] On `/posts/new` (no slug) the section is omitted and no `GetAccountQuality` is sent (R39).
- [v] `GetAccountQuality { slug }` is prefetched as soon as ①'s dock renders, re-read when the post's target language changes, and refetched after a URL paste, replace or clear, a content save or a delete (T346's `invalidateQuality`).
- [v] The start requests are unchanged. `StartGeneration` and `StartWriteExperiment` gain no member; the enqueue reads the stored ticks (T344).
- [v] Tests:
  - `widgets/generation-brief/ui/GenerationBrief.test.tsx`:
    - new 'renders the four quality states after 목표 분량', which mounts `QualityRuleChoices` in the slot;
    - new 'omits the quality section without a slot'.
  - new `features/choose-quality-rules/ui/QualityRuleChoices.test.tsx`:
    - 'saves a tick at once with the whole set and the current length';
    - 'unticks';
    - 'puts a refused tick back and says so';
    - 'keeps a stored within-band tick in the next save';
    - 'quotes the rule text verbatim in the tip';
    - 'opens the tip without toggling the box';
    - 'closes only the tip on Escape inside the brief';
    - 'keeps the tip operable while the box is disabled'.
  - `entities/quality/api/quality-mappers.test.ts`: new 'maps the account aggregate with its rule text'.
  - `entities/post/api/post-queries.test.ts` (new): 'maps the saved ticks and drops a metric this build does not know'.
  - `pages/editor/ui/EditorPage.test.tsx`: new describe 'the brief quality rows':
    - 'saves a tick and keeps it across a reload';

## impl notes
- Wire, from T322:
  - `SavePostGenerationOptionsRequest.quality_rules` is a `QualityRuleTicks { repeated QualityMetric metrics }` message field. Absent keeps, present replaces, and present with no metrics clears.
  - `Post.quality_rules` (31) holds the saved ticks.
  - `GetAccountQualityResponse.readings` carries all four metrics in enum order. `rule_text` is set only on OVER_BAND, rendered in the post's target language (R22).
  - T337 stores the ticks and T335 serves the aggregate.
- `entities/quality` additions:
  - `api/quality-mappers.ts` gains `toAccountQuality(response): AccountQuality`, where `interface AccountQuality { readings: QualityReading[] }` is built with T346's `toQualityReading`.
  - `api/quality-queries.ts` gains `accountQualityQueryKey(transport, ownerId, slug, targetLanguage) = [...qualityQueriesKey(transport, ownerId), 'account', slug, targetLanguage]`. The language is in the key because the rule text is rendered in it, so a language switch is a new read.
  - It also gains `accountQualityQuery(transport, ownerId, slug, targetLanguage)`, which returns `{ queryKey, queryFn }` over `createClient(QualityService, transport).getAccountQuality({ slug })` (the `memoryListQuery` shape).
  - `api/useAccountQuality.ts`: `useAccountQuality(ownerId, slug, targetLanguage)`, enabled when both ids are non-empty, returning `{ quality, isPending, isError, isFetching, refetch }`.
  - `usePrefetchAccountQuality(ownerId, slug, targetLanguage)` is a `useEffect` calling `queryClient.prefetchQuery(accountQualityQuery(…))` when `ownerId` and `slug` are both non-empty.
  - Both share T346's `['quality', transport, ownerId]` prefix, so `invalidateQuality` already covers them (URL save, content save, delete).
  - `@x/post.ts` adds `type QualityMetricId`, `qualityMetricFromProto` and `qualityMetricToProto`.
  - `index.ts` adds `useAccountQuality`, `usePrefetchAccountQuality` and `type AccountQuality`.
- `entities/post`:
  - `PostDraft.qualityRules: QualityMetricId[]`.
  - `toPostDraft` maps `post.qualityRules.map(qualityMetricFromProto).filter((id): id is QualityMetricId => id !== undefined)`. A metric a newer server adds names no row here, so it is dropped rather than guessed (ARCH-3).
- `entities/post/api/useGenerationOptions.ts` gains `saveQualityRules(slug: string, metrics: readonly QualityMetricId[], targetLength: number | undefined)`, in the `saveUseMemory` shape.
  - It sends `mutateAsync({ slug, targetLength, qualityRules: { metrics: metrics.map(qualityMetricToProto) } })`, then invalidates GetPost and the list.
  - `targetLength` is resent because `target_length` is the one member that is not presence-aware: `internal/post/service.go` `SaveGenerationOptions` writes it as given, and an absent value stores NULL. A tick-only save would therefore clear 목표 글자 수.
  - `tagCount` and `useMemory` stay absent, which keeps them.
- The optimistic state lives in the feature, in the `UseMemoriesField` shape: `useState<QualityMetricId[] | null>(null)` and `current = optimistic ?? ticked`, and a refusal resets it to null.
- New slice `features/choose-quality-rules`:
  - `ui/QualityRuleChoices.tsx` with props `{ ownerId: string; slug: string; targetLanguage: ContentLanguage; ticked: readonly QualityMetricId[]; targetLength?: number; disabled: boolean }`.
  - Plus `config/i18n.ts` and an `index.ts` exporting `QualityRuleChoices`.
  - A toggle computes `next` from `current` (add, deduplicate or remove), sorts it into `QUALITY_METRICS` order, sets the optimistic state and awaits `saveQualityRules(slug, next, targetLength)`. The catch shows `qualityRules.saveFailed`.
- Row markup:
  - Section: a `Typography variant="label" as="p"` heading and a `grid grid-cols-1 gap-3` of rows.
  - `over_band` row: `<div className="flex items-start gap-2">`. It holds a `<label>` with `typographyStyles({ variant: 'label', className: 'flex min-h-11 min-w-0 flex-1 items-center gap-3' })` (the `UseMemoriesField` label), wrapping the `Checkbox` and a `min-w-0 break-words` text. The `Toggletip` is the div's second child, never inside the label.
  - Other rows: `<div className="flex min-h-11 flex-wrap items-center gap-x-3 gap-y-1">` with the name, the value(s) and the badge or the line.
- Values in the brief:
  - M1 `share`, M2 `share`, M3 `repetitionShare` and `titleRelevance`, M4 `distinctBlockTypes`.
  - They are formatted with T346's `formatShare` and `formatMeasure`, and an unset value reads `absentValueLabel()`.
  - M4's three context values belong to ②, not the brief.
- The Toggletip child is one plain string (T328's Toggletip takes plain text only and mirrors it into a live region): `${what} ${why} ${t('qualityRules.adds')} “${reading.ruleText}”`.
  - `what`: `qualityRules.what.<metricId>`, one sentence each on what the metric counts. M1 counts titles, M2 identical runs of 8+ 어절 across posts, M3 noun repetition and title relevance, M4 distinct block types.
  - `why`: `qualityRules.why.<metricId>`, interpolating `count` (`publishedCount`), the value(s) and the edge(s) with their direction word.
  - M1 and M2 are fine at or below the edge (`shareWarnAbove`). M3's repetition is fine at or below its edge and its relevance at or above. M4's block types are fine above `distinctBlockTypesWarnAtOrBelow`.
  - The FE computes no verdict and mirrors no number (R21).
- `widgets/generation-brief/ui/GenerationBrief.tsx`:
  - A new prop `qualityRules?: ReactNode` is rendered right after the `{options && (…)}` 목표 분량 block, inside the same `grid grid-cols-1 gap-4 *:min-w-0`.
  - The doc comment's list gains the quality rows.

  - `targetLength` is the dock header's existing prop, the brief mirror. `targetLanguage` is the assignment, which for a saved post is the stored value.
- M1 appears only here, since T346's ② row has none (QUAL-36).
- `features/choose-quality-rules/config/i18n.ts`, posts namespace, key `qualityRules` (free). ko is given below; en carries the same keys.
