# T222 The server hands the preview the caption SVG it will render
> st:done@260917 | ssot:CDS-83 CLIP-143 | base:CDS@21 CLIP@32 | dep:T219 T221

## goal
Serve each caption's rendered SVG fragment from the one place the style set lives, so the preview and the render cannot drift.

## acceptance
- [v] one RPC returns, for a project's current plan, each caption's SVG fragment built by the same style registry the renderer uses, together with its canvas box and the ratio's safe area
- [v] the fragment carries no absolute position: the caller places it with one transform, so moving a caption needs no round trip
- [v] a sequence style returns the fragment of one representative frame, labelled as such
- [v] changing a caption's style or text returns a new fragment; changing only its position or size does not
- [v] a contract test renders the returned fragment through resvg and compares it with the renderer's own output for that caption, byte-identical
- [v] ARCH-26 and ARCH-28 pass

## impl notes
- the fragment is a `<g>` with the caption drawn at the origin plus the `<defs>` its filters need, id-prefixed per caption ← two captions on screen would otherwise collide on filter ids
- the response carries the safe area so the editor clamps without mirroring CDS-9/CDS-13 constants a second time
- fonts reach the browser as the same bundled files served statically; the fragment names the family and the viewer loads it with `@font-face` ← a system font would shape differently from resvg and break CDS-83

## result
- `GetClipCaptionPreview` returns, for the plan ② is editing, one fragment per caption plus the ratio, the canvas and the design safe area — so the editor mirrors no CDS-9/CDS-13 constant of its own. It takes the DRAFT, like `PrepareClipPreview`, because the editor must show the caption on screen rather than the one last saved, and it shares the preview's owner lock and timeout: it measures with resvg exactly as a preparation does.
- There is one drawing. `captionDocument` is the renderer's own caption — the bundled template for a static style, one representative frame for a sequence-rendered one — and the fragment is that document with its root taken off. Nothing is drawn twice, so nothing can drift (CDS-83).
- The fragment is a `<g>` brought to the origin by one transform, with the `<defs>` its filters need and every id prefixed by the caption's own instance; the caller puts it back with a transform of its own. The box it is handed is the SAME rounded number the fragment's transform carries, so the two cancel exactly and the fragment rasterises to the render's own pixels rather than to something a rounding apart.
- `TestRenderSmokeCaptionFragmentMatchesTheRenderer` is that contract, under ARCH-37 with the production resvg and the bundled faces: the fragment placed at its box and the renderer's own caption rasterise to byte-identical PNGs, for a static style and a sequence one, with a size floor so a pair of failed rasterisations cannot agree about nothing.
- A representative frame is the caption's own MIDDLE (progress 0.5): a style's entrance has finished and its exit has not begun there, whatever the interval. The response labels it, so the editor never claims to show the motion.
- Moving a caption needs no round trip — the caller re-places the fragment it already holds, which is what the transform is for. A fragment FETCHED again after a move is the same picture with different numbers in its own transform, because the body keeps the renderer's own coordinates verbatim and that is what buys the byte-identity above; the two cannot both be had. The drawing itself follows only the text, the style and the size, which the layout test pins.
- No caption carries a scrim here: the wash CDS-44 adds belongs to the sampled ground, and this path reads no footage.
- Jua and NanumMyeongjo 400/800 now ship to the browser beside Pretendard and Paperlogy (`frontend/public/fonts/clip/`, `@font-face` in `app/styles/index.css`), byte-identical to the files the renderer pins by SHA-256 and under the family names `design.json` declares. Without them a fragment in either face would shape with a system font in the preview and with the bundled one in the render.
- Verified: ARCH-26 green, ARCH-28 green, ARCH-25 green (2051 vitest, lint, lint:fsd, lint:style, build:web), and the media image stage (ARCH-37) built and run locally with the contract test inside it.
