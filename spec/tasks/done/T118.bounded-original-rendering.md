## goal
Deliver the eight owner-supplied originals within shared-server resources, reduce rendering time, and provide a local MP4 for owner review.

## acceptance
- [v] Record production job timing and available failure evidence without logging private footage, text, credentials or signed URLs.
- [v] Reproduce and remove the rendering memory/time bottleneck; retain original footage, exact transitions, audio timing, output format and advisory overlap.
- [v] The same originals at 20 s recover from the measured -14.97 LUFS result by correcting audio from the assembled PCM while copying video, then pass the unchanged ±1 LU and output-format checks.
- [v] Record bounded, safe media failure classifications and stage durations so an operational failure can be diagnosed without raw subprocess stderr.
- [v] A clip list left open refreshes queued/running jobs until their terminal result, so an old generating badge cannot persist for hours without a refresh.
- [v] Render all eight original files with production binaries under a memory limit below the server's available RAM; retain a local MP4 and measured elapsed time/resource usage for owner review.
- [v] Appropriate renderer, worker and release regression tests and local CI checks pass; owner playback review remains explicit and is never inferred from automated tests.

## impl notes
- At diagnosis production ran 5b7d668 on a shared 909 MiB, 2 vCPU server with 2 GiB swap; the container had no explicit memory cap.
- The latest generate_clip job ran 2026-09-12 02:55:29–03:14:08 UTC (1119 s), failing at render; there was no kernel OOM or container restart, and the existing log omits the media cause. Its target was 20 s and no generated plan was retained.
- T117's real-footage success at 2 GiB did not validate the shared production host. Reproduce offline before choosing an optimization; do not increase the production timeout or memory to mask the defect.
- No new provider call is required for deterministic rendering; any necessary live model verification must remain below the owner's total $0.10 ceiling.
- Reproduction: the unmodified renderer is OOM-killed on the first cut at 512 MiB; limiting input threads alone stalls an infinite PNG input. Finite single-frame reuse renders every cut at 512 MiB. A 20 s plan then exposes a separate final loudness failure (-14.97 LUFS, 0.03 LU beyond tolerance) absent from T117's 30 s fixture.
