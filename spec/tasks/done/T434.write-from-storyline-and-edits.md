# T434 Writing from the storyline, and the owner's own storyline edits (backend)
> st:done@260928 | ssot:GEN-5 GEN-30 GEN-70 GEN-71 POST-74 POST-96 POST-99 | base:GEN@17 POST@21 | dep:T433

## goal
이 스토리로 글 쓰기 / 다시 쓰기 run an ordinary generation that follows the stored storyline — which decides what the post covers and in what order — and the owner's text edits and attachment moves save into the storyline through the draft save.

## acceptance
- [v] `StartGenerationRequest.from_storyline` (bool): the post must hold a storyline with at least one paragraph (`POST_STORYLINE_MISSING`); a `reobserve` selection beside it is `InvalidArgument`; the run freezes the paragraphs into the generate payload (`storyline`) and an observe set of exactly the held attachments that have no reusable observation (no picker, GEN-70)
- [v] the writing stage is shown only the attachments the storyline holds (narrowed as GEN-12 narrows, then to the held names; videos likewise), so the attachment filter keeps no other (GEN-2)
- [v] the storyline-path write prompt: the static rules without the `storyline` member and with the storyline-path rule (impl notes); the frozen storyline rendered in the user half after the observations as `[스토리라인]`, one numbered line per paragraph with its files; answer schema `schemas/write_along_storyline_answer.schema.json` (T429's write schema without `storyline`)
- [v] the result replaces content and baseline as any generation and leaves the stored storyline exactly as it was (`SetGeneratedContent(..., nil)`), `EditedByHand` included
- [v] `SavePostDraftRequest.storyline` (`StorylineEdit { repeated StorylineParagraph paragraphs = 1; }`, absent preserves): replaces the paragraphs' texts and files and sets `EditedByHand=true`; refused `FailedPrecondition` `POST_BUSY` while a job targets the post and `POST_PUBLISHED_LOCKED` on a published post (POST-74); validation `InvalidArgument`: the paragraph count equals the stored one, each text ≤ `StorylineTextMaxChars`, every file attached and in `MadeWith` (a file added after the storyline was made is `POST_STORYLINE_FILE_UNKNOWN`), no file in two paragraphs; the save changes no status, revision, baseline or learning eligibility; `pnpm gen:proto`
- [v] pricing for a `from_storyline` run: the observe calls of its observe set + one write call
- [v] tests: start preconditions and freeze; handler narrowing (an attachment the storyline does not hold never reaches the prompt or the post); the storyline-path prompt snapshot; the storyline unchanged after the write; draft-save cases (busy, published, count, unknown file, repeated file, success sets the mark); rpc mapping
- [v] verify BE: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test -timeout 30m ./...`
- [v] verify gen: `pnpm gen:proto && git diff --exit-code -- backend/internal/gen frontend/src/shared/api/gen` · `pnpm gen:sql && git diff --exit-code -- backend`
- [v] verify FE build (generated code only): `pnpm build:web`

## impl notes
- Storyline-path rule (Korean; English twin in the same style): `[스토리라인]이 이 글이 다룰 내용과 순서를 정합니다. 스토리라인에 없는 내용은 메모에 있어도 쓰지 말고, 재료는 스토리라인이 다루는 내용의 세부를 채우는 데만 쓰세요. 각 사진과 영상은 스토리라인에서 그 파일이 놓인 문단의 자리에 한 번씩 놓으세요.`
- The paragraph count is set by the storyline job; the owner edits texts and moves attachments only (POST-96), so a save with another count is a client bug and is refused.
- The draft queue's other fields keep their presence rules; `storyline` travels as one whole value.
- A `from_storyline` run keeps every other GEN-5 freeze (target, length, tags, brief, guidelines, memories, quality rules) and GEN-23's preconditions.
- `StartWriteExperiment` never reads the storyline (GEN-72).
- Checking a real model is a paid call: ask the owner first.

## result
- Files: `generation/{service,generate_handler,write,prompts,generation_payload,types,errors,schemas}.go`, `schemas/write_along_storyline_answer.schema.json`, `generation/rpc/handler.go`, `post/{storyline.go (new),service.go}`, `post/rpc/handler.go`, `proto/postpilot/v1/{post,error}.proto` + generated code, FE failure catalogue; tests in generation (`storyline_test.go` from-storyline cases, payload/snapshot/prompt-input guards, golden `write_prompt_along_storyline.golden`), generation/rpc, post (`storyline_test.go` edit cases, lifecycle lock), post/rpc, post/store (writers comment).
- The frozen storyline travels as the generate payload's `storyline` and reaches the run as `PostInput.FollowStoryline`; a write comparison's snapshot never carries it (GEN-72).
- The storyline path's static rules are derived from the direct write's by replacement (rule, answer shape, `[스토리라인]` in the placement lines), so the two differ nowhere else; a test pins the difference.
- The write hands the post its nouns with a nil storyline, so the storyline stays exactly as it was while the nouns follow the new content (the acceptance's `SetGeneratedContent(..., nil)` would have kept the old nouns too).
- The observe set is the held attachments with no reusable observation; the frozen snapshot stays the whole reusable one so the unheld attachments keep their observations through the merge.
- An identical storyline save is no edit: it writes nothing and sets no mark. The edit is written after the rest of the draft save, but validated (busy, count, files) before any of it.
- New reasons: `POST_STORYLINE_INVALID` (count, repeated file, ceiling with `max`), `POST_STORYLINE_FILE_UNKNOWN` (`file`), `GENERATION_STORYLINE_REOBSERVE`.
