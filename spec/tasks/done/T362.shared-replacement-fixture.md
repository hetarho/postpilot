# T362 One replacement-rule fixture both sides read
> st:done@260925 | ssot:- | base:ARCH@11 | dep:-

## goal
Which replacement spans stand, which phrases they offer, the phrase cap and the tag identity are each pinned by one JSON fixture that the Go and TypeScript suites both run, so a rule that changes on one side fails a test.

## acceptance
- [v] New `backend/internal/generation/testdata/replacements/cases.json` (content, listed phrases, `spansMax`, `phrasesMax`, cases) is run by Go `ValidateReplacements` and by TS `visibleSpans`, and every case passes on both sides.
- [v] New `backend/internal/post/testdata/tag_identity/cases.json` (`tag` → `canonical`) is run by Go `post.canonicalTag` (extracted from `ValidateContent`) and by TS `canonicalTag`. It includes a U+FEFF case (not a space) and a U+0085 case (a space), and both pass on both sides.
- [v] `generation.ReplacementSpansMax` and `generation.ReplacementPhrasesMax` are asserted equal to the fixture's `spansMax` and `phrasesMax`. FE `REPLACEMENT_PHRASES_MAX` is asserted equal to `phrasesMax`, and its doc comment no longer says it is not a mirrored limit.
- [v] TS whitespace is Go's `unicode.IsSpace` set, spelled out once in `entities/post/model/replacements.ts` and used by `canonicalTag` and by `visibleSpans`' blank-source and blank-phrase checks: U+0009–U+000D, U+0020, U+0085, U+00A0, U+1680, U+2000–U+200A, U+2028, U+2029, U+202F, U+205F, U+3000, and not U+FEFF. This set was checked against `$GOROOT/src/unicode/graphic.go` `IsSpace` + `tables.go` `_White_Space` (Go 1.26.4). JavaScript's `\s`/`trim()` are that set minus U+0085 plus U+FEFF.
- [v] Tests: Go `backend/internal/generation/replacements_test.go` `TestReplacementFixture` (new) + the trimmed `TestValidateReplacementsDropsEveryInvalidEntry`; Go `backend/internal/post/content_edit_test.go` `TestCanonicalTagFixture` (new); TS `frontend/src/entities/post/model/replacements.test.ts` `describe('the shared placement fixture')` and `describe('the tag identity')` (new).
- [v] Behavior unchanged apart from the FE whitespace class now being Go's. Every existing test in `replacements_test.go`, `content_edit_test.go` and `replacements.test.ts` still passes, or moved into a fixture case.
- [v] Verify: BE `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test -timeout 30m ./...` · FE `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- from review/published-quality-260924 F6
- Mechanism and location follow the two existing shared fixtures:
  - the fixture lives in the owning context's `testdata/<topic>/cases.json` and opens with a `_comment` array naming both readers;
  - Go reads it with `os.ReadFile(filepath.Join("testdata", …))` (`post/publication_test.go:29`);
  - TS reads it with `readFileSync(resolve(import.meta.dirname, '../../../../../backend/internal/…/cases.json'), 'utf8')` under `/// <reference types="node" />` (`entities/post/model/published-url.test.ts:1-25`, `entities/template/lib/grammar.test.ts:43`);
  - limits the fixture declares are asserted equal to each side's constant (`template/grammar_test.go:63-67` for `photoRowMax`).
- There are two fixtures because the two rules have two owners. Span placement and phrase rules belong to `generation` (`ValidateReplacements`). Tag identity belongs to `post` (`ValidateContent`, `content_edit.go:20`), which is the rule TS `canonicalTag`'s doc says it mirrors.
- `replacements/cases.json` shape: `{ "_comment": [...], "spansMax": 20, "phrasesMax": 3, "phrases": [...], "content": {...}, "cases": [{ "name", "candidate": {"surface","index","source","phrases"}, "stands": bool, "offers"?: [...], "title"?: string }] }`.
  - `phrases` is the listed set Go filters by: `["솔직 후기", "분위기 좋은 카페", "디저트 맛집", "주차 가능한 카페"]`. The `_comment` requires every phrase a case offers to be in it and already trimmed, so Go's listing and trimming never decide a shared case. The browser only ever sees stored, already-trimmed, listed phrases.
  - `content` is today's `replacementContent()` from `replacements_test.go:16`. Blocks are JSON objects `{type: "TEXT"|"HEADING"|"IMAGE"|"QUOTE"|"LIST"|"VIDEO", content?, level?, file?, caption?, items?, slot?: {kind}}`.
  - `title`, when present, replaces the content's title for that one case.
  - `offers`, when present, is the exact phrase list the kept candidate (Go `got[0].Phrases`) and the span (TS `span.phrases`) carry.
- Cases moved from the Go table (`replacements_test.go:34-57`):
  - true: a title containing its source (index 0); a tag containing it; a TEXT, a HEADING and a QUOTE block containing it; a LIST with an item containing it.
  - false: a title not containing it; a tag past the list; a negative tag index; a tag not containing it; a LIST with no item containing it; an IMAGE block; an unfilled slot; a VIDEO block; a block past the content; a body block not containing it; an unknown surface `"summary"`; a blank source `"   "`; only the source itself as a phrase; no phrase at all; a source with exact case and double spaces.
- Cases added:
  - `offers at most phrasesMax, in answer order`: body 0, source `성수동 카페`, all four listed phrases, `offers` the first three.
  - `a source that is only U+FEFF is not blank`: `title: "비 온 뒤\uFEFF제주"`, source `"\uFEFF"`, `stands: true`.
  - `a source that is only U+0085 is blank`: `title: "비 온 뒤\u0085제주"`, source `"\u0085"`, `stands: false`.
  - Today's TS `trim()` gets both of these wrong, so they fail first on the FE.
