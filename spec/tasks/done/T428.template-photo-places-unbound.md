# T428 Template photo places bind no photo and a repeat renders once
> st:done@260927 | ssot:TMPL-11 TMPL-18 TMPL-21 TMPL-40 TMPL-45 | base:TMPL@14 GEN@16 | dep:T424

## goal
A frozen template brief names no attachment: each photo place renders as a marked place carrying its row size, a `<repeat each="photo">` renders once as a part the writer repeats, and attachment-order binding and the expansion bound are gone.

## acceptance
- [v] `template.Render` / `RenderTemplate` / `Service.RenderedFor` take `hasPhotos bool` instead of filenames; a photo slot renders `{{사진 자리 · 한 줄 n장}}` (n = its `count`); a `<repeat each="photo">` renders once as `<repeat>` + its rendered children + `</repeat>`, and is dropped whole, literals included, when `hasPhotos` is false
- [v] deleted: `renderState.remaining` and `take`, `iterationCount`, `groupSize`, `plannedIterations`, `checkExpansion`, `ErrExpansionTooLarge`, `PhotoToken`, `Rendered.Rows` / `PhotoRow`, `Limits.MaxRepeatExpansion` (and its `valid()` term), the platform config field, the `TEMPLATE_MAX_REPEAT_EXPANSION` env read and its `.env.example` line
- [v] generation: the `TemplateBriefs.RenderedFor` port takes `hasPhotos` (freezeTemplate passes whether the post has any photo, videos not counted); `TemplateBrief.Rows` and `TemplatePhotoRow` are removed from the domain, `cloneTemplate`, the generate payload (`templateRowJSON`) and the write snapshot (`snapshotRow`); `postFilenames` goes if nothing else uses it
- [v] `templateLegend` in `generation/prompts.go` drops the two `{{photo:파일명}}` lines and explains the two markers with the wording in impl notes; the legend still never says 지침 (TMPL-13)
- [v] tests: expand tests pin the place marker per count, repeat-once wrapping, the no-photo drop and that no rendered body contains `{{photo:`; config, limits, service, adapter, payload-golden, snapshot and prompt-assembly tests are updated to match
- [v] verify BE: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test -timeout 30m ./...`
- [v] verify gen: `pnpm gen:proto && git diff --exit-code -- backend/internal/gen frontend/src/shared/api/gen` · `pnpm gen:sql && git diff --exit-code -- backend` (both unchanged: no proto or SQL moves)

## impl notes
- Rebase on T424 first: it rewrites `renderSlot` for place/link slots (label text) and deletes `template_slots.go` and `templateSlotLegend`. Keep its place/link behaviour unchanged; only the photo branch and the repeat change here.
- Marker forms are code (TMPL constraints: "token forms … are code"). Use exactly `{{사진 자리 · 한 줄 n장}}` and `<repeat>`…`</repeat>`, with no attribute on the repeat marker, so the legend can name them. Place/link slots and the title area are untouched; the title area has no photo place.
- Legend lines, Korean for every target language (TMPL-13):
  - `- {{사진 자리 · 한 줄 n장}}: 첨부 사진 가운데 이 자리 앞뒤 내용이 요구하는 사진을 골라 IMAGE 블록으로 놓는 자리입니다. 한 줄에 n장씩 놓고, 사진이 더 있으면 줄을 이어도 됩니다.`
  - `- <repeat>…</repeat>: 흐름에서 이 부분에 해당하는 사진 묶음마다 안쪽을 한 번씩 되풀이해 쓰는 부분입니다. 묶음마다 안쪽의 사진 자리에는 그 묶음의 사진을 놓고, 태그 자체는 출력하지 마세요.`
- "Every attached photo exactly once" and the flow wording belong to T429's static rules, not to this legend.
- `hasPhotos` counts photos only. `repeat each="photo"` is about photos, and a video-only post has no photo place to fill (GEN-12 decides which attachments the writer sees).
- Revision needs no special case. StartRevision freezes the same unbound brief, and the revise pass keeps the existing IMAGE blocks verbatim (GEN-40, GEN-41).
- Old payloads and snapshots may still carry a `rows` or `Rows` member. `encoding/json` ignores unknown members on decode, so nothing needs a compatibility path (pre-alpha). New write-snapshot bytes lose the key, which changes their hash; that is expected.
- `TemplateBrief` doc comments that say the body is "expanded for this post's photos" are rewritten to say the body is resolved and unbound.
- Tests that mention the expansion bound or binding order (template `expand_test.go`, `service_test.go`, `limits_test.go`, `rpc/handler_test.go`; `platform/config/config_test.go`; `cmd/api/post_deps_test.go`; generation template, payload-golden and snapshot tests) are rewritten or deleted with it. Use each golden test's own update mechanism if it has one, then read the diff.
