# T354 A generate's payload is encoded and decoded inside generation
> st:done@260925 | ssot:ARCH-6 ARCH-40 | base:ARCH@11 | dep:-

## goal
Generate freezes its options the way revise already does: `generation.Service.Start` encodes the payload, `cmd/api` stores and returns opaque bytes, and `Generate` decodes them. Every frozen member then reaches the drain, `WriteNativeEffort` included.

## acceptance
- [v] bug F1 fixed: a Start whose write model has `ReasoningNativeEffort` produces a drained write call with `MaxTokens == budget.Write(targetLength, true)`. At HEAD that call gets `Write(targetLength, false)`, because `adapters_generation.go:350-355` never sets `WriteNativeEffort`.
- [v] Nothing in `backend/cmd` builds, encodes, decodes or retypes a generate option. `grep -rnE "EncodeGenerationPayload|DecodeGenerationPayload|GenerationOptions|options\." backend/cmd/api/jobs.go backend/cmd/api/adapters_generation.go` finds no generate-option use. `generateJob` maps only the row's subjects, models and `Payload`.
- [v] Port shape: `Jobs.EnqueueGeneration(ctx, request StartRequest, payload []byte)` mirrors `EnqueueRevision`. `GenerateJob` is `{UserID, PostSlug, VoiceID, ObserveModel, WriteModel, Payload}`, like `RevisionJob` plus the observe model.
- [v] Old queued payloads still decode. The JSON keys are unchanged, and `TestGenerationPayloadWireShapeIsPinned` passes with its `want` literal untouched. A payload without `write_native_effort` decodes `false`. An empty payload decodes as Korean with the default tag count.
- [v] Behavior is otherwise unchanged: existing tests still pass after the mechanical migration listed in impl notes.
- [v] Failing-first regression test: `cmd/api/generation_freeze_test.go` `TestANativeEffortStartDrainsWithReasoningHeadroom`. It uses real stores, the real `generationJobs` adapter, a real queue worker and `generateJob`, and a `recordingModels` whose write model resolves with `ReasoningNativeEffort: true`. It calls `Start` (no target length), waits for done, and asserts `models.last().MaxTokens == testCompletionBudget().Write(nil, true)` (16384). Write it first and see it fail at HEAD (8192).
- [v] New tests in `internal/generation/generation_payload_test.go`:
  - `TestEveryGenerationOptionRoundTrips`
  - `TestEveryFrozenOptionReachesTheRun`
  - `TestStartFreezesEveryOption`
- [v] `internal/generation/budget_reasoning_test.go` `TestNativeEffortWritingGetsFrozenHeadroom` now drains the payload Start enqueued (`jobs.queued(0)`) instead of a hand-built job.
- [v] `cmd/api/generation_freeze_test.go` `TestTheGenerateRowCarriesStartsPayloadVerbatim` replaces `TestEnqueueGenerationCarriesRulesAndPhrasesThroughTheJobRow`.
- [v] The same drop on the A/B path is fixed: `RunWriteCandidate` (`internal/generation/experiment_surface.go:193`) sizes each candidate's `MaxTokens` from that candidate model's own catalog entry (`s.models.Resolve(model)` → `ReasoningNativeEffort`), never from the shared snapshot's `Post.WriteNativeEffort`, which SnapshotWriteInput never sets. Failing-first test in `internal/generation`: a write comparison whose candidate A is native-effort and B is not drains A with `budget.Write(len, true)` and B with `budget.Write(len, false)`.
- [v] BE gate passes: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test -timeout 30m ./...`
