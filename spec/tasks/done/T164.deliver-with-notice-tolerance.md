# T164 Repair or narrow a generated plan and record its notices instead of refusing it
> st:done@260915 | ssot:CLIP-7 CLIP-64 CLIP-86 CLIP-94 CLIP-95 CLIP-97 CLIP-98 CLIP-99 CLIP-104 CLIP-106 CLIP-107 CLIP-108 ARCH-9 ARCH-17 ARCH-21 ARCH-24 ARCH-34 | base:CLIP@21 ARCH@2 | dep:-

## goal
A readable composition response produces a delivered clip: repairable breaks are applied to the plan, unrepairable ones remove only their own cut or text, and every change is recorded as a stored notice.

## acceptance
- [v] Every generated-plan check resolves as repair, removal or failure exactly as the impl-notes table states, and no check outside that table remains fatal by default.
- [v] A repairable break consumes no correction attempt: retries remain only for a response that cannot be read, and the attempt count for a repaired plan is zero.
- [v] Repair never changes an owner fact, an observed source range, a rendered word or an approved style; a break needing one of those is a removal.
- [v] Removal drops only the offending cut or generated text and leaves the rest of the plan intact, with the surviving plan revalidated before freezing.
- [v] Generation fails only when no cut survives, the remainder cannot render, or the result falls below CLIP-7's 15-second floor; the existing failure inspection is unchanged for those cases.
- [v] Each repair and removal records one notice carrying a stable code and its target (plan, cut id or element/cut pair), persisted with the assembly document and returned over RPC.
- [v] A notice whose target the owner has since edited is not returned, and a rerender recomputes the plan-level notices.
- [v] Go tests: a table over every check name asserting its ladder outcome; the two production cases (an arrival section holding two cuts, and a plan that returns to an earlier section); a plan whose removals drop it under the floor still fails; retry count is 0 for a repairable break and 3 for an unreadable response; notices survive a portable-plan round trip.
- [v] Run `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...` and, for the changed contract, `pnpm gen:proto` and `pnpm gen:sql` with a clean `git diff --exit-code`.

## impl notes
- Ladder classification. Repair, removal and failure are decided per check; put the table in one place next to the validators so a new check must declare its tier.
  - repair — `plan_cut_scene` shrink the cut to the first observed scene it overlaps · `plan_cut_rate` and an uncertain `plan_cut_usability` fall to 1x (CLIP-99 already states 1x or unused) · `plan_style` and `plan_accent` snap to the template's approved set · `plan_focal` and `plan_volume` clamp into 0–1 · `plan_cut_fade` drops the transition to a hard cut · `plan_target_duration` trims the overrun from the last cut · `plan_caption_time` clamps into the cut · `composition_cut_evidence` recomputes the references from `clip.CutEvidence` and ignores the model's list.
  - removal — `composition_section_order` and `composition_item_order` drop the cut that moves backwards, never reorder (reordering is the template's narration authority, which CLIP-107 forbids repair from touching) · an unknowable `plan_cut_usability` · `plan_source_overlap` drops the later cut · a duplicate `plan_cut_identity` drops the later cut · `plan_source`, `composition_cut_identity` and `composition_observation_gap` drop the cut · `composition_generated_identity`, `composition_generated_rows` and `composition_generated_bounds` drop that text only · `composition_plan_bounds` and `plan_cut_count` drop the cuts past the limit.
  - failure — an empty cut list, `plan_timeline` under the floor, `caption_measurement`, and every `output_*`/`plan_required`/`plan_cut_fields`/`plan_caption_fields` decode break (those stay CLIP-94 retries). `observe_*` is out of scope and unchanged.
- Removal reruns the ladder on what survives: dropping a cut can push the timeline under the target and can orphan a text bound to it. Bound the pass count so a pathological plan cannot loop.
- Notices reuse the existing reason vocabulary rather than adding a second one. `PortableText.FallbackReason` and `clip.CopyFallback` already carry text-level reasons end to end (proto `fallback_reason = 25`, rendered at `frontend/src/features/correct-clip/ui/ClipTextControls.tsx:70`); extend that model to plan and cut scope instead of replacing it, so CLIP-64's existing fallbacks become notices without a migration.
- Notices store a code, not a sentence: `SafeAttemptCheck`'s allowlist is already the shared vocabulary and T156 gave all 97 codes ko/en wording, so the language requirement of CLIP-108 is satisfied by the frontend (→T165), keeping LANG's rendering rules in one place.
- Owner-edit clearing reads the flags the editor already maintains — `PortableText.OwnerEdited` for text, the cut revision for cut-scope notices — and filters on read; do not delete stored notices, so a rerender from the same plan still explains itself.
- Keep the repair inside composition, before the assembly document is frozen. CLIP-97 keeps the executor forbidden from changing anything, so nothing in `clip/media` or the renderer may learn about notices.
- `composeTimeline` already grows and shrinks a plan and already clamps caption exposure; fold the new repairs into that pass rather than adding a second compiler over the same cuts.
