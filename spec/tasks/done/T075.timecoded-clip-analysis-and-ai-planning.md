# T075 Timecoded clip analysis and AI edit planning

## goal
Turn signed 60-second source chunks plus a frozen video template into validated timecoded observations and one deterministic edit-plan contract.

## acceptance
- [v] `internal/clip` defines `SourceAnalysis`, absolute-time `Segment`, `EditPlan`, `Cut` and `Caption` domain types with integer milliseconds, normalized focal/avoid coordinates, approved position/style/accent ids and per-cut volume
- [v] embedded closed JSON schemas cover one chunk analysis and the whole edit plan; a structured-output model receives the schema and another receives the same JSON contract in the prompt with the existing parser fallback
- [v] one observe call receives one signed proxy URL, source id/name, chunk index and absolute offset and returns chronological segments with start/end, event, visible subjects, speech, quality, focal point and a caption avoid region; returned times are clamped to the chunk then offset to source time
- [v] the merge rejects duplicate/out-of-order source ids, gaps outside supplied chunk ranges and segments with no usable description; model text can never introduce a source not in the frozen manifest
- [v] one write call receives only the frozen template recipe/answers, target duration, ratio and merged analyses and returns ordered cuts with source ranges, focal crops, exact copy, exposure timing, approved style/position/accent and default volume 1.0
- [v] plan validation requires at least one cut, unique ids, every range inside its source, captions inside their cut, styles allowed by the frozen template, total rendered length within one second of the target and within 15–90 seconds, and no overlap within one source unless the plan names two distinct cuts
- [v] automatic placement first honors the model's approved position, then moves it within `top|center|bottom` when it intersects the analyzed avoid region; no free coordinate reaches T074
- [v] the observe model must be registered for `photo-analysis` and carry `video_input`; the plan model must be registered for `writing`; no new model purpose or video-generation model is introduced
- [v] clip-specific completion budgets live in typed config: one bounded analysis budget per chunk and one plan budget large enough for 20 sources/90 seconds; both are passed as the actual `PlannedCall` completion budgets in T076
- [v] provider/parse/truncation failures normalize through the existing LLM boundary into durable clip-stage failures, with no automatic model fallback or unplanned repair call
- [v] prompt/schema/parser tests cover silent footage, speech, chunk-offset merging, unsafe placement movement, hallucinated sources, every invalid time range, plain-JSON fallback and exact ko/en template-answer text
- [v] ARCH-26 passes

## impl notes
- reuse `photo-analysis` for chunk observation and `writing` for planning: VIDEO-11/MODEL-49 already define video input as a per-run capability rather than a sixth purpose
- keep model calls behind the existing `llm` registry; the clip context supplies `StageNameObserve` and `StageNameWrite`, so registered reasoning overrides and metering continue to apply
- the analysis schema describes facts, not editing decisions; only the plan call decides order, ranges and copy, which keeps a bad stylistic choice out of the reusable observation record
- no partial analysis is persisted here; T076 commits the complete merged analysis and plan only after validation, preserving the previous successful project state on failure
