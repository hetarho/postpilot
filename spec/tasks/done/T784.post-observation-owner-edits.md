## goal
The owner's corrections to an observation are saved with the draft, kept as the owner's material by every later run, and attributed as the owner's own meaning.

## acceptance
- [x] SavePostDraft accepts observation edits per attachment filename for `scene`, `mood`, `visible_text`, `objects` and, for a video, `events`; a save replaces those fields, changes no status, revision or baseline, and refuses an unknown filename (InvalidArgument), a published post (existing lock) and a post whose observation-writing job (observe, generate, storyline) is active (`POST_BUSY`, as a storyline edit is refused).
- [x] An edited entry is stored with `OwnerEdited` and the cumulative set of fields the owner changed; GetPost projects `owner_edited` on each Observation; deleting the attachment still deletes its entry (POST-18).
- [x] Every run reuses an owner-edited entry unchanged whatever observe model is selected, even when the owner emptied every field (never forced into re-observation); only an observation job that selected that file replaces it, and the fresh entry carries no owner mark.
- [x] Writing origin material offers each owner-changed field as owner-supplied material compatible with the `owner_input` category, and the unchanged fields stay visual observation (GEN-80).
- [x] Tests: `backend/internal/post/observation_edit_test.go` (save, field replacement, refusals, flag and field set), `backend/internal/post/rpc` handler test for the request and projection, `backend/internal/generation/reobserve_test.go` (owner-edited reusable, empty owner entry not forced, replaced only when selected), `backend/internal/generation/origin_material_test.go` or the existing origin test (owner fields as owner-input sources, validation accepts them).
- [x] `pnpm gen:proto` leaves no diff after commit; gofmt, `go vet ./...`, `go build ./...` and the selected `go test` packages pass.

## impl notes
- Storage: `posts.observations` is JSON; add `OwnerEdited bool` and `OwnerFields []string` (`json:",omitempty"`) to `backend/internal/post/types.go:517 Observation` and the mirror in `backend/internal/generation/types.go:112`. No migration: absent means machine-written.
- Save path: mirror the storyline precedent — `DraftSave.Observations []ObservationEdit` in `backend/internal/post/service.go` (`SaveDraft` :154), a guard beside `checkStorylineEdit` (`storyline.go:70`), and persistence through the same draft transaction. `ObservationEdit{File string; Scene, Mood, VisibleText *string; Objects, Events *[]string}` — nil means untouched; a field whose saved value differs from the stored one joins `OwnerFields`.
- Proto: `message ObservationEdit { string file = 1; optional string scene = 2; optional string mood = 3; optional string visible_text = 4; repeated string objects = 5; bool objects_set = 6; repeated string events = 7; bool events_set = 8; }` and `repeated ObservationEdit observation_edits = <next free>` on `SavePostDraftRequest`; `bool owner_edited = <next free>` on `message Observation` (:135). Map in `toProtoObservation` (`post/rpc/handler.go:775`).
- Reuse: in `backend/internal/generation/observe.go`, `reusableObservations` and the forced check treat `OwnerEdited` as reusable before `observationEmpty`; `mergeObservations` already lets a fresh entry replace the old one.
- Origins: add source kind `owner_observation` in `backend/internal/post/origin.go` (:82-89 list); `observationSources` (`origin_material.go:194`) emits owner-changed fields under it and the rest as `visual_observation`; `originSourceCategoryCompatible` (`origin_validation.go:90`) pairs it with `OriginOwnerInput`. `ValidateObservationOrigins` keeps refusing owner_input inside the observer's own output.

## result
- outcome: SavePostDraft takes `observation_edits` (per filename, presence-aware `scene`/`mood`/`visible_text`, `objects`/`events` behind `_set` flags); `checkObservationEdits` refuses an unknown or repeated filename and `events` on a photo (`ErrObservationEditInvalid` → InvalidArgument), a create, a published post, and an active `observe`/`generate`/`storyline` job (`POST_BUSY`; a revision does not block), then marks changed entries `OwnerEdited` with the cumulative `OwnerFields` and stores them through the new `DraftWriter.EditObservations` (no status/content revision/baseline change, advances the input revision, turns no photo). JSON storage gains `ownerEdited`/`ownerFields` (omitempty, no migration); GetPost projects `Observation.owner_edited`. Generation mirrors both fields through the payload, the experiment snapshot and the cmd/api adapters; `reusableObservations` keeps an owner-edited entry before the emptiness check, so it is never forced and only a selected re-observation replaces it (the fresh entry is unmarked). `WritingOriginSources` catalogs an owner-edited entry field by field: owner-changed fields as the new attachment-bound `owner_observation` kind (owner_input-compatible), the rest as `visual_observation`.
