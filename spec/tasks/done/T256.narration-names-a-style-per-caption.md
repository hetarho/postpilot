# T256 The narration names one caption style per caption
> st:done@260918 | ssot:CLIP-142 CLIP-134 CDS-66 CLIP-108 | base:CLIP@38 CDS@23 | dep:-

## goal
Let the narration call name a style for each caption it writes, from the project's allowed set, so a clip carries the mix its project selected instead of one treatment throughout.

## acceptance
- [v] the narration response schema carries a style per caption, the prompt lists the project's allowed styles with what each one reads as, and the writing instruction no longer forbids choosing one
- [v] a named style outside the project's selection draws that caption in the default style and records one CLIP-108 notice naming the caption; no correction attempt is spent on it
- [v] a caption the response left without a style draws in the default style, with no notice — an absent choice is not a repair
- [v] layout resolves a caption's style as owner choice, then the narration's, then the default; an owner style set in ② still wins
- [v] a project whose selection holds one style renders every caption in it, exactly as before
- [v] a legacy plan frozen before this task still renders every caption in the selection's first entry
- [v] a narration test asserts a mixed selection produces more than one style across the captions, and another asserts the out-of-set fallback and its notice
- [v] ARCH-26 passes

## impl notes
- the style rides `composition.Element.Style`, the field the legacy freeze already writes ← a second field would leave two places a caption's style can come from, and the layout would have to prefer one
- resolution order lives where the layout already narrows candidates (`media/composition_layout.go`): `text.Owner.Style` first, then `Resolved.Element.Style`, then `AllowedCaptionStyles()[0]`; only the first two are a choice, so only they may be reported
- the schema's style is a plain string validated against the selection after parsing, not a generated enum ← the allowed set is per project, and a schema rebuilt per request cannot be cached with the prompt
- the out-of-set notice reuses CDS-84's shape (`composition_caption_style` / `style_fallback`), which already reports a per-caption style swap for a missing glyph
- `ai/multi_source_test.go`'s fixed-treatment assertion and `ai/service_test.go`'s "no style" expectations are the contract being reversed; both state the old rule and must state the new one
- the flow call is untouched: styles belong to captions, and captions are the narration call's alone (CLIP-135)

## result
- `ai/narration_prompt.go`, its stable prompt fixture and `schemas/narration.schema.json` now ask for an optional plain-string style on written and declared captions; each request lists only the project's allowed styles with their descriptions from the design registry.
- `ai/narration_parse.go` freezes the chosen style in the existing `composition.Element.Style`; absent choices use the selection's first entry silently, and out-of-set choices use that entry with one `composition_caption_style` / `style_fallback` notice naming the admitted caption, without another provider call.
- `media/composition_layout.go` resolves owner, narration and selection default in order; frozen legacy plans retain their previous first-entry treatment, and an invalid owner choice remains refused. A later selection narrowing falls back for the narrated caption with the same notice.
- Added ko/en owner-facing notice copy and regression coverage for mixed styles, declared fixed/generated captions, absent/out-of-set choices, owner priority, one/empty selections and frozen legacy compatibility. Focused AI and media tests pass.
