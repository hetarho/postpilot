# T734 Load the post editor routes lazily
> st:done@261109 | ssot:ARCH-14 ARCH-17 | base:ARCH@21 | dep:- | touches:frontend/src/app/routes | lane:- | explore:-

## goal
`/posts/new` and `/posts/$slug` load the editor page from its own lazy chunk, so the first load of every other page no longer downloads the editor and the features it uses.

## acceptance
- [v] `newDraftRoute` and `postEditorRoute` in `frontend/src/app/routes/posts.ts` use `lazyRouteComponent(() => import('@/pages/editor'), 'NewDraftPage' | 'PostEditorPage')`, both on the same dynamic import so they share one chunk; `editorSearchSchema` stays a static import from `@/pages/editor`
- [v] a test in `frontend/src/app/routes/` (extend `router.test.tsx` or `page-schemas.test.ts`) pins that both editor routes' components are lazy (the component exposes the `preload` function `lazyRouteComponent` adds) and that navigating to `/posts/new` and `/posts/$slug` still renders the editor
- [v] production build into a scratch outDir (`cd frontend && pnpm exec vite build --outDir <scratch>`): the entry chunk and every file `index.html` modulepreloads contain none of one unique string literal each from BlockEditor, DraftEditor and ExportPanel, and one lazy chunk contains them; result records entry raw/gzip and the modulepreload total before (entry 1,433.22 kB / 444.85 kB gzip; 76 preloads 1.98 MB / 620 kB gzip at 4b7eb82e) and after
- [v] existing tests pass: `pnpm --filter ./frontend exec vitest run src/app/routes/ src/pages/editor/ src/widgets/channel-actions/ui/ChannelActions.test.tsx src/pages/posts/ui/PostsPage.test.tsx`
- [v] `pnpm --filter ./frontend lint`, `pnpm --filter ./frontend format:check`, `pnpm lint:fsd` and `pnpm --filter ./frontend exec tsc -b` pass
