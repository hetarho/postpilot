# T252 the browser builds and encodes the audio track
> st:done@260918 | ssot:CLIP-18 CLIP-100 CLIP-153 | base:CLIP@38 | dep:T251

## goal
The browser mixes only the original sound its sources retain, at the volume each cut declares, normalised to the output contract's loudness, and encodes it as AAC.

## acceptance
- [v] only a source whose retention setting is on contributes audio, and a plan with none produces a video-only file
- [v] each cut's audio follows its own volume and its playback rate, and the cuts join in plan order with no gap or overlap against the video timeline
- [v] the mixed track is normalised to −16 LUFS ±1 and encoded as AAC at 48 kHz
- [v] at most one simultaneous source-audio track and no background music, as CDS-52's V10 requires
- [v] vitest: a plan with one retained and one silent source mixes only the retained one; per-cut volume reaches the samples; a plan with no retained source produces no audio track; the measured loudness of a synthetic input lands inside the window
- [v] verify: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- decode with `AudioContext.decodeAudioData` over the local originals and render the mix through an `OfflineAudioContext` at 48 kHz, which gives the per-cut gain and the concatenation for free
- loudness: measure integrated LUFS over the rendered buffer by BS.1770's K-weighting and apply one gain, rather than a compressor — CLIP-125 forbids changing what the clip sounds like beyond the same normalisation the server applies
- a playback rate changes the audio's duration with it; the server's own renderer is the reference for whether pitch follows, so read `backend/internal/clip/media` before choosing, and CLIP-129 keeps speech at 1x anyway
- encode with `AudioEncoder`, `mp4a.40.2`, 48 kHz, feeding `AudioData` from the offline render; T250 already refused the browser kind where this config is unsupported
- the loudness measurement is pure numeric work over a buffer: put it in `shared/lib` and test it against a synthetic tone of known level, independent of any browser API

## result
- `browser-audio-plan.ts` resolves retained sources on the existing output timeline, preserving silent cuts, fixed rates, per-cut volume, transition crossfades and the server's 60 ms paired fades at hard cuts. The intro dip reads only visible text's declared interval. `render-audio.ts` decodes originals at 48 kHz and assembles one stereo stream through OfflineAudioContext; a plan with no enabled audio-bearing source returns no track.
- `shared/lib/media/audio` performs pitch-preserving WSOLA, BS.1770-5 K-weighting with absolute/relative gates, true-peak measurement, one linear normalization gain and AAC encoding in a worker. A peak-limited loudness shortfall remains a failed measurement for T253's verdict instead of being hidden by compression. The pinned `@soundtouchjs/core` 2.1.1 package was installed through the latest resolver after reading its official offline-processing API.
- Encoded AAC is decoded once for the delivered-track loudness measurement and to determine actual codec priming against the input boundary. The returned track includes its priming sample count and exact audible sample window for T253's MP4 edit window; encoder padding is never treated as authored duration.
- `BrowserOriginals` shares one runtime-only blob per fingerprint between video and audio, uses local selections or authorized retained playback, and rejects cancelled reads. Video decoder disposal releases a cache it owns; a caller-owned cache survives until both tracks finish. The existing video utilities moved under `shared/lib/media/video` with all consumer imports updated to satisfy the shared-module grouping rule.
- Chromium rendered a six-second, three-cut fixture with a 2x cut, one disabled source, 2:1 cut volumes and a declared intro dip. The decoded AAC measured −16.00 LUFS, retained the tone's pitch, preserved the 2:1 gain and −6 dB dip, and kept the disabled cut silent. Measured priming was 2,112 samples (44 ms) on this encoder. A retained video-only source returned no audio track; cancellation rejected with AbortError. All three T251 video configurations were also rechecked.
- Official references: [BS.1770-5](https://www.itu.int/dms_pubrec/itu-r/rec/bs/R-REC-BS.1770-5-202311-I%21%21PDF-E.pdf), [Web Audio](https://www.w3.org/TR/webaudio-1.1/), [SoundTouchJS core](https://github.com/cutterbl/SoundTouchJS/blob/master/packages/core/README.md), [QuickTime handler atoms](https://developer.apple.com/documentation/quicktime-file-format/handler_reference_atom), and [WebCodecs codec priming](https://github.com/w3c/webcodecs/issues/626).
