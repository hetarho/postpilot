# T165 Show a delivered clip's notices with the result, in step ② and at finalization
> st:done@260915 | ssot:CLIP-53 CLIP-56 CLIP-85 CLIP-86 CLIP-104 CLIP-108 CLIP-109 ARCH-13 ARCH-17 ARCH-20 ARCH-24 | base:CLIP@21 ARCH@2 | dep:T164

## goal
The owner sees, in the project's language, what a delivered clip does or does not contain, beside the cut or text it concerns and again before finalization.

## acceptance
- [v] A delivered clip carrying notices shows them with its result and in step ②; a clip without notices shows no empty region or placeholder.
- [v] A cut-scope notice sits with that cut and a text-scope notice with that text, reusing the existing fallback line rather than adding a second place for the same sentence; plan-scope notices sit once with the result.
- [v] Every notice code the server can return renders a ko and en sentence naming what the clip does or does not contain; an unrecognised code falls back to the existing unknown-check wording instead of showing the raw code.
- [v] The finalization confirmation lists the unresolved notices before the owner confirms.
- [v] No notice blocks editing, rerender, download or finalization, and a notice disappears once the owner's edit removes its cause.
- [v] Notices are visually distinct from a failure: a delivered clip with notices never adopts the failed-attempt presentation of CLIP-85 and CLIP-86.
- [v] Vitest covers a delivered project with cut, text and plan notices in ko and en, a project with none, an unknown code, the finalization confirmation listing, and a notice clearing after an owner edit.
- [v] Run `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`.

## impl notes
- Wording is the product decision here: each sentence states what the finished clip contains or lacks — a dropped cut, a shortened cut, a caption that was not used — never the check name, the validator or the word 오류/실패. T156's existing `inspection.*` strings are the failure vocabulary and stay for failures; notices need their own, calmer set.
- Reuse `ClipTextControls`'s existing fallback line for text-scope notices (`frontend/src/features/correct-clip/ui/ClipTextControls.tsx:70`, key `timeline.fallback`) so a text never carries two explanations; cut scope goes on the timeline item and plan scope beside the result.
- The unknown-code path already exists for checks in `ClipAttemptInspection`; point the notice renderer at the same fallback so a server that learns a new code does not show it raw.
- Keep the notice list read-only derived state from the project response — no local store, no separate fetch — so it stays correct across rerender and revision changes without its own invalidation rule.
- Placement follows CLIP-53's single scroller and preserved preview: notices must not push the preview out of view or introduce a second scroller.
