# T376 Media stages have durable attempts and fenced leases
> st:done@260925 | ssot:ARCH-6 ARCH-7 ARCH-10 ARCH-46 ARCH-49 ARCH-55 CLIP-162 | base:ARCH@11 CLIP@44 | dep:-

## goal
Persist bounded clip media work independently of the API process, with one authoritative lease and one accepted result per stage.

## acceptance
- [v] Fresh and seeded-upgrade databases gain clip-owned media-stage and attempt/artifact records through a new embedded migration; existing jobs, results, source retention and credit data survive unchanged.
- [v] Creating the same stage twice with the same frozen input is idempotent; changing its input, owner, parent job or project revision is refused rather than overwriting it.
- [v] Concurrent claims choose one compatible queued stage once; each claim receives a fresh opaque attempt token and finite lease, and heartbeats cannot renew an expired or superseded lease.
- [v] An expired lease can be reclaimed only within its persisted attempt/deadline budget; stale progress, upload reservation and completion cannot mutate the replacement attempt.
- [v] A completion receipt is immutable: a lost reply can be acknowledged again for the identical accepted attempt/result, while a conflicting duplicate is refused and cannot replace the result.
- [v] Real SQLite tests cover competing claims, fake-clock expiry/reclaim, duplicate creation, compatibility mismatch, stale-token writes and completion/expiry races; ARCH-26 and SQL generation checks pass.

## impl notes
- Place domain values and validation in `internal/clip/media_stage.go`, behavior-shaped store ports in the owning clip/app surface, and SQL/row mapping in `clip/store`; do not create a new bounded context or let job/store query clip tables.
- Add `clip_media_stages`: id, parent_job_id, user_id, project_id, expected_revision, stage_key, operation, contract_version, input_digest, immutable input payload, required renderer/asset versions, state, current_attempt_id, created_at, queue_deadline_at, deadline_at, attempt_limit, accepted_result and typed failure. Enforce unique(parent_job_id, stage_key); initial operations are prepare and render, one stage of each at most per parent.
- Add `clip_media_attempts`: id, stage_id, ordinal, worker_id, token_hash, lease_expires_at, started_at, finished_at, selected_profile, runtime/asset manifest, bounded progress and typed outcome. Tokens are cryptographically random and returned only to the claiming worker; persistent/logged metadata contains no raw token.
- Use one serialized writer transaction with conditional UPDATE/RETURNING for claim, renew and accept; all deadlines use API-authoritative UTC time injected into tests. No database transaction crosses object I/O or an RPC.
- Store source identities/fingerprints, permitted output slots, canonical versioned plan data and their digest, never presigned URLs, local paths or media bytes. Reuse existing clip plan codecs at persistence/transport edges; domain types remain free of JSON/proto/sql tags.
- Defaults in the owning clip limits: lease 60 seconds, heartbeat hint 15 seconds, first-claim wait 30 minutes, at most 3 claimed executions including the first, total stage lifetime 2 hours. Freeze effective limits at stage creation; retain the existing per-media-operation timeout independently. Renewal never extends the total deadline, and lease accounting counts an execution only when it is claimed.
- Validate positive bounded overrides through platform/config and expose them in env examples: CLIP_MEDIA_LEASE_TTL, CLIP_MEDIA_WAIT_TIMEOUT, CLIP_MEDIA_STAGE_TIMEOUT and CLIP_MEDIA_MAX_ATTEMPTS; cap attempts at 5, total stage lifetime at 6 hours, and require lease < wait <= stage lifetime.
- Allocate the migration number from the highest existing file at implementation time; T370 also adds a migration. Do not edit applied migrations or reserve a guessed number.
- Do not wire production dispatch yet. T377 supplies the generic parent wait, and T381/T382 couple it to stage creation atomically.

## result
- Added migration 0079, clip media-stage/lease/failure values, atomic SQL/store operations and an API-clock application boundary; stage and attempt inputs, limits, compatibility and completion receipts are durable, and only token hashes are stored.
- Added typed CLIP_MEDIA_* overrides, owning-context bounds and API boot validation; both env examples document defaults. Production media dispatch is unchanged until the continuation/integration tasks.
- Verified fresh/seeded upgrades, preserved project/result/retention/credit rows, competing claims, expiry/reclaim, bounded wait/lifetime/attempts, stale heartbeat/upload/completion and immutable duplicate receipts using real SQLite; the competing-claim/expiry tests also pass with the race detector.

Deployment tests used an isolated uv environment with PyYAML because the host Python lacks it; spec lint passes with existing history/stale-base warnings.
