# T160 Record observations in the project's UI language and key reuse on it
> st:done@260915 | ssot:CLIP-104 CLIP-93 CLIP-62 | base:CLIP@21 ARCH@2 | dep:-

## goal
Every observation of one project comes back in that project's language, so owner-authored item names can match observed subjects.

## acceptance
- [v] `clip_projects` carries a checked language column (`TEXT NOT NULL CHECK (language IN ('ko','en'))`) added by a new goose migration under `backend/internal/platform/db/migrations/`, backfilling existing rows to `ko`
- [v] `CreateClipProject` requires an explicit language on the request and the server substitutes no default (the LANG-10 rule); the frontend sends the resolved UI locale
- [v] `generationPayload` carries the frozen language and its `Version` is bumped; a legacy payload without one decodes as `ko`
- [v] `BuildObservePrompt` states the required output language for `event`, `action`, `motion`, `subjects` and `quality`, and states that `speech` stays in the language spoken
- [v] `RecoveryState` carries the observation language and `selectRecovery` refuses reuse when it differs, beside the existing contract and observe-model checks
- [v] `AnalysisContractVersion` is NOT bumped — the response shape is unchanged, so same-language v2 observations stay reusable
- [v] test that two otherwise-identical projects with different languages build different observe prompts and do not reuse each other's observations
- [v] test that a recovery state recorded in `ko` is refused for an `en` run and accepted for a `ko` one
- [v] migration round-trip test: an existing project reads back as `ko` and a new project rejects an absent language
- [v] `pnpm gen:proto && git diff --exit-code -- backend/internal/gen frontend/src/shared/api/gen agent/internal/gen`
- [v] `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...` and `pnpm --filter ./frontend test`
