# T221 The owner places, sizes and restyles a caption
> st:done@260917 | ssot:CLIP-143 CDS-82 CDS-38 CDS-52 CDS-74 CLIP-15 | base:CLIP@32 CDS@21 | dep:T219

## goal
Let a caption carry its own absolute position, size and style, clamped to the safe area, and make automatic placement a starting point the owner's value replaces.

## acceptance
- [v] a plan caption may carry an absolute position, a size and a style id; absent values mean automatic placement and the project's default style, exactly as today
- [v] an owner-placed caption's measured bounds are clamped inside the ratio's safe area at store time and again at layout, and a size below CDS-3's floor for its role is refused where it is written
- [v] automatic placement never re-runs over a caption that carries its own position
- [v] V1 counts an owner placement, V3 records an owner-placed contrast shortfall as a notice instead of a failure, V13 skips an owner-placed caption, and V19 accepts the face the caption's style names
- [v] `SaveEditPlan` accepts and round-trips the three fields, and a plan saved before them decodes with all three absent
- [v] layout and verifier tests cover clamping at every ratio, the contrast notice, the skipped anchor-step check and a style outside the allowed set
- [v] ARCH-26 passes

## impl notes
- position is stored as the caption's own top-left on the 1080-wide canvas of its ratio, in integers ← the layout already resolves everything to canvas pixels and a fraction would not survive the round trip identically
- clamping moves the caption rather than shrinking it ← shrinking would silently change a size the owner set, and CDS-82 clamps position only
- size is stored as the role's font size in px, not a scale factor, so the CDS-3 floor is checked against the same number the renderer uses
- the contrast notice reuses CLIP-108's notice record with the caption named; no new notice kind is introduced

## result
- A caption now carries an `OwnerCaption` of its own — position, size and style — on `PortableText` and on the `CorrectionText` the save path reads (`internal/clip/owner_caption.go`, `composition_state.go`, `correction_composition.go`). The three are independent: resizing a caption the owner never moved does not pin its position, and the zero value is a caption placed automatically in the project's default style, which is every caption written before this.
- `clip.CaptionPlacement` is the top-left of the caption's measured bounds on the ratio's own canvas in whole pixels, and `PlaceOwnerCopy` is CDS-82's clamp: the box is MOVED back inside the safe area, never shrunk, and a box too large for the safe area at all is refused rather than made to fit. `fitCopy` uses it instead of the anchor, and an owner size is the one size tried — the shrink-to-fit walk exists to find a size nobody chose.
- Where the clamp actually runs differs by what is measurable. The save path has no font and no resvg workspace, so it clamps the stored POSITION into the safe area (`ClampCaptionPlacement`) and the layout clamps the measured bounds, which is where they first exist. CDS-82 asks for the measured bounds to be clamped and they are, at the one seam that can measure them.
- Refused where it is written: a style the PROJECT does not allow today (the project's own selection, not the plan's render input), and a size below CDS-3's floor for that style's role or above the size that role is set at — the second because V2 refuses it on the way out and a save that accepted it would only fail later. The position is clamped rather than refused: an owner who drags past the edge means the edge.
- The manifest says who placed each caption (`OwnerPlaced` on `CompositionElement` and `design.Element`), which is what the verifier reads: V1 holds an owner placement inside the safe area like anything else, V3 records a shortfall under one as a notice instead of a failure (CDS-52), V13 leaves it out of the anchor walk entirely, and V19 keeps accepting the face the caption's style names. The repair ladder also stops at one — `AutomaticCompositionRepair` is false for a caption with a position, before the owner has touched anything else.
- Over the wire: `ClipCaptionPlacement` and three fields on `ClipEditableText` (30–32), mapped both ways and pinned by a wire round-trip test.
- `testdata/automatic-anchor-defaults.json` was re-pinned. Nothing about the manifest changed except the new always-false field: hiding `OwnerPlaced` from the JSON reproduces the old hash exactly, which is how that was established before re-pinning.
- Verified: ARCH-26 green, ARCH-28 green (a second generation run is byte-identical), `pnpm build:web` green.
