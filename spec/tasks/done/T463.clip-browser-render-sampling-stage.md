# T463 Sample a browser render's grounds on a media worker and serve its assets with them

## goal
A browser render gets its grounds from a media-worker sampling stage, and the assets served for that render carry the resulting scrim, accent colour and contrast notices.

## acceptance
- [v] `StartClipRender` for the browser kind records the render as today and starts a durable `sample_browser_render` job, returned as `job_id` beside `render_id`. Its one media stage, a new `MediaOperation` `sample` versioned under ARCH-46 (frozen plan revision, source fingerprints, renderer and asset versions), runs on a media worker: the worker fetches the retained originals, lays out the frozen plan, runs T462's sampler and reports the bounded result under its current lease. The API stores it on the render's row (migration 0105: nullable `grounds_json`, `sampled_at`) and ends the job done. Originals the server no longer holds are asked for under CLIP-23 as a server render does; a failed or cancelled stage ends the job failed with a named reason.
- [v] The active-job guards (`checkBrowserProject` and the clip job checks) admit a browser render's own sampling job and still refuse every other active clip job; cancelling the browser render cancels its job (ARCH-51); an API restart reconciles the stage (ARCH-50); the job spends no credit.
- [v] `PrepareClipPreviewRequest` and `PrepareClipCaptionFramesRequest` gain `render_id`. With it the server admits only the owner's uncancelled browser render of that project at that plan revision whose grounds are stored, refusing the rest with named errors (not sampled yet, stale, unknown) mapped like today's preview errors, and draws every unplated declared visual with its stored ground: a region block's scrim inside its raster, a static caption's scrim and accent white, and each `PreviewAsset` reports `contrast_notice` from its manifest part. Without `render_id` the editing preview is exactly as today (zero ground, `source_contrast_final_only`).
- [v] A bright-ground fixture rendered on the server and prepared as render-bound assets from the sampled grounds gives the same outro scrim part and the same caption accent colour.
- [v] Tests: app/store tests for the job lifecycle (done, failed, cancelled, restart reconciliation, the active-job guard), a worker executor test for `sample` with fixture originals, rpc/preview tests for `render_id` admission and ground application, the parity test above, and the migration up and down.
- [v] ARCH-31's local gates and `pnpm smoke:media` pass.

## impl notes
- Follow the remote render stage pattern (`app/remote_render.go`, `app/media_dispatch.go`, `worker/executor.go` `renderTask`) for the new operation; the stage result is bounded domain data (ARCH-46), never paths or signed URLs.
- `sample_browser_render` belongs to the project as `render_clip` does; its progress total is 1.
- `grounds_json` is T462's serialized result keyed by instance id and phrase index; layout applies it by key and ignores keys the layout lacks, since a revision change already makes the render stale.
- `contrast_notice` is a boolean on `PreviewAsset`. Persisting CLIP-108 notices stays as today for both kinds (the server render drops them before saving too).
- Sampling runs on the worker because ARCH-45 keeps footage decoding out of the API; it is part of the render's server-side media work.

## result
- outcome: A browser render now waits on a `sample_browser_render` job (migration 0105 rebuilds generation_jobs and clip_media_stages to admit it and the `sample` stage, and gives clip_browser_renders `sample_job_id`, `grounds_json`, `sampled_at`). `StartBrowserRender` admits the render, freezes the render's own media task, starts the job (sources held and released like a render's) and returns both ids through `StartClipRender`; `RunBrowserSampling` asks one `sample` media stage, a worker runs `planInputs` (the verified originals, one at a time) and `SampleGrounds`, `ValidateMediaResult` bounds the grounds (`ValidateSampledGrounds`: one per visual, values in 0..1, at most three frames) and `SaveBrowserRenderGrounds` keeps them once, only for the render's own job at its revision. The job is free, cancellable at any time, holds the project while it runs, parks ReplaySafe across a restart, and fails with the stage's reason; cancelling the render stops it (the reconciler retires the stage). `PrepareClipPreview`/`PrepareClipCaptionFrames` with `render_id` admit only the owner's live render of that project at that revision with kept grounds (`CLIP_RENDER_NOT_SAMPLED`, `CLIP_PLAN_CONFLICT`, not found otherwise) and draw on them: region and caption scrims, accent white, `contrast_notice` per asset, and no final-only contrast caveat; without `render_id` the editing preview is unchanged. On the dev stack a real browser-render sampling of the T456 clip ran on the CPU worker in 6 s and kept eleven grounds, the outro's L=0.606 over the scrim threshold.
