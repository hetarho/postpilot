# T347 /guidelines creates, rescopes and badges guidelines by 분야
> st:done@260924 | ssot:GUIDE-5 GUIDE-14 GUIDE-20 ARCH-3 ARCH-13 ARCH-20 ARCH-24 THEME-29 | base:GUIDE@5 ARCH@9 THEME@17 | dep:T342

## goal
- The scope control offers 전역, 특정 템플릿 and 특정 분야, with a checkbox list of the product's 분야, wherever it is used (새 지침, 승인 and the whole-scope edit). A 분야-scoped guideline shows its 분야 chips, and the list keeps the server's injection order.

## acceptance
- [v] The shared scope control offers three choices: 전역 · 특정 템플릿 · 특정 분야. 특정 분야 shows the nine 분야 as a `Checkbox` list in catalogue order, never a native select. Switching kind clears the other kind's set.
- [v] The save stays disabled until the chosen shape is valid. For 특정 분야 that means at least one 분야 is checked and no template is carried.
- [v] Creating a 분야 guideline sends `{scope: FIELDS, templateIds: [], fields}`, with `fields` in catalogue order whatever the press order. A whole-scope edit sends kind and both sets as one patch, so a templates→분야 rescope carries empty `templateIds`.
- [v] A 분야 guideline's scope badge is one neutral chip per 분야 label, in catalogue order. The 전역 badge, template-name chips and `적용 대상 없음` are unchanged.
- [v] The list renders the global, template and 분야 groups in exactly the order the server sent, with no client reordering.
- [v] A `GUIDELINE_FIELD_NOT_FOUND` refusal renders its catalogue copy under the control and keeps the draft open.
- [v] 지침으로 저장 still offers only 전역 and the post's current template (GUIDE-21). 전부 수락 still sends 전역 with no 분야.
- [v] A scope number this build cannot read fails the list read: the page's existing load-failure notice with retry shows, and no scope is guessed.
- [v] `page.order` and `page.description` name the 분야 group.
- [v] Tests: `entities/guideline/api/guideline-queries.test.ts` (new): it walks `ProtoGuidelineScope`, and every non-UNSPECIFIED value round-trips through toScopeKind/fromScopeKind. UNSPECIFIED and an unknown number read undefined and make toGuideline throw. toGuideline and toScopePatch carry `fields`.
- [v] Tests: `entities/guideline/model/types.test.ts` (new): canSaveGuideline accepts the three valid shapes and refuses global+templates, global+분야, templates+분야, templates with none, and 분야 with templates or none.
- [v] Tests: `pages/guidelines/ui/GuidelinesPage.test.tsx`: a 분야 create (특정 분야, check 카페 then 맛집, recorded fields `[RESTAURANT, CAFE]`); the save disabled with none checked; a template guideline rescoped to 분야 in one patch; 분야 chips; three groups in server order; `GUIDELINE_FIELD_NOT_FOUND` copy with the draft kept; an unreadable scope showing the load failure.
- [v] Tests: `features/edit-with-ai/ui/ReviseForm.test.tsx`: the capture keeps two tabs and records `fields: []`.
- [v] Verify: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- T322 left `entities/blog-field`: `BLOG_FIELD_IDS` (catalogue order), `type BlogFieldId`, `NO_BLOG_FIELD = ''`, `blogFieldLabelKey(choice)` (a `posts`-namespace key `blogField.<id>`), `blogFieldFromProto` (UNSPECIFIED → `''`, an unknown number → undefined) and `blogFieldToProto`. T322's wire (`GUIDELINE_SCOPE_FIELDS`, and `fields` on Guideline, CreateGuidelineRequest and GuidelineScopePatch) carries T342's server behaviour.
- New `entities/blog-field/@x/guideline.ts` re-exports exactly what the guideline entity needs: `BlogFieldId`, `BLOG_FIELD_IDS`, `blogFieldFromProto`, `blogFieldToProto` and `blogFieldLabelKey`. `entities/guideline` imports blog-field only through it (ARCH-13, the `entities/template/@x/guideline.ts` precedent).
- `entities/guideline/model/types.ts`: `GuidelineScopeKind = 'global' | 'templates' | 'fields'`. `Guideline.fields: BlogFieldId[]` is empty unless the scope is `fields`, and `GuidelineScope.fields: BlogFieldId[]`.
- `globalScope()` returns `{ kind: 'global', templateIds: [], fields: [] }`. That one change covers create-guideline, the 승인 dialog seed and the bulk walk (`guideline-mutations.ts:120`).
- `canSaveGuideline` has three shapes: global needs both sets empty, templates needs ≥ 1 template and no 분야, and fields needs ≥ 1 분야 and no template.
- `isOrphanedScope` stays templates-only, because a 분야 is product-owned and never deleted.
- `api/guideline-queries.ts`: `SCOPE_TO_PROTO: Record<GuidelineScopeKind, ProtoGuidelineScope>` backs `fromScopeKind`. `toScopeKind` is its reverse lookup, returning undefined for UNSPECIFIED and unknown numbers (the `entities/plan/api/plan-mappers.ts` precedent). This replaces the `'templates'` fallback at lines 16-20 (ARCH-3).
- `toGuideline` throws an `Error` naming the number when the scope reads undefined. `useGuidelines` moves the mapping out of `useMemo` into `guidelineListQuery`'s queryFn, so the throw is a query error and the page shows `loadFailed` with retry.
- The reason for the throw: a guessed scope would misstate which posts a rule reaches (GUIDE-14). The cached data becomes domain rows, and `useGuidelines` is the only consumer of that cache.
- `toGuideline` maps `fields` through `blogFieldFromProto` and drops any element that reads `''` or undefined, because neither names a 분야. `toScopePatch` returns `{ scope, templateIds, fields }` with the 분야 mapped to proto, and create, saveScope and the bulk walk all go through it.
- `ui/GuidelineScopeField.tsx`: the `SegmentedControl` gains `{ value: 'fields', label: t('scope.fields') }`. `setKind('global')` empties both sets, `setKind('templates')` keeps `templateIds` and empties `fields`, and `setKind('fields')` keeps `fields` and empties `templateIds`.
- Under `fields` the control shows `scope.fieldsHelp` and renders `GuidelineFieldPicker` with the legend `t('scope.pickFields')`.
