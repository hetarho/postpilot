## goal
Ship the irreversible server cutover that prevents new publishing and records conservative terminal outcomes before anything is removed.

## acceptance
- [v] A new forward-only migration invalidates all pairing codes, revokes/disarms all agents, clears active leases and classifies every nonterminal job: pre-commit becomes canceled; a durable committed_at or committing/verifying/published stage becomes outcome_unknown. Existing terminal states, known URLs, source posts/media and cleanup asset rows remain intact.
- [v] All new pairing/enrollment, profile reactivation, start/retry, claim, renew and commit/progress/completion mutations refuse on the server, including master accounts, stale frontend bundles, revoked bearer tokens and requests already authenticated before cutover; no object staging or provider call follows a refused action.
- [v] The bridge has no active publisher recovery, auto-requeue, heartbeat writer, periodic sweeper or automatic manifest/asset purge. Only account-scoped history/agent reads needed by the old UI and explicit retirement reporting remain until later removal.
- [v] Database guards also reject the legacy SQL paths that create capabilities/reservations/jobs, re-arm agents or revive live leases/commit authorization; an older application image cannot resume publishing against this migrated database.
- [v] A temporary operator CLI exports a deterministic, versioned, mode-0600 retirement JSON report atomically without overwrite by default; it includes safe companion inventory and job outcome metadata, not manifests, media, tokens/hashes, signed URLs, browser paths or raw driver detail. An empty installation produces a valid empty report.
- [v] Migration/RPC/store tests cover every status and fence variant, two accounts, idempotent restart, rejected old-client writes, no source-data changes, token revocation without human logout and failure to persist the fence causing no authorization. Existing legacy-migration tests use their historical schema version, not the latest schema.
- [v] Backend formatting, vet, build and relevant tests pass; run ARCH-26 and record any unrelated failures without describing the whole gate as green.

## impl notes
- This task implements retirement, not the superseded live-smoke goal of T008; never launch a real Naver publish or mark T008 successful.
- First rollout checkpoint: stop/drain the pre-retirement API process before the cutover migration/listener starts, and do not run mixed old/new writers. The new migration number is max(existing)+1 at implementation time; never edit historical SQL. Down must refuse restoration of publication capabilities.
- Add use cases in internal/publishing/retirement.go and narrow store methods/SQL; backend/cmd/retirepublishing is wiring only. The CLI defaults to report/read mode, uses existing DB/storage configuration with no HTTP listener and makes no Naver request. T312 adds its explicit cleanup mode; T283 removes the temporary command.
- Install retirement triggers after converting existing rows: reject INSERT on publishing_pairings, publishing_agents, publish_job_ids and publish_jobs; reject clearing revoked_at/rearming an agent; reject restoring queued/running/needs_attention status, a non-null lease, or a new commit authorization on a job. Permit read, conservative terminal bookkeeping and cleanup DELETE. Assert legacy SQL rejection directly without launching a historical publisher.
- Use current terminal statuses rather than adding proto values. Existing failure reasons suffice for bridge refusals: human mutations return FailedPrecondition with PUBLISH_AGENT_UNAVAILABLE; retired agent calls return Unauthenticated and no capability; canceled jobs have no manufactured successful URL, ambiguous jobs retain the existing unknown-outcome reason.
- Keep the current protobuf definitions/generated clients for this bridge. GetPublishJob/ListPublishingAgents/ListRetryablePublishJobs remain authenticated/master-scoped read paths only; there must be no retained hidden StartPublish or direct-service bypass.
- The report carries schema_version, deployment/database identity without secrets, cutoff timestamp, safe agent ids/labels/blog ids/revocation states and job ids/account ids/source slug+creation identity/status/stage/commit/publication timestamps/safe reason/known URL, with row counts and a SHA-256 digest. Once produced, retain the original pre-cleanup report across retries instead of replacing it with an empty one.
- Record the cutover build and migration as the rollback floor in DEPLOY.md. A previously acknowledged final click cannot be recalled by this migration; classify its unfinished result as unknown and require T282 shutdown before T312 deletes data.
- Touch points: internal/publishing/{service,state,store,rpc,sweeper}, cmd/api/{contexts,serve}, auth/rpc boundaries, embedded migrations and their fixtures, temporary CLI and DEPLOY.md. Do not alter general job/credit/clip workers or human sessions.
