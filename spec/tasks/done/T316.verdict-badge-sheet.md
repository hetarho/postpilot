# T316 A winner verdict carries badges through one confirmation sheet
> st:done@260922 | ssot:MODEL-32 MODEL-36 MODEL-37 MODEL-42 MODEL-61 MODEL-62 MODEL-63 ARCH-3 ARCH-6 ARCH-7 ARCH-10 ARCH-13 ARCH-20 ARCH-24 THEME-23 THEME-27 | base:MODEL@14 ARCH@7 THEME@17 | dep:T314

## goal
- Every winner verdict opens one badge sheet whose confirm commits the verdict with optional positive, negative and 기타 badges per candidate; badges are stored as immutable verdict metadata and shown on the decided detail.

## acceptance
- [v] ChooseWinner and DecideWriteExperiment accept per-candidate badge lists (zero or more per candidate, positive and negative mixed) and an optional 기타 note of at most 200 characters, written in the same transaction as the verdict and never changed afterwards; UseSingleCandidate and DismissExperiment accept none.
- [v] Validation: candidate ids must belong to the experiment; duplicates collapse; `in_voice` / `off_voice` on an observe experiment, a note without `other`, or a note over 200 characters are refused `InvalidArgument` with the new stable reason `EXPERIMENT_BADGES_INVALID`, and the verdict is not recorded.
- [v] Badges never enter the Elo replay or match counts; the 30-day sweep and the DeletePost purge clear 기타 notes while badge ids stay; account deletion removes them with the experiment.
- [v] GetExperiment/ListExperiments expose each candidate's badges and note only alongside its revealed identity; nothing about badges crosses the wire before a verdict.
- [v] Frontend: pressing `이 결과로 선택`, `결과 적용` or `결과 적용하고 활성 모델로 변경` opens a `Sheet` (bottom sheet on a phone, centred on desktop) titled by the action, showing the chosen and the unchosen candidate by their blind A/B labels, each with positive and negative badge toggles and 기타 with a counted note field (200 max); the sheet's confirm performs the one mutation with the badges and shows pending state; cancel changes nothing; zero badges confirm; the voice pair is hidden for observe.
- [v] Dismissal and the unpaired survivor's action open no sheet; the analyze application confirm dialog is unchanged.
- [v] The decided detail's reveal band lists each candidate's badges and note beside its model label.
- [v] Tests: BE service/store (transactional write, every validation case, purge clears notes only, blind mapping), handler (new reason in the allowlist); FE (sheet open/cancel/confirm per action, toggling for both candidates, note limit, observe hides the voice pair, request payload, reveal band, enum mirror pin); ARCH-25/26/28 gates pass.

## result
- Proto: `VerdictBadge` (sixteen ids, prefixed), `CandidateBadges` on both verdict requests, and `badges` / `other_note` on the revealed candidate. `EXPERIMENT_BADGES_INVALID` joins the failure contract with copy in both locales.
- Domain: `experiment/badges.go` holds the catalog, the two groups in the order the sheet shows them, the note bound in characters, and `NormalizeBadges`, which refuses before the verdict is written and returns the survivors deduplicated in catalog order. Duplicate badges within one candidate collapse; two entries naming the same candidate are refused rather than merged, because merging two conflicting answers invents one the owner never gave.
- Migration 0075 adds `model_experiment_badges`, keyed so a repeated badge is one row and constrained so a note can only sit on `other`. The store writes the verdict and its badges in one transaction and replaces rather than appends, so a re-decided comparison never carries an earlier attempt's explanation. Both purges clear the note and keep the ids.
- Blindness holds: the handler maps badges only inside the reveal, pinned by a test that renders the same candidate before and after a verdict.
- Frontend: `ChipToggle` is a new `shared/ui` primitive, an `aria-pressed` button whose pressed state takes the accent badge pair rather than a fill. `VerdictSheet` is the one confirmation all three winner actions pass through; it presents both candidates blind by their A/B labels, offers each the catalog, opens a bounded note under 기타, and confirms with zero badges as readily as with ten. Dismissal and the single-survivor application open no sheet.
- The reveal band lists each candidate's badges and note beside the model they were said about.
- Deviation worth naming: the task's acceptance says duplicates collapse. Duplicate badges do; a duplicate candidate entry is refused, for the reason above. No SSOT change is needed — MODEL-61 says nothing about a malformed payload.
- `candidateSides` moved from the comparison widget to the model-experiment entity: a feature may not import a widget, and the A/B ordering is pure logic over candidates that three layers now need — the widget labels its panels, the page docks the switch, and the sheet names the two candidates without revealing either model.
- Committed together with T315: both were implemented in the same session and every backend file they touch is shared, so splitting them would produce a commit that does not compile.
