# T176 Region blocks keep their spacing on every ratio
> st:done@260916 | ssot:CDS-79 CDS-47 CDS-48 CDS-46 CDS-71 CDS-72 CDS-75 CDS-76 | base:CDS@18 CLIP@24 ARCH@2 | dep:-

## goal
Move an intro or outro block as one piece between ratios instead of scaling its baselines into itself.

## acceptance
- [v] the design package resolves a region slot's baseline through one shared function that keeps the preset's 9:16 spacing and applies only the block's vertical offset; the renderer and V20 both call it and `RegionScale` no longer multiplies a slot or rule y
- [v] a test asserts, for all four presets on all three ratios, that consecutive slot baselines and every rule offset differ from the 9:16 preset by the same constant
- [v] a test measures each region part with the bundled faces' own glyph boxes and asserts no two parts of one block overlap on any ratio — 1:1 outro E is the regression
- [v] every part still lies inside the ratio's safe area on all three ratios
- [v] the eight 16:9 and 1:1 region goldens are regenerated and the region preset tests and V20 pass against them
- [v] the frontend preview places region slots at the same baselines as the renderer, covered by its own test
- [v] verify BE (ARCH-26) and FE (ARCH-25) pass

## impl notes
- the block's centre is the midpoint of the preset's own y values — slot baselines and rule y together, no glyph metrics — so the offset is `centre9 * (height / 1920) - centre9` and stays a pure function of the preset and the ratio
- the offsets this produces on both 1080-high canvases, to check an implementation against: intro A −428.75 → [511.25, 591.25] · intro B −423.50 → [422.5, 536.5, 586.5, 666.5] · outro B −424.375 → [475.625, 525.625, 615.625] · outro E −425.6875 → [410.3125, 554.3125, 604.3125, 684.3125]
- 9:16 keeps every value unchanged: the offset is 0 there by construction, so the four 9:16 goldens must not move
- V20 compares `BaselineY` against the preset, so it has to consume the same function; leaving it on the old multiplication would reject every correct render
- the overlap test needs real ink boxes, which the 40 px-per-character fake measurer cannot give. Load both bundled TTFs with `sfnt`, walk each string at ppem 100 accumulating `GlyphAdvance` plus the role's tracking, take the union of `GlyphBounds` for the ink box, and scale by `size/100` — the same measurement resvg reports from `--query-all`. The tracking after the last glyph advances the pen but is not part of the ink box
- the frontend mirror already reads the preset y values from `clip-design.json`; it needs the same offset formula rather than the current `* scale`
- CDS-46 is unchanged: 16:9 and 1:1 keep every font size, `t.hook` included at 72 and 76

## result
- `design.RegionOffset`/`design.RegionBaseline` (backend/internal/clip/design/region_verify.go) own every region y; `RegionScale` is now the unexported `regionScale` and is only read inside the offset, so no call site multiplies a slot or rule y. The renderer (backend/internal/clip/media/regions.go) and V20 both resolve through `RegionBaseline`.
- the centre is the midpoint of the preset's own y values (min+max)/2 over slots and rules together; the offsets it produces on both 1080-high canvases are the four the task predicted, and the regenerated goldens carry them (intro A −428.75 · intro B −423.5 · outro B −424.375 · outro E −425.6875). The four 9:16 goldens did not move.
- tests: `TestRegionBlocksKeepTheirSpacingOnEveryRatio` (four presets x three ratios, one constant per block) and `TestRegionBlockPartsNeverOverlapOnAnyRatio` (backend/internal/clip/design/region_ink_test.go — both bundled TTFs read with `sfnt` at ppem 100, ink boxes from `GlyphBounds`, plus a safe-area assertion on the same real measurements). Both were confirmed to fail against the old `y * scale` before being kept.
- frontend: `CompositionDesignFrame` applies the same offset instead of `* scale`, pinned by a new test that asserts the exact renderer baselines on all three ratios.
- changed: backend/internal/clip/design/region_verify.go · backend/internal/clip/design/regions_test.go · backend/internal/clip/design/region_ink_test.go (new) · backend/internal/clip/media/regions.go · backend/internal/clip/media/regions_test.go · 8 region goldens under backend/internal/clip/media/testdata/ · frontend/src/entities/clip-template/ui/CompositionDesignFrame.tsx · frontend/src/entities/clip-template/ui/CompositionDesignFrame.test.tsx
- one behaviour consequence, no SSOT change needed: a block that keeps its 9:16 spacing is taller on a 1080-high canvas, so on 16:9 and 1:1 a fully visible outro E now covers BOTH automatic caption anchors and an automatic caption falls back to its default anchor and overlaps the block. CDS-56 already rules this a preserve-and-preview overlap rather than a failure. The frontend fixture that pinned the move-to-alternative path was showing three outro rows; it now shows two, which is the case where that path still exists.
- verify: ARCH-26 BE green (gofmt/vet/build/`go test ./...`) and ARCH-25 FE green (1983 tests, lint, steiger, style, build:web). `backend/internal/clip/media/zz_footage_preview_test.go` is an untracked local scratch file, not part of this task and left alone.
