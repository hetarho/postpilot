# T258 shared/config keeps env and cross-slice constants only
> st:done@260920 | ssot:ARCH-21 ARCH-15 | base:ARCH@5 | dep:-

## goal
Move every product limit and slice-local UI tuning out of `frontend/src/shared/config/index.ts` into the entity or slice that owns it, leaving env-derived and genuinely cross-slice values.

## acceptance
- [v] `shared/config/index.ts` exports only values read from `import.meta.env`, cross-slice constants used by ≥2 slices in different domains, and nothing that names a single domain (`CLIP_*`, `POST_*`, `TEMPLATE_*`, `PROMO_*`, `LISTBOX_*`, `POPOVER_*` are gone from it)
- [v] clip limits live in `entities/clip-project/config` (or the entity T260 leaves them in), post limits in `entities/post/config`, template limits in `entities/template/config`; listbox/popover tuning in `shared/ui/<control>/config.ts` beside the control; promo tuning in the slice that renders it
- [v] `clip-design.json` (882 lines) is imported only by the clip entity that reads it, not re-exported through `shared/config`
- [v] no component or handler gains an inline literal: every moved value is still a named export of a `config` segment (ARCH-21), and steiger accepts every new `config` segment
- [v] behaviour unchanged: existing tests pass; a unit test pins that `shared/config` exports no key matching `/^(CLIP|POST|TEMPLATE|PROMO|LISTBOX|POPOVER)_/`
- [v] ARCH-25 passes

## impl notes
- from review/arch-260919 F4
- keep the 14 env-backed exports and any constant with consumers in ≥2 domains (e.g. `AUTOSAVE_*` used by three save features) in `shared/config`; everything with a single consumer moves next to that consumer
- an entity `config` segment imports nothing but `shared` (ARCH-13); values several slices of one domain share go to that domain's entity, since features/pages may import entities but not each other
- do the move by fan-out table: for each export, `grep -rl` its consumers and pick the lowest-layer owner; the review measured most exports at exactly one consumer
- leave the `AUTOSAVE_*` family where it is — T266 consumes it from `shared/config`
