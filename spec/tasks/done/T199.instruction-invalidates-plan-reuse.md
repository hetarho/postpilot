# T199 An instruction change invalidates the reusable plan
> st:done@260916 | ssot:CLIP-93 CLIP-69 CLIP-121 | base:CLIP@31 ARCH@3 | dep:-

## goal
Carry the owner instruction into the two digests that decide plan reuse, so a changed instruction re-plans instead of re-rendering the plan written without it.

## acceptance
- [v] `planRecoveryDigest` (clip/recovery.go) covers the payload's `Instruction`, so two payloads differing only in it produce different digests
- [v] `QuoteInputDigest` (clip/quotes.go) covers the project's `Instruction`, so a quote taken before an instruction change is not reused after it
- [v] a quote for a project whose only change since its last successful generation is the instruction reports `RenderOnly=false` and prices the writing call; observation chunks stay reused (`ReusedChunks` unchanged) because CLIP-93 preserves matching observations
- [v] adding, editing and clearing an instruction each invalidate the candidate plan; a payload with no instruction on either side keeps today's digest behaviour for every other field
- [v] tests: both digests react to an instruction change, and a quote after an instruction-only change is not render-only while its reused chunk count is unchanged
- [v] verify BE (ARCH-26) passes

## impl notes
- the defect: `planRecoveryDigest`'s anonymous struct lists Composition, Template, Answers, Ratio, Write, Disclosure, CTA, Language, Target, Hide, Version, Analysis and Sources but not Instruction, so `skipPlan` in `quoteInputs` (clip/quotes.go) stays true after an instruction-only change and `RunGeneration` decodes the stored plan instead of calling the writer
- add the field to both structs rather than hashing the whole payload: the digests are deliberately SEMANTIC, and `planRecoveryDigest`'s comment already explains why the source-sound setting is left out (render-only, rides the render revision) — the instruction is the opposite, it is writer input frozen by CLIP-69
- both digests are stored values: `QuoteInputDigest` rides the quote row and `PlanDigest` the recovery state, so an existing quote or recovery written before this change simply stops matching and re-plans. That is the correct outcome and needs no migration
- store/recovery_test.go already proves a recovery written under another contract is refused; the new tests belong beside the existing digest assertions in clip/language_test.go, which pins the same behaviour for a language change
- do not touch `recoverySourceMatches` or the observation contract — CLIP-93 keeps matching observations reusable across an instruction change, and only the plan is invalidated

## result
- changed: `backend/internal/clip/recovery.go` (planRecoveryDigest carries Instruction, comment says why), `backend/internal/clip/quotes.go` (QuoteInputDigest carries Instruction), `backend/internal/clip/instruction_reuse_test.go` (new), `backend/internal/clip/store/recovery_test.go` (an `instruction` case in the changed-input table)
- the regression was checked both ways: with the two struct fields removed, the new unit test fails on all three of added/edited/cleared for both digests
- the unit test went into its own `instruction_reuse_test.go` rather than into `language_test.go` as the impl notes suggested — same pattern and package, but the file name now matches what it pins
- no migration: both digests are recomputed values, so a quote or recovery row written before this change simply stops matching and re-plans
- verify BE (ARCH-26) passes in full
