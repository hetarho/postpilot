# T017 The `원문` source mode, paste import and the copyable format guide
> st:done@260907 | ssot:TMPL-26 TMPL-30 TMPL-34 TMPL-41 TMPL-42 TMPL-7 TMPL-16 TMPL-19 TMPL-20 TMPL-29 | base:TMPL@3 ARCH@1 | dep:T011

## goal
Put a second mode on the template screen that shows and edits the stored body as text with live parse errors, lets a pasted body become the draft byte-exact, offers 원문 복사 and a copyable 형식 안내 an outside AI can write our format from, and gives an unreadable body a 원문에서 고치기 action — with no server change and no grammar rendered outside that mode.

## acceptance
- [v] the composition section carries a `SegmentedControl` labelled 구성 편집 방식 (en: How to edit) with two options 블록 · 원문 (en: Blocks · Source), default 블록; switching renders `TemplateComposition` or the new `TemplateSource` over the same `draft.body`, never both, and a body written in one mode is what the other shows after the switch (builder → source shows the exact serialized body; source → builder shows the pasted outline)
- [v] `TemplateSource` is a labelled textarea (label 원문, en Source) whose value is `draft.body` with no trim or normalization on input or on save: a test pastes a body with leading spaces and a trailing newline, saves, and the update call carries the identical string
- [v] while the source does not parse, a `FieldMessage role="alert"` reads `{{line}}번째 줄: {{reason}}` (en: `Line {{line}}: {{reason}}`) using the existing `builder.reasons.*` copy, the textarea is `aria-invalid`, and 저장 is disabled even when the name changed; the message disappears on the keystroke that makes the body parse; the live counter under the textarea uses `TEMPLATE_BODY_MAX_CHARS` the way the name and description counters do
- [v] `원문 복사` copies the current body; `형식 안내 복사` copies `formatGuide()`; both report `복사했어요` (en: Copied) in an always-mounted `role="status"` region for `COPY_FEEDBACK_MS`; when the clipboard is unavailable the 원문 copy leaves the body textarea selected and the guide copy opens the 형식 안내 보기 (en: Show format guide) disclosure with its read-only textarea selected, both showing the manual-copy message; a test covers the success and the fallback of each
- [v] the 형식 안내 보기 disclosure is present in 원문 mode only and holds the same text the button copies
- [v] `formatGuide()` (`entities/template/model/guide.ts`) returns, in the current UI language, a self-contained instruction for an outside AI: what a template is for, the five authorable constructs (`literal text`, `<write>…</write>`, `<slot kind="photo"/>` with optional `count="n"`, `<repeat each="photo">…</repeat>`, `<note>…</note>`) with one line each on what the reader of the post gets, the refusal rules (every non-slot tag closed · slot self-closing with `kind="photo"` only · `count` 1 … `TEMPLATE_PHOTO_ROW_MAX` · `repeat` only with `each="photo"`, never nested · `write`/`note` never empty · any other tag refused · `&lt;` for a literal `<tag`), the body ceiling `TEMPLATE_BODY_MAX_CHARS`, the fixed example `GUIDE_EXAMPLE_BODY`, and the closing instruction to answer with the body only, in the language the user writes in; it never mentions `place`, `link` or `label`
- [v] `guide.test.ts` runs for `ko` and `en`: `GUIDE_EXAMPLE_BODY` parses; the guide contains `<write>`, `<slot kind="photo"`, `count="`, `<repeat each="photo">`, `<note>`, the example verbatim, the two ceilings as digits, and contains none of `place`, `link`, `label=`, `{{` ; the guide and `EVERY_CONSTRUCT`-style fixtures are the only places grammar text is allowed in tests to be visible
- [v] an unreadable body offers two buttons, 원문에서 고치기 (en: Fix in source) and 구성 비우고 다시 만들기; the first switches to 원문 with the textarea focused and the parse error shown, the second keeps its current behaviour; the unreadable copy no longer tells the user to clear as the only way; neither writes anything until 저장
- [v] a template whose stored body does not parse cannot be saved from either mode even after the name is edited (TMPL-30, TMPL-7) — pinned in `TemplatePage.test.tsx`
- [v] `GrammarStaysInternal.test.tsx` is rewritten to the r3 rule — grammar text is visible inside 원문 mode only: the list, the builder mode (every row open), and the unreadable state before 원문에서 고치기 still render none of the `SYNTAX` list; choosing 원문 puts the body in the textarea (`toHaveValue`) and the guide disclosure is present; switching back to 블록 removes both again; the old "offers no mode switch" case is replaced by "offers the switch and nothing outside 원문 shows grammar"
- [v] i18n: ko and en `templates` gain `screen.mode.aria` `screen.mode.builder` `screen.mode.source` `screen.sourceHelp` `source.label` `source.copy` `source.copyGuide` `source.copied` `source.manualCopy` `source.showGuide` `source.error` `source.guide` `composition.fixInSource`; `composition.unreadable` is reworded; every key exists in both languages
- [v] no proto, backend, agent or `shared/api` change; `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` pass on Node 24.18.0

## impl notes
- page (`pages/template/ui/TemplatePage.tsx` `Editor`): `const [mode, setMode] = useState<'builder' | 'source'>('builder')`; `const parsed = parse(trimmed.body, { photoRowMax: TEMPLATE_PHOTO_ROW_MAX })` (the options signature T010/T011 introduced); `blocked = !dirty || !canSaveTemplate(trimmed) || !parsed.ok || pending` — the builder emits only valid bodies so this changes nothing for builder-only flows, and it is what makes TMPL-30's "cannot be saved from either mode" true; render `<SegmentedControl ariaLabel=… value={mode} options=[{value:'builder',label},{value:'source',label}] onChange={setMode} controls={sectionId} />` under the section heading, then `mode === 'source' ? <TemplateSource …/> : <TemplateComposition … onFixInSource={() => setMode('source')} />`; conditional rendering, not hiding — `TemplateComposition` reseeds its rows from the body on mount, which is exactly the TMPL-29 "value from outside" path, so no new sync code is needed
- `TemplateSource` (`entities/template/ui/TemplateSource.tsx`, exported from the entity index): props `value` `onChange(body)` `disabled` `failure: ParseFailure | null` `autoFocus?` `className?`; it is a controlled input over the entity's own field like `TemplateComposition` (TMPL-33), so it belongs in the entity, not the page; body: `FieldLabel` + `Textarea` (`rows={12} autoGrow spellCheck={false} autoComplete="off"`, monospace via the class `technical-detail` uses, `aria-invalid={!!failure}` `aria-describedby` pointing at the error message), `onChange={(e) => onChange(e.target.value)}` with no processing; below it the error `FieldMessage`, the `Count`-style remaining line (lift `Count` out of the page into `shared/ui/field` as `FieldCount` or duplicate the four lines — prefer lifting, it is the third caller), then a row of two `Button variant="secondary"`: 원문 복사 and 형식 안내 복사, the status live region, and a `<details>` with `<summary>` 형식 안내 보기 holding a read-only `Textarea` of `formatGuide()`
- parse failure to copy: the page computes `parsed` once and passes `parsed.ok ? null : parsed.failure`; `TemplateSource` formats `t('source.error', { line: failure.line, reason: t(`builder.reasons.${failure.reason}`) })` — the reason catalog already covers every `ParseReason` including `invalid_count` after T011; a reason with no key would render the key, so `grammar.test.ts` or `guide.test.ts` asserts every `ParseReason` has a `builder.reasons` entry in both languages (reuse the list `grammar.ts` exports, add `export const PARSE_REASONS: readonly ParseReason[]` if it does not)
- copy (`shared/lib` `copyText(text, fallbackElement, canFallback)` as `widgets/export-panel/ui/ExportPanel.tsx` uses it): keep `const [copied, setCopied] = useState<'body' | 'guide' | null>(null)` and a `feedbackTimer` ref cleared on unmount, dwell `COPY_FEEDBACK_MS` from `shared/config`; on `{copied:false}` set a `manualCopy` state that renders `source.manualCopy` and, for the guide, sets the `<details>` `open` so the selected fallback textarea is on screen — `copyText` has already focused and selected it; mock `navigator.clipboard.writeText` the way `ExportPanel.test.tsx` does (resolve for the success case, delete/reject for the fallback case)
- guide (`entities/template/model/guide.ts`, react-free, `i18next` import is fine as `types.ts` shows): `export const GUIDE_EXAMPLE_BODY = '<write>어디를 왜 갔는지 두세 문장으로 시작</write>\n<repeat each="photo">\n<slot kind="photo" count="2"/>\n<write>위 사진 두 장에 대해 한 문단</write>\n</repeat>\n오늘도 좋은 하루 보내세요\n<note>광고처럼 들리지 않게</note>'`; `export function formatGuide(): string { return i18next.t('source.guide', { ns: 'templates', example: GUIDE_EXAMPLE_BODY, bodyMax: TEMPLATE_BODY_MAX_CHARS, photoRowMax: TEMPLATE_PHOTO_ROW_MAX, interpolation: { escapeValue: false } }) }` — `escapeValue: false` is required or `<` in the example becomes `&lt;`; the guide's tags, attributes and the example are identical in both languages by construction because only the surrounding prose lives in the resource; write the ko text as a multi-line template literal in the resource, sections: 목적 → 형식(5 constructs) → 규칙 → 예시 → 답변 방식 (body만, 설명 없이, 사용자가 글을 쓰는 언어로)

## result
The template screen has a second way to edit its composition: 원문 shows the stored body as text with live parse errors, takes a pasted body byte for byte, and hands out a format guide an outside AI can write that body from.

changed
- `entities/template/ui/TemplateSource.tsx` (new, exported from the entity): labelled monospace textarea over `draft.body` with no processing on input, the failure as `{{line}}번째 줄: {{reason}}` in a `role="alert"` wired through `aria-describedby`, the body counter, 원문 복사 · 형식 안내 복사 with an always-mounted `role="status"`, and a 형식 안내 보기 disclosure holding the same string the button copies
- `entities/template/model/guide.ts` (new): `GUIDE_EXAMPLE_BODY` and `formatGuide()` — the tags, attributes and example are identical in both languages by construction, only the prose lives in the resource, and `escapeValue: false` keeps the example's `<` a `<`
- `entities/template/lib/grammar.ts`: `PARSE_REASONS`, so a test can prove the copy catalog covers the whole union
- `entities/template/ui/TemplateComposition.tsx`: the unreadable state takes an `onFixInSource` and offers 원문에서 고치기 before the destructive clear; `composition.unreadable` reworded to name both ways out
- `pages/template/ui/TemplatePage.tsx`: `SegmentedControl` 구성 편집 방식 over a `role="tabpanel"`, one `parse()` feeding BOTH the save gate and the source's error (so they cannot disagree), `screen.sourceHelp` in source mode, and a `focusSource` flag so only 원문에서 고치기 takes the caret
- `shared/ui/field/FieldCount.tsx` (new): the page's private `Count` lifted on its third caller
- i18n ko/en `templates`: `screen.mode.*`, `screen.sourceHelp`, the whole `source.*` block including the guide, `composition.fixInSource`
- tests: `TemplateSource.test.tsx` (byte-exact paste, the error and its wiring, both copies with success and clipboard-refused fallback, the disclosure equals the copied guide, the counter), `guide.test.ts` (both languages: the example parses and appears verbatim, every construct and both ceilings appear, no retired word and no unresolved placeholder, every `ParseReason` has copy), `TemplatePage.test.tsx` (+4: paste-import save is byte-exact · an unparsable body blocks the save from either mode even after a name edit · 원문에서 고치기 focuses the text and shows the error · builder → source → builder keeps the outline), `GrammarStaysInternal.test.tsx` rewritten to the r3 rule, `TemplateComposition.test.tsx` (+2 unreadable cases)
