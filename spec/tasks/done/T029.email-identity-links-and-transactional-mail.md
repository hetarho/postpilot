# T029 Email identity columns, single-use link rows, and the transactional mail port

## goal
Give the auth context everything the self-signup wave builds on — the email columns, the counter and lock columns, single-use link rows, a consumer-owned mail port with a real and a logging adapter, and the bilingual mail bodies — without adding a public procedure yet.

## impl notes
- the login identifier for a self-signed-up account will be the email itself (`users.id = normalized email`, T030), so the `email` column exists for two reasons only: the emailless legacy accounts that register one later (AUTH-40), and one place to look an address up regardless of how the account was created; T030 fills both columns for a signup
- SQLite unique indexes ignore NULL, which is exactly the coexistence the two legacy rows need; do not use a partial index or a sentinel string
- single-use links are ROWS, never signed tokens (AUTH constraints) — a row can be invalidated the moment it is used or superseded; `ConsumeLink` must be a single UPDATE with the predicate in the statement so two concurrent uses cannot both pass (the `SpendFromLot` shape)
- `RETURNING` on UPDATE is supported by SQLite ≥ 3.35 and by modernc; sqlc emits a `:one` query for it
- mail language: the server knows no account locale (LANG-3 keeps the locale browser-local), so every mail carries the Korean text first and the English text under it; keep each body under ~15 lines. LANG-28 lists "backend-rendered copy" as out of scope — that clause predates AUTH-41 and speaks to the app UI; record in the result that update-ssot LANG should add a transactional-mail line
- Resend is chosen over SMTP: an HTTPS call needs no library and no port 587 egress rule on the VPS, the free tier covers this product's volume, and the recipient-rejection case is a structured response rather than an SMTP code to parse; the adapter is the only file that knows the vendor, so swapping it is a one-package change
- bounce handling is deliberately minimal (AUTH-41 asks only that an address stop being retried forever): the synchronous rejection marks the address unreachable; asynchronous bounce webhooks are not built
- `SetMailer`/`SetWebOrigin` are setters for the same reason `SetMonthlyTopUp` is — the auth service is built before most of its collaborators in `cmd/api`
- do not touch the login flow, the interceptor or any proto in this task; T030 starts consuming these
