# T457 Open a storyline attachment large from its tile
> st:done@260929 | ssot:POST-100 POST-96 | base:POST@23 | dep:- | touches:frontend/src/features/edit-storyline/ frontend/src/entities/video/ui/ frontend/src/shared/ui/sheet/ frontend/src/widgets/storyline-space/

## goal
Pressing a photo or video tile in ②'s storyline space (a paragraph or 빠진 사진) opens it large, with previous/next through the space and a close.

## acceptance
- [v] every tile `StorylineTile` renders in a paragraph (`StorylineParagraphEditor`) and under 빠진 사진 (`TakenOutFiles`) is a button named for its file (e.g. `IMG_0412.jpg 크게 보기`); pressing it opens the large view on that attachment
- [v] a photo fills the view fitted inside it (`object-contain`, never cropped); a video plays there with its own controls, while the 64 px video tile shows its first frame and carries no controls of its own (a tap on it opens the view instead of a native scrubber)
- [v] the view carries a close, a position line (`3 / 7`) and previous / next buttons walking the space's order — paragraph 1's files in order, then paragraph 2's …, then 빠진 사진 — disabled at the ends; ← / → keys do the same, Escape closes and focus returns to the tile that opened it (the `Sheet` mechanics)
- [v] the view only shows: it has no move, take-out or put-back control, opening or closing it sends no save and changes no storyline, and it works the same on a read-only (published) post
- [v] a tile whose attachment has no view URL (still converting, or gone) opens nothing — it stays the filename tile it is today
- [v] from `md:` the view is wider than a form sheet (a photo is not squeezed into `max-w-md`); on a phone it keeps the bottom-sheet shape, the photo bounded by the sheet's ceiling
- [v] desktop drag-and-drop between paragraphs still works (a drag that starts on a tile does not open the view)
- [v] tests: `StorylineParagraphEditor` / `TakenOutFiles` (or the space) open the view on the pressed file; next / previous order across paragraphs then 빠진 사진, disabled ends; no `onChange` call from opening, navigating or closing; a tile without a view URL is not a button; the Sheet width variant renders its class
- [v] `pnpm --filter ./frontend test`, `pnpm build:web`, `pnpm lint`, `pnpm lint:fsd`, `pnpm lint:style` pass

## impl notes
- the order is derived, not stored: a `storylineViewOrder(paragraphs, takenOut)` helper in `features/edit-storyline/model` returns the filenames in paragraph order then the taken-out list; unit-test it beside `storyline-edits.test.ts`
- one viewer per space, not per tile: `StorylineSpace` (widget) holds `viewing: string | null` and renders one `StorylineAttachmentViewer` (new, `features/edit-storyline/ui`), handing `onView(file)` down to `StorylineParagraphEditor` and `TakenOutFiles` ← previous/next need the whole space's order, which only the space has; only files with a `viewUrl` enter the walk
- the viewer is `Sheet` (THEME-29 overlay mechanics: portal, focus trap/return, Escape, scroll lock) with the filename as its label, the position line and close in `header`, the media in the body and previous/next in `footer`
- add `size?: 'default' | 'wide'` to `shared/ui/sheet` — `wide` swaps `md:max-w-md` for a wider max width (e.g. `md:max-w-4xl`); keep every other class; the image's height cap is a token in `app/styles/index.css` (e.g. `--spacing-media-view`, derived from `--spacing-sheet` minus header/footer room), never an arbitrary `[..]` value (`pnpm lint:style`)
- video tile: add `controls?: boolean` to `entities/video` `VideoTile` (default true, so the ① strip is unchanged) and pass `false` from `StorylineTile`; the viewer renders its own `<video controls playsInline preload="metadata">` with the `source` type, no autoplay (VIDEO-14's reason still holds)
- the tile button wraps the `figure` (`Thumbnail`/`VideoTile`) — `button` with `aria-label`, the pointer-floor rule does not apply to a 64 px media tile but it keeps the focus ring; the `li` stays the drag source (`draggable`), so a drag and a click stay distinct events
- copy (posts namespace, `storylineEdit`): `view` "{{file}} 크게 보기" / "View {{file}} larger", `viewerPosition` "{{n}} / {{total}}", `viewerPrevious` "이전" / "Previous", `viewerNext` "다음" / "Next", close via the shared `action.close`; no help sentences
