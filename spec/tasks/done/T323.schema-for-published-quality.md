## impl notes
- HEAD's latest migration is `0076_remove_publishing.sql`. This task takes the next free number at implementation time (R41), and T332's guidelines rebuild, dep T323, takes the one after. No other task of this delta adds a migration.
- The migration is transactional: goose's default, with no `NO TRANSACTION`.
- Nothing is rebuilt. SQLite's `ALTER TABLE … ADD COLUMN` accepts a column CHECK that names an already-added column.
- Measured on this schema with SQLite 3.51: the pair CHECK refused `SET published_url` alone and `SET published_at` alone and accepted both in one UPDATE.
- `posts` has no CHECK on `status`, so `'published'` needs no schema change (R4).
- Up 1: `ALTER TABLE posts ADD COLUMN published_url TEXT NULL;`
- Up 2: `ALTER TABLE posts ADD COLUMN published_at TEXT NULL CHECK ((published_url IS NULL) = (published_at IS NULL));` (R8)
- Up 3: `ALTER TABLE posts ADD COLUMN field TEXT NULL;` NULL = 없음 (R1, R12).
- Up 4: `ALTER TABLE posts ADD COLUMN content_nouns TEXT NULL CHECK (content_nouns IS NULL OR json_valid(content_nouns));` (R16)
- Up 5: `ALTER TABLE posts ADD COLUMN replacement_candidates TEXT NULL CHECK (replacement_candidates IS NULL OR json_valid(replacement_candidates));` (R29)
- Up 6: `ALTER TABLE posts ADD COLUMN quality_rules TEXT NULL CHECK (quality_rules IS NULL OR json_valid(quality_rules));` (R23)
- Up 7: `CREATE INDEX posts_user_published_idx ON posts(user_id, published_at) WHERE status = 'published';` It serves the published_at-descending windows (QUAL-39). SQLite uses it only when the read repeats `status = 'published'`.
- Up 8: `CREATE TABLE post_measurements (post_slug TEXT PRIMARY KEY, user_id TEXT NOT NULL, content_revision INTEGER NOT NULL, measure_version INTEGER NOT NULL, char_count INTEGER NOT NULL, photo_count INTEGER NOT NULL, distinct_block_types INTEGER NOT NULL, avg_sentence_length REAL NULL, repetition_share REAL NULL, top_noun TEXT NULL, title_relevance REAL NULL, computed_at TEXT NOT NULL, FOREIGN KEY (post_slug, user_id) REFERENCES posts(slug, user_id) ON DELETE CASCADE);` (R15)
- Up 9: `CREATE TABLE field_phrase_lists (field TEXT PRIMARY KEY, phrases TEXT NOT NULL CHECK (json_valid(phrases)), corpus_size INTEGER NOT NULL, refreshed_at TEXT NULL, next_refresh_at TEXT NOT NULL);` (R24)
- Up 10: `ALTER TABLE templates ADD COLUMN title_area TEXT NOT NULL DEFAULT '';` (R35, TMPL-2)
- `posts_slug_user_idx` (`UNIQUE (slug, user_id)`, from 0022) is the unique parent key SQLite requires for the composite `post_measurements` foreign key.
- `db.Open` sets `foreign_keys(ON)`, so the cascade runs on every DeletePost.
- `post_measurements` has no secondary index: every read is by slug, through the primary key (R15).
- `field_phrase_lists` has no `user_id` and no FK (QUAL-22). `field` carries no CHECK (R1).
- The title area needs no backfill. ADD COLUMN's default gives every legacy template '', which is the no-title-area state (TMPL-52).
- Nothing is seeded, so the phrase lists start empty (QUAL-41, QUAL-42).
- The file's header comment names each column's owner: T329 for the published pair and the index · T337 for `field` and `quality_rules` · T341 for `content_nouns` and `replacement_candidates` · T335 for the two tables · T333 for `title_area`.
- Down 1: `UPDATE posts SET status = 'finalized' WHERE status = 'published';` A published post always holds `finalized_revision = content_revision` (R8), so finalized is its exact pre-delta meaning.
- Down 2: `ALTER TABLE templates DROP COLUMN title_area;`
- Down 3: `DROP TABLE field_phrase_lists;`
- Down 4: `DROP TABLE post_measurements;`
- Down 5: `DROP INDEX posts_user_published_idx;` This must run before `published_at` is dropped.
- Down 6: `ALTER TABLE posts DROP COLUMN …` for `quality_rules`, `replacement_candidates`, `content_nouns` and `field`, in that order.
- Down 7: `ALTER TABLE posts DROP COLUMN published_at;` It goes first because SQLite refuses to drop a column that another column's CHECK names.
- Down 8: `ALTER TABLE posts DROP COLUMN published_url;`
- The plan's "db_test.go's rollback exercises it" does not hold at HEAD, so the new test owns the rollback check.
