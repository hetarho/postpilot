# T187 The writer reads the instruction and lets it outrank guidance
> st:done@260916 | ssot:CLIP-121 CLIP-11 CLIP-31 | base:CLIP@28 ARCH@2 | dep:T186

## goal
Carry the project instruction into the composition request and state that, on content, it outranks the template's authored guidance while the declared structure stays the template's.

## acceptance
- [v] the instruction travels in the composition request beside `composition_source`, the answers and the observations, and nothing else about the request changes (→CLIP-31)
- [v] the prompt states the precedence explicitly: where the instruction and the template's authored `guide` text disagree on what a caption says, how many captions a section gives or which subjects they cover, the instruction wins
- [v] the prompt states the other half just as explicitly: section order, element presence, role, position, timing and every declared maximum stay the template's, and the instruction cannot add a section or an element (→CLIP-116 →CLIP-65)
- [v] a project with no instruction produces a request byte-identical to today's, asserted directly (→GUIDE-18's discipline)
- [v] the instruction is data, never an instruction to the tool: it cannot request footage, tools, another model or a schema change, and the existing untrusted-data sentence covers it
- [v] the instruction counts toward the frozen input allowance, and a project that overflows is refused before paid work with its measured size (→CLIP-90)
- [v] tests: the request carries it, the byte-identical baseline without one, and the overflow refusal
- [v] verify BE (ARCH-26) passes

## impl notes
- `ai/composition_prompt.go` owns both halves: `compositionPlanPrompt` for the precedence sentences and `buildCompositionPlanPrompt`'s payload map for the value
- today's second line reads `Frozen XML is the content authority`; it becomes the structure authority, with the instruction named as the content authority above the template's `guide` text — one sentence, not a section, so the contract stays one screen
- the prompt already ends with the closed response contract; the instruction changes no schema and adds no field to the response

## result
- carriage: `PlanningInput.Instruction` travels from the frozen payload into every planning input `generation.go` builds, and `buildCompositionPlanPrompt` adds `project_instruction` beside `composition_source`, the answers and the observations — nothing else about the request changes
- precedence: today's authority line moved into `compositionAuthority`, and a project carrying an instruction swaps in `compositionInstructedAuthority` — one line naming the XML the structure authority (section order, element presence, role, position, timing, every declared maximum) and the instruction the content authority above the XML's guide text, which can never add or remove a section or an element, request footage, tools, another model or a schema change
- byte-identical: the swap and the payload key both happen only when the instruction is non-empty, so a project without one produces the request it produced before the field existed; the test asserts it directly by clearing an instruction and comparing bytes
- allowance: the instruction rides the writer prompt `ValidatePreparation` measures, so it counts toward the frozen input allowance and overflows before any paid work; `ai.PromptBytes` was added so a caller can state an allowance in the units the refusal reports
- tests: `ai/instruction_test.go` covers the request carrying it with both halves of the precedence stated, the byte-identical baseline, and an overflow refusal pinned to the instruction alone — the same request without it passes the same allowance
- verify: BE (ARCH-26) green, whole suite. FE untouched. ARCH-28 not run: no proto or SQL source changed
