## goal
Billing has one regime — fixed KRW (BILL-2) — so the `fixedKRW` flag, every non-fixed branch, and the legacy monthly-lot credit methods (`StartMonthlyWindow`, `OpenMonthlyLot`, `RaiseMonthlyLot`) they call are gone, and the dev fixture opens benefits the way production does.

## acceptance
- [v] `billing.Service` always behaves as fixed KRW: `WithFixedKRW` and the `fixedKRW` field are removed, and every `if s.fixedKRW { … } else { … }` keeps only its fixed branch (subscribe, change, cancel, resume, cancel-scheduled, upgrade, pack, renew, RunDue)
- [v] the billing `Credits` port loses `StartMonthlyWindow`, `OpenMonthlyLot` and `RaiseMonthlyLot`; `usage.Service` loses their implementations when nothing else calls them
- [v] `internal/devseed` (and `cmd/seed` if it uses them) opens a fixture account's benefits through the same coverage path production uses (`OpenCoverage` or the fixed-KRW subscribe flow with a fake provider), so a seeded paid account has the grant lots and export window a real subscriber has
- [v] billing tests that ran the non-fixed service move onto the fixed-KRW service (the real-store `fixedService` harness or the fake store with the fixed flow); assertions about legacy-only behaviour are deleted, every BILL rule they also covered stays covered on the fixed path
- [v] behaviour unchanged in production: ARCH-26 green; `pnpm gen:sql` clean (ARCH-28)
