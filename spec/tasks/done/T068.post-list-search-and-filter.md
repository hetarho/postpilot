## goal
The post list carries one search field and one status filter, both held in the URL, narrowing the one list answer in the browser.

- [v] the `/posts` route validates its search params to `{ q?: string; status?: 'draft' | 'review' | 'finalized' }` and drops anything else without saying an error
- [v] `features/filter-posts` holds a pure `narrowPosts(posts, { q, status })` returning the kept rows in server order, each with the tags that matched; it trims, lowercases, collapses whitespace and ignores a leading `#` on the query; a blank query with no status keeps every row

## impl notes
- the URL is the single source for both controls (POST-67): the field is controlled from `useSearch` and each keystroke navigates with `replace: true`; no debounce and no local mirror ← the narrowing is a scan over one already-loaded array (`ListPosts` has no paging, POST-3), so a debounce would only make the field lag behind what was typed, and `replace` keeps 뒤로 meaning "the previous screen"
- placement (ARCH-14, ARCH-15): the verb is the user's, so `features/filter-posts` with `model/narrow.ts` + `model/narrow.test.ts`, `ui/PostListControls.tsx` and one `index.ts`; `pages/posts` composes and owns no narrowing logic; `entities/post` only carries the new field
- `narrowPosts` returns `{ post, matchedTags }[]` rather than a filtered array ← the row must be able to name only the tags that matched without the view re-running the match
- the search matches `post.title` as stored, not the 제목 없음 placeholder ← the placeholder is the list's word, not the post's text; a tag match covers such a post instead
- the filter keys on `post.status` alone (POST-66); `activeJob` and `pendingExperimentId` change the badge, not the status, so a generating draft stays under 초안
- matched tags render as `meta` text beside the voice and the time, NOT as the `rounded-sm` chip ② uses (owner decision at create-task) ← a fourth visual object in a 360px row, and copying the chip would be a second copy of a shape nobody has extracted (THEME-10)
- dep on T067 is a file-level one: both tasks edit `pages/posts/ui/PostsPage.tsx`, so they must not run in parallel
- no new config value: no debounce constant and no result cap, since the list is one answer
