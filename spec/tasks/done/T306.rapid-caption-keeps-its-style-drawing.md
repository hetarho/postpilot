# T306 a rapid-paced caption keeps its own style's drawing
> st:done@260922 | ssot:CDS-4 CDS-85 CDS-52 CLIP-157 | base:CDS@25 CLIP@43 | dep:-

## goal
A server render draws every caption in the drawing its own style declares at both paces, so a rapid phrase loses its motion and nothing else.

## acceptance
- [v] a rapid-paced caption in a sequence-rendered style renders in that style's own drawing — its plate, outline, colour and face — with no fade, no movement and one rasterisation for its whole window
- [v] no caption ever renders with an empty fill: 아웃라인 renders hollow and 스티커 · 버블 · 스택 render their own plate under their own ink at either pace
- [v] the bundled caption template is reached only by a static style; a sequence style reaching it is refused by name rather than drawn with the rule's plate and the style's raw paint
- [v] the drawing a caption renders with is the drawing its preview fragment showed, for every approved style at both paces
- [v] CDS-52's V9 fails a caption drawn in anything but its own style's drawing, whatever its pace
- [v] go test: a rapid sequence-style caption produces one layer drawn by its own painter and an overlay chain with no fade or dy; the static template refuses a sequence style; a golden covers 스티커 and 아웃라인 at rapid pace
- [v] the media image stage is built and run locally (ARCH-37): `docker buildx build --target media-smoke -f backend/Dockerfile .`
- [v] verify: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...`

## impl notes
- the defect: `media/composition_plates.go` `declaredLayer` takes the sequence path only when `!Static() && Pace != "rapid"`, so a rapid caption in a sequence style falls to `declaredSVG` → `overlays.Render("copy."+style, copyView(...))`. That template draws a plate only from the RULE (`design.json` `regions.caption.*.plate` is `""` for every style) and paints `Paint.Fill` raw, so 스티커 `#1A1C22` and 버블 `#10130A` become near-black text with no white plate, and 아웃라인's deliberately empty fill emits `fill=""`, which SVG resolves to black
- fix at the same branch: a rapid caption in a sequence style rasterises ONE frame through the style's painter — `captionFrame(canvas, copy, layout, duration, representativeProgress)` + `design.DrawCaptionFrame`, which is exactly what `captionDocument` already builds for the preview — and enters the chain as that one plate. CDS-81's cost promise holds: one rasterisation, not one per frame
- the overlay chain needs no branch: `elementMotion` already returns zero in/out/dy at rapid pace, so the static branch of `declaredOverlayGraph` loops the plate and adds no fade
- keep the crop the sequence path uses (`sequenceCrop`) for that one frame, so a style's bleed — the sticker's shadow, the ember glow — is not clipped by the caption's measured box
- `declaredSVG`'s `case "caption"` then holds only static styles: make it return an `elementProblem` naming the style when it is handed a sequence one, which is CDS-85's refusal by name
- V9 lives in `design/verify.go` against the manifest; the manifest element already carries `Style`, so the check is that a drawn layer's style and its drawing agree — record the drawing kind on the element rather than inferring it at verification time

## result
- `media/composition_plates.go`: `declaredLayer` took the sequence path only when the pace was not rapid, so a rapid phrase in a sequence style fell to the bundled template. That template draws a plate only from the RULE — `design.json`'s `regions.caption.*.plate` is `""` for every style — and paints `Paint.Fill` raw, so 스티커 `#1A1C22` and 버블 `#10130A` became near-black text with no plate, and 아웃라인's deliberately empty fill emitted `fill=""`, which SVG resolves to black. A rapid phrase now takes ONE frame of its own style's drawing through `captionDocument` — the frame ②'s preview shows — and keeps CDS-81's one rasterisation.
- `declaredSVG`'s caption branch refuses a sequence style by name (CDS-85): after this change only a static style can reach the bundled template, and a regression that sent one there fails rather than drawing it as something else.
- the drawing is recorded where the verifier reads it: `design.Element.Drawing`, stamped by `CompositionElement.RecordDrawing` at the moment the layer is drawn, and CDS-52's V9 fails a caption whose drawing is not its own style's. The field is `omitempty`, so a layout's own manifest identity is byte-identical and the anchor golden did not move.
- deviation from the acceptance as written: instead of a golden for 스티커 and 아웃라인, `caption_drawing_test.go` loops EVERY approved style at both paces and asserts the drawn layer is the style's own drawing, carries no `fill=""`, keeps its plate and its ink, records its drawing and passes V9. Reverting the one branch fails all 13 sequence styles at rapid pace and nothing else — checked by reverting it.
- `caption_style_test.go` drew a sequence style through `declaredSVG`; it now uses `captionDocument`, which is the one drawing per style.
- verification: backend gofmt/vet/build/test green; `docker buildx build --target media-smoke -f backend/Dockerfile .` built and ran clean — TestMediaSmoke, TestMediaProfileSmoke and TestRenderSmoke all PASS, including every ratio and the caption-timed and bright-scrim cases.
