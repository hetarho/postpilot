## impl notes
- proto: keep `Image` untouched; `Video` is its own message so the browser can tell the kinds apart without a discriminator; `AttachmentKind` unspecified = photo so every shipped client keeps working; number the new `Post` field 23 (22 is `content_language`); add `DeleteVideo` next to `DeleteImage` in `PostService`
- post types: `Video{ID, PostSlug, Filename, Key, ContentType, Bytes, DurationMs, Width, Height, CreatedAt}`; `Upload` gains `Kind` and `ContentType`; `Observation` gains `Events []string` and `Speech string`, JSON-encoded with the existing entries (`events` `speech` omitted when empty so old rows decode unchanged)
- service: split `CreateUpload` into a shared reservation path with a kind switch — photo path byte-identical to today (`uploadContentType`, `.jpg` key, `ErrTooManyPhotos`); video path chooses content type by lowercase extension; the filename check queries `ImageFilenameTaken OR VideoFilenameTaken`; `replacePendingUpload` already handles the pending case and only needs the kind-agnostic key delete
- confirm: read the upload row first; branch on `Kind`; for video verify `head.ContentType == upload.ContentType` — MinIO and R2 both echo the PUT's type; `ErrInvalidVideo` maps to `InvalidArgument` in the rpc with the existing image error mapping pattern
- store: `store/queries/videos.sql` (`CreateVideo` `ListVideosByPost` `GetVideo` `DeleteVideo` `VideoFilenameTaken` `CountVideosByPost` `ListAllVideoKeys` `VideoKeyInUse`); `uploads.sql` `CreateUpload` gains kind and content type; sqlc via `pnpm gen:sql`
- sweep (`sweep.go`): the referenced-key set unions `ListAllImageKeys` and `ListAllVideoKeys`; the `posts/` prefix listing already covers video objects because they share the prefix
- content validation (`content_edit.go`): add `BlockVideo` to the type set; the attachment filter takes two filename sets; keep `IMAGE`↔photo and `VIDEO`↔video strict — a filename is unique across kinds so a mismatch is a wrong type, not an unknown file
- generation port (`generation/ports.go` `Posts.AttachedImages`): extend `generation.Image` with `Kind` (`photo` | `video`), `ContentType`, `DurationMs` rather than adding a second slice — the reobserve selection, freezing and merge functions all iterate one list by filename; this task only fills the fields, T014 uses them
- FE is untouched except the regenerated client under `shared/api/gen`; nothing in the browser sends `kind` yet, so the photo path stays green

differs from the task, deliberately
- `AttachmentKind`'s values are `ATTACHMENT_KIND_PHOTO`/`ATTACHMENT_KIND_VIDEO`, not the bare `PHOTO`/`VIDEO` the acceptance wrote. Proto enum values are siblings of the enum in the package scope, so a bare `VIDEO` collides with `BlockType.VIDEO` and the file does not compile. Enum and field names are as specified.
- `CatalogEntry.video_input` is field 28, not 27: 27 is `reasoning_known`.
- `ObjectStore.Head` had to change shape (`int64` → `ObjectHead`) for the confirm's content-type check. One implementation and two fakes.
- `PublishingSnapshot` reads the post's videos for its revalidation only and still carries none: without them the validator would reject a legitimately attached clip as an unknown file. The snapshot's shape and content are unchanged (POST-21).
