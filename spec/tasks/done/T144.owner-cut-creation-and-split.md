## goal
Allow an owner to add footage from an observed scene or split a saved cut through the existing full-plan save without trusting invented identities or meaning.

## acceptance
- [v] `SaveClipEditPlan` accepts a new cut only with one-time creation provenance and a canonical `owner-<UUIDv4>` id, then returns and stores the approved cut without creation metadata; existing ids reject creation metadata.
- [v] An ADD range is fully contained in one retained observed scene, matches an owned source id and fingerprint, touches no selected range from that source and derives its template section and item binding from frozen owner evidence rather than client-authored facts.
- [v] A new ADD cut starts at 1x with a hard incoming cut, server-derived focal point, inherited source-audio authority, full per-cut volume and no copied caption, chip or text element; it creates footage, not a new claim.
- [v] SPLIT keeps the parent id and cut-bound content on the left, creates a text-free right cut at an interior source timestamp, and preserves source, fingerprint, rate, focal, volume, audio authority and portable binding without duplicating meaning.
- [v] The parent retains its incoming transition and the right cut starts with a hard cut; endpoint splits, a transformed side too short for the contract, missing/retired origins, duplicate ids, foreign sources, observation gaps and new or enlarged overlap are rejected with the exact affected cut.
- [v] An accepted owner cut joins portable active/retired identity history, so delete followed by save and later undo restores only the same validated cut and binding; forged retired identities cannot be resurrected.
- [v] Split or rate edits never proportionally move, duplicate or drop authored caption/element windows; an out-of-range window remains in the client draft and prevents save/render until the owner corrects it.
- [v] Correction domain, history, portable-plan, store and RPC tests cover add, split, reorder, delete/save/undo, same-source adjacency, identity forgery, provenance mismatch, evidence bounds and unchanged legacy overlap.
- [v] Run applicable ARCH-25 through ARCH-29 checks and deterministic protobuf generation with dirty-workspace snapshot protection.

## impl notes
- Extend `ClipEditCut` with optional request-only `ClipCutCreation { kind, origin_cut_id }`; admit `kind` values `add` and `split` only. Use the existing full-plan optimistic save so a temporarily invalid local draft is never prematurely committed by a separate mutation RPC.
- Require an origin cut for both operations. ADD inherits only the origin's template section/order anchor, then reruns evidence and owner-association binding for the new scene; uncertainty leaves the item unassigned. SPLIT inherits the exact existing binding.
- Normalize server-owned defaults after validating the submitted range and provenance. Do not trust client focal, audio, binding, copies or rate on first ADD, and do not allow creation metadata to persist in JSON.
- Keep half-open source intervals; adjacent endpoints are valid and any positive intersection is overlap. Grandfather only an identical legacy overlap already present in the saved plan.
- Preserve the left cut's exact cut-relative text and timing after SPLIT and create no right-side text. Existing validation then exposes any interval no longer contained by the transformed left duration.

## result
Files: `proto/postpilot/v1/clip.proto` · `backend/internal/clip/cut_creation.go` (new) `cut_creation_test.go` (new) `correction.go` `correction_composition.go` · `clip/store/cut_creation_test.go` (new) · `clip/rpc/correction.go` `correction_test.go` · `frontend/src/entities/clip-project/{model/edit-plan.ts,api/edit-plan.ts,model/edit-plan.test.ts}` and generated code.

- Creation rides the existing full-plan optimistic save, not a separate mutation, so a temporarily invalid local draft is never committed on its own. `ClipCutCreation` is request-only: an id the server already knows refuses it, an id the server does not know requires it, and nothing about it reaches stored JSON or the editing projection.
- Admission is `admitOwnerCut`. ADD needs a canonical `owner-<UUIDv4>` id, an owned source identity, a range contained whole in ONE retained observed scene, and no positive intersection with the plan's own footage; it takes the observation's focal point, 1x, a hard incoming cut, full volume and no content. SPLIT keeps the parent id and content on the left and creates a text-free right cut at an interior timestamp of the parent's ORIGINAL range, inheriting source, fingerprint, rate, focal, volume and the exact portable binding.
- A new item binding is re-derived from the owner's own associations for the new scene: one unambiguous answer binds it, and none or several leave it unassigned rather than inventing one.
- Refusals are a new `CutError` that names the exact cut and keeps the invalid-plan identity; each refusal test asserts its own reason, so no case can pass because an unrelated check fired first.
- An accepted cut joins the portable active/retired history with its binding, so delete → save → undo restores the same validated cut; a retired id that claims creation is refused, and a forged owner id is admitted only as genuinely new footage with no content to resurrect.
- Split and rate edits never retime authored text: the existing interval resolution refuses a window the shorter cut no longer contains and leaves the owner's draft untouched, which a test pins.
- Deviations: the legacy (non-portable) correction path refuses creation outright, because it has neither frozen observations nor a template binding to check against. The store test needed the first `LayoutComposition` fake in the suite — the native correction save path had no store-level coverage before this task.
