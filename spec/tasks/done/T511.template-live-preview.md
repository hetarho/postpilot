# T511 Show a live placeholder preview beside the template composition
> st:done@261001 | ssot:TMPL-65 TMPL-66 TMPL-67 TMPL-26 TMPL-37 | base:TMPL@18 | dep:- | touches:frontend/src/entities/template frontend/src/pages/template frontend/src/shared/ui/media-query

## goal
The template editor shows the post its draft makes as a placeholder preview, redrawn on every edit, beside the composition on a wide screen and one tap away on a phone.

## acceptance
- [v] `entities/template/ui/TemplatePreview` takes `{titleArea, body}` and renders the reading view's look (`entities/post/ui/BlockList.tsx` article spacing and Typography roles), the title area first in the `title` role, then the body:
  - an AI가 쓰는 글 (`<write>`) is a grey paragraph box (`bg-surface-recessed`, rounded) holding what its place is about in `text-content-secondary`
  - a 고정 문구 is its own text in the `body` role with `whitespace-pre-wrap`
  - a 사진 with `count` n is one row of n grey `aspect-square` cells
  - a 사진마다 반복 draws its children twice inside one frame labelled 사진 그룹마다 반복
  - a 데이터 받기 field shows its 제목 over an 입력한 내용 placeholder: as plain text for an empty `<ask>`, inside the grey box beside its topic for an `<ask>` holding text
  - a stored `place`/`link` slot is the 고정 문구 it reads as (its label, falling back to 지도 · 링크, →TMPL-37)
  - in the title area the same stand-ins sit inline on one title line
  - an empty draft shows one line saying the preview appears once the composition has blocks
- [v] It keeps the last parsable state of each area: while the current text does not parse it shows that state with a notice naming the area and line in the `builder.reasons` copy; before any successful parse it shows the notice alone.
- [v] It shows no grammar syntax and neither generation number, and makes no request: `GrammarStaysInternal.test.tsx` covers the preview in builder mode and on the phone's 미리보기 panel.
- [v] `TemplatePage` layout: at `lg` and wider a two-column grid — left the existing editor (fields, 블록/원문 switch, composition), right the preview, `sticky` below the header and scrolling on its own when taller than the viewport; the page widens to `pageStyles({width: 'board'})` at `lg`. Below `lg` a `SegmentedControl` 구성 / 미리보기 (`controls` set, full width) sits above the composition area and switches which panel shows; 블록/원문 stays inside 구성; the name, description and number fields stay above the switch.
- [v] The body's sticky add toolbar no longer bleeds full width at `lg` (its `-mx-4 … lg:-mx-8` margins fit the left column), so it never covers the preview column.
- [v] Tests: each stand-in, the repeat drawn twice, title area first, last parsable state plus notice, the phone switch toggles panels with the right `aria-controls`, both panels at `lg`; existing `TemplatePage*.test.tsx` pass. ARCH-25 verification runs green.

## impl notes
- Parse with `parseTemplate(titleArea, body, TEMPLATE_PARSE_OPTIONS)` from `entities/template/lib/grammar.ts`; render from its nodes, never from regexes over the text. The page already parses once (`TemplatePage.tsx` ~l.237); pass the strings and let the preview parse, or pass the parse result if that avoids a second parse — either keeps one parser.
- There is no side-by-side editor/preview in the app yet. Sticky precedents: `lg:top-header lg:sticky` in `AuthenticatedLayout`, the `top-chrome` bars; use the `--spacing-header` token for the offset. Prefer CSS (`lg:grid`, `lg:hidden` on the switch, `hidden lg:block` on a panel) over JS for the breakpoint; add an `LG_MEDIA_QUERY` to `shared/ui/media-query` only if a JS branch is unavoidable.
- The phone switch's state is page-local and resets to 구성 on mount; it never touches the draft or the dirty guard.
- Copy (ko and en) lives in `pages/template/config/i18n.ts` for the switch and in `entities/template/config/i18n.ts` for the preview's stand-in labels.
