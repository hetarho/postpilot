# T218 A clip generates without a template
> st:done@260917 | ssot:CLIP-5 CLIP-25 CLIP-130 | base:CLIP@32 | dep:T217

## goal
Make the video template optional end to end: minting, generation admission, the frozen payload and every prompt.

## acceptance
- [v] `/clips/new` mints a project with no template and `clip_projects.template_id` stays nullable through creation, generation and rerender
- [v] generation admission runs with no template: the required-field check has nothing to require, and CLIP-102's structure check is skipped rather than failing
- [v] the flow prompt and the narration prompt add no bytes at all when no template is attached, and a golden prompt fixture pins the byte-identical no-template prefix (→TMPL-12)
- [v] a rerender and a revision run on a project whose template was deleted mid-flight, using the retained composition
- [v] the frozen payload decodes with an absent template on restart-resume
- [v] prompt-builder and admission tests cover present-template and no-template paths
- [v] ARCH-26 passes

## impl notes
- the template guide section is omitted whole, not emitted empty ← an empty heading changes the prompt prefix and breaks the byte-stability the write/revise prompts rely on
- admission keeps refusing an answer above its effective maximum even with no template, because CLIP-117's position maxima still apply to the project's own instruction
- no migration: `template_id` is already nullable from the CLIP-9 detach trigger; only the admission and prompt paths assume presence

## result
Changed: `clip/composition_state.go` (new: `EmptyCompositionBody`, `NoTemplateComposition`, `ProjectComposition.NoTemplate`; `GenerationComposition` and `projectComposition` answer an absent template with the empty document) · `clip/service.go` (minting and patching accept no template, and 없음 clears one) · `clip/quotes.go` and `clip/store/quotes.go` (both quote gates stop reading a template that is not there) · `clip/ai/service.go` (a no-template input carries no recipe and the server's own empty document) · `clip/ai/flow_prompt.go` `narration_prompt.go` (the guide section is omitted whole). Tests: `clip/ai/no_template_prompt_test.go` with `testdata/flow-prompt-prefix.txt` and `testdata/narration-prompt-prefix.txt`, `clip/store/no_template_generation_test.go`, `clip/rpc/project_design_test.go`.

- A project with no template freezes the grammar's minimum document: one empty hook, one empty ending, no field, no group, no badge, no guide. Nothing of it renders (CDS-73), so the clip is its footage and its narration — and every downstream check (`Parse`, `ValidateCompositionInputs`, the layout, V20) keeps working on a real document rather than on a nil one. CLIP-102's structure check is therefore not special-cased: it runs and finds nothing to require.
- The empty document still states the design attributes the grammar demands of a root. They are inert — what a region renders in is the project's (T217) — and the comment says so where it is built.
- The guide section is omitted whenever it is empty, not only when no template is attached, which is what "omitted whole, not emitted empty" means for a template that simply says nothing. `UPDATE_PROMPT_GOLDEN=1 go test ./internal/clip/ai/` re-records the two prefixes.
- The frozen payload's absent template is covered by the run itself (the worker decodes it with `DisallowUnknownFields`) plus an explicit assertion on the stored job payload, rather than by a separate restart harness.
- `hydrateComposition` was deliberately left alone: a project with no STORED snapshot and no template is a pre-composition legacy project, and it keeps hydrating to its legacy document so its answers still reach a correction.
