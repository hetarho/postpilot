# T319 A lab comparison writes nothing to its post
> st:done@260922 | ssot:MODEL-31 MODEL-66 GEN-11 GEN-19 ARCH-6 ARCH-7 ARCH-24 | base:MODEL@16 GEN@8 ARCH@7 | dep:-

## goal
- A write comparison started in the model lab keeps its preparing observation in the frozen snapshot and leaves the source post's own observations exactly as they were.

## acceptance
- [v] Preparing a `lab` write comparison with photos observes into the snapshot and writes no observation onto the post: the post's observations, and its `updated_at`, are unchanged from before the start.
- [v] Preparing a `lab` write comparison on a post with no attachments leaves the post's observations alone instead of clearing them.
- [v] Preparing an `editor` write comparison persists exactly as it does today, including the clear for a post with no attachments.
- [v] Both candidates still read the same complete observation set, so the frozen input and its hash stay the comparison's identity; a retry of a prepared snapshot re-reads it and observes nothing again.
- [v] A snapshot frozen before this change decodes as an editor comparison and keeps persisting, so a queued job that survives the deploy behaves as it was started.
- [v] Running a lab write comparison end to end against a finalized post changes no post row: no observations, no content, no status.
- [v] Tests: generation (lab prepares without persisting, with and without attachments; editor still persists; prepared snapshot is a no-op on retry; a pre-change snapshot persists), experiment/service or cmd wiring that the origin reaches the snapshot, and the existing reobserve/language/guideline suites still pass.

## impl notes
- `generation.SnapshotWriteInput` gains a trailing `snapshotOnly bool`; `experimentSnapshot` gains `SnapshotOnly bool \`json:"snapshot_only,omitempty"\``. Absent is false, which is persist — exactly what a snapshot frozen before this change means, so a surviving queued job keeps its old behaviour without a migration.
- `PrepareWriteInput` reads that flag: with it set, skip the `SetObservations(..., nil)` branch for an attachment-less post (compute `snapshot.Observations = nil` in memory only) and call `observeCandidate(..., persist: false)`. Everything else — the merge, the freeze-time seed, `Prepared`, the hash — is untouched, so both candidates still read one complete set (GEN-11 continues to describe the editor's persist only).
- The value comes from the experiment's origin, which `experiment.StartRequest` already carries (T314): `cmd/api/adapters_experiment.go` passes `request.Origin == experiment.OriginLab`. Generation is told a plain bool rather than an origin, because it must not learn that experiments have origins (ARCH-7).
- Nothing else in a lab comparison's path writes to a post: `RunObserveCandidate` already passes `persist: false`, `RunWriteCandidate` writes nothing, and the verdict and its applications are already gated by origin and post status (MODEL-36, MODEL-37, T314). The acceptance's end-to-end check is there to prove that claim rather than to add a gate.
- Deliberate consequence to leave as it is: applying a lab write winner puts content on the post without the observations that produced it, because a lab comparison never writes observations. The post's contact sheet is what the post itself observed, and that is what MODEL-66 asks for.
- Existing `SnapshotWriteInput` callers in tests pass the new argument as `false`, which keeps them describing the editor path they were written for.

## result
- `experimentSnapshot` gained `snapshot_only`, set from the comparison's origin at freeze time and read by `PrepareWriteInput`. With it set, the preparing observation runs with `persist: false` and the attachment-less branch no longer clears the post's observations; everything else about the freeze, the merge and the hash is unchanged, so both candidates still read one complete set.
- Absent means false, which persists. That is exactly what a snapshot frozen before the field meant, so a queued job that survives the deploy behaves as it was started; a test strips the key from a fresh snapshot to pin it.
- `cmd/api/adapters_experiment.go` passes `request.Origin == experiment.OriginLab`. Generation is handed a plain bool rather than an origin, because it must not learn that comparisons have one (ARCH-7).
- The defect this closes: a lab write comparison persisted its observation onto the source post whatever the post's status, so running one on a finalized post changed it. The verdict and its applications were already gated (T314); the start was not.
- Deliberate and left as it is: applying a lab write winner puts content on the post without the observations that produced it, because a lab comparison never writes observations. The post's contact sheet stays what the post itself observed, which is what MODEL-66 asks for.
- Validation on Linux, Go 1.26.4: gofmt and go vet are clean and every backend package passes. `cmd/api` needed a raised limit and took 690 seconds, past Go's default per-package ceiling, as `internal/clip/store` also does. This task changes no proto and no SQL, so no generated code moves.
- Nothing else in a lab comparison's path writes to a post. `RunObserveCandidate` already passed `persist: false`, `RunWriteCandidate` writes nothing, and the verdict paths are origin- and status-gated. A service test pins that the origin reaches whatever freezes the input, which is the seam the decision turns on.
