# T583 Remove what the fixed-KRW billing left behind
> st:done@261005 | ssot:ARCH-3 ARCH-43 ARCH-24 | base:ARCH@15 BILL@9 | dep:- | touches:proto/postpilot/v1/ backend/internal/billing/ backend/internal/platform/db/migrations/ backend/internal/gen/ frontend/src/

## goal
Nothing in billing still serves the deleted regime: the never-emitted `PURCHASE_TOO_SMALL` reason is retired the ARCH-43 way, the caller-less `RefundPurchase` is gone, the USD columns on billing events and purchases are dropped, and the checkout journal is part of the billing store instead of a type-asserted extension.

## acceptance
- [v] `PURCHASE_TOO_SMALL` leaves the proto enum with its number and name `reserved` (ARCH-43); `ErrPurchaseTooSmall`, its RPC mapping, the FE i18n entries and the app-failure spec entry are removed; the typed-reason coverage test and the FE enum-mirror tests pass (regenerate through `pnpm gen:proto`, never hand-edit generated code — ARCH-3, ARCH-28)
- [v] `billing.RefundPurchase` and any provider method or port only it used are deleted
- [v] a forward migration drops the USD columns of the billing events and credit purchases tables; the store stops reading and writing them; the history surfaces show the same KRW values as before (BILL-15)
- [v] `IntentStore` is folded into the billing `Store` port (or its methods join it), so no `tx.(IntentStore)` / `s.store.(IntentStore)` type assertion remains
- [v] behaviour unchanged otherwise: ARCH-26 green; FE gates green; `pnpm gen:proto` and `pnpm gen:sql` clean after commit; the T571 migration lint passes on the new migration
- [v] leave nothing "still open" that is a deletion or a fold-in of this kind; anything that would need a product decision is recorded in limits instead of done

## impl notes
- left open by T582 (perf-cost follow-ups); decided under the owner's run-to-push instruction of 261005
- pre-alpha data is disposable (owner, 260927): dropping the USD columns needs no backfill
- dropping columns in SQLite: use `ALTER TABLE … DROP COLUMN` where the column has no index, trigger or CHECK referencing it; otherwise rebuild the table the 0126/0129 way with a scoped FK guard (T571's lint enforces the scope)
