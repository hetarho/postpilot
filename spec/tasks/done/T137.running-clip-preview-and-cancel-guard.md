## goal
Keep original footage visible during clip production and require one informed confirmation before requesting cancellation.

## acceptance
- [v] A queued/running generation or rerender shows one labelled original player and selectable source strip from the existing upload session; selecting a source cannot change, restart or cancel the job.
- [v] Reopening loads authorized retained playback, missing/loading/failed access is explicit, and the source viewer exposes no upload/replacement/discard or correction controls while production continues.
- [v] Preparation is labelled as a server work stage distinct from original playback; one real progress region and list navigation remain reachable at phone widths in both languages/themes.
- [v] The first cancel click only opens a confirmation with the current applicable cost rule and distinct continue-production / cancel-production actions; dismissal/Escape sends no cancellation and explicit confirmation sends at most one request.
- [v] An open confirmation cannot cancel a replaced, completed or already-cancelling job; lost replies keep existing read-only reconciliation, and unsupported cancellation stays disabled without an unsupported claim about historical pricing.
- [v] Component/page regressions cover local/retained/missing footage, source switching, no implicit job operations, free manual cancellation, reserved/exempt cost text, confirmation dismissal/double activation and completion/replacement races.
- [v] Run applicable local ARCH test/lint/formatter/build/spec checks and review 320/360/390/430 px ko/en light/dark running and confirmation states; leave T008/T110 owner gates untouched.

## impl notes
- Extend the existing source picker with a read-only presentation used only by the focused page; reuse ClipSourceSession ownership, playback deduplication and bounded refresh, with no database/proto/provider change or eager source download.
- Render only one selected full player, bounded by existing scale tokens, with normal play controls and no automatic playback; the source strip may retain its existing non-playing metadata thumbnails.
- Use the existing Dialog/Sheet primitive; add an optional generic dismissal label with the current default preserved, bind confirmation to the job id and canCancel state, and retain useCancelClip request locking/reconciliation.
- Keep the reservation-based formula and policy-version eligibility unchanged; unsupported/missing capability explains that cancellation is unavailable rather than inferring why the job was created.
- Update ClipLifecycle and source-picker tests plus focused race/cost cases; use local synthetic media for browser review, with no paid generation or server restart that could interrupt the active owner job.
