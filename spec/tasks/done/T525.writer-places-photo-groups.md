## goal
The write, storyline-following write, revision and write comparison can return GALLERY blocks, normalized photo by photo, with the format in the static rules, the grouping judgment as a 기본 지침 and a template count rendered as a suggested group.

## acceptance
- [v] write, along-storyline and revise JSON schemas list `GALLERY` and require `files` and `layout` on every block; the parser reads both
- [v] block validation drops a GALLERY with no non-blank file, or with `content` or `items`; it clears a GALLERY's stray `file`, and clears `files`/`layout` on every other block type without dropping it
- [v] the attachment filter (write and revision alike) normalizes a GALLERY: unattached names dropped, a repeated name keeps its first place, one photo left → an IMAGE with the group's alt and caption, none left → dropped, beyond `post.PhotoGroupMax` → the surplus continues as the next group of the same layout with no caption (a lone surplus photo → an IMAGE with no caption), an absent or unknown layout → COLLAGE
- [v] the Korean and English write and revise static rules name GALLERY, its fields and the 2 … `PhotoGroupMax` bound, and say each photo stands once alone or inside one group; the output-language lines cover GALLERY alt and caption
- [v] a template photo place renders `{{사진 자리}}` for count 1 and `{{사진 자리 · n장 묶음}}` for n > 1, and the legend explains both as a suggestion the writer may follow or not
- [v] 기본 지침 `photo_groups` (비슷한 사진은 한 묶음으로) follows `photo_moments` for the post kind in both languages
- [v] write-comparison candidate output, its snapshot and the experiment RPC carry `files` and `layout`; the experiment RPC block-type map also covers VIDEO and GALLERY
- [v] Go tests: schema/parse, validation cases, every filter normalization case above, revision filter, prompt goldens regenerated and reviewed, template Render markers, experiment round trip, guideline key order
- [v] ARCH-26 passes; no paid provider call is made (stubs only)

## impl notes
- `generation/types.go`: `BlockGallery = "GALLERY"`, `Block.Files []string`, `Block.Layout string` (generation keeps protojson spellings; COLLAGE/SLIDE as constants). Map both ways wherever blocks cross the boundary: `cmd/api/adapters_generation.go` (post ↔ generation, both places), `generation/revise.go` `contentForPrompt`, `generation/experiment_snapshot.go` `snapshotBlock` (new keys `Files`/`Layout`, omitempty, matching that struct's capitalized style so old snapshots decode), `cmd/api/adapters_experiment.go` `outputBlock` (`files`/`layout`, omitempty), `internal/experiment/rpc/handler.go` `outputBlock` + `setOutput` + `blockType` (add VIDEO — currently mapped to UNSPECIFIED — and GALLERY) + layout to the proto enum.
- `parse.go` `blockJSON`: `Files []string json:"files,omitempty"`, `Layout string json:"layout,omitempty"` — omitempty so the revise prompt's current-content JSON shows them on a group only; parsing is unaffected.
- schemas (`write_answer`, `write_along_storyline_answer`, `post_content`): block properties gain `"files": {"type":"array","items":{"type":"string"}}` and `"layout": {"type":"string"}`, both in `required` (strict structured output requires every property), `type` enum gains `GALLERY`. No enum on `layout`: an empty-string enum member is not portable across providers, and the filter normalizes it.
- validation (`blocks.go`): GALLERY rules above; for non-GALLERY types `Files`/`Layout` are normalized away like `level` ← the schema requires them on every block, so a schema-obedient `[]`/`""` (or a stray value) is not a malformed block.
- normalization lives in `attach.go` `FilterAttachments` (it already runs on write and on revision with the fresh snapshot, GEN-41): trim names, keep attached photos only, dedupe keeping first, then the one/none/overflow rules; layout upper-cased and trimmed, else COLLAGE. Log drops as the IMAGE path does.
