## goal
Move every placement and style decision out of the model and into the CDS rule tables: the model reports scenes and writes grounded copy, the compiler classifies, selects, times, falls back and verifies.

## impl notes
- the model stops choosing style and position because CDS-7 needs the same input to give the same output and a model choice cannot be replayed; the model is still the only writer of copy, `short_text`, `hook` and `scene`, which are judgments a table cannot make
- `short_text` in the same call replaces CDS-41's "regenerated at most twice": the credit ceiling approved before the run counts every planned call (CLIP-19, QUOTA-45) and T075 rules out repair calls; asking for the alternative up front costs a few tokens and keeps the fallback deterministic. This is a deliberate reading of CDS-41 to record in the result and, if the owner disagrees, to return through update-ssot CDS
- `subject` replaces `avoid` because CDS-38 needs the subject's area for the 15 % rule, not a keep-out box; the observe prompt names the detection order so the same footage yields the same box
- the compiler extends a cut only inside the segment the cut already came from (CDS-41 "within the source"), which is the same guard `composeTimeline` uses today
- proper-noun detection is intentionally narrow (answers' 상호 and 메뉴 values plus capitalised Latin tokens): a general Korean NER is out of scope, and every number is checked exactly, which is where the advertiser risk sits (CDS-42)
- `design.json` carries the CDS-40 table as data so a table change is a JSON edit plus a pinned test, never a code path

- **CDS-40 and CDS-38 can contradict each other.** The run guard alternates 깔끔하게 ↔ 메모, whose default anchors are BOTTOM and TOP — three steps apart — so a strict one-step rule silently dropped five of eight copies in the multi-source fixture. The step is now a PREFERENCE (taken whenever any candidate satisfies it, ignored when none does) and V13 measures the step only between consecutive cuts that SHARE a style, because a style change is itself a deliberate visual change. Both are deliberate readings to record; if the owner disagrees they return through update-ssot CDS.
- `short_text` also covers a sentence past its STYLE's character limit, not only a cut too short for it: CDS-41's "regenerated at most twice" has no second call to spend (CLIP-19, QUOTA-45), so the alternative is asked for up front and the style is re-selected for the shorter words, because a shorter sentence can be a different class.
- CDS-41's cut extension may only use the slack the owner's approved target still allows (`TargetToleranceMS` minus the current error, and never past `MaxDurationMS`): the timeline is reconciled to that target before the design system sees it, so extending freely would break the duration the owner approved.
- the copy window is CDS-27's always — cut start + 120 ms to cut end − 120 ms — so the model's caption start and end are now advisory and are not carried through. `Cut.CaptionWindow` resolves a zero start and end to it.
- a DROPPED copy carries no placement at all (no style, anchor, alignment, keyword or accent), and `ValidCopy` accepts exactly that shape; the FE model and mapper accept it too, so the correction screen shows such a cut as footage with no text rather than as an invalid plan.
- a measurement FAILURE is no longer read as "does not fit": the measure function returns an error and the composer propagates it, which is what kept `CLIP_COPY_TOO_LONG` reaching the caller.
- identity, focal and gain checks moved into `composeTimeline`, ahead of the design system, so a plan the model got wrong costs no glyph measurement.
- the structural shape checker had no `boolean` case — `readable_text` was the first boolean in either contract, and every response carrying one was refused as `output_shape` until it was added.
- `short_text`, `keyword` and `hook` are bounded at 40 characters, not the caption's 500: each has a rule of its own (14 characters, one word, two lines of nine) and a plan of 75 cuts must not be able to double its own output. `budget_test.go` measures the added cost against the 32768-token plan budget and logs what a realistic response actually costs (≈1900 tokens of it). The absolute worst case both contracts allow has always been far past every budget — sixty segments of twenty 2000-character subjects — and is bounded by the provider's own MaxTokens and by `MaxResponseBytes`.
- both recorded fixtures (`live-observation.json`, `live-plan.json`, `multi-source.json`) were MIGRATED mechanically, not re-recorded: the keep-out box became the subject box it was already measuring, `scene` and `readable_text` took their documented defaults, and the captions lost the position, style and accent the contract no longer asks for. The testdata README says so, and no new paid call was made.
- proper-noun grounding is narrow by design (exact digit runs with separators ignored, plus capitalised Latin tokens); a general Korean NER is out of scope and every NUMBER is checked exactly, which is where the advertiser risk sits.
- the composer verifies its OWN result through the renderer's `Layout` port, so a residual violation is a composition-stage failure with the check named rather than a surprise at render time.
