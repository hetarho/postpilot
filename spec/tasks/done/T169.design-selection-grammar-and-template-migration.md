# T169 Replace the declared styles with the design selection and migrate every stored template

## goal
A template names its intro, caption and outro presets on its root, its intro and outro are fixed skeletons the parser enforces, no element declares a style, and every template already saved opens with the default selection.

## acceptance
- [v] `<clip>` takes `intro="a|b"`, `caption="bold"` and `outro="b|e"`; strict `composition.Parse` requires all three and refuses `styles` on `<clip>` and `style` on `<text>` as `unknown_attribute` naming the element and line; `Document.Styles` is replaced by `Document.Design{Intro, Caption, Outro}`
- [v] `composition.ReadStored` defaults a missing selection to b / bold / e and ignores `styles`, `style` and row `role` attributes so an existing draft still opens for correction
- [v] strict parse enforces the skeleton: exactly one `role="hook"` and one `role="ending"` element directly under `<clip>`, `basis` output-start for hook and output-end for ending, no `position`, `align` or `style`, rows without `role`, at most the preset's slot count, and an optional per-row `kind="fixed|ai"` overriding the element's; a departure fails with the new reason `invalid_skeleton`, and a hook/ending whose `start`/`end` are omitted resolves to 0 – `intro_default_s` and −`outro_default_s` – 0
- [v] `ValidRoleStyle` and `styleNames` are deleted; `rowRoles` shrinks to the info rows that still carry one
- [v] goose migration `0054_clip_design_selection.sql` rewrites `video_templates.composition_body` by attribute surgery only: strips ` styles="…"` from `<clip`, strips ` style="…"` from every `<text`, inserts ` intro="b" caption="bold" outro="e"` after `version="1"` where the root has no `intro`, and leaves every other byte untouched; `copy_styles` becomes `'[]'` and the `CopyStyles` list inside `clip_projects.edit_plan_json` is stripped
- [v] `EditPlan.Styles`, `Recipe.CopyStyles`, `storedAssemblyPlan.CopyStyles`, the `styles` field of the copied authoring instructions and `PlanningInput.Template.CopyStyles` are removed; the writer prompt (`ai/prompts.go`) stops mentioning styles and `plan_style` leaves the ladder; the rpc handler ignores incoming `copy_styles` and returns it empty, with the proto untouched
- [v] V14 (template-approved styles) is removed from the verifier and `ClipEditingState` no longer carries styles server-side
- [v] legacy furniture (`LegacyCompositionBody`, `legacyProjectFurniture`) emits skeleton-shaped hook and ending elements — top-level, default intervals from `timing`, rows without role
- [v] test: a body with `styles="simple"` or `style="simple"` fails strict parse and opens under `ReadStored` with design b/bold/e
- [v] test: an ending inside a scene, a fourth outro-E row, a row with `role`, and a hook with `position` each fail `invalid_skeleton` naming the element and line
- [v] test: the migration converts the `맛집 테스트` body in `docs/design/clip-restaurant-template-v2.md` — root gains the selection, styles vanish, everything else byte-identical — and the result opens under `ReadStored`; a plan saved with `Styles` decodes after the migration
- [v] `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...` and `git diff --exit-code -- backend/internal/clip/store/sqlc`

## impl notes
- the selection lives on the root element, not in a column: the body is the lossless source the builder, 원문, the copied 형식 안내, the frozen project composition and the migration all share (CLIP-71, CLIP-69), so a column would be a second truth
- refusing a stored body outright would break every saved template until the owner edited it by hand, so the split is deliberate: strict on save, tolerant on read, and a migration that adds the root selection without restructuring hook/ending elements — the `맛집 테스트` ending sits inside a scene and stays a visible `invalid_skeleton` until the owner rebuilds it in T172's editor; until then that template cannot generate (CLIP-71), which the report to the owner states
- migration 0041 rewrote `edit_plan_json` with SQL string replacement and is the precedent; the body is XML in a text column and a targeted attribute strip is safer than parse-and-reserialize, which would normalize whitespace the owner wrote
- no proto change and no schema change in this task: `pnpm gen:proto` and `pnpm gen:sql` need Docker, which this machine cannot run (memory: clip-release-smoke-needs-docker); `copy_styles` stays a wire-compatible empty field and `SELECT *` keeps its column, and a later cleanup task removes both when the toolchain is available
- CLIP-92 keeps save, admission and the copied instructions on one vocabulary — all three must drop styles and adopt the selection in this task or they disagree
- per-row `kind` exists because outro E mixes a fixed label, an answer-bound score and a generated verdict in one element; default it to the element's `kind` so old bodies keep their meaning
