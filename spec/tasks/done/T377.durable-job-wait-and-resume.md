# T377 A job can wait durably without occupying the API worker
> st:done@260925 | ssot:ARCH-6 ARCH-7 ARCH-11 ARCH-50 GEN-28 GEN-32 GEN-33 GEN-35 | base:ARCH@11 GEN@12 | dep:-

## goal
Let an owning workflow park and resume the same active job around external work without blocking the single API consumer or replaying an interrupted model call.

## acceptance
- [v] A handler can persist an external wait and yield without finishing, settling, releasing its sources or recording a failure; the public job remains running and retains its identity and active-subject guard.
- [v] Another queued model job runs while the first job waits; waking the wait makes the same parent runnable exactly once, including a wake committed before its handler returns the yield signal.
- [v] Boot preserves waiting/ready continuations and their cancellation requests, re-readies a claimed replay-safe continuation, and still fails interrupted local/model executions with JOB_INTERRUPTED.
- [v] Cancellation of a parked job remains pending until its owning workflow acknowledges stopped external work; existing queued/local cancellation and terminal hooks retain their behavior.
- [v] Atomic suspend/wake ports can join an owning-context transaction, and duplicate wakes or terminal-job wakes neither reopen a job nor settle twice.
- [v] Queue/store tests cover park-before-yield crash, wake-before-yield, competing wake/claim, restart in waiting/ready/claimed states under both resume policies, cancellation at each boundary and continued processing of unrelated jobs; ARCH-26 and SQL generation checks pass.

## impl notes
- Add job-owned `job_continuations(job_id PK, wait_key, state, resume_policy, ready_at, created_at, updated_at)` with states waiting, ready and claimed and resume_policy fail_on_interrupt|replay_safe (default fail_on_interrupt); use a job FK with cleanup on deletion. The key is opaque to job, and clip data remains in clip/store.
- Expose generic tx-scoped `Park(jobID, waitKey, resumePolicy)` and `Wake(jobID, waitKey)` behaviors through job/store and the existing app transaction binder. Park only a currently running authorized job, and require an exact key match for Wake.
- Keep existing public status values. The runnable picker handles initial queued jobs and running jobs with ready continuations; claim a ready continuation atomically before calling its handler and order runnable work by ready_at/created_at with id as tie-breaker.
- Introduce a dedicated queue yield sentinel recognized with errors.Is before the normal terminal path. A missing durable wait is an error, not permission to leave an untracked running row. The clip boundary maps its own pending outcome to this sentinel; no generic queue code names clip operations.
- Extend SweepRunning and RecoverCancellations to exclude waiting/ready external continuations. A claimed fail_on_interrupt continuation receives the existing interrupted failure after restart; a claimed replay_safe continuation is atomically re-readied. Only workflows containing no paid or non-idempotent side effect may opt into replay_safe; T382 uses it for idempotent result publication, while T381 preparation-to-model work uses fail_on_interrupt.
- Check cancellation before dispatching a ready continuation; never resume paid work to finish a cancellation. Expose a generic terminal acknowledgement for the owning reconciler to call once remote work is stopped or its lease has expired.
- Keep dispatch_ready's existing initial-activation meaning and retain old payloads unchanged. No second credit admission occurs on a resume; settlement/notifyTerminal still follow a persisted terminal outcome.
- T354 and T372 modify registration/drain tests in cmd/api, not this state machine; preserve their generation payload ownership and shared registration harness rather than duplicating either.
- New primitives remain unused by production media work until T381/T382 wire them.

## result
- Added migration 0080 and job-owned transactional Park/Wake, conditional resume claiming, replay policy recovery and cancellation acknowledgement; the parent keeps its running status, frozen payload and active guard while the API worker handles other jobs.
- The worker honors committed waits before terminal settlement, rejects a yield without a durable wait, and does not repeat hooks when an external cancellation acknowledgement wins before the yielding handler returns. New clip transaction ports share the parent writer transaction; production media dispatch remains unchanged until T381/T382.
- Real SQLite/store and queue tests cover transactional rollback, early/duplicate/mismatched wakes, competing claims, preserved progress/start time, all waiting/ready/claimed × resume-policy × cancellation boot cases, unrelated-job progress, no second admission and one terminal acknowledgement.
- ARCH-26, FE 313 files / 2659 tests plus lint/format/FSD/style/build, SQL/proto regeneration, deployment 8 tests, retirement/skill checks and spec lint pass. Queue continuation and full store continuation suites pass under the race detector; reusing the migrated fixture across isolated boot cases removed a historical-migration setup timeout without dropping cases.
- Files: internal/job continuation/worker/types/store/SQL and tests; migration 0080; internal/clip/app/ports.go and cmd/api/clip.go transaction wiring. No SSOT deviation or live deployment.
