## goal
Opening or leaving an `Editable` from the keyboard keeps focus on the edited field instead of dropping it to `<body>`, with no change for pointer users.

## result
- outcome: a keyboard press of an Editable pencil moves focus to the edit view's `[data-autofocus]` control or its first focusable (`focusablesIn`), and `exit` returns focus to the pencil with `preventScroll: true`; both only while focus is on `<body>`/null, so autoFocus fields and focus moved elsewhere are kept; a pointer press moves no focus; no prop or consumer change. The owed move is carried in the toggle's state (`{ editing, move }`) rather than the planned ref, because `exit` is handed to the `edit` render prop and `react-hooks/refs` refuses a ref mutated there (no suppression precedent in shared/ui); behaviour is the same, and an `exit` while already closed still changes nothing
