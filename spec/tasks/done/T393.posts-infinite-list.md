# T393 /posts loads more rows as its end nears and keeps them on return
> st:done@260925 | ssot:POST-90 POST-91 POST-92 POST-93 POST-65 POST-67 POST-69 | base:POST@15 ARCH@11 | dep:T392

## goal
`/posts` reads the list as server-narrowed pages, loads the next page as the list's end nears the viewport, reports loading and failure at the list's end, and coming back from a post restores the loaded rows and the scroll position.

## acceptance
- [v] `/posts` requests `POSTS_PAGE_SIZE` (20, `shared/config`) rows with the URL's `q` and `status`; the next page loads when a sentinel after the last row comes within one viewport of the screen, never while a page is in flight, and stops once the server returns no next token; the same at every width
- [v] search and status are answered by the server: a post that sits past the loaded rows is found; the browser no longer filters rows; the tags that matched are still named on the row, only while they match (POST-65)
- [v] typing sends the query after `POSTS_SEARCH_DEBOUNCE_MS` (250) of quiet, while the URL still updates per keystroke by `replace` (POST-67 unchanged); the rows on screen stay until the new answer arrives rather than flashing to the loading text; a status change applies at once
- [v] while the next page loads the list's end says 불러오는 중 in a status region; a failed next page keeps every row shown and puts 더 불러오지 못했어요 + 다시 시도 at the list's end, which retries only that page; the page-top error notice is reserved for a failure of the first page (or a refetch with no rows)
- [v] zero rows with a narrowing is the POST-69 no-match text with 초기화; zero rows with no narrowing is the empty-account text
- [v] coming back to `/posts` (browser back or the editor's 목록 link) within `POSTS_LIST_GC_MS` (30 min) renders the loaded rows from cache and restores the window scroll position; scroll restoration is enabled for `/posts` only
- [v] every mutation that invalidated the list before still refetches the paged list (a delete, a finalize, a content save) and the whole-list `usePosts()` the model comparison picker reads
- [v] the list keeps polling while any loaded row has an active job
- [v] tests (vitest): the fake backend in `test/posts.ts` pages, narrows and tokens like T392; PostsPage — first page only on load, the next page after the sentinel reports intersection, no request past the last page, a search hit that lives on page 2 is shown for the query, matched tags named, loading-more text, failed next page keeps rows and 다시 시도 recovers, no-match vs empty account, debounce (one request for a typed word), and invalidation from a delete refetches the paged list; router — `scrollRestoration` true for `/posts` and false for `/posts/$slug` and another route
- [v] verified in a real browser against the dev stack with more than 20 posts: scrolling loads the next page, and opening row 25 then going back lands on the same row
- [v] ARCH-25 FE gate passes

## impl notes
- Hook: `entities/post/api/usePostList.ts`, exported from the entity index as `usePostList(narrowing: { q?: string; status?: PostStatus })` returning `{ posts: PostListItem[]; isPending; isError; isFetching; hasNextPage; isFetchingNextPage; isFetchNextPageError; fetchNextPage; refetch }`. It is connect-query `useInfiniteQuery(PostService.method.listPosts, { pageSize: POSTS_PAGE_SIZE, pageToken: '', query, status }, { pageParamKey: 'pageToken', getNextPageParam: (last) => last.nextPageToken || undefined, placeholderData: keepPreviousData, gcTime: POSTS_LIST_GC_MS, refetchInterval: any loaded page holds a row with an active job ? POLL_INTERVAL_MS : false })`. Rows are the pages flattened and de-duplicated by slug (a post edited between two page fetches moves above the cursor and could otherwise show twice until the next refetch). `usePosts()` stays as the unpaged read (`{}`, T392's page_size 0) for ModelComparisonPage.
- The debounce lives in the page (a small `useDebouncedValue` in `shared/lib` if none exists), so the hook's input is already the settled query; `status` is not debounced.
- Invalidation: `listPostsQueryKey` becomes `createConnectQueryKey({ schema: PostService.method.listPosts, transport, cardinality: undefined })` with no `input`, which connect-query documents as the filter matching both the finite and the infinite entries. Every verb keeps calling it, so the ARCH-14 owner rule and `arch-post-cache-keys.test.ts` are untouched. Pin with a test that the key matches a paged entry (a delete refetching the page is enough).
- `features/filter-posts/model/narrow.ts`: `narrowPosts` stops filtering; replace it with `matchedTags(post, q): string[]` over the same `normalize`, and keep `PostNarrowing`. Update `narrow.test.ts` to the new function; the filtering cases move to the BE parity tests in T392.
- Error split: react-query v5 sets `status: 'error'` for a failed `fetchNextPage` too, so the page-top notice shows on `isError && !isFetchNextPageError`, and the list-end retry on `isFetchNextPageError` calls `fetchNextPage()`. The list-end region is one `role="status"` node whose text changes, as the page-top loading text already is (one live region, a text change rather than a node swap).
- Sentinel: an `IntersectionObserver` on an empty element after the `<ul>` with `rootMargin: '0px 0px 100% 0px'` (one viewport ahead); put the hook in `shared/lib` as `useNearViewport(ref, onNear, enabled)`. It fires `fetchNextPage` only when `hasNextPage && !isFetchingNextPage && !isFetchNextPageError` (a failed page waits for 다시 시도 instead of retrying on every scroll). jsdom has no IntersectionObserver: stub it in the test the way `widgets/contact-sheet/ui/ContactSheet.test.tsx` does and report intersection by hand.
- Copy (ko/en, `posts` namespace): `list.loadingMore` 불러오는 중… / Loading more…, `list.loadMoreFailed` 더 불러오지 못했어요 / Couldn't load more; the retry button reuses `common:action.retry`.
- Scroll restoration: `createRouter({ …, scrollRestoration: ({ location }) => location.pathname === '/posts' })` in `app/routes/router.tsx`, default key `location.href`, so the narrowed URL restores its own position and every other route keeps today's reset-to-top. Export the predicate so the router test can pin it without a browser. The window is the scroller (the shell has no `overflow-y-auto`, as router.test pins).
- `POSTS_LIST_GC_MS` 30 min: an editing session routinely outlasts the 5 min default, and without the cached pages the return lands on the first page at the top; bounded rather than infinite because every debounced query is its own entry.
- Polling refetches every loaded page in sequence (react-query v5 infinite refetch); accepted — it runs only while a job does, and a page is 20 slim rows.
- The empty account with a narrowing in the URL now shows the no-match text; 초기화 then shows the empty-account text. POST-69 holds: that narrowing does match nothing. No extra wire field.
- Browser check: `pnpm dev`, seed >20 posts for a dev account (the design-shots account or `adduser` + a quick script through the API), Playwright + the local Chrome as in the design-review screenshot recipe.
