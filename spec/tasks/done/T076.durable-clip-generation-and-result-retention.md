## goal
Orchestrate one durable, metered clip-generation job from a confirmed transient source batch through analysis, plan, render, result replacement and source cleanup.

## acceptance
- [v] migration `0038_clip_jobs_and_object_deletions.sql` adds nullable `clip_project_id` to `generation_jobs`, an active-per-project partial unique index and `clip_object_deletions`; existing job rows and post/voice guards remain unchanged
- [v] job domain/store/RPC projections carry `clip_project_id`, add `generate_clip`, select initial stage `prepare`, find an active clip job and reject a foreign clip target before insertion
- [v] `StartClipGeneration` requires one owned project with a current template, a ready owned source batch, non-blank answers for every current information field, an observe model registered to observe with video input and a write model registered to write
- [v] enqueue freezes project ratio/target, template recipe/answers, complete source manifest/fingerprints and both model refs in the durable payload; later project/template edits cannot change the run
- [v] the credit hold prices exactly one observe call for each `ceil(sourceDuration/60s)` chunk plus one plan call, using T075's actual completion budgets; only the durable worker reserves after probing every source; a refused/error hold creates no debit or AI call, fails the existing job and cleans the transient batch
- [v] the batch becomes `consuming` with the created job id through a compensating sequence: the queued job is not dispatchable until linkage succeeds; an enqueue-link/activation failure fails the still-queued job, creates no hold and leaves no batch stranded; boot recovery fails any unactivated queued job
- [v] the handler streams one source at a time from private storage into a T073 workspace, probes it before any model call, creates/signs one proxy at a time, records metered analysis, deletes the proxy immediately, plans once, downloads only plan-selected originals, renders through T074 and streams the result to private storage
- [v] result keys are `clip-results/{userID}/{projectID}/{random}.mp4`; one transaction replaces analysis, edit plan and latest result metadata together and enqueues the old key for deletion, so a failed run changes none of them
- [v] `GetClipProject` mints fresh inline-view and attachment-download URLs for the current result and never persists either; list responses carry result presence/status only
- [v] a defer marks source cleanup before every handler return, including cancellation and panic; periodic/boot recovery cleans source batches tied to terminal or missing jobs and stale workspaces without touching an active one
- [v] project deletion refuses `CLIP_BUSY` while a clip job is queued/running; otherwise it atomically queues its result key for deletion and deletes metadata/analysis/plan/answers, and the object-deletion sweep retries until the result is gone
- [v] an unreferenced new result from a DB failure and an old replaced result are found by the clip-result orphan sweep after the same minimum-age safety window used by storage; a short list/read deletes nothing
- [v] progress stages are `prepare|analyze|plan|render|save|cleanup`; failures preserve the previous result, expose the failing stage with a registered reason and technical detail, settle actual model usage, and make retry possible with a new batch
- [v] service/job/store/RPC/integration tests cover frozen payloads, exact call reservations, model gates, metadata mismatch before calls, partial proxy cleanup, result swap failure, crash recovery, owner isolation, busy deletion and old-result preservation
- [v] no model call bypasses the successful full-run reservation; a worker-scoped call allowance rejects changed refs, extra calls or raised completion budgets before the LLM boundary, concurrent reservations cannot overspend, and clip settlement never debits above its reserved credits
- [v] ARCH-26 and ARCH-28 pass

## impl notes
- implement the clip-only deferred-admission queue path with dispatch gating; normal jobs retain pre-insert admission, and no caller-controlled generic bypass permits LLM work without a reservation
- keep the allowance in the running worker context after Hold succeeds, check it before every metered clip call, and never replay interrupted running jobs; release/settlement is idempotent and uses detached bounded contexts
- preserve actual provider usage even when its cost exceeds the hold, but cap clip user charges at the hold; no additional lot debit or debt is allowed for that excess
- migration 0037 belongs to concurrent T045; 0038 is the next free number
- extend `clip.ObjectStore` and `internal/storage` with streaming download/upload plus inline/attachment presign options; never materialize a whole video in a Go byte slice
- keep one generic durable job and the existing worker concurrency: analysis, planning and rendering are stages of the same user action and the result must not become visible between them
- `clip_object_deletions` is an outbox, not retained media metadata: row creation shares the DB transaction that drops a reference, object deletion happens afterwards, and success removes the row
- use the existing metered registry wrapper in `cmd/api`; neither clip service nor handler writes `usage_events` directly
- a source/proxy object may outlive a crash only until the next cleanup sweep; its database lease is the recovery authority and it never becomes a project attachment
