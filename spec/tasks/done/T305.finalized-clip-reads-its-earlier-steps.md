# T305 a finalized clip's ① and ② open read-only
> st:done@260922 | ssot:CLIP-160 CLIP-36 CLIP-76 CLIP-150 CLIP-149 | base:CLIP@43 | dep:-

## goal
A finalized project keeps all three steps selectable and opens ① and ② as readings of what the clip was made from, while every write stays refused.

## acceptance
- [v] the step bar is drawn for a finalized project and every step is selectable; finalization still lands on ③ and ③ keeps its docked download as its only action
- [v] ① states the settings, answers, instruction and design selection as read-only values in the settings form's own layout: no field accepts a change, no source upload, no 생성, no approval control and no stage model selector (CLIP-160 r43)
- [v] ② plays the confirmed result where the draft preview stood, and each cut, caption and notice opens in its own sheet as values with no control in it
- [v] ② carries no ActionBar: no revision composer, no 렌더하기, no 확정하기 and no download
- [v] the observations the successful attempt recorded are reachable from ② and stand in ①'s flow
- [v] a finalized project asks for no draft preview, no caption fragment and no original playback
- [v] `GetClipProject` carries `editing` and `observations` for a finalized project, and every write still refuses with `CLIP_FINALIZED`: SaveCorrection, render of either kind, revision, source upload, finalize
- [v] vitest: a finalized project renders the step bar, ① read-only with no editable control, ② showing the result with a caption sheet that carries values and no control, and no preview request; an unfinalized project is unchanged
- [v] go test: `GetClipProject` on a finalized project returns the editing state and the observations, and SaveCorrection on it still answers `CLIP_FINALIZED`
- [v] verify: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` · `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...`

## impl notes
- the server side is one omission: `rpc/handler.go` GetClipProject fills `out.Observations` and `out.Editing` only `if value.Finalized == nil`. Drop that condition — the editing state is a pure projection (`app/rerender.go` EditingState → `clip.EditingStateOf`) and reads no originals. Every write guard lives elsewhere (`app/*`, `store/*` return `clip.ErrFinalized`) and is not touched
- the retained-source list a finalized editing state carries names originals that finalization deleted (CLIP-76). ② must never resolve playback for them: the read-only surface passes no `resolvePlayback`, and the source strip does not mount
- the preview RPC already refuses a finalized project (`app/preview.go:15`) and stays that way — ② has no draft to prepare, so the read-only surface must not call it. The caption sheet draws its caption from the plan's own values, not from a fragment request
- frontend: `widgets/clip-workspace/ui/ClipWorkspace.tsx` gates the step bar, the panels, the attempt inspection and the settlement on `project.finalized`; `useClipWorkspace` derives the step from `stepForProject`. Keep the derived step at `finish` for a finalized project — the owner selects ① or ② themselves — and stop forcing `finishPanel` when they do
- ① read-only: `ClipProjectForm` already wraps its fields in `<fieldset disabled>`; add a read-only mode that also drops the action slot, the source picker and the model selectors' controls rather than rendering them disabled, so nothing on screen looks pressable
- ② read-only: `ClipCorrectionWorkspace` takes six handles and one `disabled` flag; add a read-only mode that swaps the preview slot for `ClipResult`, drops the revision, render, download and finalize slots and renders each sheet's controls as values. The timeline stays, because reading which cut a caption sits on is the point
- a finalized project holds no draft queue (`useDiscardQueueWhenFinalized`), so nothing autosaves from these panels

## result
- `internal/clip/rpc/handler.go`: GetClipProject filled `observations` and `editing` only while the project was unfinalized. That one condition was the whole reason ② had nothing to read; both are projections of the stored plan and evidence, so serving them touches no original. Every write guard lives in `app/`/`store/` and is untouched — SaveCorrection on a finalized plan still answers `CLIP_FINALIZED`. `FinalizeClipProject` answers through the same read, so confirming now hands back the readings ① and ② open afterwards.
- frontend: one `reading` flag in `ClipWorkspace` drives the lot. The step bar is drawn for a finalized project and every step is selectable; the panel follows the selected step instead of being forced to ③, and ③ keeps its docked download as its own. ① renders through `ClipProjectForm`'s new `readOnly` (the fieldset locks, the dock, the source strip, the model section and the reselection note do not render). ② renders through `ClipCorrectionWorkspace`'s new `readOnly`: the confirmed result plays where the draft preview stood, the dock, the scrubber, the undo/redo and the sheet's destructive footer are gone, and the sheet body is a new `ClipItemReading` stating a cut's source, ranges, rate, transition, volume and captions, or a caption's text, interval, style, pace, accent word and placement, with that item's notices.
- nothing asks for what finalization deleted: the fragment query is disabled while reading, `localSources` is empty, `resolvePlayback` is undefined, and the preview RPC — which refuses a finalized project — is never called.
- SSOT differs from what this task was written against in one clause, corrected mid-implementation as CLIP r43: ① cannot state "the models the clip was made with" because the project never records them — the stage selectors in ① are account settings, and `ClipProject` carries no model at all. The acceptance line was narrowed to match, and a finalized ① renders no model section. Recording which models produced a clip would be a new decision and new storage; it is not in this task.
- `test/clips.ts` kept dropping `editing` and `observations` on finalize, mirroring the old server; it now keeps them. Two existing assertions encoded the old rule — the lifecycle test's "a finalized project shows no step bar" (twice) and `cmd/api/clip_finalization_test.go`'s "the finalize response carries no editing or observations" — and both now assert the new one.
- verification: frontend 290 files / 2,295 tests, lint, format:check, FSD, style probe + style, production build; backend gofmt/vet/build/test green. `pnpm exec haeram-spec-creator check` and the spec lint pass (its remaining warnings are pre-existing). `pnpm gen:proto`/`gen:sql` were not run: no proto, query or generated file changed.
