# T297 Dev API accepts its media tuning while auth outages stay outages
> st:done@260921 | ssot:AUTH-26 ARCH-10 ARCH-42 | base:AUTH@6 ARCH@6 | dep:-

## goal
Restore local API readiness by making its documented media tuning pass bounded validation while retaining the existing distinction between a lost session and an unavailable backend.

## acceptance
- [v] `CLIP_ENCODE_THREADS=6` and `CLIP_DECODE_THREADS=8` pass the owning clip media constructor, the API reaches `/health`, and an out-of-range thread count is refused with a named cause
- [v] a focused backend test covers the documented development thread values without changing the production and hand-built default of one encoder thread
- [v] frontend tests prove that a GetMe 401 ends the client session and redirects an authenticated screen to `/login`, while a 5xx/proxy/network failure preserves it and reaches the route error path
- [v] migration tests prove repeated boot is idempotent and applies only pending embedded migrations; no separate migration command or startup precheck is added
- [v] ARCH-25 and ARCH-26 pass

## impl notes
- observed failure: migrations 0057 through 0071 completed, then context construction exited with `clip media initialization: invalid clip media configuration`; Air remained alive, so Vite surfaced GetMe as 502
- `docker-compose.yml` deliberately sets encoder/decoder counts to 6/8 for local work while production defaults and hand-built test configs remain 1/2; accept bounded 1..8 values in the owning media constructor instead of deleting the development override
- make the rejected field visible in constructor errors so a pre-listener failure is diagnosable from the API log
- AUTH-26 and ARCH-10 behavior already exists in the frontend guards/interceptor and `db.Migrate`; retain it and pin it with the existing focused tests rather than adding a 5xx logout or a second migration path

## result
- `internal/clip/limits.go` owns the shared 8-thread ceiling; `internal/clip/media/workspace.go` accepts explicit encoder and decoder values from 1 through 8 and names the rejected role and value instead of collapsing it into a generic media error.
- `internal/clip/media/media_test.go` pins the documented local 6/8 values and both out-of-range errors; `frontend/src/shared/api/transport.test.ts` now pins a GetMe 5xx specifically as a non-logout failure.
- The running Air child rebuilt successfully: `/health` answers 200 and GetMe through the Vite proxy answers the expected signed-out 401 instead of 502. Two later boots emitted no migration-applied lines, confirming the existing pending-only path.
- Verification passed: focused media, migration and auth tests; ARCH-25 (286 files / 2241 tests, lint, format, FSD, style and build); ARCH-26; ARCH-27; proto/sql generation checks; `pnpm smoke:media`; skill check and spec lint. Spec lint retained 17 pre-existing warnings and reported consistency success.
- No implementation deviates from AUTH r6 or ARCH r6; production and hand-built media defaults remain one encoder and two decoder threads.
