# T193 The cuts become one timeline in a single pass
> st:done@260916 | ssot:CLIP-124 CLIP-125 | base:CLIP@29 ARCH@2 | dep:T191

## goal
Join the rendered cuts into the composed footage with one bounded pass instead of a tree that re-encodes the whole clip once per level.

## acceptance
- [v] the cuts are joined in as few full-length passes as the input bound allows, rather than one pass per tree level
- [v] the number of video inputs opened by any one invocation stays within a configured bound, and a plan with more cuts than the bound still completes by merging in as few rounds as that bound permits
- [v] hard cuts and both transition lengths keep exactly the frames and boundaries they produce today, on the same output timeline (→CDS-36)
- [v] the assembled audio track and its boundaries are unchanged
- [v] the delivered clip is unchanged (→T191)
- [v] tests: filter-graph goldens for a plan of hard cuts only, of fades only and of both, at and above the input bound, plus the identity regression from T191
- [v] verify BE (ARCH-26) passes

## impl notes
- the tree is `compositionInputsFormat` (`media/composition.go:44`), which merges branches pairwise and re-encodes both branches losslessly at every level; for 11 cuts that is roughly 2.7 full-length lossless passes before the delivery encode, and one lossless pass over a 30-second 1080x1920 clip measured 67 s on prod
- stream copying the hard-cut boundaries is not available: the production ffmpeg carries no concat demuxer, confirmed by its demuxer list and by `-f concat` failing to parse; the saving therefore comes from collapsing levels, not from avoiding the re-encode
- a single graph with several inputs is affordable and already how audio is assembled (`assembleDeclaredAudio` opens every cut at once); measured container memory was 184 MiB at four lossless-444 inputs and 262 MiB at eight, against roughly 400 MiB available on prod, so default the bound to 6 and make it configurable
- the existing graph builder `compositionGraph` (`media/render.go`) already emits a mixed concat/xfade chain for a list of branches, so the change is which branches one invocation receives, not how the chain is written
- the comment that motivated the tree — a linear graph opening every future decoder at once — stays true and is what the bound now expresses explicitly

## result
- `media/composition.go` `compositionInputsFormat`: the pairwise tree became rounds of `cfg.MergeInputs` branches. A plan at or below the bound now reaches the delivery encode with NO intermediate pass at all; 100 cuts take 17 passes then 3 instead of 98
- the group's own leading transition is carried up unapplied, exactly as the pairwise merge carried it, and only the seams inside a group are joined — so the frame arithmetic is unchanged (`merged = frames[0] + Σ(frames[j] - transitionFrames(transitions[j]))`)
- `clip.RenderConfig.MergeInputs` (new, default 6 in `platform/config/clip_render.go`, bounded 2..8 by `NewRenderer`): the comment that motivated the tree — a linear graph opening every future decoder — is now what this bound states explicitly. 6 is the measured headroom: 184 MiB at four lossless-444 inputs, 262 MiB at eight, against roughly 400 MiB on prod
- nothing about the audio changed: `assembleAudio` and `compositionAudioGraph` are untouched and the final pass still opens one already-measured track
- tests: six new goldens (`testdata/merge-{cut,fade,mixed}-{6,11}.filter`) record how many passes a plan takes, how many inputs each opens and the graph each runs, for hard cuts only, fades only and both, at the bound and above it; `TestCompositionMergeBoundsVideoDecodersAndKeepsAudioForFinalPass` pins the 100-cut shape (20 passes, every merge within the bound, 1506 frames unchanged)
- identity held: `TestDeliveredClipIdentity` passes against T191's baseline in the pinned image (105.5 s), which is the real proof — the three-cut plan lost its intermediate lossless pass entirely and still delivers the same bytes
- no SSOT difference; verify BE (ARCH-26) passes (`go test ./...` with `-p 2`: the full-parallel run is OOM-killed on this box)
