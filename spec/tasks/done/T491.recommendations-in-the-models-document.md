## goal
The 일괄 편집 document reads, previews, applies and exports the recommendation sets in a `[recommendations]` section, validated against the registrations the same document leaves and written in the same transaction; a set label is unique on every save.

## acceptance
- [v] `ParseDocument` accepts one `[recommendations]` section of `set <label>` lines each followed by `observe <active> <a> <b>` · `analyze <active>` · `write <active> <a> <b>`; a document without the section parses exactly as before (existing protocol tests pass)
- [v] parse issues, each on its own line: `set_label_invalid` (empty or over 60 runes), `duplicate_set`, `set_limit` (the 11th set line), `stage_before_set`, `duplicate_stage`, `missing_stage` (on the set line, text naming the stage), `malformed_line` (unknown stage token, wrong id count, an id that is not `vendor/model`), `duplicate_section` for a second `[recommendations]`
- [v] planning validates every added or changed set against the registrations and classifications the document leaves (sections as listed, absent purposes as stored): `slot_unregistered`, `slot_unclassified`, `slot_duplicate` (a pair's B equal to A), each on the stage line with the offending id as text; a set identical to a stored one in label and slots is not re-validated (service tests: registers-and-uses in one paste passes, deregisters-and-uses fails, an unchanged stale set passes)
- [v] the plan reports `recommendations` only when the section is present: labels added, removed, changed, unchanged, and `reordered`; preview writes nothing
- [v] apply writes purpose registrations and the set list in ONE transaction: matched labels keep their id, unmatched stored sets are deleted, new labels get new ids, positions follow the document; nothing is written when any issue exists; no `model_selections` row changes (store test over real SQLite, including a rollback when the set write fails)
- [v] export appends `[recommendations]` after the five purpose sections with every set in order, an empty section when there is none, and an exported document previews as no change including a set whose model has since been deregistered
- [v] `SaveRecommendationSet` refuses a label another set uses (`label: duplicate`, trimmed exact match, the set's own label excluded) in the same refusal as the other fields
- [v] `.claude/skills/recomend-models/SKILL.md` documents the section and emits one set per classification that has enough models, labelled by grade
- [v] ARCH-26, ARCH-28, `pnpm --filter ./frontend test` and `pnpm build:web` pass

## impl notes
- document domain (modelcatalog, `protocol.go` + `types.go`): `DocumentSet{Label string; Line int; Stages map[string]DocumentStage}` with `DocumentStage{Stage string; IDs []string; Line int}`; `Document.Recommendations *[]DocumentSet` — nil when the section is absent, non-nil empty for an empty section; stage tokens are the llm stage names (`llm.StageNameObserve` …) and the stage→purpose map is observe→photo-analysis, analyze→style-analysis, write→writing; set lines are `set` + whitespace + label (the rest of the line trimmed), so a label may contain spaces, `·` and `]`
- causes are new string constants beside the existing `Issue*` ones and are named in the `CatalogDocumentIssue.cause` proto comment; the 60-rune and 10-set bounds reuse `provider.MaxRecommendationLabelRunes` / `provider.MaxRecommendationSets` values through modelcatalog's own constants (modelcatalog does not import provider)
- projection for validation: for each purpose, the section's accepted entries (id → level) when the purpose has a section, else the stored registrations; a slot passes when its id is registered to the stage's purpose with a non-empty level; a changed set is one whose label matches a stored set but whose seven ids differ
- wire (`model_catalog.proto`): `message CatalogDocumentRecommendationPlan { bool present = 1; repeated string added = 2; repeated string removed = 3; repeated string changed = 4; repeated string unchanged = 5; bool reordered = 6; }` as field 5 of both `PreviewCatalogDocumentResponse` and `ApplyCatalogDocumentResponse`; `reordered` = the kept labels (changed + unchanged) in document order differ from their stored order
- ports (ARCH-6 cross-context transaction, the billing `SetCreditsForTx` shape): modelcatalog declares `RecommendationRows { List(ctx) ([]StoredSet, error); Replace(ctx, sets []StoredSet, at time.Time) error }` with `StoredSet{ID, Label string; Observe [3]string; Analyze string; Write [3]string}` (model ids only; the registry's single provider is implied, MODEL-10); `modelcatalog/store.Store.SetRecommendationsForTx(func(*sql.Tx) modelcatalog.RecommendationRows)`; `Store.RecommendationSets(ctx)` reads through the factory inside a read-only transaction on the reader; `Store.SyncDocument(ctx, writes []PurposeWrite, sets *[]StoredSet, at)` replaces `SyncPurposes` and runs the purpose writes and, when `sets != nil`, `Replace` in one writer transaction; an unset factory with a present section is an error, never a silent skip
- provider side: `providerstore.NewTx(tx *sql.Tx)` returning a tx-bound view with `ListRecommendationSets` and `ReplaceRecommendationSets(ctx, sets []provider.RecommendationSet, at)` (delete sets whose id is not listed, update matched ones' label/slots/position, insert new ones at their position); `provider.NewRecommendationID()` exported so the adapter assigns ids to new labels; `cmd/api` adapter `catalogRecommendations` maps `StoredSet` ↔ `provider.RecommendationSet` with `ProviderID` = `registry.ProviderID()`
- label uniqueness: `ValidateRecommendationDraft(draft, lookup, otherLabels []string)`; the service passes the stored labels of every other set; no DB unique index (a failed boot migration over existing duplicates is worse than a service check on a single-writer, master-only path)
- export: `RenderDocument(registrations, sets []StoredSet)` renders `[recommendations]` last, one blank line between sets as between sections, ids verbatim; byte-stable
- skill: the paste example gains a `[recommendations]` block; the skill proposes one set per classification (무료 · 가성비 · 밸런스 · 고급 · 최고 추천) only when that grade holds a vision model pair for observe, one analyze model and a writing pair, and says a set naming a grade makes it appliable only by tiers entitled to it (MODEL-58)
