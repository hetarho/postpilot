# T188 An instruction lets the writer speak from experience
> st:done@260916 | ssot:CLIP-122 CLIP-64 | base:CLIP@28 CDS@19 ARCH@2 | dep:T186

## goal
Where a project carries an instruction, stop refusing experiential and descriptive copy for lack of an owner phrase repeating it, while every figure still needs a field.

## acceptance
- [v] with an instruction present, a generated sentence is no longer refused by the experiential-marker check in `GroundScopedText` (`evidence.go:362`)
- [v] with no instruction, that check behaves exactly as it does today, asserted by the existing cases (→CLIP-64)
- [v] the numeric half is untouched in both cases: a number, unit, currency or price basis still requires a referenced information field or item fact, and a global figure still cannot be presented as the depicted item's price (→CLIP-63)
- [v] the scoped-fact rules, the item binding and the repeated-caption rule are untouched
- [v] tests: the same generated sentence admitted with an instruction and refused without one, a figure refused in both cases, and the existing grounding cases still passing
- [v] verify BE (ARCH-26) passes

## impl notes
- `GroundScopedText` takes the presence of an instruction as an argument; it does not read the instruction's text, so no phrase matching, similarity or classification enters the check
- presence, not content, is the switch: CLIP-122 puts the authority on the owner having asked and reviewing before publishing, and a rule that scanned the text would refuse exactly the paraphrases the owner asked for
- the omission notices this stops raising are the CLIP-108 ones for copy the owner wanted; nothing about notice rendering changes

## result
- switch: `GroundScopedText` takes an `instructed bool` and, where it is true, the experiential-marker loop stands down; the marker list moved to `experientialMarkers` so it is plainly one list that never varies with an instruction. The instruction's own words never reach this function
- threading: `composition_parse.go` passes `input.Instruction != ""` into `attachCompositionCopy`, which hands it to `resolveGeneratedCopy` and `attachRegionRows` — presence only, unread
- untouched: the numeric, unit, currency and price-basis checks, the scoped-fact rules, the cross-item identity rule, the context-item rule and the repeated-caption rule all run exactly as before, with or without an instruction
- tests: `evidence_test.go` passes `false` on every existing case, so today's rule is asserted unchanged, and `TestInstructionAdmitsExperienceButNeverAFigure` covers the same sentence admitted with an instruction and refused without, a figure refused either way, and the identity and context rules still refusing with one present; `ai/instruction_test.go` adds the same pair end to end through the writer, where the admitted sentence survives and the refused one becomes a CLIP-108 omission
- verify: BE (ARCH-26) green, whole suite. FE untouched. ARCH-28 not run: no proto or SQL source changed
