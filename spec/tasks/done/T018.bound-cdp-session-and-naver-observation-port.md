# T018 The bound CDP session and the deterministic Naver observation port
> st:done@260907 | ssot:PUBLISH-20 PUBLISH-24 PUBLISH-16 PUBLISH-17 PUBLISH-19 | base:PUBLISH@2 ARCH@1 | dep:T005

## goal
Implement the read-only half of `naver.Port` — a full `Snapshot` observed from the live SmartEditor over one bound CDP target — and correct the versioned locator set against the real editor, so the deterministic publisher can finally see the page T005 was written against.

## acceptance
- [v] `browser` exports a bound single-page CDP session (attach, page URL, one reviewed-script evaluation, full accessibility snapshot, page-scoped DOM query, recheck) and carries no SmartEditor knowledge; no exported method accepts a selector, script, coordinate or key sequence originating outside the agent module
- [v] `Observe` binds every call to the one dedicated page: the target id, its `/json/list` entry and the page URL are rechecked immediately before and after the observation, and a target switch, an added or removed page, or a URL outside the Naver host allowlist returns a poisoned run rather than a snapshot
- [v] the snapshot reports `TargetID`, `URL` (exact `https://blog.naver.com/PostWriteForm.naver…` form the publisher requires), `AccountID` read from the page's own blog identity, and `SignatureID` from the versioned manifest
- [v] `Title`, `Body` (the exact ordered TEXT/HEADING/QUOTE/LIST/IMAGE sequence with level, items, ordinal, caption and uploaded state), `ImageCount`, ordered `Tags`, and `Category`/`Visibility` as `{ID, Name, Selected}` are read from DOM plus full accessibility evidence, identifying category, visibility and tags by role and state rather than label text alone, so a body paragraph equal to a setting label is neither truncated nor mistaken for a control
- [v] `LocatorMatches` holds the true match count per `MutationKind` — 1 exactly when one reviewed control resolves, and the real count when a control is missing, renamed or duplicated — and `UnversionedPublishLikeControls` counts publish-like controls outside the versioned allowlist, `NativeDialogOpen` reflects an open native dialog
- [v] `Auth` distinguishes `ready`, `login`, `captcha` and `two_factor` from page evidence and never attempts a bypass
- [v] `Token` is a deterministic digest of the observed projection, so two observations of an unchanged editor are equal and any observed change differs — the property `mutate` relies on to reject a mutation that changed nothing
- [v] every locator in `naver/compatibility.json` resolves exactly once against the owner's real signed-in SmartEditor; the known-wrong `visibility` locator is corrected, `signature_id` is bumped, and setup's probe still arms the existing connection against the corrected manifest
- [v] table-driven tests against a fake CDP server cover: each locator missing, renamed and duplicated; a second page appearing mid-observation; a target id change; a URL leaving the allowlist; each auth state; an open native dialog; an unversioned publish-like control; a body paragraph equal to a category or visibility label; token equality across an unchanged editor and inequality across every changed field
- [v] ARCH-27 passes

## impl notes
- placement: the port implementation lives in `agent/internal/naver` (new `port.go`), NOT in `agent/internal/browser`. `naver` already imports `browser` for the probe and `Port` returns `naver.Snapshot`, so putting it in `browser` would be an import cycle. This also matches `Port`'s own contract comment — "its implementation owns the reviewed SmartEditor locator set" — and the locator set already ships as `naver/compatibility.json`. `browser` stays the narrow, editor-agnostic CDP boundary PUBLISH-20 describes
- `browser` gains one exported type wrapping the existing unexported `cdpClient`, `discoverSinglePage` and `noProxyHTTPClient`; reuse them rather than opening a second connection per observation. `InspectCompatibility` should end up sharing that type instead of keeping its own copy of the attach sequence
- one observation = one `Runtime.evaluate` of a package-level const script plus one `Accessibility.getFullAXTree`, fenced by a recheck on both sides. Do not read the DOM control by control: a partial read across a mutating page is exactly the stale evidence PUBLISH-20 forbids
- `Token`: hex SHA-256 over a canonical serialization of the whole projection (target id, URL, account, signature, auth, title, the body sequence, image count, tags, category, visibility, locator matches, unversioned count, dialog flag). A monotonic counter is wrong here — `Publisher.mutate` fails closed when `before.Token == after.Token`, so the token must be content-derived or that check stops catching a no-op mutation
- the snapshot must satisfy `Publisher.observe`'s invariants or every run fails closed: `SignatureID` equal to the manifest's, non-empty `TargetID` and `Token`, `URL` prefixed `https://blog.naver.com/PostWriteForm.naver`, `UnversionedPublishLikeControls == 0` and `NativeDialogOpen == false` on a healthy editor
- the corrected visibility locator: the live editor renders visibility as `label[class^="radio_label__…"]` wrapping `전체공개 · 이웃공개 · 서로이웃공개 · 비공개`, not `[role=radio]` as the manifest still claims (`compatibility.go`'s probe was already corrected the same way). Verify all eleven against the real editor in one pass rather than trusting the file
- the reviewed observation script may read only the editor surface. It never reads cookies, storage or credentials, and its output is data — no returned string is ever evaluated or used as a selector
- the account identity is the blog id Naver itself selected (T004's `resolveAccountWriter` already establishes it); never parse it from user input or page prose
- live verification is read-only and needs no publish: PUBLISH-8 already permits opening the account's own writer without typing, uploading or publishing. Use the owner's existing armed connection `5fd6571…`, and do not type into or submit the editor in this task

## result

- `agent/internal/browser/page.go` adds `Page`, the bound single-page CDP session: it pins the target id and page WebSocket at bind, exposes only URL reads, one reviewed-script evaluation, a document probe, a full accessibility snapshot, a domain list and `Recheck`, and carries no SmartEditor knowledge. `InspectCompatibility` was rewritten onto it and no longer keeps its own attach sequence.
- `agent/internal/naver/port.go` adds `CDPPort.Observe`, fenced by `Recheck` on both sides and cross-checked against the page's own `location.href`, so a target switch, a second page, a navigation mid-read or a URL off the writer poisons the run as `editor_changed`. The account id is read only from the writer URL Naver itself resolved.
- The observed body is the same plain-text projection `mapBlock` produces: a section title and a quotation are text (the quotation wrapped in `“ ”`), a list is one `- item` block, an image carries its ordinal, caption and uploaded state. `Token` is a SHA-256 over the whole projection, because `Publisher.mutate` fails closed when the token does not move — a counter would have silently disabled that check.
- Live survey against the owner's real signed-in editor (Chrome 152, blog `understandingram`) fixed **three** manifest locators that could never have matched: `visibility` was `[role=radio]` (the real control is `input[data-testid^=openType_]`, no role attribute anywhere), `tags` matched all 26 layer inputs instead of `input[class^=tag_input__]`, and `upload_image` required `accept*=image` while the real input is `#hidden-file` with `accept=".jpg,.jpeg,…"`. `signature_id` bumped to `smarteditor-one-20260906-a2`.
- The survey also corrected two extraction traps that unit tests could never have caught: an empty title reads back as its placeholder unless only `span.__se-node` text is collected, and fuzzy attribute matching is unusable because Naver's CSS-module hashes contain arbitrary letters — a case-insensitive `otp` probe matched `icon_arrow__OTpnA` on the writer and reported a two-factor challenge on a healthy page. Every hook shipped is exact and versioned.
- Verified block vocabulary (previously unknown, now pinned): TEXT `.se-component.se-text` / HEADING `.se-component.se-sectionTitle` / QUOTE `.se-component.se-quotation` / IMAGE `.se-component.se-image`, lists as `ul.se-text-list > li.se-text-list-item` inside a text component, captions as `.se-module-text.se-caption`.
- Tests: `agent/internal/naver/port_test.go` drives a fake CDP server over the binding, projection, all four auth states, missing/renamed/duplicate locator counts, unversioned publish-like controls, a body paragraph equal to a setting label, a second page appearing mid-observation, a target id change, a page leaving the writer, a blocked evaluation, an empty accessibility tree, the host allowlist, and token stability across an unchanged editor plus token movement for every changed field. The fakes now read the signature from `Manifest()` instead of a literal.

- Live verification (2026-09-07, owner's real armed connection, blog `understandingram`): `postpilot-agent diagnostics` reports `내 Mac: ready (Chrome/152.0.7977.76, driver smarteditor-one-20260906-a2)`, so the corrected manifest still arms the existing connection. `CDPPort.Observe` run against the same editor returned the bound target, `AccountID understandingram`, the new signature, `Auth ready`, an empty title/body/tags for an untouched editor, `Category {16 리뷰 selected}` and `Visibility {public 전체공개 selected}` read from their own controls, `UnversionedPublishLikeControls 0`, and nine of eleven locators matching exactly once. `image_caption` and `upload_image` report 0 on an empty editor by design — the caption module exists only per image and `#hidden-file` is created on demand — and both were observed resolving once during the live survey with an image present. Two consecutive live observations produced the identical token, which is the property `Publisher.mutate` relies on.

**Hand-off to T019.** Category and visibility can only be read while the publish-settings layer is open and, for the category id, while its dropdown is open — the closed selectbox shows the selected name but no id. The mutation sequence must therefore open the layer and the category list before the pre-fence verification. `upload_image` resolves only after the image placeholder is clicked (`#hidden-file` is created on demand and is `multiple`, so uploads must still be one at a time), and `Page.setInterceptFileChooserDialog` + `DOM.setFileInputFiles` was verified live as the way to upload without ever opening a native dialog.
