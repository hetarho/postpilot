# T041 The memo names the subject in prose, alt and caption
> st:done@260908 | ssot:GEN-44 GEN-45 GEN-14 GEN-16 | base:GEN@3 ARCH@2 | dep:-

## goal
Tell the writer that where the memo names a subject the observation recorded only generically, the memo's name is the one written — in prose and in IMAGE `alt` and `caption` alike.

## impl notes
- GEN-44 places the rule "code beside the grounding constants, in the write prompt only". Two per-language constants rather than one appended clause on the grounding line, because `TestFixedTextAdditionsAreTheOnlyGoldenDelta` strips the grounding line by exact string match — extending that line in place breaks the strip, while a separate line is stripped by one more `Replace` and stays independently assertable.
- Placement is the static task/format rules, adjacent to grounding (GEN-14 orders the write prompt "static task/format rules including the grounding constraint → …"). Do not put it in `NaturalnessBaseline`: that constant owns style only and is Korean-target-only, while the naming rule applies to both output languages.
- Wording must not overreach. GEN-44 keeps the observation authoritative on what is in the frame: the rule renames what is already observed, it never licenses writing in a subject the observations do not carry. Phrase it as naming ("메모가 이름을 준 대상은 그 이름으로 부르세요"), not as precedence over the grounding constraint, or it reads as permission to import memo-only facts and contradicts `koreanGrounding` one line above.
- No SSOT, proto, schema, DB or FE change. `caption` and `alt` already ride the same write call that carries 가제 and 메모 (`prompts.go` `perPost`), and every other layer — `post`, `publishing`, `experiment`, the four export converters, `BlockEditor` — only carries the fields through. The gap this closes is naming authority, not a missing input.
- Goldens are hand-maintained: there is no `-update` flag in this package. Insert the line into `testdata/write_prompt_no_template.golden` at the position the code produces, then run the package's tests to confirm the bytes match rather than editing until the diff looks right.
- Observation stays context-free (GEN-45 [x]) — do not touch `ObservePrompt`, `ObserveVideoPrompt`, `observe.go`, the observation schema or the re-observation picker. Stored observations remain reusable across a memo edit, which is the whole reason the fix lives at write time.
