## goal
Publish a windowed Elo leaderboard that compares all ranked candidates, including ties, and preserves eligible historical pairwise outcomes.

## acceptance
- [v] Day/week/month and me/all scopes replay submitted rankings in decision order from 1500 within the selected window. Higher-ranked candidates beat lower-ranked ones; equal ranks draw. Unsuccessful candidates and explicit skips are excluded. Eligible historical two-candidate winner and two-delivery dismissal outcomes remain counted with their existing fixed-reference rule.
- [v] Use K=32 and pre-event ratings for every candidate pair, divide a candidate's summed expected-vs-actual delta by n−1, and apply deterministic zero-sum integer rounding for n≥3. n=2 retains the existing pairwise rounding. One five-way event increments each participating model's evaluated-comparison count once and does not produce fourfold rating volatility. Tests cover ties, upset results against stronger opponents, three/five candidates, integer zero sum, legacy replay and deterministic order.
- [v] Rank nonprovisional models before models with fewer than three evaluated comparisons, then by Elo descending, comparison count descending and model ref. Show Elo, count, pairwise wins/losses/draws and badge tallies. A model with fewer total wins can outrank another based on opponent strength and relative ranking.
- [v] Candidate usage, latency, cost quality and badges aggregate each participating candidate once in the same scope/window. Cost and its quality marker stay aggregated per model in the same scope/window for /admin's 비용·환율 tab (T516), leaderboard responses keep today's cost handling until T516 removes it for every caller, and `all` leaks no account, experiment, output or note. Historical identities remain legible after model removal. Go ranking, store, RPC and privacy tests cover mixed records, time boundaries and both scopes; regenerate sqlc/proto as needed and pass ARCH-26/28 checks.

## impl notes
- Read `completed_at` and candidate `rank` from T501, merge with eligible historical verdict events, sort by event time and stable experiment id, and group by stable model ref. Use existing leaderboard rating/wins/losses fields for wire compatibility and add evaluated-comparison and draw counts at new tags. The existing pairwise `matches` remains pairwise outcome count; comparison count is a separate field. Update the FE mapper in T506.
- Compute all candidates' raw deltas from one pre-event rating snapshot. For n≥3, floor raw changes and award remainder units by descending fractional part, then persisted display position. Include a tied pair as one draw for each candidate; each higher/lower pair adds one win/loss. Legacy dismissals retain their fixed 1500 reference and the current K=32 behaviour.
- Reuse the existing badge catalog and cost redaction path, filtering by ranked candidate ids for new events. Keep legacy detail reads and result actions in T501 untouched. Record one usage sample per participating candidate, not per pair.
