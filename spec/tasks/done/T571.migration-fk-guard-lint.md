# T571 Refuse whole-database or no-op foreign-key guards in new migrations
> st:done@261005 | ssot:ARCH-10 ARCH-43 ARCH-24 | base:ARCH@15 | dep:- | touches:backend/internal/platform/db/

## goal
A migration added after 0129 can only check foreign keys of the tables it rebuilds, and can never leave a bare `PRAGMA foreign_key_check;` that discards its rows, so boot time and deploy safety stop depending on unrelated data.

## acceptance
- [v] a test in `internal/platform/db` walks the embedded migrations numbered above 0129 and fails on `pragma_foreign_key_check` without a table argument and on a `PRAGMA foreign_key_check` statement (with or without a table) whose result nothing reads
- [v] migrations 0001–0129 are exempt by number (ARCH-43: applied migrations are never edited); the test names the rule and the scoped form to use (`EXISTS (SELECT 1 FROM pragma_foreign_key_check('<table>'))` inside the guard)
- [v] a self-test of the checker: a whole-DB guard and a bare PRAGMA in a fixture string are refused, 0129's scoped guard passes
- [v] behaviour unchanged otherwise: ARCH-26 green

## impl notes
- from review/perf-cost-261004 F22
- the scoped pattern to point at is 0129's guard (the rebuilt table plus its FK children)
- parse statements loosely (strip `--` comments, split on `;`); this is a lint, not a SQL parser
