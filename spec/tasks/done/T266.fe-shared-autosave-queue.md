# T266 one autosave queue behind three save features
> st:done@260920 | ssot:ARCH-14 ARCH-18 ARCH-24 | base:ARCH@5 | dep:-

## goal
Replace the three hand-rolled autosave machines with a generic keyed queue in `shared/lib/autosave` and turn `save-draft`, `edit-clip-project` and `edit-post-content` into thin adapters that supply `merge` and `send`.

## acceptance
- [v] `shared/lib/autosave/` exports `createAutosaveQueue<TDraft, TResult>({ debounceMs, retry, merge, send })` returning `{ queue(key, draft), flush(key, failFast?), peek(key), state(key), failure(key), subscribe(key, fn), discard(key), discardAll() }`; it imports no react (ARCH-18) and reads `AUTOSAVE_*` from `shared/config`
- [v] `features/save-draft/model/draft-queue.ts`, `features/edit-clip-project/model/clip-draft-queue.ts`, `features/edit-post-content/model/content-queue.ts` each shrink to their `merge`/`send`/state-mapping (≤120 lines) and keep their exported names so `useAutosave` and consumers are untouched
- [v] the `conflict` state of `content-queue` is a first-class queue outcome (`send` may return `{ kind: 'conflict', ... }`), not a special case inside one adapter
- [v] the generic queue has its own unit tests (debounce, merge of two queued drafts, retry backoff schedule, flush waiters, failFast, discard while in flight) and the existing 685-line `draft-queue.test.ts` plus the other two suites pass unchanged
- [v] behaviour unchanged: the editor and clip autosave render tests pass; ARCH-25 passes

## impl notes
- from review/arch-260919 F8
- the three machines share: module `Map` of queues keyed by slug/projectId, `stateOf`, `publish`, retry with backoff, flush waiters, `discard*` — that is the generic core; what differs is the payload merge and the send/revision contract, which become the two callbacks
- revision handling: `SendDraft` returns nothing, `SendContent` returns the next `bigint` revision — model it as `send(draft, ctx) => Promise<TResult>` and let the adapter store the result in its own state
- keep `SaveState` as the shared union (`shared/api` or `shared/lib`) and map `ContentSaveState`'s `conflict` onto it so the union is one

## result
- `shared/lib/autosave/` holds the machine (274 lines) and the `SaveState` vocabulary that moved in beside it: `createAutosaveQueue({ debounceMs, retryBaseMs, retryMaxMs, retry, conflict, merge, settled, follow, retryOnEdit, send })` → `{ queue, flush, peek, result, state, failure, subscribe, discard, discardAll }`. No react, timing read from `shared/config`
- `features/edit-clip-project/model/clip-draft-queue.ts` 223 → 82 lines and `features/edit-post-content/model/content-queue.ts` 236 → 155, both keeping every exported name; a conflict is a first-class queue outcome (`conflict(error)`) rather than a branch inside one adapter
- four behaviours the two adapters actually disagreed on became options instead of copies: `follow` (send a mid-flight draft as the flight lands vs debounce it again), `retryOnEdit` (an edit restarts the debounce vs leaves the backoff running), `discard(key, rejectWith)` (a deleted post's flush must not resolve as saved), and fail-fast flushes
- `shared/lib/autosave/queue.test.ts` (10 cases): debounce folding, merge across a flight, the doubling-capped backoff schedule, a refusal that stops and resumes on the next edit, flush settling vs failFast, conflict, discard while in flight with subscribers kept, discard with a reason, and a draft that is already what the server holds
- deviation from acceptance ②: `features/save-draft/model/draft-queue.ts` was NOT migrated and stays 748 lines. It is not the same machine: it is a serial channel for the text plus three ASSIGNMENTS (voice, template, target language), each with its own waiters, its own server-side baseline and its own taken-back-on-refusal rule, and it re-keys itself mid-flight when the first save mints the slug. Folding that in would put post rules into `shared/lib`; the file now says so at the top, and it shares `SaveState` and the `AUTOSAVE_*` timing
- verify: ARCH-25 green (2211 tests / 281 files, eslint 0, steiger clean, style + build ok); the 685-line `draft-queue.test.ts` and both migrated suites pass unmodified
