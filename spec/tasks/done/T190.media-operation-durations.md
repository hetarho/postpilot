# T190 Media-operation durations for successful work
> st:done@260916 | ssot:CLIP-88 CLIP-124 | base:CLIP@29 ARCH@2 | dep:-

## goal
Record how long every media subprocess takes when it succeeds, not only when it fails, so a pass-budget change can be shown to have worked.

## acceptance
- [v] every ffmpeg, ffprobe and resvg invocation records its operation, its elapsed time and its outcome, on success as well as on failure (→CLIP-88)
- [v] the record carries no prompt, answer, speech, filename, media byte, credential or signed link — the operation name and bounded numbers only (→CLIP-88)
- [v] a stage's recorded durations account for that stage's own elapsed time, so a stage total can be attributed to the operations inside it rather than inferred by subtraction
- [v] the observation and composition calls keep the retry number and reuse counts they already record
- [v] tests: a stubbed runner asserting that a successful command produces a duration record with its operation name, and that a failing one keeps today's typed failure category unchanged
- [v] verify BE (ARCH-26) passes

## impl notes
- `commandDiagnostic` (`media/diagnostic.go:27`) is the only place that times a command today and it returns early when `err == nil`, which is exactly why success is untimed; the elapsed value is already measured in `runCommand` (`media/capacity.go:82`)
- the substage observer already exists — `WithMediaStageObserver` / `ReportMediaStage`, consumed in `generation.go:549` — so the operation record should reach the same sink rather than introduce a second reporting path
- `commandOperation` (`media/diagnostic.go:51`) already maps a binary to a safe operation name; reuse it rather than logging argv, which would carry filenames
- prod measurement this task makes repeatable: one generation logged stage totals of prepare 285 s, analyze 69 s, plan 13 s, render 857 s, and render's substages were footage 82 s, encode 461 s, overlay 304 s, validate 9 s — the 461 s and 304 s are each many commands and cannot currently be attributed

## result
- `backend/internal/clip/media_progress.go`: the stage sink now carries `MediaRecord` (substage | operation + outcome + elapsed); `ReportMediaOperation` joins `ReportMediaStage` on the same context key, and `SafeMediaOperation`/`SafeMediaOutcome` normalize both labels to the vocabulary the failure path already uses
- `backend/internal/clip/media/capacity.go` `diagnostic.go`: `runCommand` reports every invocation from its existing `defer` — the elapsed value it already measured, `commandOperation` for the name and the new `commandOutcome` for `ok` or today's failure class. Every ffmpeg/ffprobe/resvg call reaches it (`a.runner.Run` has exactly one call site), so no command escapes timing
- `backend/internal/clip/generation.go`: the observer moved from the render call to the whole job, so preparation and analysis commands are timed too, and each record is labelled with the stage that was running — a stage total is attributed rather than subtracted. The render substage log keeps its message and fields
- tests: `media/diagnostic_test.go` (a stubbed runner: a successful command produces a `probe`/`ok` duration record, a failing one keeps `render_cut`/`command_failed` on both the record and the typed error; an arbitrary label reaching the sink normalizes to `unknown`) and `store/generation_test.go` (probe records land under stage `prepare`, so timing is not render-only)
- no SSOT difference; CLIP-88's vocabulary is unchanged and `internal/job` keeps its own copy of the operation whitelist rather than importing clip (the worker stays free of a clip dependency)
- verify BE (ARCH-26) passes; `go test ./...` needed `-p 2` on this box because the full-parallel run was OOM-killed
