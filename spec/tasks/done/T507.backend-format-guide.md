## impl notes
- Why the backend and not a row: TMPL-41 keeps one teacher for one grammar, changed in the same commit as the parser, and prompt wording is code (LANG-27); the guide is not a UI catalog resource, so LANG-7 (no runtime catalog fetch) stands.
- Write the two golden files first from the current client (`formatGuide()` with `i18next.changeLanguage('ko'|'en')` and default limits, e.g. a throwaway vitest), then port the prose into Go as constants and make the Go output match them byte for byte. Use explicit `strings.NewReplacer` placeholders (`{bodyMax}` …) or `fmt` with positional arguments — no template engine — and keep the example as one constant used by both the text and the tests.
- Language: the proto `Language` enum (`language.proto`, LANG-1) on the wire; map to the template package's own `ko`/`en` type at the rpc edge. On the client, map the resolved i18next locale to the enum with the helper post creation already uses for `target_language`.
- Read pattern: `CatalogDocumentPanel` with `useCatalogDocument` (load before any click, disable the copy until ready, then `copyText` on in-memory text). Put `useFormatGuide` in `entities/template/api` beside the other reads, with `staleTime: Infinity` per locale (the text only changes with a deploy).
- The template.proto service comment ("no procedure enqueues work or calls a provider") stays true here; T508 changes it.
