# T402 The writer, its repair and answer limits bound region rows by width
> st:done@260926 | ssot:CDS-86 CDS-77 CLIP-116 CDS-20 | base:CDS@26 CLIP@45 | dep:-

## goal
Generated and answer-bound intro/outro text is bounded by what fits the slot's width at its floor, not by the retired per-role character counts.

## acceptance
- [ ] `ai/composition_prompt.go` `generatedRegionSlots` states, per generated region row, the slot's role, size, floor, allowed lines and `max_syllables` from `design.RegionSlotBudget` (narrowed by the row's own declared `chars`), instead of `chars` + `lines: 1`; the system prompt says a row must fit its slot and may use two lines only where `lines` is 2; prompt goldens re-recorded (`UPDATE_PROMPT_GOLDEN=1`, including `ai/testdata/narration-prompt-prefix.txt`)
- [ ] `attachRegionRows` and `repairGeneratedSlot` judge a generated row with `design.FitRegionSlot` at the slot's width — a row that shrinks or wraps is kept as written; an `Over` row (too wide at the floor, or a glyph the slot's face lacks) takes the shortest grounded alternative that fits, otherwise it is omitted with the existing `intro_/outro_slot_shortened|omitted` notices
- [ ] both functions index the preset's slots by the entry's CLIP-147 placement offset, not by the entry-local row index (a second intro entry is bounded by the slot it lands in)
- [ ] FE `composition-field-maximum.ts` narrows an answer bound to a fixed region row to that slot's `RegionSlotBudget` (TS port over the mirrored metrics), so `ClipCompositionInputs` counts and refuses against the width budget; its test covers intro A slot 1 and a two-line slot
- [ ] the slot notices' copy no longer says "한 줄" / "one line" (ko and en in `entities/clip-project/config/i18n.ts` and `features/inspect-clip-observations`); i18n parity test passes
- [ ] `ai/region_slots_test.go`, `generated_maxima_test.go` and the narration service test pin the new slot description; BE gate (ARCH-26) and FE gate (ARCH-25) green

## impl notes
- the budget is advisory for the writer and the input counter; the fit is the judge everywhere (admission from T401, the AI repair here, the renderer), all on T400's table, so a row the counter admits can still overflow only through wide Latin — then admission or repair handles it as `Over`
- `max_syllables` counts Korean syllables at the floor across the allowed lines, so the writer's unit matches CLIP-116's counting rule (syllables excluding spaces and punctuation)
- `regionSelection` in `ai/composition_copy.go` duplicates `ProjectDesign.RegionPresets`; route it through the latter so T404's default change reaches the writer too
- a declared row maximum stays the author's stricter bound and wins when smaller than the budget (CLIP-116)
