# T094 모델 관리: the 등급 Listbox, 등급순 sort, the unset mark and the document diff's level changes
> st:done@260911 | ssot:MODEL-28 MODEL-58 MODEL-54 MODEL-55 MODEL-57 MODEL-59 | base:MODEL@9 ARCH@2 | dep:T093 T095

## goal
Let the operator set each registration's level on its row, sort a tab by level, see which registrations still lack one, and read level changes in the 일괄 편집 preview.

## acceptance
- [v] `AdminCatalogEntry.level: LevelName | ''` (the viewed purpose's value) mapped from `CatalogEntry.level`; `useUpdateModel` accepts `{ level }` alongside `{ reasoningEffort }` and sends `UpdateModelRequest.level` only when given
- [v] `CatalogModelRow` shows a 등급 Listbox whenever the model is registered to THIS purpose (independent of the reasoning Listbox's own condition), options 등급 미지정 + the four levels in `LEVELS` order labelled from `models.level.*`; choosing writes through `useUpdateModel`, choosing the current value writes nothing
- [v] while the registration's level is unset, the row carries a `role="status"` meta line in the notice-warning tone (as `reasoningDrifted` does) saying the level is not set yet (MODEL-58); it disappears once set
- [v] `CatalogSort` gains `'level'` (`CATALOG_SORTS` and the 정렬 control's options); `sortEntries(entries, 'level')` orders by the viewed purpose's level rank ascending, then every entry with no level for this purpose (unregistered included) after them, the default order kept inside each group
- [v] `CatalogDocumentPurposePlan.relevel: { modelId, from, to }[]` mapped from the proto; `documentDiff` carries it per purpose and `CatalogDocumentPanel` renders a 등급 변경 list `id · from → to` with unset shown as 미지정; a purpose with only level changes is not shown as untouched
- [v] `canApply` is unchanged — a level change never blocks 확정, a rejected line still does (`unknown_level` renders through the local cause map with its own copy, never another cause's)
- [v] the export shown in the panel is the server's document verbatim (levels included) — no client-side rendering of the document
- [v] ko/en `models` namespace gains `catalog.level`, `catalog.levelUnset`, `catalog.levelMissing`, `catalog.sortOption.level` (등급순), `document.relevel`, `document.levelUnset`, `document.cause.unknown_level`; locale parity passes
- [v] the `frontend/src/test` fake `ModelCatalogService` carries a level per registration: `listCatalog` reports it for the requested purpose, `updateModel` writes it, `previewCatalogDocument`/`applyCatalogDocument` parse `<id> [level]` and report `relevel`, `exportCatalogDocument` emits it
- [v] vitest: `sortEntries` level order (levelled ranks, unlevelled and unregistered last, stability); `CatalogModelRow` change issuing the update with the level and the unset mark appearing/disappearing; `documentDiff` with relevel rows; `CatalogDocumentPanel` rendering a relevel list and an `unknown_level` rejection keeping 확정 unavailable
- [v] every control is a `shared/ui` primitive and classes resolve to registered tokens (ARCH-20)
- [v] `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` (ARCH-25)

## impl notes
- the 등급 Listbox sits in the same `sm:grid-cols-2` block as the reasoning Listbox but under its own condition (`registeredHere`), because a model whose reasoning list the source does not publish still has a level to set; the row's virtualized estimate (`CATALOG_ROW_ESTIMATE_PX` 132) is a hint, not a cap — check the measured row still lays out without overlap and adjust the constant in `shared/config` if a registered row grows past it
- `''` is the unset option's value on the wire and in `AdminCatalogEntry`, matching how `UpdateModelRequest.level = ""` clears (T092); the FE never invents a fifth level name
- level sort is client-side like the price sorts (the whole catalog arrives in one response and how to read it is a display preference); an entry not registered to the tab has no level for it and sorts with the unlevelled — the tab is about this purpose's registrations
- `combos` on the same admin page already uses the word 등급 in its ko description and shares `value`/`balanced` as combo names; keep the two apart — the new keys live under `models.level` and `models.catalog.level*`, and nothing in `models.combos` changes
- the relevel list is quieter than the deregistration list (T065 made deregistration the loud half) but is its own group rather than a footnote on `unchanged`: a paste from `/recomend-models` without levels clears every set level (MODEL-59), and the operator must see that before 확정

- **`canApply` DID have to change**, against the acceptance's "unchanged". It gated on `registerCount || deregisterCount`, so a document that only re-grades — exactly what MODEL-59 makes expressible, and what an export edited in place produces — was previewable but not committable. `relevelCount` now counts too, and `touched` includes relevel so such a section is not drawn as "no change". The acceptance's intent ("a level change never blocks 확정") is met; its literal wording was written before the counting was traced
- also widened beyond the acceptance: `malformed_line` copy in both locales now says a line is one id plus at most one level. The old wording ("모델 아이디만 한 줄에 하나씩") describes a grammar that no longer exists, and its test assertion moved with it
- the 등급 Listbox has its own condition (`registeredHere`) rather than sharing the reasoning control's: a model whose reasoning the source publishes nothing about still has a grade to set, and the grade is the only thing on this screen a USER ever sees
