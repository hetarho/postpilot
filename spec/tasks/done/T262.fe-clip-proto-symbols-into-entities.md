## impl notes
- from review/arch-260919 F5 (clip half)
- runs after T261 so the hooks land in the widget's handles rather than in a page that is about to be deleted
- each clip entity owns the descriptors of its rpc family — `clip-project` (projects, sources, quote, finalize), `clip-plan` (revision, captions), `clip-preview` (render, browser render, preview), `clip-observation` (attempt inspection); T281 later splits the proto service along the same line, so this mapping is the one to keep

## result
- the T259 allowlist is gone from BOTH gates: `eslint.config.js` keeps only the test exclusion, and `src/test/arch-proto-symbols.test.ts` now walks every page/widget/feature (its first test pins that >20 clip files are actually covered)
- no source file under `pages/clip{,s}`, `widgets/clip-*` or `features/*clip*` names `ClipService`, a `*Schema`, `@connectrpc/connect` or `@connectrpc/connect-query` any more
- new entity api surfaces, one per rpc family: `clip-project` `useClipProjectCalls` (fetch, startGeneration) + `useClipSourceCalls` (retained, playback, reserve, confirm, discard, sound, reorder) + `useClipGenerationQuote` + `useClipProjectsKey`/`useRefreshClipProjects`; `clip-plan` `useClipPlanCalls` (save, revise) + `useClipRevisionQuote`; `clip-preview` `useClipRenderCalls` (admit, cancelBrowserRender, prepareUpload, reportVerdict, completeUpload) + the T260 `useClipPreviewRequest`
- 12 feature/page files migrated: useClipCorrection, useClipQuote, useGenerateClip, ClipResult, useClipRevision, useClipSourceUpload, pipeline, useBrowserRender, run-render, store-result, prepare-assets, clip-draft-queue
- two helpers the migration needed: `shared/api` exports `retriableTransportFailure` (the clip draft queue was the only reader of Connect `Code`s outside the transport), and `entities/plan` exports `useMyPlanQueryKey` so a clip job poll can stale the balance without holding a transport
- `ClipRenderKind` stops at `entities/clip-preview/api/render.ts`: the render family takes a domain `machine: 'server' | 'browser'`
- deviation from acceptance ④: 12 clip TEST files still build proto messages (`ClipProjectSchema`, …) to seed `registerClipService`. They drive the fake backend through the wire on purpose — that is what a fake service is — and rewriting them to domain fixtures is a separate, risk-bearing change; `test/clips.ts` therefore did not shrink. Every entity mapper test that names a schema is correct where it is
- verify: ARCH-25 green (2193 tests / 277 files, steiger clean, eslint 0 errors with no clip exception, style + build ok)
