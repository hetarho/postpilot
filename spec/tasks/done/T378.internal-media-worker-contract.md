# T378 Workers authenticate to a separate versioned media API
> st:done@260925 | ssot:ARCH-3 ARCH-6 ARCH-23 ARCH-41 ARCH-46 ARCH-47 ARCH-49 ARCH-54 | base:ARCH@11 | dep:T376

## goal
Expose a bounded internal Connect contract that authenticated workers can pull, renew and report through without gaining user or database authority.

## acceptance
- [v] The new worker service exists only on a separate internal listener; the public API has no worker procedures, and worker credentials authorize no user-facing RPC.
- [v] Authentication rejects missing, invalid, disabled and other-environment credentials before reading a request body; untrusted body fields cannot select the worker identity or acting account.
- [v] Claim advertises supported operation/contract/runtime versions and returns only compatible work; unknown versions and render/asset mismatches are visible refusals rather than indefinite silent polling.
- [v] Renew/progress, failure and completion requests require the current stage/attempt lease; no-work responses differ from incompatibility, cancellation and lost-lease responses.
- [v] Request size, timeouts, progress fields and typed diagnostics are bounded; no signed links, credentials, media bytes or raw subprocess/provider prose enter logs.
- [v] Connect contract/mapping and HTTP integration tests cover authorization isolation, pre-body refusal, caps, version negotiation and stale leases; generated-code checks and ARCH-26 pass.

## impl notes
- Create `proto/postpilot/v1/clip_media_worker.proto` with `ClipMediaWorkerService`: ClaimMediaStage, RenewMediaStage, GetMediaArtifactAccess, ReserveMediaOutputs, CompleteMediaStage, FailMediaStage and GetMediaRuntimeStatus. Reuse typed clip plan/source messages or the existing versioned plan codec; do not expose arbitrary FFmpeg args or host paths.
- GetMediaRuntimeStatus returns only deployment-scoped contract/profile versions, aggregate waiting/active counts and the authenticated worker's lease/readiness state for health/drain checks, with no user payloads. Claim is a short unary poll returning an optional lease and retry-after hint, not an open request for the duration of a render. Renew carries bounded progress and returns cancellation plus lease remaining time; the client derives a conservative monotonic expiry from the response, never trusting agreement between PC and VPS clocks.
- Place server mapping in clip/rpc and the generated client wrapper in clip/workerclient; runtime worker behavior consumes its own ports without importing generated messages. T379 supplies artifact behaviors; until then those methods explicitly refuse unsupported operations.
- Use net/http authentication middleware outside Connect handlers. Current Connect guidance requires authentication before protobuf/JSON parsing; reuse standard library crypto and the existing server plumbing rather than adding an authentication dependency.
- API configuration: MEDIA_INTERNAL_ADDR defaults empty (listener disabled during transition; worker layouts set :9000), MEDIA_WORKER_CREDENTIALS as a JSON map from environment-unique worker ids to random bearer secrets. Worker configuration: MEDIA_API_URL, MEDIA_WORKER_ID, MEDIA_WORKER_TOKEN. Reject empty/duplicate identities and weak placeholder credentials when the listener is enabled; support rotation by accepting a separately named replacement identity before removing the old one.
- Secrets are server-side env values and are never reused from user sessions or R2/provider credentials. The worker sends its configured identity and bearer credential as headers; compare fixed-size token hashes in constant time and set the authenticated principal on the request context.
- Use a 4 MiB decoded internal request cap, 10-second unary deadlines and 2-second idle polling with bounded jitter; the public API's body cap remains unchanged. Worker artifact bytes always travel through private storage.
- Allow HTTP only on the private Compose network or a documented encrypted private network; remote examples use Tailscale. The Compose task binds the VPS host port to loopback and never publishes this listener through edge Caddy.
- Official reference checked 2026-09-25: https://connectrpc.com/docs/go/interceptors/ . Re-read current docs if implementation changes the library configuration.
