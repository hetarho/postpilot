# T082 Approved clip credit quotes and admission

## goal
Bind every new clip AI attempt to an explicitly approved server-issued maximum and expose authoritative reservation and settlement amounts.

## acceptance
- [v] an authenticated quote RPC validates the owned project, ready source batch, current recipe/answers and explicit model refs, then returns a quote id, expiry and maximum credits without downloading media, starting a job, invoking AI or holding credits
- [v] a quote freezes the selected source manifest, generation settings, model refs, reasoning/budget assumptions and known unit prices; changing any bound input before start requires a fresh quote and approval
- [v] start requires both the quote id and explicit approval of exactly its maximum; missing, expired, foreign, modified or reused-for-another-attempt approval cannot enqueue paid work
- [v] one accepted quote binds to one durable job through the existing dispatch-gated source linkage; concurrent starts and ambiguous-response retries cannot produce two executable jobs or two reservations
- [v] reservation prices actual prepared chunk counts plus one plan call with the frozen assumptions, checks `required <= approved_max` and available lots atomically, and issues no debit or allowance on refusal/error
- [v] every clip settlement is bounded by both held credits and the approved maximum, while provider overage stays visible in the ledger and never drains another lot; T081's zero-charge failure rule remains intact
- [v] quote expiry before acceptance refuses start; expiry after acceptance does not invalidate the frozen job; disabled models or an ineligible execution path still stop the worker before the affected call
- [v] owner-scoped clip reads distinguish approved maximum, actual reserved credits, final user charge, refund and settlement status; unreserved, unsettled, legacy-unknown and master-exempt values cannot masquerade as a settled zero
- [v] migration and service/store/RPC tests cover old rows, integer/decimal boundaries, forged ceilings, expiry, changed settings/prices/budgets, minute-boundary durations, owner isolation, duplicate acceptance, failed linkage, hold races and provider overage
- [v] legacy clip payloads lacking approval fail before admission/AI after upgrade; newly approved payloads also remain non-executable until T084 supplies the complete guarded runner; free rerender and non-clip jobs keep working
- [v] ARCH-25 through ARCH-28 and ARCH-31 local gates pass, including regenerated Go/agent/TypeScript protobuf outputs and sqlc; no live generation is required

## impl notes
- add `QuoteClipGeneration` to `ClipService`; its request names project, source batch and both model refs, and its response carries `quote_id`, `max_credits`, `expires_at` and the priced call/budget summary; append `quote_id` and presence-aware `approved_max_credits` to `StartClipGenerationRequest` without renumbering existing fields
- persist quotes in a clip-owned `clip_generation_quotes` table: random id, owner, project, unique source-batch id, canonical input digest, versioned pricing/budget snapshot, maximum, expiry and nullable consumed job id; use the existing owner/composite-FK conventions and cascade transient quote rows with the batch
- use the next free embedded migration number, expected `0039`; add nullable `approved_max_credits` to `usage_admissions` with a nonnegative CHECK, leaving legacy rows NULL and all settled amounts untouched; SQL stays in each owning context with sqlc regeneration
- quote lifetime is the earlier of source-batch expiry and five minutes from issuance, configured in typed platform config; refreshing an unconsumed batch replaces its prior quote id, while a consumed quote cannot be refreshed into another paid attempt
- canonical binding includes project ratio/target, template id and recipe content, required answers, ordered source ids/fingerprints/metadata, explicit observe/write refs, resolved reasoning settings, completion budgets and exact unit rates; serialize neither local paths nor video bytes nor signed links
- quote conservative observation count is `min(sum(ceil((reported_duration_ms + duration_tolerance_ms) / 60000)), ceil(max_total_duration_ms / 60000) + source_count - 1)`; with current limits the global maximum is 49, and the worker still reserves only actual verified chunks; use checked integer arithmetic and test 59/60/61-second boundaries
- price through one usage-owned estimator: retain the 30,000-token prompt assumption and analyze/plan completion caps of 8,192/32,768 including reasoning; parse exact decimal rates, accept explicit known zero, refuse missing/invalid/negative rates and never lower budgets merely because media is compressed
- expose pricing through consumer-owned ports wired in `cmd/api`; durable payload version 2 freezes the accepted maximum, pricing, budgets and policy version independently of the transient quote row, so source cleanup cannot erase settlement authority
- consume the quote and link the source batch in the same clip-store transaction after inserting a non-dispatchable job; preserve activation compensation and active-project uniqueness, and resolve duplicate acceptance to the already linked job rather than activating a second one
- compare current bound assumptions at acceptance; after acceptance use the frozen rates for reservation and token-derived clip usage estimates, and enforce those maximum rates at the provider boundary in T083/T084 instead of silently repricing a running job
- extend the successful worker allowance with approved maximum and frozen call policy; require the ceiling inside usage's write transaction, not only in the handler, and retain QUOTA-16 master shadow accounting without any actual lot debit or insufficient-balance refusal
- add an optional accounting projection to `ClipProject`, keyed by job id, through a clip-owned reader port backed by usage's published behavior; use presence-aware amounts and states `not_reserved|reserved|settling|settled|exempt|unavailable`, with actual master debit/refund zero and shadow cost separate
- map refusal reasons `CLIP_QUOTE_REQUIRED`, `CLIP_QUOTE_EXPIRED`, `CLIP_QUOTE_CHANGED`, `CLIP_CREDIT_CEILING_EXCEEDED` and `CLIP_MODEL_PRICING_UNAVAILABLE` through the typed RPC error seam and both language catalogs; a required amount above approval is information for a newly approved attempt, never permission to debit it
- staged safety is intentional: version-1 paid jobs fail closed, and version-2 execution remains guarded as unavailable until T084 replaces the old signed-proxy runner; do not deploy a partial series as an enabled clip feature or add a switch that bypasses these guards
