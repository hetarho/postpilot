# T062 Price sort on 모델 관리 and the retired delisted badge
> st:done@260909 | ssot:MODEL-28 MODEL-20 | base:MODEL@6 | dep:-

## goal
The operator can order the catalog by price on every tab, and the screen no longer carries the 제공 종료 badge or the delisted banner that MODEL-20 r4 retired.

## acceptance
- [v] a 정렬 Listbox sits beside the 제공사 Listbox with three options — 기본 · 가격 낮은순 · 가격 높은순 (en: Default · Price: low to high · Price: high to low) — defaulting to 기본, which is today's provider/newest order
- [v] price sorts key on `outputUsdPerMillion` numerically, tie-break on `inputUsdPerMillion`, then the default order; entries with an empty price (video models, 토큰 단가 미공개) come last in BOTH directions
- [v] the sort is applied after the tab gate and the operator's filters, over the whole response (virtualized rows included), and survives a tab switch the same way the filters do
- [v] `Badge 제공 종료`, the delisted banner, `delistedCount` and the `catalog.delisted` / `catalog.delistedBanner_*` keys (ko + en) are removed; the `listed` field stays on the entity and mapper
- [v] tests: `catalog-view.test.ts` — `sortEntries` with each order: numeric (not lexical: "9.5" before "10"), the input tie-break, unpriced last both ways, default order untouched; `AdminModelsPage.test.tsx` — choosing 가격 낮은순 reorders the visible rows, and the test at the "제공 종료" / delisted-banner block is replaced by one asserting a `listed: false` curated entry renders with no badge and no banner
- [v] verify FE (ARCH-25) green on the pinned Node

## impl notes
- MODEL-28: `catalog-view.ts` gains `export type CatalogSort = 'default' | 'price-asc' | 'price-desc'`, `DEFAULT_SORT`, and `sortEntries(entries, sort)` — the current `sortEntries` body becomes the `default` branch; price branches use `Number(price)` on the decimal strings (display ordering only, no arithmetic, so float is fine) with `''` mapped to `+Infinity` for asc and treated as "always last" for desc via an explicit unpriced partition
- keep sort out of `CatalogFilters` ← filters narrow, sort orders; the manager holds `const [sort, setSort] = useState<CatalogSort>(DEFAULT_SORT)` and computes `visible = sortEntries(filterEntries(tabEntries, filters, purpose), sort)`; the base `sorted` memo becomes the default-order input so switching sorts never re-runs the gate
- the Listbox is the existing `shared/ui` `Listbox<CatalogSort>` with `FieldLabel` and `aria-labelledby`, the same pattern as the provider control; keys `catalog.sort` `catalog.sortDefault` `catalog.sortPriceAsc` `catalog.sortPriceDesc` in `resources/ko/models.ts` and `resources/en/models.ts`
- MODEL-20: the server no longer sends delisted rows (sibling task T061), so the FE removal is safe in either order; the `catalog.delisted*` keys go with the badge — i18n keys with no reader are lint noise
- the count line (`catalog.count`) and the empty states are unchanged; sorting never changes `shown`/`total`
