## goal
Replace per-output-frame DOM seeking with worker-owned sequential decoding and bounded original access.

## acceptance
- [v] Selected source intervals use Mediabunny range/sample decoding with source/output timestamp mapping, rather than setting HTMLVideoElement.currentTime for each exported frame.
- [v] Local File/Blob sources are read lazily and remote retained originals support bounded/range access where available; no render downloads every complete original eagerly.
- [v] Transitions retain only the required active source set, with named in-flight frame/byte limits and prompt VideoFrame/texture release.
- [v] Fixed rates, VFR/cadence eligibility, crop and frame selection preserve the established timeline; proxy cadence is never used as original slow-motion evidence.
- [v] Cancellation, seek supersession, unsupported codecs, expired access and decode failures stop owned work without frame drops, unbounded retries or server fallback.
- [v] Tests cover same-source split/reordered ranges, transitions, rate/cadence cases, queue pressure, stale callbacks and resource release; real-browser fixtures and required local checks pass.

## impl notes
- Parallel group execution uses isolated worktrees; exact final cross-slice edits remain uncertain (touches:-). Coordinate shared public exports and adapter seams explicitly; review and integration are serial and resolve overlap without shared-checkout writes.
- Use Mediabunny VideoSampleSink and source adapters supported by the locked version; resolve any upgrade with T588's inventory and ARCH-33.
- Pass decoded VideoFrames directly through the compositor resource adapter where supported. Measure any required bitmap/texture copies and make no zero-copy claim.
- Start with at most two simultaneously active footage inputs for the supported transitions. Bound decoded windows by bytes as well as frame counts and avoid whole-frame CPU readback in the ordinary path.
- Preserve accurate seeks to a decodable preceding keyframe and decode forward to the required interval; reordered cuts open independent bounded iterators rather than sharing a mutable DOM playhead.
- Remove the normal export dependence on source/bitmap request round trips to the window; retain a tested capability refusal or composition-preserving fallback where an API is unavailable.
- Register source/decode/resource timings in the T588 harness; headless correctness is distinct from final device throughput.

Container stream order replaces player default/bitrate selection, with a bounded two-packet ambiguity refusal.
