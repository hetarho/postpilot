# T233 The template's caption entries reach the narration in outline order
> st:done@260918 | ssot:CLIP-65 CLIP-112 CLIP-121 CLIP-134 | base:CLIP@33 ARCH@3 | dep:T228

## goal
Hand the narration call the outline's caption entries in order and keep a fixed entry's text exact by substituting the server's own resolved text.

## acceptance
- [v] the narration request carries the outline's caption entries in order, each with its id, its position among the outline's entries, and either its resolved exact text or its writer instruction and character bound
- [v] the response supplies an interval for each declared caption; the writer decides where in the resolved flow it sits
- [v] a fixed entry's text in the saved plan is the server's resolved text byte-for-byte even when the response returns something else (CLIP-65)
- [v] a generated entry is grounded and repaired exactly as a written caption is today
- [v] a declared caption the response omits records one CLIP-108 notice with action `removal` and refuses nothing
- [v] the outline order is guidance, not a check: a response that orders two declared captions differently is delivered as written
- [v] the request stays byte-identical for a template that declares no caption entry (the section is omitted whole, as `template_guide` already is)
- [v] tests: fixed text survives a rewriting response, an omitted entry notices, no-caption templates leave the request unchanged, and the plan's captions still hold disjoint windows (CDS-62)
- [v] ARCH-26 verify clean

## impl notes
- model it on the existing `generated_region_slots` payload in `ai/narration_prompt.go`: one entry per declared caption, and a matching response array the schema requires — the pattern for "the template declared it, the writer places it" already exists for region rows.
- substitution follows `ai/composition_copy.go:attachRegionRows`: resolve the entry through the composition resolver, then overwrite the response's text for fixed entries rather than validating it — a check would leave the owner reading a diff the product can simply not produce.
- a declared caption is a caption like any other afterwards: CLIP-66's non-overlap, CDS-62's windows and CLIP-137's grounding all apply, and the repair ladder needs no new rung.
- this is the one new capability in CLIP r33 (a template could not declare a caption before, `unsupported_role`); keep it behind the same admission the other declared elements pass so a malformed entry fails before any paid call (CLIP-92).

## result
- `clip.DeclaredCaptions` (in `region_lines.go`) is the one reading of "the outline's caption entries": role `caption` and no cut, which a frozen legacy snapshot's cut-bound caption is not (CLIP-140).
- the flow call stops resolving them into the plan (`ai/flow_parse.go`), the narration request carries them in outline order as `declared_captions` (`ai/narration_prompt.go`, `schemas/narration.schema.json`), and `narrationCaptions` merges the response's placements back with the written captions so all of them pass the same window, exposure and repetition admission (`ai/narration_parse.go`).
- a fixed entry's text is the template's: the response's text for it is discarded before admission, and `PortableText.Authored` carries that fact to V11 so the grounding a WRITTEN claim answers to is not applied to the owner's own words (CLIP-65, CLIP-122).
- a declared caption takes a MINTED narration identity like every other caption, not its entry id: `ValidNarrationShape` holds every caption on the timeline to one identity rule, and ② edits them all the same way (CLIP-17). Only a refusal or an omission names the outline entry, which is what the owner has to fix.
- an entry the response leaves out records one `copy_omitted` notice naming it and refuses nothing; the outline order is never checked.
- tests: `ai/declared_caption_test.go` (the request's own JSON for a fixed and an ai entry, the authored text surviving a rewriting response, the writer's placement being used, disjoint windows, an omitted entry's single notice, an ungrounded ai entry dropped beside an authored one that is not, and a reversed order delivered as written) and `ai/no_template_prompt_test.go` (no entry, no key). The narration prompt golden was re-recorded for the new paragraph.
- no media behaviour changed — a declared caption reaches the renderer in the same shape a written one does — so ARCH-37's image stage was not re-run for this task.
