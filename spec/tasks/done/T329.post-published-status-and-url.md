# T329 A finalized post becomes 발행됨 from a pasted Naver URL, replaceable and clearable
> st:done@260924 | ssot:POST-13 POST-21 POST-73 POST-75 POST-77 POST-78 POST-84 QUAL-25 QUAL-39 ARCH-6 ARCH-7 ARCH-24 | base:POST@11 QUAL@3 ARCH@9 | dep:T322 T323

## goal
- The post context knows `published`: pasting a valid Naver address on a post whose current revision is the finalized one publishes it, replacing restamps it, clearing returns it to 확정, VOICE learning keeps working on it, and QUAL can read the published window.

## acceptance
- [v] SavePostPublishedUrl with a valid address on a `finalized` post whose `finalized_revision = content_revision` answers the post with status `published`, `published_url` the normalized address and `published_at` now (RFC3339); `can_finalize` is false on it.
- [v] A different valid address on a `published` post replaces it and restamps `published_at`; the identical normalized address is a no-op that writes nothing and keeps `published_at`.
- [v] An empty or whitespace-only `url` on a published post returns it to `finalized` with both columns NULL and `finalized_revision`/`finalized_at` untouched; on any other status it is a no-op.
- [v] An address failing POST-77 (scheme not http/https, host not `blog.naver.com`/`m.blog.naver.com` case-insensitively, userinfo, any port, an empty path, over 2048 characters) is InvalidArgument `POST_PUBLISHED_URL_INVALID` and nothing is written: status, URL and `updated_at` are unchanged (POST-84).
- [v] A `m.blog.naver.com` address and an `http` address are stored as `https://blog.naver.com` + path (+ `?query`); the fragment is dropped; no check is made against the account's other published URLs (POST-78).
- [v] A draft or review post, or a finalized post whose finalized revision is stale, answers FailedPrecondition `POST_NOT_FINALIZED` (132).
- [v] While a generate, revise or model_experiment job targets the post the save answers `POST_BUSY`; a learn_voice, extract_memory or compare_voice_rule job does not block it.
- [v] An unknown slug is `POST_NOT_FOUND`, another account's is `POST_FORBIDDEN`.
- [v] LearningSnapshot succeeds on a published post exactly as on a finalized one (POST-21, R11).
- [v] `PublishedPosts(ctx, user, limit)` returns the account's published posts only, `published_at DESC, slug DESC`, at most `limit`, each with slug, content revision, content, content language, nouns and `published_at` (QUAL-39).
- [v] A published post lists with status `published`; DeletePost removes it and its `post_measurements` row (FK cascade), and is still refused with `POST_BUSY` while any job is active (POST-29).
- [v] Tests: `internal/post/publication_test.go` (`TestParseNaverBlogURL` over `testdata/published_url/cases.json`, `TestPostStatusSetIsTheFourLifecycleValues`, `TestSavePublishedURLPublishesReplacesAndClears`, `TestSavePublishedURLRefusesAnInvalidAddressAndWritesNothing`, `TestSavePublishedURLNeedsTheCurrentFinalizedRevision`, `TestSavePublishedURLIsBusyOnlyForContentWritingJobs`, `TestSavePublishedURLIsOwnerScoped`, `TestLearningSnapshotReadsAPublishedPost`, `TestDeletePostRemovesAPublishedPostAndStillWaitsForAnyJob`, `TestPublishedPostsAreNewestFirstAndBounded`); `internal/post/limits_test.go` `TestPublishedURLMaxChars`; `internal/post/store/publication_store_test.go` (publish/replace/clear round trip, the refusal predicate on a draft and a stale finalized row, the window order and owner scope, `content_nouns` NULL and array decode through GetPost and the window, LearningSnapshot on a published row, a published row in ListPosts, the measurement cascade); `internal/post/rpc/handler_test.go` (`TestToProtoPostCarriesThePublication`, T322's session test renamed `TestSavePostPublishedUrlRequiresASession`); `cmd/api/job_subjects_test.go` `TestOnlyGenerationRevisionAndComparisonsWritePostContent`.

## impl notes
- T322 left the proto (`Post.published_url`, `Post.published_at`, `SavePostPublishedUrl`), `post.ErrPublishedURLInvalid` and `post.ErrPostPublished` declared in types.go and mapped in `rpc/handler.go` `toConnectError`, and a CodeUnimplemented `SavePostPublishedUrl` stub. T323 left the columns `published_url`, `published_at`, `content_nouns` (the pair CHECK, `json_valid`), the partial index on `posts(user_id, published_at) WHERE status = 'published'`, `post_measurements` with its cascade, and GetPost selecting every new column in table order so it still returns `sqlc.Post`. This task generates no proto and adds no migration.
- `types.go`: `StatusPublished = "published"` beside the three. Replace the stale "this context only ever writes `draft`" comment with who writes each value: the create writes draft; generation, revision and an applied comparison write review; FinalizePost writes finalized; SavePublishedURL writes published and its clear writes finalized.
- `Post` gains `PublishedURL string` ("" = none), `PublishedAt *time.Time` and `ContentNouns []string` (nil = none). T341 writes nouns; this task only reads them.
- New `types.go` `PublishedPost{Slug string; ContentRevision int64; Content PostContent; ContentLanguage *Language; Nouns []string; PublishedAt time.Time}`. A nil ContentLanguage is for QUAL to read as Korean (R16); post does not default it.
- `ActiveJob` gains `WritesContent bool`, documented as "a job that writes this post's content or observations when it completes". Post never names a job kind (ARCH-6).
- `cmd/api/job_subjects.go` gains `postContentWork(kind string) bool`, beside `voiceOwnedKind`: true for `job.KindGenerate`, `job.KindRevise` and `job.KindModelExperiment`, false otherwise. `adapters_post.go` `postJobFinder.ActiveForPost` sets `WritesContent: postContentWork(found.Kind)`.
- Kinds that carry a post subject at HEAD: generate, revise, model_experiment, extract_memory, learn_voice and compare_voice_rule (`postVoiceWork` callers). analyze_voice, validate_voice_profile and seed_voice carry none, and the three clip kinds carry a project instead. Only the first three write the post.
- A lab comparison job also counts as busy, because post cannot see a comparison's origin. While one runs on a published post, replacing or clearing its URL waits for it (R8 names the kind).
- `limits.go`: `const PublishedURLMaxChars = 2048`, counted with `utf8.RuneCountInString` like every other *MaxChars bound. T343 mirrors it on the FE.
- New pure `publication.go` `ParseNaverBlogURL(raw string) (string, error)`. It trims, checks the length, runs `url.Parse`, then refuses in this order: scheme not `http`/`https`; `Opaque` set or `Host` empty; `User != nil`; `Host` containing `:` (any port, including an empty `host:`); `strings.ToLower(Hostname())` not exactly `blog.naver.com` or `m.blog.naver.com`; `strings.Trim(EscapedPath(), "/") == ""`.
- ParseNaverBlogURL returns `"https://blog.naver.com" + EscapedPath()`, plus `"?" + RawQuery` when RawQuery is non-empty. The fragment and a bare `?` are dropped, and path case is preserved.
- Every refusal is `fmt.Errorf("%w: <rule>", ErrPublishedURLInvalid)`: one wire reason with no params, because the FE pre-check states POST-77's rule itself (T322).
- A path of only `/` counts as empty, because it is the blog's home and not a post address. The FE mirror must apply the same rule.
- The case table is a shared fixture, not a Go literal: `backend/internal/post/testdata/published_url/cases.json`, `{ "_comment": [...], "cases": [{ "name", "input", "stored": string | null }] }` (`null` = refused), after the `internal/template/testdata/grammar/cases.json` precedent. `TestParseNaverBlogURL` reads it, and T343's FE mirror runs every case of the same file, so the fixture is the contract between the two parsers.
- The fixture covers each refusal, including `blog.naver.com.evil.com`, `section.blog.naver.com`, a missing scheme, `ftp:`, `:443`, `user@`, a bare `/` path and an empty path. It also covers `http`→`https`, an upper-case host, mobile normalization with a query, fragment dropping and surrounding whitespace. The at-limit and over-limit cases are built in the harness from `PublishedURLMaxChars`, never spelled out as 2 KB strings.
- `ports.go` gains `Publication{ PublishPost(ctx, slug, userID, url string, publishedAt time.Time) (bool, error); UnpublishPost(ctx, slug, userID string, updatedAt time.Time) (bool, error); ListPublishedPosts(ctx, userID string, limit int) ([]PublishedPost, error) }`. It joins the `Storage` composite, and Service holds it as `publications`, assigned in NewService like the other narrow ports.
- `posts.sql` stays ASCII. `PublishPost :execrows` is `UPDATE posts SET status = 'published', published_url = ?, published_at = ?, updated_at = ? WHERE slug = ? AND user_id = ? AND ((status = 'finalized' AND finalized_revision = content_revision) OR status = 'published')`. The service passes `s.now()` for both stamps, and the store formats it with `formatTime`, whose fixed width is what makes `ORDER BY published_at` a correct string order.
- `UnpublishPost :execrows` is `UPDATE posts SET status = 'finalized', published_url = NULL, published_at = NULL, updated_at = ? WHERE slug = ? AND user_id = ? AND status = 'published'`.
- `ListPublishedPostsByUser :many` selects `slug, content, content_language, content_revision, content_nouns, published_at` `WHERE user_id = ? AND status = 'published' ORDER BY published_at DESC, slug DESC LIMIT ?`. A NULL content cannot occur (FinalizePost requires content), so the store returns an error naming the slug if one does.
- `store.go` `toPost` maps `published_url` (NULL → ""), parses `published_at` with `parseTime` (NULL → nil) and decodes `content_nouns` with `encoding/json` into `[]string`. NULL and `[]` both read as nil, and invalid JSON is an error naming the slug. Put the nouns decoder in `store/content.go` beside the content codec so T341's encoder sits next to it.
- `Service.SavePublishedURL(ctx, userID, slug, raw string) (Post, error)` first trims raw. A non-empty value goes through ParseNaverBlogURL before anything is read, like SaveGenerationOptions' argument checks.
- It then calls `ownedPost`, which gives ErrNotFound or ErrForbidden.
- An empty value on a post that is not `published` returns `Get` and writes nothing.
- A non-empty value on a `published` post whose `PublishedURL` equals the normalized one returns `Get` and writes nothing.
- A non-empty value on draft or review, or on finalized with `FinalizedRevision != ContentRevision`, returns `ErrPostNotFinalized`.
- Next comes the busy check: `s.jobs.ActiveForPost`, where `active != nil && active.WritesContent` returns `ErrPostBusy`. Pending experiments are not consulted; R8 names jobs only.
- Last is the write: `PublishPost` for a non-empty value, `UnpublishPost` for an empty one, then `Get`.
- A zero-row PublishPost re-reads the post. The ownedPost error wins; a published post already carrying this URL is success; anything else is ErrPostNotFinalized.
- A zero-row UnpublishPost re-reads the post. The ownedPost error wins; a post that is no longer published is success.
- `Service.PublishedPosts(ctx, userID string, limit int) ([]PublishedPost, error)` refuses `limit <= 0` with an error and otherwise delegates. It is the read T335's `PostSource.Published` adapter consumes (R14).
- `LearningSnapshot` gate, in `service.go:856` and `store.go:305` alike: `status IN (finalized, published)` with the revision equality and the FinalizedAt check unchanged (R11). The fake_test.go `LearningSnapshot` follows.
- `fake_test.go` implements the three Publication methods with the same predicates, and keeps `PublishedURL`/`PublishedAt` on the stored Post.
- `rpc/handler.go` `SavePostPublishedUrl` replaces the stub: `actingUser`, then `svc.SavePublishedURL(ctx, userID, req.Msg.GetSlug(), req.Msg.GetUrl())`, then `toConnectError("save published url", err)`, then `SavePostPublishedUrlResponse{Post: toProtoPost(saved)}`.
- `toProtoPost` sets `PublishedUrl: p.PublishedURL` (field 27), `PublishedAt: formatOptionalTime(p.PublishedAt)` (field 28) and `CanFinalize: p.Content != nil && p.Status != post.StatusPublished`.
- T322's `TestSavePostPublishedUrlRequiresASessionAndIsNotYetImplemented` asserts a signed-in call answers CodeUnimplemented, which stops being true here. Rename it `TestSavePostPublishedUrlRequiresASession` and keep the anonymous `AUTH_REQUIRED` call and the `user_id`/`account_id`/`owner_id` field walk; the signed-in behaviour is pinned by the service tests.
- `ErrPostBusy`'s comment gains the URL save as its second use.
- Test fixtures reach `published` through the real path: `SetGeneratedContent` → `Finalize` → `SavePublishedURL`. In the store tests it is `UpdateGeneratedContent` → `Finalize` → `PublishPost`.
- The measurement-cascade store test inserts a `post_measurements` row with raw SQL through `newStoreWithHandle`, filling R15's NOT NULL columns.
