# T404 New projects start at intro A and outro B; existing projects keep their presets
> st:done@260926 | ssot:CLIP-111 CLIP-139 | base:CLIP@45 | dep:-

## goal
A newly minted clip project renders intro A and outro B unless the owner picks otherwise, while every project that already exists keeps rendering the presets it renders in today.

## acceptance
- [ ] a new migration (next free number after the highest in `backend/internal/platform/db/migrations/`, re-checked right before creating it) sets `intro_preset = 'b'` where it is `''` and `outro_preset = 'e'` where it is `''` on every existing clip project, with a migration test beside `migration_0062_test.go`
- [ ] `composition.DefaultDesign()` returns intro `a` and outro `b`, and project creation stores those explicit ids when the request names none, so no new row carries `''`
- [ ] every surface that draws a region without a project's selection (template editor preview, legacy conversion) uses the new defaults; the legacy body root attributes stay inert
- [ ] FE: `CLIP_DEFAULT_REGION_PRESETS` is `{ intro: 'a', outro: 'b' }`, `ClipRegionPresets` and the project draft's preset types are the key unions of the mirrored design.json (`keyof typeof design.regions.intro/outro`), and `ClipDesignSelection` falls back through the constant instead of `'b'`/`'e'` literals; the fake server seeds the defaults on create
- [ ] store, rpc and FE tests that pinned b/e defaults (`store/project_design_test.go`, `store/no_template_generation_test.go`, `rpc/project_design_test.go`, `CompositionDesignFrame.test.tsx`, `ClipDesignSelection.test.tsx`) pin the new defaults and the kept presets of an existing project
- [ ] BE gate (ARCH-26), `pnpm gen:sql` diff-clean (ARCH-28) and FE gate (ARCH-25) green

## impl notes
- why the backfill: `''` has meant "the shared defaults" (CLIP-139), so flipping the default would silently restyle every project that never chose; writing the old defaults into those rows first keeps them (CLIP-111 "an existing project keeps the presets it renders in")
- the backfill bumps no `edit_plan_revision`: the rendered look does not change, so nothing is stale
- keep `RegionPresets()`' empty-id fallback for rows written by an older binary during a rolling deploy; it now resolves to a/b
- memory note: a goose migration edited after it ran locally never re-runs — create the file once, and on a dev DB verify with the host-side schema diff
