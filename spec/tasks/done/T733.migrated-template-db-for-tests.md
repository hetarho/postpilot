# T733 Migrate a template database once per test binary and copy it per test
> st:done@261109 | ssot:ARCH-10 ARCH-24 ARCH-26 | base:ARCH@21 | dep:- | touches:backend/internal/platform/db/dbtest backend/internal backend/cmd | lane:- | explore:-

## goal
DB-backed Go tests get a private, fully migrated SQLite file copied from a template migrated once per test binary, instead of replaying all 164 migrations per test; no production code and no assertion changes.

## acceptance
- [v] new package `backend/internal/platform/db/dbtest` (test support, imported only from `_test.go` files): `dbtest.Open(t testing.TB) *db.DB` returns a fresh migrated private DB under `t.TempDir()` closed on cleanup, and `dbtest.WriteMigrated(t testing.TB, path string)` writes a migrated copy at a caller-chosen path for sites that open or reopen by path
- [v] the template is built once per binary (sync.Once) by the real `db.Migrate` on a `db.Open`ed file in its own temp dir, then `PRAGMA wal_checkpoint(TRUNCATE)`, both pools closed, the file's bytes kept in memory and the temp dir removed; a template failure fails every caller with the original error
- [v] `backend/internal/platform/db/dbtest/dbtest_test.go` TestCopyMatchesFreshMigration: a copy and a fresh `db.Migrate` file match on `sqlite_master` (type, name, tbl_name, sql), `PRAGMA user_version`, `journal_mode` = wal and `foreign_keys` = 1 on the opened copy, an empty `PRAGMA foreign_key_check`, and every table's rows (goose's version table compared without `tstamp`); TestCopiesAreIndependent: a write through one copy is invisible to a second copy and to a later copy
- [v] every site that opens a new file and immediately runs `db.Migrate` on it, with nothing between them, uses dbtest; test bodies, fixtures seeded after migration and assertions are unchanged
- [v] the exclusions in impl notes are untouched (`git diff` shows no change in those files)
- [v] before/after recorded in result from the same Mac with `cd backend && go test -count=1 ./internal/post/store/ ./internal/experiment/store/ ./internal/usage/store/` (wall time per package, base measured in the worktree before editing) and the full `go test -count=1 ./...` wall time after the change
- [v] fast checks: `gofmt -l .` empty, `go vet ./...`, `go build ./...`, and `go test -count=1` on `./internal/platform/db/...` plus every package whose test files changed — all pass (the shared harness change cannot be import-bounded, so the converted packages are the affected suite)
