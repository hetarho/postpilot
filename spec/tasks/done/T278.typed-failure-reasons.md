# T278 a failure reason is a proto enum both sides compile against
> st:done@260920 | ssot:ARCH-3 ARCH-17 ARCH-24 | base:ARCH@5 | dep:-

## goal
Replace the untyped failure-reason strings with a `FailureReason` proto enum whose names are the current strings, so a new reason is one proto edit that the BE compiler and the FE type checker both enforce, and delete the hand-kept 212-entry allowlist.

## acceptance
- [v] `proto/postpilot/v1/error.proto` gains `enum FailureReason` with one value per reason now in `rpcserver/failure_reasons_test.go` (names identical, `UNKNOWN_FAILURE = 0`); `AppErrorDetail.reason` stays a `string` on the wire and carries `FailureReason.String()` — no wire change, agent untouched
- [v] `rpcserver.NewAppError(code, message, reason postpilotv1.FailureReason, params)`; all 280 call sites in `*/rpc/` pass the enum constant, and the 33 `"UNKNOWN_FAILURE"` / 19 `"AUTH_REQUIRED"` literals are gone (`grep -rn '"[A-Z_]*FAILURE"' backend/internal --include=*.go | grep -v _test` is empty)
- [v] `failure_reasons_test.go`'s allowlist is deleted; a small test pins that every enum value except 0 is referenced by at least one rpc adapter (dead reasons are flagged)
- [v] FE: `AppFailureReason = keyof typeof FailureReason` (generated), `appFailureSpecs: Record<AppFailureReason, Spec>`, and `errors.ts` in both locales typed `Record<AppFailureReason, string>` so a missing spec or translation is a `tsc` error; `resources.test.ts`'s failure-coverage check still passes
- [v] behaviour unchanged: ARCH-25, ARCH-26, ARCH-28 pass; the error copy shown for an existing reason is identical (snapshot one ko and one en rendering)

## impl notes
- from review/arch-260919 F19
- why an enum and not a generated catalog: buf already generates for all three sides (ARCH-3), so the enum is the catalog with no new tooling; keeping the wire as a string means old clients and the agent need nothing
- buf lint: `ENUM_VALUE_PREFIX` is already excepted in `buf.yaml` (the LLM-contract enums use bare names), so the bare reason names lint clean
- FE typing: `Record<AppFailureReason, string>` over 212 keys is fine for `tsc`; use `satisfies` so the object literal keeps literal key inference

## result
- `proto/postpilot/v1/error.proto` gains `enum FailureReason` with 222 values, `UNKNOWN_FAILURE = 0`, names identical to the strings that were on the wire. `AppErrorDetail.reason` is still a `string` carrying `FailureReason.String()`, so the wire, older clients and the agent are untouched
- `rpcserver.NewAppError(code, message, reason postpilotv1.FailureReason, params)`; 276 literal call sites became typed constants in one pass, and the five that pass a domain string (`plan.ReasonMasterOnly`, a typed failure's `Reason()`, an eligibility refusal) go through the new `rpcserver.ReasonOf`, which is the one translation and lives at the adapter because the domain may not import proto (ARCH-7)
- the 212-line hand-kept allowlist is deleted. Its scanner survives and now reads the typed constants, and two tests stand where it stood: every reason the tree emits must be a `FailureReason` value, and every value must be emitted by something — with six documented exceptions (the zero value, the agent's two publish failures, the browser's `NETWORK_UNAVAILABLE`, and two notice codes the plan and the profile carry as data)
- four reasons the browser renders were missing from the rpc list the enum was built from — `CLIP_PROCESSING_FAILED` `CLIP_LAYOUT_FREQUENCY` `VOICE_PROFILE_FIELD_REQUIRED` `NETWORK_UNAVAILABLE` — and the enum is now the union of both halves, which is the point of having one
- FE: `AppFailureReason = keyof typeof FailureReason` (generated), `appFailureSpecs` is `Record<AppFailureReason, FailureParamSpec>` and both `errors.ts` catalogues `Record<AppFailureReason, string>`, so a reason with no params spec or no copy is a `tsc` error
- deviation from acceptance ②'s grep: `"UNKNOWN_FAILURE"` still appears in three DOMAIN files (`llm/errors.go`'s constant, the clip pipeline's durable failure, the publishing store's legacy row read). Those are durable job failures, not Connect statuses, and typing them would put proto in the domain — `ReasonOf` translates them at the edge and the new dead-reason test covers them
- verify: ARCH-25, ARCH-26, ARCH-27 and ARCH-28 green (2214 FE tests, 61 BE packages, regenerated protos byte-identical after `pnpm gen:proto`)
