## impl notes
- one embedded JSON is the single source of the constants because CDS-7 promises identical output for identical input and CDS's constraints ask the renderer and verifier to read one file; the FE copy exists so the preview and validators mirror the same numbers, and the byte-equality test is what keeps the two from drifting (the earlier `COPY_STYLE_MEASUREMENTS` mirror had only a comment)
- `align` is a new field rather than a widened `position` because the anchor-step rule (CDS-38, V13) reasons over the vertical anchor alone; a combined id would force every consumer to split strings
- `center` → `lower_mid` on migration: the old centre sat at y ≈ 846 in 9:16, between UPPER_MID 700 and LOWER_MID 1100, and LOWER_MID keeps a bottom-leaning caption closest to where the owner saw it
- the migration uses exact-token `REPLACE` because `encoding/json` emits no whitespace and the tokens include their quotes and key, so a caption text can never match; the read-time mapping is a belt for the deploy window, not the authority
- style ids stay short ASCII (`clean memo bold mark`) because they are wire and JSON identifiers; the Korean names live in the `clips` i18n namespace
- text limits count Korean syllables per CDS's constraints; a Latin or digit run counts one per character — the CDS tables are Korean-first and the stricter reading is safe
- no rendering changes here: T103 draws the four styles; this task only makes every stored and incoming plan speak the new vocabulary and pins the numbers
