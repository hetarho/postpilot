# T182 Generated text obeys its declared maximum
> st:done@260916 | ssot:CLIP-118 CLIP-116 CDS-55 CLIP-106 CLIP-108 | base:CLIP@26 CDS@19 ARCH@2 | dep:T179

## goal
State each generated element's declared maximum to the composition model and repair an over-long response through the existing shorten-then-omit ladder.

## acceptance
- [v] the frozen request states the declared maximum of every ai element and ai row as that element's own bound, with the response schema unchanged
- [v] a generated text above its maximum is repaired by the existing ladder — the grounded shorter alternative first, then omission with its notice — where that ladder is reached today only by region slots (`composition_copy.go:229`)
- [v] a shortened or omitted element records a CLIP-108 notice naming the element and the action, and the plan stays deliverable under CLIP-106 rather than failing the attempt
- [v] an element within its maximum is passed through untouched, with no notice
- [v] tests: over-long with a fitting alternative is shortened, over-long without one is omitted with the notice, within-bound is unchanged
- [v] verify BE (ARCH-26) passes

## impl notes
- the bound goes into the prompt text (`ai/composition_prompt.go`), never into the response schema ← a numeric constraint in a provider schema has already cost this project a production outage, and the server re-measures the response anyway
- reuse `repairGeneratedSlot` (`ai/plan_ladder.go:265`) with the element's declared maximum instead of writing a second ladder; it already takes the limit as an argument and already prefers the grounded alternative
- notices follow the existing `clip.AddPlanNotice` call beside the slot repair (`composition_copy.go:251`), with names in the same `_shortened`/`_omitted` shape
- measure with `design.Chars`, the same counter T179 and T181 use
- fixed and answer-bound text never enters this ladder — it is an authoring or admission refusal (→CDS-64 →CLIP-118)

## result
- the request gained `generated_text_limits`, one entry per declared maximum outside a region block ({element_id, chars} and row_index for a row), with one prompt sentence bounding that element. The response schema is untouched: a numeric constraint in a provider schema is what caused the 260914 outage, and the server measures the answer itself anyway
- region rows already carried their slot's count in `generated_region_slots`; that entry and its repair now take the smaller number when a row declares one
- `boundGeneratedText` runs the existing `repairGeneratedSlot` — grounded shorter alternative, then omission — and only for a text already over its maximum, so an element inside its bound is passed through exactly as generated, with no notice and no newline rule applied to it that did not apply before
- notices are `composition_text_shortened` and `composition_text_omitted`, allowlisted in `SafeAttemptCheck` and mapped to owner copy on the frontend; the omitted one reuses the existing 긴 문구 sentence. The notice is the whole record — a second CopyFallback entry would report one omission twice
- fixed and answer-bound text never enters the ladder: only an `ai` element or an `ai` row is measured here
- base moved CLIP@25→26 at completion: r26 is group item minimums and the writer's cut budget, untouched by character maxima
- tests: shortened with a fitting alternative, omitted without one, unchanged within the maximum, and the request listing exactly the declared maxima (never a region row)
