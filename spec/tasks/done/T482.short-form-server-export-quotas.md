## goal
Enforce the same 15–60-second output contract everywhere and spend one monthly server slot only for a successful stored export.

## acceptance
- [v] Generation targets, manual plan validation, render admission, template preview and browser/server final output checks share the 60-second maximum and existing 15-second minimum, measured on the transformed timeline with transitions. No legacy over-60-second exception is introduced.
- [v] Commercial server allowances are free 0, Light 2, Basic 6, Pro 15 and Max 60 per benefit month; annual coverage renews counts monthly. Export admission atomically reserves before queueing rendering and simultaneous requests cannot exceed available allowance.
- [v] One available stored successful server result commits one count once; explicitly changing and exporting another output needs another slot. Existing-result reuse/download, manual previews/edits and browser exports consume no slot. Storage failure, cancellation or failed output validation releases the reservation.
- [v] Duplicate enqueue/completion, cancellation races, worker retries/restart and an active render crossing monthly reset/paid expiry retain one originating reservation; releasing an expired slot never increases the new period’s allowance.
- [v] GetMyPlan/clip UI show used, reserved, remaining and renewal; exhaustion offers renewal/eligible upgrade/supported browser export. Browser incapability offers server only if entitled, and never silently switches kind. No credits-to-export exchange or separate count purchase appears.
- [v] Real-store concurrency and job-recovery tests prove reservation invariants; FE tests cover duration bounds and render choice states. Run ARCH-25/26/28 plus the matching local CPU media-image smoke for exactly 60 seconds and refusal above 60 under ARCH-36/37.

## impl notes
- Extend the clip-owned benefit windows opened by T477 with a reservation table keyed uniquely by render/job id and its origin window, plus guarded reserve/commit/release mutations. Store a bounded reservation state and count against used + open reservations in one writer transaction.
- Compose allowance reads in plan’s response through a consumer-owned clip port; usage remains product-agnostic and never decrements export counts. Preserve the existing operator render path separately from commercial numeric offers; no master plan is sold or assigned a fabricated quota.
- Bind reservation to the canonical requested output revision/kind and durable render id. Same-job retries reuse the slot, a retained matching stored result returns without rerender, and an explicit changed-output render starts a new reservation. Release orphan reservations if job creation fails; recover terminal jobs once on boot.
- Cap duration at the owning domain constant and align all projections/prompts/FE controls, template samples, preview and measurement tolerances. Do not lower source-input bounds or change the established rendering contract, browser sampling/caption workload, worker profile or concurrency.
- The provider/grade check for clip AI is integrated by T480 and the workspace can consume it through T481; this task gates server rendering independently of AI credits. A free account can still manually edit and use a supported browser render.
- Use typed quota-exhaustion data (counts and exact renewal instant) with ko/en copy. A browser export is not described as unlimited server work. No existing long-video migration is necessary per the confirmed test-data scope.
