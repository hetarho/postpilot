# T314 A comparison's origin decides its verdict form
> st:done@260922 | ssot:MODEL-31 MODEL-34 MODEL-36 MODEL-37 MODEL-41 MODEL-60 POST-13 ARCH-3 ARCH-6 ARCH-7 ARCH-10 ARCH-24 ARCH-40 | base:MODEL@14 POST@9 ARCH@7 | dep:-

## goal
- A comparison records whether it was started from the editor or the model lab; the lab's verdict is a pick that applies nothing, its follow-ups are gated by the source post's status, and the editor's verdict keeps applying.

## acceptance
- [v] StartWriteExperiment stores `origin` (`editor` from the editor's A/B 비교 생성, `lab` from the model lab's write tab; an unspecified value is stored as `editor`); observe and analyze comparisons store `lab`; GetExperiment/ListExperiments expose it; existing rows are backfilled (write → `editor`, others → `lab`).
- [v] On a `lab` experiment of any stage, ChooseWinner records the winner verdict and applies nothing: the experiment is `decided` with no pending application, PendingForPost stops reporting it, and the editor's 생성 / A/B 비교 controls re-enable for that post.
- [v] On an `editor` write experiment DecideWriteExperiment behaves as before (verdict + application, optional adoption); ChooseWinner on an `editor` write experiment and DecideWriteExperiment on a `lab` experiment are refused `FailedPrecondition` `EXPERIMENT_STATE_INVALID` before any write. UseSingleCandidate is not the paired verdict and stays available to both origins (→MODEL-34 →MODEL-37): it ranks nothing either way and applies exactly where a verdict applies.
- [v] ApplyWinnerOutput on a `lab` write or observe experiment succeeds only while the source post is `draft` or `review`; a finalized post is refused `FailedPrecondition` with the new stable reason `EXPERIMENT_POST_FINALIZED`; a detached (deleted) post is refused `EXPERIMENT_STATE_INVALID`; the editor's retry path and analyze application are unchanged.
- [v] An application attempted on a `lab` experiment marks it requested, so a failed one keeps the experiment unresolved for its post with a visible retry, exactly as an editor apply failure does; the unresolved-per-post unique index and PendingWriteForPost share the new predicate.
- [v] AdoptWinnerModel works for a decided `lab` write experiment (the 활성 모델로 사용 follow-up) with the existing catalog checks.
- [v] Frontend: the action bar offers `결과 적용` / `결과 적용하고 활성 모델로 변경` only for an `editor` write experiment; every `lab` experiment offers `이 결과로 선택`; a decided `lab` write/observe experiment offers content application only while the post is `draft`/`review` (absent for a finalized or missing post) plus 활성 모델로 사용; analyze keeps its confirm dialog; dismissal and the unpaired survivor's action keep their labels.
- [v] The editor and the lab send their origin explicitly on start; the RPC test helper records it.
- [v] Tests: BE service (lab pick applies nothing and resolves, editor pick applies, cross-form refusals, finalized/detached gate, requested-apply failure stays pending), store (backfill, new index predicate, PendingWriteForPost), handler (origin mapping, new reason in the stable-reason allowlist); FE (ExperimentActions per origin/stage/post status, start calls carry origin, review page with a finalized post); ARCH-25/26/28 gates pass.

## result
- Proto: `ExperimentOrigin` (UNSPECIFIED/EDITOR/LAB) on `StartWriteExperimentRequest` and `ModelExperiment`, plus the `EXPERIMENT_POST_FINALIZED` failure reason. UNSPECIFIED reads as EDITOR on both ends, so a client predating the field keeps the behaviour it was written against.
- Migration 0073 adds `origin` and `apply_requested`, backfills every write comparison to `editor` and every decided write verdict to an owed application, and rebuilds `one_unresolved_write_experiment_per_post` around the owed-application predicate that `PendingWriteForPost` now shares. `CountPublishableForVoice` and the 0048 voice-deletion trigger are untouched, as planned.
- Domain: `Origin` on `Experiment` and `StartRequest`; `Experiment.AppliesOnVerdict()` is the one place the two verdict forms are told apart. `Start` forces `lab` for observe and analyze. `ApplyWinner` consults the new `PostDirectory` port before the runner and records the owed application first, so a failure leaves the comparison holding its post with a retry.
- `post.Service.PostStatus` is a new ownership-checked status read that skips the image listing and presigning `Get` performs; `experimentPosts` in the composition root adapts it and turns a missing or foreign post into `ErrInvalidState`.
- Frontend: `ModelExperiment.origin`, a required `origin` argument on the write-comparison start (the editor sends `editor`, the lab sends `lab`), and an action bar that reads `commits` from the origin. A decided lab comparison asks for its post only while it might still write to it, through a new `enabled` option on `usePost` that also reports a disabled read as settled rather than pending.
- Deviation from this task's own acceptance, resolved in favour of the SSOT it cites: the draft refused `UseSingleCandidate` on an editor write comparison as well. MODEL-34 and MODEL-37 make the unpaired survivor a separate path that ranks nothing and may still be applied, and an editor comparison's post holds no content until it is. Only the paired verdict is refused per origin; the acceptance line was corrected to say so. No SSOT change is needed.
- Three existing service tests moved from `Choose` to `DecideWrite` because the editor's paired write verdict now commits through that call alone. The in-memory store's `PendingForPost` was rewritten to carry the real predicate rather than `!Revealed()`, so the service tests test what the index enforces.
