# T220 Sequence-rendered caption styles
> st:done@260917 | ssot:CDS-81 CDS-4 CDS-80 | base:CDS@21 | dep:T219

## goal
Render the styles that draw one layer per output frame, through a bounded temporary PNG sequence the existing overlay chain consumes.

## acceptance
- [v] a sequence style rasterises one PNG per output frame of its caption interval into the attempt's temporary workspace and the overlay chain reads it with `image2` at the output frame rate
- [v] the frames are deleted when the cut they belong to finishes, and the sequence budget joins CLIP-33's temporary-disk accounting so a long caption cannot exhaust the workspace
- [v] a static style still rasterises exactly once and keeps the `loop` filter path, unchanged
- [v] each style's motion matches what the registry declares and V9 verifies it per style
- [v] a render with one sequence caption and one static caption produces the same output twice (determinism), pinned by a golden test
- [v] the media image stage builds and runs locally with a sequence caption in the fixture (ARCH-37)
- [v] ARCH-26 passes

## impl notes
- frames go to disk and enter through `image2` rather than `image2pipe` ← the overlay chain already takes several inputs and feeding pipes concurrently makes scheduling and partial-failure retry much harder, while files let one failed caption re-render alone
- decoder threads stay limited on the sequence input exactly as the existing single-frame overlay inputs do ← an unbounded image demuxer can leave the scheduler waiting after an overlay stops consuming
- the sequence is generated per caption, not per cut, because a caption may cross cuts (→CDS-27)

## result
- `internal/clip/design/caption_draw.go` draws the thirteen sequence styles, one frame at a time, from the same measured lines the manifest carries; `caption_frame.go` is the input they are handed. Every frame is a pure function of the plan and the frame index, so a golden pins each style at three points of one interval and a second run of any frame is byte-identical.
- `internal/clip/media/sequence.go` rasterises one PNG per output frame of the caption's interval into `seq-NNNN/` under the attempt's workspace, cropped to the caption's box grown by the style's own declared bleed. `rasterize` became `rasterizeTo`, which reserves the LAYER's bytes rather than the canvas's, and `workspaceFile` admits the one directory the workspace now nests.
- The overlay chain gained a layer kind: `captionLayer` is either a plate or a sequence. A sequence enters through `-f image2 -start_number 1` at the output frame rate with decoder threads bounded exactly as a single-frame input's, is shifted to its own start with `setpts`, and is overlaid at the crop origin with no `loop` and no `fade` — its motion is already drawn into every frame. A static style's path is untouched, which the graph goldens show unchanged.
- CLIP-33 now descends into that directory: the workspace total counts the frames, and `releaseLayers` deletes them the moment the overlay pass that read them is encoded, so a long sequence never sits beside the output.
- `CaptionMotion` was already per style from T219; the composition manifest now recomputes an element's motion after the layout picks its style, because `declaredManifest` had computed it from the authored `auto`. A per-style V9 test walks every approved style.
- The determinism check renders both kinds at once and compares the delivered file twice, byte for byte (`TestRenderSmokeSequenceCaption`, ARCH-37). The composition grammar retired the per-element `style` attribute, so a project cannot yet name two styles for two captions — that is T221's — but CDS-84 already produces the mix: the project allows only `팝 바운스`, Jua sets `여기 진짜 좋아요` and cannot set 똠얌꿍, so the second caption falls back to the static default and the two kinds share one overlay chain. The graph-level golden pins the same pair of layers without a real binary.
- Verified: ARCH-26 green, `docker buildx build --target media-smoke` (ARCH-37) green with the sequence fixture, `--target media-tooling` (ARCH-39) green.
