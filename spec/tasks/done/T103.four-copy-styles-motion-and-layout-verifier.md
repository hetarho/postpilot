## impl notes
- the manifest is produced by a pure layout pass so the verifier can run before any source byte is downloaded, which keeps a rejected plan credit-free and fast (CLIP-20); the same manifest is what T105 feeds its fallbacks and what T107's contrast sampler extends
- the settle motion is an overlay `y` expression (`Y0 + 12*pow(1-min(1,(t-T0)/0.18),3)`) and an alpha `fade`, never a second rasterisation per frame; CDS-4 forbids anything else and a plate PNG stays one file per copy
- `Keyword` is a caption field, not a marker inside the text, because the text must stay exactly what the owner typed and the verifier compares text against the answers set (T105's V11)
- drop shadow is resvg's `feDropShadow` (supported in 0.48); the stroke uses `paint-order="stroke fill"` as today
- V3 contrast for unplated styles needs frame sampling and lands in T107; here `bold` and `mark` are accepted on the strength of stroke and shadow, and the verifier leaves V3 as a documented gap until then
- stable-reason naming follows LANG-21: one code per verifier check so the correction step can point at the field, never a generic "invalid plan"

- **the bundled FFmpeg had no `fade` filter.** Its `--enable-filter` list is a deliberate allowlist, and the nonroot smoke found this at once (`No such filter: 'fade'`). CDS-4 admits no other entrance, and the alternatives — nine pre-rasterised opacity plates per caption — are strictly worse, so `fade` joined the allowlist and MEDIA.md now says why. The media image layer rebuilds once.
- the verifier could not have the signature the acceptance named: `design.Verify(manifest, plan, canvas)` taking `clip` types would make `design` import `clip`, which imports `design`. The manifest is instead defined IN `design` (each element carrying its cut, style, anchor, window and motion) so `design.Verify(manifest, ratio)` needs nothing else, and `clip.Manifest` is an alias of it so the name the acceptance uses exists. `clip.VerifyLayout` restates a `design.Violation` as the `planViolation` the acceptance asks for.
- V5 (lines and characters) shares `plan_layout_size`: the six codes the acceptance lists have no text-specific one, and size is the closest of them. `ValidateEditPlan` still refuses over-long copy first, with `plan_copy_lines`/`plan_copy_chars`, so V5 is the belt on the manifest.
- the keyword's offset is measured from the line UP TO AND INCLUDING the keyword, not from the prefix alone: the smoke proved a prefix can be a single space, which has an advance but no ink box, and `--query-all` reports boxes. 크게 강조 colours its word as a `tspan` inside the line so the run stays shaped as one — an overdrawn glyph at a measured offset would drift by the kerning between the prefix and the word, which a highlight rectangle can absorb and a glyph cannot.
- `Keyword` is a new caption field (proto field 8) and rides the plan through the FE model and mapper; only 크게 강조 and 형광펜 accept one, and `parse.go` drops it for any other style. A keyword absent from the text is `plan_copy_keyword`.
- the six `CLIP_LAYOUT_*` reasons are each their own named constant because the public-reason scan reads literals assigned to a name containing "reason"; they are registered in `failure_reasons_test.go`, `appFailureSpecs` and both locales.
- `COPY_STYLE_MEASUREMENTS` now carries the CDS numbers and the Go mirror test compares it against `design.Styles` rather than a second table; T106 should delete it once the preview reads `clip-design.json`.
- CDS-20's word (어절) wrapping is still grapheme-boundary candidate generation, as it was before this task; the fit prefers a single line and then the narrowest, so word breaks are among the candidates but not required. Worth an update-ssot or a follow-up if CDS means it strictly.
