## goal
A clip stores at most one linked post of its owner. ①'s 글 연결 sets, replaces or clears it, ③'s 이 체험으로 클립 만들기 sets it, and a deleted or replaced post reads as no link.

## acceptance
- [v] `UpdateClipProject` takes `optional string linked_post_slug`. An empty value clears the link. A slug that is not the caller's post reads as not found, and a post without canonical content is refused as invalid input. A running or finalized project refuses the change the way it refuses other edits.
- [v] `GetClipProject` and the project list project the link as `ClipLinkedPost { slug, title, updated_at }` only while the post still exists with the same identity. When the post was deleted, or its slug now names a different post, the field is absent. The stale columns are cleared on the project's next write. The post context is not touched.
- [v] ① shows a 글 연결 row with the linked post's title, or the empty state. Pressing it opens a picker:
  - The search starts with the clip's title.
  - First come `ListPosts(query = clip title)` rows, then `ListPosts(query = "")` rows, in the list's own order. Both lists keep only `content_ready` rows and drop duplicates.
  - Picking a row links that post. The picker also offers 연결 해제 while a post is linked.
  - Following feedback-no-help-copy, the row and picker carry names only, with no help text.
- [v] `createClipFromPost` (T692) links the source post in the same update that seeds the new clip.
- [v] Linking changes no other project setting and starts no AI work.
- [v] Tests:
  - Backend, `backend/internal/clip/app`: `TestLinkPostRequiresOwnedCanonicalPost`, `TestLinkPostRefusedWhileRunningOrFinalized`, `TestLinkedPostAbsentAfterDeleteOrSlugReuse`, `TestUnlinkClearsLink`.
  - The rpc projection test for `ClipLinkedPost`.
  - Frontend, `features/edit-clip-project`: `links a post from the picker with title matches first`, `unlinks`, `hides posts without content`.
  - `pages/editor`: `createClipFromPost links the post`.
- [v] Relevant go test, vitest, `pnpm lint`, `pnpm lint:fsd`, buf/proto generation and the ARCH-24 checks pass.

## impl notes
- The new picker’s320px/200% browser check exposed existing shell/account-column and clip-return-label overflow (mobile layout viewport expanded to413px). Keep account controls intrinsic, wrap the return label, let generation actions wrap at enlarged text, and cap the closed link label at two lines with its full accessible name. Verify the actual visual viewport, not only innerWidth.
- POST-91 also searches tags. Keep actual title matches from the narrowed query first (CLIP-215), then the unfiltered list in server order; tag-only matches stay in that fallback order.
- T692 currently seeds through CreateClipProject, not a later Update. Add optional linked_post_slug to CreateClipProject as well so the seed and link are one atomic project write. Existing clients omit it. Picker link mutations send only the link through the project write lane and never resubmit unrelated settings.
- CLIP r62–r63 source-colour changes do not affect linking; base refreshed to r63. Use the repository’s `gen:proto` command.
- Storage: a new goose migration adds `clip_projects.linked_post_slug TEXT` and `clip_projects.linked_post_created_at TEXT`. Write bare `TEXT`, never `TEXT NULL` (sqlc types an explicit NULL as interface{}). Keep every queries file ASCII-only for sqlc.
- Why the creation time is stored: `posts.slug` is reused after a delete (for example `20261015-untitled`), so the created-at pair is the identity fence. No foreign key is used, because SQLite `SET NULL` on a composite key would null `user_id`.
- Clip reads posts through a new port in `internal/clip`: `LinkedPosts.Get(ctx, user, slug) (LinkedPost, error)` returning `Slug, Title, CreatedAt, UpdatedAt, ContentReady`. Implement it in `backend/cmd/api` over the post service's owner-scoped read, like the existing `adapters_post.go` adapters (ARCH-6: `internal/clip` never imports `internal/post`).
- Proto: use the next free field numbers in `UpdateClipProjectRequest` and `ClipProject` after T689 and T690's additions. Regenerate with `pnpm gen:proto` (gen.mjs normalizes the end of file; never hand-edit generated files).
- Errors: an unknown post maps to `clip.ErrNotFound`, a post without content to `clip.ErrInvalid`, and a running or finalized project goes through the existing guards. No new FailureReason is needed.
- The picker reuses `entities/post` list queries. Matching titles stay first because `query` is the clip title; the server's search is the existing POST-91 one.
- The link is not a writing input in this task. T699 sends the post's text to the writers.
