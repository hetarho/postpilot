# T563 Record every confirmed refund and release credits a refused refund froze
> st:done@261004 | ssot:ARCH-24 | base:ARCH@15 | dep:T562 | touches:backend/internal/billing/

## goal
A second confirmed refund on a credit pack is recorded once like the first (BILL-11), a refund the provider definitively refused releases the customer's frozen credits, a renewal blocked by an order in review is logged rather than skipped silently, and expired quotes are purged.

## acceptance
- [v] `reverseRefundedEntitlements` for a pack treats a purchase already marked refunded as done (its lot was voided by the first refund) instead of returning `ErrRefundConflict`; the completion transaction then records the refund event, the confirmed total and the mail as for a first refund
- [v] a refund cancel answered with a definitive 4xx refusal (the docs' codes, e.g. NOT_CANCELABLE_AMOUNT, ALREADY_CANCELED_PAYMENT, alongside today's INVALID_REQUEST) reads the payment back: balance unchanged → the request fails and the frozen credits are released; our cancel key present with the expected amount → completed; otherwise it stays processing
- [v] `RunDue` logs (with user and order) every renewal it skips because an intent is in `review`
- [v] the billing worker pass deletes `billing_quotes` rows that expired more than a day ago
- [v] tests: two partial refunds on one pack both complete with two refund events and a confirmed total equal to their sum; NOT_CANCELABLE_AMOUNT with an unchanged balance fails the request and restores the lots; quote purge removes only old expired rows
- [v] behaviour unchanged otherwise: ARCH-26 green

## impl notes
- from review/perf-cost-261004 F3 F12 F21
- an operator way out of `review` (apply, refund or void a captured-but-unapplied order) and whether `review` should lock the account's billing actions are planning decisions BILL does not make — recorded in the review's notes for update-ssot, not decided here
- the "definitive refusal" code set is shared with T562's charge handling where the codes overlap; keep one named set per call (cancel vs charge) in billing
