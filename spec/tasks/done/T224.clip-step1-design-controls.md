## goal
Give step ① the intro and outro presets, the allowed caption styles and a template picker that defaults to none.

## acceptance
- [v] `/clips/new` offers the template as optional with 없음 selected by default and mints without one
- [v] ① shows the intro preset, the outro preset and a multi-select of caption styles beside the existing pace and accent controls, each previewing its own look
- [v] selecting a template fills all five and every one stays editable afterwards; clearing the template leaves the values in place
- [v] the style multi-select states which styles cost a per-frame render, and an empty selection reads as the default style
- [v] the controls autosave on a pause like the rest of ① and a change marks the result stale
- [v] vitest covers the default-none mint, the template seed, editing after seeding and the empty-selection reading
- [v] ARCH-25 passes

## impl notes
- the style multi-select is a `shared/ui` control over the style list the server already sends with the project, not a hand-rolled one (→ARCH-20)
- preset and style previews use the same served SVG fragments as the editor (→T222) rather than screenshots ← a picture would go stale the moment a style changes
- the template picker keeps the post-template pattern: presence-aware patch, 없음 sends a clear (→TMPL-32)

## result
- backend (beyond the task's own frame, see below) — `clip/caption_style_sample.go` builds the sample plan one caption per style owns and `GenerationService.CaptionStyleSamples` draws it through the SAME fragmenter ② uses; `GetClipCaptionStyleSamples` (proto + `clip/rpc/preview.go`) serves it; `clip/media/caption_style_sample_test.go` pins one sample per approved style with the registry's own sequence answer
- `frontend/src/entities/clip-project` — the draft owns `introPreset`, `outroPreset` and `allowedCaptionStyles` (read, normalized, compared and sent presence-aware: minting sends none so the server seeds from the template, an empty style list is sent as a selection of none), and `useClipCaptionStyleSamples` fetches the samples once per project
- `frontend/src/features/edit-clip-project` — `ClipDesignSelection` puts the intro preset, the outro preset and the sixteen styles beside pace and accent, each style drawn by the server's own fragment and the frame-by-frame ones saying so; `ClipProjectForm` seeds all five when a template is chosen, keeps them when it is cleared, and every change rides the existing draft queue
- the template became optional everywhere the FE still required one (`validNewClipProject`, `savableClipProject`, `validClipProject`), the picker now reads 없음 and says a clip can be made without one
- `frontend/src/test/clips.ts` — the fake seeds the design selection the way the server does, applies the three fields presence-aware, updates a template-less project, and serves the style samples
- SSOT divergence: none, but the task assumed the served style previews already existed. T222's preview needs a saved plan, so ① could not use it; the owner chose (asked mid-task) to add a sample RPC rather than draw an approximation the render could disagree with (CDS-83). The backend addition is outside this task's FE-only acceptance — worth a create-task note if the same happens again.
