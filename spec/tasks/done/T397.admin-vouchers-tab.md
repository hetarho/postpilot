# T397 admin vouchers tab: issue, list, copy, revoke
> st:done@260925 | ssot:GIFT-2 GIFT-3 GIFT-4 GIFT-5 GIFT-6 GIFT-10 GIFT-14 | base:GIFT@2 | dep:T396

## goal
Give the operator a `/admin/vouchers` tab that issues vouchers from presets or custom values, records sold/given, copies the gift link, and lists and revokes every voucher.

## acceptance
- [v] `/admin/vouchers` is a fourth admin tab under the existing master-only `adminRoute`, with its own label, short label and icon; the other three tabs are unchanged
- [v] the issue form offers:
    - the server's presets (basic/pro/max credits · 30 days from `ListVouchers.presets`) and a custom mode with numeric credits and days
    - a sold/given switch; sold requires a KRW amount and a payer name
    - an optional one-line message
    - client-side bounds that mirror T395's, with the server's `VOUCHER_INVALID` shown if it still refuses
- [v] a successful issue shows the full gift link (`<origin>/gift/<token>`) with a copy button reporting copied/failed, then refreshes the list
- [v] the list shows each voucher, newest first:
    - issue date, credits, validity days, sold amount + payer or 선물, state
    - redeeming account and redemption date, remaining credits and their expiry
    - copy-link only while redeemable
    - revoke while not revoked, behind a confirm dialog that says whether unspent credits will be voided
- [v] the page states: an empty list, a loading state, and the shared failure message on a failure
- [v] revoke refreshes the row in place from the returned voucher
- [v] admin i18n keys in ko and en at parity
- [v] vitest covers:
    - preset and custom issue payloads
    - sold/given validation
    - copy success and failure
    - list rendering per state
    - revoke confirm and cancel
    - the new tab link
- [v] ARCH-25 passes

## impl notes
- FSD placement:
    - `features/issue-voucher` (form + mutation)
    - `features/revoke-voucher` (confirm + mutation)
    - `pages/admin/ui/AdminVouchersPage.tsx` composes them over `entities/voucher` (created by T396), adding its list/issue/revoke calls and mappers there
- Route: `adminVouchersRoute` in `app/routes/admin.ts` (path `/vouchers`, lazy `AdminVouchersPage` from `@/pages/admin`), appended to `adminRoutes`. `ADMIN_TABS` in `AdminLayout.tsx` gains `{ to: '/admin/vouchers', labelKey: 'vouchers', icon: Gift }` (lucide).
- The link is built on the client from `window.location.origin` and the token. The page never renders a token outside that link field, and nothing logs it.
- Copy: `navigator.clipboard.writeText`. On rejection, select the read-only field and show the failed state rather than throwing.
- The KRW amount is entered as digits and shown with thousands separators via `Intl.NumberFormat('ko-KR')`. The server receives an integer.
- Presets come only from the server response; the FE hardcodes no credit numbers (QUOTA-8).
- Table at desktop, stacked rows at phone width, no horizontal page scroll at 320 px; the 44 px pointer floor on actions (THEME).
