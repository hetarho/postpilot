# T013 `video_input` capability, the video content part and the publish refusal
> st:done@260906 | ssot:VIDEO-10 VIDEO-11 VIDEO-16 MODEL-5 MODEL-18 MODEL-49 | base:VIDEO@1 MODEL@3 PUB@2 ARCH@1 | dep:T012

## goal
Record `video_input` from the catalog, let the LLM port carry a video by URL and refuse it before a call on a model without the capability, and make StartPublish refuse a post whose content holds a VIDEO block.

## acceptance
- [v] `modelcatalog`: `"video" ∈ architecture.input_modalities` → `VideoInput`, persisted in `catalog_models.video_input` on every successful live read, carried through `ListCatalog`, the browse response and the `llm.ModelSource` projection; the admin's `photo-analysis` tab shows a 영상 badge for a model with the flag and the observe stage selector shows the same badge (copy `영상` / `Video`)
- [v] `llm`: `Part.VideoURL` + `MIME`, `VideoPart(url, mime)`, `Part.IsVideo()`, `Request.HasVideos()`; `Registry.resolve` returns `ErrUnsupported` (`… does not take video`) for a request with a video part on a model whose `VideoInput` is false, before any network call; `ModelInfo` / `SourceModel` gain `VideoInput`
- [v] `openaicompat.buildRequest` emits a video part as `{"type":"video_url","video_url":{"url":"<url>"}}` (OpenRouter multimodal video contract, checked 2026-09-06); the image part encoding is byte-identical to today; the boundary test still passes
- [v] `publishing.Start` refuses a snapshot whose content holds a `VIDEO` block with `ErrVideoNotPublishable` → `FailedPrecondition` reason `VIDEO_NOT_PUBLISHABLE`, before the atomic gate, before any staging copy and before a job id is reserved; the publishing content parser accepts `BlockVideo` so such a post is refused with that reason and never with a parse failure; a post with videos attached but no VIDEO block starts as before
- [v] tests: catalog mapping fixture with and without `video` in `input_modalities`; registry refuses a video part on a non-video model and accepts it on one with the flag; `openaicompat` request golden with one text + one video part; publishing Start refusal test; the existing image-only goldens unchanged
- [v] `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...` passes; `pnpm gen:sql` diff clean

## result
`video_input` is recorded from the source, the LLM port carries a video by URL and refuses one before the call on a model without the capability, and StartPublish refuses a post whose content places a clip.

changed
- `modelcatalog`: `openrouter/client.go` maps `"video" ∈ architecture.input_modalities`; `Candidate.VideoInput` / `Model.VideoInput` / `EntryOf`; `service.go` fills it on register and projects it into `llm.SourceModel`; `store/queries/catalog_models.sql` (select · upsert · mark-seen) + `store.go`; `rpc/handler.go` browse response
- `llm`: `Part.VideoURL`, `VideoPart`, `Part.IsVideo`, `Request.HasVideos` (`HasImages` untouched, so the vision check keeps its meaning); `SourceModel.VideoInput` / `ModelInfo.VideoInput` and the `describe` projection; `registry.resolve` refuses a video part on a model without the flag as `ErrUnsupported` before any network call
- `llm/openaicompat/client.go`: `video_url` content part carrying the URL alone; the image part's encoding and the single-text-part collapse are unchanged, except that a lone VIDEO part now stays a part list instead of collapsing to a bare string

- `publishing`: `BlockVideo`, `ErrVideoNotPublishable`, `holdsVideo` checked in `Start` after the revision gate and before the job id, the staging copies and the atomic insert; `rpc/errors.go` → `FailedPrecondition` `VIDEO_NOT_PUBLISHABLE`; `rpc/mapping.go` projects `BlockVideo` as `BlockType_VIDEO` instead of UNSPECIFIED
