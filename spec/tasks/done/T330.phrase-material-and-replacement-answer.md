# T330 Frozen 분야 phrases in per-post material and the write answer's replacement candidates
> st:done@260924 | ssot:GEN-14 GEN-48 GEN-53 GEN-54 GEN-57 QUAL-21 POST-79 ARCH-24 | base:GEN@10 QUAL@3 POST@11 ARCH@9 | dep:T324

## goal
- A write whose post froze 분야 phrases carries them once in the per-post half together with the `replacements` instruction, and returns candidates parsed, bounded and validated against the final stored content; with no phrases the prompt, schema and parse are exactly what T324 left.

## acceptance
- [v] `PostInput.FieldPhrases` renders one section in the per-post half after the `메모:` line and before `[기억]` and the attachment lines: `FieldPhrasesHeading`, one bullet per phrase in frozen order, the observation sentence and the `replacements` instruction. The system prompt is byte-identical with and without phrases; nil or empty adds zero bytes.
- [v] The section states only what was observed (the phrases appear often in the titles and descriptions of top Naver blog results for the 분야), never what they improve (QUAL-21), and says the list licenses writing nothing the source lacks.
- [v] With phrases, a structured write request carries `WriteAnswerReplacementsSchema()`: T324's schema plus `replacements` (≤ 20 items; `surface` a string enum `title|tag|body`, `index` integer, `source` string, `phrases` ≤ 3 strings). Without phrases it carries `WriteAnswerSchema()` byte for byte.
- [v] `ParseWriteAnswer` reads `replacements`: a missing, `null` or non-array member is none; an item lacking any of the four keys, or failing to decode, is dropped alone; the write never fails over it.
- [v] `writeCandidate` runs `ValidateReplacements` after `ValidateBlocks → FilterAttachments → ApplyTemplateSlots`, on the final content, and returns the survivors in `WriteAnswer.Replacements`. With no frozen phrases it returns none even when the model sent an array.
- [v] An entry survives only while its source is present at its place: a title containing it; `tags[index]` after the frozen `tag_count` trim containing it; `blocks[index]` a TEXT with no slot, a HEADING or a QUOTE whose content contains it, or a LIST with an item containing it.
- [v] Offered phrases outside the frozen list, equal to the source, or repeated in the entry are dropped; an entry left without phrases, or repeating an earlier entry's surface, index and source, is dropped; then the first 20 entries and each one's first 3 phrases survive, in model order (GEN-54).
- [v] An index that shifted because `FilterAttachments` dropped an invented IMAGE, or `ApplyTemplateSlots` inserted an omitted slot, is read against the final content: the entry is kept only when the block now at that index still contains its source, and is never re-pointed (GEN-53).
- [v] Neither revise prompt ever carries the section or `FieldPhrasesHeading`, whatever the post holds (GEN-57).
- [v] Tests: `internal/generation/replacements_test.go` (`TestValidateReplacementsDropsEveryInvalidEntry` with one row per drop reason, `TestValidateReplacementsCapsSpansAndPhrasesAfterDrops`, `TestReplacementIndexesResolveAgainstTheFinalContent` through writeCandidate); `internal/generation/field_phrases_test.go` (`TestFieldPhrasesRenderOnceInThePerPostHalf`, `TestAWriteWithoutPhrasesIsUnchanged`, `TestTheRevisePromptCarriesNoFieldPhrases`, `TestWriteAnswerReplacementsSchemaExtendsTheNounsSchema`); `internal/generation/write_answer_test.go` (`TestParseWriteAnswerShapesReplacements`); `TestWriteSystemPrefixIsStableAcrossPostMaterial` still green.
- [v] Verify: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test -timeout 30m ./...`

## impl notes
- `types.go` `PostInput.FieldPhrases []string \`json:"field_phrases,omitempty"\``: the frozen phrase list, which T344 fills at enqueue and in the write-experiment snapshot. `omitempty` keeps every existing snapshot's bytes and hash.
- `prompts.go` exports `FieldPhrasesHeading = "[분야 상위 글 문구]"`. It is exported because T342's `guideline.PresetText` embeds a literal copy (guideline may not import generation, ARCH-7) and T342's `TestPresetTextNamesThePhraseSectionHeading` pins the two equal. Renaming either side is a change to both.
- `fieldPhrasesSection(phrases []string) string` mirrors `memorySection`: `""` when empty. Otherwise it is the heading, one `"\n- " + phrase` per phrase, `"\n" + fieldPhrasesObservation`, `"\n" + replacementsInstruction` and a trailing `"\n"`.
- The per-post half becomes `fmt.Sprintf("[이번 글]\n가제: %s\n메모: %s\n%s%s%s", title, memo, fieldPhrasesSection(fieldPhrases), memorySection(memories), photoMaterial)`. That is the GEN-14 order: memo, phrases, `[기억]`, attachments.
- The section is Korean-framed for every target language, as the whole per-post half already is. GEN-48 has no language gate, so there is none here.
- `fieldPhrasesObservation` (QUAL-21) says these phrases appeared often in the titles and descriptions of the top Naver blog search results for this post's 분야. It carries no word about ranking, exposure or quality gain.
- It also says the list is not a source: nothing the memo, the observations and the template facts do not carry may be written because of it (GEN-16). It is not an instruction to put a phrase into the post either; the preset line in `[작문 지침]` (T342) is the only substitution instruction.
- `replacementsInstruction` (R27) asks for a `replacements` array beside the content, one entry per span in the title, a tag or a body block that refers to the same thing a listed phrase names.
- Its fields: `surface` is `title`, `tag` or `body`; `index` is the 0-based position in the returned `tags` or `blocks`, and 0 for the title; `source` is the exact text written at that place; `phrases` holds 1–3 listed phrases copied verbatim, never the source itself.
- The instruction also says: at most 20 entries, an empty array when there is none, and the entries change nothing in the title, the tags or the blocks.
- `BuildWritePromptForLanguage` gains a trailing `fieldPhrases []string` after T324's `qualityRules`. `BuildWritePrompt` and every existing call pass nil, and `writeCandidate` passes `post.FieldPhrases`.
- New `schemas/write_answer_replacements.schema.json`: T324's `write_answer.schema.json` plus a `replacements` property, with `replacements` added to the top-level `required`.
- The property is `{"type": "array", "maxItems": 20, "items": {"type": "object", "additionalProperties": false, "required": ["surface", "index", "source", "phrases"], "properties": {"surface": {"type": "string", "enum": ["title", "tag", "body"]}, "index": {"type": "integer"}, "source": {"type": "string"}, "phrases": {"type": "array", "maxItems": 3, "items": {"type": "string"}}}}}`.
- The enum is string-only and `index` carries no enum: a numeric enum makes Gemini return `{}` for the whole object. `schemas.go` adds a `//go:embed` var and `WriteAnswerReplacementsSchema() []byte`.
- `write.go` selects `WriteAnswerReplacementsSchema()` only when `len(post.FieldPhrases) > 0`, and otherwise T324's `WriteAnswerSchema()`.
- New `replacements.go`: `type ReplacementSurface string` with `ReplacementTitle = "title"`, `ReplacementTag = "tag"` and `ReplacementBody = "body"`; `type Replacement struct { Surface ReplacementSurface; Index int; Source string; Phrases []string }`; and `WriteAnswer.Replacements []Replacement` on T324's type.
- `config.go`: `ReplacementSpansMax = 20` and `ReplacementPhrasesMax = 3` (GEN-54).
- `parse.go`: `replacementJSON{Surface string \`json:"surface"\`; Index int \`json:"index"\`; Source string \`json:"source"\`; Phrases []string \`json:"phrases"\`}`. `ParseWriteAnswer` decodes `fields["replacements"]` into `[]json.RawMessage`, and each item needs `hasFields(item, "surface", "index", "source", "phrases")` and a clean decode. The parse only shapes; bounds and validation are `ValidateReplacements`'s.
- `ValidateReplacements(candidates []Replacement, content PostContent, phrases []string) []Replacement` first trims `Source` and drops a blank one.
- Surface check: `title` forces `Index = 0` and keeps the entry iff `strings.Contains(content.Title, source)`; `tag` needs `0 <= Index < len(content.Tags)` and the tag containing the source; `body` needs `0 <= Index < len(content.Blocks)` and the block rule in acceptance. IMAGE and VIDEO never qualify, and any other surface string is dropped.
- Phrase check: trim each phrase, then drop a blank one, one not exactly equal to a frozen phrase, one equal to the source, or one already kept in this entry. An entry with no phrase left is dropped.
- Then drop an entry whose `(Surface, Index, Source)` repeats an earlier survivor, and finally keep the first `ReplacementSpansMax` entries and each entry's first `ReplacementPhrasesMax` phrases. Caps apply after drops, so invalid entries never spend them.
- Containment is an exact substring (`strings.Contains`): no case folding and no normalization. The index is strict against the final content: never shifted to follow a dropped or inserted block, and the source is never searched for elsewhere (GEN-53: blocks carry no identity).
- Logging mirrors `ValidateBlocks` and never logs user text. A dropped entry logs `slog.Warn("dropping generated replacement candidate", "surface", …, "index", …, "reason", …)` with reason `surface|index|block_type|source|phrases|duplicate|cap`; a dropped phrase logs `"dropping generated replacement phrase"` with reason `not_listed|is_source|duplicate`.
- These containment rules are the contract T351's FE `visibleSpans` mirrors against the stored content: exact substring, title index 0, an unfilled slot is never a surface, and a LIST matches on any item. A change to them is a change on both sides.
- `writeCandidate`: after `ApplyTemplateSlots`, it sets `answer.Replacements = ValidateReplacements(answer.Replacements, answer.Content, post.FieldPhrases)` when phrases are present, and nil otherwise. The list comes from the payload or the snapshot, never a live read.
- `RunWriteCandidate` and `Generate` are unchanged here: T341 persists and returns the replacements. The snapshot's `PostInput` already carries `FieldPhrases`, so both candidates validate against one list.
- Revise: `BuildRevisePromptForLanguage` takes no phrase parameter and `revisionPayloadJSON` gains no member (GEN-57, R30). The test also runs `Revise` with a fake post input carrying `FieldPhrases` and asserts neither half contains the heading or a phrase.
- `TestAWriteWithoutPhrasesIsUnchanged` pins three things: nil and empty phrases leave both write goldens byte-equal; the request's `JSONSchema` equals `WriteAnswerSchema()`; and a model answer carrying `replacements` yields nil `Replacements`.
- `TestWriteAnswerReplacementsSchemaExtendsTheNounsSchema` pins that the file is valid JSON, that every object level has `additionalProperties: false` and lists every property in `required`, and that no enum is numeric. It also pins that removing `replacements` from `properties` and `required` deep-equals `WriteAnswerSchema()`.
- `TestReplacementIndexesResolveAgainstTheFinalContent` has two cases through writeCandidate. First, a model answer `[TEXT, IMAGE invented.jpg, TEXT]`: after `FilterAttachments`, a candidate at index 2 is dropped (out of range) and one at index 1 is kept only if the second TEXT contains its source.
- Second, a brief with two slots whose first token the model omitted: `ApplyTemplateSlots` inserts it before the second slot and every later block shifts by one. A candidate whose index now names a slot block is dropped, and one naming a shifted TEXT is kept only on containment.
- The completion budget is unchanged.
- Out of scope: freezing phrases at enqueue (T344); persisting candidates (T341); the ② marks (T351); a tokenizer or a second provider call (GEN-55, QUAL-16).
