# T183 A group holding a required field admits at least one item
> st:done@260916 | ssot:CLIP-119 CLIP-61 CLIP-102 | base:CLIP@28 ARCH@2 | dep:-

## goal
Give every repeated item group an effective minimum — its declared one, or one when it holds a required field — and refuse an empty group at generation admission by the group's own name.

## acceptance
- [v] the effective minimum is computed once in the composition grammar: the declared `min`, else 1 when any field of that group is `required`, else 0
- [v] the TypeScript grammar owner returns the same number for the same template, pinned by the shared corpus the way T179 pinned the maxima
- [v] the owner's group controls open at the effective minimum rather than the declared one, and a group that admits any number still admits any number above it (→CLIP-61)
- [v] generation admission refuses a group below its effective minimum with the group's owner-visible name, the limit and the actual count, through the existing `items_required` shape rather than a new failure code (→CLIP-102)
- [v] a template saved before this rule still loads and is refused only at admission, never at template load (→CLIP-119)
- [v] tests: the effective number per group shape in both grammars, the admission refusal naming the group, and a legacy template that loads and then fails admission
- [v] verify BE (ARCH-26) and FE (ARCH-25) pass

## impl notes
- `composition_state.go:230` already raises `items_required` against `Group.Min`; this task changes what that comparison reads, not where it lives, so the quote path and the save path inherit it
- the number belongs beside `Document.Maxima` (T179): one derivation the input control, the admission check and the writer all read, never three
- carry the group's owner-visible name into the refusal parameters the way T181 carried a field label; `formatAppFailure` already special-cases `items_required`
- no migration — this is a read-time rule over stored template text, and no stored project is rewritten

## result
- grammar: `composition/parse.go` `groupMinima` and `Document.Minima`, mirrored by `composition-parse.ts` `groupMinima` and `ClipComposition.minima` — the declared min, else one when any field of the group is required, else zero
- admission: `composition_state.go` compares against `d.Minima[group.ID]` and the refusal now carries the group name, the number admitted and the number given; `composition/types.go` gained `Problem.Min` and emits `label`/`min`/`actual` for `items_required` the way it already did for `answer_limit`
- owner surface: `composition-inputs.ts` opens each group at its effective minimum and `ClipCompositionInputs.tsx` withholds the remove control there, so an item carrying a required field cannot be removed down to nothing; `failure.ts` plus both `clips.ts` resources say how many items are admitted and how many were given, keeping the plain wording for a refusal that carries no count
- tests: four shared-corpus cases pin the number per group shape in both grammars (every existing group row gained `effectiveMin`), `TestRequiredFieldGroupAdmitsOneItemAtQuoteNotAtTemplateLoad` loads a template saved with no minimum and refuses it only at Quote with the full parameters, `TestOptionalFieldGroupAdmitsNoItem` keeps an all-optional group admitting none, and the FE covers the counted message and the opened item
- verify: BE (ARCH-26) green; FE (ARCH-25) green — test 2010, lint (1 pre-existing DraftEditor warning), lint:fsd, lint:style, build:web. ARCH-28 not run: no proto or SQL source changed, and this machine's Docker daemon is down
- no SSOT divergence
