## goal
Create a reproducible comparison harness and version-specific license inventory before replacing browser media execution.

## acceptance
- [v] A fixture manifest covers simple text, all approved caption styles, blur/neon/glitch/ember stress, transitions, fixed rates, ordinary/source/narration audio and all three ratios with stable fixture IDs.
- [v] The current renderer's cold/warm source, layout/assets, video, audio, encode/mux, sampling wait and upload phases are separately captured with actual supported codec/device metadata; unavailable measurements remain unavailable.
- [v] The harness accepts the existing Canvas 2D path, an optimized Canvas 2D control and later PixiJS adapters with identical plan/output settings; an isolated representative Remotion web-renderer comparison does not enter the production bundle.
- [v] An inventory records exact package/source versions, licenses, covered-source access, MIT/OFL notices, transitive binary dependencies and commercial SDK conditions; no unverified watermark-removal or free-use claim is made.

## impl notes
- Start from the existing clip timeline/parity fixtures and native rendering diagnostics; export test-owned reference frames and media, not private uploaded footage or signed URLs.
- Use current official docs and the package manager to resolve qualified stable PixiJS 8, matching Filters 6 and compatible resvg-wasm versions. Keep Mediabunny 1.58.0 as the initial baseline and document any required upgrade explicitly.
- Mediabunny/resvg-wasm/current SoundTouchJS core are MPL-2.0; PixiJS/Filters are MIT and bundled fonts are OFL-1.1. Source evidence: mediabunny.dev, pixijs.com, github.com/pixijs/filters, github.com/thx/resvg-js and Mozilla MPL FAQ.
- Keep Remotion experiments in an isolated development harness with its actual free/commercial eligibility and telemetry documented; do not assume its custom license is MIT.
- Add only necessary real-browser development tooling following ARCH-33. Software-rendered headless runs can prove integration correctness but cannot certify representative GPU throughput.
- Later renderer tasks plug into this harness; this task establishes the measured current baseline and report format, not final GPU or AI-quality approval. No live model calls or deployment occur here.
