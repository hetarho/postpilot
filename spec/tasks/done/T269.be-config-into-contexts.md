# T269 platform/config holds env only; limits live in their context
> st:done@260920 | ssot:ARCH-21 ARCH-7 ARCH-6 | base:ARCH@5 | dep:-

## goal
Move every product constant out of `backend/internal/platform/config` into the owning context and make platform import no domain package.

## acceptance
- [v] `internal/platform/config` imports nothing under `internal/` except `platform/*`; `config.go`'s `internal/llm` import and the `clip*.go` imports of `clip`, `clip/ai`, `clip/composition`, `clip/design` are gone
- [v] clip limits (`ClipMinDurationMS`, `ClipSourceCount`, `MaxSegments`, `PlanCompletionTokens`, FPS/CRF, retention windows) are `clip.DefaultLimits()` (or `clip.Limits` fields with defaults) in the clip context; `clip/store/*` and the clip services read them from the `clip` package, never from `config`
- [v] post tag range and voice personalization thresholds live in `post` and `voice` (`post.TagCountRange`, `voice.PersonalizationThresholds`); `generation/config.go` and `generation/revise.go` read them from `post`/`voice`, not from `config`
- [v] `platform/config` keeps parsing env into the typed struct; where an env var overrides a domain default, `cmd/api` merges it into the domain config at construction (`clip.Limits{...}.WithEnv(cfg)` or a plain struct literal) — the domain never reads env
- [v] a test in `platform/config` pins the import surface (`go list -deps` or a `depguard`-style check) so a domain import fails CI; existing context tests pass
- [v] behaviour unchanged: ARCH-26 passes; the clip release smoke (`CLIP_RELEASE_SMOKE`) is run once locally because it exercises the limits (ARCH-37)

## impl notes
- from review/arch-260919 F14
- ARCH-21 r4: platform/config = env + cross-context only; limits are named constants in the owning context that the ctor merges env into
- the near-cycle today is `clip/store → platform/config → clip`; after the move `platform/config` has no domain edge and `clip/store → clip` is the normal inward edge
- keep the env names in `.env.example` unchanged; only the Go home of the default value moves

## result
- `platform/config` now imports nothing under `internal/` — `go list` shows an empty internal import set, and the near-cycle `clip/store → platform/config → clip` is gone (`clip/store` imports only `clip`, `clip/composition`, `clip/store/sqlc`).
- new: `internal/clip/limits.go` (the constants + `clip.Default{Limits,CompositionLimits,SourceLimits,MediaConfig,RenderConfig,AnalysisLimits,GenerationConfig}` over a `clip.Environment`), `internal/clip/ai/config.go` (`ai.DefaultConfig`), `internal/post/limits.go` (`post.TagCountRange` with `Allows`), `internal/voice/limits.go` (`voice.PersonalizationThresholds`), `generation.DefaultReasoningPolicy`.
- removed from `platform/config`: `clip.go clip_ai.go clip_composition.go clip_generation.go clip_render.go` (+ `clip_ai_test.go`), `PostTagCount*`, `VoicePersonalizationConfig`, `LLMReasoningPolicy` and the `internal/llm` import. `clip_media.go` stays — it is env parsing only.
- `cmd/api` merges the two halves in one place: `clipEnvironment(cfg *config.Config) clip.Environment` (cmd/api/clip.go).
- tests: `internal/platform/config/imports_test.go` walks this package's own imports with go/parser and fails on any `internal/` import that is not `platform/*`; the moved product shape is pinned by `internal/clip/limits_test.go`, `internal/post/limits_test.go`, `internal/voice/limits_test.go`, `internal/generation/reasoning_policy_test.go`; the env half stays pinned in `platform/config` (`clip_test.go`, `clip_media_test.go`, split so each side tests its own half).
- behaviour: ARCH-26 green; clip release smoke built and run locally (`--target release-smoke`, `--memory 1g --cpus 2`) = 19/28 with the same pre-existing 9 `no result` failures STATE already records — unchanged by this task.
- deviation from the goal line, no SSOT change needed: the `Template*`, `Guideline*` and publish ceilings left in `platform/config` are read from env (`TEMPLATE_PHOTO_ROW_MAX` etc.) because the browser mirrors them as `VITE_*` and both sides must move together — acceptance bullet 4 keeps env parsing here, so they stay.
- one test-visible change: `ai.DefaultConfig` sets `Observe/PlanReasoning` to `llm.ReasoningLow` unconditionally. Production always passed that; only tests that built a zero `config.Config` saw `ReasoningUnspecified`, and none asserted on it.
