# T383 Recovery bounds media retries and cleans cancelled or abandoned work
> st:done@260925 | ssot:ARCH-6 ARCH-49 ARCH-50 ARCH-51 ARCH-52 CLIP-21 CLIP-73 CLIP-74 CLIP-79 CLIP-80 CLIP-82 CLIP-87 CLIP-88 CLIP-162 CLIP-164 GEN-33 | base:ARCH@11 CLIP@44 GEN@12 | dep:T381 T382

## goal
Reconcile worker loss, API restart and cancellation without losing valid work, leaking private artifacts or extending a media job indefinitely.

## acceptance
- [v] Boot and a periodic reconciler recover queued/waiting/accepted media handoffs before generic failure/cleanup can destroy them; a valid remote lease survives API restart.
- [v] Transient worker/transport loss consumes only the affected stage's frozen retry/deadline budget; first-claim timeout, exhaustion and invalid media produce stable distinct failures and never replay paid AI work.
- [v] Accepted cancellation stops further claims/access renewal and result acceptance immediately, remains cancellation-pending until stop acknowledgement or lease expiry, then settles/releases once; a completion committed first remains authoritative.
- [v] Project deletion/finalization blocks new access and publication while preserving the existing confirmed result rules; original expiry cannot delete media bound to a still-active attempt.
- [v] Every reserved output is either referenced by accepted live work/canonical content or covered by recoverable deletion; failures during object deletion are retried after restart without discarding the key.
- [v] Lost workers clean their abandoned local workspaces at restart; still-live stages and another worker's workspaces are never swept by an unrelated API restart or a broad prefix delete.
- [v] Fault-injection integration tests exercise offline workers, lease expiry, repeated cancel, invalid input, deadline exhaustion, upload-before-report crash, cancellation/report races and failed cleanup; ARCH-26 and release smoke pass.

## impl notes
- Implement a clip-owned MediaReconciler over the media and job behavior ports. Run a bounded reconciliation pass during API boot before ordinary job sweeps, then every 5 seconds while serving; fake time drives tests instead of real sleeps.
- Keep at most 3 claimed attempts and the original total stage deadline from T376. Use retry not-before delays of 5 then 15 seconds for explicit transient failures; an expired lease is reclaimable after expiry. No heartbeat, retry or API restart resets the initial wait/total budget.
- Classify only worker disappearance and recoverable control/storage transport failures as retryable. Invalid inputs, plan/profile incompatibility, exceeded product/workspace limits and failed output checks terminate; cancellation is its own outcome.
- Typed owner reasons: CLIP_MEDIA_UNAVAILABLE for no compatible worker before the waiting deadline, CLIP_MEDIA_RETRY_EXHAUSTED for exhausted transient attempts and CLIP_MEDIA_TIMEOUT for total lifetime expiry. Reuse existing detailed media-input/output reasons where available; emit bounded stage/attempt diagnostics, never raw stderr or URLs.
- Couple retries to the same stage and parent; allocate a fresh attempt/token and fresh output keys. Reject late attempts even when their artifact upload was valid when it began. Do not turn an internal retry into a new user job or a new credit admission.
- Use a durable clip-owned artifact deletion outbox and the existing original/result cleanup machinery where applicable. Active accepted analysis objects survive until observation no longer needs them; canonical final outputs cease to be temporary. Keep the artifact-to-outbox intent when a project row is deleted.
- An orphan pass compares reserved keys and accepted/canonical references after the existing orphan grace, including outputs uploaded with an already issued URL after cancellation. HEAD/LIST/Delete remain outside database transactions.
- At shutdown stop admission/claims and drain or cancel within the lease rules; cancellation finalization uses the generic terminal acknowledgement so notifyTerminal, source-release time and credit settlement run once.
- Reconcile inconsistent missing-child/missing-parent records to an explicit owned failure/cleanup, never preserve a generic parked row forever. Preserve unknown interrupted model calls as failures with explicit continuation.
- Do not equate MEDIA_ACCEL=auto with moving work back to the VPS: it selects a backend inside one worker. An offline sole worker causes bounded waiting/recovery; another live compatible worker may independently claim queued/reclaimed work.

## result
- Added clip-owned boot recovery and a bounded five-second reconciler before generic interruption/hold cleanup. Stage and wait cursors recover absent children/attempts, preserve live remote leases and accepted handoffs, and never run a paid continuation from the recovery loop.
- Explicit transport failures retain the stage deadline and use 5s/15s backoff; expired leases receive fresh attempts and credentials. The default remains three claims; the already validated T376 override (up to five) remains frozen per stage. Request timeouts are retryable while total-stage timeouts are terminal.
- Claims, renewal and artifact access share parent/project/source fences. Cancellation remains pending until stopped/expired, uses the queue's once-only terminal acknowledgement and preserves the publication winner. Bound originals remain protected until the owning attempt ends.
- Migration 0082 adds recovery scheduling and bounded failure detail, and transfers every retired reservation (including deleted canonical results) to a durable deletion outbox. Cleanup waits beyond PUT expiry plus grace, preserves accepted/live and canonical objects, and retries failed keys without blocking unrelated deletions. Object I/O never holds the SQLite writer.
- Worker roots are namespaced by identity and protected by a kernel lock. A successor clears only its abandoned workspaces; unrelated worker/API roots remain untouched. Stop acknowledgements follow executor shutdown and descendant reaping.
- Registered three stable media failures in the shared protobuf contract and existing ko/en error catalog so the typed-contract CI gate stays green; T384 adds stage progress and interaction coverage. Existing workspace/input/analysis limit reasons survive remote execution. No raw worker diagnostics or private URLs enter these failures.
- Real SQLite/private HTTP fault tests cover offline waiting, bounded retries, late reports/uploads, cancellation, missing rows, source revocation, retained analysis, unknown paid interruption and failed cleanup/restart. ARCH-26, the 314-file/2,698-test FE suite, final shared-error tests (4 files/27 tests), lint/format/FSD/style/build, race checks, eight deployment tests and generated-code consistency pass. The final worker image passes preparation/render byte-and-frame parity, health and Linux descendant reaping (341.50s parity run). All 28 real release scenarios pass under a 2-vCPU/1-GiB container envelope. This is a local verification, not a measurement of the live VPS.
- No live deployment, host setup, topology migration or GPU activation was performed. No SSOT decision changed.
