# T436 ②'s storyline space: reading it and editing it by hand (frontend)

## goal
② shows the post's storyline in a space that opens and closes above the draft: paragraphs with their photo and video thumbnails, text edited in place, attachments moved, taken out and put back, every edit autosaving, and a notice when attachments were added after it was made.

- [v] `widgets/storyline-space`, mounted by `pages/editor/ui/EditorRefinePanel.tsx` above the draft when `post.storyline` is present (nothing otherwise): open while the post has no content — the draft area then saying it waits for 이 스토리로 글 쓰기 — and closed when ② first shows content during this mount; opening or closing changes nothing else

- [v] moves: each thumbnail has a move control (the single-choice `Menu` with `n번째 문단` options and `빼기`); from `sm:` an HTML5 drag onto another paragraph's drop zone does the same; `빠진 사진` under the paragraphs lists `taken_out_files`, each with a `넣기` menu choosing the paragraph; `added_files` are never offered
- [v] `features/edit-storyline`: every change goes through the draft queue as `storyline` (the whole paragraph list; `features/save-draft/model/draft-queue.ts` gains the field with its newest-wins rules; `useAutosave` sends it only when changed) and the cached GetPost is patched from the answer (`applyingSavedDraft` owns the field)

- [v] the notice when `added_files` is not empty (copy below); its 다시 만들기 is T437's
- [v] tests: Disclosure unit; widget tests (open/closed rules, a text edit queues a save, move, take out, put back, added files never offered, the read-only states); draft-queue test for the field; page test in `EditorPage.refine.test.tsx`

## impl notes
- Copy (namespace `posts`): heading `스토리라인` / `Storyline`; waiting draft `이 스토리로 글을 쓰면 여기에 글이 나와요` / `Write from this storyline to see the post here`; `{{n}}번째 문단` / `Paragraph {{n}}`; `빼기` / `Take out`; `빠진 사진` / `Taken out`; `넣기` / `Put back`; notice `이 스토리라인을 만든 뒤 사진이 추가됐어요. 다시 만들면 새 사진도 들어가요.` / `Photos were added after this storyline was made. Make it again to include them.`
- The server validates every save (T434); the client never adds or removes a paragraph.
- Thumbnails use `viewUrl` (a `blob:` URL right after an upload is fine; a missing URL shows the filename).
- The widget composes `features/edit-storyline` now and the storyline actions in T437; `pages/editor` only mounts it.
- A post with content and no storyline (written before storylines existed) shows no space.

## result
- Files: `shared/ui/disclosure/Disclosure.tsx` (+ test), `features/edit-storyline/**` (new: edit functions, attachment lookup, `StorylineParagraphEditor`, `TakenOutFiles`, copy + tests), `widgets/storyline-space/**` (new: `StorylineSpace`, copy, tests), `features/save-draft/model/{draft-queue,useAutosave}.ts` (+ `storyline-queue.test.ts`), `entities/post/api/useSavePostDraft.ts`, `entities/{image,video}/ui` (a `small` tile size), `pages/editor/ui/{DraftEditor,LifecycleSteps,EditorRefinePanel}.tsx`, `app/providers/i18n/resources/index.ts`, `shared/api/index.ts`, `test/posts.ts` (storyline edits), page tests in `EditorPage.refine.test.tsx`.
- The storyline rides the draft queue as a `storyline` member of the draft; a save carries it only while it differs from what the server holds, so a title save never re-marks it. When the server's storyline moves with no edit of it queued (a storyline job replaced it, or this editor's own save landed), the local copy is dropped and the queue rebases on the server's.
- A refused storyline save (`POST_STORYLINE_INVALID`, `…_FILE_UNKNOWN`, `…_MISSING`) is taken back rather than retried, like the published lock; `POST_BUSY` keeps the existing retry.
- The cached GetPost takes the storyline from a save's answer only when that save carried an edit of it.
- 넣기 uses the `ActionMenu` (it runs an action per paragraph); the move control is the single-choice `Menu`. The drag works wherever the browser supports HTML5 drag (desktop), which is the `sm:`-and-up case.
- The taken-out list is computed locally from the server's held and taken-out files, so it follows unsaved edits.
