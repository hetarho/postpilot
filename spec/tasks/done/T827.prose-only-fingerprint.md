## impl notes
- prose-only posts (VOICE-62): in `measure`, a line with `heading: true` (blocks mode, from a HEADING block) is appended to `headings` but is never segmented into sentences, never adds to a paragraph's size and never increments the `lines` count used by ④'s line-break share. Text mode (`MeasureText`, `FingerprintOf`) keeps today's `isPlainHeading` behavior unchanged ← a short one-line chat answer must not vanish from the sentence count
- `firstAndLast` skips heading lines: opening = first non-heading line, closing = last non-heading line; a post with no prose line has neither
- recurrence (VOICE-24 ⑤): in `openCloseOf` for 학습 글 (`text == false`), group candidate lines by `firstSyllables(line)` (the existing 3-syllable key used by `sharesLine`; a line with fewer than 3 Hangul syllables keys on its whitespace-collapsed text) and keep a group only when it spans two or more distinct source ids; the group's displayed line is its newest line (sources are already newest first). Keep `rankLines`' top-3 cap over the surviving groups. Text mode (a post or a test piece) keeps its own first/last line unfiltered
- `Example` for ⑤ points at the surviving group's newest line and material
- stored analyses: new file `backend/internal/voice/open_close.go` with `withRecurringOpenClose(Analysis) Analysis`:
  - personal analysis with `len(AcceptedMaterials) > 0`: rebuild `Materials` from `AcceptedMaterials` (Body, Kind, PromptKey → `PromptByKey(...).Part`, CreatedAt, Source.SampleID as ID) and replace `Counted.OpenClose` with `FingerprintOf(materials).OpenClose`; nothing else in `Counted` changes
  - synthetic analysis: replace `Counted.OpenClose` with `FingerprintOf` over its one `SyntheticSample` material (which yields no recurring line)
  - otherwise return the analysis unchanged (VOICE-74: never reconstruct from current edited material)
- apply it at the store seam, not at each caller: in `service.go` where the `AnalysisStore` is wired, wrap it in a small decorator whose `CurrentAnalysis` returns `withRecurringOpenClose` of the stored value; every reader (projection, post fingerprint, checks, reflection, authoring, profile view) then sees the same ⑤. Publishing/restoring analyses passes through unchanged
- no stored data is rewritten; no migration
