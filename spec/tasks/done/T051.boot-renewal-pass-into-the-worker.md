# T051 The boot renewal pass belongs to the worker
> st:done@260908 | ssot:ARCH-32 | base:ARCH@2 | dep:-

## goal
Move the startup renewal pass into the billing worker goroutine so a backlog of due subscriptions cannot hold the HTTP listener shut.

## acceptance
- [v] no renewal pass runs synchronously in the composition root: the listener starts without waiting for `RunDue`
- [v] the billing worker still catches up at startup rather than waiting a full tick, by running one pass as its first action inside its own goroutine
- [v] a pass that fails or runs long is logged and does not stop the worker's later ticks
- [v] the worker still stops with the server's context
- [v] a test pins that the worker performs its first pass without a tick elapsing, and that a failing first pass leaves the ticker running
- [v] ARCH-26 passes

## impl notes
- from review/diff-260908 F5
- the defect: `billingSvc.RunDue(ctx, time.Now())` sits in `cmd/api` composition, hundreds of lines before `rpcserver.New` and `ListenAndServe`. `RunDue` walks every due row doing Eximbank rate lookups, `PaymentByOrder`, `Charge` and a mail send per account on `http.DefaultClient` timeouts, so a backlog after an outage keeps `/health` unanswerable and the health-gated rollout (ARCH-32) rolls the release back
- the precedent is already in the file: `post.NewSweeper` carries a comment explaining why it is deliberately NOT run at boot, for the same class of reason
- keep the catch-up, move the blocking: `runBillingWorker` runs one pass before entering its `select`, which preserves the "an outage's backlog is cleared promptly" behaviour the boot pass was there for while the listener comes up regardless

## result
- Changed: `backend/cmd/api/main.go` (the composition-time `billingSvc.RunDue` block is gone; `runBillingWorker` delegates to a new `runBillingPasses` that runs one catch-up pass and then one per tick) · new `cmd/api/billing_worker_test.go`.
- The loop is split from the service call so the pass is injectable: the test drives `runBillingPasses` at a millisecond interval with a first pass that fails, and pins the catch-up before any tick, a tick after the failure, and the worker stopping with its context. It passes under `-race`.
- The `cfg.BillingEnabled` gate is unchanged in substance: it used to gate the boot pass and the worker separately, and now gates only the worker, which carries the pass.
- Nothing diverged from ARCH-32; no update-ssot owed.
