# T225 ② places captions over their own cut frame
> st:done@260917 | ssot:CLIP-143 CLIP-17 CDS-82 | base:CLIP@32 CDS@21 | dep:T221 T222

## goal
Turn the caption track into an editor where each caption is dragged, resized and restyled over a frame of the cut it starts in.

## acceptance
- [v] selecting a caption shows it over a still frame of the cut its interval starts in, drawn from matching local media or an unexpired retained original
- [v] dragging moves the caption and it stops at the safe area edge, which is drawn while dragging; both pointer drag and arrow-key nudging work
- [v] resizing is refused below the role's floor at the control, and the style is changed from the project's allowed set
- [v] a placement under the contrast floor shows the caption's warning in place without blocking 다시 렌더
- [v] with no source media the editor still edits text, timing, size and style over a neutral ground and says why the frame is missing (→CLIP-57)
- [v] every change rides the existing draft queue and undo/redo, and 다시 렌더 stays blocked only by the existing overlap and out-of-output rules
- [v] vitest covers clamping at an edge, the floor refusal, the missing-frame state and keyboard placement
- [v] ARCH-25 passes

## impl notes
- the frame is captured in the browser by seeking a `<video>` to the cut's start and drawing one frame to a canvas ← the originals are already local or authorised for playback here (→CLIP-50) and a server-side extract would add a round trip and a stored artefact for something transient
- the caption is positioned with one CSS transform over the served fragment (→T222), so a drag never re-fetches
- dragging updates local state and flushes on release, not per pointer event ← the draft queue is a save path, not an animation loop

## result
- `ClipCaptionStage` is ②'s placement surface: the still frame of the cut the caption's interval STARTS in — a caption may cross several and is placed once — with the server's own fragment over it, positioned by one CSS/SVG transform so a drag never re-fetches anything (→T222). The frame comes from the session's local media, falling back to the unexpired retained original through `resolvePlayback`, remembered with the fingerprint it belongs to so a caption on another cut never shows the last one's frame.
- Dragging moves the caption and stops it at the safe area edge, which is drawn only while the drag is happening; the arrow keys nudge it and Shift nudges it further, both in CANVAS pixels so a keystroke means the same thing at every ratio and at every size the stage is drawn at. The position rides local state during the gesture and reaches the draft queue once, on release — the queue is a save path, not an animation loop.
- The clamp is the same rule on all three sides now: the control moves the box inside the safe area, the save clamps the stored position, and the layout clamps the measured bounds (CDS-82). The safe area itself is the server's, not a second copy of CDS-9/CDS-13 on the client.
- `ClipTextControls` gained the caption's own style and size. The style list is the PROJECT's allowed set, narrowed to the styles this build knows; the size is refused at the control outside CDS-3's floor and the role's own size, and the owner keeps what they typed while the caption keeps the size it had. A caption the owner has placed also offers its way back to automatic placement.
- A contrast shortfall shows as the caption's own notice on the stage, where the caption is, and blocks nothing: 다시 렌더 stays gated by the existing overlap and out-of-output rules alone.
- With no footage for that cut the editor still edits — text, timing, size and style over a plain ground — and says why the frame is missing (CLIP-57).
- The project's `allowedCaptionStyles` now reaches the frontend as a READ projection (T217 put it on the wire; ① choosing them is T224's). Nothing in ② writes it.
- Every change goes through the existing `change()` edit, so autosave, undo and redo carry a placement exactly as they carry a word: pinned by a timeline test that places a caption, watches the draft key move and takes it back with one undo.
- vitest covers the drag clamped at an edge, keyboard placement, the floor refusal, the allowed-style list, the missing frame, the contrast notice and the representative-frame label. An obsolete assertion ("without a style control") was retargeted: CLIP-143 gave a caption its own style, so the control belongs there now.
- Verified: ARCH-25 green (2066 vitest, lint, lint:fsd, lint:style, build:web), ARCH-26 and ARCH-28 green. For about twenty minutes the shared composition corpus was mid-edit by the parallel T223 session and 27 clip-template tests failed in files this task never touched; they were green again on the run this task was finished against.
