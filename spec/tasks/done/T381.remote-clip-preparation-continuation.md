# T381 Generation resumes from prepared artifacts without repeating AI work
> st:done@260925 | ssot:ARCH-6 ARCH-11 ARCH-45 ARCH-48 ARCH-49 ARCH-50 GEN-33 CLIP-19 CLIP-21 CLIP-29 CLIP-30 CLIP-32 CLIP-33 CLIP-73 CLIP-74 CLIP-87 CLIP-93 CLIP-151 CLIP-162 | base:ARCH@11 GEN@12 CLIP@44 | dep:T376 T377 T379 T380

## goal
Park clip generation while a worker prepares its originals, then continue the approved AI pipeline from verified private artifacts under the same parent job.

## acceptance
- [v] The worker path atomically creates one frozen preparation stage and parks the parent before yielding; crashes before/after commit cannot orphan a stage, lose a wake or create duplicate work.
- [v] A durable accepted preparation result and parent Wake commit together; a restart in waiting or ready state resumes that handoff, while a crash after the continuation enters model work keeps the existing failed/explicit-retry rule.
- [v] Every source and analysis-copy verdict is validated before ReserveApproved or a provider call, and actual chunk counts/prices are rechecked against the frozen approval exactly as today.
- [v] The API streams each required bounded analysis object into the existing inline-video provider path, reopens it for bounded response correction, and sends neither signed URLs nor original video bytes to the provider.
- [v] Completed compatible observations and plans retain their current reuse rules; a media retry invokes zero additional provider calls or credit holds, and a repeated completion cannot restart analysis.
- [v] Preparation waiting does not block unrelated API jobs; accepted cancellation, deletion, expiry and source/plan mismatch prevent continuation, with prior successful project content preserved.
- [v] Real-store integration tests inject crashes at park, completion, wake, reserve and first paid call; assertions include exact provider-call/hold counts and original retention. ARCH-26 and the relevant real-media/input smoke pass.

## impl notes
- Refactor generationRun.prepare into request/consume phases around a durable stage, and make `GenerationService.Run` resume from that stage rather than wrapping prepare→AI in one process-local WithWorkspace callback.
- Extend the clip/app transaction Ports/Binder with behavior-shaped media-stage and generic job continuation ports. Both create+Park and accept+Wake commit through WriteTx on the existing single SQLite writer; no HTTP/storage/provider operation runs inside either transaction.
- Use wait_key `clip-media:<stage-id>` and derive the stable stage key from the parent job and prepare operation. The parent payload stays the original approved GenerationPayload; durable prepared state belongs to the new clip records.
- Select compatible prior observations before requesting preparation; include verified reused chunk identities in the frozen input so the worker need not encode already-observed intervals. Preserve the one verification/decode pass per required original and the existing source/cadence validation.
- Replace preparedChunk's local-path dependence with a reopenable bounded artifact reader for inline video. Fetch at most one copy into the existing bounded request path at a time, and retain accepted analysis objects until the parent no longer needs them; do not delete a copy merely because one format-correction call read it.
- Use the existing ReserveApproved/allowance and finisher paths after consuming the result. Idempotence of the reservation is tested, and a claimed local continuation is not automatically replayed after a crash with an uncertain provider outcome.
- Introduce one temporary rollout setting CLIP_MEDIA_EXECUTION=embedded|worker with embedded as the compatibility default while this wave is incomplete. In worker mode both preparation and, after T382, server rendering require the remote contract; never fall back to embedded processing on a worker error. T387 removes this setting and the embedded production dispatch after release validation.
- Keep existing preview/caption measurement and model validation in the API; they consume the same versioned fonts/renderer assets but do not move source preparation back into the process.
- Treat the dedicated media-pending signal as yield before StageFailure/checkpoint/terminal cleanup defers; pending work must not appear as a failed attempt or release its retained originals.
- Add the rollout setting to both env examples during its temporary lifetime. Existing stacks without new credentials still start in embedded compatibility mode; T386 provides upgrade configuration and instructions for the operator, and T387 validates the final worker-only release locally without migrating a live deployment.

## result
- Added `clip/app.MediaDispatch` over transaction-scoped stage, source, project and job ports. Frozen preparation creation + Park and accepted receipt + Wake share the API writer; `ErrYield` bypasses failure recording and terminal release.
- Generation consumes only the accepted attempt's complete ordered manifest, preflights every bounded analysis object's bytes/SHA-256 before admission, and streams reopenable private objects through the existing inline-video path. No API original download or source workspace is used in worker mode.
- Retained the existing approval, actual-count/price checks, call allowance, explicit recovery selection and plan-only finisher. Fully observed sources skip worker download/decode. The temporary `CLIP_MEDIA_EXECUTION` switch defaults to embedded in both env examples; worker mode has no fallback.
- Fixed the ledger's open-hold replay behavior required by this handoff: identical account/kind/amount/approval/policy reuses the committed hold inside the writer transaction; a conflict refuses without changing account lots.
- Added real SQLite fault tests for park/wake rollback, waiting/ready boot recovery, claimed paid-work interruption, stale worker completion, cancellation/deletion/expiry/source/revision refusal, unrelated queue work, original retention, observation/plan reuse and exact hold/call counts. A production-adapter ledger test proves reservation replay preserves both accounting and balance; reader tests cover four opens, corruption/length limits and interrupted transfers.
- Verification: isolated ARCH-25/26 and CI checks passed (314 frontend files, 2,698 tests), focused race tests passed, generated outputs remained identical after proto/SQL regeneration, deployment tests passed (8), and spec lint passed with pre-existing unrelated warnings. The real nonroot clip-input image smoke passed. The real nonroot CPU worker image also passed preparation, footage/audio/fade and sequence-caption byte/frame parity plus command health checks (253 seconds for parity).
- No SSOT policy changed; no live deployment or GPU activation was performed.
