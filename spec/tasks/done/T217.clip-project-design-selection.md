# T217 The design selection and the allowed caption styles belong to the project
> st:done@260917 | ssot:CLIP-139 CLIP-14 CLIP-111 CLIP-142 CLIP-144 | base:CLIP@32 CDS@21 | dep:-

## goal
Move the intro preset, the outro preset and the allowed caption styles off the template onto the clip project, seeded from the template at creation and changeable afterwards.

## acceptance
- [v] migration adds `intro_preset`, `outro_preset` and `allowed_caption_styles` to `clip_projects`, backfilling each row from the template it was made from and falling back to the current defaults where no template is attached
- [v] creating a project from a template copies those three plus the pace and the accent; creating without one writes the defaults
- [v] `UpdateClipProject` accepts the three presence-aware like the pace and the accent, and changing any marks the result stale without invalidating an observation or a plan
- [v] the renderer and the layout read the presets and the allowed styles from the project, never from the frozen template composition
- [v] an empty `allowed_caption_styles` resolves to the default style alone at layout
- [v] store and service tests cover the backfill, the template seed, the no-template default and the stale marking
- [v] ARCH-26 passes

## impl notes
- `allowed_caption_styles` stores a JSON array of style ids in one TEXT column rather than a join table ← it is read whole on every layout, never queried across projects, and the set is small and closed (→CDS-80)
- the two preset columns take the same string enum the template already stores, so the backfill is a copy and no value is invented
- seeding happens in the project-creation use case beside the existing pace/accent seed from T209, not in a trigger ← the seed is product behaviour and belongs where the other four already are
- an unknown style id in the column is refused at layout as an authoring error (→CDS-66), not silently dropped
