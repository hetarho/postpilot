# T147 Render fixed-rate cuts and opted-in source audio

## goal
Materialize every supported fixed-rate plan deterministically from original footage and include audio only for owner-enabled sources.

## acceptance
- [v] Both legacy and portable FFmpeg paths trim the exact original source range, apply the plan's constant rate and emit the shared transformed duration at 30 fps without changing the saved range, rate, order, crop, transition or text.
- [v] Video filters use timestamp scaling and ordinary frame-rate conversion only; filter graphs contain no interpolation, synthesis, reverse, freeze or implicit unsupported-effect fallback, and an invalid rate fails before FFmpeg starts.
- [v] Audio from an enabled source is trimmed to the same range, pitch-preserved at the exact fixed rate, then receives per-cut volume, seam/transition treatment and whole-track loudness normalization; a disabled source's audio is never decoded into the mix.
- [v] When at least one selected enabled source has audio, disabled or silent cuts contribute explicit silence of their transformed length so A/V and transitions stay aligned; when none do, the MP4 has no audio stream rather than a synthetic silent track.
- [v] Slow playback is rechecked against verified original cadence before encode; 60 fps admits 0.5x, 40 fps admits 0.75x and insufficient, VFR or unknown cadence returns a typed cut/rate/cadence failure without 1x substitution.
- [v] Caption plates, rapid phrases, hook/end elements, preview assets, transition overlap and final duration all use transformed output windows and cumulative 30 fps rounding, with source evidence untouched.
- [v] A failed transform or output verification preserves the validated assembly and previous successful result for credit-free render-only continuation.
- [v] Filter-unit, golden graph, media probe, output verification and production smoke tests cover all six rates, same-source adjacent cuts, mixed/on/off/no-audio matrices, pitch stability, duration/frame bounds and absence of prohibited filters.
- [v] Production-runtime media gates pass under the existing nonroot resource profile, and applicable ARCH-26 through ARCH-29 checks run with no paid provider call or deployment.

## impl notes
- After source trim, use `setpts=(PTS-STARTPTS)*1000/rate_permille,fps=30` and trim to the cumulative frame budget. Derive cut frame endpoints by cumulative rounding of the shared transformed timeline so individually rounded clips cannot drift from captions or transitions.
- For enabled audio use source `atrim`, `asetpts=PTS-STARTPTS`, one `atempo=rate` stage for the supported 0.5-2 range, resample/format, volume and exact transformed sample trim. Preserve the existing 60 ms seams, transition crossfades, hook dip and loudnorm values.
- Determine global audio presence from source permission plus probed `HasAudio`, never from per-cut volume. Use `anullsrc` only as an internal timing segment in a mixed audio output and `-an` when the whole plan has no authorized source audio.
- Extend original probing to retain conservative verified cadence; do not use analysis-copy FPS or unverified container declarations. Refuse slow playback for VFR where the selected range cannot prove the required unique-frame cadence.
- Update output verification to accept video-only MP4s while retaining the existing AAC 48 kHz stereo checks whenever an audio stream is present.

## result
- transform: one `rateChain` (video) and `audioRateChain` (audio) own how a fixed rate becomes pixels and samples — `setpts=(PTS-STARTPTS)*1000/rate,fps=30` and a single pitch-preserving `atempo` stage, which every CLIP-98 rate fits without chaining. 1x emits exactly the graph it always did, so an existing result re-renders byte-for-byte. The source `trim`/`atrim` keeps the cut's ORIGINAL range; only the frames it decoded to are scaled.
- clock: `cutFrames` and `cutOffsets` now round the TRANSFORMED timeline cumulatively, and the legacy layout, the composition layout and the rapid-cue offsets follow, so caption plates, hook/end cards, transition overlap, preview assets and the final duration all sit on one output timeline.
- audio: `RetainsOriginalAudio` plus probed `HasAudio` decides both the global audio track and each cut. A disabled source is never opened; a disabled or silent cut contributes explicit silence of its transformed length; a plan with nothing enabled delivers a video-only MP4 (`-an`). Per-cut volume stays a gain applied afterwards and never a permission.
- rates: `RefuseUnsupportedRates` became `RefuseUnrenderableRates(plan, sources)`, which rechecks every cut against the ORIGINAL's verified cadence immediately before encode and refuses with `plan_cut_rate` before one FFmpeg process starts — no 1x substitution, no plan rewrite. This also lifts T146's staging gate, so the two commits together are deployable.
- fixed beyond the stated scope, because rates created it: the legacy luminance sampler seeks SOURCE time from a CUT-RELATIVE OUTPUT window, so a sped-up cut was sampled at the wrong instant; offsets are now converted through the cut's rate. The composition path samples already-transformed footage and was correct.
- verification: V12's audio checks already applied only where an audio stream exists, so a video-only delivery passes and an unauthorized one is still rejected; a test now pins that matrix. Original probing already retained cadence (T142/T152), so nothing there changed.
- tests: six-rate filter units and goldens (`testdata/rate-*.filter`), cumulative frame budget, the enabled/disabled/silent/no-audio matrix, the cadence recheck matrix (60 fps admits 0.5x, 40 fps admits 0.75x, VFR and unmeasured refuse), absence of every prohibited filter at every rate, rate-aware luminance sampling, refusal before FFmpeg, and video-only output verification. `TestRenderSmokeRatesAndSourceAudio` adds the production-runtime matrix with pitch measurement.
- verify: ARCH-25/26/27/29 pass and ARCH-28 needs no rerun (no proto or SQL change). NOT run here: the Docker media gates (`CLIP_MEDIA_SMOKE=1`, `CLIP_RELEASE_SMOKE=1`), because the Docker Desktop daemon is down on this machine — the new smoke test is written and skipped, and T151/T110 run it. Credit-free render-only continuation after a transform or verification failure is unchanged and stays covered by the existing store recovery tests.
