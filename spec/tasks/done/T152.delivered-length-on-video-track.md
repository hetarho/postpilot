# T152 Judge delivered clip length on the decoded video track
> st:done@260914 | ssot:CDS-52 | base:CDS@13 | dep:-

## goal
Read a finished clip's length from its decoded video track so AAC container padding stops refusing correct renders.

## acceptance
- [v] `clip.MediaInfo` carries the decode pass's video frame count and `Probe` fills it from the `-progress` output it already reads, with no extra command
- [v] `validateRenderedOutput` compares the plan against that frame count at the already-verified output rate, and reads neither `DurationMS`, `ContainerDurationMS` nor any audio declaration for the length
- [v] `DurationMS` keeps its max-across-streams meaning for source probing; the new field is additive
- [v] the `render_output_duration` rejection still reports the container and decoded readings and adds the video-track measure, and every value key survives `SafeAttemptValues`
- [v] ko and en inspection labels exist for the new measurement key
- [v] a media test reproduces the production refusal — video 760 frames at 30 fps, audio and container declaring 25.400 s, plan 25334 ms — and accepts it
- [v] a media test refuses a video track genuinely short of the plan by more than one output frame
- [v] verify BE `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...`
- [v] verify FE `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- Production evidence, jobs b12a4bcdf9447704f7c3bf0be8563432 and d66ec47e243d492a0873e3c45e90e0d8: the delivered file was correct (760 video frames = 25333 ms, audio decoding to exactly 1,216,000 samples = 25333 ms) while its AAC track declared `duration_ts` 1219200 / 48000 = 25400 ms with `initial_padding` 1024 and `nb_frames` 1189. `Probe` takes `max(out_time_us)` across mapped streams, so the padded declaration became `DurationMS`, overshooting the plan by 66 ms against a 33.33 ms tolerance.
- Measure with the decoded frame count rather than the video stream's declared `duration`: `Probe`'s decode pass already parses `frame=`, so it costs nothing, and it is the one reading no container declaration can inflate. Compare as `float64(frames) * 1000 / float64(cfg.FPS)` against `plan.DurationMS` with the existing one-frame tolerance — the check runs after `render_output_frame_rate` has already pinned the output to `cfg.FPS`, so the frame count is a sound clock there.
- Add `DecodedVideoFrames int` to `clip.MediaInfo` ([types.go](backend/internal/clip/types.go) or wherever `MediaInfo` lives) and set it in [probe.go](backend/internal/clip/media/probe.go) beside `DecodedDurationMS`. Do not repurpose `DurationMS`: source admission depends on its max-across-streams reading.
- Short audio is out of scope and is not a regression — the old max-across-streams reading never caught it either, and V12 states no audio-coverage rule. Do not add one here; that would need update-ssot.
- Diagnostic values for `render_output_duration` become `duration_ms` (the video-track measure), `expected_duration_ms`, `video_frames`, `decoded_duration_ms`, `container_duration_ms`. Add `video_frames` to the non-negative list in `SafeAttemptValues` ([attempt_diagnostics.go](backend/internal/clip/attempt_diagnostics.go)) or it is silently dropped.
- Frontend: add `video_frames` to the displayed measurement keys in [ClipAttemptInspection.tsx](frontend/src/features/inspect-clip-observations/ui/ClipAttemptInspection.tsx) and to `inspection.measurements` in both `ko/clips.ts` and `en/clips.ts` — the locale parity test compares key order, so insert at the same position in both.
- Tests extend [render_output_test.go](backend/internal/clip/media/render_output_test.go); its `probeRunner` already emits `frame=` and `out_time_us`, so both new cases are table rows.
