## goal
Define one bounded video-template source language and typed composition with matching Go/TypeScript interpretation.

## acceptance
- [v] Go and TypeScript parser/resolver tests run the same valid/invalid corpus, preserving source text and reporting a stable element ID, 1-based line and allowlisted reason for invalid syntax or bindings.
- [v] The contract expresses footage sections, selected-scene and item repetition, private guidance, optional/required fields, AI copy, literal/answer-bound text, card rows, placement and all four timing scopes.
- [v] Pure resolution preserves grouped fact identity, omits elements dependent on blank optional facts, rejects unresolved required references and keeps fixed literals byte-exact after explicit substitution.
- [v] Output-start, output-end, whole-output and cut-relative intervals resolve consistently across nonzero transitions, reordering, trimming and deletion without silently adjusting an authored interval.
- [v] Contract fixtures include several differently priced items, global context versus item facts, multi-cut fixed text, reordered cuts, malformed XML, duplicate IDs, unsafe constructs, Unicode, unknown versions and every finite bound.
- [v] Run the applicable local ARCH-25 through ARCH-29 checks, deterministic proto/SQL regeneration when changed, and spec lint; use a before/after generation snapshot when unrelated generated changes already exist.

## impl notes
- Own Go grammar/validation under backend/internal/clip/composition and pure TypeScript counterparts under entities/clip-template/lib and model; expose project-facing types through entities/clip-template/@x/clip-project. Do not change the blog template grammar or import backend/internal/template internals.
- Use an XML-delimited <clip version="1"> body. Root attributes are styles (approved space-separated IDs), accent and pace; root children are field, group, guide, scene, repeat and text. A group declares repeated item fields; field attributes are stable id, label and required (default false), with its text as the input prompt. A guide is invisible text. A scene declares id and scope=scene|item|context, contains guide/text, and always selects real observed footage. A repeat uses for=scenes or a declared group ID, contains scene definitions and cannot nest.
- A text declares stable id, kind=fixed|ai, role=caption|info|badge|hook|ending, style=auto or an approved style, position=auto|top|upper_mid|lower_mid|bottom|header, align=left|center|right and basis=whole|output-start|output-end|cut; card text may contain row elements with the existing CDS typography roles. A header position is valid only for info/badge. Caption anchors are CDS anchors; automatic card placement uses CDS card geometry. IDs in repeats remain template IDs, with resolved instance IDs derived from item/cut identity.
- Text content is literal or AI guidance according to kind; <value field="fieldId"/> and <value field="groupId.fieldId"/> are the only substitutions, restricted to the current item scope. No expressions, inferred variables, remote includes, HTML, script, DTD, external entities or arbitrary CSS. Unknown tags/attributes refuse. A role does not create sibling rows or hidden content.
- Finite technical defaults: source body 16,000 Unicode scalar values, 200 syntax nodes, 10 field declarations including grouped fields, 20 items per group, 100 resolved cuts and 2,400 resolved text cues including rapid phrases; reuse current name/label/prompt/answer/copy limits. Keep configurable bounds in both config owners, expose them to the guide and preflight expanded input against the current provider request budget before charging.
- Author start/end in decimal seconds with at most three fractional places and parse exactly to integer milliseconds. Whole has no numeric endpoints. output-start resolves [start,end); output-end uses signed offsets relative to output end, e.g. start=-2.5,end=0; cut is relative to its associated cut. Omitted cut times request CDS automatic timing; explicit times carry authored authority. Interval resolution accounts for transition overlap and produces errors rather than clamping.
- Preserve original source plus node spans; switching editor modes without edits returns exactly that source, while a builder edit replaces only its node/subtree using a canonical serializer. Share a JSON corpus of semantic trees, source ranges, errors and resolved intervals between Go and TS. This is a pure foundation task: no schema write, provider call, rendered output or UI rollout.
