# T034 Remove the provisioning bonus and move the monthly grant window to the anchor day
> st:done@260908 | ssot:AUTH-3 QUOTA-9 QUOTA-37 QUOTA-38 QUOTA-12 QUOTA-31 QUOTA-26 BILLING-3 | base:AUTH@2 QUOTA@5 BILLING@2 ARCH@2 | dep:-

## goal
Stop granting credits at account creation, and make the monthly lot run from anchor day to anchor day — the account's creation day until BILLING supplies a subscription's start day — resolved in Seoul and clamped to a short month's last day.

## acceptance
- [v] `plan.SignupBonusCredits`, `usage.Service.GrantSignupBonus` and the bonus branch of `cmd/api`'s `creditBootstrap` are deleted; `adduser` on a `free` account opens only the monthly lot; the `InsertLotIfAbsent` query stays (the cycle lot below and T037's payment-method bonus use it); a `cmd/api` test proves a fresh `free` account holds exactly one lot and it is `monthly`
- [v] `plan.AnchorWindow(anchor, now time.Time) (start, end time.Time)`: with D = the anchor's day of month in Seoul, the window containing `now` starts at 00:00 Seoul on the latest date ≤ now(Seoul) whose day is `min(D, days in that month)` and ends at the next such date; `plan.NextRenewal(anchor, now)` returns `end`; `MonthWindow` and the calendar `NextRenewal` are removed; `plan_test.go` pins: anchor day 31 → Feb window ends on the 28th (and 29th in a leap year) and the next on Mar 31; anchor day 1 = the calendar month; `now` before the anchor day in the month falls into the window that began the previous month; a `now` exactly at 00:00 Seoul on the anchor day starts the new window; nothing depends on the host zone
- [v] `usage/ports.go` declares `type Anchors interface{ AnchorFor(ctx context.Context, userID string) (time.Time, error) }`; `usage.Service.SetAnchors(Anchors)`; `renew` (and through it `Hold`, `BalanceFor`, `EnsureMonthlyLot`) fails loudly when no anchors are set rather than falling back to a calendar month
- [v] `renew` opens the lot for `AnchorWindow(anchor, now)` with the deterministic id `monthly:<userID>:<start as YYYY-MM-DD in Seoul>` through `InsertLotIfAbsent`, `expires_at = end`, `granted = remaining = MonthlyCredits(plan)`; a test opens twice for one window and finds one lot; a test with a frozen clock moves past `end` and finds a second lot for the next window with the first left lapsed in place; master opens nothing and reports `end` as its renewal instant
- [v] a lot that already exists with a calendar expiry (every row before this migration-free change) keeps being the active monthly lot until it lapses, and the next lot then opens on the anchor window — a test seeds a calendar lot expiring on the 1st for an account anchored on the 20th and asserts the transition (one short cycle 1st→20th, then full anchor cycles)
- [v] `auth.Service.CreatedAt(ctx, userID) (time.Time, error)` behind a narrow `GetUserCreatedAt` query (no hash loaded); `cmd/api` wires `usageAnchors{auth}` returning the creation instant as the anchor for every ledger the API builds AND for the provisioning-path ledgers (`creditBootstrap`, `topUpMonthlyLot`, `grantCreditsTo`); the adapter is the seam T038 extends with the subscription's start
- [v] `Balance.RenewsAt` and `InsufficientCreditsError.RenewsAt` carry the window end; the `GetMyPlan` handler and the FE (`balance.renews`, the refusal copy) need no change beyond passing tests
- [v] the account popover's `balance.assignedByOperator` line stays (tier assignment is still the operator's until T038) — nothing in this task touches copy
- [v] gates: ARCH-26 · ARCH-28 (`pnpm gen:sql` for the new auth query) · ARCH-25 (FE tests still green)

## impl notes
- the anchor for an account with no subscription is its creation day (QUOTA-37); auth owns `created_at`, so the ledger asks through a consumer-declared port and never reads `users` — the composition root translates, the same shape as `jobAdmission{plans: authSvc}`
- deterministic lot ids are the idempotency T030's signup relies on ("in the same transaction … idempotently", AUTH-3) and what lets a concurrent first request and the bootstrap both call `EnsureMonthlyLot` safely; the date in the id is the Seoul date so two windows can never share one
- the clamp rule: a day-31 anchor lands on the 30th in April and on the 28th/29th in February, and returns to the 31st in May — compute the candidate as `time.Date(y, m, min(D, lastDay(y, m)), 0, 0, 0, 0, seoul)` for the current and previous month and pick the latest one ≤ now
- `seoul` stays the fixed +9 zone (QUOTA-31); no tzdata
- migration-free by design: existing lots keep their ids and expiries; the deterministic id applies to new lots only, and `InsertLotIfAbsent` on an id that never existed is a plain insert
- `worstCaseMicrousd` and settlement are untouched; only the window moves
