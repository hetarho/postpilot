# T138 Inspect completed clip work and diagnose timeline failures
> st:done@260913 | ssot:CLIP-7 CLIP-26 CLIP-48 CLIP-51 CLIP-52 CLIP-85 CLIP-86 CLIP-87 CLIP-88 CLIP-89 LANG-21 LANG-23 ARCH-10 ARCH-24 ARCH-31 | base:CLIP@14 LANG@3 ARCH@2 | dep:T137

## goal
Preserve inspectable completed work from unsuccessful clip attempts and repair reproducible timeline failures with bounded, actionable diagnostics.

## acceptance
- [v] A later analysis/plan/render failure or interruption preserves completed observation chunks and safe candidate ranges in a latest-attempt checkpoint without replacing canonical observations, editing state or result; cancellation and replacement are fenced by job identity.
- [v] The owner can reopen a failed/cancelled attempt, read completion counts and known failure measurements, inspect completed source observations and play valid selected original ranges; missing historical checkpoints/media and unknown failure locations are explicit, and no partial video is downloadable/finalizable.
- [v] Logs identify stage boundaries, source/chunk and cut ordinals, completed work, validation phase/category and bounded timeline measurements without raw provider output, user text, filenames, keys or media URLs; terminal failure details survive in the checkpoint.
- [v] A synthetic authored-composition plan with usable footage before its selected start succeeds through deterministic bidirectional reconciliation without another AI call, range overlap, unobserved gaps, identity changes or copy-time corruption; truly insufficient footage remains a diagnosed inspectable failure.
- [v] Store/service/RPC tests cover partial progress, restart/reopen, owner isolation, superseding jobs, cancellation, finalization/deletion and legacy absence; timeline and logging tests cover insufficient/growth/shrink/mismatch diagnostics, unsafe metadata and zero extra provider calls.
- [v] Frontend tests cover current-attempt provenance, previous-result preservation, source/range playback, missing data/media, refresh and locale changes; browser review verifies ko/en, light/dark, narrow layouts and accessible controls.
- [v] ARCH local gates, spec lint, production media verification relevant to timing, pushed CI and deployment checks pass.

## impl notes
- Add one clip-owned checkpoint row per project (job identity, owner, bounded versioned JSON, update time), using an embedded migration and generated SQL. A latest-job/ownership/nonfinalized fence prevents stale attempt writes or reads; project deletion cascades. Canonical successful fields and accounting remain unchanged.
- Generation records preparation/analysis boundaries and each validated completed chunk before the next paid call, retaining source metadata and completion counts. A bounded final checkpoint write using a detached timeout preserves cancellation/failure evidence; checkpoint write failures emit safe diagnostics and never disguise the primary job failure or trigger paid retries. No running-view streaming or historical-attempt directory.
- Carry typed plan diagnostics with allowlisted category/phase, numeric bounds and ordinal locations through existing errors, preserving normalized failure reasons. Retain only source identities grounded in this attempt and range-valid candidates for playback; rejected candidates are labelled and never promoted to an edit plan. Provider text is never logged or stored as a raw response.
- Extend the owner-only GetClipProject detail with a structured latest-attempt inspection projection. It has no object URLs; existing authorized retained-source playback supplies pixels. Expose terminal unsuccessful attempts only; old servers/rows show missing-checkpoint guidance. Reuse observation inspection with explicit attempt provenance and no saved-plan usage inference.
- The generated MP4 is produced after planning succeeds; an invalid plan therefore has no partial rendered MP4. This task shows original ranges and completed observations, including when a later render fails. It does not publish a candidate plan, reuse observations for a new paid generation, resume automatically or add a second writer call.
- Timeline repair first exhausts permitted forward growth, then backward room within contiguous observed evidence and neighboring selected ranges; preserve relative copy exposure when moving a legacy cut start, preserve authored section order, and recompute total/transition arithmetic from the actual cuts. Do not invent additional footage or relax the 15-second minimum.
- Use existing domain ports, Connect schemas, generated SQL, UI primitives and i18n catalogs; add no dependency. Bound checkpoint JSON and diagnostic arrays using clip configuration. Test representative synthetic source media and stubbed model output without external-provider calls.
- Deployment is authorized by the user. Check for active clip work before the backend rollout; preserve running work by waiting for its normal terminal state rather than restarting it.
