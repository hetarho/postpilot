## goal
Publish conversational drafts through idempotent domain-owned settings writes.

## acceptance
- [v] Five target adapters provide owned seed snapshots, friendly grammar guides, domain validation and account/lifecycle preflight without unrelated private material.
- [v] New template and guideline publication atomically writes the entity and its deterministic authoring receipt; existing targets require the captured version and preserve template numbers and guideline scope.
- [v] Writing-style publication atomically creates a made synthetic voice and analysis with a separate authoring receipt, no personal samples, explicit first-publication defaulting and bounded collision names.
- [v] Repeated/ambiguous publication returns the same entity without recreating deleted objects, changing later fields/defaults or inserting duplicate settings; conflict/cap/name/scope errors retain the draft.
- [v] API composition registers protected authoring RPC/job, uses frozen metered dispatch, owner cancellation and privacy redaction. SQLite concurrency/atomicity/idempotency and application wiring regressions pass.

## impl notes
- Root owns shared checkout, STATE, protocol bindings and commits; independent workers prepare isolated patch proposals only. Preserve existing uncommitted browser-media work.
- Use existing prepared active write models without a selector. No live paid completion for verification; use deterministic transports and real SQLite.
- Root provides T613 types/ports; add narrow published AuthoringSeed/Validate/Publish behavior in template, guideline, voice and clip contexts and transaction-owned store implementations. No context reads another context table and no SQL is added to cmd/api.
- Allocate0147_authoring_publication_receipts.sql with domain-owned tables for template, video-template, guideline and voice publication keys; user FK cascades, target IDs stay recorded after deletion to refuse resurrection. A domain entity write and its publication receipt share one writer transaction.
- Recoverable publication is two phases: authoring seals (session,revision,artifact,target version,key), target publisher atomically creates/updates+receipt, authoring finalizes saved ref. Do not call a DB-owning Create inside an outer transaction and do not expose a duplicate window between Create and receipt.
- Existing template updates preserve target_length/tag_count, clip design parameters and links not present in model output. Existing guideline updates preserve kind/scope/template/field links; new guides show/use global scope. Check owners, caps, parse rules, duplicate text and captured target version.
- All voice publication creates a new synthetic style, including seeded personal or synthetic voices; never rewrite source material/fingerprint. Reuse pure normalization/fingerprint builders but use a separate authoring-key receipt rather than legacy(job,candidate) adoption. First publication may set default; replay never reverses later default/deletion. Stored sample is bounded fictional Korean prose.
- Prepare wiring proposal only for contexts/jobs/serve/job_subjects/job_reporting and authoring models/jobs/estimator/targets adapters. Root integrates shared files and generators. Keep existing template_request and writing_voice_candidates APIs/data compatible.
