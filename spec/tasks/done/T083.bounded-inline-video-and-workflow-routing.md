## goal
Add bounded inline/static clip requests with strict price routing while independently rejecting incompatible signed-URL post workflows.

## acceptance
- [v] the provider-neutral LLM port distinguishes a bounded streaming inline video from a referenced post video, validates exactly one part variant and keeps `HasVideos`/capability checks correct without changing catalog `video_input`
- [v] inline analysis serializes one `video/mp4` data URL per request from a bounded reader; source payload above 8 MiB or complete encoded request above 12 MiB is refused before HTTP, with no all-file/base64 buffering or public RPC body-limit change
- [v] compatible clip requests select fixed sampling, explicitly `static` where supported; unknown or incompatible delivery/mode combinations fail before a completion request, never fall back to signed URLs or adaptive processing
- [v] quote and admission share a versioned, frozen price profile covering applicable input, audio, visual, reasoning and per-request charges; nonzero media prices are eligible, while unknown applicable pricing fails closed
- [v] both clip analysis and text-only planning carry the frozen routing limits, disallow supplier/model fallback and require supported parameters; endpoint/profile drift fails before a completion without retry or relaxed limits
- [v] final accounting prefers reported cost (including zero); aggregate tokens cannot be priced with a conservative quote envelope when media, cache discounts or conditional rates make that usage insufficient, and all existing approval/hold/waiver protections remain unchanged
- [v] post generation and write experiments with attached videos require a verified ordinary signed-video-URL path before enqueue; refusal remains `MODEL_VIDEO_UNSUPPORTED`, with no job, hold, original download or model request
- [v] the observe selector keeps the raw 영상 capability badge, but post generation and write-experiment controls explain URL incompatibility; otherwise eligible inline CLIP selection, photo-only work and model registration remain unaffected
- [v] streaming cancellation, request-body failure, HTTP redirect/error and provider truncation do not cause another completion attempt; sanitized errors/logs expose no data URL, signed URL, media, prompt or raw echoed request
- [v] adapter/registry tests verify exact wire placement, decimal units, known-zero prices, unsupported modes, body boundaries, bounded reads and single-request behavior; generation/experiment/RPC/frontend tests verify workflow-specific refusal before enqueue
- [v] ARCH-25 through ARCH-28 and ARCH-31 local gates pass; official wire references and representative sanitized fixtures are recorded without a paid provider call

## impl notes
- extend `llm.Part` with a trusted bounded-reader value carrying MIME, exact size and an opener, plus a provider-neutral fixed-sampling intent; a reader is runtime-only and must not be serializable into the job payload or supplied by public RPC
- encode through a fixed-buffer base64 stream with small pre-marshaled JSON segments and a computed complete Content-Length; validate limits before HTTP, verify short/extra reads, close readers/pipes on every exit and disable redirect/replay behavior for strict clip calls
- code-owned typed config sets the inline limit to 8 MiB, encoded clip request limit to 12 MiB and non-video metadata envelope to 1 MiB; the latter includes prompts/schema/structured planner material, which must be checked before its request rather than truncated silently
- add a provider-neutral execution policy for frozen decimal unit-price maxima, no fallback and required delivery/mode; only `llm/openaicompat` knows the OpenRouter keys, and existing non-clip text/image request behavior remains unchanged
- freeze adapter-discovered endpoint pricing into a provider-neutral versioned value in `llm.CallPolicy`; include an opaque endpoint/profile fingerprint, delivery, exact decimal routing maxima and separately bounded per-request/per-image charges. Upgrade the clip pricing-policy version, not the durable job version; old token-only quotes must be refreshed. Extend T082's quote/hold foundation here without modifying its archived task
- normalize overlapping prompt/audio/image-token/cache input prices using their maximum per-token rate for the conservative 30,000-input-unit quote envelope, and ordinary/reasoning output prices using their maximum within the frozen completion budget, rather than adding overlapping token categories. Account separately for documented per-image (at most 60 static frames) and per-request charges. Keep exact rational arithmetic, overflow rejection and the same calculator for quote and actual-count admission
- retain all recognized conditional price tiers conservatively in the envelope, regardless of their time/long-context predicates; missing required rates and unknown fields/conditions fail closed. Discounts never increase the quote and do not justify charging an undiscounted estimate as actual use. Strict static input remains at most 60 seconds; bound text/schema input conservatively inside the reserved input allowance as well as the byte envelope
- optional search/tools/plugins, explicit cache-control markers and generated media are absent from strict requests; their advertised prices do not disqualify a documented profile. Gemini implicit caching has no write/storage charge, so explicit-cache write prices are inapplicable without cache control. Other model families need a documented cache-applicability profile before excluding such charges; automatic token-priced writes must be covered, not silently ignored
- OpenRouter wire uses `provider.allow_fallbacks=false`, `provider.require_parameters=true`, one explicit `provider.order` plus `provider.only`, and string-valued `max_price`: prompt/completion in USD per million tokens, image in USD per image, audio in USD per input audio token and request in USD per request. Re-discover the selected frozen fingerprint before every completion; reject drift, ambiguous root-tag variants and unsupported parameters without supplier fallback
- reported cost is authoritative; token-only estimated settlement is allowed only when the frozen profile proves aggregate usage sufficient and uniform. Otherwise keep cost unavailable, not a fabricated zero or the reserved worst case. Never alter raw usage history, user ceilings, zero-charge unused failures or service-owned overage
- do not send a fallback `models` array, issue repair calls or silently omit an unsupported policy; a router rejection consumes at most the current request slot and terminates the attempt, preserving any returned usage
- keep an adapter-owned, tested delivery profile per documented model family/endpoint rather than inferring transport from a modality flag; expose only derived `signed_video_url` and `inline_static_video` readiness through the LLM/provider projection, without persisting them as catalog capabilities
- Gemini's ordinary signed object URLs are not eligible for the post path; an inline-compatible Gemini profile may remain eligible for CLIP; enable another URL or fixed-sampling profile only with current official evidence and a wire fixture, otherwise report unsupported
- placement: `llm`/`openaicompat` own transport checks, `generation` and `experiment` own pre-enqueue URL validation, `provider` publishes the derived readiness, and FE `features/generate-post` plus `features/start-model-experiment` consume it through `shared/api`/entity mappers; append protobuf fields and regenerate all three outputs if needed
- post URL gates follow VIDEO-11 even when reusable observations exist; this task neither transcodes/downloads post attachments nor enables VIDEO publishing nor changes the photo-analysis registration gate
- verify the exact `processing` location on the video content part and supported endpoint modes from [OpenRouter video inputs](https://openrouter.ai/docs/guides/overview/multimodal/videos), price/fallback keys from [provider routing](https://openrouter.ai/docs/guides/routing/provider-selection), and applicable sampling semantics from [Gemini video understanding](https://ai.google.dev/gemini-api/docs/video-understanding) under ARCH-33; no direct Google SDK or second provider is introduced
- this task adds and tests the guarded transport but does not lift T082's version-2 runner guard; T084 owns its first executable integration with prepared files and the metered allowance
