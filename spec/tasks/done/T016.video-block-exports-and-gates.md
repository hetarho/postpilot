## impl notes
- the converters take `(content, attachments)` where attachments carry both kinds; the site and Markdown filename encoding reuses the image's single-path-segment encoder (EXPORT-3); Tistory's comment text: reuse the image comment with 영상 / video wording in the same position; escape rules identical
- `widgets/export-panel`: the Naver preview already renders through `BlockList` — pass a `renderVideo` that wraps the `<video>` with the hint and no `<button>`; keep the photo copy controls untouched (EXPORT-12)
- publish gate: derive `hasVideoBlock(content)` in `shared/lib/blocks/walk.ts` and use it in the publishing surface's blocker list with the existing blocker precedence; the server refusal maps through `shared/api/app-failure.ts` like other typed reasons
- generate blocker: `features/generate-post` already computes the observe-model blockers from `GetSelections` + catalog flags; add `videoInput` to the catalog entity and one more reason in that chain, before the pending/temporal reasons
- badge: `shared/ui/badge` with tone `neutral`, text from the `models` namespace key `capability.video`
- i18n keys: `posts.export.videoHint`, `posts.export.videoMarker` is code (the marker is a contract, not copy), `posts.generate.blocked.videoModel`, `publishing.blocked.videoBlock`, `errors.MODEL_VIDEO_UNSUPPORTED`, `errors.VIDEO_NOT_PUBLISHABLE`, `models.capability.video`
- nothing here touches the agent or the template editor

## result
A clip now reads, edits and exports like the attachment it is, and the two things the product cannot do yet say so before the button is pressed.

changed
- `BlockList`: a VIDEO block plays the matching clip as `<video controls preload="metadata">` with its caption, holds its position with the filename when nothing matches, and offers a `renderVideo` seam; `BlockEditor` picks from the ATTACHED VIDEO list, edits alt and caption, and only offers the type when the post has a clip — `validContent` refuses a VIDEO block naming a photo exactly as the server does
- the four converters: Naver `[동영상 <file> — <caption>]` (en `[Video …]`) plus `naverVideoOrder`; Tistory `<video controls data-file>` with the same replacement-instruction comment; site `<figure><video controls src="<relative>">`; Markdown a link line with the optional italic caption. Every existing snapshot is byte-identical — the video cases are new snapshots over a new fixture
- `widgets/export-panel`: the Naver preview plays each clip in marker order with NO copy control and a per-clip hint; the photo copy controls are untouched
- `shared/lib/blocks/walk.ts`: `hasVideoBlock`; `PublishPostForm` disables 발행하기 and says where to paste instead; `preconditions.ts` gains the `videoModel` blocker, checked only when the post carries a clip and only after the simpler vision one
- `entities/model-catalog` maps `videoInput`; the observe selector and the admin `photo-analysis` row badge it; `app-failure.ts` allowlists `MODEL_VIDEO_UNSUPPORTED` (with `model`), `VIDEO_NOT_PUBLISHABLE`, `POST_VIDEO_LIMIT`, `UPLOAD_VIDEO_UNSUPPORTED`, `UPLOAD_VIDEO_INVALID`, all with ko/en copy
- tests: BlockList VIDEO cases, the four converter snapshots, the export panel's no-copy hint, the badge, both blockers, and a VIDEO block edited end to end on the editor page

- the export panel test reads the preview through its own `네이버 미리보기` article rather than clicking a tab: the Naver tab is the default and there is no tab named 네이버 to click.
