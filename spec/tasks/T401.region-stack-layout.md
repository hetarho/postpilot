# T401 Region presets stack by gaps and fit their width (A, B, outro B, E)

## goal
The four existing presets render, verify and preview from one gap-based stack layout that fits each slot's width instead of fixed baselines and character counts.

## acceptance
- [ ] design.json `regions.intro/outro` use the new preset schema (below) for intro `a`, `b` and outro `b`, `e` with the gaps and block centres of CDS-75 CDS-71 CDS-76 CDS-72; no slot `y` remains; the FE copy stays byte-identical
- [ ] `design.LayoutRegion(kind, id, ratio, rows)` is pure: it fits every non-empty row with T400's `FitRegionSlot`, stacks slots and rules by the preset's ink-to-ink gaps, drops an empty slot together with the gap before it (CDS-73), keeps the block's rules while any slot draws, places the block by CDS-79, and returns per slot its lines (text, size, baseline, horizontal anchor), each rule's box, the block bounds and whether any slot is `Over`
- [ ] one region's layout is computed from all of that region's outline entries together (CLIP-147 order and slot offsets unchanged); each entry draws only its own slots, and the entry that paints the rules paints them at the shared layout's positions
- [ ] the renderer draws each fitted line (two `<text>` lines for a wrapped slot) at the layout's size and baseline, horizontally centred on its resvg ink bounds; the manifest records every line with its fitted `FontSize` and the slot's floor, and the element check floors a region copy part at that floor rather than `Type.Min`
- [ ] V20 (`VerifyRegion`) recomputes the region layout from the manifest's rows and requires the parts to match it — slot, text, fitted size within 0.01 px, baseline, centring, rule boxes — and refuses a part below its floor or wider than its width

- [ ] region goldens re-recorded (`UPDATE_CLIP_GOLDENS=1`), the pinned-geometry tests rewritten for gaps (regions_test, region_ink_test overlap on the fitted worst case, media regions_test, project_design_layout_test, CompositionDesignFrame.test), `node scripts/media-assets.mjs --update` run and `MediaAssetVersion` bumped per media_protocol.go

## impl notes
- preset schema (a JSON object per id): `anchor` {`kind`: `centre`|`top`|`bottom`, `y` for centre/top on 9:16, `x`: `centre`|`left`, `inset` px added to LEFT} · `width` optional measure override · `scrim` `radial`|`top`|`bottom` · `items`: ordered array of `{"slot":{role, size?, floor?, face?, weight?, tracking?, fill, alpha?, stroke: text|small|none, shadow, lines?}}`, `{"rule":{kind: hair|bar, w?, alpha?}}` and `{"gap":px}`; size/floor/face/weight/tracking default to the role's CDS-19 values; T403 extends the item kinds, so keep the decoder strict about unknown kinds only at the item level
- ink box of a line = baseline − ink.top×size … baseline + ink.bottom×size from T400's metrics (face-level Hangul ink); a two-line slot is ink.top×size + (lines−1)×size×line_height + ink.bottom×size; gaps are measured between these boxes and rule rectangles
- centre anchor: block centre at `y` on 9:16, and at the same fraction of canvas height on 16:9 and 1:1 (CDS-79) — this replaces `RegionOffset`; the measure is the ratio's `copy_max_width` unless the preset sets `width`
- the gap numbers in CDS-71/72/75/76 were derived so that single-line short text lands where the old baselines put it; the rewritten tests should show that (e.g. intro A slot 1 baseline ≈ 940 and slot 2 ≈ 1020 on 9:16)
- move the per-entry `layoutDeclaredRegion` to a per-region pass: compute `LayoutRegion` once per kind from `clip.ResolvedElements` rows in outline order (the same rows `RegionPlacements` counts), then hand each entry its slots; admission (`ValidateAuthoredInput`) blanks AI rows before layout, so generated rows do not refuse the template
- `roleBounds`' character refusal stays for badge and info callers; region rows skip it and use `Fit.Over`
- manifest: region copy parts gain `Line` (0 or 1) and `Floor`; `verifyElementParts` uses `Floor` when set; `design.ElementKinds` unchanged in this task
- the TS port lives in `entities/clip-design` (pure `model` segment) so `clip-template` consumes it through the existing @x/clip-template export; FE measurement for layout comes from clip-metrics.json, not canvas `measureText` (keep `useInkBounds` only for horizontal centring in the preview)
- the preview frame still draws the default presets only; T404 flips the defaults and T405 replaces the ① thumbnails, so the port needs only the item kinds these four presets use
