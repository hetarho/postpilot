# T454 Validate manual caption styles independently of the AI set

## goal
Allow any approved style on an owner-selected caption while preserving its content/timing and reporting authored appearance errors without repair.

## acceptance
- [ ] Manual correction accepts every product-approved caption style even outside the project's AI set and rejects unknown styles. AI-generated choices remain restricted to the AI set, with the existing default when it is empty; a manual choice never expands that set.
- [ ] An already authored approved style remains valid after the AI set changes, across reload, further corrections, draft preview and either render. Merely changing that set never restyles existing captions or falsely makes an unchanged render stale.
- [ ] Changing one caption's style preserves exact text, output interval, phrase intervals and every other caption/cut. Existing owner position/size are retained where valid; measured bounds clamp placement into the safe area, and an invalid requested size reports the required correction rather than silently resetting it.
- [ ] Word/line overflow and other authored errors name the caption and refuse the save/render while leaving the caller's draft recoverable. No generated-content repair silently shortens, removes, retimes or substitutes that caption; existing CDS-84 glyph handling and contrast/overlap notices retain their semantics.
- [ ] Both static and sequence-rendered style overrides reach the server drawing, frame/asset cache keys and browser manifest correctly. A style edit advances the saved plan revision, leaves the previous result intact/stale and makes no AI call or credit approval, including a more expensive rendering style than the earlier AI estimate allowed.
- [ ] Extend `owner_caption_test.go`, correction/store/RPC tests and media owner-placement/style tests for outside-set styles, changed AI sets, retained size/position, role-floor/overflow errors, static↔sequence changes and exact content/timing preservation. Include AI parser tests proving its restriction still holds.
- [ ] Pass ARCH-31's local gates and the matching CPU media image smoke under ARCH-37; GPU activation remains outside this change.

## impl notes
- `ValidateOwnerCaption` in `backend/internal/clip/owner_caption.go` currently takes the AI allowlist and `correction_composition.go` passes it through. Separate owner approval against the product registry from AI admission rather than weakening the AI validator or copying a second style list.
- Audit project caption-set update invalidation in `store/queries/clips.sql` and `store/store.go`: invalidate future quotes/planning inputs, but preserve the current plan's resolved authored styles. Keep the current plan/result revision tied to actual visible changes.
- Reuse `design.CaptionRule`, role sizes, measured layout and existing owner-placement paths. Apply the new style before measuring safe-area bounds; retain explicit size instead of replacing it with the style default. An out-of-range explicit size remains an error the editor must correct.
- Keep owner overrides in the existing correction/portable representation and output manifest. Include every appearance input in relevant caches so a successful style save cannot reuse old overlays or frame sheets. Additive transport work is needed only if current structured errors lack the affected caption/constraint.
- T455 supplies the visual picker and unsaved error presentation; this task establishes acceptance through the domain, save, preview and render boundaries without adding independent face, plate, outline or motion overrides.
