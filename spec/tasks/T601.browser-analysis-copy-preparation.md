## goal
Generate only missing qualified analysis intervals locally and hand them to server verification without lowering input quality.

## acceptance
- [v] The browser measures original source time/cadence independently and prepares complete non-overlapping intervals under the existing count, duration and 60-second/8-MiB limits.
- [v] The initial target retains long edge 720, 15fps, H.264 and mono 48-kHz AAC at 64kbps; bitrate is bounded under the current 0.9-Mbps initial/0.65-Mbps retry target without claiming x264 CRF equivalence.
- [v] Actual completed copy duration, frame/audio coverage, aspect/rotation and bytes are checked; encoder size truncation, unsupported codecs or incomplete coverage never becomes a successful handoff.
- [v] Prepared artifacts upload directly to private owner/attempt-bound slots through T602; valid retained compatible intervals are reused and originals/proxies are not persisted in browser storage.
- [v] Preparation progress/cancellation/reselection integrates with the current generation action without paid AI calls before verification; page leave stops local work and no failure silently starts native preparation.
- [v] Tests cover long/rotated/VFR/no-audio originals, chunk seams, size retry, capability refusal, ownership/upload failures and resource bounds; browser/native proxy comparisons and required local checks pass.

## impl notes
- Parallel group execution uses isolated worktrees; exact final cross-slice edits remain uncertain (touches:-). Coordinate shared public exports and adapter seams explicitly; review and integration are serial and resolve overlap without shared-checkout writes.
- Use worker-owned Mediabunny conversion/input/output primitives and T592's lazy source access. Copy preparation is sequential and independent of export's 1080p/30fps component drawing.
- Use the existing code-owned analysis profile as the authority; resolve browser encoding quality from bitrate and compare actual frames rather than mapping native CRF 28 to an invented WebCodecs option.
- Treat source measurement as client provenance and preserve the measured original cadence for later rate eligibility. T602 rechecks copy safety; the frontend does not confer native verification.
- New feature orchestration belongs in prepare-clip-browser; the existing clip-project entity owns source/preparation RPC mapping and generated contracts.
- Keep current native preparation only behind an explicit qualified operational route during rollout. The browser profile remains disabled for ordinary provider work until T603 passes.
- The privacy copy distinguishes local computation, original/private artifact upload and external AI processing; local preparation is not marketed as no-upload privacy.
