# T022 The header credit control that leads to the ladder
> st:todo | ssot:QUOTA-27 QUOTA-26 QUOTA-29 | base:QUOTA@3 THEME@3 ARCH@1 | dep:-

## goal
Put the remaining credits in the authenticated header as one control that navigates to `/plans`, read by the shell rather than only while the account popover is open, and make the popover's own `/plans` link unconditional.

## acceptance
- [ ] a new `widgets/credit-badge` renders a `Link to="/plans"` carrying the credit figure, `min-h-11` with horizontal padding so the target passes 44 × 44 including width (THEME-23), and its accessible name states both the tier and the balance (ko `플랜 {{tier}}, 남은 크레딧 {{count}}`, en parity) so the short visible label costs the screen reader nothing
- [ ] the visible label is the number alone below `sm:` and the tier name appears beside it from `sm:` up ← at 320 px the header already carries the wordmark plus three controls, and the tier name is what gives way first
- [ ] `master` renders the unlimited label instead of a figure and still links to `/plans`
- [ ] while the balance is pending the control renders with a placeholder figure and the same box, and a failed read leaves the link with its label and no notice ← the header must not shift layout on arrival and the popover is where a failure is already reported
- [ ] `AuthenticatedLayout` mounts it first in the right-hand control cluster so the account control stays last, and a layout test asserts the phone header holds exactly the credit link, the two preference controls and the account trigger, with no primary nav
- [ ] the account popover's `플랜 보기` link is rendered for every tier, including `master`, and `AccountMenu.test.tsx` covers the master case that previously hid it
- [ ] the badge and the popover share one `useMyPlan()` read: a test that opens the popover after the header has rendered asserts the transport saw a single `GetMyPlan` call
- [ ] `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` pass

## impl notes
- placement is `widgets/credit-badge/{ui/CreditBadge.tsx,index.ts}` following `widgets/interface-preferences` (a shell block composed by a layout, not a page slice); it imports `useMyPlan` and `planLabel` from `entities/plan` and styles the link with `typographyStyles({ variant: 'label', className: 'text-link-fg hover:text-link-fg-hover inline-flex min-h-11 items-center px-2' })`, the same recipe the header nav links already use — no hand-rolled control (THEME-10)
- the tier name hides with `hidden sm:inline` on its own span while the accessible name is a single `aria-label` on the link ← two visible spans whose text changes by breakpoint would give one destination two different accessible names
- the pending placeholder is the ko/en `plans.balance.loading`-style dash, not a `Spinner`: the control is 44 px of chrome and a spinner in the header reads as work in progress somewhere on the page
- QUOTA-26's "reading a balance also renews it" means the shell's read now triggers the lazy monthly renewal on every app load instead of only when a popover opens; that is the same idempotent per-cycle insert `renew` already performs, so nothing else changes — state it in the widget doc comment so the next reader does not treat it as a new write path
- the popover keeps the meter, the lots and the renewal instant (QUOTA-27); only the link's condition moves. The link currently sits inside the non-unlimited branch of `PlanPanel` — lift it out below the branch
- no proto, backend or `shared/api` change
