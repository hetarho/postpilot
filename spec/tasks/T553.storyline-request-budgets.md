# T553 Size storyline and template-request completions through the stage budget policy
> st:todo | ssot:ARCH-21 ARCH-24 | base:ARCH@15 | dep:- | touches:backend/internal/platform/config/config.go backend/internal/generation/ backend/internal/template/ backend/cmd/api/adapters_generation.go backend/cmd/api/adapters_template.go

## goal
A storyline call and a template-request call get the writer floor with the same native-effort reasoning headroom every write gets (GEN-22), so a native-effort model no longer spends the whole 8,192 cap reasoning and returns nothing, and the hold prices exactly the cap the call sends.

## acceptance
- [ ] `config.LLMCompletionBudget` gains `Short(nativeEffort bool) int` = `withReasoningHeadroom(WriteFloor, nativeEffort)` (bounded by Ceiling); `StorylineCompletionBudget` and `RequestCompletionBudget` constants are deleted
- [ ] `generation.CompletionBudget` gains `Storyline(nativeEffort bool) int`; a storyline job (`StartStoryline`, `StartStorylineRevision`) resolves the write model's `ReasoningNativeEffort` at start, freezes it in its payload as `Start` does (`service.go` request.WriteNativeEffort), and both the call (`storylineCall`) and the hold (`storylinePricingCalls`, `storylineRevisionPricingCalls`) read the frozen flag
- [ ] the template requester receives the budget policy as a constructor argument (ARCH-40); `StartRequest` computes the cap from the resolved model's native effort, freezes it in the request payload (`completion_tokens`), passes it to the hold (`RequestJob.CompletionTokens`), and `RunRequest` sends that frozen cap on every call (a payload without it uses `Short(false)`)
- [ ] tests: config — `Short` doubles only for native effort and never exceeds Ceiling; generation — a native-effort storyline start prices and sends 16,384 at the 8,192 default, an ordinary one 8,192; template — the frozen cap reaches both the enqueue and every correction call
- [ ] behaviour unchanged otherwise: ARCH-26 green

## impl notes
- from review/perf-cost-261004 F6
- `Short` is the name for "a short structured answer whose visible output fits the floor": no per-char scaling, because a storyline's paragraphs and a template's four fields do not grow with a target length
- freezing the flag (not re-resolving at run time) keeps the hold and the call equal even if the operator flips the catalog's native-effort flag between enqueue and run — the same reason write freezes `WriteNativeEffort`
- `cmd/api` already passes the platform budget to generation; pass the same value to the template requester's constructor
- `platform/config/config.go` may be edited by another session (T533 touches platform/config): check `git status` first and commit only this task's hunks
