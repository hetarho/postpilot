## goal
Render and edit VIDEO blocks, map them in the four export formats with inline playback and no copy control on the Naver tab, show the `video_input` badge, and state the two new refusals — a video-blind observe model before 생성 and a VIDEO block before 발행하기.

## acceptance
- [ ] `BlockList` renders a VIDEO block as `<video controls preload="metadata">` from the matching video's `viewUrl`, caption below like an IMAGE, and a filename placeholder when no attached video matches; `BlockEditor` edits `alt` and `caption`, moves and deletes a VIDEO block, and its type switch is exhaustive so an unknown type still falls to the existing default
- [ ] Naver export: `[동영상 <file> — <caption>]` / `[동영상 <file>]` (en `[Video …]`) on its own line in block order; Tistory: `<video controls data-file="<file>"></video>` followed by the same replacement-instruction comment as an image; site: `<figure><video controls src="<relative file>"></video><figcaption>` when a caption exists; Markdown: `[동영상: <file>](<file>)` (en `[Video: …]`) plus the optional italic caption line; every output byte-identical to today's snapshots for a post without videos (snapshot tests extended with one video fixture per format)
- [ ] the export panel's Naver tab plays a VIDEO block inline in marker order with no copy control and a per-video hint 기기의 원본 영상을 편집기에서 직접 첨부해 주세요 / Attach the original video from your device in the editor; the format guidance for all four tabs mentions videos only when the post has one
- [ ] the observe stage selector and the admin `photo-analysis` tab show a 영상 badge for a model with `videoInput`; `entities/model-catalog` maps the new proto field
- [ ] 생성 and A/B 비교 are disabled with the reason `선택한 관찰 모델은 영상을 볼 수 없어요. 영상을 지원하는 모델을 골라 주세요.` when the post has at least one video and the saved observe model lacks `videoInput`, rendered in the same place as the missing-observe-model reason (POST-47/48); the server's `MODEL_VIDEO_UNSUPPORTED` reason has entries in the ko/en `errors` catalogs
- [ ] 발행하기 is disabled with `영상이 들어간 글은 아직 발행할 수 없어요. 내보내기에서 직접 붙여 주세요.` when the finalized content holds a VIDEO block, and the server reason `VIDEO_NOT_PUBLISHABLE` has catalog entries
- [ ] tests: BlockList and BlockEditor VIDEO cases; the four converter snapshots; export panel shows no copy button on a video and shows the hint; badge rendering; both blockers; `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` pass on Node 24.18.0

## impl notes
- the converters take `(content, attachments)` where attachments carry both kinds; the site and Markdown filename encoding reuses the image's single-path-segment encoder (EXPORT-3); Tistory's comment text: reuse the image comment with 영상 / video wording in the same position; escape rules identical
- `widgets/export-panel`: the Naver preview already renders through `BlockList` — pass a `renderVideo` that wraps the `<video>` with the hint and no `<button>`; keep the photo copy controls untouched (EXPORT-12)
- publish gate: derive `hasVideoBlock(content)` in `shared/lib/blocks/walk.ts` and use it in the publishing surface's blocker list with the existing blocker precedence; the server refusal maps through `shared/api/app-failure.ts` like other typed reasons
- generate blocker: `features/generate-post` already computes the observe-model blockers from `GetSelections` + catalog flags; add `videoInput` to the catalog entity and one more reason in that chain, before the pending/temporal reasons
- badge: `shared/ui/badge` with tone `neutral`, text from the `models` namespace key `capability.video`
- i18n keys: `posts.export.videoHint`, `posts.export.videoMarker` is code (the marker is a contract, not copy), `posts.generate.blocked.videoModel`, `publishing.blocked.videoBlock`, `errors.MODEL_VIDEO_UNSUPPORTED`, `errors.VIDEO_NOT_PUBLISHABLE`, `models.capability.video`
- nothing here touches the agent or the template editor
