# T564 Stop the clip detail polling forever and stop each settings save from refetching it
> st:todo | ssot:ARCH-14 ARCH-24 | base:ARCH@15 | dep:- | touches:frontend/src/entities/clip-project/api/clip-project.ts frontend/src/features/generate-clip/

## goal
The clip detail polls a finished job only while the server will still report its settlement, and a settings autosave updates the cache it just received instead of refetching the detail and awaiting every clip read.

## acceptance
- [ ] `useClipProject`'s settlement wait applies to exactly the kinds the server projects accounting for — `generate_clip` and `revise_clip` (`backend/internal/clip/app/accounting.go` chargedClipKind) — so a finished `storyline_clip` / `revise_storyline_clip` stops polling, and a finished `revise_clip` now waits for its settlement
- [ ] when a storyline job reaches a terminal state, the account's balance/plan query is invalidated once (settlement is synchronous with the job's finish), so the header balance updates as it does after a generation
- [ ] `useClipProjectMutations().save` sets the detail from the response and invalidates only the clip project list and the clip template queries, without awaiting them; the detail is not refetched
- [ ] tests: refetchInterval returns false for a terminal storyline job without accounting and 2 s for a terminal revise_clip job whose accounting is unsettled; one save triggers no GetClipProject and resolves before the list refetch completes; the balance invalidation fires once per terminal storyline job
- [ ] behaviour unchanged otherwise: FE suite, `pnpm lint`, `pnpm lint:fsd`, `pnpm build:web` green
