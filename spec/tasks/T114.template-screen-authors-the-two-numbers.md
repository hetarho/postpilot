# T114 The template screen authors the two numbers and the post shows what a template seeded

## goal
Let a template's 목표 글자 수 and 태그 수 be authored on the template screen as part of its one draft, and make the values a template seeds visible on the post the moment the picker applies it.

## acceptance
- [ ] `entities/template` carries the two optional numbers on its `Template` type and its proto mapper, and `TEMPLATE_LIMITS`/`canSaveTemplate` stay about the three text fields — the numeric bounds come from the existing `POST_TARGET_LENGTH_MIN`/`MAX`/`DEFAULT` and `POST_TAG_COUNT_MIN`/`MAX`/`DEFAULT` in `shared/config`, with no new key and no literal in a component (ARCH-21)
- [ ] the template screen edits both numbers above the composition, beside 이름 and 설명, each behind its own 사용 tick: unticking clears the value, ticking with nothing typed this session fills the default, and a value typed earlier in the session outranks the default when the tick returns (the 목표 글자 수 rule of POST-20, applied to both)
- [ ] both numbers belong to the one draft behind the one 저장: they make it dirty, they are part of the leave guard, they are compared against the same saved baseline, and an out-of-range number blocks 저장 with its message under the field rather than being sent
- [ ] `useCreateTemplate` and `useUpdateTemplate` send both numbers on every save, sending nothing for an unticked one, and the server's `TEMPLATE_NUMBER_OUT_OF_RANGE` renders through the existing template error message path
- [ ] the builder, `원문`, the format guide (형식 안내 복사) and the grammar parser neither show nor carry the numbers — the `원문` round trip and the copied guide stay byte-identical to today (TMPL-49)
- [ ] picking a template in the post editor makes the post's 목표 글자 수 and 태그 수 show the seeded values without a reload: `applyingSavedDraft` copies `targetLength`/`tagCount` from the response ONLY when the response's template id differs from the cached one, so an ordinary autosave of title/memo can never roll back an option save that landed while it was in flight
- [ ] a seeded length turns 목표 글자 수 사용 on in the generation options form, a template with no length leaves the tick as it stands, and nothing on the post says a template wrote the value (POST-70)
- [ ] Korean and English `templates` copy covers both fields, their ticks, their help and their range message, with locale parity green
- [ ] tests: the template screen's two fields (tick/untick, default seeding, dirty, range block, save payload), the mapper's optional numbers, `applyingSavedDraft`'s copy-on-assignment-only rule, and a post-editor test proving the picker updates both displayed options
- [ ] `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` (ARCH-25)

## impl notes
- the two fields live in `pages/template`'s `Editor` beside `NameField`/`DescriptionField`, not in `entities/template/ui` — that component is the composition editor over `body` alone, and the numbers are not part of the body (TMPL-2)
- extend `Draft` with `targetLength?: number` and `tagCount?: number` and keep the input's own text in local state per field; the draft holds the parsed value, `undefined` meaning unticked, so the dirty comparison stays a value comparison against `draftOf(stored)`
- reuse the checkbox + number-field shape already written in `features/generate-post/ui/GenerationOptions.tsx` (`Checkbox`, `FieldLabel`, `TextField type="number"`, `FieldMessage`) rather than a second control; it is the same question asked in the other place, and the user should meet the same field twice
- do not add a 태그 수 tick to the post's own options form — the post's count is always concrete (POST-63); only the TEMPLATE's is optional
- `applyingSavedDraft` in `entities/post/api/useSavePostDraft.ts` must compare the template ids BEFORE it overwrites `post.template`, or the guard will always read equal
- no new query, no new invalidation: the seeded values arrive on the SavePostDraft response the picker already awaits, and `DraftEditor` already mirrors `post.targetLength`/`post.tagCount` into its local state when the server value changes
- the template list rows stay as they are — name, description, post count. The numbers are an authoring detail, not a thing to scan a directory by
