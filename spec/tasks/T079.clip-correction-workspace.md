## goal
Give a completed clip a focused correction workspace for cuts, exact copy, approved placement/style and per-cut source volume, followed by source reselection and free rerender.

## acceptance
- [ ] `/clips/$clipId` enters 수정 mode without replacing the result preview and builds a local draft from the current edit plan and its revision
- [ ] an ordered cut list uses `SortableList`; every row names its source, shows start/end/duration controls, delete, exact copy, copy exposure times, `top|center|bottom`, allowed style/accent and original-audio volume 0–100%
- [ ] extending/shortening is bounded live by the retained source duration and final 15–90 second result limit; errors sit beside the responsible field and no invalid plan is sent
- [ ] copy fields show deterministic previews for `clean|diary|emphasis`, use the template's approved choices only and cannot select arbitrary font, decoration, motion, generated image or background music
- [ ] save is optimistic, reports a revision conflict without dropping local edits, and after success clearly distinguishes `수정됨 · 다시 출력 필요` from a result already matching the plan
- [ ] rerender first asks for only the source files still referenced by cuts, fingerprints them through T072's bounded helper, names missing/mismatched files and reserves a transient batch only after every required source matches
- [ ] the rerender action states that no credits are used, starts once under double-click, polls the durable render job and replaces the preview only on success; failure keeps both the prior preview and saved edits
- [ ] local source previews use revocable object URLs and may seek to a cut start for inspection; source File objects, URLs and bytes never enter query persistence, localStorage or IndexedDB
- [ ] leaving with unsaved edits uses the app's existing navigation guard pattern; leaving after save needs no warning even when rerender is still owed
- [ ] phone layout is one scroller with result preview before controls and one docked save/rerender bar; desk layout may widen the ordered list but does not introduce a multitrack NLE
- [ ] tests cover every edit kind, bounds, reorder/delete, revision conflict, fingerprint reselection, source subset, no-credit copy, render progress, failure preservation, object-URL cleanup and 320 px accessibility
- [ ] ARCH-25 passes

## impl notes
- this is a structured correction form, not a canvas timeline: integer time fields plus source seeking make every operation accessible and testable while satisfying CLIP-17's lightweight correction pass
- keep the result video mounted while editing so a form rerender never resets playback; cut-source previews are separate local elements created only after reselection
- expose pure edit-plan reducers and validation from `entities/clip-project/model`; UI components dispatch operations and never mutate nested JSON in place
- T078 saves before it renders, so a failed render does not discard authored corrections and retry needs no second save
