# T223 A template carries named composition stages
> st:todo | ssot:CLIP-141 CLIP-4 | base:CLIP@32 | dep:-

## goal
Add an ordered list of named stages to the template and hand it to the flow call as guidance that never admits or forbids footage.

## acceptance
- [ ] the template grammar gains a stage construct holding a short name and one line of intent, parsed by both the Go and the TypeScript parser against the shared fixture corpus
- [ ] stages are ordered, the order round-trips byte-exactly through parse → serialize, and a template with none behaves exactly as today
- [ ] the flow prompt renders the stages in the template guide's position as a numbered flow to follow where the footage allows
- [ ] footage matching no stage produces no refusal, no notice and no empty section — the flow is written from what exists
- [ ] a bounded count is enforced at save time and a stage beyond it is a parse error naming its line
- [ ] parser tests land in the shared fixture first, and a prompt test pins the rendered stage block
- [ ] ARCH-26 and ARCH-25 pass

## impl notes
- the construct follows the existing tag grammar (`<stage name="식당 소개">…</stage>`) rather than a new field ← the body is already the single source of truth for a template's shape (→TMPL-2) and a second representation would break the builder round trip
- stages sit outside `repeat` and cannot nest, like `ask` ← a stage is a property of the whole clip, not of a photo group
- the prompt states them as an order to follow where the footage allows, never as a requirement ← CLIP-141 and CLIP-136 both forbid a structure that admits or refuses footage
