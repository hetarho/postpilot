## goal
Make clip correction usable through one visible preview, selectable timeline items and focused editing controls.

## acceptance
- [ ] One composed preview stays above a horizontal cut/text timeline and selected-item controls; mobile keyboard opening leaves the active field and usable preview visible with one vertical scroller.
- [ ] Selecting a cut/text seeks the associated interval; playback highlights the active cut without stealing input focus, and timeline/source timestamps are explicitly distinct.
- [ ] Trim handles, scrub, current-frame start/end, precise seconds, reorder/delete, per-cut volume and generated/fixed/rapid text edits work with keyboard and touch alternatives.
- [ ] Undo/redo restores cuts, item associations and text/interval edits; debounced saving and revision conflicts preserve the draft, and invalid authored intervals remain visible and disable rerender.
- [ ] An item can be linked to multiple matching source ranges beside its preview; changing that association preserves recorded observations, marks stale generated claims and never copies another item's price into the caption.
- [ ] Successful rendering remains in ② with latest-result download available; no-source and prior-render modes remain usable without presenting outdated pixels as an updated draft; saved-plan observation usage keeps T124 revision semantics.
- [ ] Browser/UI tests exercise multiple cuts/items, rapid cues, global overlays, reorder during editing, delete/undo, failed save, stale preview, result comparison, keyboard-only trim and 320/360/390/430 px layouts.
- [ ] Run the applicable local ARCH-25 through ARCH-29 checks, deterministic proto/SQL regeneration when changed, and spec lint; use a before/after generation snapshot when unrelated generated changes already exist.

## impl notes
- Replace the expanded per-cut field list in features/correct-clip with a reducer-owned draft, selection, playhead and undo history. Keep pure timeline operations in entities/clip-project/model and reuse the T130 player via its public slice API; pages/clip composes upload, observations and correction without feature-to-feature imports.
- Implement domain-neutral RangeSlider/TimelineRuler primitives in shared/ui only where the current primitives cannot express accessible two-handle editing; controls use registered theme tokens. Timeline rows are domain UI, not a second vertically scrolling panel. Preview max height responds to visual viewport/keyboard space while retaining the project ratio.
- Use integer milliseconds internally, display seconds with up to three decimals, and snap pointer gestures to the 30 fps output grid while preserving precise typed values. Show source start/end in selected-cut controls and output intervals on text bars. Frame actions read displayed media-frame timestamps, not an arbitrary wall clock.
- Keep up to 100 undoable user transactions in session memory, coalescing typing and each pointer gesture; server saves do not add undo entries. Undo after an accepted save submits a new optimistic revision rather than restoring an old revision number. A conflict keeps the local draft until explicit reload/reapply.
- Identity-based selection survives reordering; deleting a selected cut selects the next surviving neighbour, removes only its cut-relative elements and leaves output-relative elements intact. Out-of-bounds authored intervals become errors, never repaired silently.
- Item association editing changes project composition facts, not raw AI observations. Invalidate evidence for generated text whose association changes and show the affected sentence for owner correction; do not trigger a provider call. Preserve T124's read-only observations and saved-plan usage labels separately from the unsaved timeline.
- Keep the owner in ② after rendering and expose current-draft preview alongside revision-labelled latest-result download. 다시 렌더 uses the saved valid revision and no text/trim change auto-exports. Compose one ActionBar with room for T136 primary 확정하기 and secondary rerender/download; never treat download or a matching render as finalization. Source availability uses T133 through the T130 player/source-access contract.
