# T551 Index the job and admission lookups every poll and provider call makes

## goal
A clip project's latest job, a post's or project's FK cascade, and a job's admission and usage events are found through an index instead of a full table scan, and a failed generation's checkpoint survives a browser render's sampling job.

## acceptance
- [ ] Migration `0128_hot_lookup_indexes.sql` (embedded, forward-only, ARCH-43) adds `generation_jobs_project_latest_idx ON generation_jobs(clip_project_id, created_at DESC, id DESC) WHERE clip_project_id IS NOT NULL`, `generation_jobs_post_idx ON generation_jobs(post_slug, user_id) WHERE post_slug IS NOT NULL`, `usage_admissions_job_idx ON usage_admissions(job_id)` and `usage_events_job_idx ON usage_events(job_id)`, and rewrites trigger `clip_checkpoint_next_attempt` so it no longer fires for `kind = 'sample_browser_render'`
- [ ] A store test applies every migration and asserts with `EXPLAIN QUERY PLAN` that `LatestForProject`, `LatestForProjectExcept`, `OpenAdmissionForJob`, `MarkAdmissionSettled`, `DeleteAdmissionForJob` and `CostForJob` use an index (no `SCAN generation_jobs` / `SCAN usage_admissions` / `SCAN usage_events`)
- [ ] A test inserts a failed `generate_clip` job with a checkpoint, then a `sample_browser_render` job for the same project, and the checkpoint is still there; inserting a `generate_clip` (or `render_clip`) job still clears it
- [ ] `usage/store` HoldForJob outside a transaction reads through the read pool; a transaction-bound store still reads inside its transaction
- [ ] the `clip/app/allowance.go` Reserve comment no longer claims a unique job key; it names the writer-serialized re-check that refuses a second hold
- [ ] behaviour unchanged otherwise: ARCH-26 (`go test -timeout 30m ./cmd/... ./internal/...`, vet, gofmt) green

## impl notes
- from review/perf-cost-261004 F4 F5 F23
- plain (non-unique) index on `usage_admissions(job_id)`: a UNIQUE index would abort boot on any legacy duplicate and roll the deploy back; the one-hold-per-job rule is already enforced by Hold's in-transaction re-check on the single writer
- partial indexes serve the FK child lookups because SQLite treats `col = ?` as implying `col IS NOT NULL`; keep the `WHERE … IS NOT NULL` so rows without a project or post cost nothing
- the trigger exclusion mirrors Go's `clip.ProjectLatestExcept` (a sampling job is not one of the project's attempts); name the kind literally in the trigger, as the other clip triggers do
- the query-plan test lives beside the migrations runner tests in `internal/platform/db` (or the job/usage store tests if they already open a migrated DB); reuse the existing migrated-DB helper
- HoldForJob: switch `s.write.OpenAdmissionForJob` and the follow-up debit read to `s.read` only in the non-transaction store; `NewTx` already binds both query sets to the tx — verify, and keep it that way
