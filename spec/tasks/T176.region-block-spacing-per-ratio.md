# T176 Region blocks keep their spacing on every ratio
> st:todo | ssot:CDS-79 CDS-47 CDS-48 CDS-46 CDS-71 CDS-72 CDS-75 CDS-76 | base:CDS@18 CLIP@24 ARCH@2 | dep:-

## goal
Move an intro or outro block as one piece between ratios instead of scaling its baselines into itself.

## acceptance
- [ ] the design package resolves a region slot's baseline through one shared function that keeps the preset's 9:16 spacing and applies only the block's vertical offset; the renderer and V20 both call it and `RegionScale` no longer multiplies a slot or rule y
- [ ] a test asserts, for all four presets on all three ratios, that consecutive slot baselines and every rule offset differ from the 9:16 preset by the same constant
- [ ] a test measures each region part with the bundled faces' own glyph boxes and asserts no two parts of one block overlap on any ratio — 1:1 outro E is the regression
- [ ] every part still lies inside the ratio's safe area on all three ratios
- [ ] the eight 16:9 and 1:1 region goldens are regenerated and the region preset tests and V20 pass against them
- [ ] the frontend preview places region slots at the same baselines as the renderer, covered by its own test
- [ ] verify BE (ARCH-26) and FE (ARCH-25) pass

## impl notes
- the block's centre is the midpoint of the preset's own y values — slot baselines and rule y together, no glyph metrics — so the offset is `centre9 * (height / 1920) - centre9` and stays a pure function of the preset and the ratio
- the offsets this produces on both 1080-high canvases, to check an implementation against: intro A −428.75 → [511.25, 591.25] · intro B −423.50 → [422.5, 536.5, 586.5, 666.5] · outro B −424.375 → [475.625, 525.625, 615.625] · outro E −425.6875 → [410.3125, 554.3125, 604.3125, 684.3125]
- 9:16 keeps every value unchanged: the offset is 0 there by construction, so the four 9:16 goldens must not move
- V20 compares `BaselineY` against the preset, so it has to consume the same function; leaving it on the old multiplication would reject every correct render
- the overlap test needs real ink boxes, which the 40 px-per-character fake measurer cannot give. Load both bundled TTFs with `sfnt`, walk each string at ppem 100 accumulating `GlyphAdvance` plus the role's tracking, take the union of `GlyphBounds` for the ink box, and scale by `size/100` — the same measurement resvg reports from `--query-all`. The tracking after the last glyph advances the pen but is not part of the ink box
- the frontend mirror already reads the preset y values from `clip-design.json`; it needs the same offset formula rather than the current `* scale`
- CDS-46 is unchanged: 16:9 and 1:1 keep every font size, `t.hook` included at 72 and 76
