## goal
`BlockList` renders a GALLERY as one place — 콜라주 rows or a 슬라이드 strip — with one caption, and the shared helpers every later FE task uses exist.

## acceptance
- [ ] a COLLAGE group renders its photos in one grid (two columns for 2 and 4 photos, three otherwise) with the caption once under the group
- [ ] a SLIDE group renders a horizontal snap strip with a `현재 / 전체` indicator and previous/next buttons disabled at the ends; the indicator follows the settled slide and the buttons move it
- [ ] an UNSPECIFIED layout renders as COLLAGE; a photo of the group that is not attached holds its cell as a placeholder naming the file
- [ ] each photo's alt is the group's alt (or the filename) followed by its position `(1/3)`
- [ ] `blockPhotos(block)` and `PHOTO_GROUP_MAX` exist; `blockKey` distinguishes groups by their files
- [ ] the write-comparison widget lists a GALLERY as one line naming its layout, files and caption
- [ ] vitest pins each case above (BlockList, PhotoGroup, the helper, CandidateComparison)
- [ ] ARCH-25 passes

## impl notes
- `shared/lib/blocks`: `blockPhotos(block): string[]` — IMAGE → `[block.file]` (an empty file kept, the exporters number it), GALLERY → `block.files`, anything else → `[]`; exported through `shared/lib`. Pure, no React (ARCH-18).
- `entities/post/config`: `PHOTO_GROUP_MAX = 10` typed constant mirroring the BE `post.PhotoGroupMax` (POST constraints, ARCH-21).
- `entities/post/ui/PhotoGroup.tsx`, exported from `entities/post` so the export panel can wrap its cells (T528):
  - props `{ block, images: ReadonlyMap<string, PostImage>, renderPhoto?, renderMissingPhoto?, renderCaption? }`; `renderPhoto(file, position, image, defaultImg)` lets a caller wrap a cell, `renderCaption(block)` replaces the caption.
  - COLLAGE: `grid gap-2` with `grid-cols-2` for 2 and 4 photos, `grid-cols-3` otherwise; cells `aspect-square overflow-hidden rounded-lg`, the img `h-full w-full object-cover` (a collage crops to even cells, as Naver's does).
  - SLIDE: `flex snap-x snap-mandatory overflow-x-auto overscroll-x-contain` (THEME-25's horizontal-strip exception), each slide `w-full shrink-0 snap-center`, the img inside an `aspect-[4/3]` `bg-surface-recessed` box with `object-contain` so slides of mixed shapes keep one height; indicator via IntersectionObserver on the strip as `widgets/contact-sheet` does (no scroll handler); previous/next are `shared/ui` `Button variant="ghost"` with aria-labels, calling `scrollTo({ left: index * clientWidth })` with `behavior: 'smooth'` unless `prefers-reduced-motion: reduce`.
  - photos use the view URL with `width`/`height` like the IMAGE case; missing view URL → the recessed placeholder box.
- `BlockList`: a GALLERY case renders `PhotoGroup` through the existing `wrap`; `renderBlock` still receives the rendered group so callers can replace it.
- `entities/post/model/content.ts` `blockKey`: use `block.files.join('\u001f')` for a GALLERY.
- `widgets/candidate-comparison`: a GALLERY line `사진 묶음(콜라주|슬라이드): a.jpg, b.jpg: <caption>` via i18n keys beside `comparison.photo`.
- i18n (`posts` namespace, ko/en): previous/next aria labels, the position indicator, layout names 콜라주/슬라이드 (Collage/Slide) — names only, no help copy.
- tests: a jsdom IntersectionObserver stub as `ContactSheet.test.tsx` uses; stub `scrollTo` on the element.
