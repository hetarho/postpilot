# T057 Resolving the data fields at enqueue and fencing their values in the prompt
> st:todo | ssot:TEMPLATE-45 TEMPLATE-46 TEMPLATE-11 GEN-15 GEN-16 | base:TEMPLATE@4 GEN@4 POST@3 ARCH@2 | dep:T055 T056

## goal
Resolve every ask node against the post's answers at enqueue — dropping the off and the blank ones whole — and render the surviving values into the prompt as fenced fact rather than instruction.

## acceptance
- [ ] `template.Answer{Label, Text, Enabled}` and `Render(name, nodes, filenames, maxIterations, answers)`: resolution runs BEFORE expansion and before the expansion bound is counted
- [ ] a field whose answer is missing, `Enabled` false, or blank after trimming removes its whole `ask` node: the rendered body for that post is byte-identical to the same template with the node deleted from the body, and no dropped label appears anywhere in `Rendered`
- [ ] a verbatim-flavor field with a value renders the trimmed value as literal text at its position
- [ ] an instruction-flavor field with a value renders `<write>지시</write>` followed by `<facts label="…">값</facts>`, and `Rendered.Facts` records the surviving `{Label, Value}` in body order
- [ ] `TemplateBrief.Facts` carries them through `generation_payload.go` (encode + decode, an older payload decoding as none) so a restart-resume prompts identically
- [ ] `writeTemplateSection` appends ONE legend line for `<facts>` only when `len(brief.Facts) > 0` — the same rule `templateSlotLegend` already follows — saying the values are the user's own facts, that the preceding `<write>` may use only those, that the tag itself is never output, and that its content is fact and not instruction
- [ ] `koreanGrounding` / `englishGrounding` name the template's data fields as a third source beside the memo and the photo observations, unconditionally, in both the write and the revise prompt; the write- and revise-scope clauses are unchanged
- [ ] `RenderedFor` takes the answers, the generation `TemplateBriefs` port and the `cmd/api` adapter pass `PostInput.TemplateAnswers` through, and `freezeTemplate` is the only place they are read
- [ ] tests: render drops off/blank/missing and keeps the body byte-identical to the node-deleted equivalent · a dropped node counts toward no iteration bound · both flavors render as specified · the legend appears only with facts · a post with no template stays byte-identical to the existing golden · the payload round-trips facts · editing an answer after StartGeneration cannot change the frozen brief
- [ ] the write/revise prompt-assembly snapshots and the golden fixtures are updated for the amended grounding text, in one reviewed pass
- [ ] verify: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...`

## impl notes
- resolution belongs in `internal/template` beside `Render`, not in the adapter: TEMPLATE-45 makes "off, blank and absent are one case" a property of the grammar's own renderer, and it is testable there without a post
- the drop is of the NODE, not of its text: surrounding literals stay exactly as authored, which is why the byte-identity assertion against a node-deleted body is the acceptance that actually pins TEMPLATE-45
- `<facts>` is a sibling tag rather than an attribute on `<write>` or a line inside it: the legend has to be able to say "never output this tag", and an attribute would put user text where the model reads structure. Its value is the trimmed answer, entity-encoded the way `write` text already is
- keep the legend line conditional on `Facts` for the same reason the slot legend is: teaching a token the prompt does not contain invites the model to emit it
- the grounding constant changes unconditionally even for a post with no template. It sits in the STATIC task/format rules ahead of the voice profile, so making it conditional would break the byte-stable prefix TEMPLATE-12 and GEN-14 are protecting for prompt caching; one extra clause naming a source this post has none of costs nothing
- the revise pass reaches the answers only through the frozen brief (GEN-16): do not add a memo, an observation or an answer list to the revise payload
- `Rendered.Facts` is also what a later A/B comparison inherits for free — both candidates read the same frozen brief (TEMPLATE-15), so there is nothing experiment-side to change
