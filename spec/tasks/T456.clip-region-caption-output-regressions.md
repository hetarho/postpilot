## goal
Verify the complete edit-to-output workflows with repeatable regression fixtures and actual browser/server render evidence.

## acceptance
- [ ] A no-template project can enable intro/outro, obtain text through either approved generation path, edit exact slot words and render those words in both kinds. Disabling, blank slots, all-empty unresolved blocks, unused slots and preset shrink/grow preserve the specified content/absence and notices.
- [ ] A selected caption can switch outside the AI set and between static/sequence styles, move, resize and undo/redo without changing words, phrase/output intervals, other captions or cuts. Save/reopen and correction-to-storyline edits preserve the same canonical result.
- [ ] Extend resolved-element checks V17/V20 and cross-path fixtures to compare enabled regions, exact ordered slot text, preset geometry and caption style/size/position at representative start/middle/end frames. Cover all ratios and both caption paces, including captions crossing cuts and a cut with no caption.
- [ ] Add an integrated UI/API regression for flush-before-render after mixed slot/caption edits and a failed/conflicting save. An invalid authored overflow stays editable and does not launch rendering; an old file is never presented as the new draft or accepted for finalization.
- [ ] Read-only compatibility fixtures include an existing project with stored presets but no region elements, one with saved generated regions and a finalized project without originals. Opening them changes no confirmed content, enables nothing implicitly and makes no AI call.
- [ ] Run representative full clips through browser and CPU server rendering using controlled retained-original fixtures, reviewing muted and configured-audio playback. Record manifest/frame comparisons plus timing, audio and delivered-file checks; distinguish deterministic provider fixtures from any actual provider run, and do not claim unsupported real-time preview animation or decoded-byte equality.
- [ ] Pass ARCH-31's local gates and matching media image smokes. Record commands, artifacts and any unexecuted browser/media checks in result; a fixture-only run is not reported as actual renderer verification.

## impl notes
- Add to existing clip domain/media manifest suites, `frontend/src/pages/clip/ui` workspace tests, `entities/clip-preview` tests and `features/render-clip-browser/api` render tests rather than creating a parallel harness. Extend release media smoke fixtures only where the new paths need executable coverage.
- Use renderer-produced rasters/frame sheets for browser comparisons. Check semantic text/timing/appearance and the declared output measurements rather than requiring identical compressed files; preserve the preview's static flow-simulation and motion limitations under CDS-65.
- Use controlled/synthetic test originals and provider doubles for repeatability and call-count assertions. Do not mutate an owner's localhost project, contact paid providers or claim real-provider provenance without the required authorization. If a generation-failure fix emerges, follow CLIP-91's additional verification requirements separately.
- Exercise source expiry/finalization reads without trying to revive originals. Include failing autosave and delayed responses so cross-surface consistency is tested at the workflow boundary, not only in individual reducers.
- No CPU/GPU acceptance decision is made here: CLIP-163 remains open, and existing GPU activation work stays outside these tasks. Task-level tests in T450–T455 are still required before those tasks complete; this task adds cross-feature and delivered-output evidence.
