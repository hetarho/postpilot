# T186 A project carries its own instruction
> st:todo | ssot:CLIP-121 CLIP-1 CLIP-69 | base:CLIP@27 ARCH@2 | dep:-

## goal
Store one optional free-text instruction of at most 1000 characters on a clip project, typed beside its answers and frozen into every generation.

## acceptance
- [ ] migration `0055_clip_project_instruction.sql` adds `clip_projects.instruction TEXT NOT NULL DEFAULT ''`, embedded and run at boot (→ARCH-10)
- [ ] `ClipProject.instruction = 30`, `CreateClipProjectRequest.instruction = 11` and `UpdateClipProjectRequest.optional string instruction = 10` carry it; generated code is regenerated, not hand-edited (→ARCH-3)
- [ ] the instruction is bounded where it is typed, CLIP-117's way: no character beyond 1000 is accepted, a paste is cut to it, and a live counter sits with the control (→CLIP-121)
- [ ] the control sits with the project's answers in `ClipProjectForm`, is optional, and an empty instruction is indistinguishable from never having written one
- [ ] generation freezes the instruction into the attempt payload beside the answers and the composition, so editing it mid-flight changes nothing in flight (→CLIP-69)
- [ ] a payload written before this field decodes as no instruction, and every existing project reads as having none
- [ ] tests: the bounded input and counter, the round trip through create/update/read, and a frozen payload that ignores a later edit
- [ ] verify BE (ARCH-26) and FE (ARCH-25) pass

## impl notes
- a column, not a member of `composition_inputs_json`: the instruction belongs to the project (CLIP-1), while that JSON holds answers the template declared
- the 1000 lives once on each side — backend `internal/platform/config` and `frontend/src/shared/config` — never as a literal in a component or handler (→ARCH-21)
- reuse the bounded-input helper T181 built for answers (`boundedAnswer`, `FieldCount`); the counting rule is CDS-20's
- this task stores and freezes only. The writer does not read it yet — T187 does
