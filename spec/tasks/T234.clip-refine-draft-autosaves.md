# T234 ②'s edit draft autosaves and 저장 leaves the dock
> st:todo | ssot:CLIP-39 | base:CLIP@34 | dep:-

## goal
Step ② saves its edit draft the way ① saves its settings, so no 저장 button stands in the dock and no dirty state gates 다시 렌더 or a revision request.

## acceptance
- [ ] ②'s dock carries no 저장 button at any draft state
- [ ] 다시 렌더 is enabled while the draft is dirty and flushes the pending save before it starts the render, so the render always runs against the saved revision
- [ ] a draft the validation refuses is still held unsaved, 다시 렌더 stays disabled and the surface names the cut or caption to correct
- [ ] the revision request keeps flushing before it starts, unchanged
- [ ] vitest: 다시 렌더 on a dirty valid draft saves first and renders the returned revision; an invalid draft leaves 다시 렌더 disabled with its message
- [ ] verify: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- `useClipCorrection` ALREADY autosaves on `CLIP_TIMELINE.autosaveMs` (its `useEffect` calling `saveRef.current()`), so this task removes a redundant control rather than building a queue
- drop the `correction.dirty && <Button timeline.save>` branch from `ClipCorrectionWorkspace`'s dock row; keep `correction.save` on the hook for the flush path
- `onRender` in `ClipPage` currently early-returns while `correction.dirty`; make it `await correction.flush()` then render with the revision that flush returns, matching how `ClipRevisionRequest` already receives `flush`
- `renderReady` in `ClipPage` compares `correction.revision === project.editPlanRevision`; after flush that holds, so keep the comparison but evaluate it after the flush resolves rather than gating the button on `!correction.dirty`
- the workspace's render Button loses `correction.dirty` from its `disabled` expression and keeps `disabled || correction.pending || !renderReady || !correction.validation?.valid`
- `timeline.save` stays in the ko/en resource files only if something still reads it; remove the key from both when nothing does
