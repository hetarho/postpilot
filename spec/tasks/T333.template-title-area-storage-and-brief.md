# T333 Templates store, validate and render a title area into the frozen brief
> st:todo | ssot:TMPL-2 TMPL-8 TMPL-43 TMPL-50 TMPL-51 TMPL-52 TMPL-53 TMPL-54 GEN-52 ARCH-21 ARCH-24 | base:TMPL@10 GEN@10 ARCH@9 | dep:T322 T323 T324 T327

## goal
- A template's title area is saved with presence semantics and validated together with the body inside the update transaction. At enqueue it is expanded with the post's answers and frozen with the body into the generate, revise and write-experiment inputs. Stored templates and template-less posts stay byte-identical.

## acceptance
- [ ] Reads and create:
  - CreateTemplate stores `title_area`;
  - ListTemplates and every Template in a response carry it;
  - a template stored before this task reads `''`.
- [ ] UpdateTemplate follows the presence rule:
  - an absent `title_area` is named by no statement;
  - a present `''` clears it;
  - a present value is written by `UpdateTemplateTitleArea` in the same transaction as the other present fields (TMPL-8).
- [ ] The title area is edge-trimmed exactly as the body is, may be empty, and is bounded by `TEMPLATE_TITLE_AREA_MAX_CHARS` (default 200, counted in Unicode scalar values). Over the bound is InvalidArgument `TEMPLATE_FIELD_TOO_LONG` with `field=title_area`, `max` and `actual`.
- [ ] Create and update parse both areas together with T327's `ParseTemplate`.
  - An error in the title is `TEMPLATE_PARSE_FAILED` with `line`, `reason` and `area=title_area`.
  - An error in the body carries only `line` and `reason`, as today.
  - No FailureReason is added.
- [ ] Update checks the patch against what is stored. When `body` or `title_area` is present, the check runs inside the update transaction, pairing each present value with the stored counterpart of the other.
  - A title-only patch whose label a stored body already uses is refused `duplicate_ask_label` in the body.
  - A body-only patch is checked against the stored title.
  - A refused update writes nothing, including `updated_at`.
- [ ] `TEMPLATE_ASK_MAX_PER_BODY` counts the title area's asks and the body's together. `TEMPLATE_ASK_LABEL_MAX_CHARS` (`FieldTooLongError{Field: "ask_label"}`) bounds title-area asks too.
- [ ] RenderedFor:
  - either area failing to parse gives `ok=false`, as a body that no longer parses does today;
  - the title area renders with the post's answers resolved and zero photos;
  - `Rendered.TitleArea` is `''` when the area is empty or blank after its asks drop;
  - `Rendered.Facts` lists the title's facts first (TMPL-55).
- [ ] Generation:
  - `TemplateBrief.TitleArea` is filled from `Rendered.TitleArea`;
  - the generate and revise payloads carry `template.title_area` (omitempty), and a payload written before it decodes as none (TMPL-51);
  - a frozen payload ignores a later edit of the live row;
  - a different title area is a different write-experiment snapshot;
  - the write and revise prompts built from a real rendered brief carry the title area before the body.
- [ ] With an empty title area nothing moves: every golden, `TestGenerationPayloadWireShapeIsPinned` and every existing snapshot stay byte-identical.
- [ ] `TEMPLATE_TITLE_AREA_MAX_CHARS` is boot-fatal when malformed or non-positive, and appears in `.env.example` and `.env.production.example`.
- [ ] Tests:
  - `internal/template/service_test.go`: `TestCreateStoresATitleAreaAndRefusesOneThatDoesNotParse`, `TestUpdateChecksTheTitleAreaAgainstTheStoredBody`, `TestUpdateChecksTheBodyAgainstTheStoredTitleArea`, `TestTheAskCeilingCountsBothAreas`, `TestRenderedForRendersTheTitleAreaFirst` (asks off, blank and answered; blank gives `''`; facts title first; an unparsable title gives `ok=false`);
  - `internal/template/store/title_area_store_test.go`: `TestTitleAreaRoundTripsAndAPresentEmptyClearsIt`, `TestUpdateRunsTheCheckOnTheStoredRowBeforeAnyStatement`;
  - `internal/template/rpc/handler_test.go`: `TestListTemplatesCarriesEveryFieldAcrossTheWireEdge` and `TestCreateAndUpdateCarryPresenceRatherThanZeroes` extended with `title_area`, and `TestEveryDomainRefusalHasItsOwnCodeAndReason` extended with the `area` param (present for a title error, absent for a body error);
  - `internal/platform/config/config_test.go`: `TestLoadTemplateLimitDefaultsAndValidation` covers the new key;
  - `internal/generation/template_test.go`: `TestTheTitleAreaRidesBothPayloadsAndALegacyOneDecodesAsNone`, `TestTheFrozenTitleAreaSurvivesAnEditOfTheLiveRow`, `TestADifferentTitleAreaIsADifferentWriteSnapshot`;
  - `cmd/api/bootstrap_test.go`: `TestGenerationAdapterCarriesTheTitleAreaIntoTheFrozenBrief`;
  - every existing golden and pinned test, unedited.
- [ ] Verify: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test -timeout 30m ./...` · `pnpm gen:sql && git diff --exit-code -- backend`

## impl notes
- What the deps provide:
  - T322's proto: `Template.title_area = 10`, `CreateTemplateRequest.title_area = 6`, `UpdateTemplateRequest` `optional string title_area = 7`, which is `TitleArea string` and `*string` in Go;
  - T323's `templates.title_area TEXT NOT NULL DEFAULT ''`;
  - T324's `generation.TemplateBrief.TitleArea` (`json:",omitempty"`) and the prompt section;
  - T327's `ParseTemplate`, `AreaTitle` and `ReasonNotInTitle`.
- `store/queries/templates.sql` (keep it ASCII-only):
  - add `t.title_area` after `t.body` in `ListTemplates` and `GetTemplate`. T323 left both selects to this task;
  - `InsertTemplate` becomes `(id, user_id, name, description, body, title_area, target_length, tag_count, created_at, updated_at)` with ten `?`;
  - add `-- name: UpdateTemplateTitleArea :execrows` / `UPDATE templates SET title_area = ?, updated_at = ? WHERE id = ? AND user_id = ?;` beside `UpdateTemplateBody`;
  - run `pnpm gen:sql` and commit the generated code.
- `store/store.go`:
  - `Insert` passes `TitleArea`;
  - `toTemplate` gains a `titleArea string` parameter, which `List` and `get` fill from `row.TitleArea`;
  - `Update` runs `UpdateTemplateTitleArea` when `patch.TitleArea != nil`, after the body statement and before the numbers. It uses the same `n == 0` → `ErrNotFound` and `touched` handling.
- The port changes in `ports.go`: `Update(ctx, userID, id string, patch Patch, updatedAt time.Time, check func(current Template) error) (Template, error)`.
  - With `check != nil`, the store reads the row with `s.get(ctx, q, userID, id)` inside the transaction, before any statement. An unknown or foreign id is `ErrNotFound` before check runs.
  - It then calls `check(current)` and returns check's error with nothing written.
  - The writer handle is `_txlock=immediate` with one connection (`platform/db/db.go`), so no other write can move the counterpart between that read and the statements.
  - Existing store test callers pass `nil`.
  - The fakes in `service_test.go` and `rpc/handler_test.go` run `check` on their stored row, and the service fake also applies `patch.TitleArea`.
- `types.go`:
  - `Template.TitleArea string` (`''` is none);
  - `Patch.TitleArea *string`, which is part of `Patch.empty()`;
  - `Limits.TitleAreaMaxChars int`, required `> 0` in `valid()`;
  - `Rendered.TitleArea string`.
- `service.go`:
  - `validBody` keeps trim, required and length, and drops its parse.
  - New `validTitleArea(value string) (string, error)` uses `strings.TrimSpace`, the same edge trim `validBody` applies. `''` is allowed. Over `TitleAreaMaxChars` it returns `&FieldTooLongError{Field: "title_area", Chars, Max}`.
  - New `validShape(titleArea, body string) error` runs `ParseTemplate(titleArea, body, s.parseOptions())`, then the existing ask-label bound over `Asks(title)` and then `Asks(nodes)`.
- `Create(ctx, userID, name, description, body, titleArea string, numbers Numbers)` takes the title area after the body.
  - Every existing caller passes `""`: the rpc handler, `service_test.go`, `numbers_test.go`, and five calls in `cmd/api/bootstrap_test.go`.
  - Validation order is name, description, body, title area, shape, numbers.
- `Update` validates each present field as today, plus `validTitleArea`.
  - When `patch.Body` or `patch.TitleArea` is present, it passes a check closure. The closure takes each area from the patch when present, else from `current`, and returns `s.validShape(title, body)`.
  - Otherwise it passes `nil`, so an edit of the name alone parses nothing, as today.
- Blame follows `ParseTemplate`'s order, title first. A title-only patch reusing a stored body label is reported in the body at the body's line: TMPL-55's order, not the field the request touched.
- `expand.go` gains `RenderTemplate(name string, title, body []Node, filenames []string, maxIterations int, answers []Answer) (Rendered, error)`:
  - the body is rendered by `Render(name, body, filenames, maxIterations, answers)`, exactly as today;
  - the title is rendered by `Render(name, title, nil, maxIterations, answers)`. A title holds no slot or repeat, so it binds nothing and costs nothing against the bound;
  - `Rendered.TitleArea` is the title's text, set to `''` when `isBlank`, and otherwise kept verbatim;
  - `Rendered.Facts` is the title's facts followed by the body's;
  - `Render` itself is unchanged, so `expand_test.go` and `ask_resolution_test.go` stay as they are.
- `RenderedFor` calls `ParseTemplate(found.TitleArea, found.Body, s.parseOptions())`. Any error returns `(Rendered{}, false, nil)`, as the body-only parse does today. It then calls `RenderTemplate`.
- Config:
  - `internal/platform/config/config.go` gains `TemplateTitleAreaMaxChars int` beside `TemplateAskMaxPerBody`, read with `positiveInt("TEMPLATE_TITLE_AREA_MAX_CHARS", "200")`;
  - `cmd/api/contexts.go` passes `TitleAreaMaxChars: cfg.TemplateTitleAreaMaxChars`;
  - `TitleAreaMaxChars: 200` goes into the four `template.Limits` literals in `cmd/api/bootstrap_test.go`, `testLimits()` in `service_test.go` and `handler()` in `rpc/handler_test.go`. Without it `NewService` panics on `valid()`;
  - add `TEMPLATE_TITLE_AREA_MAX_CHARS=200` to the template section of both env examples. The `VITE_` mirror belongs to T336.
- `rpc/handler.go`:
  - `CreateTemplate` passes `req.Msg.GetTitleArea()`;
  - `UpdateTemplate` sets `Patch.TitleArea = req.Msg.TitleArea`, so presence passes straight through;
  - `toProtoTemplate` sets `TitleArea`;
  - the parse branch of `toConnectError` adds `params["area"] = template.AreaTitle` only when `parseErr.Area == template.AreaTitle`;
  - the operator message becomes `"template does not parse"`.
- A gap until T340, known and unreachable. The FE's `TEMPLATE_PARSE_FAILED` spec allows only `line` and `reason`, and `validateParams` in `shared/api/app-failure.ts` turns an unlisted param into `UNKNOWN_FAILURE`.
  - An `area` param needs a title that fails. Title asks are counted first, so a stored title parses again whatever body it is paired with (short of an operator lowering `TEMPLATE_ASK_MAX_PER_BODY`).
  - T336 only resends the stored title, and T340 adds `area` to the spec.
- `cmd/api/adapters_generation.go`: the returned `generation.TemplateBrief` gains `TitleArea: rendered.TitleArea`.
- `internal/generation/generation_payload.go`:
  - `templatePayload` gains `TitleArea string` with `json:"title_area,omitempty"` after `Body`;
  - `encodeTemplate` and `decodeTemplate` copy it;
  - `revise.go`'s payload reuses `templatePayload`, so this one field covers generate and revise, and an absent key decodes to `''`;
  - `cloneTemplate` in `generate_handler.go` copies the struct by value (`copied := *value`), so the string needs no edit there.
- The experiment snapshot marshals `PostInput`, and with it `*TemplateBrief`, directly. T324's omitempty keeps a title-less snapshot byte-identical, and no snapshot code changes.
- `TestGenerationAdapterCarriesTheTitleAreaIntoTheFrozenBrief` runs on real SQLite, like `TestGenerationAdapterCarriesThePostTemplateThroughToTheFrozenBrief`:
  - the template's title area is `<ask label="가게 이름">가게 이름을 넣어 쓰세요</ask> 방문 후기` and its body is `<ask label="총평">총평을 쓰세요</ask>`;
  - the post answers both, enabled;
  - `brief.TitleArea` holds the fenced fact, and `brief.Facts` is `[가게 이름, 총평]`;
  - in `BuildWritePrompt` and `BuildRevisePrompt` output, `strings.Index(system, brief.TitleArea)` falls after `[글 템플릿:` and before `strings.Index(system, brief.Body)`.
- Prompt wording and position belong to T324. This task only proves that a real brief reaches them.
