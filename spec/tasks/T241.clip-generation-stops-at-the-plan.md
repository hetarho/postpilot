# T241 a generation stops at the validated plan and renders nothing

## goal
A clip generation succeeds with a validated plan and no result file, and a project holding a plan with no render is a normal state everywhere that reads one.

## acceptance
- [ ] a generation job ends after the plan is validated and saved; no media execution runs and no result is written
- [ ] the attempt settles as a successful generation under QUOTA-46 with its notices, exactly as a rendering generation did
- [ ] a project with a plan and no result opens ② and is presented as a plan to review, never as a missing or failed result
- [ ] an existing project keeps its stored result and its revision unchanged
- [ ] a revision request already stops at the plan; its path is unchanged by this task
- [ ] go test: a generation completes with `editing.plan` set and `result` empty; the previous result of a regenerated project survives; the job's terminal state is success
- [ ] vitest: ② mounted on a project with a plan and no result shows the draft preview and no result-missing failure
- [ ] verify: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...` · `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- the generate worker's stages end at the saved, validated plan; the execute stage moves to the render path T242 owns, so this task REMOVES a stage rather than adding a branch
- `internal/job/worker.go`'s generate_clip case and the clip service's post-plan steps are where the cut lands; keep the recovery-plan save, the notice recomputation and the retention renewal
- the quote and the reservation are unchanged: the render is credit-free either way (CLIP-20), so nothing about the ceiling moves
- `clip/store` tests run ~759 s, past `go test`'s default; run that package with `-timeout 30m` rather than reading the default timeout as a failure
- FE: every place that treats "no result" as a failure state — the step router's `ClipStepWaiting`, the download and the finalization refusals — reads it as the first state instead; the copy for it belongs to T246 and this task only stops the false failure
