# T090 Safe clip failure diagnostics
> st:blocked@260911 | ssot:ARCH-7 ARCH-9 ARCH-11 ARCH-23 ARCH-24 ARCH-26 ARCH-31 CLIP-21 CLIP-26 CLIP-29 | base:ARCH@2 CLIP@3 | dep:T086

## goal
Preserve bounded, nonprivate server-side diagnostics for failed clip provider attempts without changing user-visible failures, billing or retry behavior.

## acceptance
- [v] clip failure logs identify the failed stage and, when available, the provider-call operation, code-owned failure classification, HTTP status, numeric upstream code and validated response request ID
- [v] HTTP rejection, metadata failure, network/timeout/cancellation, local body-read failure and response decoding failures retain distinct diagnostics through wrapped errors
- [v] no raw provider message, body, prompt, media, URL, credential or arbitrary header enters diagnostics or public failure payloads; invalid/oversized request IDs are omitted
- [v] existing error classification, errors.Is/errors.As behavior, recorded usage, settlement and no-retry guarantees are unchanged, with focused fake-HTTP/privacy regression tests
- [ ] local ARCH verification gates and remote CI/deployment pass; no paid completion or user-media replay is performed

## impl notes
- Owner-approved follow-up to the deployed T086 incident: raw failures were correctly excluded but all operator diagnostics were also lost. This is an implementation defect within existing CLIP privacy/failure contracts; no SSOT policy change or database/protobuf change.
- Use provider-neutral diagnostic error metadata in internal/llm and a strict allowlist projection at the worker logging boundary; preserve causes for existing classifications without adding public params or changing stable error strings.
- Capture only bounded response correlation headers, never request headers or provider prose. Read no additional response beyond existing bounds. Do not add retries, change model selection, loosen pricing or send diagnostic provider calls.
- Keep concurrent T087/frontend work untouched; run unrelated-side verification from an isolated committed-source snapshot if the shared worktree is changing.
