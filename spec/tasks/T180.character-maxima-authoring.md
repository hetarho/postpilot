# T180 Author a character maximum in the template editor
> st:todo | ssot:CLIP-116 CLIP-113 CLIP-71 CLIP-58 | base:CLIP@25 ARCH@2 | dep:T179

## goal
Give the composition editor a 최대 글자 수 control bounded by what each position allows, and describe `chars` in 원문 errors and the copied 형식 안내.

## acceptance
- [ ] the builder shows a 최대 글자 수 control on an information-field row and on a text or slot row, bounded by that position's derived cap with the cap stated beside it, and clearing it means 자동
- [ ] a region slot row shows its preset's cap (아웃트로 E의 display 6자) so the author sees the ceiling before typing a number
- [ ] a pasted 원문 whose `chars` exceeds its position shows `invalid_max` at its 1-based line in plain words with 저장 disabled, like every other authoring error (→CLIP-71 →CLIP-113)
- [ ] 형식 안내 복사 documents the attribute and the per-position caps, so an outside AI writes a number the parser accepts
- [ ] ko and en copy for the control, its cap hint and the new reason
- [ ] tests: the control clamps to the cap and round-trips through the body, the guide text carries the attribute, and the new reason renders at its line
- [ ] verify FE (ARCH-25) passes

## impl notes
- surfaces: `entities/clip-template/ui/CompositionBuilder.tsx` for the row, `CompositionTextControls.tsx` for the element fields, `model/composition-guide.ts` for the copied format guide, and the reason copy beside the existing ones in `app/providers/i18n/resources/{ko,en}/clips.ts`
- the number input is a `shared/ui` primitive with tokens only (ARCH-20); no hand-rolled control and no arbitrary values
- the control writes the attribute through the same node edit path the other attributes use, so the draft stays lossless between the builder and 원문 (→CLIP-71)
- the cap shown is the one T179 computes; the editor must not derive its own number
