# T011 Plain-language block names, fixed text instead of place/link, and the photo row stepper
> st:todo | ssot:TEMPLATE-18 TEMPLATE-20 TEMPLATE-26 TEMPLATE-36 TEMPLATE-37 TEMPLATE-38 | base:TEMPLATE@2 ARCH@1 | dep:T010

## goal
Rename the composition toolbar and row badges to what the reader gets, show each block's help on the button, retire the place/link buttons by reading stored ones as fixed text, and let a photo position carry a side-by-side count edited with a stepper.

## acceptance
- [ ] the TypeScript parser reads `count` on photo slots with the same rules and reasons as Go (`invalid_count`, `malformed_tag` on non-photo slots), the shared fixture `cases.json` passes on both sides including the cases T010 added, and the differential corpus still matches
- [ ] the add toolbar offers exactly five buttons in this order: `AI가 쓰는 글` · `고정 문구` · `사진` · `사진마다 반복` · `AI에게만 하는 말` (en: `AI writes here` · `Fixed text` · `Photo` · `Repeat per photos` · `Note to AI`); each button shows its name and its one-line help as visible text, not a `title` or tooltip; `사진마다 반복` is still hidden when the aim is inside a repeat
- [ ] a collapsed row's badge uses the same name as the button that creates it; no palette or row copy contains 작성, 삽입 or bare 반복
- [ ] a stored body with a `place` or `link` slot opens as a `고정 문구` row whose text is the slot's label, falling back to 지도 / 링크 (en: Map / Link) when the label is empty; the draft is not dirty until the user edits; the next 저장 writes that row as literal text and the body no longer contains the slot; the composition is not shown as unreadable
- [ ] a 사진 row expanded shows a stepper labelled 가로로 놓을 사진 수 (en: Photos side by side) with − and + buttons, the current value, min 1 and max `TEMPLATE_PHOTO_ROW_MAX`; the buttons disable at the bounds; the collapsed summary reads `사진 1장` for 1 and `사진 n장 가로로` for n > 1 (en: `1 photo` / `n photos side by side`)
- [ ] a photo row inside a repeat shows the repeat's help stating how many photos one iteration takes: `한 번 되풀이할 때 사진 n장을 씁니다` where n is the sum of the counts inside it (en: `Each repetition uses n photos`)
- [ ] `toBody` emits `<slot kind="photo"/>` for count 1 and `<slot kind="photo" count="n"/>` for n > 1; builder → body → builder is byte-identical for every builder output including counts; `blocks.test.ts` pins both
- [ ] `shared/ui/stepper` is a new primitive (group with an accessible label, − / + buttons, `aria-valuenow`/`min`/`max` on the value, keyboard arrow support) with its own test, built from tokens only and used by the composition editor
- [ ] `frontend/src/shared/config` exports `TEMPLATE_PHOTO_ROW_MAX` from `VITE_TEMPLATE_PHOTO_ROW_MAX` falling back to 4; `.env.example` documents the mirror beside the backend var
- [ ] `GrammarStaysInternal.test.tsx` still proves no grammar syntax reaches the page, extended with `count="` in its syntax list and a body carrying `count="3"`
- [ ] every existing test that clicked or read 작성 / 메모 / 반복 / 지도·장소 / 링크 is updated to the new names; the i18n `builder.reasons` gains `invalid_count` (ko: `가로 사진 수가 1~{{max}} 사이가 아니에요`, en: `Photos per row must be between 1 and {{max}}`)
- [ ] `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` pass on Node 24.18.0

## impl notes
- grammar (`entities/template/lib/grammar.ts`): add `count?: number` to `TemplateNode` and `'invalid_count'` to `ParseReason`; parse `count` in the `slot` branch after `kind` with the same trim → integer → range rule as Go; the ceiling is a `parse(body, { photoRowMax })` option and the fixture test passes the file's `photoRowMax`; the production call sites pass `TEMPLATE_PHOTO_ROW_MAX` from `shared/config`; `serialize` keeps re-emitting raw slices so counts round-trip untouched
- blocks (`entities/template/model/blocks.ts`): `BuilderBlock` gains `{ kind: 'photo'; count: number }` replacing the `slot` variant; `PaletteKind = 'write' | 'text' | 'photo' | 'repeat' | 'note'`; `BuilderBlockKind` equals `PaletteKind`; `newBlock('photo')` → count 1; `fromNodes` maps a `slot` node with kind `photo` to `{kind:'photo', count: node.count ?? 1}` and a `place`/`link` node to `{kind:'text', text: decoded label || t('builder.legacy.place'|'link')}` — take the fallback strings as a parameter the way `decodeText` is passed, so `model` stays react- and i18n-free
- the migration of a legacy slot to a text row changes the body on the next save only: `fromBody(stored)` → rows; `toValidBody(rows)` differs from `stored`, so the page's dirty check would light up — keep the clean baseline as the stored body but compare the draft against `toValidBody(fromBody(stored))` for the composition (compute once when the row list is seeded); pin this with a TemplatePage test that opens a legacy body and asserts 저장 is disabled until an edit
- `blockSummary`: photo → i18n key `composition.summary.photo` with count (`사진 {{count}}장` / `사진 {{count}}장 가로로`); pass `t` in from the UI or return a structured `{key, count}` and format in the row component — keep `model` free of react but `i18next` is already imported by `types.ts`, so calling `i18next.t` in `blocks.ts` is acceptable and consistent
- palette (`TemplateComposition.tsx` `Palette`): render each button as a two-line `Button` (name in body weight, help in `text-content-tertiary` caption) or a `shared/ui/button` with a `description` slot if the primitive supports it — check the primitive before extending it; keep `size="compact"` off, the buttons wrap on 360 px; `kinds` becomes the five-value array
- photo row fields: replace the label `Field` with the `Stepper` for `block.kind === 'photo'`; the repeat row's help line (`composition.repeatHelp`) becomes a function of its children's total count
- stepper (`shared/ui/stepper/Stepper.tsx` + `index.ts` + test): props `label`, `value`, `min`, `max`, `onChange`, `formatValue?`; buttons use the existing `Button` primitive (`variant="secondary" size="compact"` with `aria-label` 줄이기 / 늘리기, en Fewer / More); export from `shared/ui/index.ts`
- i18n (`resources/ko/templates.ts`, `resources/en/templates.ts`): replace `builder.palette.*` with the five names + help; drop `place`/`link` keys and placeholders; add `composition.summary.photo`, `builder.block.count`, `builder.legacy.place`, `builder.legacy.link`, `builder.reasons.invalid_count`; the `slot.*` keys stay (legacy content still renders them)
- config (`shared/config/index.ts`): `TEMPLATE_PHOTO_ROW_MAX = positiveIntEnv(import.meta.env.VITE_TEMPLATE_PHOTO_ROW_MAX, 4)` beside the other template mirrors; `.env.example` line `VITE_TEMPLATE_PHOTO_ROW_MAX=4`
- tests to update: `TemplateComposition.test.tsx` (button names, summaries, stepper, legacy slot → text row), `TemplatePage.test.tsx` (button names, legacy body clean baseline), `GrammarStaysInternal.test.tsx` (count syntax), `blocks.test.ts` (count round-trip, legacy mapping), `grammar.test.ts` (fixture ceiling); `EditorPage.test.tsx` and `Field.test.tsx` only if their matched strings were these palette names — check before editing
- nothing in export, the post editor, the reading view or publishing changes: TEMPLATE-40 keeps a count-n position as n consecutive single-photo IMAGE blocks until TEMPLATE-39 is decided
