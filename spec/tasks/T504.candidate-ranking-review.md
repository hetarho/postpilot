## goal
Replace the new comparison's winner/dismissal controls with a complete candidate ranking that permits ties, optional badges and explicit skip.

## acceptance
- [ ] Before identities are revealed, each successful candidate has an accessible rank control and optional badge/note controls. Equal rank choices are possible; failed candidates show a failure and retry but cannot be ranked. Candidate controls remain associated with stable blind A–E positions while switching on a phone.
- [ ] `순위 저장` submits all successful candidates exactly once with dense ranks starting at 1, including ties; it cannot submit a partial list or submit when fewer than two succeeded. `순위 건너뛰기` submits none and is available for a single survivor. Badges cannot attach to an unranked candidate, notes stay within 200 characters, pending submissions cannot repeat, and server refusal leaves local choices intact.
- [ ] Submission or skip reveals identities, stored ranks, badges and permitted accounting from the server and survives reload. The UI distinguishes a rank tie from a quality score. Ranking and skip never apply content or change the active model.
- [ ] Old decided/dismissed/unpaired A/B records retain readable output, outcome, badges and their legacy follow-up controls, without fabricated candidate ranks. FE tests cover five candidates, ties, partial success, incomplete ranks, single survivor, skip, failure and reload, accessibility and old records; run ARCH-25 verification.

## impl notes

- Replace the new-record use of `VerdictSheet` with a blind rank editor and one completion action. Use ordered position selection with a tie option or numeric rank controls that can represent dense rank groups; do not hide any successful candidate. Reuse the badge catalog, stage-specific voice badges, 200-character note limit, `shared/ui` controls and ko/en resources. Legacy records may retain the old sheet only for an outstanding old verdict action.
- Submit `CompleteExperimentReview` with `skip=false` and exactly all successful candidates, or `skip=true` with an empty list. Invalidate experiment/history/leaderboard owner queries after success; server response is authoritative for identity reveal.
- Keep the failed-candidate retry available only before completion. Preserve the comparison's entry-context back link and its distinct model-lab/editor navigation.
