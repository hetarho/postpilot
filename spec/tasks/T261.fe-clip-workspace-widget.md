# T261 the clip page composes a widget instead of wiring eleven hooks
> st:todo | ssot:ARCH-14 ARCH-13 ARCH-24 | base:ARCH@5 | dep:T260

## goal
Move the `ExistingClip` orchestration out of `pages/clip/ui/ClipPage.tsx` into `widgets/clip-workspace`, so the page routes and composes while the widget owns the clip session state, and the wiring gets unit tests.

## acceptance
- [ ] `pages/clip/ui/ClipPage.tsx` is ≤150 lines: route params, blocker, layout, and `<ClipWorkspace projectId />`; it imports no feature hooks and holds no `useEffect`
- [ ] `widgets/clip-workspace/model/useClipWorkspace.ts` returns handle objects (`sources`, `generation`, `correction`, `render`, `revision`, `observations`, `finalization`) instead of 22 scalars; `features/correct-clip/ui/ClipCorrectionWorkspace.tsx` takes ≤6 props
- [ ] the clip rules the page encoded — required-source rule, job→upload-attempt lifecycle, sound-batch handoff, conflict-retry routing — live in named model functions/hooks under the widget or the owning feature, each with a unit test (`.test.ts`, no DOM) covering the branches the page's effects covered
- [ ] `frontend/src/test/clips.ts` shrinks: the widget's tests use the model hooks with fake handles, and the page test only checks routing + rendering of the widget
- [ ] behaviour unchanged: `ClipPage.test.tsx` and the correct-clip render tests pass; the sibling-test gap for `features/correct-clip/model/useClipCorrection.ts` is closed (unit test beside it)
- [ ] ARCH-25 passes

## impl notes
- from review/arch-260919 F1 F7 F10
- a widget is the FSD home for a large block that composes several features (ARCH-14); it may import features and entities, and the page imports only the widget
- handle shape: `{ state, actions, failure }` per concern; the correction workspace receives `correction` and `render` handles and reads what it needs — this is what collapses 22 props
- keep effects out of the widget ui: each of the page's five `useEffect`s becomes either a model hook (`useUploadAttemptLifecycle`, `useSoundBatchHandoff`) or is deleted when the entity hook already covers it
- F10's list of untested model files is the acceptance target here only for clip: `useClipCorrection.ts` and every new `model/*.ts` this task creates get a sibling `.test.ts`
