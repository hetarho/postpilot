## goal
Persist independent project regions and editable slot drafts, with template seeding and lossless reads of existing projects.

## acceptance
- [ ] Create without a template starts with both regions off; selecting a preset explicitly enables its region without requiring a template entry. Disabling retains the preset and every slot draft.
- [ ] Each ordered slot retains its instruction, final text, direct-edit provenance and any active fact binding. Explicitly clearing final text is distinguishable from text awaiting generation and remains owner-fixed; editing an instruction alone neither changes text nor invokes AI.
- [ ] Template selection copies design settings and seeds region entries in outline order, enabling regions with entries. Generated entries seed instructions; fixed/bound entries seed exact content. Later selection preserves owner-edited slot content; editing/deleting/deselecting a template leaves copied values intact.
- [ ] Preset changes retain common and surplus slots by order and restore them when capacity grows again. Newly available slots without retained content await input or generation; no text is truncated to fit a smaller preset.
- [ ] Existing projects derive absent metadata from their retained region content, with the saved plan taking precedence for effective presence/text. A stored preset alone never inserts an absent region. Reading changes neither plan/result/revisions nor retention and works for finalized projects without originals.
- [ ] Add Go domain, SQLite migration/store and RPC tests for off versus omitted updates, explicit blank text, template reseeding, binding detachment on direct edit, capacity round trips, foreign IDs, busy/finalized writes and existing projects with/without plans. Add frontend mapper tests for explicit false/empty values and unknown enum handling where applicable.
- [ ] Regenerate proto/sqlc outputs and pass their repeat-generation checks plus ARCH-31's local gates; record actual commands in result.

## impl notes
- Start in `backend/internal/clip/types.go`, `design_selection.go`, `app/service.go`, `store/store.go`, `store/queries/clips.sql` and the project RPC mappers. Use an additive migration and a versioned region-state envelope; a missing envelope means compatibility derivation, not the new-project default. Keep domain types free of transport/storage tags.
- Carry explicit region enablement separately from the retained preset. Slots need stable identity/order, instruction-edit ownership, text ownership and retained binding information: one edited flag cannot distinguish an edited instruction from owner-fixed final text. Keep surplus drafts in the same project-owned state.
- Extend `proto/postpilot/v1/clip.proto` and `clip_generation.proto` additively and map the values in `frontend/src/entities/clip-project`. Preserve field presence in patches; an omitted region/slot field means unchanged, while false and an empty final-text value are real edits. Keep existing generated fields and enum conventions.
- Implement deterministic seeding/compatibility helpers once and reuse them at creation, template selection and reads. Do not infer content from a live template when retained composition/plan content is available. Do not rewrite stored plans in a migration or backfill finalized projects through a write endpoint.
- Use existing bounded composition/instruction limits and stable owner-facing input errors. Authorize before updates and enforce existing active-job/finalized guards in the transaction. T451 owns projection into an existing plan and stale-plan conflict handling; T452 owns approved AI drafting.
- These are implementation choices for CLIP's recorded ownership/compatibility rules, not an additional reusable template format. Keep the reusable template source and starting design defaults unchanged.
