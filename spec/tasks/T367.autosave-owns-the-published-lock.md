# T367 The autosave owns the published lock, and every control reads the lock from the post it holds
> st:todo | ssot:ARCH-14 | base:ARCH@9 | dep:T355 T365 T366

## goal
`useAutosave` owns ①'s text and decides the published lock itself. While the post is published it queues nothing and shows the server's title, memo and answers. When the post reopens it saves again, starting from the server's values. `DraftEditor` loses its lock masking and its render-time reseed. The lock stops being a threaded prop: every component that holds the post asks `isPublished(post)` itself.

## acceptance
- [ ] `UseAutosaveArgs.post` carries `status: PostStatus`. The hook decides `locked = post ? isPublished(post) : false` with the entity predicate, and it is the only place the autosave's lock is decided.
- [ ] The hook owns ①'s text. It no longer takes `title` / `memo` / `answers`. It returns the shape in impl notes (`title`, `memo`, `answers`, `setTitle`, `setMemo`, `setAnswers`, plus today's members).
  - While locked, the hook calls no `queue`. `title` / `memo` / `answers` are the server's. The setters do nothing. `reassign` / `assignTemplate` / `assignTargetLanguage` reject without touching the queue.
- [ ] A save refused as published takes the text back all the way to the screen. `attachDraftQueue` gains `onTakenBack`, called once on the non-retry path. The hook resets its local text to the post's server values. So nothing the lock refused is shown or queued again, before or after the post reopens.
- [ ] `DraftEditor.tsx` holds no ① text state and no lock masking. `opening`, the `title` / `memo` / `answerEdits` states, `lockedFields`, `lockedAnswers`, `shownTitle`, `shownMemo` and `wasLocked` with its render-time `setState` (:64-71, :81-120 at HEAD) are gone. The page renders `autosave.title` / `.memo` / `.answers` and passes `autosave.setTitle` as `onTitleFinalized`.
- [ ] The lock is decided once, at the leaf. No component under `pages/editor/ui` takes a `locked` prop: `LifecycleSteps`, `EditorGeneratePanel`, `EditorPhotos` and `EditorDockHeader` lose it and read `isPublished(post)` themselves. This returns nothing: `grep -nE "\blocked(=|\?:|:| =)" frontend/src/pages/editor/ui/*.tsx | grep -v test`.
- [ ] New tests in `features/save-draft/model/useAutosave.test.tsx`, new `describe('a published post')`:
  - "sends nothing for a published post, across edits and refetches"
  - "never sends a text the lock refused a second time" (T339's measured loop)
  - "saves again from the server's values once the post reopens"
- [ ] A new test in `features/save-draft/model/draft-queue.test.ts`, `describe('a refusal that is an answer')`: "tells the attached editor its text was taken back". It covers once on a locked refusal, never on an outage, and never after `release`.
- [ ] Behavior unchanged. The existing tests still pass, with only the `useAutosave.test.tsx` harness rewritten for the new arguments. That includes every `pages/editor/ui/EditorPage.test.tsx` case in `describe('a published post')`: "shows ① read-only, says why once and sends no write" (as T355 left it, asserting 기억 사용 and the 분야 chips disabled inside the brief), "takes a draft save refused as published for an answer, and ① locks after the refetch" and "reseeds ① from the server when the post reopens", unmodified.

- **Why the hook owns the text, not only the lock.** The shown values could be derived from the page's own state. But reopening would then still need someone to throw away the refused text, which is a state machine in the page again.

  - It cannot be a `setState` in an effect: `react-hooks/set-state-in-effect` is `error` in `eslint-plugin-react-hooks` 7's recommended set, which `frontend/eslint.config.js:19` uses.
  - What is left is the queue's own answer. The queue already "takes the text back" on a locked refusal (`draft-queue.ts:563-585`); the take-back now reaches the text on screen. A second editor on `useAutosave` then gets the lock by construction (ARCH-14: a page owns no state machine).
