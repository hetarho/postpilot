# T002 Give the write budget reasoning headroom and let the adapter disable reasoning
> st:done@260905 | ssot:MODEL-46 MODEL-47 MODEL-48 MODEL-7 MODEL-8 GEN-22 QUOTA-33 | base:MODEL@2 GEN@1 QUOTA@2 ARCH@1 | dep:T001

## goal
Stop native-effort reasoning models from spending the whole write budget thinking: multiply the write and revision budgets by a code-owned headroom when the resolved model reasons natively on effort, send `reasoning: {enabled: false}` where a model cannot take `none`, and surface reasoning-caused truncations on the curation screen (legacy change 29).

## acceptance
- [v] a write call to a model recorded as `reasoning_native_effort` is sent a completion budget larger than today's by the code-owned multiplier, still bounded by `Ceiling`
- [v] a write call to a model not recorded as native-effort is sent exactly the budget it is sent today
- [v] an observation call is sent exactly the budget it is sent today, for every model
- [v] a revision is sent the headroom-adjusted budget under the same native-effort condition, still derived from the larger of the existing content and the requested target
- [v] a post with no requested target is never sent less than `WriteFloor`
- [v] resolving effort `none` on a model whose recorded `reasoning_efforts` lacks `none` produces a body carrying `reasoning: {enabled: false}` and no `effort` key; on a model whose list contains `none` the body still carries `effort: "none"`
- [v] `reasoning.exclude` is absent from every request body, and a request with an unresolved effort still carries no `reasoning` key at all
- [v] a reasoning-caused truncation still fails the job with `MODEL_OUTPUT_TRUNCATED` and the unchanged user-facing message, and `technical_detail` still carries the reasoning/visible split
- [v] the 모델 관리 surface shows, per model and purpose, how many calls ended in a reasoning-caused truncation beside the reasoning spend it already shows
- [v] replaying the recorded 2026-09-04 08:56 failure shape (8 116 reasoning tokens against an 8 192 budget) against the new write budget leaves visible-output room rather than truncating (unit test)
- [v] ARCH-26 and ARCH-28 pass; the `internal/llm` boundary test still passes; frontend tests, lint and build pass for the admin surface change

## impl notes
- headroom constant lives beside `writeBudgetPerChar` and `writeBudgetCeilingFactor` in `backend/internal/platform/config` (`LLMCompletionBudget`); applied to write and revise only, never observe
- the registry must pass the resolved model's native-effort signal into the budget decision without leaking a catalog type across the `internal/llm` boundary (ARCH-9, MODEL-1): carry a plain boolean on the llm-side model info that the dynamic `ModelSource` fills from `catalog_models.reasoning_native_effort`
- `openaicompat.buildRequest` (`backend/internal/llm/openaicompat/client.go`) gains the disable path keyed on the model's recorded `reasoning_efforts`; keep `reasoning_format: openrouter` gating the nested object
- the truncation count is sourced from the ledger the way change 24's reasoning spend already is: extend the consumer-declared port the modelcatalog context reads through (it never reads `usage_events` directly), counting `MODEL_OUTPUT_TRUNCATED` rows whose technical detail names a reasoning split, per (model, stage) over the same recent window; the FE `manage-model-catalog` row shows it beside the spend
- must not change: automatic retry or in-app fallback (rejected), any user-facing copy or reason, the observation budget, `LLM_MAX_TOKENS_DEFAULT` and `WriteFloor`'s meaning, per-user effort selection, `reasoning.max_tokens` as a cap, the stage policy and override order
- T001 must already have landed so the raised budget is held for rather than absorbed at settlement (QUOTA-33)

## result

- Native-effort write and revision budgets now receive a code-owned 2× headroom, capped by the existing ceiling. The selected model's boolean is frozen into durable generation/revision payloads so admission pricing and delayed execution cannot drift; observation and non-native models retain their exact prior budgets.
- The registry carries the recorded effort vocabulary across the `internal/llm` boundary. OpenRouter serializes unsupported `none` as `reasoning: {enabled:false}`, preserves supported `effort:"none"`, and continues to omit both unresolved reasoning and `exclude`.
- Migration 0025 records a non-sensitive reasoning-truncation flag in the usage ledger. Its per-model/per-stage aggregate crosses the modelcatalog consumer port and is shown beside recent reasoning spend in the Korean and English admin UI.
- Regression coverage fixes the 8,116/8,192 incident, payload freezing, matching credit holds, request body shapes, ledger persistence/aggregation and per-purpose UI counts. The unchanged truncation failure contract remains covered.
- All ARCH gates pass on Node 24.18.0: 988 frontend tests, frontend lint/FSD/style/build, complete backend and agent gofmt/vet/build/test, proto/SQL regeneration, and the spec checker.
