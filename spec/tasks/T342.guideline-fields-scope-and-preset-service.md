# T342 Guidelines scoped by 분야, the 상위 노출 단어 사용 preset, and 분야-aware freezing
> st:todo | ssot:GUIDE-5 GUIDE-14 GUIDE-15 GUIDE-17 GUIDE-29 GUIDE-30 GUIDE-31 GUIDE-32 GUIDE-33 GUIDE-34 GUIDE-36 GUIDE-37 GUIDE-38 GUIDE-39 GEN-57 ARCH-3 ARCH-40 ARCH-24 | base:GUIDE@5 GEN@10 ARCH@9 | dep:T332 T337 T330

## goal
- An owner can scope a guideline to 분야 and switch the product's 상위 노출 단어 사용 preset on per 분야, and every generation, revision and write-experiment snapshot freezes the global, template and 분야 texts in that order with the preset line last, which a revision never carries.

## acceptance
- [ ] CreateGuideline and UpdateGuideline accept `GUIDELINE_SCOPE_FIELDS` with ≥ 1 known 분야 and no template ids; `global` carrying template ids or 분야, `templates` carrying 분야 or no template, and `fields` carrying template ids or no 분야 are all `GUIDELINE_SCOPE_INVALID`; UNSPECIFIED stays refused.
- [ ] An unknown 분야 id, or a `BLOG_FIELD_UNSPECIFIED` element, is NotFound `GUIDELINE_FIELD_NOT_FOUND` and nothing is written; duplicate 분야 in one request collapse to one link in first-seen order.
- [ ] A scope patch moving a guideline between `templates` and `fields` replaces the kind and both link sets in one transaction; a text-only update leaves the 분야 set untouched; deleting a guideline removes its 분야 links.
- [ ] ListGuidelines answers the owner's guidelines in injection order (global, templates, fields; each `created_at, id`) with each one's `fields`, plus `preset` = {text: the constant, enabled, fields}; an account that never touched the preset reads `enabled=false` with no 분야.
- [ ] UpdateGuidelinePreset is a presence patch: absent `enabled` keeps it, absent `fields` keeps the set, a present `fields` replaces the whole set (present-and-empty clears); an unknown 분야 is refused with nothing applied; the answer is the resulting preset; no `guidelines` row is created, counted or changed.
- [ ] ForPrompt returns global → template → 분야 texts and appends the preset text LAST only when the preset is enabled, the post's 분야 is in its set, and the call is not for a revision; switched on with no 분야 it reaches no post; a post with no 분야 never receives it.
- [ ] The preset is outside the cap and the text uniqueness: an account at `GUIDELINE_MAX_PER_ACCOUNT` with the preset on is refused at exactly the same count, and an owner guideline whose text equals the preset text is accepted.
- [ ] Start and SnapshotWriteInput freeze with the post's 분야 and `forRevision=false`; StartRevision freezes with its 분야 and `forRevision=true`; handlers read only the payload, so enabling, disabling or re-picking after the start changes nothing in flight.
- [ ] An account with no 분야 guideline and the preset never enabled freezes exactly the texts it froze before this task, so its payload, snapshot hash and prompt bytes are unchanged (GUIDE-34).
- [ ] Nothing but the owner's GuidelineService procedures writes `guidelines` rows, and the preset never appears as one (GUIDE-33).
- [ ] Tests: `internal/guideline/service_test.go` (shape refusals for all three kinds; fields create with collapse and an unknown 분야 writing nothing; rescope templates↔fields as one normalized patch; preset patch presence and 분야 validation; ForPrompt with the preset off, on with no 분야, on for another 분야, on for the post's 분야 appended after an owner 분야 guideline, for a revision, and with no 분야 never reading the preset; the cap unchanged with the preset on; an owner text equal to `PresetText` accepted; NewService panics without a field directory); `internal/guideline/rpc/handler_test.go` (GuidelineScope walk both ways, fields and preset projection, UpdateGuidelinePreset presence mapping and `GUIDELINE_FIELD_NOT_FOUND`); `internal/generation/guideline_test.go` (the field and the revision flag each entry point asks with, the experiment snapshot freezing one set for both candidates); `cmd/api/bootstrap_test.go` (real wiring below); `cmd/api/boundary_test.go` (GUIDE-33).
- [ ] Verify: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test -timeout 30m ./...`
