# T133 Retain and reuse private clip originals for 24 hours
> st:todo | ssot:CLIP-2 CLIP-21 CLIP-22 CLIP-23 CLIP-24 CLIP-26 CLIP-34 CLIP-47 CLIP-50 CLIP-57 CLIP-73 CLIP-74 CLIP-82 ARCH-3 ARCH-6 ARCH-7 ARCH-10 ARCH-11 ARCH-13 ARCH-21 ARCH-24 | base:CLIP@12 ARCH@2 | dep:T126

## goal
Make unfinalized originals reusable for preview and retry across completed attempts and browser sessions until their 24-hour deadline.

## acceptance
- [ ] Generation success, failure and manual rerender release worker files but preserve matching private originals; a reload or reopened project reuses them without another upload.
- [ ] Source confirmation, actual settings/plan changes, accepted starts and active-attempt termination renew retention to 24 hours; reads, polling, playback, downloads, no-op saves and repeated terminal cleanup do not renew it.
- [ ] Expiry denies new access/attempts without deleting pixels in active use; a permanent project cleanup fence takes precedence over renewal and survives storage errors/restart, with finalization invoking that same contract in T135.
- [ ] Authorized source playback uses bounded-lived private URLs with correct content types and range support; foreign IDs, stale selections, expired objects and deletion fences cannot yield new URLs or start jobs.
- [ ] The upload/source access model rehydrates retained manifests, keeps local previews after terminal work while mounted, releases URLs on replacement/unmount and explains retention/expiry before selection and beside the source workspace.
- [ ] Store/RPC/worker/browser tests cover a fake-clock expiry boundary, an attempt spanning expiry, repeated recovery, partial uploads, missing objects, retry on the same batch, source replacement, delete/renew races, foreign ownership and stale signed URLs without fetching whole originals into API memory.
- [ ] Run applicable ARCH-25 through ARCH-29 local gates, deterministic proto/SQL generation and spec lint; preserve unrelated generated changes using a before/after snapshot.

## impl notes
- Replace unconditional Finish → cleanup_pending in backend/internal/clip/sources.go and store/sources.go with ReleaseAttempt(job ID, terminal timestamp) after the worker's durable terminal write or recovery. Generation/rerender handler defers clean local analysis/workspace files only; they cannot release a durable source binding while its job is still active. Persist the release once so a sweeper retry cannot extend the deadline repeatedly.
- Introduce clip-owned clip_source_attempts keyed by job ID with owner/project/batch, immutable source manifest identity, bound_at and released_at; keep batch object identities reusable across attempts rather than overwriting their sole job_id. Backfill existing links, preserve old lookup compatibility during migration and adapt quote consumption/LatestAttempt to use the attempt linkage.
- Keep originals immutable under conditional PUT. A new source selection creates a new manifest; replacing a selection never mutates an in-flight binding or deletes media still referenced by the current saved plan/previous successful result. Retain still-live manifests until their deadline, explicit discard when unused, or project cleanup; enforce existing per-selection source/count/byte bounds and fail closed on orphan enumeration failure.
- Persist source_retention_expires_at and nullable source_access_revoked_at on clip_projects plus batch/source availability sufficient to distinguish uploading, available, active, expired, missing and cleanup-pending; renewal updates only confirmed objects still eligible at the time of the mutation. An active binding remains eligible for its first terminal release even across the wall-clock deadline, but a permanently revoked/expired unprotected object is never revived by text saves or cleanup retries. Successful reselection establishes new object leases while preserving canonical source IDs/fingerprints used by a matching retained plan.
- The verified-original retention duration is a code-owned 24-hour policy passed through typed source configuration and published as an expiry instant. Existing CLIP_SOURCE_BATCH_TTL remains an incomplete-upload bound, with comments/config tests clarifying that unconfirmed objects follow it while individually confirmed originals follow the retention deadline; do not let the current 6h default shorten confirmed-original retention. Update both env examples when clarifying that operational bound; no frontend duration literal.
- A changed accepted project/plan save extends only live confirmed originals; an accepted attempt protects its immutable binding, and its first terminal release extends those originals to terminal time + 24h unless deletion/finalization is already fenced. Boot recovery uses the durable terminal time. Never extend on Get/List, signed URL creation, update polling or idempotent confirmation replay.
- Add owner-scoped GetClipSources(project_id) for the byte-free reusable manifest/availability/expiry and GetClipSourcePlayback(project_id, source_id, expected_fingerprint) for a temporary URL and its expiry. The latter checks ownership, current retained identity, deletion/finalization fence, deadline and object existence; use min(5 minutes, remaining retention) and decline a nonpositive duration. Keep signed links out of persisted entities, logs and job payloads.
- Add the signed GET implementation through the clip-owned ObjectStore port in storage/clip.go, preserving each allowed original container's Content-Type and browser range playback. Reads stream directly from private storage; do not proxy full video bodies through unary RPC or persist playback URLs in query caches/storage beyond the session.
- Rehydrate features/upload-clip-sources through entities/clip-project adapters and expose local-or-retained source access for T130; local matching object URLs take precedence. Handle URL expiry once by refreshing the capability and re-seeking, with typed unavailable state after retention expiry; never loop retries or silently select another file.
- Cleanup identities outlive project metadata using the existing deletion queue; the sweeper checks all active bindings before deleting. A still-valid PUT URL can recreate a deleted key, so retain its tombstone until the last issued PUT expires and repeat object deletion after that bound. Finalization's immediate access fence and result preservation are completed by T135.
