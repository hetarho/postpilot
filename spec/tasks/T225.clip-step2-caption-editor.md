# T225 ② places captions over their own cut frame
> st:todo | ssot:CLIP-143 CLIP-17 CDS-82 | base:CLIP@32 CDS@21 | dep:T221 T222

## goal
Turn the caption track into an editor where each caption is dragged, resized and restyled over a frame of the cut it starts in.

## acceptance
- [ ] selecting a caption shows it over a still frame of the cut its interval starts in, drawn from matching local media or an unexpired retained original
- [ ] dragging moves the caption and it stops at the safe area edge, which is drawn while dragging; both pointer drag and arrow-key nudging work
- [ ] resizing is refused below the role's floor at the control, and the style is changed from the project's allowed set
- [ ] a placement under the contrast floor shows the caption's warning in place without blocking 다시 렌더
- [ ] with no source media the editor still edits text, timing, size and style over a neutral ground and says why the frame is missing (→CLIP-57)
- [ ] every change rides the existing draft queue and undo/redo, and 다시 렌더 stays blocked only by the existing overlap and out-of-output rules
- [ ] vitest covers clamping at an edge, the floor refusal, the missing-frame state and keyboard placement
- [ ] ARCH-25 passes

## impl notes
- the frame is captured in the browser by seeking a `<video>` to the cut's start and drawing one frame to a canvas ← the originals are already local or authorised for playback here (→CLIP-50) and a server-side extract would add a round trip and a stored artefact for something transient
- the caption is positioned with one CSS transform over the served fragment (→T222), so a drag never re-fetches
- dragging updates local state and flushes on release, not per pointer event ← the draft queue is a save path, not an animation loop
