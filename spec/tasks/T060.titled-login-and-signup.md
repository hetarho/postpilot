# T060 Titled login and signup screens with password confirmation
> st:todo | ssot:AUTH-30 AUTH-42 AUTH-43 | base:AUTH@5 | dep:-

## goal
`/login` and `/signup` each name themselves as the page heading, lead to each other through a question-and-answer sentence, and signup asks for the password twice and refuses a mismatch before any request.

## acceptance
- [ ] `/login` renders an `h1` reading 로그인 / Log in under the logo lockup; `/signup` renders an `h1` reading 회원가입 / Sign up; the lockup itself is no longer the heading
- [ ] below the Google button, `/login` shows 계정이 없으세요? followed by the 회원가입 link and `/signup` shows 이미 계정이 있으세요? followed by the 로그인 link; the link's accessible name stays the bare verb, its `href` and `redirect` search behaviour unchanged
- [ ] `/signup` has a third field 비밀번호 확인 / Confirm password (`autoComplete="new-password"`); submitting with a mismatch shows a localized alert, marks both password fields invalid and issues no `Signup` call; matching passwords submit exactly as before
- [ ] 비밀번호 찾기 / Forgot password and the About link keep their place and names on `/login`
- [ ] tests: `SignupPage.test.tsx` gains the heading, the sentence link, the mismatch (no RPC, alert) and the matching-submit cases; a new `pages/login/ui/LoginPage.test.tsx` pins the heading, the sentence link and the untouched link row; `router.test.tsx` and every existing `name: '로그인' | '회원가입'` assertion still pass
- [ ] ARCH-25 gates green: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- heading: the title is a `Typography variant="display" as="h1"` with an `id` the page section points at through `aria-labelledby`, the pattern `ForgotPasswordPage` already uses; the logo lockup (`favicon.svg` + `Logo`) stays above it as a plain `div` — one `h1` per page, and the visible word is what a screen reader announces
- signup's mailed state keeps its own `h2` 메일을 확인해 주세요 under the 회원가입 `h1` ← the visitor is still on the sign-up path, unlike forgot-password whose sent state replaces the heading
- copy: new i18n keys in `app/providers/i18n/resources/{ko,en}/auth.ts` — `login.heading` 로그인 / Log in · `signup.heading` 회원가입 / Sign up · `links.noAccount` 계정이 없으세요? / No account yet? · `links.haveAccount` 이미 계정이 있으세요? / Already have an account? · `field.passwordConfirm` 비밀번호 확인 / Confirm password · `signup.passwordMismatch` 비밀번호가 서로 달라요 / The passwords do not match; `login.id` stays 이메일 또는 아이디 ← operator accounts log in with a non-email id (AUTH-40)
- sentence link: a `<p>` of `Typography variant="label"` text followed by the existing `Link` — no `Trans` interpolation ← the link's accessible name must stay the bare verb so the router and page tests keep matching on it; the row keeps the `nav` with its `links.more` label and, on `/login`, the forgot-password and About links beside the sentence
- mismatch: checked in `onSubmit` before `signup.mutate`, held in local state, rendered through the existing `Notice tone="danger" role="alert"` slot with `aria-invalid` + `aria-describedby` on both password fields, cleared when either field changes; no HTML5 `pattern` or `setCustomValidity` ← the message must be localized copy from i18next, and a native bubble cannot be
- both password fields keep `minLength={8} maxLength={128} required`; the hint stays under the first
- AUTH-43 needs no code: `GOOGLE_CLIENT_ID/SECRET` pairing, `VITE_GOOGLE_CLIENT_ID` gating and DEPLOY.md rows already exist — the owner registers the OAuth client and sets the env on the VPS `.env` and the Cloudflare build variables (STATE next)
