## goal
Persist current-result origins and preserve them through manual edits.

## acceptance
- [ ] Store origin review as a versioned result-related sidecar tied to content revision/hash, preserving exact frozen evidence and keeping canonical prose/baseline free of presentation metadata. Legacy rows stay usable with unconfirmed origin and no inferred backfill.
- [ ] Machine generation/revision and compatible source application atomically publish matching content/plan/origins under existing ownership/CAS/idempotency/lifecycle fences; malformed origins do not discard valid content or finalize implicitly.
- [ ] Manual content save preserves provably unchanged spans and known origins; punctuation/style edits, photo movement, plan selection/finalization never promote AI meaning. New explicit material is distinguishable; ambiguous replacement/reorder/duplicate matches become unconfirmed.
- [ ] Source removal makes evidence unavailable rather than retargeting it. Post/account deletion and current source/payload sweep remove related private evidence, and late callbacks cannot restore purged content.
- [ ] Owner read/save responses return the authoritative current revision and aligned review state, never another result or owner. Published read-only rules and original finalize/export readiness stay unchanged.
- [ ] Real SQLite store/API regressions cover legacy upgrade, revision races, unchanged/no-op edits, punctuation/new content, duplicate/reordered blocks, attachment deletion, machine baseline equality, lost receipt and purge; memory extraction still stores only explicit approved facts.
