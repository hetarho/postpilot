# T073 Clip media probe, analysis proxies and isolated workspaces
> st:todo | ssot:CLIP-6 CLIP-10 CLIP-21 CLIP-23 CLIP-26 CLIP-27 ARCH-21 ARCH-24 ARCH-32 ARCH-33 | base:CLIP@1 ARCH@2 | dep:T069

## goal
Provide a bounded, deterministic media adapter that verifies uploaded sources and prepares model-sized video chunks without making any model call or final render.

## acceptance
- [ ] a consumer-owned `clip.Media` port exposes probe, analysis-chunk preparation and workspace cleanup in domain types; `backend/internal/clip/media` implements it by invoking binaries with argument arrays, never a shell
- [ ] the production image contains pinned `ffmpeg` and `ffprobe` executables compatible with the distroless nonroot runtime; the dev image has the same major/minor behavior, and third-party versions, checksums and licenses are recorded
- [ ] `Probe` reports decoded duration, display width/height after rotation, streams, frame rate and audio presence and refuses a corrupt, unsupported or empty source before any LLM call
- [ ] manifest verification allows only the four T071 containers, enforces 1–20 files and 30 minutes against probed durations, and rejects a browser claim whose duration differs by more than one second or whose dimensions ignore rotation
- [ ] `PrepareAnalysisChunks` emits chronological MP4 proxies of at most 60 seconds each, with absolute source offsets, at most 720 px on the long edge, 30 fps H.264 video and AAC audio when present; a final short chunk is not padded
- [ ] the chunk count is exactly `sum(ceil(probedDuration/60s))`, so T076 can reserve one existing 30k-input hold per actual observation call without changing QUOTA-14
- [ ] every operation runs under a job-specific directory below one validated clip work root, uses bounded stderr in errors, obeys context cancellation and removes its directory on success, ordinary failure and panic
- [ ] boot cleanup removes only stale directories whose validated basename starts with `postpilot-clip-` beneath that work root; it never recursively targets the root, `/`, a home directory or an unresolved environment value
- [ ] a source and each proxy are processed sequentially so the adapter never holds the whole batch in memory and peak disk is bounded by the current source plus its current proxy
- [ ] unit tests use a fake command runner to pin arguments, cancellation and cleanup; a Docker media smoke test creates rotated, silent and audio fixtures, probes them and verifies 61 seconds becomes 60+1 second proxies
- [ ] ARCH-26 passes and `docker build -f backend/Dockerfile .` completes with the media smoke command green

## impl notes
- build FFmpeg from an official pinned source release in a dedicated Docker stage with only the decoders/encoders/muxers the accepted inputs and H.264/AAC MP4 outputs need; do not replace ARCH-32's distroless final image with a general Linux image
- source files reach the workspace through a streaming object-store download added in T076; this adapter accepts paths and has no R2 or signed-URL knowledge
- analysis proxies deliberately trade visual fidelity for bounded model context; they are transient derivatives and T076 deletes their object-store copies immediately after each observation
- keep the process runner behind a tiny interface so ordinary Go tests require no host FFmpeg; the Docker smoke is the one real-binary gate
