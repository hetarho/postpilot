# T026 The operator assigns a model to each estimator combo
> st:todo | ssot:QUOTA-39 QUOTA-25 | base:QUOTA@5 THEME@4 LANG@1 ARCH@2 | dep:T025

## goal
Add a 편수 기준 조합 section to `/admin`'s 모델 관리 tab where the operator picks the observe and write model for each of the four combos.

## acceptance
- [ ] the section lists the four combos in ladder order — 품질 · 균형 · 가성비 · 최저가 (en: Quality · Balanced · Value · Cheapest) — each with two labelled `Listbox`es, 사진 분석 and 글 작성, whose options are the models registered to `photo-analysis` and `writing` respectively (never a native `<select>`, THEME-29)
- [ ] choosing a model calls `SetEstimatorCombo` with both refs and reports the outcome where the operator is looking: a pending state in place, and a server refusal (`MODEL_NOT_REGISTERED`, `COMBO_UNKNOWN`) as a localized `Notice` rather than raw transport prose
- [ ] an unassigned combo renders both pickers empty with one line saying that plan comparison shows no estimate for it until both are chosen
- [ ] a combo assigned to a model that is no longer registered renders the ref as a greyed value with the same line, and choosing again clears it ← the operator must be able to see WHY the comparison dropped a combo
- [ ] a successful write invalidates the catalog query so the section and the model list agree without a reload
- [ ] i18n ko/en at full parity for every label, option name, empty line and failure message (LANG-7)
- [ ] `AdminModelsPage.test.tsx` covers: the four combos rendered with their pickers, a successful assignment carrying both refs, a refused assignment leaving the previous value and showing the notice, and the unassigned line
- [ ] `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` pass

## impl notes
- placement: a new `features/assign-estimator-combo` (a verb, ARCH-14) composed by `pages/admin/ui/AdminModelsPage.tsx`, which stays composition only
- the mutation lives beside the feature in its `api` segment and invalidates the catalog key the models tab already uses; the combo assignments arrive on `ListCatalogResponse` (T025), so there is no second read to keep in step
- both pickers write together in one call: the RPC takes a complete assignment, so a half-chosen combo is a client state that has not been sent yet rather than a row with one ref
- the combo names are copy, not data — the four keys are fixed by the contract's enum and the labels live in i18n, so a renamed label never changes what the server stores
- no THEME exception applies here: this is an operator surface, not a promotional one, so it stays on the ordinary field and row vocabulary
