# T045 The commit fence: arming, one activation, and readback through the post-view URL
> st:todo | ssot:PUB-22 PUB-15 PUB-20 PUB-14 PUB-13 | base:PUB@4 ARCH@2 | dep:T044 T043

## goal
Arm exactly one final control against a still-current observation, send exactly one activation that can never repeat, and verify the published post by reading it through the account's own post-view URL.

## acceptance
- [ ] `ArmFinal` observes the same bound target, requires the arming token to still equal a current observation, and returns exactly one control whose accessible name is in the versioned allowlist; it matches on `data-testid="seOnePublishBtn"` rather than on the hashed class, and a scheduled (`nowTimeRadioBtn` / `preTimeRadioBtn`), generic, renamed or duplicate publish-like control returns a count that refuses to arm
- [ ] `ActivateFinal` sends exactly one low-level activation with automatic retry disabled; the port sets an `activated` latch BEFORE the call is issued, so a second `ActivateFinal`, or any `Apply` or `ArmFinal` after it, returns a `PortError` from the port itself and not only from the publisher
- [ ] `Readback` navigates the same bound target to `https://blog.naver.com/PostView.naver?blogId=<paired blog>&logNo=<numeric id>`, where the numeric id is taken from the permalink the editor itself reached after activation, and reads the post from that document: title at `.se-module-text.se-title-text`, the block sequence from `.se-component.se-*` in order, images including those grouped into a `se-imageStrip`, captions at `.se-module-text.se-caption`, tags at `.__se-hash-tag` inside `.wrap_tag`, and the category at `.category_title`
- [ ] `Readback` returns the CANONICAL permalink `https://blog.naver.com/<blog-id>/<numeric-id>` as the verified URL even though it observed the post-view URL, and `validateReadback` accepts that pair while still rejecting a post for another account, a non-numeric post id, a foreign host, a different bound target, or a body that drifted from the frozen snapshot
- [ ] visibility is carried from the verified pre-fence snapshot rather than re-observed, since the published post does not render it (PUB-15)
- [ ] a process death simulated before the fence requeues the job, and one simulated after the activation yields `outcome_unknown` with no second activation and no automatic retry (PUB-15)
- [ ] the reporter records `filling_settings` before `committing` and the stage sequence is monotonic through `committing → verifying → published` (PUB-13)
- [ ] against a fake CDP editor and a fake post-view document, table-driven tests cover: an arming token that no longer matches; a duplicate and a renamed final control; a scheduled control offered beside the immediate one; a second activation attempt; an `Apply` after activation; a readback for another account, a non-numeric id, a foreign host and a different target; a readback whose title, block order, image count, caption, tag order or category drifted; an image count that matches only when strip-grouped images are counted; and the two process-death simulations
- [ ] ARCH-27 passes

## impl notes
- T019's `## survey` item 3 is the whole basis for the readback design: the permalink `blog.naver.com/<id>/<logNo>` is a frameset whose iframe is built by JavaScript, so nothing static matches there, while `PostView.naver?blogId=&logNo=` serves the same post in the bound page's OWN top-level document in the editor's own `.se-component` vocabulary. That is why PUB-20 r4 states the observation URL and the reported URL differ, and why no frame-scoped method joins the driver surface
- a real published post on the owner's blog was observed with one `se-documentTitle`, nine `se-text`, eight `se-image`, one `se-imageStrip` and one `se-placesMap`; `se-imageStrip` is a grouped image row the editor vocabulary does not have, so the readback's image count must count images inside strips too or an eight-photo post will read back short
- `observe()` requires the URL to start with `PostWriteForm.naver`, so readback needs its own observation path with its own URL predicate; do not relax `observe()`
- `ActivateFinal` is one `Input` activation on the armed control: no loop, no fallback, no coordinate path and no retry wrapper anywhere in its call chain. An ambiguous outcome after it is the designed result
- the latch must be set before the call is issued, not after it returns, because a crash inside the call is exactly the case PUB-15 turns into `outcome_unknown`
- the owner's queued job `0182794e…` (`20260905-test`) is a live queued fixture, not a test target. No live publication happens in this task; that is T008's explicitly authorized smoke
