- Digest test design:
  - `measureDigests := map[int]struct{ corpus, output string }`, with one comment per row naming what changed. Row 1: "before T364: emoji tails stayed on tokens". Row 2: "T364: variation selectors, ZWJ, format runes and keycaps trim at 어절 edges".
  - `corpus` = hex sha256 of the raw `corpus.json` bytes.
  - `output` = hex sha256 of `json.Marshal` of `[]struct{ Name string \`json:"name"\`; Self measuredSelf \`json:"self"\` }`, in corpus order.
  - `measuredSelf` is a test-local struct with json tags: `share`, `title_relevance`, `char_count`, `photo_count`, `distinct_block_types`, `avg_sentence_length`. Nil pointers encode as null. `encoding/json` float formatting is deterministic.
  - Deliberately excluded: `Repetition.TopNoun` ← it is dead (F16) and T370 removes it, so the projection covers exactly the stored numbers the aggregate reads, and T370 needs no bump.
- Assertions and their messages:
  - Row missing: "MeasureVersion N has no digest row: add N: {corpus: C, output: O}".
  - Corpus differs from row N: "testdata/measure/corpus.json changed: re-pin row N as {corpus: C, output: O} — only if this diff leaves MeasureSelf's code unchanged; otherwise bump MeasureVersion and add a row".
  - Output differs: "MeasureSelf's answer changed while MeasureVersion is still N (stored rows of this version would never be recomputed and published posts never change revision): bump MeasureVersion to N+1 and add N+1: {corpus: C, output: O}".
  - Also assert the output digests of all rows are pairwise distinct ← a bump the corpus cannot see is a bump with no evidence, so extend the corpus in the same change.
- Corpus format, a JSON array of `{name, language: "ko"|"en", nouns: [...], title, blocks: [{type, content, file, items}]}` (the four fields of `quality.Block`):
  - The test maps each entry to `Sample{Slug: name, Doc: Document{…}, Language, Nouns}` and calls `MeasureSelf`.
  - `quality.Document` has no JSON tags (ARCH-7), so the test owns the fixture struct.
  - `type` uses the quality BlockType spellings (`TEXT HEADING IMAGE VIDEO QUOTE LIST`).
- Corpus entries, enough to move every stored number:
  - Korean reviews with headings, lists and quotes, and nouns that repeat (감자탕 ×3, a prefix pair 감자/감자탕)
  - a title naming none of the nouns (relevance absent)
  - nouns empty and nil (M3 absent)
  - a body whose only TEXT is a `{{slot:1}}` token
  - IMAGE with and without `file`, VIDEO blocks
  - NFD-decomposed Hangul
  - English posts with case-varied nouns and multi-sentence TEXT

  - emoji-tailed Korean nouns in the body (`감자탕❤️`, `라떼☕️`, `추천1️⃣`)
  - a ZWJ family 👨‍👩‍👧, a flag 🇰🇷, a skin tone 👍🏻, ZWSP and BOM at word edges
  - one long post (~1,500 chars)
- The rune set. text.go:26 `edgeRune(r)` becomes `unicode.IsPunct(r) || unicode.IsSymbol(r) || unicode.Is(unicode.Variation_Selector, r) || unicode.Is(unicode.Cf, r) || unicode.Is(unicode.Me, r)`. Measured on Go 1.26:
  - `IsSymbol` already covers ❤ ☕ 😀 (So), 🏻 (Sk) and regional indicators (So).
  - Variation selectors: U+FE0F is Mn, so today it survives.
  - Cf: ZWJ U+200D, emoji tag runes U+E0020–E007F, ZWSP U+200B, BOM U+FEFF and the soft hyphen are all Cf.
  - Me: U+20E3 and the other enclosing marks.
  - None of these classes holds a letter, a digit or a Hangul rune. Hangul syllables and the Hangul filler U+3164 are Lo. Other Mn/Mc marks stay, so an accent NFC could not compose is never cut.
- Keycaps (`1️⃣` = digit + U+FE0F + U+20E3): trimming runes one at a time would leave the digit (`추천1️⃣` → `추천1`). Replace `strings.TrimFunc(field, edgeRune)` in `Tokens` with `trimEdges(field string) string`:
  - It works on `[]rune`. From the left, each step first drops a whole keycap sequence (`[0-9#*]`, then an optional U+FE0F, then U+20E3); otherwise it drops one `edgeRune`; it stops at anything else. From the right it does the mirror image.
  - Keycap first on both sides, so `#️⃣맛집` loses `#️⃣` whole instead of stopping at a bare U+20E3.
  - Update the `Tokens` doc comment accordingly.
- `TestTokensTrimEmojiAtTheEdges` cases, all verified with a scratch run of this exact algorithm:
