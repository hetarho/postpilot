# T078 Manual clip-plan save and credit-free rerender

## goal
Persist validated manual cut/copy/audio corrections and rerender them as a durable job that creates no LLM call, hold or credit charge.

## acceptance
- [ ] `clip.proto` adds optimistic `SaveClipEditPlan` and `StartClipRender`; the save carries expected edit-plan revision, the render carries that revision plus one ready source-batch id, and both remain owner-scoped
- [ ] save accepts reorder/delete, source start/end changes, exact copy/timing changes, approved position/style/accent changes and volume 0.0–1.0 while keeping ratio immutable
- [ ] server validation requires at least one cut, every cut inside its retained source duration, captions inside the cut, only retained source fingerprints, a final 15–90 second timeline and every T074 renderer invariant; invalid input changes nothing
- [ ] a successful save increments `edit_plan_revision` and leaves the current result and `rendered_plan_revision` untouched, so an edited-but-not-rendered state survives reload
- [ ] `StartClipRender` requires a ready batch containing exactly the source fingerprints the corrected plan still references, freezes the plan/revision and links the batch to a new `render_clip` job; unrelated sources are refused and unused original sources need not be reselected
- [ ] `job.NewJob` gains an explicit non-metered admission mode used only by `render_clip`: it rejects any planned LLM call, skips Hold/Settle entirely and leaves every existing job kind's admission behavior byte-for-byte unchanged
- [ ] the handler probes selected files, renders the frozen plan through T074, uploads a new result, atomically swaps result metadata and `rendered_plan_revision`, and queues the prior key for outbox deletion
- [ ] a newer plan revision, active job, missing/mismatched source or expired batch is refused before render; a failed render preserves the previous result and saved corrections and exposes a retryable durable failure
- [ ] source cleanup runs on success, failure, cancellation, panic and boot recovery exactly as in T076; no source key is copied into project columns
- [ ] deleting a project with no active job removes even an unrendered corrected plan and queues its current result; a busy project remains `CLIP_BUSY`
- [ ] service/job/store/RPC tests cover optimistic conflict, every plan mutation, source-subset matching, no admission/usage rows, result preservation, revision swap, cleanup retry and owner isolation
- [ ] ARCH-26 and ARCH-28 pass

## impl notes
- represent volume on the wire and in persisted JSON as integer thousandths (`0..1000`), mapping to FFmpeg's float only at T074's boundary; this avoids unstable JSON float equality in optimistic saves
- save the complete plan as one guarded JSON document: cut order, caption timing and total length are one invariant and cannot be correct under per-row partial writes
- non-metered is a queue input, not a new QUOTA rule; the queue has no hold to settle because this job makes zero provider calls, satisfying CLIP-20 without teaching the credit ledger about render cost
- disallow plan saves during an active clip job so the frozen revision and the screen never diverge; the client keeps local edits and retries after the job ends
