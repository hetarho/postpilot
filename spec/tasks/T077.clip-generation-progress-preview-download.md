## goal
Complete the first-generation browser flow from a ready source batch through durable progress to a persistent preview and download.

## acceptance
- [ ] the clip project page composes T072's setup/source state with existing observe/write model selectors, lists only registered models, marks video input, and blocks start until the project, template answers, models and ready batch satisfy the server contract
- [ ] pressing `생성` calls `StartClipGeneration` once, releases local File/object-URL state after the server owns the batch, and polls the returned durable job through the existing generation-job entity
- [ ] one page-top progress region maps `prepare|analyze|plan|render|save|cleanup` to ko/en stage copy, uses numeric progress only in the bar, and never duplicates state in the action dock
- [ ] completion invalidates and reloads the project, then presents the latest result in a native `<video controls preload="metadata">` plus one attachment download action using the fresh server URL
- [ ] a reload with a saved result previews and downloads without any source video; a reload before start or retry asks for source reselection and never suggests that the originals were retained
- [ ] analysis/render failure leaves the prior video visible, renders the stable failure at the failed stage, and offers retry only after another source batch is ready
- [ ] insufficient credits reported by the durable prepare stage use the existing plan refusal presentation and link to `/plans`; manual preview/download show no credit estimate or charge language
- [ ] while a job runs, setup, template reassignment, delete and a second start are disabled client-side while the server remains authoritative with `CLIP_BUSY`
- [ ] project-list result state and project-detail job state remain consistent after back navigation, polling completion and cache invalidation
- [ ] tests cover one start under double-click, every stage label, completion refetch, previous-result-on-failure, insufficient credits, refresh/reselection, preview URL expiry refetch and ko/en topology
- [ ] ARCH-25 passes

## impl notes
- preparation starts before credit admission: poll its durable job immediately, and show an admission refusal from the job failure without assuming that a rejected hold means no job exists
- extend `entities/generation-job` only with the new target/stages; clip-specific start/cache behavior stays in `features/generate-clip`
- keep result URLs out of query persistence and browser storage; a failed media load invalidates the project once to obtain a new signed URL, then shows a normal failure
- the download control is an ordinary authenticated result URL from T076, never a fetched Blob assembled in browser memory
- do not add editing controls here; T079 owns the correction workspace after the first complete result
