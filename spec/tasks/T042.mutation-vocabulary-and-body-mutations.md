# T042 The r4 mutation vocabulary and the body mutations
> st:blocked@260908 | ssot:PUB-21 PUB-36 PUB-37 PUB-19 PUB-20 | base:PUB@4 ARCH@2 | dep:T018

## goal
Replace the r3 mutation vocabulary with r4's, reorder `Prepare`'s plan to body → photos → settings, and implement `Apply` for the five body kinds against the live SmartEditor's verified mechanics.

## acceptance
- [v] `MutationKind` drops `image_placeholder` and gains `open_settings`; the constant, its `Prepare` branch, its locator entry and every test that names it are gone, and no code path can emit it
- [v] `Prepare` plans in exactly this order: `title` → the body blocks in manifest order → `upload_image` per photo in ordinal order → `open_settings` → `tags` → `category` → `visibility`; a plan that puts any body or image mutation after `open_settings` is refused by a `Prepare`-level assertion, not only by the driver (PUB-37)
- [ ] `CDPPort.Apply` implements `title`, `text`, `heading`, `quote` and `list` as typed data only: it resolves the kind's versioned locator, requires exactly one match, reads that element's `getBoundingClientRect()` in the same reviewed script, dispatches one `Input.dispatchMouseEvent` press/release at it, discards the rect, and enters text with `Input.insertText`; no selector, script, coordinate, key sequence or native-dialog operation is accepted from the caller
- [ ] the caret rule is the paragraph's right edge, not its box centre: the click point is taken at 98 % of the resolved paragraph's own width so the caret lands at the text's end on a paragraph of any length, and a test on a long wrapped paragraph proves a centre click would have landed mid-text
- [ ] `heading` and `quote` convert the caret's paragraph through `button.se-text-format-toolbar-button` then `button.se-toolbar-option-text-format-{sectionTitle,quotation}-button`; `list` opens `button.se-list-bullet-toolbar-button` then `button.se-toolbar-option-list-{bullet,decimal}-button`; each asserts the caret's component kind before resolving the control, because the property toolbar carries the list control only while the caret sits in a text block
- [v] a second and later `text` block is appended by `Input.dispatchKeyEvent` Enter followed by `Input.insertText`, and the projection counts PARAGRAPHS rather than `.se-component.se-text` nodes, since Enter appends a paragraph inside the same component
- [v] `Publisher.mutate`'s post-condition still holds for every body kind: the snapshot token moves and the observed snapshot equals the expected one
- [ ] against a fake CDP editor, table-driven tests cover: each of the five kinds; a paragraph appended after another; a heading and a quote applied to the right paragraph; a list of three items; text that reads like a CSS selector, a `<script>`, a coordinate pair, a keystroke phrase or a setting label entering verbatim; a locator matching 0, 2 or a renamed control failing closed before the page is touched; and a mutation planned after `open_settings` being refused
- [v] ARCH-27 passes

## result
blocked 260908: the vocabulary, the plan order and its assertion, and the two body kinds whose
mechanics the survey actually verified are implemented, tested and green. `heading`, `quote` and
`list` are NOT, because the one fact they need was never observed and PUB-19 forbids guessing
it: **what the 문단 서식 변경 menu converts when the caret's text component holds more than one
paragraph.** Every conversion seen live on 260907 acted on a component with exactly one
paragraph and turned the whole component into `se-sectionTitle`. Prepare appends consecutive body
blocks as paragraphs INSIDE one `se-text` component, so the very first manifest of the shape
[TEXT, HEADING] reaches a two-paragraph component — and whether the menu then converts that
paragraph or the whole component decides whether the first block silently becomes a heading too.
A second live pass on 260908 could not answer it: the leftover scratch draft now holds an image
between its blocks, the caret would not settle from a resolved click, and
`button.se-text-format-toolbar-button` matched 0 while no editor selection existed.

shipped and verified:
- the r4 vocabulary: `image_placeholder` is gone from the constants, `mapBlock`, the manifest
  locators, the observation script, the probe and every test; `open_settings` replaces it;
  `reviewedMutationKinds` and `bodyMutationKinds` are now the single source of truth the
  manifest check, the observed locator counts and the probe all iterate
- `Prepare` builds the whole plan first and runs `assertPlanOrder` before touching the page, so

two real bugs found and fixed while implementing:
- `driverPointFn`'s `body_end` resolved `.se-component .se-module-text.__se-unit p.se-text-paragraph`
  under `.se-body.__se-body` — but the document TITLE is a `.se-component` inside that container
  and an image's caption is a paragraph too, so on an empty editor the caret would have landed in
  the title and body text would have been typed into it. It is now scoped to
  `.se-component.se-text`
- the same function aimed at each element's box CENTRE. A centre click lands at the text's end
  only while the text stops short of the centre; on a paragraph that fills or wraps its line it
  lands mid-text and the next insertion would split it. `caretEnd` now aims at 98 % of the
  paragraph's width on its last line
