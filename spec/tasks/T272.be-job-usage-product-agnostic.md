# T272 job and usage expose primitives; clip composes them
> st:blocked@260919 | ssot:ARCH-6 ARCH-11 ARCH-7 ARCH-24 | base:ARCH@5 | dep:T270

## goal
Remove every clip-specific method and type from `internal/job` and `internal/usage`, replace them with product-agnostic primitives, and move the clip compositions into `clip/app`.

## acceptance
- [ ] `internal/job` has no file or identifier containing `Clip`: `job/clip.go` and `ClipReservation ClipCall ClipGuard ClipStore ClipCancellationStore` are gone; `job.Queue` offers `Reserve(kind, subject, payload)`, `Activate(id)`, `SweepUnactivated(kind, ttl)`, `Guard(id, fn)`, `Snapshot(id)`, `AuthorizeDispatch(id)` keyed by job kind + opaque payload
- [ ] `job.Store.ActiveForPost/ActiveForVoice/ActiveModelExperiment` collapse into `ActiveFor(subjectKind, subjectID)`; `job` imports no `internal/llm`
- [ ] `usage/clip_pricing.go` is gone; `usage` exposes lot/ledger primitives and `clip/app` holds `ClipCredits`, `ClipAccounting`, `ClipReservation` as compositions
- [ ] the clip activations/reservations/sweeps/guards live in `clip/app` over the new primitives, with the moved tests passing
- [ ] behaviour unchanged: ARCH-26 passes and the clip release smoke runs once locally (ARCH-37) because reservation and cancellation are on the path

## impl notes
- from review/arch-260919 F15
- ARCH-6 r4: `job`/`usage` never name a product; ARCH-11's queue stays generic
- job kinds are already strings; the payload is the existing JSON blob — the primitive takes/returns it opaque and the consumer decodes
- `job/store` gains tests in T275, so keep its exported surface small here

## result
- blocked@260919: the impl notes do not decide three things the code forces, and each changes charge outcomes, so they are the owner's (create-task re-decomposition, not an implementer's guess):
  1. `jobs.clip_project_id` and `dispatch_ready` are columns: "job names no product" means a migration to a generic `subject_kind`/`subject_id` (and the 5 SQL queries + `job.Job`/`JobSummary`/proto projections that read them) — or the column stays and only the Go API goes generic. Decide which.
  2. `job.ReserveClip` (`job/clip.go:139-205`) is not a queue primitive: it validates the clip reservation policy (observe 8192 tokens inline-static, write 32768 text-only, two writing calls on one model, the cancellation policy version) before opening an allowance. The generic primitive is "open an allowance of (ref, budget)→count entries consumed at the LLM boundary, guarded by an admitter"; the policy validation moves to `clip/app`. Decide the shape of the allowance port (`job.Reserve(ctx, Start, Allowance)`?) and whether `ConsumeClipPolicy` stays in `job` as `ConsumeCall`.
  3. `usage.Hold/Settle` carry clip settlement rules (`chargedClipKind`, `boundedClipCharge`, `cancelledClipCharge`, cancellation-fee waiver at policy version 1, shadow charges; `service.go:211-283, 425-460, 565, 619`) and `ClipAccounting` is a SQL projection. Making usage product-agnostic needs a `SettlementPolicy` port per kind that reproduces today's charges exactly; the T270-era cmd/api race tests pin them, but the policy interface (inputs: confirmed micro-USD, ceiling, outcome, policy version → charge, fee, reason) must be decided first.
- What is not blocked and can be a smaller first task: `job.Store.ActiveForPost/ActiveForVoice/ActiveModelExperiment → ActiveFor(subjectKind, subjectID)` and dropping the `llm` import from `job/failure.go`/`worker.go` (diagnostics only) — neither touches money.
- Proposal: create-task splits T272 into T272a (job: allowance primitive + policy move to clip/app + `ActiveFor`), T272b (usage: `SettlementPolicy` port with the clip policy in `clip/app`, charge parity pinned by the existing cmd/api tests), T272c (schema: subject columns, only if 1 is decided as a migration)
