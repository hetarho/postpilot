## goal

## acceptance
- [ ] README.md links to DEPLOY.md, whose environment matrix and separate procedures cover (1) one server without GPU, (2) one server with NVIDIA GPU, and (3) one API server plus one NVIDIA GPU worker server; the current CPU VPS is explicitly the default.
- [ ] Each procedure names the services on each host, prerequisite setup, image tags, exact Compose file/service selections, complete per-host env examples, startup/update/health/log commands, resource limits, stop/drain and rollback; placeholders are identified and match implemented configuration.
- [ ] The split-host procedure preserves API/SQLite/Caddy on the VPS and explains private outbound worker connectivity, reachable artifact URLs, credentials, firewall/Tailscale setup, PC-off behavior and optional CPU-worker eligibility; no inbound public listener or API secrets are required on the friend's PC.
- [ ] GPU sections distinguish one-time driver/toolkit/device setup from later env/image/Compose changes and mark production acceleration as pending hardware validation and CLIP-163 approval; CPU operation on a GPU host and isolated GPU diagnostics have runnable instructions without implying that GPU acceleration is already approved.
- [ ] A separately tagged NVIDIA candidate image builds required FFmpeg support and compatible runtime dependencies; explicit GPU overrides exist for colocated and standalone worker layouts, and default CPU configuration never reserves a GPU or requires NVIDIA tooling.
- [ ] Bounded diagnostic/probe commands and representative synthetic fixture instructions are provided for a later hardware run, with result fields for device/driver/tool/asset versions, selected parameters, CPU/GPU times, resources and output differences; diagnostics cannot claim user jobs or publish a project result.
- [ ] Unit/config/build checks, CPU execution in the candidate image, missing-device failure behavior and rendered Compose configurations pass locally; reviewed guide commands/env names correspond to repository files and CLI options, and GPU execution is recorded as unverified rather than as a passing hardware test.
- [ ] Completion requires no production deployment, second-host provisioning, friend-PC access, live worker move or real-GPU benchmark; those steps appear only as later operator procedures, with no claim that documentation replaces the production GPU activation gate.
