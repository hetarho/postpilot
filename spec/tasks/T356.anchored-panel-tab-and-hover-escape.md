# T356 Tab moves through an anchored panel; a hover-opened panel closes on Escape
> st:todo | ssot:THEME-42 THEME-33 ARCH-20 | base:THEME@18 ARCH@9 | dep:T355

## goal
Every control in an `InlinePopover` panel can be reached from the keyboard and Tab leaves it past either end. A panel opened by hover closes on Escape and nothing around it closes. Anchored panels share one placement, one wiring and one focusable selector, and the quality entity's copied helpers become one.

- **THEME-42 Tab (F18)**: rewrite `InlinePopover`'s `onPanelKeyDown` (`InlinePopover.tsx:79-89`).
  - A non-Tab key goes to `disclosure.escape(event)`, as today.
  - On Tab:
    - `controls = focusablesIn(panelRef.current)`
    - `active = document.activeElement` (not `event.target`, see the Listbox case below)
    - past-the-end forward: `controls.length === 0 || active === controls.at(-1)`
    - past-the-start backward (Shift): `controls.length === 0 || active === controls[0] || active === panelRef.current`
  - Inside, neither edge: call `event.stopPropagation()` only, with no `preventDefault`. The native Tab then moves to the neighbouring control. The panel is portalled to the end of `body`, so the next or previous tabbable in DOM order is the neighbour. Stopping propagation keeps `Popover`'s document Tab trap from firing (its `onKeyDown`, the `!panelRef.current?.contains(activeElement)` clauses). That trap treats focus outside its own panel (`!panelRef.contains(active)`) as a reason to jump to its first or last control. The React handler on the portalled panel stops the native event at the portal container, as Escape already does (THEME-30).
  - Forward edge: `triggerRef.current?.focus()` synchronously, then `close(false)`. Do not `preventDefault` or `stopPropagation`. The native traversal continues from the trigger to the next page control. An ancestor trap (`Sheet`, `Popover`) also sees a target it owns, and wraps if the trigger is its last control. This is today's mechanism, kept.
  - Backward edge: `event.preventDefault()`, `event.stopPropagation()`, `triggerRef.current?.focus()`, `close(false)`. Focus lands ON the trigger. A disclosure's content follows its button in reading order, so the trigger comes right before the panel's first control ← if the native Shift+Tab ran from the trigger it would skip the mark the user opened. Propagation is stopped because a trap would otherwise see Shift+Tab on its own first control (the trigger) and wrap to its last.
  - A composite moved by arrows counts as one. Say so in a comment, no code: a `Listbox` inside the panel handles its own Tab first. `Listbox.tsx:154-163` focuses its trigger synchronously, and the React event then bubbles through the portal tree to this handler. `document.activeElement` is then the listbox trigger, so the edge test treats the whole listbox as that one control.
  - Update the component doc comment (`InlinePopover.tsx:43-46`): "Tab hands focus back to the trigger" becomes the THEME-42 rule.
  - Focus-in on open (`:70-77`) uses `focusablesIn(panelRef.current)[0] ?? panelRef.current`.
- **Toggletip needs no Tab rule**: its panel is `aria-hidden` plain text ("A tip with anything to press in it is an `InlinePopover`", `Toggletip.tsx:24`), and focus never enters it. The same holds for `ExplainedButton`'s bubble. THEME-42 has nothing to act on there, so add no Tab handler.
