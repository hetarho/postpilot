# T054 Every backend failure reason the browser can be handed
> st:todo | ssot:ARCH-24 ARCH-3 | base:ARCH@2 | dep:-

## goal
Register the three reasons the backend already emits but the browser cannot display, and add the gate that would have caught them.

## acceptance
- [ ] `BILLING_SELECTION_INVALID`, `COMBO_INCOMPLETE` and `COMBO_UNKNOWN` are registered in `appFailureSpecs` and carry a message in both the Korean and English error catalogs
- [ ] each message says what the person can do about it, matching the specificity of the handler that chose the reason
- [ ] a backend test pins the complete inventory of reason strings the API can return, so adding a reason without registering it fails a test rather than reaching a user as the generic unknown failure
- [ ] that inventory names, in its own doc comment, the browser file a new entry must also be added to
- [ ] the existing frontend check that both catalogs cover every registered failure still passes
- [ ] ARCH-26 and the frontend test suite pass

## impl notes
- from review/diff-260908 F8
- the defect: the three reasons are emitted at `billing/rpc/handler.go:154` and `auth/rpc/admin.go:113,119` but appear in neither `appFailureSpecs` nor `resources/{en,ko}/errors.ts`, so `appFailureFromConnect` cannot match them and the operator assigning an unknown combo, or a client quoting an unbillable tier, reads the catch-all copy instead
- the frontend gate is not broken, it is one-sided: `resources.test.ts` compares the two catalogs against `appFailureSpecs`, which only proves the browser agrees with itself. A reason missing from all three is invisible to it, which is exactly what happened
- so the missing half belongs on the Go side, where the reasons are actually created: one committed inventory the API's own tests assert against. Several rpc packages already pin their reason strings in tests (`auth/rpc/plan_test.go`, `provider/rpc/errors_test.go`), so this consolidates a habit rather than inventing a mechanism
- the proto carries no enum for these reasons, so a generated cross-language check is not available; a committed list plus a pointer in its comment is the honest gate at this stack's seam (ARCH-3 keeps the proto the only generated contract)
