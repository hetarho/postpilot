## goal
네이버 블로그 · 네이버 클립 · 인스타 클립 open straight onto their own history with no visible heading, their creation, templates, 지침 and 말투 in the T721 floating action menu, and the old history addresses replace themselves with the channel address.

- [ ] /naver-blog renders the post history (q/status filters in its own URL, paging, outage and empty states, scroll return) with no visible heading and an `sr-only` h1 naming 네이버 블로그; /naver-clip and /insta-clip render that channel's clip history the same way
- [ ] /posts?q=&status= replaces itself with /naver-blog carrying the same q/status; /clips?channel=instagram_clip&… with /insta-clip and the remaining filters; /clips without a valid channel with /naver-clip
- [ ] the blog menu: `+ 새 글` → [[글 템플릿 /templates, 글 지침 /guidelines, 말투 /voices], [새 글 쓰기 /posts/new]]; each clip channel: `+ 새 클립` → [[영상 템플릿 /video-templates?channel=, 영상 지침 /video-guidelines?channel=, 말투 /voices], [새 클립 만들기 /clips/new?channel=]]; 말투 carries the channel as its explicit `entry`, so /voices shows a contextual return to that channel

- [ ] ChannelPage, its test and its 기록/템플릿/지침 link list are gone; the empty history text points to the menu's creation item
- [ ] navigation hierarchy: /posts/$slug and /clips/$id have the channel as their only structural ancestor; no `posts`/`clips` location appears as an ancestor; Library links, DeletePostButton, the publishing redirect and scroll restoration target the channel path
- [ ] tests pass and cover the change: `pages/posts/ui/PostsPage.test.tsx` (no visible heading, filters on /naver-blog), `pages/clips/ui/ClipsPage.test.tsx` (channel from the route, filters on the channel path), `app/routes/router.test.tsx` (both redirects, menu items per channel, 말투 contextual return), `app/routes/navigation.test.tsx` and `navigation-hierarchy.test.tsx` (ancestors), `entities/post` and `entities/clip-project` navigation-context tests (legacy path normalization, history scroll return), `widgets/channel-actions` test (items and creation entry)

## impl notes
- Pages keep their components: route /naver-blog → `PostsPage` with `validateSearch: postsSearchSchema`; /naver-clip and /insta-clip → `NaverClipHistoryPage` / `InstaClipHistoryPage` exported from `pages/clips`, wrapping `ClipsPage` with a `channel` prop that replaces `narrowing.channel`. Each page's `narrow()` navigates to its own channel path with `replace: true`.
- Old addresses: keep `postsRoute` / `clipsRoute` objects with `beforeLoad` throwing `redirect({ …, replace: true })` so bookmarks work; update every in-app `to: '/posts'` / `to: '/clips'` link to the channel path.
- New widget `widgets/channel-actions` (`ChannelActions({ channel?: ClipChannel })`) builds the T721 `FloatingActionMenu` groups; pages/posts and pages/clips both render it, which FSD forbids between pages. Move the creation labels from `pages/channel/config/i18n.ts` into the widget's namespace and add 글 템플릿/글 지침/영상 템플릿/영상 지침/말투/menu labels (ko and en). Icons (lucide): `PenLine` creation, `LayoutTemplate` templates, `ListChecks` 지침, `MessageSquareQuote` 말투.
- 말투 href: `/voices?entry=<encodeURIComponent(channel path)>`; `AuthenticatedLayout` already reads `search.entry` through `navigationParent`, whose STABLE_PARENTS include the channel paths. If the /voices route's `validateSearch` drops `entry`, add it there.
- Post return model (`entities/post/lib/navigation-context.ts`): `PostEntry.path` becomes `'/naver-blog'`; history-opened entries keep `section: 'posts'` and the history scroll return keys on `section === 'posts'` instead of `path === '/posts'`; `readPostReturnContext` maps a stored `/posts` path to `/naver-blog` keeping filters. Same shape in `entities/clip-project/lib/navigation-context.ts`: `/clips` maps to `clipChannelPath(filters.channel)`; drop the `channel` filter from the returned href once the path carries it.
- `app/routes/navigation.ts`: `/posts` and `/clips` map to their channel location; post children always [NAVER_BLOG], clip children [clipHub]. Drop the `creationOrigin` branches that only chose between history and channel; keep the parameter only while a caller still needs it. Remove `/posts` and `/clips` from `app/model/navigation-entry.ts` STABLE_PARENTS (they redirect).
- Editor/clip return labels (`copy.home`/`copy.history` in DraftEditor and EditorPage, `navigation.returnHistory`/`returnCreation` in ClipPage) collapse to one label naming the channel.
- `pages/library` stays; its links point to /naver-blog and /naver-clip.
