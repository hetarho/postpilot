# T517 Keep a 학습 글 sheet open for the next entry
> st:todo | ssot:VOICE-65 VOICE-64 VOICE-60 VOICE-43 VOICE-55 | base:VOICE@6 THEME@21 | dep:- | touches:frontend/src/features/answer-voice-prompt frontend/src/features/paste-voice-material frontend/src/pages/voice

## goal
문항 풀기 and 글 붙여넣기 keep taking entries until the owner closes the sheet, instead of closing after each save.

## acceptance
- [ ] 문항 풀기: a saved answer keeps the sheet open on the next unanswered prompt in the served order after it, wrapping to the start, with a blank form (no text, no photo, no error)
- [ ] the prompt just saved is never offered again in the same sitting, even before the profile refetch lands
- [ ] `건너뛰기` opens that same next prompt without an AnswerVoicePrompt call, and is absent when no other unanswered prompt exists
- [ ] saving the last unanswered prompt shows the list with every prompt marked `답함` (disabled)
- [ ] `답을 저장했어요` is announced in a `role="status"` region after a save; the answer field of the next prompt has focus
- [ ] 글 붙여넣기: a saved post keeps the sheet open with both fields empty, `글을 추가했어요` in a `role="status"` region, focus on 제목 (선택), and the secondary action reads `닫기` instead of `취소`; a second post can be added in the same sitting
- [ ] a refused save (photo upload failure on a prompt, an AddVoiceSample rejection) keeps the same entry with its text and shows the reason, as today
- [ ] 검증's answer-one path (VoiceChecksPage → AnswerPromptForm) still saves one answer and returns to 검증, with no `건너뛰기`
- [ ] en strings exist for every new key (`Skip`, `Answer saved`, `Post added`)
- [ ] tests in `pages/voice/ui/VoiceMaterialsPage.test.tsx` cover: advance after a save, wrap-around, skip without a call, skip absent on the only unanswered prompt, list after the last one, the status lines, paste staying open for a second post with `닫기`, both refusal paths; `VoiceChecksPage.test.tsx` still passes unchanged
- [ ] ARCH-25 FE gates pass: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`
- [ ] rendered check at 320 and 1440 px in both themes: the three answer buttons (문항 목록 · 건너뛰기 · 답하기) wrap without overflow, the status line sits under the sheet title

## impl notes
- frontend only: no proto, RPC or backend change — AnswerVoicePrompt and AddVoiceSample already save one entry each, and the prompt set's served order (`voice.Prompts()`: openings, descriptions, closings) is the "set's order" VOICE-65 names
- `PromptsPanel` (features/answer-voice-prompt/ui/AnswerPromptsSheet.tsx) owns the run:
  - answered = the answer keys in `samples` ∪ a local `Set` of keys saved in this sitting ← the save resolves before the profile refetch, and without the local set the just-saved prompt would be offered next
  - `nextAfter(key)` walks `prompts` from the index after `key`, wrapping, and returns the first prompt that is not answered and not `key` itself, or `null`
  - on a save: add the key to the local set, set the saved status, `setChosen(nextAfter(key))` (null shows the list)
  - `AnswerForm` is rendered with `key={chosen.key}` so each prompt mounts a fresh form: body, photo, upload flags and the mutation's error all reset without manual clearing
- `AnswerForm` keeps `onDone: () => void` (the 검증 caller stays as is) and gains two optional props:
  - `onSkip?: () => void` — renders a `ghost` `건너뛰기` between `문항 목록` and `답하기`, disabled while pending; the panel passes it only when `nextAfter(chosen.key)` is non-null
  - `focusOnMount?: boolean` — focuses the answer `Textarea` (it forwards its ref) in a mount effect; the panel passes it, 검증 does not ← the list row that opened the form unmounts with the list, so focus would otherwise fall to the body; a mount effect, not `autoFocus`, so the Sheet's own focus setup (its effect depends on `open` only) is not fought
- status line: one always-rendered `<Typography variant="meta" as="p" role="status">` under the sheet title in each panel, empty at rest ← a live region present before its text changes is announced reliably; it holds `prompts.saved` / `paste.added` from a save until the owner's next action (typing in a field, 건너뛰기, 문항 목록, picking a prompt from the list) — no timer
- `PastePanel` (features/paste-voice-material/ui/PasteMaterialSheet.tsx): on success reset `label` and `body`, increment an `added` count, set the status, focus the 제목 field (TextField forwards its ref); the secondary button reads `t('action.close', { ns: 'common' })` once `added > 0`, `action.cancel` before; the Sheet's onClose stays blocked while pending
- closing a sheet mid-entry discards the unsaved text as today; nothing is persisted as a draft
- i18n (voices namespace, each slice's own fragment): `prompts.skip` 건너뛰기 / Skip, `prompts.saved` 답을 저장했어요 / Answer saved, `paste.added` 글을 추가했어요 / Post added; no other copy, no help line (owner keeps simple controls to their name)
- update the existing materials tests that expect the sheet to close after a save; the fake serves four prompts (`opening_greeting`, `photo_food`, `situation_value`, `closing_greeting`), so answering `closing_greeting` exercises the wrap to `opening_greeting`, and seeding three answered `samples` leaves one prompt for the skip-absent and all-answered cases; the photo refusal uses `vi.mocked(putPhoto).mockRejectedValueOnce`, the paste refusal `addError`
- update the doc comments on `AnswerPromptsSheet` / `PasteMaterialSheet` ("one prompt answered at a time") to cite VOICE-65
