## goal
A clip revision request needs no owner-chosen target: it is approved at two writing calls, the first call decides whether the footage flow changes, a narration-only request finishes after one call, and an optional selected scene scopes it.

## acceptance
- [ ] QuoteClipRevision/StartClipRevision accept an empty `target` as auto and still accept `flow | narration | both`; auto prices the two writing calls the flow target prices today, for ordinary and narrated plans (CLIP-132)
- [ ] both requests take an optional `scope_cut` (1-based scene block number in the quoted plan revision); it is part of the quote's input digest, refused when outside the plan's cut count, and stated in the writing prompt as the scene to change while the rest stays unless the request requires otherwise (CLIP-131)
- [ ] `ai.Service.Revise` with auto makes call 1 with a new routing prompt/schema that returns either `{flow_changed:false}` plus the narration revision or `{flow_changed:true}` plus a revised flow; on `flow_changed` call 2 writes the narration exactly as the flow target does today; the narrated (spoken) path routes the same way
- [ ] the job settles the usage actually spent through the existing settlement: a narration-only auto revision settles one call's usage below the approved maximum (QUOTA-46)
- [ ] the request record kind for auto is `revision:auto` and older kinds still parse (CLIP-133); progress stages report `flow` or `narrate` from the routing result
- [ ] Go tests: `backend/internal/clip/ai` routing tests with a fake LLM (narration-only → one call; flow → two calls; malformed routing output → existing bounded correction/failure), `backend/internal/clip/app/revision_test.go` (auto quote prices two calls, scope digest and refusal, narration-only settlement), compatibility cases for explicit targets
- [ ] `pnpm gen:proto` regenerates cleanly; `cd backend && go vet ./internal/clip/... && go test -timeout 30m ./internal/clip/ai/... ./internal/clip/app/...` passes

## impl notes
- Today: `app/revision.go` prices by target (`revisionPricing`, narration-only = one call) and `ai/service.go` `Revise` runs the flow call then narration unless the target is narration (`reviseSpoken` for narrated plans). Add `clip.RevisionAuto = "auto"` in `analysis.go`, accept `""` → auto at the RPC mapper, and keep `ValidRevisionTarget` accepting the old three plus auto.
- Routing schema: one JSON schema with a required boolean `flow_changed`; when false it carries the same fields the narration revision schema returns today, when true the same fields `RevisionFlowSchema()` returns. Build it as `RevisionRouteSchema()` beside the existing schemas; the prompt reuses `buildFlowRevisionPrompt` content plus the current narration and an instruction to change the flow only when the request needs footage, order or timing changes.
- Pricing: auto uses `freezeWork(..., narrationOnly=false, ...)` (two calls). Settlement is unchanged; do not add a refund path.
- Scope: proto `optional int32 scope_cut` on both request messages; carry it through `RevisionInput` and `RevisionInputDigest`; the prompt names the cut by number and its current captions/segments.
- Model choice stays an input per stage (ARCH-9); no provider type leaves `internal/llm`.
- FE switches to auto in T765; until then FE still sends explicit targets, which keep working.
