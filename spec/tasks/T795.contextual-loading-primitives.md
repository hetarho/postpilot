## goal
Create a single reusable LoadingState and Skeleton vocabulary for initial and compact loading without layout flashes.

## acceptance
- [ ] Shared LoadingState supports list, cards, form, detail, table and inline presentations with a required localized label, optional className and bounded representative rows. Skeleton is decorative and nonfocusable.
- [ ] Each loading region exposes busy state and one polite status; skeleton shapes are hidden from accessibility while its localized status remains available. Inline feedback contains the existing Spinner.
- [ ] Reserve geometry immediately. One shared CSS loading reveal delay of 150ms suppresses decorative flashes without any JS ready-data delay or minimum loading duration. Reduced motion leaves static visible shapes and a still indicator.
- [ ] Add focused accessibility/shape tests only for uncovered primitive behavior, run affected Vitest tests plus targeted ESLint/Prettier and the ARCH task check.

## impl notes
- Own the API at shared/ui/loading-state/LoadingState.tsx and export LoadingState, Skeleton through shared/ui/index.ts. Use variant: list|cards|form|detail|table|inline, label:string, className?:string, rows?:number. Keep the consumer API stable for dependent tasks.
- Use semantic tokens, existing card/layout scales and Spinner; no dependency or domain imports. Define the reveal timing once in index.css with opacity-only keyframes and retain the delay when reduced motion removes pulsing. Do not use a React timeout to gate ready data.
- Look at shared/ui/spinner/Spinner.tsx, shared/ui/card/cardStyles.ts and app/styles/index.css animation/token and reduced-motion blocks. Any extra tuning belongs beside this primitive.
- Unit tests cover accessible status, busy marking, decorative noninteractive shapes and variants; actual CSS timing, reflow and both-theme appearance are coordinator browser checks.
- Task checks are impact-selected unit tests, targeted ESLint/Prettier and the ARCH task command via vibe check --tier task.
