# T179 A template position declares its character maximum
> st:todo | ssot:CLIP-116 CLIP-117 CLIP-60 CDS-20 CDS-77 | base:CLIP@25 CDS@19 ARCH@2 | dep:-

## goal
Let a field, an element and a slot row declare a character maximum, refuse one larger than the position already allows, and carry each field's effective maximum in the parsed document.

## acceptance
- [ ] `<field chars="6">`, `<text chars="15">` and `<row chars="6">` parse; the value is a positive integer no larger than that position's derived cap and the grammar's own `CopyChars`/`AnswerChars`, anything else failing as `invalid_max` at the element's 1-based line
- [ ] an undeclared position keeps its derived cap: a region row takes its preset slot type's CDS-20 characters, an info row its row role's, an info element without rows `caption`, and a badge or caption element stays uncapped
- [ ] the parsed document exposes each field's effective maximum = the smallest of its declared value, the cap of every position its value reaches, and `AnswerChars`; a field reaching only uncapped positions keeps the smaller of its declared value and `AnswerChars`
- [ ] `Resolve` refuses an answer above that maximum with `answer_limit` naming the field and its line, where today only the global `AnswerChars` is measured (`resolve.go:44`)
- [ ] `ReadStored` still opens saved bodies that carry no `chars`, and a body that declares one round-trips byte-identically through the builder (→CLIP-71)
- [ ] `testdata/corpus.json` carries the accept, refuse and effective-maximum cases, and both owners — Go and the TypeScript mirror — pass it unchanged
- [ ] verify BE (ARCH-26) and FE (ARCH-25) pass

## impl notes
- the attribute is `chars`, not `max`: `<group max>` already means the item count (`parse.go:217`) and one grammar must not carry two meanings of max
- allowlists to extend: `readField` (`parse.go:181`), `readElement` (`parse.go:391`) and the row attributes (`parse.go:505`); strict `Parse` only — `ReadStored` accepts its absence and never a second spelling
- derived caps come from the design package the parser already imports: region slot → `design.Type[preset.Slots[i].Type].Chars` (a ratio changes only the hook's size, not its characters — `design.RegionType`, `region_verify.go:11`) · info row → `design.Type[row.Role].Chars`, `label` 22 and `caption` 18 being the only roles `layoutDeclaredInfo` renders (`composition_roles.go:105`) · info element without rows → `caption` · badge → `design.Type["badge"].Chars` is 0, meaning uncapped · caption role → uncapped here, its line and wrap rules staying with CDS-25, CDS-59 and the repair ladder
- effective maximum per field: walk every element and row `Part` that names the field and take that position's cap; grouped fields resolve inside their own repeat exactly as the binding scope check already does (`parse.go:468`)
- `Field`, `Element` and `Row` (`types.go:29`) gain the declared value and the document gains the computed per-field maximum, so no caller recomputes it (→CLIP-117) and T181's input, T180's editor and the admission check read one number
- refuse a declared value above the derived cap instead of clamping it ← a template that silently asks for less than it wrote is the failure CLIP-116 exists to prevent
- `answer_limit` already exists as a reason for the global ceiling; reuse it rather than minting a second one, and let the label/limit/actual parameters T181 adds carry the difference
- the TypeScript owner is `frontend/src/entities/clip-template/lib/composition-parse.ts` and `composition-resolve.ts` with the types in `model/composition.ts`; the shared oracle is `backend/internal/clip/composition/testdata/corpus.json`, read by `composition.test.ts:26`
- characters are counted by `design.Chars` — Korean syllables excluding spaces and punctuation (CDS-20) — on both sides, so the template's number, the owner's counter and the renderer's check are one rule
