# T278 a failure reason is a proto enum both sides compile against
> st:todo | ssot:ARCH-3 ARCH-17 ARCH-24 | base:ARCH@5 | dep:-

## goal
Replace the untyped failure-reason strings with a `FailureReason` proto enum whose names are the current strings, so a new reason is one proto edit that the BE compiler and the FE type checker both enforce, and delete the hand-kept 212-entry allowlist.

## acceptance
- [ ] `proto/postpilot/v1/error.proto` gains `enum FailureReason` with one value per reason now in `rpcserver/failure_reasons_test.go` (names identical, `UNKNOWN_FAILURE = 0`); `AppErrorDetail.reason` stays a `string` on the wire and carries `FailureReason.String()` — no wire change, agent untouched
- [ ] `rpcserver.NewAppError(code, message, reason postpilotv1.FailureReason, params)`; all 280 call sites in `*/rpc/` pass the enum constant, and the 33 `"UNKNOWN_FAILURE"` / 19 `"AUTH_REQUIRED"` literals are gone (`grep -rn '"[A-Z_]*FAILURE"' backend/internal --include=*.go | grep -v _test` is empty)
- [ ] `failure_reasons_test.go`'s allowlist is deleted; a small test pins that every enum value except 0 is referenced by at least one rpc adapter (dead reasons are flagged)
- [ ] FE: `AppFailureReason = keyof typeof FailureReason` (generated), `appFailureSpecs: Record<AppFailureReason, Spec>`, and `errors.ts` in both locales typed `Record<AppFailureReason, string>` so a missing spec or translation is a `tsc` error; `resources.test.ts`'s failure-coverage check still passes
- [ ] behaviour unchanged: ARCH-25, ARCH-26, ARCH-28 pass; the error copy shown for an existing reason is identical (snapshot one ko and one en rendering)

## impl notes
- from review/arch-260919 F19
- why an enum and not a generated catalog: buf already generates for all three sides (ARCH-3), so the enum is the catalog with no new tooling; keeping the wire as a string means old clients and the agent need nothing
- buf lint: `ENUM_VALUE_PREFIX` is already excepted in `buf.yaml` (the LLM-contract enums use bare names), so the bare reason names lint clean
- FE typing: `Record<AppFailureReason, string>` over 212 keys is fine for `tsc`; use `satisfies` so the object literal keeps literal key inference
