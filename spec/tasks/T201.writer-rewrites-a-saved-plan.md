# T201 The writer rewrites a saved plan from a written request
> st:todo | ssot:CLIP-131 CLIP-135 CLIP-92 CLIP-94 CLIP-97 | base:CLIP@31 CDS@20 ARCH@3 | dep:T212

## goal
Give the two writing contracts a revision mode: the project's current plan plus an owner-written request and its target, answered with a complete replacement of the targeted document — the flow and then the narration, or the narration alone — bound to the observations already stored.

## acceptance
- [ ] `clip.RevisionInput{PlanningInput, Current EditPlan, Request string, Target string}` with `Target` one of `flow` · `narration` · `both`; `ai.Service.Revise(ctx, model, RevisionInput) (EditPlan, Usage, error)` runs `Flow` then `Narrate` for `flow` and `both`, and `Narrate` alone for `narration`
- [ ] each revise request carries the current plan (the flow's cuts, and for a narration target the current captions), the owner's request text, the stored observations and the same template composition, answers, instruction and item hints a generation freezes
- [ ] the contracts state that the response replaces the targeted document whole, keeps the template's fixed regions (intro and outro skeleton, badge, declared maxima), and that a narration-only target may not change a cut; a request needing something the contract cannot express is answered within it rather than by inventing structure
- [ ] the observations are the only admissible footage evidence: no range outside a recorded scene, no invented fact, and CLIP-137 grounding, CLIP-128's share and CLIP-129's speech rule apply exactly as they do to a generation
- [ ] the response is validated, repaired or narrowed through the CLIP-106 paths T211 and T212 built and records CLIP-108 notices the same way; an unreadable response follows CLIP-94's three bounded correction attempts
- [ ] request text is bounded at `InstructionChars` (1000) where it is typed (CLIP-117) and checked again here; the current plan counts against CLIP-90's frozen allowance and overflow is reported with size and limit, never trimmed
- [ ] tests: a flow-target request carries the cuts and runs two calls; a narration-target request carries the captions and runs one; a returned plan is validated by the shared paths; an over-share or ungrounded response behaves as in a generation; verify BE (ARCH-26)

## impl notes
- `Revise` sits beside `Flow`/`Narrate` in clip/ai/service.go and reuses `completeValidated` (CLIP-94 loop, budgets, usage); the port in clip/generation_ports.go gains `Revise`
- revision mode is the same two prompts with one appended block — `current_plan` and `revision_request` — and one sentence on replacement; a second wording of the cut, rate or caption rules is what CLIP-92 forbids
- the response schemas are T211's and T212's; asking for the whole targeted document back is CLIP-97's rule, and a diff format would need a merge rule the SSOT does not define
- keep `RevisionInput` a separate struct rather than an optional plan on `PlanningInput`: every generation path would otherwise carry a revise concern
- this task is the domain contract only — no RPC, no job, no credits; T202 wires it up
