# T338 The daily per-분야 phrase extraction and refresh pass
> st:todo | ssot:QUAL-1 QUAL-17 QUAL-20 QUAL-22 QUAL-23 QUAL-24 QUAL-26 QUAL-38 QUAL-41 QUAL-42 GUIDE-33 ARCH-11 ARCH-40 ARCH-24 | base:QUAL@3 GUIDE@5 ARCH@9 | dep:T335 T326

## goal
- An in-process pass keeps each 분야's top-50 phrase list fresh from up to 300 Naver blog results through one extraction implementation, on a durable per-field schedule that survives restarts; a failed field keeps its last list, and a box without Naver keys runs no pass at all.

## acceptance
- [ ] `quality.ExtractPhrases` turns titles and descriptions into at most 50 phrases of 2–5 tokens, never a single token, never a run made only of stopwords, counted once per title or description, with a run dropped when a longer run containing it has the same count, ranked by count desc, then fewer tokens, then lexicographic.
- [ ] A pass visits the nine fields of `quality.Fields()` in catalogue order; a field is due when it has no `field_phrase_lists` row or its `next_refresh_at` is at or before now; a field not yet due makes no search call.
- [ ] A due field requests `start` 1, 101 and 201 with its QUAL-23 query string, stopping early after a page with fewer than 100 items; a short or empty corpus is a success.
- [ ] A success replaces that field's row with the ranked phrases, `corpus_size` = results collected, `refreshed_at` = now and `next_refresh_at` = now + the refresh interval (24h unless `QUALITY_PHRASE_REFRESH_INTERVAL` overrides it).
- [ ] A failed page keeps the field's phrases, `corpus_size` and `refreshed_at` exactly and moves only `next_refresh_at` to now + min(interval, 1h); a field that never had a row gets one with `[]`, 0 and a NULL `refreshed_at`, which reads as no 분야 (QUAL-41).
- [ ] One failing field never stops the others; the pass returns the per-field errors joined, each naming its field id.
- [ ] No write transaction is open while an HTTP call is in flight; the pass writes `field_phrase_lists` only and records no usage, credit or job row (QUAL-24).
- [ ] With either Naver key unset the pass makes zero search calls and zero store reads or writes, and the API boots and serves exactly as before (QUAL-42).
- [ ] On boot the pass catches up once in its own goroutine (off the listener path), then checks every min(interval, 10m); cancelling the server context stops it without writing for a field whose fetch it interrupted.
- [ ] Tests: `backend/internal/quality/phrases_test.go` (table: single token excluded, 6-token cap, stopword-only runs dropped, one count per item, subsumption, ties, 50 cutoff, Korean and English, a punctuation-only field breaks a run, NFD input); `backend/internal/quality/batch_test.go` (`TestPhraseBatchRefreshesOnlyDueFields`, `TestPhraseBatchFetchesThreePagesOfOneHundred`, `TestPhraseBatchShortCorpusIsASuccess`, `TestPhraseBatchPageFailureKeepsTheLastList`, `TestPhraseBatchFirstFailureSchedulesAnEmptyRow`, `TestPhraseBatchOneFailingFieldDoesNotBlockTheOthers`, `TestPhraseBatchDisabledMakesNoCalls`, `TestPhraseBatchCatchesUpOnBoot`, `TestPhraseBatchStopsOnCancel`, `TestPhraseBatchZeroIntervalUsesTheProductDefault`); `backend/cmd/api/phrase_batch_test.go` (`TestPhraseSearchIsAbsentWithoutBothKeys`, `TestQualityBlogSearchMapsItemsInOrder`); `cmd/api/wiring_test.go` still passes with the batch disabled; the quality import test forbids `guideline` and `naversearch`.
- [ ] Verify: `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test -timeout 30m ./...`

## impl notes
- Why this is not an ARCH-11 job record: the refresh has no owner — a phrase list is installation-wide product data (QUAL-17, QUAL-22) — and `generation_jobs.user_id` is `NOT NULL REFERENCES users(id)` (migration 0063). It follows the billing renewal precedent instead: an in-process loop with a durable per-row next time and a boot catch-up (R24).
- `backend/internal/quality/limits.go` (T331's file) gains `PhraseRefreshInterval = 24 * time.Hour` (the product default T326's config leaves to this context, ARCH-21), `PhraseRefreshCheck = 10 * time.Minute` (the check cadence, as `config.BillingTickInterval`), `PhraseRetryDelay = time.Hour`, `PhrasePageSize = 100`, `PhrasePages = 3` (QUAL-17's 300 results; `PhrasePageSize` must equal naversearch's `display=100`), `PhraseMinTokens = 2`, `PhraseMaxTokens = 5`, `PhraseListMax = 50` (QUAL-38). Extend T331's limits test to pin them.
- The check cadence is separate from the refresh interval on purpose: ticking once per interval against a `next_refresh_at` stamped a few seconds after the tick finds nothing due on the next tick and refreshes every second interval.
- `stopwords.go` (R21, QUAL-26): two unexported sets and `isStopword(token string) bool` — a Korean token matches exactly, an English one after `strings.ToLower`. Starter lists (product data, changeable without a schema change): ko `및 등 그리고 그러나 그런데 하지만 그래서 또는 또한 또 더 덜 잘 좀 꼭 너무 정말 진짜 아주 매우 많이 조금 가장 제일 그 이 저 그런 이런 저런 어떤 모든 각 것 거 수 때 중 위해 통해 대한 대해 있는 있다 있어요 없는 없다 하는 한 할 합니다 했다 해요 하고 된 되는 입니다 같은 나 저는 제가 우리 저희`; en `a an the and or but of to in on at by for with from as is are was were be been it its this that these those i you we they my your our me us`.
- `phrases.go` (R26, the ONE implementation; T344's freeze and T348's fixture read its output, never a second copy): `type Phrase struct { Text string; Tokens, Count int }`; `func ExtractPhrases(units []string) []Phrase`, where a unit is one title or one description.
- Tokenizing: split each unit with `strings.Fields`, pass each field through T325's 어절 tokenizer in `text.go` (NFC plus edge-punctuation trim); a field that reduces to nothing (a lone `|`, `-`, `…`) ends the current segment, so `성수 카페 | 분위기 좋은` yields the segments `성수 카페` and `분위기 좋은` and never the run `카페 분위기`.
- Runs: every contiguous run of `PhraseMinTokens`…`PhraseMaxTokens` tokens inside one segment, skipping a run whose every token `isStopword`; a run's key is its tokens joined by one space (case kept); each distinct key counts once per unit.
- Subsumption: for every counted run R, each shorter contiguous sub-run r of R (at least 2 tokens) with `count(r) == count(R)` is dropped. Then sort by Count desc, Tokens asc, Text asc (Go byte order) and keep the first `PhraseListMax`.
- `batch.go`: `type SearchItem struct { Title, Description string }`; consumer port in `ports.go` `type BlogSearch interface { SearchBlog(ctx context.Context, query string, start int) ([]SearchItem, error) }` (ARCH-6: quality owns the port, the wrapper never imports quality).
- Store: the pass consumes T335's `PhraseLists` port as declared (`PhraseList(ctx, field) (PhraseList, bool, error)` and `ReplacePhraseList(ctx, PhraseList) error`) and declares no second port; `*store.Store` satisfies it and the fake in `batch_test.go` implements only it, so the pass cannot reach any other table.
- Due selection reads each of the nine rows by field: a field the batch never refreshed has no row, and no row means due. T335 therefore ships no due listing and no reschedule query.
- `type PhraseBatch struct`; `func NewPhraseBatch(store PhraseLists, search BlogSearch, interval time.Duration, now func() time.Time) *PhraseBatch` panics on a nil store or clock (ARCH-40); a nil `search` is the legal, tested disabled mode (QUAL-42); `interval <= 0` becomes `PhraseRefreshInterval`.
- `func (b *PhraseBatch) RunOnce(ctx context.Context) error`: disabled → return nil before any store call. Otherwise, per field in `Fields()` order: get the row (a read error joins and skips the field); not due → skip; fetch pages sequentially (`start = 1 + page*PhrasePageSize`, stop after a page shorter than `PhrasePageSize`); flatten each item's non-blank title and description into units; `ExtractPhrases`; one replace-upsert. No transaction spans a fetch: the three calls finish before the one write.
- Success row: `Phrases` = the ranked `Text`s (a JSON array of strings, T335's column), `CorpusSize` = items collected, `RefreshedAt` = `b.now()` read after the fetch, `NextRefreshAt` = that + interval.
- Failure row: the stored `Phrases`, `CorpusSize` and `RefreshedAt` unchanged (or `[]`, 0, nil when the field had no row) and `NextRefreshAt` = `b.now()` + `min(interval, PhraseRetryDelay)`; the error joins as `fmt.Errorf("refresh %s: %w", id, err)`. A nil `RefreshedAt` requires T335's upsert to write SQL NULL, which R24's schema allows.
- `ctx.Err() != nil` at any point stops the pass at once without writing for the field in hand; that field stays due and the next boot's catch-up retries it.
- `func (b *PhraseBatch) Run(ctx context.Context)`: disabled → one `slog.Info("quality phrase refresh disabled: no Naver search credentials")` and return. Otherwise create a ticker of `min(b.interval, PhraseRefreshCheck)`, run `RunOnce` once (the catch-up, logging a failure with `"boot", true` as `runBillingPasses` does), then `RunOnce` per tick until `ctx.Done()`; a failure is `slog.Error("quality phrase refresh failed", "err", err)` and never stops the loop.
- Tests use a fake `BlogSearch` recording `(query, start)`, a fake `PhraseLists` recording reads and writes, and a fixed clock; `Run` tests pass a millisecond interval for ticks, an hour interval for "no tick has elapsed", and a channel with a two-second timeout as `billing_worker_test.go` does. The cancel test blocks the fake search until its context ends.
- Extend the QUAL-16 import test (T331, extended by T335) so `internal/quality` also imports no `guideline` (GUIDE-33: no guideline package is touched and no guideline text is written) and no `naversearch` (the port stays consumer-owned).
- QUAL-22: no rpc or service method writes a phrase list; QualityService (T322) stays read-only, and nothing here adds a write path an owner could reach.
- `backend/cmd/api/adapters_quality.go` (T335's file): `type naverBlog interface { SearchBlog(ctx context.Context, query string, start int) ([]naversearch.Item, error) }`; `type qualityBlogSearch struct{ client naverBlog }` maps each `naversearch.Item` to `quality.SearchItem` in order; `func phraseSearch(cfg *config.Config) quality.BlogSearch` returns nil unless `cfg.NaverSearchEnabled`, else `qualityBlogSearch{client: naversearch.New(cfg.NaverSearchClientID, cfg.NaverSearchClientSecret, http.DefaultClient)}`. Returning the interface type means disabled is a true nil, never a typed nil that would pass as enabled (the `var exchangeRates billing.Rates` precedent in contexts.go).
- `backend/cmd/api/contexts.go`: `contexts` gains `phraseBatch *quality.PhraseBatch`, built after T335's `quality` service over the same `qualitystore.New(handle.Writer, handle.Reader)` value: `quality.NewPhraseBatch(store, phraseSearch(cfg), cfg.QualityPhraseRefreshInterval, time.Now)`. It is non-nil in the disabled mode, so `TestBuildContextsWiresEveryRequiredCollaborator`'s nil-field walk needs no exception.
- `backend/cmd/api/serve.go`: `go c.phraseBatch.Run(ctx)` beside the other background loops, before the listener goroutine; nothing runs before `ListenAndServe` synchronously, so a slow Naver answer cannot hold `/health` shut (the reason `runBillingPasses` catches up inside its goroutine).
- `TestPhraseSearchIsAbsentWithoutBothKeys`: `phraseSearch(&config.Config{})` `== nil` as an interface; with `NaverSearchEnabled` and both keys set it is non-nil. `TestQualityBlogSearchMapsItemsInOrder` injects a fake `naverBlog`.
- Out of scope: an owner-editable list (QUAL-22); full-text collection (QUAL-33); the store queries (T335); generation reading the list (T344); the wrapper and config keys (T326).
