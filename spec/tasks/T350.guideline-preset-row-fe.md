## goal
- The 상위 노출 단어 사용 preset is always on screen above the owner's list. It shows its server text read-only, its own switch, and a 적용할 분야 multi-select that is its fields scope, and it says it yields to the owner's rules. When it is on with no 분야, it asks for a first one.

## acceptance
- [ ] Once the list is read, the preset row is the first block under the page description, above the saved list and above the empty state, whatever the account holds. It is a region named 상위 노출 단어 사용.
- [ ] The row shows the server's `preset.text` verbatim. It has no `Editable`, pencil, textbox or delete, because the text cannot be edited (GUIDE-32).
- [ ] A `switch` named 상위 노출 단어 사용 reflects `enabled`. Flipping it sends UpdateGuidelinePreset carrying `enabled` alone, and the switch shows the saved state as soon as the answer lands, with no flash of the old state while the list refetches.
- [ ] 적용할 분야 is T347's `GuidelineFieldPicker` with a visible legend. Each check or uncheck sends UpdateGuidelinePreset carrying `fields` alone, holding the whole next set in catalogue order, and picking while the preset is off is allowed. The switch and the picker are disabled while a preset save is pending.
- [ ] The row says the owner's own guidelines win over it (GUIDE-37), and it describes the phrases only by what is observed about them: nothing about ranking gains, and nothing implying the post was read (QUAL-19, QUAL-21).
- [ ] When the preset is on with no 분야, the row says it applies to no post and asks for a first 분야 (GUIDE-38). The notice leaves once a 분야 is picked or the preset is switched off.
- [ ] A refused preset save shows the failure catalogue's message under the row and keeps the saved state. The client predicts no refusal (GUIDE-24).
- [ ] `page.order` and `page.description` name the preset, its last-of-all place in the injection order and that it cannot be edited.
- [ ] Mounting the page sends no UpdateGuidelinePreset, and the existing no-job call allowlist test stays green.
- [ ] Every control in the row meets the 44 px floor under a coarse pointer through its primitive (`Switch`, `Checkbox`), and the slice sizes nothing itself (THEME-23).

## impl notes
- T342 left `ListGuidelinesResponse.preset {text, enabled, fields}` (always set) and `UpdateGuidelinePreset({optional bool enabled; GuidelinePresetFields fields})`, whose answer carries the resulting preset. T347 left the queryFn-mapped list cache, `GuidelineFieldPicker` and the blog-field `@x` barrel.
- `shared/api/index.ts` adds `GuidelinePresetSchema`, `UpdateGuidelinePresetResponseSchema` and `type GuidelinePreset as ProtoGuidelinePreset` from `guideline_pb`, because only shared/api names generated code (ARCH-17).
- `entities/guideline/model/types.ts`: `GuidelinePreset { text: string; enabled: boolean; fields: BlogFieldId[] }`, exported from `index.ts`.
- `api/guideline-queries.ts` `toGuidelinePreset(preset: ProtoGuidelinePreset | undefined): GuidelinePreset` maps the 분야 through `blogFieldFromProto` and drops `''` and undefined. An absent message throws, exactly like T347's unreadable scope: T342 always sets it, so its absence is a malformed read, and the page's load failure covers it.
- `guidelineListQuery`'s queryFn returns `{ guidelines, preset }`. `useGuidelines` also returns `preset: GuidelinePreset | undefined`, which is undefined until the first read lands.
- `api/guideline-mutations.ts` gains `useUpdateGuidelinePresetCall(ownerId)`, named like its three `…Call` siblings and exported from `index.ts`. It wraps `useMutation(GuidelineService.method.updateGuidelinePreset)` and returns `{ ...mutation, errorMessage: guidelineErrorMessage(mutation.error), setEnabled, setFields }`.
- `setEnabled(enabled: boolean)` calls `mutateAsync({ enabled })`, and `setFields(fields: BlogFieldId[])` calls `mutateAsync({ fields: { fields: fields.map(blogFieldToProto) } })`. Each patch carries its own half only, so a switch flip can never overwrite a 분야 set saved from another tab, or the reverse.
- The hook's `onSuccess` first writes the answered preset into the list cache: `queryClient.setQueryData(guidelinesQueryKey(transport, ownerId), (old) => old && { ...old, preset: toGuidelinePreset(response.preset) })`. It then calls `invalidateGuidelines`. This is what keeps the switch from showing the old state until the refetch lands.
- New slice `features/adopt-guideline-preset` (a verb slice that renders UI, ARCH-14): `index.ts` exporting `GuidelinePresetRow`, `ui/GuidelinePresetRow.tsx`, and `config/i18n.ts`.
- That fragment sits in the `guidelines` namespace under one top-level key `preset`, so resources.test.ts finds no key claimed twice (R38). Register it in `app/providers/i18n/resources/index.ts` in both `guidelines` spreads.
- `GuidelinePresetRow({ ownerId, preset }: { ownerId: string; preset: GuidelinePreset })` is a `<section aria-labelledby={nameId}>`. Its first line copies the row shape of `features/fill-template-answers/ui/TemplateAnswerFields.tsx:43-53`: `div.flex.min-h-11.items-center.gap-3` holding `FieldLabel id={nameId} htmlFor={switchId} className="min-w-0 flex-1"` with `preset.name`, and `Switch id={switchId}`. Unlike that file, the label names the switch itself, so the switch's accessible name is the visible name and needs no `aria-label`.
- Below that line, in order: `preset.text` as `Typography variant="body"` with `whitespace-pre-wrap`; `preset.about` and `preset.yields` as secondary body lines; `GuidelineFieldPicker` with `legend={t('preset.fields')}` and `legendVisible`; a `Notice tone="warning" role="status"` with `preset.needsField` when `enabled && fields.length === 0`; and a `FieldMessage` with `errorMessage` after a refusal.
- The row is a plain block in the page flow. It has no card, border or `sticky` (ARCH-20, THEME-29): "pinned" means always first.
- The next set for a pick is computed from `preset.fields`, which the last answer wrote into the cache, and the controls are disabled while pending. Presses therefore serialize, and none is computed from a stale set.
