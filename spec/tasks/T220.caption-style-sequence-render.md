# T220 Sequence-rendered caption styles
> st:todo | ssot:CDS-81 CDS-4 CDS-80 | base:CDS@21 | dep:T219

## goal
Render the styles that draw one layer per output frame, through a bounded temporary PNG sequence the existing overlay chain consumes.

## acceptance
- [ ] a sequence style rasterises one PNG per output frame of its caption interval into the attempt's temporary workspace and the overlay chain reads it with `image2` at the output frame rate
- [ ] the frames are deleted when the cut they belong to finishes, and the sequence budget joins CLIP-33's temporary-disk accounting so a long caption cannot exhaust the workspace
- [ ] a static style still rasterises exactly once and keeps the `loop` filter path, unchanged
- [ ] each style's motion matches what the registry declares and V9 verifies it per style
- [ ] a render with one sequence caption and one static caption produces the same output twice (determinism), pinned by a golden test
- [ ] the media image stage builds and runs locally with a sequence caption in the fixture (ARCH-37)
- [ ] ARCH-26 passes

## impl notes
- frames go to disk and enter through `image2` rather than `image2pipe` ← the overlay chain already takes several inputs and feeding pipes concurrently makes scheduling and partial-failure retry much harder, while files let one failed caption re-render alone
- decoder threads stay limited on the sequence input exactly as the existing single-frame overlay inputs do ← an unbounded image demuxer can leave the scheduler waiting after an overlay stops consuming
- the sequence is generated per caption, not per cut, because a caption may cross cuts (→CDS-27)
