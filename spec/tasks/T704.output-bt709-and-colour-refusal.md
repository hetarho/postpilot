# T704 Tag every render as SDR BT.709 and name a refused source's colour format
> st:todo | ssot:CDS-52 CLIP-219 CLIP-155 | base:CDS@35 CLIP@62 | dep:- | touches:frontend/src/entities/clip-preview frontend/src/shared/lib/media backend/internal/clip/media frontend/src/shared/api/app-failure.ts | lane:-

## goal
Both render kinds write and check BT.709 limited-range colour tags (CDS-52 V12). A colour refusal names the source and its colour format instead of asking the owner to reselect it.

## acceptance
- [ ] The browser H.264 encoder writes BT.709 primaries, transfer and matrix and the limited range into the stream, and the browser's output verdict checks them.
- [ ] The native libx264 encode sets `-color_primaries bt709 -color_trc bt709 -colorspace bt709 -color_range tv`, and the native output check reads them back with ffprobe.
- [ ] A render whose tags differ fails V12 like any other output check.
- [ ] `CLIP_SOURCE_COLOR_UNSUPPORTED` carries `source` (the file name) and `format`, a short label such as `HDR10 (PQ)` or `BT.2020 HLG` built from the declared tags. Both params are added to the param allowlist in `shared/api/app-failure.ts` (memory: one unlisted param turns the refusal into UNKNOWN_FAILURE). The ko and en copy names them and says which formats are accepted, with no 다시 선택 advice.
- [ ] Tests:
  - frontend render verdict: `refuses an untagged output`, `accepts BT.709 tags`
  - app-failure: `names the source and its colour format`
  - backend: `TestNativeEncodeTagsBT709`, `TestOutputCheckRefusesWrongColourTags`
- [ ] Relevant vitest, go test `-count=1`, `pnpm lint` and `pnpm lint:fsd` pass. The Docker render smoke runs once.

## impl notes
- This task is independent of T702/T703. It changes the encoders and checks only, and SDR sources gain only the tags.
- The browser encoder lives in `entities/clip-preview/model/browser-video.ts` and `lib/video.worker.ts`, with muxing in `shared/lib/media/mux-mp4.ts`. Set the encoder's colour space, or the mp4 track's `colr` box through mediabunny's output options, whichever the code path exposes. Verify by ffprobe on a browser-rendered file in the browser integration check.
