## impl notes
- Read `WritingTestStudio.tsx` only in these ranges: the `asks` memo and `missingFacts` (~L311–347), the material view (`flow.view === 'material'`, ~L997–1262), the candidates view's `requiredChoices` message and its StepBar (~L945–995), and `WritingSelect`/`WritingOptionField` at the end of the file.
- Replace the label-merged `asks` with ordered groups `{ key, name, asks: { label, required, prompt, shared }[] }`: template factor → one group per distinct contestant template in slot order (setting entrant → `choices` name; authoring entrant → `preparedMetadata(entrant)?.name ?? t('preparedSlot')`; two slots of the same template id give one group); any other factor → one group for the fixed template. `shared` = the label appears in two or more groups. Answers stay keyed by label in `plan.context.material.templateAnswers` (MODEL-30: one shared answer; the wire is unchanged). `missingFacts` keeps its meaning across all groups.
- New `WritingTestTemplateFacts.tsx` in the same widget renders the groups. Phone detection uses the existing `useMediaQuery` (`frontend/src/shared/ui/media-query/useMediaQuery.ts`) with the `sm` breakpoint query the codebase already uses elsewhere (grep `useMediaQuery(` for the existing sm query string). Phone: `SegmentedControl` (shared/ui) as the tab row with `controls` set to the panel id; panel `role="tabpanel"`. Desktop: stacked `section`s with the template name as heading. Mount one layout at a time so no field is duplicated in the DOM. Field ids must be unique per group: `test-fact-${groupIndex}-${label}`.
- 필수 mark: i18n `requiredMark` (ko `필수`, en `Required`) rendered inside the FieldLabel after the label text as text, never colour alone. Shared mark: `sharedFact` (ko `공통`, en `Shared`).
- Problems: derive one ordered list `{ fieldId, label, message }[]` in on-screen order from the existing checks (`targetLengthBounds`, `tagCountBounds`, `requiredMaterial`, `requiredObserver`, fixed writer/observer `ineligibleModel`/`unsupportedVideo`, each missing required question → `requiredInput`). Show each message as a `FieldMessage` directly under its field with `aria-invalid` on the control, only after `attempted`. Remove the stacked FieldMessages above the StepBar.
- Step bar reason: `StepBarReason` (shared/ui step-bar) above `StepBarActions`, text `t('fixFields', { first, count })` with i18next plurals (ko `fixFields_one: '{{first}}을 확인해 주세요'`, `fixFields_other: '{{first}} 등 {{count}}곳을 확인해 주세요'`; en equivalents); the CTA gets `aria-describedby` to it. The candidates step's `requiredChoices` moves into its StepBar the same way. A flow failure shown for this step (search `flow.context.failure` in the material view) also renders inside the StepBar.
- Focus: on a refused press set a `focusRequest` state; a `useEffect` switches the tab when the first problem is a question in another group, then on the next frame calls `getElementById(fieldId)?.focus()` and `scrollIntoView({ block: 'center' })`.
- Docked bar: `StepBar` is the ActionBar `step` dock (`sticky bottom-0`). Check at phone width that it stays at the viewport bottom while the step scrolls; if not, fix the cause inside this widget or `pages/writing-tests` only (an ancestor `overflow`, or the section not reaching the column's end) and record what was observed in result.
- jsdom has a `matchMedia` stub in `frontend/src/test/setup.ts`; override it per test for the phone case.
