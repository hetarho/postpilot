# T558 Sample browser renders without a full decode and load each original once
> st:todo | ssot:ARCH-37 ARCH-48 ARCH-24 | base:ARCH@15 | dep:- | touches:backend/internal/clip/worker/executor.go backend/internal/clip/localmedia/source.go backend/internal/clip/media/composition_render.go backend/internal/clip/media/ground_sampler.go

## goal
A browser render's sampling job downloads only the originals its reads need, once each, with no full-file decode, and a server render downloads and verifies each original once instead of once to verify plus once per run of cuts.

## acceptance
- [ ] `sampleTask` no longer calls `planInputs`' fetch + `Probe` loop: sources carry the frozen `s.Info` from the task, and its loader fetches lazily (the download's fingerprint check still runs) only for cuts whose reads need frames
- [ ] `renderTask` verifies each original inside its loader on first fetch (fetch → `Probe` → `SameMediaOriginal`, recording the `MediaVerifiedSource`), instead of fetching, probing and dropping every source up front; every source the task names is still verified and reported, including one no cut draws (fetched once for verification at the end if no cut loaded it)
- [ ] both the server render's cut loop (`composition_render.go`) and `SampleGrounds` visit cuts grouped by source (stable: source order of first appearance, then cut index); per-cut outputs stay indexed by the original cut index, so the rendered file is unchanged
- [ ] tests: a 12-cut plan alternating 4 sources fetches each source exactly once in render and in sampling; a sampling plan whose reads touch 2 of 4 sources fetches 2 and probes none; a source whose probe disagrees still fails the render with `ErrInvalidMedia`
- [ ] ARCH-37: the `production` target's media smokes pass (`docker buildx build --target production -f backend/Dockerfile .`, grep the output for `did not complete successfully` → 0), the identity smoke digest is the same before and after this change on this host, and the release smoke (`--target release-smoke`, `--memory 1g --cpus 2`) passes — update its per-source download expectations only if they count the remote worker path and drop as designed
- [ ] behaviour unchanged otherwise: ARCH-26 green

## impl notes
- from review/perf-cost-261004 F7 F15
- the full-decode `Probe` stays on the server render path: the source fingerprint hashes only the size, type, duration and the first/last slices, so the decode is what proves the delivered file's inputs; a sampling job writes no file, and a wrong frame there could only move a scrim decision
- not in this task: skipping the sampling job when a layout has no sampled text (nearly every clip has captions, and the API would need the laid-out visuals), and reusing grounds across retried browser exports at the same revision
- grouping order must be deterministic so the sampler's grounds and the render's step progress stay reproducible
