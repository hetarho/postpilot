## goal
Let owners save two to five distinct lab candidates and start observe, write or voice comparisons that display all returned results.

## acceptance
- [ ] Each model-lab comparison tab displays the saved A/B pair plus Add candidate controls for up to three optional C/D/E rows. Optional add, change and remove save immediately; removal compacts the list, while the editor and recommendation forms still show A/B alone.
- [ ] The form never starts with a blank, duplicate, unavailable, locked or unsaved visible ref. It identifies the offending row, preserves a removed/disabled ref's explanatory state, and blocks start while either pair or extras save is pending. A changed recommendation pair that collides with an extra is shown as a conflict rather than silently dropping the extra.
- [ ] Observe, post-write and voice-reflection starts send the full two-to-five-ref list and the same source/target/voice/photo inputs they already freeze; editor A/B sends the new full-list field containing exactly two refs, so it uses the candidate-ranking review contract. Server count/refusal and insufficient-credit errors are shown in place without opening a result page.
- [ ] Result review, history entry and blind candidate labels handle two to five candidates, stable after reload. Desktop uses at most two columns per row; phone has a reachable candidate switch, keeps each candidate's reading position, 44 px controls and no horizontal prose overflow. No model identity or accounting reaches a blind panel.
- [ ] FE tests cover pair-only defaults, add/remove/max-five, duplicate/unavailable/locked/save-race states, observe/write/voice start payloads, all five outputs, responsive candidate navigation and old two-candidate records; run ARCH-25 verification.

## impl notes
- Extend the `entities/model-catalog` pair projection with `extraCandidates` from T499's `ComparisonPair` field. Keep `ModelPairForm` itself as the editor-compatible two-field feature; compose the lab-only optional rows in the comparison page or a dedicated feature without importing a page into a feature.
- Use T499's complete-list optional save RPC for C/D/E and T500's new full-list start field, even for the editor's two-candidate action; this marks a current ranking-format comparison. Build the request only from server-confirmed pair and extra state matching the visible rows; explicit refs always travel to Start, never inferred from saved selections by the server.
- Keep `VoiceReflectionStart` on the write-stage candidate list and require every candidate to support images for a photo prompt. Preserve the existing post picker, re-observation picker, URL stage filter and localized reason catalog.
- Extend the entity's display-position mapping for LEFT/RIGHT/C/D/E with an exhaustive generated-enum parity test. Render labels A–E without associating them with the pre-start model picker order; the server has shuffled that association.
- Use existing `shared/ui` controls and design tokens. Store per-candidate phone reading positions by candidate id in the review page state so switching five long outputs does not reset the owner's place.
