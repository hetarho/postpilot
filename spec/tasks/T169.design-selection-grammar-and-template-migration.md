# T169 Stop accepting a declared style and migrate every stored template
> st:todo | ssot:CDS-66 CLIP-14 CLIP-4 | base:CDS@15 CLIP@22 ARCH@2 | dep:T166

## goal
No template declares a style, and every template already saved keeps working without the owner editing it.

## acceptance
- [ ] strict `composition.Parse` rejects a `styles` attribute on `<clip>` and a `style` attribute on `<text>` with an authoring error naming the element and line
- [ ] `composition.ReadStored` tolerates both so an existing draft still opens for correction
- [ ] a goose migration under `backend/internal/platform/db/migrations/` strips `styles="..."` from `video_templates.composition_body` and `style="..."` from its `<text>` elements, leaving every other byte untouched
- [ ] the same migration clears `video_templates.copy_styles` and the `Styles` list stored in `clip_projects.edit_plan_json`, so no saved plan carries an approved-style set
- [ ] `EditPlan.Styles` and the `styles` field of the copied authoring instructions are removed; the writer prompt and the template format guide stop mentioning styles
- [ ] V14 (template-approved styles) is removed from the verifier and its failures no longer exist
- [ ] test: a body with `styles="simple"` fails strict parse and opens under `ReadStored`
- [ ] test: the migration converts a real stored body (use the `맛집 테스트` body in `docs/design/clip-restaurant-template-v2.md`) and the result parses strictly
- [ ] test: a plan saved with `Styles` renders after the migration
- [ ] `pnpm gen:sql && git diff --exit-code -- backend` and `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...`

## impl notes
- refusing a stored body outright would break every saved template until the owner edited it by hand, so the split is deliberate: strict on save, tolerant on read, and a migration that makes the tolerance unnecessary
- migration 0041 rewrote stored `Position` values inside `edit_plan_json` with SQL string replacement and is the precedent for the plan half of this
- the template body is XML in a text column; a targeted attribute strip is safer than a parse-and-reserialize, which would normalize whitespace the owner wrote
- CLIP-92 keeps save, admission and the copied instructions on one vocabulary — all three must drop styles in this task or they disagree
