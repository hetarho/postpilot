# T202 A revision request runs as its own job and charges the writing calls its target needs
> st:todo | ssot:CLIP-131 CLIP-132 CLIP-135 CLIP-20 CLIP-93 | base:CLIP@31 ARCH@3 | dep:T201 T213

## goal
Quote, approve, run and settle a revision request as a clip job that prices one writing call for a narration target and two for a flow or both target, reuses every stored observation, updates the saved plan and renders nothing.

## acceptance
- [ ] a revision quote prices one writing call (narration target) or two (flow or both target) with their response-correction allowances, prices no observation call, and reuses the stored observations without re-verifying sources
- [ ] the quote binds the project, the current plan revision, the request text, the target and the writing model; a plan saved after the quote invalidates it rather than rewriting a plan the owner did not approve
- [ ] starting a revision creates a clip job the owner can cancel, reports its stage while running, and refuses to start while another clip job is active
- [ ] a completed revision replaces the project's edit plan and advances the plan revision without touching the rendered revision, so the existing result is correctly shown as stale and 다시 렌더 stays credit-free
- [ ] a failed or cancelled revision leaves the saved plan and the existing result untouched and settles under QUOTA-46 and QUOTA-49 as a generation does
- [ ] original retention renews on an accepted revision start exactly as CLIP-73 renews it for a generation
- [ ] tests: the quote prices one writing call and no observation call; a completed revision advances the plan revision and leaves the result stale; a cancelled one changes neither plan nor result
- [ ] verify BE (ARCH-26) and generated code (ARCH-28) pass

## impl notes
- RPC: add `QuoteClipRevision` and `StartClipRevision` to proto/postpilot/v1/clip.proto beside the generation pair, and handlers beside `QuoteClipGeneration` (rpc/quotes.go) and `StartClipGeneration` (rpc/handler.go). `pnpm gen:proto` runs buf through Docker (ARCH-28) — T186's log notes proto/sqlc regeneration needs the daemon up
- the job is a third kind alongside generation and render: `GenerationStart` already carries `RenderOnly`, and `generation_jobs.kind` already distinguishes clip work, so add the revise kind there rather than inventing a second queue. `HasActiveClipJob` then keeps CLIP-79's one-job-at-a-time rule for free
- the run path is a short sibling of `RunGeneration`: no `WithWorkspace`, no probe, no render — load the project, the recovery observations and the saved plan, call `Revise` (T201), then persist. Reuse `SaveCorrection` (store/queries/generation.sql), which already advances `edit_plan_revision` alone and leaves `rendered_plan_revision` behind; that is exactly the stale-result state CLIP-132 wants
- pricing: T213's `freezeWork` prices a run with 0 observation calls and `SkipFlow`/`SkipNarration`; a narration target skips the flow, a flow or both target skips nothing, so no new pricing shape is needed
- the quote must bind the plan revision it was taken against; `QuoteInputDigest` covers project settings but not the saved plan, so add the revision to the revise quote's binding and refuse a changed one with `ErrQuoteChanged`
- stages: reuse T213's `flow` and `narrate` stage names so CLIP-78's progress and CLIP-88's diagnostics need no new vocabulary; there is no prepare, render, save or cleanup stage in this job
- unchanged: manual correction, rerender, preview, download and finalization stay credit-free (CLIP-20) — this is the single charged action in ②
