# T254 ② runs the browser render with its own progress and cancellation
> st:todo | ssot:CLIP-156 CLIP-79 CLIP-34 CLIP-152 | base:CLIP@37 | dep:T253 T247

## goal
Choosing the browser kind runs the render inside ②, showing real progress across the encode and the store, cancellable there, and never the focused job view.

## acceptance
- [ ] a browser render shows its real progress in ②, covering the encode and the store that completes it
- [ ] it is cancellable in ②, and cancelling stops the work and leaves the plan and the previous result standing
- [ ] the focused job view never opens for it, and the settings, steps and correction controls stay where they are
- [ ] leaving the page ends the render while the project keeps its plan and its previous result
- [ ] a server render keeps its focused view and its own cancellation, unchanged
- [ ] the page stays interactive while the render runs
- [ ] vitest: the browser render reports progress through both phases in ②; cancelling stops it and preserves the previous result; unmounting ends it; the focused view never opens
- [ ] verify: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- CLIP-126 closed at r37 with no wall-clock committed: the progress names the stage it is on — encode, then store — and never an estimate, a remaining time or a slow-run state of its own; a long render is a slow success
- the render runs in the Worker T251 set up; ② holds a handle carrying progress, a cancel and a promise, and the Worker is terminated on cancel and on unmount
- progress is one scale across both phases — frames encoded, then bytes stored — so the owner sees one bar rather than two that each restart; `ProgressBar` is determinate here because both totals are known
- this render is NOT a `generation_jobs` row, so `useClipGeneration`'s `busy` and the focused-view branch in `ClipPage` must not see it; it is local state beside them, and CLIP-78's view stays for server jobs alone
- the dock's 렌더하기 (T247) is where the kind is chosen; this task gives that choice its browser path and leaves the server path untouched
- leaving the page ending the render is CLIP-156's own decision, so no leave-confirmation dialog is added for it
