# T168 Replace the information frame with an unplated label/value pair and retune the disclosure pill
> st:todo | ssot:CDS-30 CDS-31 CDS-69 CDS-16 CDS-44 | base:CDS@15 ARCH@2 | dep:T166

## goal
Information reads as a small dimmed label over a crisp value with no shape behind it, and the disclosure keeps the only pill left.

## acceptance
- [ ] `role="info"` renders unplated: `t.label` 36 `text.muted` +0.08em above `t.caption` 44 white, both with `stroke.dark` 4 px and `shadow.text`, CENTER column
- [ ] the CDS-69 drawn frame family added by T163 is removed — the frame assets, the variant selection and the `info.Frame` plumbing in `media/composition_roles.go` and `media/composition_header.go`
- [ ] the disclosure badge keeps `radius.chip`, takes padding 4 vertical / 8 horizontal and `t.badge` 32/800, white on `badge.ad`, with no motion or accent
- [ ] brightness sampling now runs for the caption, both region blocks and the information pair; the plated-element exemption is gone
- [ ] `arrangeDeclaredHeader` still aligns the disclosure and any header-positioned information on one row with the new padding
- [ ] test: a label/value pair over a bright frame gains the scrim and over a dark frame does not
- [ ] test: the disclosure's measured pill height matches 32 px text plus 4 px padding top and bottom, in all three ratios
- [ ] test: no manifest element carries a rounded plate except the disclosure
- [ ] `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...`

## impl notes
- T163 shipped the drawn frame family and r15 retires it before it ever rendered in production; remove rather than deprecate, and delete its assets so no unused SVG stays embedded
- the label/value pair is the same typographic idea as the intro block's two slots — small dimmed over crisp — so share the measurement helper with T167 rather than writing it twice
- the disclosure is the single exception to "no pills": CDS-31's reason is that it has to read as an imposed marker, so do not restyle it toward the rest
- `pad.chip` is already 4/8 after T166; read it from the token, never a literal (ARCH-21)
