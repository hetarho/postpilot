# T700 Record when post photos, post videos and clip sources were shot

## goal
Read the shooting time in the browser when a photo, post video or clip source is added, and store it, so CLIP-218 can place footage by capture order.

## acceptance
- [ ] JPEG photos: before decoding or re-encoding, the browser reads EXIF `DateTimeOriginal` (0x9003), with `OffsetTimeOriginal` (0x9011) when present, from the original file's APP1. It sends the value as optional `captured_at` (RFC 3339) on `ConfirmUpload`, beside the browser-measured size, and the server stores it on `images.captured_at`. Other formats, and files without the tag, send nothing.
- [ ] Videos, both post videos (through the same `ConfirmUpload`) and clip sources: the browser reads the MP4/MOV `mvhd` creation time. Mediabunny metadata is used when it exposes the value; otherwise the `moov/mvhd` box is parsed from the bounded range reads already made. A zero, or a value before 2000, counts as absent. Post videos store it on `videos.captured_at`, and clip sources send it in the source manifest and store it on `clip_source_leases.captured_at`.
- [ ] The value never enters the source fingerprint, and a source keeps its existing identity.
- [ ] Rows written before this task read as no capture time.
- [ ] Tests:
  - `shared/lib/media` exif: `reads DateTimeOriginal with offset`, `ignores a JPEG without EXIF`, `ignores non-JPEG`.
  - `shared/lib/media` mvhd: `reads creation time`, `treats 1904 epoch zero as absent`.
  - The upload and manifest tests carry `captured_at`.
  - Backend: store round-trips for `images`, `videos` and `clip_source_leases`, and `TestFingerprintIgnoresCaptureTime`.
- [ ] Relevant vitest, go test, `pnpm lint`, `pnpm lint:fsd` and proto generation pass. No new npm dependency is added, because a lockfile change moves ink provenance in CI.

## impl notes
- The EXIF reader is a small hand-written parser of the JPEG APP1 TIFF structure, reading IFD0 → ExifIFD pointer (0x8769) → 0x9003 and 0x9011, with both byte orders. It reads at most the first 128 KiB of the file.
- The `mvhd` time counts seconds since 1904-01-01 UTC; handle both version 0 (32-bit) and version 1 (64-bit).
- Use three migrations or one, as long as every column is bare `TEXT` and the sqlc queries stay ASCII-only.
- Proto: add `optional string captured_at` to `ConfirmUploadRequest` and to the clip source manifest entry, using the next free numbers. Photos and videos both confirm through `ConfirmUploadRequest`, and the upload's `AttachmentKind` tells them apart.
- A clip source carried from a post by T692 is re-read from its blob, so it gets its time the same way.
- Capture order from file names (the camera file sequence) needs no storage, because file names are stored already. T701 derives it.
