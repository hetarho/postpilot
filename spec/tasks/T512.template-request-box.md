# T512 Ask the 글 작성 모델 from the template editor, and start a template from a post

## goal
An owner types or pastes what they want into the editor's box, sees the 글 작성 모델's answer in the draft with the separated wishes and an undo, and can open a new template from a post's ③.

## acceptance
- [ ] Limits: `TEMPLATE_REQUEST_MAX_CHARS` (default 12000) and `TEMPLATE_MAX_PER_ACCOUNT` (default 50) are mirrored through `VITE_TEMPLATE_REQUEST_MAX_CHARS` and `VITE_TEMPLATE_MAX_PER_ACCOUNT` in `shared/config` and `entities/template/config`, making ten mirrored limits (TMPL-6).
- [ ] Placement: `features/request-template` renders the box at the top of the editor, above both columns and below the back link and page title. It is open on `/templates/new` while name, description, title area and body are all blank or a 참고 글 chip is attached; otherwise it is a collapsed `AI에게 요청` button that opens it, and collapsing keeps the typed text.
- [ ] The box is an auto-growing `Textarea` (the `ReviseForm` pattern) with the placeholder 원하는 템플릿을 설명하거나 참고할 글을 붙여넣으세요, a live counter to `TEMPLATE_REQUEST_MAX_CHARS`, a send button, and beside it the write model's label with `약 n 크레딧` from `EstimateTemplateRequest`, `무료` for a free model, and no figure when unavailable.
- [ ] Disabled with one stated reason: no usable write model (`useStageSelection('write')` with no selection or an unavailable one) shows the generation's blocked-model copy and a link to `/ai-models` (the `StartCheckSheet` pattern); a new template while the directory holds `TEMPLATE_MAX_PER_ACCOUNT` templates shows the limit reason; over the counter limit, or blank text with no chip, disables send. A stored template's box is never disabled by the cap.
- [ ] Send calls `StartTemplateRequest` with the selected write ref, the UI locale's language, the trimmed text, the draft's name, description, title area and body as they stand, the template id on `/templates/$templateId`, and the chip's slug. A start refusal renders in place through `AppFailureMessage` and keeps the text.
- [ ] While the job is queued or running (`useJob(jobId)`): name, description, both numbers, the 블록/원문 switch, both compositions and 저장 are disabled; the box shows progress and 취소, which calls `CancelTemplateRequest`. Leaving the editor in-app or by `beforeunload` warns with request copy (요청이 취소돼요), and confirming cancels the request and leaves; this joins the existing dirty guard in one `useBlocker`.
- [ ] Done: `GetTemplateRequestResult` replaces the draft's name, description, title area and body (the two numbers untouched); the builder reseeds from the new value; the draft is dirty; the box empties. The wishes, if any, are listed under the box headed 지침에 넣을 내용 with a `지침 만들기` link to `/guidelines?new=1`, which opens an empty `CreateGuidelineSheet` once (the guidelines page validates `{new?: boolean}` and drops it on close). `요청 전으로 되돌리기` restores all four fields from the snapshot taken at send, and stays until the next send or leaving the editor; undoing hides the wishes.
- [ ] Failed: `FailureNotice` with the job's reason (an `INSUFFICIENT_CREDITS` failure links to `/plans` as `ClipFailureNotice` does), the box keeps its text and the draft is untouched. Cancelled: the box returns to idle with its text.
- [ ] ③ entry (POST-103): `EditorFinishPanel` renders `이 글 형식으로 템플릿 만들기` beside `ExtractMemoriesButton` whenever it renders that button, as a link to `/templates/new?from=<slug>`; it starts nothing and changes nothing on the post. `EditorPage.finish.test.tsx`'s order expectation is updated.
- [ ] `/templates/new` validates `{from?: string}` (`pages/template/model/search.ts`, `validateSearch` on `newTemplateRoute`). With `from`, the box opens with a `참고 글: <제목>` chip (title from `usePost(slug)`, 제목 없음 when blank) and a remove control; an unreadable post shows no chip and a one-line notice. The chip does not count toward the counter. The create redirect's `replace` drops the search.
- [ ] Tests cover: the open/collapsed rules, each disabled reason, the cost line (credits, 무료, unavailable), the send payload with chip and template id, the lock while running, 취소, leave-guard cancel, the result applied with dirty and reseed, wishes with the 지침 만들기 link, undo, failure keeping the text, the ③ link, the chip from the search param; `GrammarStaysInternal.test.tsx` and the existing template page tests pass. ARCH-25 verification runs green.

## impl notes
- Hooks: start, cancel, result and estimate are connect-query mutations/queries in `entities/template/api` (bare hooks are entity `api`, →ARCH-14); the box with its state machine (`idle → running → done | failed | cancelled`) is `features/request-template`; the page composes it and owns the draft, the snapshot and the lock.
- The builder reseeds itself when the value is not what it last emitted (`TemplateComposition`'s `emitted` ref); a result replacing the draft goes through the page's `setDraft`, so nothing else is needed for the reseed. The draft text replacing the stored one is not trimmed (`body` and `title_area` are canonical, TMPL-8).
- Polling uses `useJob` (`entities/generation-job`), 2 s interval, which stops at a terminal state; fetch the result once on `done`. Failure rendering goes through `appFailureFromProto` / `FailureNotice` as `VoiceRunStatus` does.
- Leave guard: today `guard = !leavingAfterSave.current && dirty && !pending` (`TemplatePage.tsx` ~l.272). Make it `running || that`, and pick the dialog copy by which held. On a confirmed leave call `CancelTemplateRequest` without awaiting; on `beforeunload` the cancel is best effort and a request that keeps running is still charged confirmed usage only.
- The new-guideline link: `CreateGuidelineSheet` keeps `open` in local state, so give it an `initialOpen` prop and have `GuidelinesPage` pass it from the validated search, clearing the param with `navigate({ search: {}, replace: true })` when the sheet closes.
