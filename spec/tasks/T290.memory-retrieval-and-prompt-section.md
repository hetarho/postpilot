# T290 retrieval, the frozen [기억] section and the draft's opt-in
> st:todo | ssot:MEM-6 MEM-7 MEM-8 MEM-18 MEM-19 MEM-20 MEM-21 MEM-22 GEN-5 GEN-14 GEN-15 GEN-30 GUIDE-28 POST-71 ARCH-24 | base:MEM@1 GEN@7 GUIDE@3 POST@8 | dep:T289

## goal
Retrieve a post's memories by tag, freeze them at enqueue and render them as one `[기억]` section in the per-post half of the write prompt.

## acceptance
- [ ] posts carry `use_memory`, default false, saved through `SavePostGenerationOptions` presence-aware, changing no status, revision, baseline or learning eligibility
- [ ] retrieval: `preference` and `persona` are candidates for every post, `place` `person` and `history` only when a tag matches; score is the count of distinct matching tags; ties break by `last_seen_at` then `created_at` descending; at most `MemoryInjectMax` are returned
- [ ] a tag matches when it occurs as a substring of the folded key text; the key is the memo, the 가제, the template answers and the observation `objects` and `visible_text` of the post's photos and videos
- [ ] folding is Unicode lower-casing plus whitespace and punctuation collapse, using the Go standard library alone — no morphology, stemming, vector or similarity dependency
- [ ] `MemoriesForPrompt` is a consumer-owned port in `generation/ports.go` with its adapter in `cmd/api`, mirroring `GuidelinesForPrompt`; the generation context receives texts and never a memory row
- [ ] StartGeneration resolves and freezes the selected texts into the payload; the handler reads only the payload; editing or deleting a memory after the start changes nothing in flight, across restart-resume and retry
- [ ] the write prompt renders one `[기억]` section in the PER-POST half beside the memo and the observations, never in the stable prefix, closed by a line naming the memories as material for this post and stating that a guideline outranks them
- [ ] a post with `use_memory` off produces a write prompt byte-identical to T287's goldens, asserted directly
- [ ] the revise prompt carries no memories in any case
- [ ] a payload without the member decodes as no memories
- [ ] tests: a retrieval table covering both halves of the enum, the tie-break and the cap; a golden for the section; the byte-identity assertion; the pinned payload wire shape
- [ ] ARCH-26 and ARCH-28 pass

## impl notes
- retrieval lives in `internal/memory` and answers texts only, so `internal/generation` never learns the row shape (ARCH-7)
- substring matching is the deliberate choice over token equality: Korean agglutination means `연남동` has to match `연남동에서`, and VOICE-51 rules out a morphological analyser. A short tag can over-match; that is the accepted cost and the reason `MemoryTagsMax` is small
- the `[기억]` section goes into the per-post string, NOT into the stable builder where the template brief and the guideline section sit. This is the one place the pattern differs from GUIDE-15, and the reason is that the selected set differs per post while the stable prefix is what the provider cache and every golden rest on (MEM-20)
- the closing line carries the grounding permission too, appended only when the section exists, the way `templateFactLegend` is appended only when the brief carries a fact — a post with the option off must not read a word about a source it has none of
- `use_memory` is a generation option, so it rides `SavePostGenerationOptions` rather than the draft save; the column defaults false so every existing row decodes as off
