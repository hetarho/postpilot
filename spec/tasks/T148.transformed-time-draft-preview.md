## goal
Make the browser draft preview and timeline use the same transformed-time mapping, fixed rate and source-audio authority as the saved assembly.

## acceptance
- [ ] One entity-level timeline implementation replaces raw `end-start` calculations in edit-plan, timeline and draft-preview models and maps all six rates, transitions and half-open cut boundaries identically to the backend contract.
- [ ] Output-to-source seeking uses the cut's fixed rate, source-to-output display uses its inverse and observation evidence remains labelled in source time; playhead, scrub, current-frame actions and active-cut highlighting remain stable at 0.5x and 2x.
- [ ] The draft player applies `HTMLMediaElement.playbackRate`, enables supported pitch preservation and never treats browser master mute or per-cut volume as source-audio permission; an off source stays muted even when preview audio is enabled.
- [ ] Rate, range or order changes recompute cut and resolved element placement but preserve explicit caption and rapid-phrase output milliseconds exactly; invalid windows remain visible and block save/render without proportional retiming or deletion.
- [ ] Transition preview keeps at most the existing two video elements, aligns opacity/audio gain on transformed time and separately labels browser frame timing and final-only loudness limits without claiming rate/audio-state mismatch as parity.
- [ ] Missing current originals retain text/timing editing and the separately revision-labelled previous result, while the draft preview never substitutes that result for changed transformed footage.
- [ ] Entity and component tests cover six-rate duration/seek inverses, cumulative boundaries, transition overlap, explicit-window invalidation, audio on/off, pitch-preservation setup, playback drift correction and the two-player bound.
- [ ] Browser tests cover ko/en, keyboard seeking and narrow mobile layouts without focus theft or a second vertical scroller.
- [ ] Run applicable ARCH-25, ARCH-28 and ARCH-29 checks with deterministic protobuf output and dirty-workspace snapshot protection.

## impl notes
- Place pure rate/duration/source-output conversion helpers in `entities/clip-project/model`; `ClipDraftPreview` and correction UI consume that public entity API rather than reimplementing arithmetic.
- Keep integer milliseconds as UI state and use the T142 rounding rule at conversion boundaries. Frame actions snap to the displayed 30 fps output frame, then map that instant back to source time through the selected cut rate.
- Set standard `preservesPitch = true` and the prefixed equivalent only when present. Unsupported browser timing remains an explicit preview limitation; it never changes the saved plan or exported media.
- Preserve the current autoplay/master-audio control as a preview-only gate layered after source permission and per-cut gain.
