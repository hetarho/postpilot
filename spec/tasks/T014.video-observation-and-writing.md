# T014 Observe videos, write from them and validate VIDEO blocks
> st:todo | ssot:VIDEO-8 VIDEO-9 VIDEO-10 VIDEO-11 VIDEO-12 VIDEO-13 VIDEO-18 GEN-2 GEN-5 GEN-7 GEN-13 GEN-14 GEN-23 GEN-41 | base:VIDEO@1 GEN@2 MODEL@3 ARCH@1 | dep:T012 T013 T010

## goal
Make generation observe each attached video in its own call by signed URL, freeze and reuse video observations like photo observations, feed 영상 관찰 and the video filenames to the writer, validate VIDEO blocks, and refuse a start whose observe model cannot take video.

## acceptance
- [ ] StartGeneration and StartWriteExperiment with at least one attached video refuse an observe model without `VideoInput` before enqueue with `FailedPrecondition` `MODEL_VIDEO_UNSUPPORTED` and param `model`; a post with photos only is unaffected; a post with videos and no observe model gets the existing missing-observe-model refusal first
- [ ] the reobserve picker contract covers videos: `resolveObserveSelection`, `freezeObserveSelection`, `frozenObserveSelection`, `mergeObservations` and the reusable-entry rule treat a video like a photo by filename (a video entry is reusable when any of scene, mood, visible text, objects, people, events or speech is set)
- [ ] the observe stage runs the photo batches first (unchanged: `ceil(photos/OBSERVE_BATCH_SIZE)` calls), then one call per frozen video with a `VideoPart` whose URL is a presigned GET minted for that call (`PRESIGN_GET_TTL`) and the video observation system prompt; the observations schema for video requires `events` (array of strings) and `speech` (string) beside the photo fields; progress totals photos + videos and reports 1 per video; a failure names `영상 관찰` in its provider-call error
- [ ] the planned calls stated to the admitter add one observe call per frozen video at the observation completion budget (→VIDEO-13); a reuse-everything run plans zero video calls (test with a stubbed admitter)
- [ ] the write prompt lists 첨부 사진 파일명 and 첨부 영상 파일명 separately, renders 영상 관찰 (with `events` and `speech`) after 사진 관찰, asks for VIDEO blocks placed where natural, and the per-post material is byte-identical to today for a post without videos (golden fixtures updated only for the new video fixture)
- [ ] `post_content.schema.json` allows `VIDEO`; the validator applies the IMAGE field rules to VIDEO; `FilterAttachments` matches `IMAGE.file` against photo filenames and `VIDEO.file` against video filenames, dropping and logging the rest; revision filters both with the fresh attachment snapshot
- [ ] the observation persisted for a video carries `events` and `speech` and reaches the browser through `GetPost`; the FE reads them in T015
- [ ] tests: stubbed provider counts `ceil(P/4) + V` calls and asserts a `video_url` part per video; frozen selection with a video; non-shrinking merged snapshot with mixed kinds; validator and filter VIDEO cases; precondition refusal; prompt snapshot with a video fixture; no write transaction across a provider call still holds
- [ ] `cd backend && test -z "$(gofmt -l .)" && go vet ./... && go build ./... && go test ./...` passes

## impl notes
- generation input: T012 gives `generation.Image{Filename, Key, Kind, ContentType, DurationMs}`; add helpers `photosOf(images)` / `videosOf(images)`; keep every selection/merge function on the one list
- URL minting: a new consumer-owned port in `generation/ports.go` — `type VideoLinker interface { PresignGet(ctx, key string, ttl time.Duration) (string, error) }` — satisfied by the post context's storage adapter and wired in `cmd/api`; mint inside the loop right before `Complete` so the URL's clock starts at the call ← the call is bounded by `LLM_STAGE_TIMEOUT` (5 min) and the URL lives 10 min; the API never reads video bytes. Local MinIO is not reachable by the provider, so end-to-end video observation is a production/staging check; unit tests use a fake `LLM`
- observe prompts (`prompts.go`): `ObserveVideoPrompt` — the photo observe prompt's facts-only rule plus: `events`는 일어난 일을 시간 순서대로 짧은 사실 문장으로, `speech`는 들린 말의 요약(들리지 않으면 빈 문자열); one video per call so the `files:` line names exactly one file; schema `schemas/video_observations.schema.json` = observations schema + `events` `speech` required; `parseObservations` unchanged (the struct gains optional fields)
- budget: `s.budget.Observation()` for a video call (VIDEO-13 says one full batch's budget); planned calls: find where StartGeneration builds the observe `PlannedCall` count from `ceil(n/batch)` and add `len(videos to observe)` with the same budget figure (same ref + same budget collapse into one entry with the summed count, QUOTA-32)
- precondition: `ErrVideoUnsupported` in `generation/errors.go`; both start paths check `info.VideoInput` via `s.models.Resolve(observeRef)` when any attached video exists; rpc maps to `connect.CodeFailedPrecondition` with `ErrorInfo` reason `MODEL_VIDEO_UNSUPPORTED` and param `model` (allowlisted) — the FE catalog entry is T016
- write prompt (`prompts.go`): extend `photoMaterial` building — `observationsForPrompt` splits by kind; render `\n영상 관찰: ` + JSON only when videos exist; the filename line becomes two lines only when videos exist so the no-video byte-identity holds; add one rule line under the IMAGE placement rule: `VIDEO 블록은 첨부 영상 파일명만 쓰고, 영상이 보여주는 내용이 글에서 언급되는 위치에 놓으세요.`
- this task edits `prompts.go` after T010 (which changed the template legend in the same file) — hence the dep
- `blocks.go` / `attach.go`: `BlockVideo` constant, validator branch identical to IMAGE, `FilterAttachments(content, photoNames, videoNames)`; update the two callers (write and revise handlers)
