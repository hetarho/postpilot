# T149 Add cut, split and fixed-rate editing controls

## goal
Let the owner create footage-only cuts, split existing cuts and choose supported rates inside the preview-led correction workflow.

## acceptance
- [ ] An observed scene offers an accessible add-cut action with source-range handles and precise source-time fields; the new draft cut uses injected canonical UUID identity and the T144 request provenance without editing the observation.
- [ ] The selected cut offers playhead and precise-time split actions plus a fixed-rate control limited to the server-authorized choices; unsupported slow choices explain cadence refusal and cannot be submitted.
- [ ] ADD creates a 1x text-free hard cut and SPLIT keeps parent content on the left and a text-free right cut, preserving server-owned binding/audio data and surfacing any now-invalid authored interval for correction.
- [ ] Add, split, rate, trim, reorder and delete recompute transformed duration, selection, playhead and observation usage; each observed scene lists intersecting saved cut numbers and rates in plan order with source-time ranges.
- [ ] Every new operation participates in the existing 100-transaction undo/redo model, including an accepted save; undo submits a new optimistic revision and never restores an old revision number or forged retired identity.
- [ ] Save conflicts, invalid overlap, evidence bounds and timing failures preserve the complete local draft and identify the affected cut; no operation silently changes rate, range, text, association or source order.
- [ ] Pointer operations have touch and keyboard alternatives, controls meet the existing touch target, and the preview remains visible with one document scroller at 320, 360, 390 and 430 px widths and an open mobile keyboard.
- [ ] Reducer, timeline, observation viewer, correction workspace, page integration and browser tests cover add/split/remove/reorder/rate/undo, UUID stability, same-source adjacency, invalid text and ko/en accessibility.
- [ ] Run applicable ARCH-25, ARCH-28 and ARCH-29 checks with deterministic protobuf output and dirty-workspace snapshot protection.

## impl notes
- Extend the existing reducer with `addCut`, `splitCut` and `rate` transactions. Generate `owner-<canonical UUIDv4>` through an injected identity function so tests are deterministic; creation provenance is sent only until the first accepted save.
- Compose observation UI and correction through a page-owned `onAddCut` callback; do not import one feature slice from another. Reuse or extend shared range controls only when the existing accessible primitives cannot express the source selection.
- ADD uses the chosen observed half-open range and server-projected focal/defaults. SPLIT keeps the original id/range start and all cut-bound text on the left, while the new right side has no copies/elements; do not duplicate claims.
- Keep explicit captions and phrases at their stored output milliseconds after any operation. Validation, not automatic repair, tells the owner when the transformed cut became too short.
