# T177 Release QA viewing checklist
> st:doing@260916.qa | ssot:CDS-53 CDS-70 CLIP-27 ARCH-24 | base:CDS@18 CLIP@24 ARCH@2 | dep:T176

## goal
Run CDS-53's owner review over rendered clips and record what it finds.

## acceptance
- [ ] three clips are rendered, one per intro/outro preset pair currently selectable, each carrying a disclosure badge, an information pair and at least one caption
- [ ] each clip is reviewed muted and again with its configured source audio, and the CDS-53 questions are answered per clip: two facts recalled from the muted pass, subject known within 1.5 s, copy reads as editor-placed, tone constant, disclosure legible
- [ ] the same clips are checked for the assembly cases CDS-53 names — a same-source split, every rate preset, a transition overlap, a transformed caption boundary, an absent optional field — with no unintended audio, temporal gap, stale caption or invented text
- [ ] findings are written to `docs/design/clip-release-qa-YYMMDD.md` with the date, the clip sources and one line per question, and anything failing becomes a review finding or an update-ssot request rather than a silent fix here
- [ ] no automated gate beyond ARCH-26 on any constant this task changes; the review is manual by nature and the document is its evidence

## impl notes
- this replaces the viewing half of the retired T110; the platform overlay measurement it carried is gone with CDS-10 and CDS-11
- render through a clip project's step ③, or the Docker media-smoke target with `CLIP_SMOKE_EXPORT` set to keep its own renders; the smoke needs Docker, which does not currently start on the owner's machine, so the project path is the reliable one
- the owner watches; an agent session can prepare the renders, list the questions and write the document from the owner's answers
- CDS-53 is a standing quality bar, so this task is repeatable — number a later run separately rather than reopening this one
