# T065 일괄 편집: the paste box, the diff preview and the export
> st:todo | ssot:MODEL-54 MODEL-55 MODEL-56 MODEL-52 | base:MODEL@7 ARCH@2 | dep:T064

## goal
Give 모델 관리 one 일괄 편집 surface that exports the current document, previews a pasted one as a per-purpose diff, and applies it on confirmation.

## acceptance
- [ ] 모델 관리 carries exactly one 일괄 편집 entry shared by the five tabs — not a control per tab — and it opens over the catalog without losing the tab underneath
- [ ] the surface shows the current document (from `ExportCatalogDocument`) in a copyable form and a paste box for the operator's own
- [ ] 미리보기 calls `PreviewCatalogDocument` and renders, per purpose, what would be registered, what would be deregistered and what already holds; nothing is written until 확정
- [ ] the deregistration list is visually the loud half of the diff, and a purpose absent from the document is shown as untouched rather than as an empty diff
- [ ] rejected lines render with their line number, the offending text and the cause, and 확정 is unavailable while any rejection stands
- [ ] a failed live read renders the fetch error and no diff
- [ ] 확정 sends the same document text to `ApplyCatalogDocument`, then invalidates the catalog query so every tab reflects the new registrations
- [ ] the paste box keeps its text across a failed preview so the operator can fix one line without re-pasting
- [ ] placement: UI in `frontend/src/features/manage-model-catalog/ui`, pure diff shaping in that slice's `model`, the three calls in `entities/model-catalog/api` beside the existing hooks (ARCH-14, ARCH-15)
- [ ] every generic control is a `shared/ui` primitive and classes resolve to registered tokens (ARCH-20)
- [ ] a vitest beside the code covers: a diff with adds and removes, a document with rejected lines keeping 확정 unavailable, an untouched purpose, and 확정 issuing the apply call with the pasted text
- [ ] `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web` (ARCH-25)

## impl notes
- the entry belongs to `ModelCatalogManager` rather than to a tab: one document names any purpose (MODEL-56), so a per-tab control would misrepresent what a paste changes
- diff shaping is pure and lives in the slice's `model` segment beside `catalog-view.ts`; the server already returns the three per-purpose lists, so the client sorts and groups them and invents no comparison of its own
- the preview response is display state only — 확정 re-sends the document text, never a preview id (MODEL-54), so the component keeps the text as the source of truth
- copy is Korean admin copy local to this surface; the rejection causes are rendered from the server's cause strings through a local map, not through the FE reason catalog (see T064)
- no new dependency: the textarea, buttons and the diff list are existing `shared/ui` primitives and the calls reuse the Connect client `entities/model-catalog/api` already holds
