## goal
Each section list page's floating button opens that section's creation directly — 새 글 / 새 영상 · 새 템플릿 · 새 말투 · 새 지침 — with no menu, scrim or second step.

## acceptance
- [ ] `ChannelActions({ channel?, section, className })` renders one extended link button (plus glyph + label) in `ActionBar dock="list"`: blog `새 글` → `/posts/new`, clip channel X `새 영상` → `/clips/new?channel=X`, `새 템플릿` → `/templates/new` or `/video-templates/new?channel=X`, `새 말투` → `/voices?new=1` (`&channel=X`), `새 지침` → `/guidelines?new=1` or `/video-guidelines?new=1&channel=X`
- [ ] 새 글 / 새 영상 records the channel creation entry before navigating, so the editor and clip workspace return to the channel
- [ ] no `role="menu"`, scrim or `aria-haspopup` remains on section pages; the `FloatingActionMenu` primitive, its test and its export are removed
- [ ] the button stays on the eight section list pages only (not on the editor, clip workspace, settings or other pages)
- [ ] tests pass and cover the change: `widgets/channel-actions` test (label and target per section and channel, creation entry, absence on writing screens), updated page tests (posts, clips, templates, video templates, voices, guidelines via `ConfigurationHosts`), `app/routes/navigation-hierarchy.test.tsx`

## impl notes
- The button is a TanStack `Link` with `to` and `search` (not a query string in `to`), styled `buttonStyles({ variant: 'cta', className: 'rounded-full' })` with a `Plus` glyph, so the list dock gives it its own shadow (THEME-24) and its shape matches T721's closed state.
- i18n `channel` namespace keeps only the five button labels (`button.work|video|templates|voices|guidelines`); the `menu.*`, `create.*` and `close` keys go.
- Keep `NavigationLinkProps`' anchor pass-through from T721; it is generic and the shell's link already honours a supplied `onClick`.
