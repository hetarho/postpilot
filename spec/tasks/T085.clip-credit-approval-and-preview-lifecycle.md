# T085 Clip credit approval and preview lifecycle

## goal
Show and explicitly approve the maximum before generation, preserve local previews throughout the attempt and explain its final credit settlement.

## acceptance
- [ ] before source selection, ko/en copy discloses external analysis of compressed footage and audible speech, service-side transient cleanup and the distinction from provider retention
- [ ] after uploads and settings are ready, a quote is displayed as a maximum rather than an actual-cost prediction; the explicit `maximum N credits, approve and generate` action sends exactly the displayed quote and maximum once
- [ ] changed files, project/template answers, model choices or expired quotes invalidate approval; dirty settings must be saved before quoting, and neither a refreshed quote nor a larger server requirement automatically starts paid work
- [ ] insufficient credits and incompatible inputs/pricing have readable reasons beside generation; master sees the exemption without bypassing compatibility/execution bounds, and saved model selections are not cleared merely for affordability
- [ ] source previews, filenames and progress remain visible while the accepted job is queued, preparing, analyzing, planning or rendering; job acceptance alone does not revoke object URLs or discard Files
- [ ] terminal success/failure releases every File/object URL and preserves only filename/status summaries; component unmount, route change, logout or refresh also releases local media without canceling/restarting the accepted server job
- [ ] local media is associated with its accepted job id, so stale poll responses, another tab, an old terminal job or an ambiguous start response cannot clear a newly selected batch or trigger a duplicate start
- [ ] approved maximum, actual reservation, final charge and refund are shown distinctly; terminal job state with pending settlement shows a settling state until authoritative accounting arrives, not an assumed zero
- [ ] a failure preserves the previous result and exposes stage, safe reason and settlement; another AI attempt requires source reselection and fresh explicit approval, while manual corrections, preview, download and rerender remain credit-free and quote-independent
- [ ] component/session/query tests cover preview lifetime through all stages, one-time revoke, ownership races, unmount, double click, ambiguous start, quote invalidation/expiry, settlement lag, refunded no-usage failure, partial charge and master
- [ ] responsive browser checks at phone and desktop widths verify usable video controls, accessible approval/reason text and no horizontal overflow; ARCH-25 through ARCH-28 and ARCH-31 local gates pass without a live provider call

## impl notes
- use `entities/clip` and `shared/api` for quote/accounting mappings, `features/generate-clip` for explicit approval and request guards, `features/upload-clip-sources` for runtime media ownership, and `pages/clip` only for composition; no cross-feature implementation import
- split source-session ownership into `markOwned(jobId)` and terminal release: ownership removes the batch from selectable/cancelable upload state but keeps the local previews, while terminal release revokes URLs and drops File references exactly once, retaining only primitive display summaries
- expose ownership/terminal callbacks through slice public APIs and compose them on the page; associate epoch, batch and job identity before applying poll transitions, replacing the current accepted-job `finishAttempt` call and matching page effect
- keep Files, object URLs and abort controllers in the active runtime session only; neither query cache nor browser persistence stores them, and logout cleanup must not leave a provider/model/source session reference behind
- quote loading may retry a read-only failure within existing query policy, but start keeps `retry:false`, an in-flight guard and no automatic retry on token refresh/focus/reconnect; ambiguous acceptance is resolved by owned-job reads, not by submitting generation again
- approval is the click on the displayed maximum action, not a persistent prechecked checkbox; invalidate immediately on any bound input change, fetch a replacement quote without generating, and require another click even if its amount happens to match
- poll accounting while the job is terminal but settlement is pending; use the returned job id to reject stale projections, distinguish absent amounts from zero and invalidate the plan/header balance after hold and settlement transitions
- retain latest successful result preview during a new attempt; show the source previews separately so progress never replaces the result with a blank area, and never label refunded unknown usage as an OpenRouter zero bill
- keep free-rerender mutation/model guards separate from AI approval; an AI ceiling refusal must not disable editing, rerendering a saved plan, downloading or reading the project
- use shared controls, existing tokens and both locale catalogs; deferred CLIP-35 analysis reuse and unrelated shell/navigation changes are outside this task
