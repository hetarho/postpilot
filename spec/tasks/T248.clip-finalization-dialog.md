# T248 확정하기 opens the finalization dialog
> st:todo | ssot:CLIP-75 CLIP-109 CLIP-152 | base:CLIP@36 | dep:T247

## goal
확정하기 opens one confirmation dialog that states what confirming ends, lists the unresolved notices and carries the confirming action, and it stands only while a render matches the current plan.

## acceptance
- [ ] pressing 확정하기 flushes pending saves, then opens a dialog rather than finalizing
- [ ] the dialog states that confirming deletes the originals and ends editing, lists every unresolved notice with the cut or caption it names, and carries the confirming action beside a way out
- [ ] a stale or absent render explains that 렌더하기 is required first, said where the owner presses, with no dialog opening
- [ ] every other refusal (busy, already finalized, invalid plan, unavailable) is said in the same place and opens no dialog
- [ ] a render of either kind satisfies the match
- [ ] confirming from the dialog finalizes and opens ③, exactly as before
- [ ] no finalization copy and no notice list stands in ②'s page
- [ ] vitest: 확정하기 opens the dialog with the notices and does not finalize; the dialog's action finalizes once; an absent render keeps the dialog shut and names 렌더하기
- [ ] verify: `pnpm --filter ./frontend test` · `pnpm lint` · `pnpm lint:fsd` · `pnpm lint:style:probe && pnpm lint:style` · `pnpm build:web`

## impl notes
- `Dialog` is `Sheet` with the confirm shape and stacks over an open item sheet, which is the right order if the owner confirms with one open
- `FinalizeClipNotices` becomes the dialog's body: `finalization.notice`, the `ClipNoticeList` with `withTargets` and the refusal line; `FinalizeClipAction` stays the dock's button and gains the opening behaviour
- the flush happens BEFORE the dialog opens, not on confirm, so the listed notices are the saved plan's; the confirm path then calls `action.confirm()` unchanged
- `action.uncertain` and `action.failure` keep their place beside the button — they are reasons a dock may carry (THEME-39) and must be seen without opening anything
- `finalization.refusal.stale_render` and `missing_render` are re-worded to name 렌더하기; add `finalization.dialogTitle` in ko/en
