## goal
The backend accepts an untitled clip, records a reversible 확정 of the current plan, finalizes only through a posted URL or 완료로 표시, and saves the checklist ticks per clip.

## acceptance
- [ ] CreateClipProject and UpdateClipProject accept an empty or whitespace-only title (stored trimmed as `''`) and still refuse a title over `clip.TitleChars`; generation, storyline and render admission never refuse over an empty title (CLIP-130)
- [ ] new `ConfirmClipProject(project_id, expected_plan_revision)` records `confirmed_plan_revision` and `confirmed_at` for the owner's unfinalized project with a valid saved plan, ready required narration and no active attempt; it needs no render, deletes nothing, is idempotent for the same revision and refuses a stale expected revision (CLIP-75, CLIP-229)
- [ ] `ClipProject` exposes `confirmed_plan_revision`, `confirmed_at`, `can_confirm`, `confirmation_refusal` (empty | finalized | busy | invalid_plan | narration | stale), `published_url`, `published_at` and `checklist_ticks`; the project reads as confirmed exactly while `confirmed_plan_revision == edit_plan_revision`, with no write on later plan saves
- [ ] FinalizeClipProject additionally requires `confirmed_plan_revision == edit_plan_revision`, reports `unconfirmed` in `finalization_refusal` otherwise, and takes an optional `published_url`: present ⇒ validated and stored with `published_at`, empty ⇒ 완료; original deletion, finalized triggers and the existing render-match checks are unchanged (CLIP-76, CLIP-232)
- [ ] new `SaveClipPublishedUrl(project_id, url)` saves or replaces the URL of a finalized project only, refuses an invalid URL with new error code `CLIP_PUBLISHED_URL_INVALID` and refuses while a job or render of the project runs; it changes no other column
- [ ] UpdateClipProject takes presence-aware checklist ticks, saved as a JSON array and accepted on finalized projects too (advisory notes, not content)
- [ ] migration `NNNN_clip_confirmation_and_publication.sql` (next free number) adds the columns with CHECKs and a Down section; existing finalized rows keep `published_url` NULL and read as 완료
- [ ] Go tests: `backend/internal/clip/app/confirmation_test.go` (confirm success, each refusal, idempotence, plan save after confirmation reads unconfirmed, finalize refused while unconfirmed, finalize with and without URL, URL host validation per channel, SaveClipPublishedUrl on unfinalized/finalized/busy), title cases in the existing service tests, store round-trip of the new columns and rpc mapping tests including the new error code
- [ ] `pnpm gen:proto && git diff --stat -- backend/internal/gen frontend/src/shared/api/gen` shows only this task's regeneration; `cd backend && go vet ./internal/clip/... && go test -timeout 30m ./internal/clip/... ./internal/platform/db/...` passes, plus the FE error-code mirror tests under `frontend/src/shared/api`

## impl notes
- Proto (check the next unused field numbers when editing): `clip_generation.proto` gains `rpc ConfirmClipProject(ConfirmClipProjectRequest) returns (ConfirmClipProjectResponse)` and `rpc SaveClipPublishedUrl(SaveClipPublishedUrlRequest) returns (SaveClipPublishedUrlResponse)`, both answering `ClipProject project`; `FinalizeClipProjectRequest` gains `string published_url`; `UpdateClipProjectRequest` gains `ClipChecklistTicks checklist_ticks` with `message ClipChecklistTicks { repeated string ticks = 1; }` (absent preserves, present replaces — the post's `ChecklistTicks` pattern in `post.proto`). `clip.proto` `ClipProject` gains the fields listed in acceptance. `error.proto` gains `CLIP_PUBLISHED_URL_INVALID`; update the BE string mapping and FE mirror that ARCH-3's enum-walk tests pin.
- Domain/store: confirmation lives beside finalization in `backend/internal/clip/finalization.go` (pure rules: `ConfirmationRefusal(p Project) string`, `Confirmed(p Project) bool`) and `app/finalization.go` (service `ConfirmProject`, `SavePublishedURL`); store columns in `store/` with sqlc queries ASCII-only (sqlc breaks on non-ASCII comments); `pnpm gen:sql` after editing queries.
- Columns: `confirmed_plan_revision INTEGER` (NULL or >0), `confirmed_at TEXT` (both NULL or both set), `published_url TEXT`, `published_at TEXT` (both NULL or both set, URL only when `finalized_at IS NOT NULL`), `checklist_ticks TEXT NOT NULL DEFAULT '[]'`. The existing `clip_finalized_content` trigger must not list the new columns, so URL replacement and ticks stay writable after finalization; keep `confirmed_*` frozen after finalization by adding them to `clip_finalized_identity`.
- Busy/active-attempt and plan-validity checks: reuse the predicates FinalizeProject already uses; narration readiness reuses the DUB-26 readiness check finalization uses.
- URL rule, decided here (CLIP-232 says configuration): `https` scheme, host equal to or a subdomain of `naver.com` or `naver.me` for `naver_clip`, `instagram.com` for `instagram_clip`; at most `clip.PublishedURLMaxChars` (2048) characters; configuration `clip.PublishedURLHosts` in `backend/internal/clip/channel.go`. Trim whitespace; no network fetch.
- Ticks: mirror the post's tick normalization in `backend/internal/post` (find its checklist tick validation) as `clip.NormalizeChecklistTicks` in `backend/internal/clip/campaign.go`, with the same bounds constants.
- Title: change the `BoundedText(title, 1, …)` lower bound to 0 in `app/service.go` CreateProject and the UpdateProject title patch; grep generation/storyline admission for any title check and remove it.
- FE consumers adapt in later tasks (T765–T768); this task only regenerates FE code and keeps FE type-check passing (`pnpm --filter ./frontend exec tsc -b --pretty false`).
