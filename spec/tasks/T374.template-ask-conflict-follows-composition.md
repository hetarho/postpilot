## impl notes
- from review/published-quality-260924 F28
- **Decided: reset on unmount in the composition, not derived in the page.** The page cannot derive the flags from the draft. A conflicting row is deliberately left OUT of the emitted text (`TemplateComposition.tsx:76-80`, `toValidBody(…, taken)`). Neither `draft.body` nor `draft.titleArea` contains it, which is why the flag is "reported upward rather than derived by the caller" (`:242-243`). The component that raises the flag therefore owns lowering it. That covers every unmount path: the 블록→원문 switch (`TemplatePage.tsx:382-386`), and `TemplateComposition` swapping `Composition` for `Unreadable` when its value stops parsing (`:97-114`).
- In `Composition` (`entities/template/ui/TemplateComposition.tsx:244-245`), after the existing report effect, add `useEffect(() => () => onAskConflict?.(false), [onAskConflict])`, with a comment: an unmounted composition has no rows left to conflict, and a flag it raised must not outlive it.
  - The page hands over `setTitleAskConflict` / `setBodyAskConflict` (stable setters), so the cleanup runs only on unmount.
  - If the callback ever changed identity, React runs this cleanup before the report effect's next setup in the same commit, so the last word is still the current `conflicted`.
  - StrictMode's mount → unmount → mount also ends on the report.
- Do not add resets to the page's mode switch, and do not touch `titleAskLabels`, `blocked` or the flags' state (`TemplatePage.tsx:240-264`). What 원문 shows is what is saved, which is the source the page parses. The conflicting row was never in it: leaving 블록 already drops it, and returning reseeds the rows from the value. That is unchanged by this task.
- The regression tests reuse the existing helpers in that describe: `titleSection()`, `bodySection()`, `paletteButton('고정 문구')`, `renderTemplate('/templates/template-titled', { templates: [TITLED], updates })`. Both fail at HEAD: 저장 stays disabled in 원문.
