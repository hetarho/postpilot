## goal
An owner can presign, PUT and confirm a photo for a photo observation test without any post, and photos nothing uses any more are removed from storage.

## acceptance
- [ ] Deterministic, unit (fake object store and clock): CreateTestPhotoUpload returns a presigned PUT for `tests/{user}/{id}.jpg` as `image/jpeg` and records a pending row; ConfirmTestPhotoUpload refuses another owner's id (indistinguishable from unknown), missing objects, invalid dimensions and objects over the size limit, and is idempotent for an already confirmed photo; an owner at the unattached photo cap is refused with the post photo-limit failure.
- [ ] Deterministic, unit: the sweep deletes expired unattached rows with their objects, deletes `tests/` objects no row names once older than the orphan minimum age, keeps attached and unexpired photos, and one failing delete does not stop the pass.
- [ ] Deterministic, unit: affected `cd backend && go vet ./internal/experiment/... ./cmd/api/ && go test ./internal/experiment/...` plus the ARCH-24 task lint pass. Hand off cmd/api integration and the full suite to the batch gate.

## impl notes
- Mirror `voice.Service.CreatePhotoUpload` (`backend/internal/voice/service.go:413`) and `post.Service.ConfirmUpload` (`backend/internal/post/service.go:1395`, photo branch: dimension check against the same `maxImageDimension`, `Head` for the object size against the post upload size limit, `ErrObjectMissing`). Reuse post's configured limits by name rather than new numbers: the PUT TTL and max file size the post upload uses, and `UPLOAD_MAX_PHOTOS_PER_POST` as the cap on one owner's unattached ready+pending photos (MODEL-97 reuses the post count). New config only for `WRITING_TEST_PHOTO_TTL` (how long an unattached photo lives, default 24h) in `experiment/config.go`, read where the other experiment config is read in `cmd/api`.
- The service (`experiment.TestPhotos` in `test_photos.go`) exposes `Create`, `Confirm` and `ViewURL(ctx, key) (url string, expires time.Time, err error)` (a `PresignGet` with the post photo GET TTL) over an `ObjectStore` port with `PresignPut`, `PresignGet`, `Head`, `Delete`, `List`, satisfied by `storage.Bucket` (`internal/storage/r2.go`). `NewWritingTestHandler` gains a third parameter for it and `cmd/api/serve.go:244` passes it; T893 uses `ViewURL` for the review projection.
- Object key prefix const `TestPhotoPrefix = "tests/"`; the post sweep only lists `posts/` and the voice sweep only `voices/`, so this prefix is owned solely by the new sweep.
- Refusal mapping: unknown/foreign id → the existing not-found test refusal; bad dimensions/size/missing object → `WRITING_TEST_MATERIAL_INVALID`; cap reached → the failure reason post uploads use for the photo limit (find it from `UPLOAD_MAX_PHOTOS_PER_POST` handling in `post/service.go`) so the client already has its copy.
- `TestPhotoSweeper` in `experiment/test_photo_sweep.go` copies `voice/sweep.go`'s structure (expired unattached rows first, then stray objects under the prefix with the referenced set read before the listing, `minAge` guard, log-and-continue). Wire it in `cmd/api/serve.go` beside `voice.NewPhotoSweeper` (L81) with `cfg.OrphanMinAge` and `cfg.OrphanSweepInterval`.
- Handlers in `experiment/rpc/writing_test_handler.go` replace T890's `CodeUnimplemented` stubs, derive the owner with `authactor.ActingUser(ctx)` and map errors through the existing writing-test refusal mapping (L200 area).
- The photo rows and their store methods come from T891 (`store/writing_test_photos.go`); signed view URLs for review are T893's concern; this task only writes, confirms and sweeps.
