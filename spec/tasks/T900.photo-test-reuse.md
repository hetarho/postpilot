## impl notes
- Flicker: `useWritingTestFlow` sends RELOAD every `POLL_INTERVAL_MS` while `running`; the machine went `running → loading → settling → running`, and the studio words `loading` as 내용을 확인하고 있어요 and hides the progress lines and 테스트 끝내기. Add a `refreshing` phase entered from `running` that invokes the same read and accepts CANCEL; the presentation `work` guard and the studio's progress block include it; it is not an operation-busy phase.
- Results: `WritingTestContestantStatus` wraps a succeeded, readable row (payload available) in the `Disclosure` primitive (`size="row"`) and renders `WritingTestObservationRows` with one column or `WritingTestPost`; labels from `writingTestCandidateLabel`. The wire already carries stored outputs blind before review (MODEL-32).
- Photos: extract the editor's slot (`PhotoDropZone` + `PhotoPicker` + `UploadProgress` + failure notices + `PhotoStrip` + `SkippedList` + `AttachmentViewer`) into `features/upload-photos/ui/PhotoAttachments.tsx`; `EditorPhotos` binds the post's hooks to it, `PhotoTestStudio` binds `useKeyedPhotoUploads`, keeps the confirmed `PostImage`s (session storage per owner/seed for reload), deletes and moves by rewriting the draft's `photoIds`, and offers no turn (no test photo rotate API). Unattached test photos are reclaimed by `TestPhotoSweeper`.
