# T495 Per-post credit figures from recent usage on the model and plan responses
> st:todo | ssot:QUOTA-40 QUOTA-64 MODEL-27 | base:QUOTA@27 MODEL@24 | dep:T494 | touches:proto/postpilot/v1/plan.proto proto/postpilot/v1/provider.proto backend/internal/usage backend/internal/plan backend/internal/provider backend/internal/modelcatalog backend/cmd/api

## goal
`ListModels` carries each paid model's per-stage credits per post and `GetMyPlan` each estimator level's per-post credits, taken from the last 30 days of real usage or, below the sample floor, from the catalog-based estimate, each labelled with its basis.

## acceptance
- [ ] a stage figure is the upper median over the last 30 days of per-post stage credits from `generate` admissions settled `succeeded`, counted only when at least 10 such posts from at least 3 accounts exist; exempt accounts count at their reference amount
- [ ] below that floor the figure is the catalog-based estimate (default 5 photos for observe, 1000 finished characters for write) with basis ESTIMATE; with no eligible rate or no bounded price there is no figure
- [ ] `ModelInfo.post_credits` lists one `{stage, credits, basis}` per paid classified stage that has a figure; free-grade stages and unpriced models have none; no field names a price, cost or rate (the T494 descriptor test stays green without new allowlist entries)
- [ ] `EstimatorCombo` gains `post_credits` and `post_credits_basis` = observe figure + write figure of the assigned pair (basis ESTIMATE when either part is an estimate); the existing blog milli rates stay populated until T496
- [ ] figures are cached up to one hour and survive a cold start by recomputing on the next read
- [ ] tests: usage store query (window edges, `succeeded` only, `generate` only, unavailable-cost exclusion, median rule, sample floor by posts and by accounts), plan estimate helpers, provider `ListModels` population incl. free/unpriced, plan handler combo figures; ARCH-26 and ARCH-28 pass

## impl notes
- product constants in `backend/internal/plan` (QUOTA-8): `PostFigureWindow = 30 × 24h`, `PostFigureMinPosts = 10`, `PostFigureMinAccounts = 3`, `EstimatorDefaultPhotos = 5`, `EstimatorDefaultChars = 1000` (the defaults the frontend holds today as `PLAN_ESTIMATE_DEFAULTS`; T496 deletes the FE copy).
- usage query (new sqlc query in the usage store; the query file must stay ASCII-only): join `usage_admissions a` to `usage_events e` on `job_id` where `a.kind = 'generate' AND a.settlement_reason = 'succeeded' AND a.settled_at >= ? AND a.fx_applied_e4 IS NOT NULL`, group by `a.job_id, a.user_id, e.stage, e.model, a.fx_applied_e4` with `SUM(e.cost_microusd)` and `HAVING SUM(e.cost_source = 'unavailable') = 0`. Go converts each row to credits with the plan package's existing charge function at that admission's applied rate, then per `(stage, model)` takes the upper median (`ceil((a+b)/2)` for an even count) and counts distinct jobs and users.
- `usage_events.model` is the registry `provider/model` string; split on the first `/` as `parseRegistryRef` does.
- estimate helpers in `plan`: `ObservePostMilliAt(observe Pricer, rate, photos)` = `photos × PerPhoto` and `WritePostMilliAt(write Pricer, rate, chars)` = `PerPostBase + chars × Per1000Chars / 1000`, sharing `EstimatorRatesAt`'s token assumptions; credits = milli rounded up to a whole credit.
- wiring: provider declares a `PostFigures` port (`StageFigures(ctx) (map[StageModel]Figure, error)`), implemented in `cmd/api` over the usage service with a one-hour in-memory cache; the estimate fallback uses the ledger's `SelectRate`. `modelcatalog.comboRates` takes the same port for the combo sum.
- proto: define `enum PostCreditsBasis { POST_CREDITS_BASIS_UNSPECIFIED = 0; POST_CREDITS_BASIS_RECENT_USAGE = 1; POST_CREDITS_BASIS_ESTIMATE = 2; }` and `message StagePostCredits { Stage stage = 1; int32 credits = 2; PostCreditsBasis basis = 3; }` once (plan.proto if provider.proto can import it without a cycle, otherwise a small shared file); `ModelInfo.post_credits` and `EstimatorCombo.post_credits`/`post_credits_basis` take the next free numbers after re-reading each message.
- the FE compiles unchanged: new fields are additive and unused until T496.
