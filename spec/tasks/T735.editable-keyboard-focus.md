## goal
Opening or leaving an `Editable` from the keyboard keeps focus on the edited field instead of dropping it to `<body>`, with no change for pointer users.

## acceptance
- [ ] `frontend/src/shared/ui/editable/Editable.tsx`: a keyboard activation of the pencil (`event.detail === 0`) moves focus into the edit view (`[data-autofocus]` if present, otherwise the first focusable from `shared/ui` focus helpers); leaving edit mode through the `exit` callback returns focus to the pencil with `preventScroll: true`; both act only while focus is lost (`document.activeElement` is null or `document.body`), so an autoFocus field keeps its caret and focus the user moved elsewhere stays there; a pointer press of the pencil moves no focus; no prop or caller API change
- [ ] new `frontend/src/shared/ui/editable/Editable.test.tsx`: "moves focus into an edit view that places none, when the pencil is pressed from the keyboard", "leaves an autoFocus field where it put focus", "does not move focus on a pointer press", "returns focus to the pencil when a keyboard exit leaves edit mode", "does not take focus back when it already moved elsewhere" — the first and fourth fail at the base commit
