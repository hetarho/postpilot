# T345 ① picks the post's 분야 and autosaves it through the draft queue
> st:todo | ssot:POST-51 POST-54 POST-82 QUAL-19 ARCH-13 ARCH-20 ARCH-24 THEME-29 | base:POST@11 QUAL@3 ARCH@9 THEME@17 | dep:T337 T343

## goal
- An app-drawn `Listbox` labelled 분야, defaulting to 없음, sits on ① under the template data fields and above 기억 사용, on `/posts/new` too; it saves at once through the draft queue with presence semantics, takes a refused choice back, and is disabled on a published post.

## acceptance
- [ ] On ① of a saved post, a `Listbox` with a visible `FieldLabel` 분야 renders after the template data fields and before 기억 사용. Its trigger is named `분야 <current>`, and it offers 없음 followed by the nine 분야 in `BLOG_FIELD_IDS` order. A post with no 분야 reads 없음.
- [ ] On `/posts/new` the picker renders after the data fields and before the photos, since 기억 사용 needs a slug. The writing brief holds no 분야 control (POST-51's stated exception).
- [ ] On a saved post, picking a 분야 sends one `SavePostDraft` at once, without waiting for the debounce, carrying `field` = that `BlogField`. Title and memo saves that follow carry no `field`. After a reload the picker shows the saved 분야.
- [ ] Picking 없음 on a post that has a 분야 sends `field` = `BLOG_FIELD_UNSPECIFIED` as a present value, which clears it. Picking the current value sends nothing.
- [ ] On `/posts/new` a pick is local state and sends nothing. The create carries it, and a create left on 없음 omits `field`. A pick made while the create is in flight is followed by an immediate update carrying it.
- [ ] While the assignment is out, the trigger is disabled. When it lands, the picker shows the saved value with no snap back to the old one.
- [ ] A refused 분야 save (`POST_FIELD_NOT_FOUND`, `POST_PUBLISHED_LOCKED` or any other failure) is taken back. The picker keeps the server's value, a `FieldMessage` under it says why, and the next title save carries text only, so nothing retries forever.
- [ ] On a published post the picker is disabled and adds no reason of its own; T339's single reason covers it (POST-86).
- [ ] The help line under the picker states what the choice feeds (this 분야's guidelines and the frequent phrases seen in Naver search result titles and descriptions). It promises no exposure gain and never implies that a whole post was read (QUAL constraints, QUAL-19).
- [ ] Tests:

  - `entities/post/api/useSavePostDraft.test.ts`: new 'takes the 분야 from every save, a clear included'.
  - `pages/editor/ui/EditorPage.test.tsx`: new describe 'the post 분야':

## impl notes
- Wire, from T322: `SavePostDraftRequest.field` is `optional BlogField` (absent keeps, UNSPECIFIED clears), and `Post.field` is `BlogField` (29). T337 made the server honour both, including on a create.
- FE vocabulary, from T322's `entities/blog-field`: `BlogFieldChoice` (`BlogFieldId | ''`, '' = `NO_BLOG_FIELD` = 없음), `BLOG_FIELD_IDS`, `blogFieldLabelKey(choice)` (posts namespace), `blogFieldFromProto` (an unknown number → undefined) and `blogFieldToProto`.
- `features/save-draft/model/draft-queue.ts` gains a fifth channel, a copy of the 템플릿 channel. The header comment's "four things at once" becomes five, naming 분야.
  - `SendDraft` gains a trailing `fieldId: string | undefined`: undefined keeps, '' clears, an id assigns.
  - `interface FieldWaiter extends FlushWaiter { fieldId: string }`.
  - `Queue` gains `fieldId`, `savedFieldId` ('' until the post exists, as for the template) and `fieldWaiters`.
  - New `fieldDirty(queue)`: `Boolean(queue.slug) && queue.fieldId !== queue.savedFieldId`.
  - New `fieldToSend(queue)`: on a create `queue.fieldId || undefined`, so 없음 is omitted; on an existing post the value only while dirty.
  - `settleFieldWaiters` and `rejectFieldWaiters` copy the template pair, including the 'superseded' rejection.
  - `run()` computes `sentField = fieldToSend(queue)` and passes it as the sixth argument. On success it sets `savedFieldId = sentField` when defined, then calls `settleFieldWaiters` after `settleTemplateWaiters`.
  - On failure with `sentField !== undefined && queue.slug`, it sets `queue.fieldId = queue.savedFieldId` and rejects the waiters. Like the template, this is taken back rather than retried. The take-back sits with the voice, template and target-language take-backs, before T339's `retry` answer check, so a `POST_PUBLISHED_LOCKED` refusal also takes the 분야 back.
  - `!fieldDirty(queue)` joins the success stand-down test, the failure stand-down test and the `queue()` handle's stand-down test. `|| fieldDirty(queue)` joins the success branch's urgent follow-up.
  - `discardQueue` rejects `fieldWaiters` with the reason.
  - `DraftQueueHandle.assignField(fieldId: string): Promise<void>` is the body of `assignTemplate` with the field members.
  - `attachDraftQueue` options gain `fieldId?: string`, defaulting to ''. A new queue sets `savedFieldId: options.slug ? fieldId : ''`. The option is optional so the three existing queue test files compile unchanged, and '' is 없음, which is what an omitted value means.
- A refused create that carries a 분야 keeps retrying with it, exactly as a refused create carrying a template does today. The ids come from a closed list, so an unknown id cannot be sent.
- `features/save-draft/model/useAutosave.ts`:
  - `UseAutosaveArgs.post` gains `field?: string` and the args gain `fieldId?: string`, both defaulting to ''. They are optional so `useAutosave.test.tsx`'s literals compile.
  - `fieldRef` follows the others. The attach passes `fieldId: opened?.field ?? fieldRef.current`.
  - `send` passes `field: fieldId === undefined ? undefined : blogFieldToProto(fieldId as BlogFieldChoice)`, so '' maps to UNSPECIFIED, which clears.
  - Add `useLayoutEffect(() => { if (!postRef.current) void queueRef.current?.assignField(fieldId) }, [fieldId])`.
  - Return `assignField` in the `assignTemplate` shape.
  - `toEqual` ignores a member whose value is undefined, so the existing exact `draftSaves` assertions stay green.
- `entities/post`:
  - `PostDraft.field: BlogFieldChoice`. `toPostDraft` maps `blogFieldFromProto(post.field) ?? ''`, because a 분야 a newer server adds is not one this build can offer or show.
