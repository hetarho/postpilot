# TMPL post templates (템플릿)
> r5 | A reusable, account-owned document that decides the shape of a post — fixed text, photo positions (one or several side by side), what repeats per photo group, where prose goes — written in a small tag grammar the builder hides and `원문` shows, authorable by hand, by the builder or by an outside AI handed the format guide, expanded at enqueue with the photos it binds and the facts its author-facing fields ask the post's author for, frozen there, and never learned from. Migrated from legacy policy/templates.md, tech/post-template-grammar.md, plan/11.

## decisions
- TMPL-1 [o] a template decides the shape of a post; three authored axes stand beside each other and each owns one question — the voice decides how sentences sound (VOICE), the template what shape the post has, a guideline what the post must avoid (GUIDE); a post combines exactly one voice and at most one template; it replaced the retired 용도 ← prose about shape had to be re-derived by the model every run, could not require a literal line, and could not bind output to the attachments
- TMPL-2 [o] a template has exactly three authored fields — `name`, `description`, `body` — plus timestamps; `body` is the single source of truth for the shape: what the database stores, what the prompt receives after expansion, and what the builder round-trips; the builder is a parser plus a renderer over that string and never a second representation
- TMPL-3 [o] every store query and RPC is scoped by the authenticated user and no request carries a user id; a foreign template id is `NotFound` like an unknown one; `templates_id_user` is the composite target `posts.template_id` points at, so a post can never name another account's template; `templates_user_name` keeps display names unique per account
- TMPL-4 [o] there is no tombstone: a deleted template is gone and its name is free again at once ← unlike a voice, a template is not something a post was written in, only something the next machine run is told
- TMPL-5 [o] migration 0022 created `templates` and `guideline_templates`, replaced `posts.purpose_id` with `posts.template_id` under the same composite account FK and detach trigger, renamed `model_experiments.purpose_name` to `template_name` (renamed, not cleared ← a frozen comparison must keep saying what both candidates were given), and dropped `purposes` and `guideline_purposes`; destructive by the owner's decision after inspecting production (two purposes and two assigned finalized posts dropped rather than converted)
- TMPL-6 [o] field rules: `name` trimmed, non-empty, ≤ `TEMPLATE_NAME_MAX_CHARS` (40), unique among the account's templates after trim (`AlreadyExists`, `TEMPLATE_NAME_TAKEN`); `description` trimmed, may be empty, ≤ `TEMPLATE_DESCRIPTION_MAX_CHARS` (200), management copy that never reaches a prompt; `body` trimmed at the edges only, non-empty, ≤ `TEMPLATE_BODY_MAX_CHARS` (4000) and it must parse; creating beyond `TEMPLATE_MAX_PER_ACCOUNT` (50) is `FailedPrecondition`, checked inside the insert transaction; limits are Unicode scalar-value counts on both sides; a bound violation is `InvalidArgument` `TEMPLATE_FIELD_TOO_LONG` with `field` `max` `actual` params; the backend is authoritative and the frontend mirrors the three ceilings only for live counters
- TMPL-7 [o] parsing is part of validation: a body that does not parse has no meaning and cannot be saved; the refusal is `InvalidArgument` `TEMPLATE_PARSE_FAILED` with allowlisted `line` and `reason` params ← the editor must point at the offending line without parsing wire prose
- TMPL-8 [o] UpdateTemplate is presence-based with one statement per present field inside one transaction, so an omitted field is never named by any statement and no read-modify-write can restore a stale value; a present empty `description` clears it, a present empty `name` or `body` is refused; the template screen sends all three fields in one call because they are one draft edited in one place; the `body` is never trimmed on its way to the server ← it is the canonical serialization
- TMPL-9 [o] DeleteTemplate removes the template and returns `detached_posts`; the detach is the schema trigger `templates_detach_posts_on_delete` running in the delete's own transaction ← `ON DELETE SET NULL` on a composite child key would null `posts.user_id` too; the delete also cascades the template's `guideline_templates` rows while every guideline survives (one left with no links applies nowhere and lists as 적용 대상 없음); no post, content, photo, guideline or history is deleted; frozen payloads and snapshots keep the rendered body; the confirmation names detached posts only
- TMPL-10 [o] assignment to a post is presence-aware with three meanings (absent preserves, present-empty clears to 없음, present value assigns), validated before anything else in the request, allowed in every status and while a job runs, and touches no content, revision, baseline, finalization or learn eligibility ← nothing is ever learned from a template; `TemplateRef {id, name}` reaches the post through the consumer-owned `TemplateDirectory` port (→POST-26)
- TMPL-11 [o] the template is resolved once, at enqueue, and what gets frozen is the rendered body — expanded for the post's attached photos, filled with the post's answers to the template's data fields (→TMPL-45) and turned into prompt text with copy tokens ← expansion inside the freeze is what makes "attaching a photo after the start cannot change the run" true, and it is the only place the expansion bound can refuse before a provider is called
- TMPL-12 [o] one `[글 템플릿: {name}]` section enters the write and revise prompts after the complete voice profile and before the per-post material, with `[작문 지침]` after it; it carries a fixed grammar legend, the rendered body between `---` fences, then a fixed precedence sentence; absent a template the builder adds no bytes at all ← the position is load-bearing twice: the voice-profile prefix stays byte-stable across posts of different templates, and the section stays in the stable half so every revision re-injects the identical block
- TMPL-13 [o] the heading, legend and precedence sentence never use the word 지침 ← the retired purpose section used it for two different things one section apart; the framing stays Korean for every target language (it frames user-authored text, not the output-language contract) and the target language outranks a conflicting language instruction inside a template (LANG)
- TMPL-14 [o] handlers read the frozen copy from the payload and never the live row: editing or deleting the template after StartGeneration or StartRevision returns — including across a restart-resume or an explicit retry — cannot change the prompt; a template deleted between the save and the start is simply absent; a payload written before templates existed decodes as no template
- TMPL-15 [o] a write A/B experiment freezes the same rendered body into the shared snapshot so both candidates receive byte-identical system prompts; a different template is a different input hash; `ModelExperiment.template_name` records the name, stored rather than derived, so the detail keeps reading after a rename, a delete or the retention sweep
- TMPL-16 [o] nothing about a template is learned, inferred, suggested or written by a model (I4 stays entirely with voice); no template is selected from a title, memo, tags, photos or content; there is no default and no seeded library; the observe stage never sees one (I3); no template surface makes a provider call or enqueues a job (I5) — listing, selecting, creating, editing, deleting, parsing and the builder are plain CRUD and pure client work
- TMPL-17 [o] the grammar is XML-tag delimited ← an LLM reads tag-delimited structure most reliably and the write prompt already asks for protojson, so a second brace language is the one thing to avoid; closing tags make nesting decidable; attributes carry the machine-readable parts; and `[사진 …]` is already the Naver export's photo marker
- TMPL-18 [o] six constructs: bare text is literal (verbatim in prompt and post) · `<write>지시</write>` writes prose here per the instruction (tags intact in the prompt) · `<slot kind="photo" count="n"/>` is a photo position holding `count` attached photos side by side in one row (copy tokens in the prompt; IMAGE blocks in the post) · `<repeat each="photo">…</repeat>` expands once per photo group · `<note>지시</note>` instructs the model only and reaches the page as nothing · `<ask label="제목">지시</ask>` takes the facts for its position from the post's author instead of the model (→TMPL-43); `slot` is self-closing only, `kind` is required and the only authorable value is `photo`, `count` is optional (1 … `TEMPLATE_PHOTO_ROW_MAX`, default 1); `place` · `link` kinds and `slot`'s `label` attribute are no longer authored and survive only as read-compatibility for stored bodies (→TMPL-37); `repeat` requires `each` whose only value is `photo` and may hold literal · write · slot · note; `write` and `note` hold text only; everything else is a parse error with no lenient fallback ← a body that half-parses would silently drop the structure the user asked for
- TMPL-19 [o] a body parses to an ordered node list; literal and text-holding nodes keep their raw source slice and serialization re-emits those slices, so parse → serialize is byte-exact by construction for hand-written and builder bodies alike; `<` starts a tag when followed by an identifier (or `/` plus one) and then whitespace, `>` or `/`, otherwise it is literal text (`3 < 5` needs no escape); an identifier that is not one of the six is `unknown_tag`, not literal ← a mistyped tag printing itself into every post is worse than needing `&lt;` for a rare literal tag; entities `&lt;` `&gt;` `&amp;` decode when a node's text is read, never in the stored slice
- TMPL-20 [o] a body that does not parse cannot be saved and every error names a 1-based line and one reason: `unknown_tag` · `unclosed_tag` · `unexpected_close` · `malformed_tag` (unparsable attributes, or `slot` with a closing tag) · `missing_attribute` · `unknown_slot_kind` · `unknown_repeat_each` · `nested_repeat` · `empty_write` · `invalid_count` (not an integer in 1 … `TEMPLATE_PHOTO_ROW_MAX`) · `duplicate_ask_label` · `ask_in_repeat` · `too_many_asks` (more than `TEMPLATE_ASK_MAX_PER_BODY`), an `ask` with no `label` or an empty one being `missing_attribute`; the Go parser (`backend/internal/template`) and the TypeScript parser (`frontend/src/entities/template/lib`) are tested against one shared fixture file `backend/internal/template/testdata/grammar/cases.json` plus a committed differential corpus, and a new rule lands in the fixture first ← that file is the only mechanism keeping two implementations of one grammar honest
- TMPL-21 [o] expansion at enqueue consumes the attached photos once, in attachment order, across every photo position in body order: a photo position with `count` n binds the next n unbound photos; a `<repeat each="photo">` becomes one copy of its children per group, where one iteration binds as many photos as its positions ask for together (a repeat whose positions total n photos runs ⌈photos ÷ n⌉ times and the last iteration may be short); a position with no photo left renders nothing; zero photos drops every repeat block whole including its literals; an expansion whose total node count would exceed `TEMPLATE_MAX_REPEAT_EXPANSION` (40) is refused at start rather than sending an unbounded prompt; rendering keeps literals and `write`/`note` tags as written and turns each bound photo into a copy token the model must reproduce verbatim — `{{photo:<filename>}}`, one token per photo, the tokens of one position adjacent (emit an IMAGE block with exactly that file) ← copying twelve characters exactly is something a model does reliably; a bare position no longer repeats the first photo ← a photo the author placed twice by accident is worse than an empty position; the rendered text and the ordered photo-row specs are frozen beside `target_length`
- TMPL-22 [o] legacy content only (no new run produces a `{{slot:n}}` token since r2 →TMPL-37): a slot stays honest rather than filled: an unfilled slot is a TEXT block carrying the optional typed `slot {kind, label}`, not a sixth BlockType (→GEN-1); the template pass after validation and the attachment filter (→GEN-3) turns a TEXT block whose content is exactly `{{slot:n}}` into slot n's block, strips a token embedded in a paragraph and inserts the slot before it, and inserts a slot with no token at its template position; the slot block's content is the token, not the label ← the structured-output block object is closed and cannot carry the marker, so a token in the content survives a revision round-trip and lets the pass find the slot at its own position instead of re-appending it; the pass is idempotent and re-runs after every revision; literal fidelity and section order are not verified and no deviation fails, retries or discards a usable generation
- TMPL-23 [o] legacy content only (→TMPL-37): unfilled slots warn, they never gate: finalization and export are not blocked; the editor states how many remain and the reading view shows where each is; the export panel states the count and the four outputs render each slot as a bracketed placeholder in marker order, distinguishable from the Naver `[사진 …]` markers by their filename suffix (EXPORT)
- TMPL-24 [o] `/templates` is a top-level destination (템플릿, after 말투, lazily split) and a LIST: one-target rows carrying the name, the description and the post count, the whole row linking to the template and the delete painted above the link layer; one docked `+ 새 템플릿` is the only thing that adds; the empty state says what a template is for in plain language, shows no worked body and no marker syntax, and creates no row — there are no shipped presets
- TMPL-25 [o] `/templates/$templateId` edits one template and `/templates/new` is the same component with nothing in it; the screen holds one draft (name, description, composition) and one 저장 as its only committing action, disabled while the draft equals what is stored; in-app navigation away from a dirty draft is warned about, and `beforeunload` warns only when something unsaved would be lost; the clean baseline is the mutation's own response, not the directory query ← the query lags a save by a refetch, which would leave 저장 re-enabled and the guard warning about a template just written; the create path's own post-save redirect is exempted from the guard through a ref
- TMPL-26 [o] the composition is authored through one control in two modes over the same `body` string: the block builder (default) and `원문`, a plain text view of the stored body; both edit the one draft behind the one 저장, switching is lossless because neither holds a second representation (→TMPL-2), and grammar syntax is rendered to the user inside `원문` only — nowhere else in the product ← the builder stays the way a person authors a shape, but the grammar is also the format an outside AI can be told to write (→TMPL-41), and there was no place to put such a body; one row is one block, collapsed to its kind name (→TMPL-36) and a one-line summary of its own text so the rows read as the outline of the post; a `repeat`'s children are a nested list beneath it, always visible; at most one row is expanded at a time and its fields and its delete edit in place (supersedes r1's no-source-view rule from change 30)
- TMPL-27 [o] an always-visible add toolbar, sticky to the top, inserts at the current position — after the row last touched, and inside a `repeat` when that is where the position is — with that position drawn in the list before the click; an aim whose block is gone resolves to the end, where the marker is drawn too ← without the visible marker one toolbar would be worse than the two entry points it replaced
- TMPL-28 [o] reordering offers both pointer drag and move buttons ← HTML5 drag events do not fire on touch and the base breakpoint is a 360 px phone; both are scoped to a sibling group (a `repeat`'s children are their own list) ← the grammar cannot express a block that left its repeat; drag events stop propagating so a nested list's drag never moves its parent; `SortableList` carries a `compact` density for the collapsed rows
- TMPL-29 [o] the editor holds its rows in local state and contributes only complete blocks to the body ← a block exists as a row the moment it is added and an empty `<write></write>` does not parse; a value that is not what the editor last emitted came from outside (a refetch, a clear) and only then are the rows reseeded; a row with nothing in it makes the draft no dirtier; builder → body → builder is byte-identical for anything the builder produced
- TMPL-30 [o] a body the parser cannot read (from before the builder, pasted or edited outside the app) shows the composition as unreadable and offers exactly two actions: `원문에서 고치기`, which opens `원문` with the parse error at its line (→TMPL-20), and `비우고 다시 만들기`, which empties the composition in the draft; name and description stay editable and nothing is written until 저장 ← inventing a structure the author did not write would be worse than saying so; a body that does not parse still cannot be saved from either mode (→TMPL-7)
- TMPL-31 [o] the directory query is re-read on every mount (`staleTime: 0`, `refetchOnMount: 'always'`) ← `post_count` is a projection over posts that no template mutation can invalidate, and it is the number the user confirms a destructive detach against; a rename also invalidates the post caches because the name is projected onto every assigned post
- TMPL-32 [o] the editor and `/posts/new` show a 템플릿 picker defaulting to 없음 on ①'s dock row beside the 말투 picker (→POST-51) with an `sr-only` label, no description line and no 템플릿 관리 link; selecting writes a presence-aware patch through the draft queue; on a create 없음 sends no field at all; the select stays enabled while a job runs and says the running job keeps the template it started with; a failed directory read shows a failure with a retry, never an empty directory ← that would leave clearing as the only available action; the post list shows the template name beside the voice for an assigned post
- TMPL-33 [o] the composition editor lives in `entities/template/ui` ← it performs no mutation, it is a controlled input over one of the entity's own fields, and the shape of a block is the entity's business; `features/create-template` and `features/edit-template` keep their mutation hooks and nothing else; the page owns the draft and composes the three
- TMPL-34 [x] learning, inferring or model-writing a template inside the product (a provider call, a suggestion, a generate button — the AI that writes a body is outside the app →TMPL-41); guessing one from post material or a default; seeded templates; filling a slot in the app (map or place lookup, URL validation, platform call); strict compliance validation; a richer grammar (other iterators, conditionals, variables, expressions, nested repeats, inheritance, includes); per-template model, target length, tags, reasoning effort or quota; version history, soft-delete, sharing, a file-based import/export (the only import is pasting text →TMPL-42); per-voice templates or a template–voice link; changing the memo's role; for a data field — a typed one (number, date, rating, select), any validation of what was typed, blocking 생성 on a blank one, one field per photo or per repeat iteration, a default, a placeholder or a remembered previous answer, and a value reaching the observe stage — out of scope; the model catalog's "purposes" (MODEL) share only the English word
- TMPL-35 [o] four defects are regression-pinned in the shared fixtures: a Go/JS blank-character disagreement (`U+FEFF` vs `U+0085`), slot insertion that reversed template order, a block holding two tokens leaving one behind, and a slot label containing `"` producing a body the builder's own parser refused
- TMPL-36 [o] every block kind is named by what the reader of the finished post gets, in plain Korean a first-time user needs no legend for, and the add toolbar shows each name with its one-line help on the button itself rather than in a tooltip; the five names are `AI가 쓰는 글` (write) · `고정 문구` (literal) · `사진` (photo) · `사진마다 반복` (repeat) · `AI에게만 하는 말` (note), and the collapsed row badge uses the same name as the toolbar button; verb-nouns that name the mechanism (작성, 삽입, 반복 alone) are not used ← the owner looked at 작성 and could not tell what it adds to the post; a name and its help must answer that without a click
- TMPL-37 [o] the `place` and `link` positions are retired: a map, address, link or any other thing the author fills in later is written as a 고정 문구 in the author's own words (e.g. `지도는 아래에`) ← a reserved position gave the model a token to copy and the user a placeholder to hunt for after pasting, and a fixed line does the same job with nothing to fill; a stored body carrying a `place`/`link` slot keeps parsing and the builder shows it as a 고정 문구 row whose text is the slot's label (falling back to 지도 · 링크), so nothing already saved becomes unreadable (→TMPL-30) and the next 저장 writes it back as literal text; the app still fills nothing (TMPL-34 stands); content already produced with slot blocks keeps rendering under →TMPL-22 →TMPL-23 (EXPORT-4)
- TMPL-38 [o] a photo position carries how many photos stand side by side in one row: `count` 1 … `TEMPLATE_PHOTO_ROW_MAX` (4), default 1, edited on the expanded 사진 row with a stepper and read in the collapsed summary as `사진 n장 가로로` (1 reads `사진 1장`); inside a 사진마다 반복 the help states how many photos one iteration takes ← Naver lays several photos in one row and a template that could only stack them one per row could not describe the posts people already write; the ceiling is 4 ← beyond four a row's thumbnails are unreadable on a 360 px phone
- TMPL-39 [?] how a photo row of n > 1 travels from the frozen template through the post to the reader: the block array (GEN-1 knows one file per IMAGE block), the copied Naver text (EXPORT-5's `[사진 …]` marker is a contract users rely on) and the publisher's photo step (PUB-21 uploads one JPEG at a time and verifies one added image each) must each carry the row; candidates are n consecutive IMAGE blocks sharing a row marker vs. one IMAGE block naming several files, and one marker line per row vs. one per photo; owner's call, decided in GEN · EXPORT · PUB by update-ssot, and not before T007/T008 close ← a PUB rev now would stale the publisher work in flight
- TMPL-40 [o] until →TMPL-39 is decided a position with `count` n renders its n tokens adjacent and the post carries them as n consecutive single-photo IMAGE blocks — byte-identical to n single positions in a row — so the template side ships and the count is preserved in the frozen row specs for the later pass ← the author's intent is recorded now and nothing downstream has to change to stay correct
- TMPL-41 [o] `원문` carries a copyable 형식 안내: one button puts on the clipboard a self-contained instruction a user can hand to any outside AI (ChatGPT, Claude, …) so it writes a body in our format — the six authorable constructs of →TMPL-18 with their meaning, the rules that make a body refuse (→TMPL-20), the size ceilings, one worked example, and the instruction to answer with the body only; it teaches no retired construct (`place` · `link`, `slot`'s `label`); the prose follows the UI language (LANG) while tags, attributes and the example stay as they are; it is static client text and no template surface makes a provider call (TMPL-16 stands) ← the owner wants to describe a post to an AI and import the result rather than click a shape together, and an AI can only write our format if it is told the format exactly; the guide and the grammar rule change together — a construct added to or removed from TMPL-18 lands in the guide in the same rev
- TMPL-42 [o] import is pasting or typing into `원문`: the text becomes the draft's body byte-exact (no trim, no normalization →TMPL-8 →TMPL-19), is parsed on the client as the user types with the first error shown at its 1-based line with its reason in plain words (the same `builder.reasons` copy the builder uses), and 저장 stays disabled while it does not parse or exceeds `TEMPLATE_BODY_MAX_CHARS`, with the live counter beside it; switching back to the builder reseeds the rows from the body (→TMPL-29) so what was pasted is what the outline shows; a pasted body with a `place`/`link` slot is accepted as read-compatibility and shows as 고정 문구 (→TMPL-37); `원문 복사` puts the current body on the clipboard so an existing template can be handed to an AI as a sample; the field rules and the parse refusal on the server are unchanged and remain authoritative (→TMPL-6 →TMPL-7)
- TMPL-43 [o] `<ask label="총평 별점">지시</ask>` is a position whose facts the post's author supplies instead of the model inventing them ← a template can require a section the memo has no way to anticipate (a rating, a price, a date), and prose about a shape cannot ask a question; `label` is required, non-empty, ≤ `TEMPLATE_ASK_LABEL_MAX_CHARS` and unique within the body, and it is both the answer's key (→POST-62) and the title shown over the field in the write screen; an empty element puts what the author typed on the page verbatim (the 고정 문구 flavor), an element holding text uses that text as the writing instruction and the typed value as the only facts that position's prose may state (the AI가 쓰는 글 flavor); it holds text only and may not appear inside a `repeat` ← how many fields a template asks for is the template's own answer and must not depend on how many photos this post happens to carry; a body carries at most `TEMPLATE_ASK_MAX_PER_BODY` of them ← a form long enough to push the memo off a 360 px screen would cost more than the invented sentence it prevents
- TMPL-44 [o] the builder offers 데이터 받기 as a switch on the AI가 쓰는 글 and 고정 문구 rows and on no other kind ← those are the two positions whose text a post decides, a 사진 holds an attachment and an AI에게만 하는 말 reaches no reader; turning it on adds a 제목 field seeded from the row's own text and the row keeps its kind with its badge extended, turning it off restores the authored text and drops the title; on a row inside 사진마다 반복 the switch is shown disabled with its reason in place ← a control that silently disappears in a nested list reads as a bug; the flip is an edit of that block like any other and makes the draft dirty by itself
- TMPL-45 [o] a field is resolved at enqueue against the post's answers, before expansion: a field whose switch is off or whose text is blank after trimming has its whole `ask` node removed, so the frozen body neither names it nor leaves a gap and a template with the field off produces a byte-identical prompt to one that never carried it ← the guarantee being bought is that the model is never handed a section it has no facts for, and a blank answer must not buy less than the switch does; a field with a value renders the verbatim flavor as literal text and the instruction flavor as its instruction with the value beside it as that position's facts; removed nodes count toward no bound (`TEMPLATE_MAX_REPEAT_EXPANSION` included) and the frozen copy rules are unchanged, so editing an answer after a start cannot reach the run (→TMPL-11 →TMPL-14)
- TMPL-46 [o] a typed value is authored fact, never an instruction: it is fenced as data inside the rendered body and cannot override the template's own instruction or the target language (→TMPL-13), and it joins the material the writer is allowed to state facts from (→GEN-16); nothing about a value is learned, suggested or model-written and the observe stage never receives one (TMPL-16 stands)

## flow
- author: `/templates` → `+ 새 템플릿` → `/templates/new`(toolbar names: AI가 쓰는 글 · 고정 문구 · 사진(n장) · 사진마다 반복 · AI에게만 하는 말 → rows(데이터 받기 → 제목) → complete blocks → body) → 저장(parse ok → row | TEMPLATE_PARSE_FAILED line + reason)
- import: `/templates/new` → `원문` → `형식 안내 복사` → outside AI writes a body → paste(parse ok → outline in builder | error line + reason, 저장 disabled) → 저장 → same run/delete paths as any body
- run: post picks template → ① fills the template's data fields (제목 + textarea + switch, autosaved →POST-62) → StartGeneration / StartRevision(resolve once → drop every off or blank field's node → bind photos in order, n per position, per group in a repeat → bound check → render tokens → freeze) → prompt section after the voice profile → model output → template pass(legacy slot tokens only) → post with photo rows(→TMPL-39 | interim consecutive blocks →TMPL-40)
- delete: DeleteTemplate → trigger detaches posts (count returned) + cascades guideline links → name free again

## constraints
- config: `TEMPLATE_NAME_MAX_CHARS` 40 · `TEMPLATE_DESCRIPTION_MAX_CHARS` 200 · `TEMPLATE_BODY_MAX_CHARS` 4000 (BE `platform/config` env; FE `shared/config` mirrors via `VITE_TEMPLATE_*` falling back to the default) · `TEMPLATE_PHOTO_ROW_MAX` 4 (both sides, same mirroring) · `TEMPLATE_MAX_PER_ACCOUNT` 50 · `TEMPLATE_MAX_REPEAT_EXPANSION` 40 (BE only; a non-positive or malformed value is boot-fatal) · `TEMPLATE_ASK_LABEL_MAX_CHARS` 40 · `TEMPLATE_ASK_VALUE_MAX_CHARS` 500 · `TEMPLATE_ASK_MAX_PER_BODY` 10 (all three both sides, same mirroring); the tag names, token forms, slot kinds, section heading, legend, precedence sentence and the proto/SQL schema are code, not configuration
- schema (migration 0022): `templates(id PK, user_id FK, name, description, body, created_at, updated_at, UNIQUE(id, user_id), UNIQUE(user_id, name) …)` · `posts.template_id` composite FK + `templates_detach_posts_on_delete` trigger · `guideline_templates` composite FK · `model_experiments.template_name`
- placement BE: `backend/internal/template` (types, grammar, expand, corpus and grammar tests, `testdata/grammar/cases.json` + `corpus.json`, store, rpc; `TemplateDirectory` and the enqueue lookup consumed by post and generation through ports wired in `cmd/api`)
- placement FE: `entities/template` (`lib/grammar.ts`, `model/types.ts`, `ui` composition editor) · `features/create-template` `edit-template` `delete-template` `select-post-template` · `pages/templates` `pages/template` · `shared/ui/sortable-list`
