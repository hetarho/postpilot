# THEME theme preference and design language
> r1 | The browser-owned System / Light / Dark preference that maps onto the `day` and `night` semantic token maps, and the binding design language every frontend surface is held to — phone-first, planes not lines, colour as role, one design system. Migrated from legacy policy/themes.md, plan/14, tech/design-language.md.

## decisions
- THEME-1 [o] three browser-owned preferences: `system` (the default, follows `prefers-color-scheme`), `light` → the `day` semantic map, `dark` → the `night` map; the effective theme is always exactly `day|night`; components consume semantic or functional tokens and never branch on a preference, an effective theme or a palette step
- THEME-2 [o] the storage key `localStorage['postpilot.theme']` holds only the explicit values `light|dark` and choosing System removes it; a missing, malformed, unknown, unreadable or throwing value resolves to System; storage read, write and removal failures never prevent rendering and a failed write leaves the tab's in-memory selection active for the session
- THEME-3 [o] theme is not account or session state: it survives navigation, logout, later login and reload on the same browser and has no RPC, row, cross-device sync, provider call, job, analytics event or env value; the same single preference serves the public `/about` page (→MARKETING-7), so a visitor's choice there is what the app starts from after login
- THEME-4 [o] one synchronous bootstrap snapshot is resolved and applied before React creates its root — the source entry is render-blocking in `<head>` and the Vite HTML transform preserves that on the hashed production entry — and the mounted provider starts from that snapshot instead of rereading storage ← the first frame and runtime state cannot disagree; while System is active the provider listens to `matchMedia('(prefers-color-scheme: dark)')` and an explicit Light or Dark detaches that listener; a same-origin `storage` event for the key updates the open tab without writing back, a removed or invalid value meaning System; listeners are cleaned and reattached safely under Strict Mode
- THEME-5 [o] every effective-theme transition atomically synchronizes `<html data-theme="day|night">`, the document element's native `color-scheme`, `<meta name="color-scheme">` and `<meta name="theme-color">`; the day and night chrome colours are owned by `frontend/index.html`'s theme-colour element as `data-day` and `data-night` and TypeScript selects one rather than duplicating literals ← Chrome for Android tints its address bar from that tag alone; the static no-JavaScript fallback is Night; changes are immediate with no full-page transition; the app icon is fixed art on its own tile that does not follow the theme (`public/favicon.svg` is the source; `favicon.ico` and `apple-touch-icon.png` are rasterised from it and regenerated when it changes)
- THEME-6 [o] the translated `widgets/interface-preferences` is the single composition of the locale and theme controls, mounted by login, the authenticated shell and `/about`: a labelled group of two icon-triggered app-drawn `Menu`s (WAI-APG menu button, `menuitemradio` options, roving focus, Escape and outside-press close with focus return); the theme trigger wears the stored preference's icon (monitor = System, sun = Light, moon = Dark) and carries a translated accessible name so the closed header reports the preference; theme and locale are independent and changing either changes neither the other nor the URL, session, query or server state; the pair never overflows at 320 px
- THEME-7 [o] both themes keep primary, secondary and tertiary content on every surface and every functional foreground on its background at WCAG AA (4.5:1 body, 3:1 large text — for Korean "large" is the CJK equivalent of 18 pt, so 19 px Hangul earns no exemption); every mapped pair is re-checked with a contrast tool when a foundation moves; the audited minimum was 5.07:1 in Night and 4.58:1 in Day
- THEME-8 [o] the premise: a tool used on a phone, often one-handed, to get a post out before the moment passes — content is the interface and chrome is small, quiet and at the edges; planes, not lines; colour means something or is absent, the rest a near-monotone mauve so the one violet thing on screen is unmistakably the thing to press; nothing announces itself — motion confirms, it does not perform
- THEME-9 [o] the device contract every surface is designed and reviewed against: design width 360 CSS px (390 and 430 also checked); conformance floor 320 px with no horizontal page scroll (WCAG 1.4.10); a one-handed grip where the top ~40 % of a 430 × 932 phone is out of thumb reach; a software keyboard covering the bottom ~40 % whenever a field has focus; Korean script, ~1.8× wider per character than Latin and breaking between syllables unless told not to; a cellular network where every RPC can be slow or fail; a change looked at only in a desktop browser is not reviewed
- THEME-10 [o] hard rule, only design-system UI: every generic control the product renders lives in `frontend/src/shared/ui/<name>/` and is used from there; slices never hand-roll a control (a bare `<button className>` is a design-system bug); the inventory is demand-driven — use the existing primitive, otherwise add the smallest domain-agnostic one the current screen needs, and never prebuild unused controls, variants or states; a primitive has no product noun in its name (`Button`, `TextField`, `Menu`; not `PhotoStrip`); two slices reaching for the same shape means a missing primitive and the second copy is the bug report
- THEME-11 [o] hard rule, only Tailwind-registered tokens: a class must resolve to a token registered in `@theme` — the colour foundations and functional roles, the radius, duration, ease, shadow and font scales, the safe-area spacing tokens, and Tailwind's stock spacing and type scales — using the narrowest role that describes the element; forbidden with no exception in `frontend/src`: Tailwind's stock colour palette (removed in `index.css`, so such a class emits no CSS at all), arbitrary colour values and raw literals in TS, TSX or CSS, and arbitrary sizes off the scale (change the scale in `index.css`, never the call site; the sole 10 px recipe is the `eyebrow` chip); `pnpm lint:style` fails on colour escapes, arbitrary text sizes and weights in slice `.tsx`, and the retired `bg` · `surface` · `text` · `primary` · bare status · `border` · `overlay` · `depth` utility families, and `pnpm lint:style:probe` proves the scanner catches them without rejecting the live names; a line that is genuinely not UI colour carries `// style-escape: <why>`
- THEME-12 [o] hard rule, borders are the last resort: depth and grouping come from the surface steps and from spacing; a `border-*` class is allowed only for the outlined button variant, a `divide-divider` hairline between rows with no background of their own, a table rule and a spinner's ring; never around a card, a panel, an input at rest, a header or a section — step one of them to a different surface or add space
- THEME-13 [o] hard rule, cards are rare: a card is a raised surface with its own padding and radius, used only when its contents belong together AND are separate from their neighbours (controls acting on one object, a preview that must read as one unit, an item in a grid of peers); not a card: a page section, a form, a list, a paragraph, the whole page; a card holding one line of text is always wrong; never nest a card in a card
- THEME-14 [o] hard rule, the base breakpoint is the phone: every layout is authored unprefixed for 360 px and `sm:` / `md:` / `lg:` only override upward — `sm:` never means "on small screens"; deleting every prefixed class must still leave a finished screen; `sm:` (640) changes density, `md:` (768) changes shape (the pointer is assumed fine: side-by-side panes, dialog not sheet), `lg:` (1024) changes only the shell and the content-column width (THEME-26) and a component never reaches for it to rearrange itself; a breakpoint is chosen because the content breaks there, and a shape that depends on its container uses `@container`
- THEME-15 [o] colour is authored once in `frontend/src/app/styles/index.css` in three layers with a one-way dependency palette → foundation → function → component: OKLCH palette ramps (`mauve`, `violet`, `red`, `green`, `gold`, `blue`, white, black), the only raw literals in the frontend and deliberately not Tailwind variables; semantic foundations (`--surface-*` `--content-*` `--stroke-*` `--intent-*` `--interaction-*` `--physical-*`) mapped per theme to palette steps, never literals; functional roles referencing foundations, grouped by what the product renders — buttons `button-cta-*` `button-secondary-*` `button-ghost-*` `button-danger-quiet-*`, fields `field-bg` `field-bg-hover` `field-bg-focus` `field-fg` `field-label` `field-placeholder` `field-error`, navigation and lists `link-*` `link-fg-current` `row-bg-*` `divider`, labels and feedback `badge-{neutral,accent}-*` `notice-{danger,success,warning,info}-*`, system and media `focus-ring` `selection-*` `media-scrim-*` `shadow-color`, brand `brand-wordmark` `brand-mark`; `@theme inline` exposes the roles plus the surface and content foundations; state names are explicit (`bg`, `bg-hover`, `bg-active`, `fg`) so a primitive never invents a hover by opacity; direct `intent-*` utilities are deliberately not registered; a role is added only when a current need cannot be expressed
- THEME-16 [o] the neutral is mauve: the greys carry the primary hue (298°) at a whisper-level chroma (~0.01) so the interface reads as one material rather than a grey box with a purple button; never a true grey or a different-hue neutral
- THEME-17 [o] the surfaces are an ordered depth scale walked one step at a time — `surface-lowest` (deep wells) · `surface-recessed` (inputs and regions pressed into the plane) · `surface-base` (the page canvas) · `surface-raised` (rows on interaction, compact controls, cards, resting floating content) · `surface-highest` (menus, sheets, dialogs, popovers, a docked action bar) — plus `surface-overlay`, outside the scale, for a panel that opens OVER one of the others (a portalled listbox): a step down plus its own `shadow-lg` ← up is unavailable in both themes; `content-primary` → `secondary` → `tertiary` carry copy hierarchy and `content-disabled` is never used for readable metadata; `stroke-subtle` and `strong` are rare structural hairlines, never a substitute for a surface step; `intent-*` is meaning before a component; `interaction-focus` is the one keyboard-focus colour; `physical-*` is light and occlusion, not product meaning
- THEME-18 [o] applying colour: surfaces move one physical step (a field is recessed on base, a card is raised, a modal is highest — depth is the step plus rarely a shadow, not a border; `surface-lowest` is not a generic dark fill and `surface-highest` is not emphasis); one CTA per view uses `button-cta-*` and every other button is ghost, secondary or rarely outlined ← two filled CTAs means one is lying about its importance; accent is for action and identity — a control, a selected state, a focus ring, a single word — never area; status colour never travels alone; inline notices use the notice contract with explanatory text and no border; primitives use functions, not foundations
- THEME-19 [o] typography: one family, the system stack (`--font-sans`; Apple SD Gothic Neo, Pretendard, Noto Sans KR for Korean), no second family and no web-font download ← the app must paint at once on a phone; weight carries emphasis, colour importance, size hierarchy, never all three for one thing; the roles are code in `shared/ui/typography` — `<Typography variant>` and `typographyStyles({ variant })` for an element that keeps its own component: `display` (`h1`, `text-2xl font-semibold tracking-tight`, the screen's one top title) · `title` (`h2`, `text-lg font-semibold tracking-tight`, every section heading and dialog title, `as` for deeper levels) · `fieldTitle` (`h3`/`label`, `text-base font-bold tracking-tight`, a field's own name beside a step's action) · `body` (`p`, `text-sm leading-relaxed`) · `input` (field primitives only, `text-base sm:text-sm`) · `label` (`span`, `text-sm text-content-secondary`, no ad-hoc weight) · `meta` (`span`, `text-xs text-content-tertiary`, `mono` for verbatim ids) · `eyebrow` (`span`, `text-[10px] font-medium uppercase tracking-wide`); a slice never composes a raw type utility (`text-<size>` `font-<weight>` `font-mono` `tracking-*` `leading-*`) and `pnpm lint:style` fails on one in a non-test slice `.tsx` outside `shared/ui` unless it carries a reasoned `// style-escape:` pragma (the sanctioned case is a nav control's active-state `font-medium`); a caller's colour wins over the recipe's while the size stays the role's; prose is capped at `max-w-measure` (40rem); field labels and placeholders use `text-field-label` and `text-field-placeholder` owned by the primitive; an eyebrow is not a heading; `text-xs` (12 px) is the floor and for metadata only — copy the user must act on is never 12 px
- THEME-20 [o] the 16 px input floor: every control the user types into computes to at least 16 px on a phone (the `input` role, `text-base sm:text-sm`) ← iOS Safari zooms the whole layout when a focused field is smaller and never zooms back out on blur; the fix is the font size and nothing else — `user-scalable=no` and `maximum-scale=1` are forbidden (WCAG 1.4.4, and iOS ignores them anyway)
- THEME-21 [o] Korean line breaking: `body` sets `word-break: keep-all` and `overflow-wrap: anywhere` together, once ← `keep-all` alone lets an unbreakable Latin token (a model id, a slug, a provider URL) push the page into horizontal scroll; `break-all` is never used since it excludes CJK; any container rendering a server- or model-supplied string additionally carries `break-words` at the call site — the global rule protects the layout, the local class protects the box
- THEME-22 [o] space and hierarchy: one 4 px scale — inside a control 2–3, inside a group 3–4, between groups 6–8, between page sections 10–16; hierarchy is built position → size → weight → colour → surface → border, each used only when the one before is not enough; a group of actions reads left to right by rising emphasis, the way out first and the committing action last and the only filled one; pages are full-bleed on `surface-base` with `px-4` (phone) → `px-6` (from `sm:`) gutters and no visible container
- THEME-23 [o] touch targets and padding: 44 × 44 CSS px is the house minimum for anything the thumb presses, counting both dimensions (a bare text link like `말투` is ~28 px wide and fails, so text-sized controls get horizontal padding); 24 × 24 is the absolute floor; ≥ 8 px between adjacent targets; when the visible box must stay small the primitive grows the hit area itself; a row in a list is one target; padding is a ratio, not a leftover — `min-h-11` is a floor, not padding, and a control's horizontal padding is roughly twice its effective vertical: buttons, fields and selects `px-4` (`px-5` for a CTA), icon buttons `size-11`, list rows `px-4 py-3`, a row holding a control `px-4 py-2 min-h-16`, chips `px-2 py-0.5`, inline notices `px-4 py-3`, cards `p-4` (`p-5` for a sheet); a row is never inset less than the gutter it sits in; a control and its panel never share a padding step or a radius; a list's row-height floor is set once by the tallest thing any row can hold (the 말투 directory, where only the default offers neither 기본으로 설정 nor 삭제)
- THEME-24 [o] reach and placement: the committing action of a view lives in the lower band, not a top corner and not flush against the bottom edge (`새 글`, `생성`, `저장`, `복사`); navigation is reachable from anywhere in the scroll; a control and the thing it commits stay on one screen — after the field, or docked; a dock for a list's add action is a PHONE dock (`ActionBar dock="phone"`) that dissolves into the list's last row above the phone ← a floating card with one left-aligned button over a half-empty page reads as debris, while a dock whose reason is the distance between content and control (the editor's) stays at every width, and the bar is one element either way; one docked bar per scroller ← two sticky bars pin to the same offset; a dock may carry more than one row and an unused row collapses; feedback renders where the user is looking, in a live region mounted before its text changes; a dock holds controls and refusals while what is merely TRUE goes to ONE page-top status region — a `ProgressBar` pinned to the top edge (`sticky`, in normal flow, no layout height, `top-0` on the phone and `sm:top-16` under a sticky header) plus one `meta` line carrying at most one thing in a stated precedence where a state the user must act on outranks one they only need to know, numbers belong to the bar and not the prose, and a standing state never gets an event's presentation (owner decision 2026-09-02; the editor is the reference, →POST-45)
- THEME-25 [o] one scroller per screen: the document is the only vertical scroll container — no `max-h-* overflow-y-auto` content panel and no fixed-`rows` textarea holding more than it shows (a textarea grows with `autoGrow`); three deliberate exceptions: a horizontal strip (a photo strip, a tab row, the contact-sheet carousel whose cards are narrower than the strip so a sliver of the next one shows, with a 현재/전체 indicator), a sheet's own body, and a form field capped at `max-h-field` ← an uncapped generated value would put the committing control thousands of pixels from the caret, and reach wins; the editor's title and memo are not capped; all three set `overscroll-behavior: contain`
- THEME-26 [o] the desk (`lg:`, ≥ 1024 px, owner decision 2026-09-05): the destinations move into a persistent left rail hanging from the top bar's bottom edge (`top-header`, `h-sidebar`) while the bar stays and keeps the brand, theme, locale and account exactly once ← a vertical rail scans faster, holds an active state as a plane and has room for a seventh destination; the content column widens by kind through `shared/ui/page`'s `pageStyles` — `prose` for something authored or read (bounded by ~75 characters), `wide` for a directory of rows, `board` for a genuinely two-dimensional screen — chosen once per page; three planes, not two: the rail on `surface-recessed`, the content on `surface-base`, the bar on `surface-raised`, rail rows walking recessed → base under the pointer → raised for the current destination and never borrowing `row-bg-*` ← that pair is calibrated for rows on `surface-base`; an edge-to-edge row cancels all three gutters (`-mx-4 sm:-mx-6 lg:-mx-8`) and a page-level sticky bar offsets with `sm:top-header`, never a repeated `16`; the scroller count, the committing action's placement and the phone shape do not change
- THEME-27 [o] elevation and shape: three shadow steps mixed from `shadow-color` — `shadow-sm` resting, `shadow-md` a floating panel, `shadow-lg` a modal — encoding distance from the page, never importance, and most surfaces cast none; radii `rounded-sm` (6 px) chips · `rounded-md` (10) controls · `rounded-lg` (14) panels and cards · `rounded-xl` (20) sheets, dialogs and a docked bar · `rounded-full` avatars and pills; an inner control is one step smaller than its panel; an edge-attached surface rounds the free side only (`rounded-t-xl`); no gradients on surfaces and no glassmorphism — a translucent dock was built and compared beside the opaque one in both themes and the owner kept the opaque bar (change 12, 2026-09-01)
- THEME-28 [o] motion: `duration-fast` (120 ms) hover and press · `duration-base` (200 ms) reveal and dismiss · `duration-slow` (320 ms) a sheet or page transition; `ease-standard` for everything and `ease-emphasized` only for something arriving; animate `opacity` and `transform` only, never layout properties; every control has an `active:` press state and a variant needing a resting plane on touch uses `pointer-coarse:` ← `hover:` compiles to `@media (hover: hover)` and a touchscreen never matches it; a pending action shows its state in place at a fixed size — a spinner covers a label hidden with `opacity-0`, never `visibility: hidden`, `display: none` or unmounting, which would drop the accessible name — and the button sets `aria-busy`; feedback is paced to the wait (under 1 s nothing, 2–9 s indeterminate, 10 s or more determinate plus a way out); `prefers-reduced-motion` is honoured globally
- THEME-29 [o] the primitives: `Button` (`cta`, `secondary`, `ghost`, quiet `danger` with a pressed plane on touch; `default` and `icon` sizes 44 px padded to the ratio; `compact` 36 px only for a low-emphasis way out sharing a dock with the content it would otherwise cover, never a committing action; no vertical padding and `leading-snug`; `pending` swaps the label for a `Spinner` while holding the box; `buttonStyles` for router links and the file-input label; a committing action is `w-full sm:w-auto` on a phone) · fields (`TextField`, `Textarea`, `FieldLabel`, `FieldMessage` with `well` and editor-only `bare` appearances: a recessed `field-bg` well with no border at rest, `field-bg-hover` / `field-bg-focus` plus the global ring, validation as a `field-error` message under the field plus `aria-invalid` — the field never turns red or grows a border, labels always visible, `autoGrow`; every field states `type`, `inputMode`, `autoComplete`, `autoCapitalize`, `autoCorrect`, `enterKeyHint`; the editor title is bare and the memo a well) · no native `<select>` anywhere — `pnpm lint:style` fails on the literal (owner decision 2026-08-31) — replaced per surface by `Listbox` (the labelled form field: a 44 px `field-bg` trigger, `role="combobox"` + `aria-haspopup="listbox"`, named `"<label> <current value>"`, an app-drawn `surface-overlay` panel of `role="option"` rows with a check, the trigger the only tab stop, arrow/Home/End, Enter/Space, Escape and outside press; generic over the option value; its panel a bounded scroller measured to the room actually beneath its trigger, flipping above when that is larger, capped at `LISTBOX_MAX_VIEWPORT_RATIO` and floored at `LISTBOX_MIN_PANEL_PX`; an option's text is the choice and a reason goes in the message slot), `SegmentedControl` (a bounded 2–5 shown at once — the editor steps, the plan ladder — scrolling horizontally rather than crushing labels) and `Menu` (an icon trigger with a short preference set, `aria-haspopup="menu"`, `menuitemradio`) · `TabLinks` (tabs that are addresses: a `nav` of links marking `aria-current="page"`, `SegmentedControl`'s shape without `onChange`; a text-only row scrolls, and when every item carries an `icon` it reshapes by `@container` below the `@tabs` 38rem token into icon-over-caption tabs sharing the row evenly, the full label staying the one accessible name) · `Editable` (read first, edit on request behind a pencil `aria-label`led with the field; the caller supplies both views and every action) · `Badge` (`rounded-sm`, no border, `px-2 py-0.5`, always a text label; `badge-accent-*` for a mid-way state, a `notice-*` tone for good/bad/urgent) · `Notice` (a tone, explanatory text, no border, `px-4 py-3`, the caller's `role="alert"` or `"status"`) · `ActionBar` (the dock: `surface-highest`, `rounded-xl`, `shadow-md`, `p-3 sm:p-4`, opaque, clearing the phone tab bar and home indicator itself and floating a step clear of what is under it, at the end of a `flex-1 flex-col` page with `mt-auto`, mounted only when it holds something) · overlays (all portalled, all return focus, all `Escape`-closable, all lock the body scroll; `Sheet` takes arbitrary content and on a phone is a full-bleed bottom sheet, `rounded-t-xl`, safe-area padded, its body the one scroller, rising from and sinking back into the edge (`duration-slow`, emphasized in, standard out) while a `md:` dialog only fades; the panel outlives `open` by exactly one animation and `animationend` unmounts it while scroll lock, focus and the `Escape` claim are surrendered the moment `open` goes false, the leftover picture `inert`; `Dialog` is `Sheet` with the confirm shape — one title, one explanation, its pair ONE row split 3 : 7 on a phone with cancel left and the CTA right, collapsing to a right-aligned row from `md:`; a destructive action is confirmed through `Dialog`, never `window.confirm`; `Popover` anchors to a trigger with `align`, measures both bounds against where the trigger sits, corrects horizontal overflow into the gutters, caps vertical room and scrolls inside with a `POPOVER_MIN_PANEL_PX` floor, offers `phone="sheet"`, `triggerSize`, `triggerVariant` and a `PopoverHandle`, and treats a press inside a modal it opened as inside itself) · empty and loading states are text on the page (`text-content-tertiary`), never a card or illustration, and a section never renders nothing at all; a skeleton mirrors its content with `bg-surface-recessed animate-pulse` · `ProgressBar` (`role="progressbar"`, determinate or indeterminate with no `aria-valuenow`, zero height) · `Logo` (inline SVG from `brand-wordmark` and `brand-mark`, self-named, sized by height — `h-6` in the header, `h-9` on login) · `Spinner` · `SortableList` (with `compact` density) · `Checkbox` · `Meter` · `Page` · `TechnicalDetail` · `AppFailure`
- THEME-30 [o] a panel anchored to a trigger inside a scroller is portalled to the document body and positioned `fixed` from the trigger's measured rect, or it is clipped ← an `absolute` panel is bounded by every scrolling ancestor, and a field near a sheet's bottom is exactly the one whose panel flips upward out of it; the portal's four costs: it tracks the trigger by re-measuring on captured `scroll` and on `resize` and closes once the trigger leaves the viewport, returning focus with `preventScroll`; every ancestor overlay's outside-press test must treat the panel as inside (`Popover` exempts `[role="listbox"]` as it does `[aria-modal="true"]`); `Escape` dismisses only the innermost overlay through the panel's own `stopPropagation()` on the portalled event — not to be replaced by a capture listener without re-checking; the measured position and size live in state by value ← callers pass `options` inline, so a fresh object per render is a render loop; the panel stacks on `z-overlay-panel`, above `Sheet`'s `z-50`
- THEME-31 [o] the phone platform layer, owned by `frontend/index.html` and the base layer of `index.css`: the one viewport meta `width=device-width, initial-scale=1, viewport-fit=cover` with `user-scalable`, `maximum-scale` and `minimum-scale` never added; safe-area insets registered once as spacing tokens and consumed as utilities (`pb-safe-b`) on controls only, with backgrounds running to the edge; the inset ADDS to the design padding and never replaces it — two padding utilities on one side collide and the longhand wins, so a summing token (`--spacing-dock-b`, `--spacing-sheet-b`) or a `mb-safe-b` margin is used (the dock, the sheet and the about footer were all bitten); heights use `dvh` / `svh`, never `vh`; `html` sets `overscroll-behavior-y: contain` ← pull-to-refresh at `scrollTop: 0` reloads the SPA and discards unflushed autosave, and every overlay and inner scroll region sets the same; the keyboard does not resize the layout viewport, so `fixed` and `sticky bottom-0` stay pinned behind it — a form's committing action and its error sit directly after the last field, forms anchor to the top rather than centring, and the field being typed into is never re-mounted ← removing it dismisses the keyboard and a non-gesture `focus()` cannot bring it back on iOS
- THEME-32 [o] touch affordance and weight: nothing is reachable only by hovering; `touch-action: manipulation` on tappable controls so a tap is not held 300 ms; dragging is never the only way to do something and nothing commits on the down-event; `user-select: none` is for chrome, never content; at 320 px the page scrolls only vertically — the recurring causes are a flex or grid text child without `min-w-0` (so `truncate` does nothing), a `shrink-0` on the item that should give way, an unbreakable string without `break-words`, and a fixed `w-*` wider than the column; `overflow-x: hidden` on `html` or `body` hides the symptom and is never the fix; every `<img>` carries `width`, `height` and `alt`, below-the-fold images carry `loading="lazy" decoding="async"`, and `aspect-ratio` reserves the box; the INP budget is ≤ 200 ms
- THEME-33 [o] the accessibility baseline, enforced at review: every control has a visible label or an `aria-label` (icon-only buttons always); focus is always visible through the one global `:focus-visible` indicator (`outline: 2px`, `outline-offset: 2px`) and a primitive adds no second ring; a scroller whose contents can be focused reserves the ring's 4 px with `p-focus-gutter -m-focus-gutter` ← a scroll container resolves its cross axis away from `visible` and cuts a `w-full` field's ring; live regions (`role="status"` / `role="alert"`) for save state, upload progress and errors render where the user is looking; the current destination is marked `aria-current="page"` and shown, not implied by a URL a phone may not display; contrast ≥ AA in both themes; everything is keyboard reachable, overlays trap and return focus and `Escape` closes; orientation is never locked and text survives 200 % zoom
- THEME-34 [o] the review checklist runs over every FE diff before it is done: design system — no control hand-rolled in a slice, no unused primitive or speculative variant, functional roles only and none of the retired vocabulary, `pnpm lint:style` and `lint:style:probe` green with no arbitrary sizes, every `border-*` one of the four exceptions, every card passing the two-part test, exactly one CTA per view on the `button-cta-*` contract, slice text through `Typography` with every pragma reasoned, state reported once in the page-top region and never also in the dock or a `Notice` nothing takes down, focus gutters on focusable scrollers, portalled panels paying their four costs; the phone at 360 px — a finished screen with every `sm:`/`md:` class deleted, no horizontal scroll at 320 px with `min-w-0` on text children, every target ≥ 44 × 44 including width with ≥ 8 px gaps, the padding ratio with no 1 : 1 boxes, every typeable control ≥ 16 px stating its keyboard, the committing action in the lower band on the same screen as what it commits, one scroller, an `active:` state on everything, pending states holding size and accessible name with feedback in a pre-mounted live region, at most one docked `ActionBar` per scroller on a page that fills the shell, safe-area padded edge chrome; and both themes, toggled on `<html data-theme>` in devtools
