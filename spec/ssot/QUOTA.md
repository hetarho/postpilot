# QUOTA plans, credits, metering
> r2 | Every account carries one plan that grants monthly credits; LLM work is held at job start and settled against a persisted ledger; master is the operator tier. Migrated from legacy policy/plans.md, plan/17, tech/usage-quota-and-plan-gating.md; r2 carries legacy change 28 (not yet built).

## decisions
- QUOTA-1 [o] every account carries exactly one plan `free | basic | pro | max | master`, a `users.plan` column with a CHECK so an off-ladder value cannot be stored; `free` is the provisioning default (`api adduser <id> [--plan=<tier>]`, flag accepted in either order)
- QUOTA-2 [o] a tier decides exactly two things: the monthly credit grant, and — for master alone — access to the master-only publishing and admin procedures; which models an account may run is not one of them ← affordability already answers that (QUOTA-19)
- QUOTA-3 [o] only master changes a plan: `AdminService.SetUserPlan` or `api setplan <id> <tier>`; a change re-sizes the next monthly lot and never edits the current one
- QUOTA-4 [o] the last master cannot be demoted on either path; the guard is a condition inside the UPDATE statement, not a count taken before it ← two concurrent demotions must not both commit
- QUOTA-5 [o] the acting plan is resolved once per request on the session path, from the row (→AUTH-15)
- QUOTA-6 [o] a credit is a product-fixed $0.01 of list value stored as an integer — a billing unit, not a cost measurement; the ledger keeps true provider cost in micro-USD underneath and the two never reconcile ← what a user is entitled to must not move with provider prices or exchange rates
- QUOTA-7 [o] grants: free 50 · basic 200 (intended $2/mo) · pro 500 ($5) · max 1000 ($10) · master unlimited; prices are published through GetMyPlan so a comparison screen can name them; no money moves — no checkout, PG, or subscription lifecycle
- QUOTA-8 [o] every number in the ladder is a code-owned product rule in `backend/internal/plan`, published to the client; the frontend hardcodes none ← two deploys must never disagree
- QUOTA-9 [o] a free account is additionally provisioned with a non-expiring 50-credit signup bonus, idempotent (lot id derived from the account); `api grantcredits <id> <amount> [--expires=<RFC3339>]` is the only other path to credits beyond the monthly grant
- QUOTA-10 [o] charge: `credits = ChargeBase(2) + ceil(actual_cost_usd × 100 × ChargeMultiplier(3))`, integer-only (one credit = 10 000 micro-USD), rounding up so a call too cheap to reach a credit still costs ChargeBase + 1; an unpriced model costs ChargeBase alone ← the base recovers per-request infrastructure and keeps near-free models metered; the multiplier covers provider top-up, card fees, VAT, and margin
- QUOTA-11 [o] a balance is lots, not a counter: one `credit_lots` row per grant (granted, remaining, `expires_at` NULL = never), `CHECK (remaining >= 0 AND remaining <= granted)`, spend and refund statements guarded by the amount available ← the never-negative guarantee rests on SQL, not on Go alone
- QUOTA-12 [o] consumption walks lots by `expires_at` ascending, NULLs last, then creation ← "spend the monthly grant before the bonus" falls out of one ordering; expiry is a read-time predicate; monthly renewal is computed on access inside the same write transaction; a lapsed remainder does not carry over and the lapsed row is kept for history
- QUOTA-13 [o] every LLM-consuming job start (`generate` `revise` `analyze_voice` `learn_voice` `compare_voice_rule` `validate_voice_profile` `model_experiment`) passes one gate at the shared enqueue seam (`job.Queue.Enqueue`, a consumer-declared Admitter port wired in `cmd/api`); one A/B comparison is one admission even though it fans out to two candidates
- QUOTA-14 [o] hold: price every planned call at its worst case — an assumed 30 000-token prompt (`holdInputTokens`) at the model's input price plus that call's own completion budget at its output price — run the total through the charge formula, and deduct it from the lots in consumption order, inside one `BEGIN IMMEDIATE` transaction with the admission row, before the job row exists; the enqueuing service states the call count ← only it knows that observation batches photos per call or that a validation repeats per sampled post
- QUOTA-15 [o] settle at the terminal state: reconcile the hold against the job's `usage_events`, refund the difference to the lots it came from (`credit_hold_lots`), idempotent on `settled_at IS NULL`; a job whose actual cost exceeds its hold drains the lots to zero and stops — the difference is ours, never a debt carried forward
- QUOTA-16 [o] master is held, recorded and settled like everyone else but spends no lot and is never refused ← unlimited spend is exactly the spend the operator most wants readable
- QUOTA-17 [o] a hold whose job row then failed to insert is released in full on a context that outlives the caller's cancellation; a boot sweep settles any hold left open behind an already-terminal job
- QUOTA-18 [o] a refusal is `resource_exhausted` with reason `INSUFFICIENT_CREDITS` carrying `required`, `balance`, `renews_at` (RFC3339); it writes nothing and creates no job row; the client renders copy from the reason and formats machine values (micro-USD, instants, tier names) with i18next, never from the message string
- QUOTA-19 [o] there is no plan floor: `min_plan` exists nowhere (registry, `config/providers.yaml`, boot validation, RPCs); every account may select, save and run every registered model; affordability is the only access rule and it is the hold itself ← a floor answered a question the balance already answers, worse, across ~50 enforcement sites
- QUOTA-20 [o] `ListModels` reports per model, for the caller, the credits one call would require and whether the balance covers it, computed by the same estimator the gate applies — display only; an unaffordable model is temporary state and a saved selection is never invalidated, cleared, or reported missing because of a balance
- QUOTA-21 [o] ledger: every server-side LLM call writes one `usage_events` row — prompt/completion tokens, provider-reported reasoning tokens (0 = not reported; kept for diagnosis, never re-priced), `cost_microusd`, `cost_source` resolved reported → estimated → unavailable; a failed call is recorded when the provider reported usage; rows are append-only and kept indefinitely
- QUOTA-22 [o] recording happens at the llm boundary: `cmd/api` wraps the registry every context receives and the worker stamps `usage.Work{user, kind, job}` on the handler context ← every present and future call site is metered by construction
- QUOTA-23 [o] the ledger `stage` is the stage the call named for itself (`observe` · `write` · `analyze`), falling back to ref inference; A/B candidate calls appear in both the experiment tables and the ledger; credit math never joins experiment internals
- QUOTA-24 [o] a post holds at most 30 photos (`UPLOAD_MAX_PHOTOS_PER_POST`, in both config owners); the server refuses the upload that would cross it and the browser reports the excess as skipped before decoding ← it bounds the worst case a hold must price, not storage
- QUOTA-25 [o] master-only surfaces: the nine human PublishingService procedures and the two AdminService procedures are the closed `masterProcedures` set (→AUTH-18); the frontend hides the publishing nav, publish panel and `/admin`, and redirects a non-master away from `/publishing-agents` and `/admin` — UX only, the server stays authoritative
- QUOTA-26 [o] GetMyPlan returns the caller's tier, balance, the individual lots with expiries, the renewal instant, the tier's monthly grant, and every rung on offer with its grant and intended price; reading a balance also renews it
- QUOTA-27 [o] the app shell shows a plan badge; opening it (inside `widgets/account-menu`, mounted only while open) fetches the balance and shows one meter (`shared/ui/meter`), the renewal instant, the lots behind the total, and the statement that plans are operator-assigned
- QUOTA-28 [o] `/plans` lists the four offered tiers with grants and intended prices; each tier's action is the seam a checkout would later attach to and today states plans are operator-assigned; no upgrade, purchase, or checkout affordance exists anywhere
- QUOTA-29 [o] a zero balance blocks every LLM-consuming action and nothing else: writing, editing, exporting and reading posts keep working
- QUOTA-30 [x] mid-flight cancellation on exhaustion, per-model or per-stage rate limits, charging non-LLM resources (storage, uploads, publish jobs), retroactive usage reconstruction, team plans, payments — out of scope
- QUOTA-31 [o] renewal and reset instants use calendar Asia/Seoul as a fixed UTC+9 constant, not a tzdata lookup ← the distroless image ships no zoneinfo and KST has had no DST since 1988
- QUOTA-32 [o] a planned call carries the completion budget it will actually be sent: `PlannedCall` gains that figure beside `Ref` and `Count`, `worstCaseMicrousd` prices each entry at its own figure, a ref used for two stages with different budgets becomes two entries (the collapse rule stays for equal budgets), and `CreditsFor` (behind the catalog's `RequiredCredits` and `EstimatePostCredits`) prices with the same per-call budgets, naming the stage it quotes for; `holdInputTokens` stays 30 000 and a call declaring no budget keeps a completion fallback ← the spend side moved to per-stage budgets (observe from batch size, write/revise from target length up to a ceiling) while the hold kept pricing every call at `LLM_MAX_TOKENS_DEFAULT`: observation over-held and long writes under-held
- QUOTA-33 [o] QUOTA-32 changes no provider request body and no budget any stage is sent, and leaves the floor guarantee (QUOTA-11), settlement (QUOTA-15), the exempt tier, the ladder, the charge formula, lot order, renewal, and the photo ceiling untouched; it must land before MODEL's write-budget reasoning headroom so no window exists where the write budget is raised but still held at 8 192

## flow
- job start → Enqueue → Hold(renew monthly lot → price planned calls → spend lots in order) → ok(admission + hold lots → job row) | refused(INSUFFICIENT_CREDITS, no row)
- worker call → metered registry → llm → `usage_events` row (stage, tokens, cost)
- terminal state → Settle(Σ usage_events → charge → refund remainder to the same lots; once)

## constraints
- config: no env for the ladder, charge constants, or timezone (code-owned); `LLM_MAX_TOKENS_DEFAULT` = completion cap for a caller with no budget and the base of the write budget's floor/ceiling; `UPLOAD_MAX_PHOTOS_PER_POST` 30 in BE + FE config
- schema: `users.plan` (migrations 0013, 0019) · `credit_lots` · `credit_hold_lots` · `usage_admissions` · `usage_events` (reasoning token column added by change 27)
- placement: `backend/internal/plan` (ladder, grants, charge, windows, typed refusals) · `backend/internal/usage` (lots, hold/settle, ledger, metering seam) · `backend/internal/auth` (plan on user/session, master set) · `frontend/src/entities/plan` · `pages/plans` · `pages/admin` + `features/manage-users` · `widgets/account-menu`
- not yet built as of 260905: QUOTA-32 QUOTA-33 (legacy change 28)
