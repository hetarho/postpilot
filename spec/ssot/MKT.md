# MKT the public /about page
> r6 | The product's one public explanation surface: a localized, themed, read-only `/about` route reached from the login page, with Get started as its only CTA, describing only shipped behaviour and collecting nothing.

## decisions
- MKT-1 [o] `/about` is a direct child of the root route beside `/login` and deliberately not a child of the authenticated pathless layout ← being public is structural, not a check someone has to remember; it has no `beforeLoad`, loader, session branch or query, and mounting it issues no Connect call at all — not even GetMe — because the page exists for a visitor with no account; it is refreshable and deep-linkable through the Cloudflare `single-page-application` fallback with no SSR, prerender, marketing deployment or metadata worker
- MKT-2 [o] `/about` carries one search param, `redirect`, which it never reads for itself and hands straight back to `/login` so a detour through the public page does not cost an expired session its destination; both ends filter it with `isInAppPath` so an off-site value cannot survive the round trip (→AUTH-27)
- MKT-3 [o] `/login` links to it as `Postpilot이란? / What is Postpilot?` below the credential action and outside the form; a signed-in visitor who follows About's Login link is redirected by `/login`'s signed-in guard, and About itself never special-cases session state
- MKT-4 [o] every product claim describes shipped behavior; automatic publishing, present or promised, is not advertised; the blog handoff is manual copy/export (EXPORT); no unsupported accuracy, privacy, availability, security or performance guarantee, testimonial, usage metric, case study or fabricated social proof is presented
- MKT-5 [o] the plans section mirrors the code-owned grant table in `backend/internal/plan` (→QUOTA-7): the monthly credit grant and the intended monthly price for `free` 50 / free · `basic` 330 / $3 · `pro` 1150 / $10 · `max` 2400 / $20, model access stated once as the same for every tier, and what a plan decides stated as that monthly grant alone — never as a number of jobs per day, a daily or monthly spend allowance, or a range of selectable models, none of which the product has (→QUOTA-2, →QUOTA-19); it is presented as the same promotional plan cards `/plans` shows (→QUOTA-28, →THEME-37) — the compact phone summaries from `widgets/plan-ladder` on their `PromoStage`, with price beside name, monthly grant and inline bonus, `pro` marked recommended, no action on any card — fed from a static code-owned ladder table in `pages/about` (tier, monthly grant, whole-dollar price, the recommended flag) with the tier names and figure formats from the `plans` namespace, not a GetMyPlan read ← a visitor with no account has no plan to read; the values are duplicated in the page test so a drift fails a test rather than shipping, and changing the ladder means changing this table in the same change; `master` appears only as prose describing the operator tier (unlimited, owns administration) and is never presented as an obtainable tier or a fourth row
- MKT-6 [o] no collection, no selling, no tracking: no signup, invitation, waitlist, contact or sales FORM on this page, no newsletter, comment field or CMS — it contains no `<form>` and no input of any kind, so the way in is always a link to a page that owns it; plans are presented, never sold — no price tag beyond the shipped figures and no purchase, upgrade or checkout affordance; the page carries exactly one filled CTA and it is the way in — 시작하기 / Get started leading to signup — in the header, with 로그인 / Log in as a quiet link in the hero's access paragraph rather than a second control beside it (→MKT-16, →THEME-18) ← two controls in the header read as two buttons, and the header row has no room for both at 320 px once it stops stacking — and the footer is product identity only; no analytics, tag manager, tracking pixel, cookie banner, advertising or marketing experiment; no screenshot, generated hero art, embedded media, remote font or any other third-party request — every asset is same-origin
- MKT-7 [o] all visible labels, accessible names and metadata strings live in the typed `marketing` namespace for `ko` and `en` at full parity (→LANG-7); the page composes keys and embeds no language; locale follows and persists by the browser-local rules and never changes the URL — no locale prefix, no automatic redirect; theme follows the same single browser-local preference the app uses and the public header composes the shared `widgets/interface-preferences` rather than forking either control (→THEME-6)
- MKT-8 [o] while `/about` is mounted it applies a localized `<title>` and `description`, `og:type=website`, localized `og:title`, `og:description` and `og:locale`, and canonical + `og:url` equal to the current origin plus the fixed `/about` path; no `og:image` is invented; the whole set is reapplied when the locale changes; leaving the route removes every tag the page created and hands the title and description back to the app default for the locale current then ← the transaction's undo restores the bytes captured at apply time, so without the second step switching to English on `/about` and navigating away would put the Korean title back
- MKT-9 [o] exactly one module writes document head metadata: `shared/lib/document-metadata`'s transactional `applyDocumentMetadata`, which records each touched tag's prior state and returns an exact undo; the i18n provider's app-default application goes through it too, discarding the undo because a baseline has nothing above it to restore to; a second head writer is forbidden ← two of them cannot share the head safely
- MKT-10 [o] `index.html` keeps a product-level static title and description for clients that do not run JavaScript — neither route-specific nor localized, carrying no Open Graph promise ← it is the only metadata a crawler that refuses JavaScript will ever see, on every deep link, because this is a CSR SPA; emptying it would break every link preview, and the product does not claim localized social previews for such crawlers (→LANG-8)
- MKT-11 [o] the information architecture: a header in ONE row at every width — the wordmark at the page gutter, then viewport-side the one filled `시작하기 / Get started` CTA and the preferences pair, vertically centred in the bar with the top safe-area inset added, never stacked under or centred beneath the wordmark · a hero with one H1 saying photos and rough notes become a ready-to-copy blog draft in the user's chosen voice, the access sentence MKT-16 governs, and the quiet `로그인 / Log in` link under it (→MKT-6) · how it works as a real ordered list — choose a voice, template and target content language → add browser-converted photos and rough notes → Postpilot observes the photos first, then writes with explicit model choices and the selected voice → revise and finalize, then copy a platform format and publish manually on the destination service · why it is different (mutually isolated voice profiles, observation separated from writing, structured canonical blocks, user-selected models and explicit A/B and revision actions) · where the result goes (Naver, Tistory, standalone-site HTML and Markdown derived from the same canonical post; manual posting by the owner on each destination service) · the plans section (MKT-5) · control and privacy facts (images are converted in the browser before upload, account and voice evidence is isolated, opening pages triggers no background AI work, no destination-platform credentials are required for copy/export) · a footer of concise product identity only
- MKT-12 [o] structure and accessibility: one H1, descriptive H2 sections, the product flow as an ordered list ← the order is semantic information, not four numerals; section separation uses spacing and semantic surface steps, never bordered card stacks; the existing `Logo`, button, link and icon primitives and the promotional primitives are reused and no About-only control is hand-rolled; the header is sticky and safe-area padded so the single Get started CTA stays reachable without being repeated; controls keep the pointer floor THEME-23 sets, focus is visible and no state is carried by colour alone; there is no horizontal page scroll at 320 px — the plan cards stack on a phone, nothing is wider than the column, and the page keeps exactly one vertical scroller; the footer's inset is a margin (`pb-8 mb-safe-b`) ← two padding utilities on one side collide (→THEME-31)
- MKT-13 [o] the page's responsive and accessibility invariants are pinned as assertions in place of a real-device sweep at 360 / 390 / 430 px, 200 % zoom, keyboard and both themes — the plan cards stacking unprefixed, one vertical scroller, header controls at the pointer floor, safe-area padding, header tab order
- MKT-16 [o] every sentence about how a person gets an account states the path that exists — self-signup with email verification (→AUTH-1, →AUTH-34) — and the hero's access sentence, the header CTA and the plans assignment sentence (→MKT-15) all move in the change that alters that path ← a sentence denying the path the Get started button offers is a claim violation, not a stale string
- MKT-14 [x] signup or contact flows, price tags beyond the shipped figures, purchase, upgrade or checkout actions, testimonials, screenshots or generated hero art, analytics or tracking, SSR, SSG or prerendering, a blog, docs portal, changelog, legal or privacy-policy authoring, a sitemap or SEO tooling, backend, proto or database changes, a public marketing API, locale-prefixed URLs or redirects — out of scope
- MKT-15 [o] the sentence naming who assigns a plan states the path that actually does so — a subscriber's own checkout (→BILL-1) — and a sentence outliving its path is a MKT-4 violation, not stale copy; the public ladder carries the same code-owned recommended rung `/plans` shows and not the post estimate, which needs the operator's priced combos (→QUOTA-28, →QUOTA-36), and stays static either way, so a ladder change edits both copies together

## flow
- visit `/about` in any session state → static SPA fallback → the page renders from the `marketing` and `plans` namespaces with no request → Get started → `/signup` | the hero's Login link (with `redirect` handed through) → `/login`

## constraints
- placement FE: `pages/about` (ui, the static ladder table and the route-scoped metadata lifecycle in model) · `widgets/plan-ladder` (the shared plan cards) · `app/providers/i18n/resources/{ko,en}/marketing.ts` · `app/routes` (public registration beside `/login`) · `pages/login` (the About link) · `shared/lib/document-metadata` · reused `features/change-locale`, `features/change-theme`, `widgets/interface-preferences`
- no environment value, tuning value, Connect contract, server package, migration or job; the canonical origin is derived from the current document origin
