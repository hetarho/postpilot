# POST posts, drafts, photos
> r1 | A post is a slug-identified, account-owned aggregate: autosaved title + memo, browser-converted photos in private object storage, block-array canonical content with an immutable machine baseline, a draft → review → finalized lifecycle, and the editor that presents it. Migrated from legacy policy/posts.md, policy/uploads.md, plan/02, tech/draft-autosave.md.

## decisions
- POST-1 [o] a post is identified by a slug minted once on the first save and never changed ← it is the primary key and part of every photo object key, so renaming would orphan the photos
- POST-2 [o] slug = `YYYYMMDD-<sanitized title>` with a serial suffix `-2`, `-3`, … on collision; an empty or fully stripped title gives `YYYYMMDD-untitled` (never a bare date); sanitizing trims, lowercases, collapses whitespace and separators to one `-`, drops path/URL-unsafe characters and controls, truncates to 60 runes, never ends in a separator, and keeps Korean and every other letter; slugs are globally unique across accounts; the insert decides — a slug taken between check and insert retries with the next serial
- POST-3 [o] every read and write is scoped to the acting user from the session and no request carries a user id; someone else's slug is `PermissionDenied` (`POST_FORBIDDEN`), an unknown slug `NotFound` (`POST_NOT_FOUND`); ListPosts returns only the caller's posts, newest first by `updated_at`
- POST-4 [o] SavePostDraft is create-or-update and the autosave endpoint: an empty slug creates (requiring a concrete supported `target_language` and an active owned `voice_id`) and returns the minted slug; a slug updates title, memo, `updated_at`; repeated saves are idempotent; a response carrying no post is treated by the client as a failed save ← trusting it would let the next edit mint a second post
- POST-5 [o] there is no save button: the editor saves 1 s after the last keystroke (`AUTOSAVE_DEBOUNCE_MS`) and on every way out (tab hidden, `pagehide`, unmount, leaving the editor); a failed save retries with capped exponential backoff (`AUTOSAVE_RETRY_BASE_MS` 1000, doubling, capped at `AUTOSAVE_RETRY_MAX_MS` 30000); the flush on hide is best-effort so the loss bound is the debounce window
- POST-6 [o] one save queue per post lives outside React (`features/save-draft/model/draft-queue.ts`): for a given post at most one save is in flight and what it sends is always the newest text and the newest voice assignment; the queue outlives its editor and survives the `/posts/new` → `/posts/<slug>` route swap, but never the session — logout and a session that dies mid-use discard every queue ← a retry landing under the next account's cookie would file one person's draft in someone else's account
- POST-7 [o] queue rules: a draft with no slug gets its own key `new:<n>`; the comparison is against the request in flight, not the last saved text (an undo made while a request is out is sent); typing during an outage replaces the retry payload and never restarts the backoff; text pushes through a layout effect so a `pagehide` cannot outrun it; `mint()` sends what is queued (even an empty draft) and resolves with the slug so the first photo can attach before any typing; a pick made only of skipped files creates no post
- POST-8 [o] a voice reassignment rides in the queue as an action, not a keystroke: sent at once without debounce, reported on its own promise, text typed meanwhile waits and goes afterwards without the voice; a refused reassignment is taken back so later saves carry text only; a create always sends `voice_id`, an ordinary edit never does
- POST-9 [o] `saved` settles in presentation only: `useSaveStatus` shows 저장됨 for `SAVE_STATUS_SETTLED_MS` (2000) and then goes quiet, re-arming on every state change; the queue's state machine is untouched ← autosave correctness is tested against the queue, not against how long a word stays on screen
- POST-10 [o] a save's answer supplies the text; the cached photo list is kept and only confirm and delete patch it ← a save that left before a confirm would otherwise land after it and undo the patch, and the fresh presigned URLs in every answer would re-render each thumbnail once a second
- POST-11 [o] the first save of a new draft mints the slug and the editor navigates to `/posts/<slug>` with `replace` (back goes to the list); the text rides the queue and the caret rides a one-shot handoff (`EDITOR_HANDOFF_TTL_MS` 5000) so the next keystroke lands where the user was typing
- POST-12 [o] a successful DeletePost ends that slug's draft and content queues (their waiters reject `post deleted`) before navigating to `/posts`; every other slug's queue is untouched
- POST-13 [o] status `draft → review → finalized`: a successful ordinary generation, AI revision, or applied write-experiment result replaces canonical content and moves the post to `review`; FinalizePost requires valid canonical content and the exact expected `content_revision`, records `finalized_revision` / `finalized_at`, creates no job, calls no provider, and deliberately requires no learning baseline ← reassignment or a deleted voice must not prevent a content-only finalization; the first changed-content save or machine result returns the post to `review`; title/memo and option saves do not
- POST-14 [o] `PostContent` (a block array, invariant I2) is the only canonical value; direct editing covers title, summary, tags and TEXT / HEADING / QUOTE / LIST / IMAGE blocks; the server rejects invalid shapes and IMAGE filenames not attached to the post
- POST-15 [o] `content_revision` is optimistic concurrency: SavePostContent is owner-scoped, requires the expected revision, increments it once for changed content, answers `Aborted` on a stale tab, and never changes `machine_baseline`; an identical save is a no-op, including on a finalized revision
- POST-16 [o] a machine result (selected generation winner, successful AI revision, applied A/B winner) atomically writes canonical content plus an immutable `machine_baseline`, sets `machine_baseline_revision` to the new content revision and `machine_baseline_voice_id` to the post's voice, and stores or preserves `content_language`; equal revisions mean the text still equals the baseline; a manual edit makes them differ until the next machine result
- POST-17 [o] FinalizePost copies the confirmed `content.title` into `posts.title` in the same guarded statement as the finalization (an empty trimmed title leaves the 가제); it advances no revision, changes no baseline, and the slug never changes; the early return for an already-finalized revision happens before the store call; the list shows the 가제 while draft/review and the confirmed title once finalized (falling back to `content.title` for an empty 가제)
- POST-18 [o] `observations` and `content` are owned by the post aggregate and changed by generation only through the ownership-checked `SetObservations` / `SetGeneratedContent` behaviors; GetPost returns both; no other context reads or writes the `posts` table; deleting a photo deletes its observation entry ← observations are paired to photos by filename alone, and a leftover entry would become reusable eyesight for a different photo uploaded under that name
- POST-19 [o] `target_language` is the language of the next ordinary generation or write A/B run; `content_language` is nullable provenance of the current machine-established content; changing the target preserves content, observations, revisions, baseline, status, finalization, assignments and content language, and never translates or relabels (LANG owns the language model)
- POST-20 [o] `target_length` is an optional per-post option saved and cleared independently of content: NULL means natural length and stays absent from prompts and snapshots; a positive value is frozen by generation, revision and write comparisons; option changes advance no revision and demote nothing; ticking 목표 글자 수 사용 fills the field with `POST_TARGET_LENGTH_DEFAULT` (1000) unless the user already typed a value in this session ← a revealed empty number field showed a range error under a control nobody had touched
- POST-21 [o] the post publishes an ownership-checked baseline/final snapshot to VOICE only while the current revision is exactly the finalized one, and a deeply detached finalized snapshot to PUBLISH that exposes stable JPEG object identities, mints no view URL, advances no revision, changes no state and calls no provider; neither context reads post tables
- POST-22 [o] timestamps are stored as fixed-width RFC3339 in UTC (string comparison in SQL stays correct) and travel as RFC3339 strings
- POST-23 [o] every post is written in exactly one voice of the same account (`posts.voice_id`, composite FK to `voices(id, user_id)`); a create must name an active owned voice — missing is `InvalidArgument`, unknown or foreign `NotFound`, deleted `FailedPrecondition`; the server never substitutes the default
- POST-24 [o] `voice_id` on a draft save is presence-aware: absent preserves, a value equal to the current voice preserves, a different value is a reassignment — refused `FailedPrecondition` while a job targets the post or an undecided write experiment could still apply output; otherwise, in one post-owned transaction, it changes `voice_id`, clears `machine_baseline` and `machine_baseline_voice_id`, and makes learning ineligible until a new machine result; slug, title, memo, photos, content, revision, status, finalized revision and exportability are untouched and no prior learning moves
- POST-25 [o] `Post.voice` and `PostSummary.voice` are a transport-only `VoiceRef {id, name, deleted, source_language}` resolved through the voice directory port; the post stores only the id and never joins voice tables; a deleted voice still names itself so the post stays readable, manually editable, copyable and exportable, while generation, AI revision, save-as-rule, sentence feedback and learning are refused before any enqueue with one fixed reason (`삭제된 말투예요. 말투를 복원하거나 다른 말투로 바꿔 주세요.`); the list row, picker and editor warning render `삭제된 말투 · {name}` and the warning offers `복원`
- POST-26 [o] a post has zero or one template of the same account (`posts.template_id`, nullable composite FK); 없음 is the default and a real answer the server never overrides; `template_id` on a save is presence-aware with three meanings (absent preserves, empty string clears, a value assigns), validated before anything else so a bad id changes no title, no memo and mints nothing; allowed in every status and while a job or undecided experiment is outstanding; it writes only `template_id` and `updated_at` ← nothing is ever learned from a template, so assigning one costs nothing and needs no confirmation; deleting a template detaches it from every post in that delete's transaction; `TemplateRef {id, name}` is resolved through the template directory (rules in TEMPLATE)
- POST-27 [o] the owner deletes a post from that post's editor (`/posts/$slug`) through a danger-toned `글 삭제하기` button in the top row — words, not an icon ← a bare X read as "close the editor", and this misread cannot be undone — followed by a dialog naming the post and stating what is destroyed; `/posts/new` offers nothing and the list is not a delete surface
- POST-28 [o] the delete is hard and unrecoverable: no `deleted_at`, no trash, no restore, no retention window; it removes the row, its photos and their objects, and every cascaded post-scoped row (`images`, `uploads`, `generation_jobs`, the `voice_*` learning tables); `model_experiments.post_slug` is `ON DELETE SET NULL` and the required `ExperimentContentPurger.PurgePost` hook removes the experiment's content first
- POST-29 [o] a delete is refused, destroying nothing, when a generation job is active (`FailedPrecondition`, `POST_BUSY`) or a publish job is non-terminal — `queued`, `running`, `needs_attention` — (`POST_PUBLISHING`) ← the remedies differ: wait out a generation, cancel or finish a publication; terminal publication history neither blocks nor is deleted; the publish check is the consumer-declared `LivePublishFinder` port and the guideline-candidate detach the `GuidelineCandidateDetacher` port (runs after the row is gone, its failure logged rather than failing the delete); `internal/post` imports neither context
- POST-30 [x] account deletion — no RPC exists; a separate gap
- POST-31 [o] the browser is the only place a photo is decoded (I6); the selection gate runs before conversion: extension ∈ `jpg jpeg png webp heic heif` (case-insensitive), size ≤ `UPLOAD_MAX_FILE_MB` (25), the post below `UPLOAD_MAX_PHOTOS_PER_POST` (30, →QUOTA-24); anything else is listed under 건너뜀 with the reason and is never read, converted or sent
- POST-32 [o] decode: JPEG/PNG/WebP through the browser's decoder with EXIF orientation applied; HEIC/HEIF through `libheif-js` in a Web Worker loaded on the first HEIC and torn down after `HEIF_DECODER_IDLE_MS` (30 s), one file at a time ← its WASM heap does not shrink after a 12 MP decode; an unreadable file is skipped as unreadable, a decoder that cannot come up skips HEICs as unsupported on this device; the other files proceed
- POST-33 [o] resize and encode: long edge ≤ `IMAGE_MAX_LONG_EDGE_PX` (1024), never upscaled, white behind transparency, JPEG at `IMAGE_JPEG_QUALITY` (0.85); the canvas re-encode drops the GPS, device and timestamp metadata a phone writes; at most `UPLOAD_CONVERT_CONCURRENCY` (2) files convert at once; the copy is `<original stem>.jpg`, de-duplicated with ` (2)`, ` (3)` against the post and the same pick before CreateUpload
- POST-34 [o] handshake: `CreateUpload(post_slug, filename)` → `upload_id`, presigned PUT, `content_type`, `expires_at` → the browser PUTs directly to storage → `ConfirmUpload(upload_id, width, height)` → the server HEADs the object and records the photo; no RPC accepts or returns image data, the server never decodes an image (dimensions come from the client, bytes from the HEAD), and `maxRequestBytes` stays at 256 KiB ← the largest thing an RPC carries is a memo
- POST-35 [o] the image id is minted at CreateUpload because the object key contains it; the `uploads` row is written only after the presign succeeds; confirm is one transaction (photo row written, upload row dropped together) and idempotent; a confirm whose object is not in storage is `FailedPrecondition` and the upload row stays so the PUT can be retried with the same id
- POST-36 [o] server refusals: `Content-Type: image/jpeg` is part of the presigned signature (returned so the client sends exactly it); dimensions positive and ≤ 20000 px; object size 1 byte … 10 MiB (`MAX_IMAGE_BYTES`; a rejected object is deleted at once) ← the browser's 25 MB cap is advice a presigned URL can ignore; a filename held by a confirmed photo is `AlreadyExists` (the filename is how the model and exporters address a photo); a filename held by a pending upload is the retry case and that upload is replaced (row and object dropped, fresh id); `UNIQUE(post_slug, filename)` on both `images` and `uploads` closes the concurrent race
- POST-37 [o] client retry: a failed PUT or expired URL restarts at CreateUpload; a confirm whose answer was lost retries the same `ConfirmUpload(upload_id)` (only `FailedPrecondition` sends it back to CreateUpload); `AlreadyExists` and `InvalidArgument` are final; a confirmed photo enters the cached post with the local object URL of its converted copy until the next GetPost supplies a presigned one; per-post upload state lives outside React and is discarded with the session by `endSession()`
- POST-38 [o] the bucket is private; view URLs are presigned GETs (10 min) minted fresh on every GetPost, never stored, issued only after the ownership check; the storage key never crosses the wire; key `posts/{slug}/{image_id}.jpg` with a random 16-byte id ← not guessable, reveals no count
- POST-39 [o] DeleteImage removes the object first, then the row ← the reverse order could drop the only reference to an object whose delete then failed; a missing object is not an error, and a crash in between is recovered by retrying the delete
- POST-40 [o] the orphan sweep runs every `ORPHAN_SWEEP_INTERVAL` (24 h, env) and reclaims uploads past `expires_at + ORPHAN_MIN_AGE` (1 h) with their objects — never an object an `images` row still references — and `posts/` objects no row names that are older than `ORPHAN_MIN_AGE`; the referenced-key set is read in one transaction; a failed listing or key read deletes nothing ← a short read looks exactly like "these objects are gone"; it does not run at boot ← a restart loop would turn every crash into a bucket listing
- POST-41 [o] `internal/storage` is the S3-compatible adapter behind the post context's consumer-owned `ObjectStore` port (`PresignPut` `PresignGet` `Head` `Delete` `List`); it holds two clients — one for the API's own calls, one that only signs URLs against `R2_PUBLIC_ENDPOINT` (default `R2_ENDPOINT`) ← a SigV4 signature covers the Host header; SDK request/response checksums are turned off ← R2 lacks the full-object CRC32 form; local development runs MinIO with the same four variables and path-style addressing; the server refuses to boot without `R2_ENDPOINT` `R2_ACCESS_KEY_ID` `R2_SECRET_ACCESS_KEY` `R2_BUCKET`, naming the missing one, checked before the listener but outside `config.Load` ← `api adduser` must work on a fresh box before a bucket exists
- POST-42 [o] a confirmed Naver publication copies the existing JPEG inside object storage to a job-owned `publishing/` key by source/target identity only, verified with HEAD; the API still never receives image bytes (PUBLISH owns the lifecycle of those keys)
- POST-43 [o] routes: `/` redirects to `/posts`; `/posts` lists title (or 제목 없음), status badge, relative `updated_at` up to a week then a date, and the one CTA 새 글; `/posts/new` is a draft with no slug; `/posts/$slug` renders 다른 사람의 글이에요 (403), 없는 글이에요 (404) or an unavailable view, offering a retry only for a failure that is not an answer; all under the authenticated layout; login's default destination is `/posts`; list rows are whole-row links with no row menu, swipe, or per-row button
- POST-44 [o] the editor presents the lifecycle as three steps 글 생성 · 글 다듬기 · 글 완성, the current step derived from `post.status` (draft ①, review ②, finalized ③) so a reload and the list badge cannot disagree; the step bar (`SegmentedControl`) is the first thing on the screen; any step is selectable — a step with no work says what it waits for and offers the way to the step that produces it; selecting a step changes no status and starts nothing; `/posts/new` has no step bar; the steps are panels of ONE mounted editor: title, memo, the autosave queue, the slug mint and the caret handoff live outside them
- POST-45 [o] the editor reports its own state in exactly one region at the page top (`pages/editor/ui/EditorStatus.tsx`): a 2px `shared/ui/progress-bar` pinned along the top edge while a job runs — determinate where the stage reports a ratio, indeterminate otherwise, zero layout height, `sticky` at `top-0` on a phone and `sm:top-16` above — and ONE `meta` line on the 목록/삭제 row carrying at most one thing in this precedence: a failing save, the running job's stage, the save state, the post's status; it replaced the status badge (the row never carries two indicators) and is present on `/posts/new` too ← a failing autosave outranks a job because a generation runs for minutes and the screen has no save button
- POST-46 [o] the job label names only the stage (사진 관찰 중 · 작성 중 · 문체 분석 중 and their A/B forms); its numbers are the bar's value and are never also spelled out; an unrecognized stage says 생성 중, never that nothing has started; the editor polls its job once at the page (`useEditorJob`, 2 s) and the status region and panels share it
- POST-47 [o] the docked bar holds controls and the reason a control is refused, and nothing else — no save line, progress notice, or status badge; a job's `FailureNotice` stays with its retry (a failure the user can act on is a control), as do the empty-profile warning, the deleted-voice warning and the language-mismatch notice; a bar holding neither is not rendered; exactly one docked bar per step; every blocker renders above the control it explains ← the software keyboard may hide a control but never its reason
- POST-48 [o] a refusal is said once, by the surface that resolves it: a pending A/B result disables 생성 and A/B 비교 and the A/B 결과 확인 link is the single statement; purely temporal reasons (a job in flight, a selection saving or loading) are not written under the buttons because the status line already says so; a setup refusal names something the user must choose, only once the model catalog has answered, collapsed to one line when both actions share it; no precondition or server refusal changed
- POST-49 [o] a standing state is never presented as an event: 확정 is reported on the status line; a finished job keeps only an `sr-only` live region that speaks on the transition to `done` (silent for a job already finished at mount); a completed learning run stays a notice on ③ ← it is the outcome of an action taken on that screen
- POST-50 [o] the 가제 belongs to ① alone; from ② on, the one title on screen is `content.title`, edited through the block editor's header; the 가제's value and autosave still live above the panels so unmounting the field cannot strand a queued save; the editor re-seeds its local 가제 from the confirmed title after a finalize
- POST-51 [o] one options surface — the writing brief (`widgets/generation-brief`), behind a settings glyph at the right end of ①'s dock row — holds 관찰 모델 · 작성 모델 · the A/B 후보 pair (two self-saving dropdowns, saving once both name different models, neither offering blank or its neighbour's model) · 목표 언어 · 목표 분량, and nowhere else; 말투 and 템플릿 sit on that same dock row as their own dropdowns with `sr-only` labels (each trigger reads its value; the voice's source-language chip appears only from `sm:`) ← both are chosen per draft and silently change a run, so they must be readable without opening anything, and three controls across 360 px leave no room for captions; 목표 언어 stays behind the trigger ← set once and followed by every run; a bottom sheet on a phone, a right-aligned popover bounded by the measured room from `sm:`
- POST-52 [o] when the only thing between ① and a run is that the models were never chosen, the bar drops 생성 and A/B 비교 and renders the per-action reason plus ONE route — the brief; any other blocker (a job running, a deleted voice, a selection loading) keeps ordinary disabled buttons ← waiting is the answer to those
- POST-53 [o] ①'s two actions split the dock row 3 : 7 on a phone, `A/B 비교` left and 생성 right ← the committing action takes the side a right-handed one-handed grip reaches first; from `sm:` the pair right-aligns at natural width
- POST-54 [o] each step renders only its own panel: ① the 가제, memo, photos, empty-profile warning and the contact sheet (one horizontal snap carousel with a 현재/전체 indicator on a phone); ② the draft as prose; ③ 말투 학습, export and publishing; the memo belongs to ① as the input 글 생성 works from
- POST-55 [o] ② opens as prose: `entities/post`'s `BlockList` renders title, summary, tags and every block read-only, each block and the header carrying one edit control on the shared `Editable`; opening a block does not close another; edits write through so autosave keeps running; 취소 restores the value the block held when its editor opened; moving or deleting a block closes it
- POST-56 [o] ②'s dock is ONE surface (`widgets/refine-dock`): the AI revision instruction with an icon-only send button under a visible heading `수정 요청을 입력하세요` at the `fieldTitle` role that IS the field's `<label>`, and `확정하기` as the CTA filling the rest of that row, opening `확정` (leads — available whenever the draft can be finalized) and `확정하고 말투 학습` (additionally needs an analyze model and a baseline) in a popover, a bottom sheet below `sm:`; the panel is the confirmation and no modal stands between press and run ← a finalize is reversed by the next content save anyway; on an already-finalized post the trigger is replaced by `글 완성으로 가기`; the secondary controls (character counter, `규칙으로 저장`, post-revision `지침으로 저장`) collapse while the field is empty and unfocused and expand on focus of the controls, not of the row
- POST-57 [o] 확정 flushes the block editor and the slug's content queue (which outlives an unmounted editor) before naming a revision, so it can never finalize one that omits a pending edit, and carries the user to ③; ③'s in-flow `말투 학습` stays on screen once the revision has been learned from, disabled with the outcome shown, and is disabled with the reason said in place while the revision on screen is not the finalized one or a voice gate refuses (the voice gate named ahead of the finalize gate ← confirming would not unblock it); ③ docks only for a running or failed job, never as an empty card
- POST-58 [o] a job's progress and failure are reported on every step (the status region is outside the panels; the dock's failure carries the retry, offered only on the step that owns the job); its completion is not
- POST-59 [o] editable `PostContent` uses a second per-post content queue: one request in flight, later edits replace one pending snapshot so the newest wins, each response supplies the next expected revision, an `Aborted` conflict stops retry and asks for a reload, transport failures back off exponentially, logout discards timers, snapshots and waiters, page hide calls `saveNow()` best-effort, and AI revision and finalization await `flush()`, whose promise returns the exact saved revision FinalizePost uses; manual saves never touch the baseline and machine writes never use this queue
- POST-60 [x] face blurring (its seam is inside the browser conversion step), image correction or generation, keeping originals or larger resolutions, version history, offline queueing beyond debounce + retry, server-side image decoding — out of scope

## flow
- new post: `/posts/new` (voice picker seeded with the default) → type or pick photos → `mint()` → slug → `/posts/<slug>` (replace) → autosave 1 s after each pause
- photo: select(gate) → decode → resize/encode → CreateUpload → PUT to storage → ConfirmUpload → cache patch → next GetPost supplies the presigned view URL
- lifecycle: draft →(machine result) review →(FinalizePost) finalized →(changed content save | machine result) review
- delete: 글 삭제하기 → dialog → DeletePost(generation active → refuse | publish non-terminal → refuse | purge experiment content → row + cascades + objects → detach guideline candidates) → end queues → `/posts`
