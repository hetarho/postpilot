# GEN generation, revision, job queue
> r15 | Photos, videos + memo become a validated block-array post in the author's voice through observation, a grouping of the photos into spaces the owner reviews, a story plan and then the write; AI revision changes only what was asked; every long model call rides one durable in-process job queue (invariants I2, I3, I5).

## decisions
- GEN-1 [o] a generated post is a `PostContent` block array, never HTML (I2); the flat `Block` types `TEXT` `HEADING` `IMAGE` `VIDEO` `QUOTE` `LIST` are the model-facing protojson contract (`VIDEO` carries the IMAGE fields →VIDEO-2)
- GEN-2 [o] every model-produced block passes one validation function right after parsing: missing required fields, fields forbidden for the type, empty list items and unknown types drop that block and log its type and field; an invalid heading level is clamped to 2; a non-heading `level` is normalized to 0 silently ← the structured-output schema requires `level` on every block; then every `IMAGE.file` is matched exactly and case-sensitively against the attached photo filenames and every `VIDEO.file` against the attached video filenames, and the rest are dropped and logged (→VIDEO-12)
- GEN-4 [o] ordinary generation and a chosen write-experiment result replace `posts.content` wholesale, establish a machine baseline and set `status = review`; A/B candidate completion alone never mutates canonical content; there is no generation version history or partial update
- GEN-5 [o] ordinary generation is two durable jobs — `group_photos` observes and groups (→GEN-58), `generate` plans and writes: StartGeneration validates ownership, one explicit active write model and, on a post with photos, a complete grouping (→GEN-12), freezes the required target language, the optional target length, the tag count, the post's optional template brief (→TMPL-11), the account's applicable writing-guideline texts, the ticked quality-rule texts (→GEN-51), whether the write model takes its effort natively (`write_native_effort` →MODEL-46), the confirmed grouping with its photos' observations and — only when the post opted in — the retrieved memory texts into the payload (→MEM-19), and returns only `job_id` — no provider call, no experiment
- GEN-6 [o] StartWriteExperiment is the separate explicit A/B path: two distinct write candidates, one shared frozen post/profile/option snapshot, the experiment and its job created before any provider work (MODEL owns experiments)
- GEN-7 [o] observation runs in the grouping job, before the grouping call: photos ordered by `created_at, id` — an order that only composes the batches and means nothing for the post (→TMPL-21) — read from private storage as the already-normalized JPEGs and capped again at `MaxImageBytes` by response length and by the stream, sent in batches of `OBSERVE_BATCH_SIZE` (4); each attached video follows in its own call, delivered by reference (→VIDEO-8 →VIDEO-10); the server decodes no image and reads no video
- GEN-8 [o] a run observes only the photos it was frozen to observe and reuses the rest: 사진 분석 on a post with at least one reusable stored observation opens the re-observation picker first, a post with nothing reusable starts directly, and the board's `사진 다시 분석` opens the same picker; every checkbox starts CLEAR so confirming untouched observes only what has nothing to reuse ← the common case is photos added to a post already analyzed; a photo with nothing to reuse (no entry, or none of scene, mood, visible text, objects, people) is checked, cannot be cleared, and is forced into the selection server-side ← a run must not group or write from a photo it has never looked at; a changed observation model warns naming both models but does not compel
- GEN-9 [o] the selection is frozen at enqueue with presence: a `ReobserveSelection` message absent means observe every attached photo (a client predating the picker), present with an empty list means observe nothing; the server intersects it with the attached photos, drops unknown names, forces the non-reusable ones, and freezes the resolved filenames together with the whole reusable snapshot into the payload; editing photos or switching models afterwards cannot change queued work; the lab comparison shares the picker and the contract (→GEN-19)
- GEN-10 [o] each observation batch is matched back by exact filename; results for unknown filenames are discarded; a missing result becomes an empty observation; every entry records the model ref that produced it, per entry ← re-observing a subset is what lets one snapshot hold two models' work; an entry written before provenance existed reads as unknown
- GEN-11 [o] every persist writes the merged snapshot and it never shrinks: the freeze-time seed with this run's fresh entries laid over it, so a partial re-observation is complete from the first persist; a photo neither half covers is left out rather than given an empty entry (an unseeded full run's persist sequence is unchanged); an empty frozen set makes no provider call and no snapshot write; observation progress totals the frozen set, so a reuse-everything run reports `observe 0/0` and proceeds to grouping at once
- GEN-12 [o] the write is shown only the photos in the frozen grouping, every one of which carries an observation, narrowed at dequeue to the photos still attached; a photo attached after the grouping was confirmed is in no space, so 글 쓰기 gives way to 사진 분석 until it is observed and placed (→GEN-25) and StartGeneration refuses an incomplete grouping; a deleted photo's observation and its place in the grouping go with it (→POST-18)
- GEN-13 [o] with no photos and no videos there is no grouping job and no plan call: 글 쓰기 starts the write at once, which clears stale observations and grouping and tells the writing model to use the memo without images; a post with videos and no photos observes them through 사진 분석, groups nothing and writes without a plan
- GEN-14 [o] write prompt order: static task/format rules including the grounding constraint, the altitude rule (→GEN-47) and the two title prohibitions (→GEN-49) → `[한국어 자연 문체 기준선]` for a Korean target only → the voice projection (typed descriptors once → active rules → excerpts → `[사용자 규칙]` → `[종결어미 제약]`) → the optional template brief bound from the plan (→TMPL-21) → the optional frozen `[작문 지침]` section (after the template when the post has one, otherwise directly after the ending constraint, always before per-post material, closed by a fixed precedence sentence: a guideline outranks a conflicting template instruction and the story, 문체 and 종결어미 stay with the voice, and a concrete vocabulary substitution outranks the profile →GUIDE-35) → the optional ticked quality rules (→GEN-51) → the per-post title hint, memo, the optional frozen `[기억]` section (→MEM-20, present only when the post opted in), the plan's `[오늘의 흐름]` (→GEN-65) and photo and video observations (→VIDEO-9) with the exact photo and video filenames; the prompt requires the frozen target for title, summary, tags, prose, alt text and captions, one paragraph per TEXT block, only attached filenames, IMAGE blocks at their template tokens when a template is bound and in the plan's photo order otherwise, a one-line summary and exactly the frozen `tag_count` tags
- GEN-15 [o] the template brief, the guideline texts and the selected memories are resolved once at enqueue from the post's template id through the template and guideline contexts' published lookups and written into the payload as text, the brief carrying the post's answers to the template's data fields already substituted and every field switched off or left blank already dropped (→TMPL-45), so an off field leaves the payload byte-identical to a template that never carried it and no separate answer field rides along; handlers build the prompt from the payload and never re-read the rows, so editing or deleting them later — across a restart-resume or an explicit retry — cannot change queued work; a template deleted before the start is simply absent; with no applicable guideline there is no section and the prompt is baseline-identical; the observe stage never receives either
- GEN-16 [o] the grounding constraint is code, not config: the writer may state no concrete fact absent from the memo, the observations and the template's data-field answers — the three standing as one authored-and-observed material, a value being the only fact its own position may state (→TMPL-46) — and may invent no interaction, facility, service, conversation or price; the write pass, which holds that material, is told to omit or confine to the observed range whatever it cannot confirm, and the rule is stated to bind factual claims alone so the author's impressions, opinions and changes of subject stay writable ← an unqualified rule left describing the photographs as the only safe thing to write; a post that opted into memories carries them as a fourth source, named inside their own section and nowhere else (→MEM-21); the revise pass, which holds neither memo nor observations and reaches the answers only through the frozen brief, is scoped to the sentences the request touches ← an unscoped rule would license stripping real facts out of untouched blocks; the shared core is in every write and revise prompt in both languages, disjoint from the naturalness baseline, and never in the observe prompt
- GEN-17 [o] `NaturalnessBaseline` is one code-owned constant shared by write and revise, injected exactly once after the static rules for Korean output and before the voice projection, omitted entirely for an English target; it is subtraction-only — capping stock antithesis, formulaic closers, obligation-ended paragraphs, connective-ending commas, uniform sentence structure, generic policy verbs, piled invented metaphors, abstract-noun chains, hype and unwarranted rhetoric — on newly written or explicitly revised TEXT prose only (titles, summaries, HEADING/LIST content and untouched text excluded); it adds no extra pass or call; its closing line makes the voice profile, active contrast rules and user rules authoritative on conflict; it must never gain bans on `~에 대해`, `~를 통해`, `~것이다` or sentence-initial conjunctions ← those folk rules were rejected against the corpus
- GEN-18 [o] the A/B snapshot freezes the same target, projection, brief, guideline texts, ticked quality rules, the confirmed grouping with its photos' observations and, for a post that opted in, 기억 (→MEM-19) so both candidates receive byte-identical inputs except for the model ref, and each candidate plans and writes on its own model (→GEN-63) ← the plan is part of writing; the input hash changes with target, template, the applicable guideline set, the ticks, the grouping or the memories; the experiment records the target and `template_name`; guideline texts are not projected for display
- GEN-19 [o] ordinary generation and an editor comparison observe nothing — both start from a complete confirmed grouping (→GEN-5); ordinary generation calls one writer and persists validated content directly; A/B gives both writers identical prepared snapshots, schema and options, runs them concurrently and stores validated candidate output under the experiment until an explicit verdict (I3); a lab comparison (→MODEL-66) reads the post's stored observations and grouping, observes a photo with nothing to reuse into its snapshot alone, treats a photo in no space as 그외, makes no grouping call and leaves the post's own observations and grouping untouched, including a post with no attachments
- GEN-20 [o] a model declaring structured output receives the relevant JSON schema; other models use the same parser, which accepts direct JSON, fenced JSON or the first complete JSON object; unparseable output is the durable reason `MODEL_OUTPUT_INVALID` with the raw head (`BadOutputErrorHeadChars` 200) as diagnostic detail only; output with terminal reason `length` and no usable content, including partial JSON, is budget exhaustion `MODEL_OUTPUT_TRUNCATED` with a shorter-target or different-model remedy; a failed write or observe candidate still returns provider-reported usage; revision uses the same classification
- GEN-21 [o] every provider call is bounded by `LLMStageTimeout` (5 min); no database transaction spans a provider call — observations, progress and final content are separate short writes
- GEN-22 [o] observation, grouping, the plan and writing/revision request reasoning effort `low` and voice analysis sends no preference; a per-(model, purpose) operator override may replace the value or omit the wire key (MODEL), grouping and the plan resolving under the write purpose they run on; completion budgets are per stage through `LLMCompletionBudget` — observation scales with the batch size, grouping and the plan with the photo count, writing derives from the requested target length, revision from the larger of that and the content it must re-emit — floored at `LLM_MAX_TOKENS_DEFAULT` (8192) and capped at a multiple of it; reasoning and visible output share the budget
- GEN-23 [o] start preconditions: the actor comes only from the session (a foreign post is `PermissionDenied`, an unknown one `NotFound`); 사진 분석 requires an enabled vision-capable observe model — with videos one that also carries `video_input`, refused `MODEL_VIDEO_UNSUPPORTED` (→VIDEO-11) — and an enabled write model for the grouping call; ordinary generation requires one enabled explicit write model and never depends on an A/B pair, A/B requires two distinct enabled write candidates, and on a post with photos ordinary generation and an editor comparison require a complete grouping (→GEN-12 →GEN-19); the queue's one-active-job-per-post constraint is authoritative under concurrency and a collision is `FailedPrecondition` carrying the active job id; ordinary generation is also refused `FailedPrecondition` while an editor write comparison of the post is still `queued`, `running`, `partial` or in `review`, or holds a decided verdict whose application or adoption is still pending, the refusal naming that experiment and never carrying its id as a job id, while a lab comparison (→MODEL-66) and a failed one never block; the post's voice must be active — a deleted voice is refused before any enqueue, for every path, with no fallback (→POST-25)
- GEN-24 [o] the contact sheet pairs each attached image and video with its persisted observation by exact filename and shows `scene`, `mood`, `visible_text`, `objects` (a video card also `events` and plays the clip inline →VIDEO-9); it is ①'s attachment view until the post holds a grouping, from which point the space board takes its place and a photo's card opens from its tile (→GEN-61); completed entries appear immediately and the rest say 관찰 대기; each non-terminal job snapshot refreshes the post read model; thumbnails use only the presigned `view_url` from GetPost, never a `blob:` upload preview; on a phone it is one horizontal snap carousel with cards narrower than the strip, a 현재/전체 indicator and no inner vertical scroller, from `sm:` a fixed-width strip; the reading view renders the block array directly and never stores or renders canonical HTML
- GEN-25 [o] everything the next run is given is set in ①'s dock and rendered nowhere else (→POST-51); ①'s actions follow the post (→POST-53): `사진 분석` while a photo or video awaits observation or a photo is in no space, then `글 쓰기` with `A/B 비교` once every photo is placed or the post has none; each action has its own model blockers and pending state, all await the latest title/memo/board save and refuse concurrent post work; 사진 분석 needs the observe and write models, 글 쓰기 the active writer and A/B 비교 the pair, so a zero-photo post needs no observe model; a published post blocks every action first (→POST-86), then a deleted voice, ahead of every other reason, with the shared message; the model lab's write comparison applies the same model and voice preconditions except the published lock, since it accepts a post in any status (→MODEL-31), and needs no grouping (→GEN-19)
- GEN-26 [o] the A/B pair fields offer only rows the surface can carry out: no blank row (`SaveComparisonPair` refuses an empty ref and no RPC clears a pair) and never the model the neighbour holds (a pair of one model twice is refused) ← either would have emptied or duplicated the FIELD while the saved pair went on running; swapping A for B is unnecessary since sides are fixed blind at start; the AI 모델 page's copy of the form saves the pair on change like the brief's, with no 저장 (→MODEL-65)
- GEN-27 [o] the voice projection is frozen per run: start freezes the owned post's exact `voice_id` with the input, the handler resolves that voice's profile version and language projection and nothing else; equal source/target receive the complete profile, a mismatch only the portable allowlist (LANG); candidate, retired and rejected rules, excluded cross-language fields and any other voice's data never enter the prompt; a result whose frozen voice no longer matches the post or is deleted is refused rather than written (applying an A/B winner rechecks the same rule); `target_length` absent is carried as absence with no hidden 1 200-character fallback while `tag_count` is always concrete (→POST-63); zero samples is valid and generation never starts learning, comparison, validation, embedding or judge work
- GEN-28 [o] long model work is a durable `generation_jobs` row: enqueue writes `queued` and returns the id without running the handler in the request; the worker inside the API process moves it `queued → running → done | failed` (I5); terminal rows are never reopened and a retry is a new row
- GEN-29 [o] enqueue is the one credit gate (→QUOTA-13): the queue hands the injected admitter the calls the job will make, with exact counts — zero included, so a reuse-everything run is held for no observation call, and per model across the whole job: a grouping job its observation calls plus one grouping call when a photo awaits a place, a write one plan call when the post has photos plus the write, each comparison candidate its own plan and write — and returns its refusal unwrapped so each rpc edge maps one typed error; the count is the enqueuing service's to state; the worker stamps owner, kind, id and stage refs onto the handler's context so every provider call lands on the ledger without the handler knowing
- GEN-30 [o] the row records owner, nullable `post_slug`, frozen `voice_id` (nullable only for work that neither reads nor publishes voice state), kind, stage, exact progress, frozen target language, a structured failure (`reason + params + technical_detail`; deprecated raw text read only for legacy rows), selected observe and write refs as `provider_id/model_id`, a kind-specific JSON payload and created/updated/started/finished timestamps; a `group_photos` payload freezes `observe_files` (carrying presence), the reusable observation snapshot and the stored grouping ← collapsing present-and-empty into absent would decode "reuse everything" as "re-observe everything", a silent double spend; a `generate` payload freezes target language, target length, tag count, the resolved template brief, guideline texts, the selected memory texts, the ticked quality-rule texts (`quality_rules`), `write_native_effort` and the confirmed grouping with its photos' observations; a `group_photos` row runs stages `observe` `group` and a `generate` row `plan` `write`; a `revise` payload freezes the instruction, `save_as_rule`, content language, template brief, guideline texts, `tag_count` and `write_native_effort`; a `model_experiment` payload is the experiment id with stages `observe` `compare_write` `compare_observe` `compare_analyze` and one monotonic compare counter
- GEN-31 [o] guards: one non-terminal job may target a post regardless of kind (partial unique index); one non-terminal voice-owned job per `(voice_id, kind)` (a `BEFORE INSERT` trigger, so pre-0009 active rows survive without rewriting statuses), a row also naming a post satisfying both; a row with neither keeps the older `(user_id, kind)` guard; `ErrAlreadyInProgress` carries the active id to attach to; a post-targeted row has a composite FK to `(posts.slug, posts.user_id)` and the guard lookup is owner-scoped; the voice context asks `HasActiveForVoice` before a soft delete and the job context never reads voice tables
- GEN-32 [o] the worker runs with concurrency 1 inside the API process; enqueue sends a best-effort in-process wake and a 1 s fallback poll catches a missed signal; the oldest queued row is picked first with one `UPDATE … RETURNING`; every progress callback is a separate short write through the serialized writer; handler success becomes `done`, a returned error `failed` with a stable owned reason and allowlisted params (a normalized `llm.ProviderError` maps to a model reason while provider prose stays technical detail), a panic `JOB_PANICKED`, and the worker continues
- GEN-33 [o] graceful shutdown stops the in-process worker before HTTP shutdown; a cancelled handler leaves its row running and a handler with an outcome gets one bounded terminal write; boot fails interrupted in-process jobs with JOB_INTERRUPTED before new work, but reconciles a CLIP job durably waiting on a media stage under ARCH-50; experiment boot recovery reconciles its own aggregates, and no recovery automatically repeats an uncertain paid provider call
- GEN-34 [o] queued `learn_voice` `compare_voice_rule` `validate_voice_profile` `seed_voice` rows are marked failed at boot before the worker starts and their aggregates expose failure and explicit retry (a seed simply leaves an empty voice) ← boot must never turn old user intent into a new provider call (→VOICE-45)
- GEN-35 [x] automatic retry, cancellation, a separate model-worker process or external model queue, multi-node model execution, a job-history RPC and streaming partial text remain outside post generation; CLIP media execution and its cancellation/retry policies are governed by CLIP and ARCH-45 through ARCH-58
- GEN-36 [o] GetGeneration(id) takes the acting user only from the session: another account's job is `PermissionDenied`, an unknown id `NotFound`; `Post.active_job` and `PostSummary.active_job` carry the post's queued/running job through the post context's consumer-owned `ActiveJobFinder` port (which also refuses a voice reassignment while a job targets the post); the list renders an active row 생성 중, recovers the durable id on reopen, and polls only while some returned post has an active job, stopping once the projection switches to a pending experiment review id
- GEN-37 [o] `useJob` asks GetGeneration every `POLL_INTERVAL_MS` (2 s) while `queued | running`, stops after `done | failed`, and on either terminal state invalidates the owner query keys the caller supplied, once per job; stage labels and progress templates are catalog keys rendered in the active locale; a failed row exposes its structured failure and an unknown, malformed or legacy value becomes localized `UNKNOWN_FAILURE`, never raw text; `FailureNotice` delegates retry to the owning feature's `onRetry`; progress and error feedback use live-region semantics and the design system's notice roles
- GEN-38 [o] revision is a durable `revise` job: StartRevision validates the authenticated user's post, existing content, a concrete `content_language`, a trimmed non-empty instruction of at most `RevisionInstructionMaxChars` (500) and an enabled explicit write model, is refused under GEN-23's pending editor write comparison rule, freezes the content language (never substituting the newer target), the exact `voice_id`, the template brief, the guideline texts, the tag count (→GEN-46) and `write_native_effort`, and returns the job id; it uses the same guard, polling, progress, restart and recovery mechanics as generation
- GEN-39 [o] `규칙으로 저장` requires the content language to equal the current voice's immutable source language, refused before any rule or job is created; when eligible the trimmed instruction is appended to the post's current voice before enqueue — never the default or another voice — and that append stands even if enqueue or the provider call later fails; exact duplicate lines are not appended twice (→VOICE-48)
- GEN-40 [o] the revise prompt reloads the frozen voice's current profile projected relative to the frozen content language (complete in canonical order when equal, portable allowlist otherwise), injects the Korean baseline before it, the template brief after the whole profile and before the current content, and the `[작문 지침]` section at the same relative position as in the write prompt, then the current full `PostContent`, the attached filenames and the instruction; it requires the smallest requested change, verbatim preservation of unrelated sentences, unchanged title/summary/tags unless requested (a requested tag change is bounded by the frozen `tag_count`), immutable attached filenames, the frozen content language with no translation semantics, and a complete replacement `PostContent` rather than a diff; a post with no template or no applicable guideline adds no bytes and stays byte-identical to the fixed golden
- GEN-41 [o] revision output uses the generation parser and validator; IMAGE and VIDEO blocks are filtered with exact filenames from a fresh attachment snapshot taken after the provider call ← a deletion during an in-flight revision must not leave a dangling reference; reordering attached IMAGE blocks is preserved; success replaces the whole canonical content and the machine baseline atomically, preserves the frozen `content_language`, and leaves status `review` (clearing a prior finalized revision); failure leaves content and baseline unchanged; revision never finalizes or learns
- GEN-42 [o] a completed revision records its instruction verbatim as a guideline candidate at this contract's 500-character bound, inside the job's completion path after the revised content is persisted and before the last progress tick, so a failed, cancelled or running revision records nothing; it creates no job and calls no provider, and a recording failure never fails the revision ← the result the user is looking at is authoritative; deduplication, counts and the pending bound belong to GUIDE, and no candidate ever reaches a prompt; `지침으로 저장` after a completed revision saves the user-edited instruction through the standard guideline RPC — an explicit save of user-authored text, nothing learned — approving the matching recorded candidate in the create's own transaction (`AlreadyExists` shown as already-saved); an edited save is a different rule and the original candidate stays pending; this adds no revision history
- GEN-43 [o] the revision form is the first row of ②'s dock (→POST-56), shown only when canonical content exists, using the account's explicit write-stage selection; disabled for an empty instruction, a missing or pending selection, an unresolved start, another active job, or a deleted voice (first, with the shared message; sentence feedback is not offered on such a post at all); every blocker renders above the row; the frontend flushes block-content autosave before StartRevision and a save conflict stops the action; the form refreshes the voice-profile cache after a rule append; a failed revision started in this editor session retries with its retained instruction, one resumed from an earlier session shows the failure and enables a new instruction ← the browser cannot reconstruct a private job payload
- GEN-44 [o] the memo is the naming authority: where the memo names a subject the observation recorded only generically, the writer uses the memo's name — in prose and in IMAGE `alt` and `caption` alike, a caption being written text rather than a transcript of the observation (키티 인형, not 고양이 인형) — while the observation stays authoritative on what is in the frame and nothing the observations do not show may be written as being in the frame ← the prohibition was written wide enough to read as a ban on any subject the memo alone carries, which is the material GEN-16 admits ← the grounding constraint holds the memo and the observations as one undifferentiated source, so nothing decided which noun won a disagreement and the observer's generic one reached the page; the rule is code beside the grounding constants, in the write prompt only — the revise pass holds no memo
- GEN-47 [o] the altitude rule is code beside the grounding constants and sits in the write prompt only: the observations are grounding and placement material rather than a list to describe, no paragraph is required to point at a photo, and visual detail that carries nothing for the post — lighting, walls, ceilings, fixtures, the arrangement of a room — is not written ← the writer was covering the observation array entry by entry, which reads as a caption for every photograph rather than as one post
- GEN-45 [x] the observe prompt receiving the post's title and memo — observation stays context-free
- GEN-46 [o] `tag_count` is frozen into every prompt-building path that asks the model for tags — generation, revision and write comparison (→MODEL-30 →LANG-18), not rule comparison (→VOICE-42) — from the post at start, and a different count is a different input hash; a result carrying more tags than the frozen count keeps the first `tag_count` in model order and one carrying fewer is accepted as written ← failing a paid write over a tag miscount is worse than a shorter list; legacy queued payloads without the member decode as `POST_TAG_COUNT_DEFAULT`
- GEN-49 [o] two code-owned title prohibitions ship beside the grounding constants — no title whose long text varies only by a single piece of information, and no keyword repeated twice or more inside one title; an authored title form outranks both, which then bind only what the model writes inside the form's `<write>` (→TMPL-52) ← they are the only two title rules with a primary source, and every other claim about titles stays out

- GEN-51 [o] a ticked quality rule's text (→QUAL-13) renders at the head of the per-post half, never in the stable prefix, closed by a fixed line saying a conflicting 지침 outranks it ← the ticks differ per post, and the prefix is what the provider's cache and every prompt golden rest on (→MEM-20)

- GEN-56 [o] 사진 분석, Start, StartRevision and applying a write-experiment winner refuse a published post before any job, snapshot or provider call, beside GEN-23's and GEN-38's preconditions (→POST-74)
- GEN-58 [o] 사진 분석 enqueues a durable `group_photos` job after the preconditions of →GEN-23 and →GEN-56: it freezes the re-observation selection with the reusable snapshot (→GEN-9) and the stored grouping and returns only `job_id`; the worker observes the frozen set (→GEN-7), then makes one grouping call when a photo is in no space and outside 그외 (→GEN-59) and persists the grouping onto the post; with nothing to observe and nothing to place it enqueues nothing
