# GEN generation, revision, job queue
> r1 | Photos + memo become a validated block-array post in the author's voice through observe-then-write; AI revision changes only what was asked; every long model call rides one durable in-process job queue (invariants I2, I3, I5). Migrated from legacy policy/generation.md, policy/jobs.md, policy/revision.md, plan/05, plan/06, plan/07.

## decisions
- GEN-1 [o] a generated post is a `PostContent` block array, never HTML (I2); the flat `Block` types `TEXT` `HEADING` `IMAGE` `QUOTE` `LIST` are the model-facing protojson contract; a `Block` may carry an optional typed `slot {kind, label}` on TEXT for an unfilled template slot ← a sixth BlockType would force every switch (reading view, block editor, four exports, revision, validator) to change merely to stay correct (TEMPLATE)
- GEN-2 [o] every model-produced block passes one validation function right after parsing: missing required fields, fields forbidden for the type, empty list items and unknown types drop that block and log its type and field; an invalid heading level is clamped to 2; a non-heading `level` is normalized to 0 silently ← the structured-output schema requires `level` on every block; then every `IMAGE.file` is matched exactly and case-sensitively against the attached filenames and the rest are dropped and logged
- GEN-3 [o] one template pass runs after validation and the attachment filter, only when a template was frozen: it resolves the copy tokens the model reproduced into slot blocks and re-inserts any slot the model omitted at its template position (after the nearest preceding resolved slot, else before the nearest following one, else at the end); a block holding several tokens resolves each and keeps the prose between; a repeated token resolves once; idempotent, and run again after a revision; it verifies nothing else — no deviation drops a block, fails a run or retries
- GEN-4 [o] ordinary generation and a chosen write-experiment result replace `posts.content` wholesale, establish a machine baseline and set `status = review`; A/B candidate completion alone never mutates canonical content; there is no generation version history or partial update
- GEN-5 [o] ordinary generation is a durable `generate` job: StartGeneration validates ownership and one explicit active write model (plus an explicit vision-capable observe model when photos exist), freezes the required target language, the optional target length, the post's optional template brief and the account's applicable writing-guideline texts into the payload, and returns only `job_id` — no provider call, no experiment
- GEN-6 [o] StartWriteExperiment is the separate explicit A/B path: two distinct write candidates, one shared frozen post/profile/option snapshot, the experiment and its job created before any provider work (MODEL owns experiments)
- GEN-7 [o] with photos, observation always precedes writing: photos ordered by `created_at, id`, read from private storage as the already-normalized JPEGs and capped again at `MaxImageBytes` by response length and by the stream, sent in batches of `OBSERVE_BATCH_SIZE` (4); the server decodes no image
- GEN-8 [o] a run observes only the photos it was frozen to observe and reuses the rest: a post with photos and at least one reusable stored observation opens the re-observation picker first, a post with nothing reusable starts directly; every checkbox starts CLEAR so confirming untouched reuses everything and skips observation ← the common case is a write stage that failed on photos that did not change; a photo with nothing to reuse (no entry, or none of scene, mood, visible text, objects, people) is checked, cannot be cleared, and is forced into the selection server-side ← a run must not write from a photo it has never looked at; a changed observation model warns naming both models but does not compel
- GEN-9 [o] the selection is frozen at enqueue with presence: a `ReobserveSelection` message absent means observe every attached photo (a client predating the picker), present with an empty list means observe nothing; the server intersects it with the attached photos, drops unknown names, forces the non-reusable ones, and freezes the resolved filenames together with the whole reusable snapshot into the payload; editing photos or switching models afterwards cannot change queued work; the A/B path shares the picker and the contract from both entry points
- GEN-10 [o] each observation batch is matched back by exact filename; results for unknown filenames are discarded; a missing result becomes an empty observation; every entry records the model ref that produced it, per entry ← re-observing a subset is what lets one snapshot hold two models' work; an entry written before provenance existed reads as unknown
- GEN-11 [o] every persist writes the merged snapshot and it never shrinks: the freeze-time seed with this run's fresh entries laid over it, so a partial re-observation is complete from the first persist; a photo neither half covers is left out rather than given an empty entry (an unseeded full run's persist sequence is unchanged); an empty frozen set makes no provider call and no snapshot write; observation progress totals the frozen set, so a reuse-everything run reports `observe 0/0` and proceeds to writing at once
- GEN-12 [o] the writing stage is shown only the photos the run has eyesight for: attachments are read live at dequeue and narrowed to the merged snapshot, so a photo confirmed between enqueue and dequeue is neither observed nor named and belongs to the next run; a deleted photo's observation is deleted with it (→POST-18)
- GEN-13 [o] with no photos, observation makes no provider call, reports `observe 0/0`, clears stale observations and tells the writing model to use the memo without images
- GEN-14 [o] write prompt order: static task/format rules including the grounding constraint → `[한국어 자연 문체 기준선]` for a Korean target only → the voice projection (typed descriptors once → active rules → excerpts → `[사용자 규칙]` → `[종결어미 제약]`) → the optional frozen template brief → the optional frozen `[작문 지침]` section (after the template when the post has one, otherwise directly after the ending constraint, always before per-post material, closed by a fixed precedence sentence: a guideline outranks a conflicting template instruction, register stays with the voice) → the per-post title hint, memo, observations and exact filenames; the prompt requires the frozen target for title, summary, tags, prose, alt text and captions, one paragraph per TEXT block, only attached filenames, context-appropriate image placement, a one-line summary and `TagsMin`–`TagsMax` (3–6) tags
- GEN-15 [o] the template brief and the guideline texts are resolved once at enqueue from the post's template id through the template and guideline contexts' published lookups and written into the payload as text; handlers build the prompt from the payload and never re-read the rows, so editing or deleting them later — across a restart-resume or an explicit retry — cannot change queued work; a template deleted before the start is simply absent; with no applicable guideline there is no section and the prompt is baseline-identical; the observe stage never receives either
- GEN-16 [o] the grounding constraint is code, not config: the writer may state no concrete fact absent from the memo and the observations and may invent no interaction, facility, service, conversation or price; the write pass, which holds that material, is told to omit or confine to the observed range whatever it cannot confirm; the revise pass, which holds neither memo nor observations, is scoped to the sentences the request touches ← an unscoped rule would license stripping real facts out of untouched blocks; the shared core is in every write and revise prompt in both languages, disjoint from the naturalness baseline, and never in the observe prompt
- GEN-17 [o] `NaturalnessBaseline` is one code-owned constant shared by write and revise, injected exactly once after the static rules for Korean output and before the voice projection, omitted entirely for an English target; it is subtraction-only — capping stock antithesis, formulaic closers, obligation-ended paragraphs, connective-ending commas, uniform sentence structure, generic policy verbs, piled invented metaphors, abstract-noun chains, hype and unwarranted rhetoric — on newly written or explicitly revised TEXT prose only (titles, summaries, HEADING/LIST content and untouched text excluded); it adds no extra pass or call; its closing line makes the voice profile, active contrast rules and user rules authoritative on conflict; it must never gain bans on `~에 대해`, `~를 통해`, `~것이다` or sentence-initial conjunctions ← those folk rules were rejected against the corpus (legacy change 10)
- GEN-18 [o] the A/B snapshot freezes the same target, projection, brief and guideline texts so both candidates receive byte-identical inputs except for the model ref; the input hash changes with target, template or the applicable guideline set; the experiment records the target and `template_name`; guideline texts are not projected for display
- GEN-19 [o] observation runs at most once in either mode; ordinary generation calls one writer and persists validated content directly; A/B gives both writers identical prepared snapshots, schema and options, runs them concurrently and stores validated candidate output under the experiment until an explicit verdict (I3)
- GEN-20 [o] a model declaring structured output receives the relevant JSON schema; other models use the same parser, which accepts direct JSON, fenced JSON or the first complete JSON object; unparseable output is the durable reason `MODEL_OUTPUT_INVALID` with the raw head (`BadOutputErrorHeadChars` 200) as diagnostic detail only; output with terminal reason `length` and no usable content, including partial JSON, is budget exhaustion `MODEL_OUTPUT_TRUNCATED` with a shorter-target or different-model remedy; a failed write or observe candidate still returns provider-reported usage; revision uses the same classification
- GEN-21 [o] every provider call is bounded by `LLMStageTimeout` (5 min); no database transaction spans a provider call — observations, progress and final content are separate short writes
- GEN-22 [o] observation and writing/revision request reasoning effort `low` and voice analysis sends no preference; a per-(model, purpose) operator override may replace the value or omit the wire key (MODEL); completion budgets are per stage through `LLMCompletionBudget` — observation scales with the batch size, writing derives from the requested target length, revision from the larger of that and the content it must re-emit — floored at `LLM_MAX_TOKENS_DEFAULT` (8192) and capped at a multiple of it; reasoning and visible output share the budget
- GEN-23 [o] start preconditions: the actor comes only from the session (a foreign post is `PermissionDenied`, an unknown one `NotFound`); ordinary generation requires one enabled explicit write model and never depends on an A/B pair, A/B requires two distinct enabled write candidates, and with photos both require an enabled vision-capable observe model (stored empty without photos); the queue's one-active-job-per-post constraint is authoritative under concurrency and a collision is `FailedPrecondition` carrying the active job id; the post's voice must be active — a deleted voice is refused before any enqueue, for both paths, with no fallback (→POST-25)
- GEN-24 [o] the contact sheet pairs each attached image with its persisted observation by exact filename and shows `scene`, `mood`, `visible_text`, `objects`; completed entries appear immediately and the rest say 관찰 대기; each non-terminal job snapshot refreshes the post read model; thumbnails use only the presigned `view_url` from GetPost, never a `blob:` upload preview; on a phone it is one horizontal snap carousel with cards narrower than the strip, a 현재/전체 indicator and no inner vertical scroller, from `sm:` a fixed-width strip; the reading view renders the block array directly and never stores or renders canonical HTML
- GEN-25 [o] everything the next run is given is set in ①'s dock and rendered nowhere else (→POST-51); the editor's 생성 and A/B 비교 have independent model blockers and pending states, both await the latest title/memo save and refuse concurrent post work; a missing pair blocks only A/B and a missing active writer only 생성; a zero-photo post needs no observe model; a deleted voice blocks both, before every other reason, with the shared message; the model lab's write comparison applies the same preconditions
- GEN-26 [o] the A/B pair fields offer only rows the surface can carry out: no blank row (`SaveComparisonPair` refuses an empty ref and no RPC clears a pair) and never the model the neighbour holds (a pair of one model twice is refused) ← either would have emptied or duplicated the FIELD while the saved pair went on running; swapping A for B is unnecessary since sides are fixed blind at start; the AI 모델 page's copy of the form keeps both entries behind an explicit 저장 that says the choice is not in effect
- GEN-27 [o] the voice projection is frozen per run: start freezes the owned post's exact `voice_id` with the input, the handler resolves that voice's profile version and language projection and nothing else; equal source/target receive the complete profile, a mismatch only the portable allowlist (LANG); candidate, retired and rejected rules, excluded cross-language fields and any other voice's data never enter the prompt; a result whose frozen voice no longer matches the post or is deleted is refused rather than written (applying an A/B winner rechecks the same rule); `target_length` absent is carried as absence with no hidden 1 200-character fallback; zero samples is valid and generation never starts learning, comparison, validation, embedding or judge work
- GEN-28 [o] long model work is a durable `generation_jobs` row: enqueue writes `queued` and returns the id without running the handler in the request; the worker inside the API process moves it `queued → running → done | failed` (I5); terminal rows are never reopened and a retry is a new row
- GEN-29 [o] enqueue is the one credit gate (→QUOTA-13): the queue hands the injected admitter the calls the job will make, with exact counts — zero included, so a reuse-everything run is held for no observation call, and per model across the whole job — and returns its refusal unwrapped so each rpc edge maps one typed error; the count is the enqueuing service's to state; the worker stamps owner, kind, id and stage refs onto the handler's context so every provider call lands on the ledger without the handler knowing
- GEN-30 [o] the row records owner, nullable `post_slug`, frozen `voice_id` (nullable only for work that neither reads nor publishes voice state), kind, stage, exact progress, frozen target language, a structured failure (`reason + params + technical_detail`; deprecated raw text read only for legacy rows), selected observe and write refs as `provider_id/model_id`, a kind-specific JSON payload and created/updated/started/finished timestamps; a `generate` payload freezes target language, target length, template brief, guideline texts, `observe_files` (carrying presence) and the reusable observation snapshot ← collapsing present-and-empty into absent would decode "reuse everything" as "re-observe everything", a silent double spend; a `model_experiment` payload is the experiment id with stages `observe` `compare_write` `compare_observe` `compare_analyze` and one monotonic compare counter
- GEN-31 [o] guards: one non-terminal job may target a post regardless of kind (partial unique index); one non-terminal voice-owned job per `(voice_id, kind)` (a `BEFORE INSERT` trigger, so pre-0009 active rows survive without rewriting statuses), a row also naming a post satisfying both; a row with neither keeps the older `(user_id, kind)` guard; `ErrAlreadyInProgress` carries the active id to attach to; a post-targeted row has a composite FK to `(posts.slug, posts.user_id)` and the guard lookup is owner-scoped; the voice context asks `HasActiveForVoice` before a soft delete and the job context never reads voice tables
- GEN-32 [o] the worker runs with concurrency 1 inside the API process; enqueue sends a best-effort in-process wake and a 1 s fallback poll catches a missed signal; the oldest queued row is picked first with one `UPDATE … RETURNING`; every progress callback is a separate short write through the serialized writer; handler success becomes `done`, a returned error `failed` with a stable owned reason and allowlisted params (a normalized `llm.ProviderError` maps to a model reason while provider prose stays technical detail), a panic `JOB_PANICKED`, and the worker continues
- GEN-33 [o] graceful shutdown stops the worker before HTTP shutdown; a handler that returns cancellation leaves its row `running`; one that already produced an outcome gets one bounded terminal write even if shutdown raced it; the next boot sweeps every still-running row to `failed` with `JOB_INTERRUPTED` before a new worker starts, and experiment boot recovery then reconciles its own aggregates
- GEN-34 [o] queued `learn_voice` `compare_voice_rule` `validate_voice_profile` `seed_voice` rows are marked failed at boot before the worker starts and their aggregates expose failure and explicit retry (a seed simply leaves an empty voice) ← boot must never turn old user intent into a new provider call (→VOICE-45)
- GEN-35 [x] automatic retry, cancellation, a separate worker process or external queue, multi-node coordination, a job-history RPC, streaming partial text to the client — out of scope
- GEN-36 [o] GetGeneration(id) takes the acting user only from the session: another account's job is `PermissionDenied`, an unknown id `NotFound`; `Post.active_job` and `PostSummary.active_job` carry the post's queued/running job through the post context's consumer-owned `ActiveJobFinder` port (which also refuses a voice reassignment while a job targets the post); the list renders an active row 생성 중, recovers the durable id on reopen, and polls only while some returned post has an active job, stopping once the projection switches to a pending experiment review id
- GEN-37 [o] `useJob` asks GetGeneration every `POLL_INTERVAL_MS` (2 s) while `queued | running`, stops after `done | failed`, and on `done` invalidates the owner query keys the caller supplied; stage labels and progress templates are catalog keys rendered in the active locale; a failed row exposes its structured failure and an unknown, malformed or legacy value becomes localized `UNKNOWN_FAILURE`, never raw text; `FailureNotice` delegates retry to the owning feature's `onRetry`; progress and error feedback use live-region semantics and the design system's notice roles
- GEN-38 [o] revision is a durable `revise` job: StartRevision validates the authenticated user's post, existing content, a concrete `content_language`, a trimmed non-empty instruction of at most `RevisionInstructionMaxChars` (500) and an enabled explicit write model, freezes the content language (never substituting the newer target), the exact `voice_id`, the template brief and the guideline texts, and returns the job id; it uses the same guard, polling, progress, restart and recovery mechanics as generation
- GEN-39 [o] `규칙으로 저장` requires the content language to equal the current voice's immutable source language, refused before any rule or job is created; when eligible the trimmed instruction is appended to the post's current voice before enqueue — never the default or another voice — and that append stands even if enqueue or the provider call later fails; exact duplicate lines are not appended twice (→VOICE-48)
- GEN-40 [o] the revise prompt reloads the frozen voice's current profile projected relative to the frozen content language (complete in canonical order when equal, portable allowlist otherwise), injects the Korean baseline before it, the template brief after the whole profile and before the current content, and the `[작문 지침]` section at the same relative position as in the write prompt, then the current full `PostContent` — slot markers included, a slot block's content being its copy token because the structured-output block object is closed — the attached filenames and the instruction; it requires the smallest requested change, verbatim preservation of unrelated sentences, unchanged title/summary/tags unless requested, immutable attached filenames, the frozen content language with no translation semantics, and a complete replacement `PostContent` rather than a diff; a post with no template or no applicable guideline adds no bytes and stays byte-identical to the fixed golden; the template pass runs again on the result so a dropped slot returns to its own position
- GEN-41 [o] revision output uses the generation parser and validator; IMAGE blocks are filtered with exact filenames from a fresh attachment snapshot taken after the provider call ← a deletion during an in-flight revision must not leave a dangling reference; reordering attached IMAGE blocks is preserved; success replaces the whole canonical content and the machine baseline atomically, preserves the frozen `content_language`, and leaves status `review` (clearing a prior finalized revision); failure leaves content and baseline unchanged; revision never finalizes or learns
- GEN-42 [o] a completed revision records its instruction verbatim as a guideline candidate at this contract's 500-character bound, inside the job's completion path after the revised content is persisted and before the last progress tick, so a failed, cancelled or running revision records nothing; it creates no job and calls no provider, and a recording failure never fails the revision ← the result the user is looking at is authoritative; deduplication, counts and the pending bound belong to GUIDE, and no candidate ever reaches a prompt; `지침으로 저장` after a completed revision saves the user-edited instruction through the standard guideline RPC — an explicit save of user-authored text, nothing learned — approving the matching recorded candidate in the create's own transaction (`AlreadyExists` shown as already-saved); an edited save is a different rule and the original candidate stays pending; this adds no revision history
- GEN-43 [o] the revision form is the first row of ②'s dock (→POST-56), shown only when canonical content exists, using the account's explicit write-stage selection; disabled for an empty instruction, a missing or pending selection, an unresolved start, another active job, or a deleted voice (first, with the shared message; sentence feedback is not offered on such a post at all); every blocker renders above the row; the frontend flushes block-content autosave before StartRevision and a save conflict stops the action; the form refreshes the voice-profile cache after a rule append; a failed revision started in this editor session retries with its retained instruction, one resumed from an earlier session shows the failure and enables a new instruction ← the browser cannot reconstruct a private job payload

## flow
- generate: 생성 → StartGeneration(preconditions → freeze target, length, brief, guidelines, voice, reobserve selection + snapshot → hold credits → job row) → worker(observe frozen set in batches → merged snapshot persists → write → validate → attachment filter → template pass → content + baseline, `review`) → `useJob` polls 2 s → `done`
- revise: instruction (+ 규칙으로 저장 → AppendRule) → StartRevision(freeze content language, voice, brief, guidelines) → worker(revise prompt → validate → fresh attachment filter → template pass → content + baseline, `review` → record guideline candidate) → done
- queue: Enqueue(guards → admitter → `queued`) → worker picks oldest(`running`) → progress writes → `done | failed(reason, params, detail)`; boot: running → `failed JOB_INTERRUPTED`, queued personalization → `failed`

## constraints
- config BE (`internal/platform/config`): `OBSERVE_BATCH_SIZE` 4 (env) · `LLMStageTimeout` 5m · `LLMMaxTokensDefault` 8192 (env) · per-stage completion budgets and the stage reasoning policy (typed constants) · `WorkerConcurrency` 1 · `WorkerPollInterval` 1s; `internal/generation`: `TagsMin` 3 · `TagsMax` 6 · `BadOutputErrorHeadChars` 200 · `RevisionInstructionMaxChars` 500; `internal/job`: `JOB_INTERRUPTED` `JOB_PANICKED`; FE `shared/config`: `POLL_INTERVAL_MS` 2000 · `REVISION_INSTRUCTION_MAX_CHARS` 500
- prompt text, JSON schemas, the naturalness baseline and the grounding constraint are code, never config or rows
- schema: `generation_jobs(id, user_id, post_slug NULL, voice_id NULL, kind, status, stage, progress_done, progress_total, target_language, reason, params, technical_detail, observe_model, write_model, payload, created_at, updated_at, started_at, finished_at)` with the post/account partial unique indexes and the voice `BEFORE INSERT` trigger
- placement BE: `backend/internal/generation` (observe, write, revise, prompts, schemas, handlers; consumer-owned ports to post, voice, template, guideline, llm) · `backend/internal/job` (queue, worker, guards, `PlannedCalls`, `ActiveJobFinder` behaviour)
- placement FE: `entities/generation-job` · `entities/observation` · `features/generate-post` · `features/edit-with-ai` · `features/configure-model-pair` · `widgets/contact-sheet` · `widgets/generation-brief` · `widgets/refine-dock` · `pages/editor`
- tests that pin it: prompt-assembly snapshots (order, baseline presence per language, grounding constraint) · block validator and attachment filter with crafted payloads · `ceil(N/4)` observation calls with a stubbed provider · frozen re-observation set and non-shrinking snapshot · no write transaction across a provider call (handler harness) · guard collisions carry the active id · boot sweep reasons
