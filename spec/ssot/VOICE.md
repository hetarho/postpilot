# VOICE voices and voice profiles
> r1 | An account owns one or more mutually isolated 말투 (voices); each owns one typed, versioned profile and every piece of evidence that can change it — optional pasted samples, a written description, explicitly finalized posts — and is projected into prompts without fallback (invariant I4). Migrated from legacy policy/voice.md, plan/03, plan/10, tech/voice-personalization-learning.md, tech/multi-voice-partitioning.md.

## decisions
- VOICE-1 [o] an account owns one or more voices (`voices`), the user-facing noun 말투; each voice owns exactly one possibly-empty profile and every row that can change it — `voice_profiles`, `voice_samples`, profile versions, manual overrides, learning events, authored sources, contrast rules and evidence, confirmations, sentence feedback, rule comparisons, validations, version snapshots — all keyed by `(user_id, voice_id)`; no shared account-level profile, inheritance, copying or fallback: a voice with no evidence is empty even when a sibling is well trained ← a merged profile can never be separated again
- VOICE-2 [o] every account has at least one active voice and exactly one active default (partial unique index `voices_one_default`); active display names are unique within the account (`voices_active_name`); a tombstone's name reserves nothing
- VOICE-3 [o] every store query and RPC is scoped by the authenticated user and by one voice, named explicitly (`voice_id` on profile, sample, version, override, confirmation-list, validation and analyze-experiment requests) or derived from an owned aggregate (a rule, an event, a post); no request carries a user id; a foreign voice id is indistinguishable from an unknown one (`NotFound`); a same-account id from another voice is refused — never interchangeable evidence
- VOICE-4 [o] migration 0009 created one active default `기본 말투` per existing account and reassigned every post and profile/evidence row to it losslessly (bodies, snapshots, revisions, statuses, timestamps kept; a guard table asserts no unassigned rows before the swap; its Down refuses to collapse multi-voice data); `adduser` runs the voice context's idempotent `EnsureDefaultVoice` right after creating the account and exits non-zero if it cannot; a rerun repairs without duplicating; reads never create a voice or a profile
- VOICE-5 [o] a profile is never modified by, and never contains, template text or a writing guideline: neither enters `ProfileForPrompt`, the profile's bytes are identical with and without them, register stays voice-owned, and `규칙으로 저장` is the only revision path that writes voice state (TEMPLATE, GUIDE)
- VOICE-6 [o] the profile is the structured profile, its earned rules and its sample excerpts; the free-text styleguide no longer exists — migration 0017 dropped the column, `UpdateVoiceProfile` was removed, both editors and the 이전 수동 안내 section are gone, and a voice whose analysis lived only in that text was rescued as its version 1 with the text as an `analyzed` lexical description; `voice_profiles.rules` survives as the 규칙으로 저장 text alone, with no editor, no RPC, and untouched by analysis
- VOICE-7 [?] retire 규칙으로 저장 in favour of GUIDE's 지침으로 저장 — an open product decision inherited from legacy job 43's build notes
- VOICE-8 [o] a sample body is private server-side source material; RPCs return only id, label, Unicode character count and creation time, never the body
- VOICE-9 [o] ListVoices returns the account's voices including tombstones — active first, the default first among them, then by name and id; the order is part of the contract and the frontend re-applies it after a cache patch; GetVoiceProfile returns the owning voice summary with the profile
- VOICE-10 [o] CreateVoice trims the name, requires 1–`VoiceNameMaxChars` (50) Unicode scalar values and an explicitly present supported immutable `source_language` (`InvalidArgument` otherwise), refuses an active-name collision (`AlreadyExists`), and creates an empty isolated profile without copying the default; existing and bootstrap voices are Korean; no RPC changes a source language after creation; there is no voice-count limit
- VOICE-11 [o] CreateVoice also takes an optional trimmed `description` of at most `VoiceDescriptionMaxChars` (500) scalar values (`VOICE_DESCRIPTION_TOO_LONG`, `InvalidArgument`) with the account's analyze-stage ModelRef: with one it creates the voice, enqueues exactly one `seed_voice` job and answers the job id; without one it needs no model and answers an empty job id; length and model are checked before the insert so a refusal leaves no voice; a seed the queue refuses to start (too few credits) still leaves a real, usable, listed voice ← creation and seeding are separable outcomes
- VOICE-12 [o] RenameVoice changes the display name of an active or deleted owned voice with the same validation, rewriting no post row and no immutable snapshot; SetDefaultVoice accepts only an active owned voice, atomically clears the previous default, and answers with the whole directory ← the previous default changed too
- VOICE-13 [o] DeleteVoice is a soft delete (`deleted_at`): it refuses the active default, the last active voice, and a voice that still has a queued or running voice-owned job, an undecided rule comparison or validation, or a publishable analyze experiment (all `FailedPrecondition`); posts, samples, versions, rules, sources and completed history stay; the voice disappears from selectable options at once; deleting a tombstone is a no-op; there is no hard-delete path ← a tombstone keeps post history renderable without cascading profile rows away
- VOICE-14 [o] RestoreVoice clears `deleted_at` without enqueueing anything, fails `AlreadyExists` while an active voice holds the same name (rename the tombstone first), and never changes the default
- VOICE-15 [o] a deleted voice stays addressable for display — profile, versions and history readable — but every profile mutation (samples, updates, overrides, adopting a version, analysis, learning, feedback, comparison, validation, experiment application) is refused `FailedPrecondition` before any enqueue or provider call
- VOICE-16 [o] directory reads, lifecycle mutations, page load, polling, copy, export, time and boot make no provider call and enqueue no work (I5); a described creation is the one explicit exception, and it enqueues rather than calling a provider in the request
- VOICE-17 [o] `seed_voice` is voice-owned like every personalization kind: it serializes against that voice's other work, is refused for a deleted voice, blocks that voice's deletion while queued or running, and fails before the boot worker drain; the handler makes exactly one completion against the account's analyze-stage selection, in the voice's `source_language`, in the same nine-section shape the analysis produces, and publishes it as profile version 1 with origin `seed` (migration 0016 widened the origin check)
- VOICE-18 [o] a description is an instruction, never evidence: it becomes no `voice_samples` row, no source count, no few-shot entry, no embedding, no `corpus_version` bump, and `can_validate` is unchanged; the published version carries only the `analyzed` lexical description and leaves every measured quantity and axis unset, rendered `unknown` and never `0` ← measuring the request's own prose would report the user's prompt style as their writing
- VOICE-19 [o] a seed never overwrites real work: it publishes only while the profile is still empty and unversioned and the corpus version it read still holds; a seed that resolves after a sample analysis or a finalization completes without writing; seeding happens once at creation with no re-seed RPC — a failed seed leaves an ordinary empty voice whose 말투 tab shows the failure, and the recovery path is 기존 글 가져오기
- VOICE-20 [o] a sample body is trimmed and must contain at least `SampleMinChars` (200) Unicode characters (the rejection names the measured count); an empty label falls back to the first `LabelFallbackChars` (20) characters; before storing, the requested model must exactly match the account's current enabled analyze-stage selection, otherwise nothing is stored or enqueued
- VOICE-21 [o] adding a sample stores it under its voice and enqueues `analyze_voice` frozen to that voice; if that voice already has an active analysis the sample stays stored and the existing durable job id is returned; two voices of one account analyze independently; deleting a sample re-enqueues while samples remain, deleting the last leaves the published profile untouched; a non-conflict queue failure is compensated before the RPC returns (a just-added sample removed, a just-deleted one restored)
- VOICE-22 [o] sample insertion/deletion and finalized-source writes advance the voice's `corpus_version` in the same transaction; analysis publishes only when `ClaimCorpusVersion` still matches — it writes no text, its whole job is to decide whether the finished analysis still describes the newest corpus — otherwise the same job repeats over the newest snapshot; typed publication also compares the profile head ← stale provider output can never overwrite a concurrent source, override, rule or restore; deleting the last sample during a call finishes the job without publishing
- VOICE-23 [o] analysis loads the voice's full current corpus (imports plus finalized authored sources) with labelled separators and runs through the shared job queue (`analyze 0/1 → 1/1`, the model recorded in `write_model`); it selects a source-language prompt and schema: Korean keeps the nine ordered sections and a deterministic ending distribution; English measures word length, register and contractions, connectives, passive and nominal tendencies, terminal cadence, structure, lexical habits and the same six axes without projecting into Korean ending categories; each corpus holds only evidence declared for its immutable source language
- VOICE-24 [o] the nine Korean sections, in order: 종결어미 distribution (the primary signal) · average sentence length · sentences per paragraph · frequent connectives and adverbs · verbal tics and signature phrases · emoji, interjections, ellipses · metaphors and numerals · common expressions this author never uses · first-person expression; the handler fails a result missing the 종결어미 section
- VOICE-25 [o] a successful analysis publishes a new structured version whose lexical description IS the analysis and preserves the 규칙으로 저장 text; provider failures follow the job queue's user-facing error policy; when a version already exists the frontend asks for confirmation before adding a sample ← re-analysis replaces the current analysis
- VOICE-26 [o] the effective profile is a whole immutable snapshot: lexical description with preferred/banned words and patterns; endings as the primary layer (base register, measured distribution, bans and signatures, constraints); syntax measurements; opening/closing and paragraph/heading/list/emoji structure; six integer axes bounded to `-3..3`, each carrying presence — an unanswered axis publishes as unknown and renders 알 수 없음, never 0, while an answered value out of range fails the job; rule metadata, authored-source/few-shot references, feedback references, version, timestamps, source count; snapshots already holding explicit zeros are immutable
- VOICE-27 [o] the analysis call names every key it expects including the `axes` object and its six keys, attaches the embedded schema `internal/voice/schemas/voice_analysis.schema.json` when the resolved model declares `structured_output` and falls back to the prompt alone otherwise; deterministic Unicode measurements override conflicting model estimates for ending distribution and average sentence length; weak evidence is represented explicitly as `unknown`
- VOICE-28 [o] a manual field override is stored separately, replayed after analysis, and published as a new whole-profile version; clearing it replays the newest analysis snapshot plus the remaining overrides; adopting an older version copies its snapshot into a new head; history is never moved or deleted; a profile field is read first (label, provenance badge, wrapping text) and its pencil opens that one field — a capped growing textarea, 저장, 취소, and 직접 설정 해제 only when the source is `manual`; fields are independent and a rejected save keeps edit mode and the draft
- VOICE-29 [o] every published version may carry at most one generation snapshot (`voice_version_samples`, primary key `(voice_id, version)`, foreign key `(voice_id, user_id)`): a copy of the raw AI output of the last post generated under it, written by `generation` — the only context depending on both post and voice — through the consumer-declared `VersionSampleWriter` port right after each machine-baseline write; a failure to record never fails the generation; a later generation under the same head replaces it; the content crosses as opaque `PostContent` protojson that `internal/voice` never parses; the version list carries `has_sample` only and `GetVoiceProfileVersionSample(voiceID, version)` returns the body on open; being a copy, deleting, regenerating, editing or reassigning the source post leaves it unchanged
- VOICE-30 [o] 버전 기록 is a list of openable rows naming number, origin and restored-from; opening shows the version's date and its generation snapshot — the title and body of the last post it wrote — bounded by `VOICE_VERSION_PREVIEW_CHARS` (400) with a way to read the rest, read as text rather than re-rendered ← it has no image rows behind its file references — and `이 버전으로 변경`; the preview IS the confirmation; a version that never produced a post says so and shows no empty preview; the head is openable and offers no way to adopt itself; a deleted voice's versions are read-only
- VOICE-31 [o] `GetVoiceProfile.active_job_id` exposes the voice's queued or running analysis so clients resume polling after navigation or reload
- VOICE-32 [o] zero sources is supported: the typed profile is empty/unknown and generation stays enabled; historical imports are optional and only their paste surface carries the 200-character minimum; no screen requests or recommends 30 posts; three finalized posts are required only for the separately started profile validation
- VOICE-33 [o] finalization and learning are separate explicit boundaries: 확정 records the exact finalized revision without a model or a voice mutation; `확정하고 말투 학습` performs that finalization and starts learning with an explicitly selected enabled analyze model, and `말투 학습` may do so later while the same revision remains finalized; the input-hashed `voice_learning_events` row (unique on account, voice, post, baseline revision and input hash) freezes post-owned baseline/final JSON before enqueue; repeats return the existing event and retries never duplicate a source, version, feedback or evidence row
- VOICE-34 [o] learning derives its voice from the post and freezes it on the event — the caller cannot nominate another; it requires `post.voice_id == machine_baseline_voice_id == event.voice_id` and concrete frozen content/source languages equal to the voice's source language; a mismatch is refused before event, job or provider creation; a deleted voice cannot receive evidence; retries follow the event's frozen voice even after the post is reassigned; completed sources, rules and versions stay in their original voice ← a correction against voice A's text must never become evidence about voice B
- VOICE-35 [o] a learning setup, enqueue, worker or provider failure leaves the post finalized and exposes a separate retryable learning outcome; retry never repeats finalization or demotes the post; when boot has failed an old queued job, Learn or Retry re-enqueues the same immutable event
- VOICE-36 [o] a completed event adds the finalized post to that voice's authored-source/few-shot bank in one short transaction (source, excerpt, extracted evidence and rules, whole profile version, completion) after provider calls finish; the first source is eligible for the next generation even when its topic differs; topic/tag matches rank ahead of stable recent fallback; a completed event is a no-op on retry and source/evidence uniqueness constraints are the final arbiters
- VOICE-37 [o] rule extraction: the deterministic segmenter counts Unicode code points and classifies `다`, polite `해요`, formal `니다/습니다` and other endings; an LCS diff keeps stable equal sentences and pairs unmatched runs in order; inside the learning job `voice-diff-rules-v1` asks the selected analysis model to discard factual or topic changes and return strict JSON with at most `VOICE_DIFF_MAX_RULES` (3) generalized `LLM does …, but I do …` rules, each citing at least `VOICE_DIFF_MIN_PATTERN_EDITS` (2) independent edits; the server rejects unknown layers, malformed statements, duplicate or out-of-range citations and citations inconsistent with measured endings/length, and stores citation references rather than source prose
- VOICE-38 [o] canonical equality and direct negation are checked first; only undecidable cases ask `voice-semantic-rule-v1` for `same | contradicts | distinct` against same-layer rules; one event adds at most one evidence row per matched rule; evidence moves `candidate/1 → candidate/2 → active/3` (`VOICE_RULE_ACTIVATION_EVIDENCE`); candidate, retired and rejected rules never enter generation; a contradiction against an active rule stores the source and a pending confirmation and leaves rule state and the head unchanged until the owner resolves it; resolution reloads the rule set inside the same transaction so the published version matches the row exactly
- VOICE-39 [o] an active rule older than `VOICE_RULE_RETIRE_AFTER` (180 d) retires only while servicing a later explicit generation or revision request — no clock-driven process exists; retirement and its new profile version commit together, and a failed retirement blocks prompt construction rather than using stale rules
- VOICE-40 [o] rule status changes, confirmations and comparisons name only the rule and the server reads the voice off the owned row; sentence feedback derives its voice from the post and its finalization source, is one of vocabulary, ending, length or structure, is retry-idempotent against owned final text, and a no-edit satisfaction is auxiliary — neither alone creates or activates a rule; feedback, revision save-as-rule, post-backed comparison and validation all repeat the content/source-language equality gate before any mutation or provider work
- VOICE-41 [o] 문장 의견 is offered on 글 완성 only, for a post whose voice-learning run has completed (the server's own precondition); its surface states that it teaches the voice and does not change this post, naming AI 수정 as the way to change the post; the sentence is chosen from a vertical wrapping `radiogroup` of full-width rows (one tab stop, select-one semantics); no free-text field
- VOICE-42 [o] rule comparison is an explicitly started blind one-rule job frozen to the rule's voice, source, profile version, optional target length, examples and an explicit write model; its two calls share the input and differ only by the selected rule; the rule-on side is hidden until a decision, which requires exactly two successful non-empty candidates; a rule-on verdict adds evidence to that rule only, a rule-off verdict rejects it; model Elo is untouched
- VOICE-43 [o] profile validation starts with an explicit active voice, requires `VOICE_VALIDATION_POST_COUNT` (3) finalized authored sources of that voice, freezes the profile and explicit analyze/write models, selects three sources deterministically from a random id, writes topic-only neutral summaries and then new prose from them, and calls a judge only when the user explicitly enables it (Y/N for endings, sentence rhythm, opening/closing, vocabulary, addressee against the frozen version); no Elo
- VOICE-44 [o] comparison and validation are durable jobs with partial retry: a failed enqueue fails the aggregate and stops blocking a new start; a failed link compensates by failing the queued row, or returns the durable ids when a worker already owns it
- VOICE-45 [o] boot marks queued `learn_voice` `compare_voice_rule` `validate_voice_profile` `seed_voice` rows failed before the worker starts (running ones use the ordinary restart sweep) and never drains old personalization rows into provider calls; page load, navigation, copy/export, polling, profile age, scheduler and cron never enqueue or call a personalization model; a failed job stays visible and retryable while the last valid post and profile head stay unchanged
- VOICE-46 [o] `PromptProfileForTopic(userID, voiceID, retrievalText, tags, targetLanguage)` publishes one voice's language-aware projection: with equal source and target languages the complete typed descriptors injected once (no legacy free text beside them), evidence-ranked active rules, bans and ending constraints, up to `ExcerptCount` (3) unique excerpts (topic/tag matches first, stable recent fallback, `ExcerptChars` 1500), and the 규칙으로 저장 lines as `[사용자 규칙]` after the excerpts; with a different target only the exact portable structure/axes allowlist LANG defines; it never translates, leaks excluded fields, falls back to another voice or consults another language's evidence; `empty` means no published version, no sample and no finalized source — rules alone do not count
- VOICE-47 [o] the prompt tells the model not to copy source phrases or facts, follows the measured ending distribution and forbids a third consecutive identical ending (`VOICE_ENDING_MAX_CONSECUTIVE` 2); candidate and retired rules are excluded; zero excerpts is valid
- VOICE-48 [o] `AppendRule(userID, voiceID, line)` trims one line, de-duplicates an exact existing line, and appends with a newline; it is the only writer of that text and appends are serialized in the single API process so concurrent revision flows cannot lose a line
- VOICE-49 [o] an analyze-model experiment (MODEL) names one explicit active owned `voice_id` — the server never substitutes the default — freezes that voice's complete corpus once and runs two explicit analyze refs through the same nine-section prompt and validator; candidates change neither profile nor rules; a verdict reveals model identities; applying the winner requires overwrite confirmation, publishes a structured version with origin `analysis` whose lexical description is the winning analysis and whose measured half is measured from the current corpus as an analysis run would, carrying the manual overrides and earned rules, and only while still the head — a lost race is reported as a failure to apply; a deleted voice or a moved head refuses; adopting the winner as the account's analyze model is separate, and Elo and stage selections stay account-scoped
- VOICE-50 [o] every provider-backed operation freezes a `voice_id` before enqueue: generation and revision from the owned post, learning from the post onto the event, comparison from the owned rule, validation and experiments from an explicit active voice, retries from the durable owner row — never from the post's current assignment; the handler rechecks that the frozen voice belongs to the account and may receive the result and never follows a later reassignment; `generation_jobs.voice_id` is nullable only for work that neither reads nor publishes voice state; voice-owned kinds are guarded per `(voice_id, kind)` and a post-linked row must satisfy both the post guard and the voice guard
- VOICE-51 [o] no third-party sentence, Korean morphology, diff, vector, embedding, SDK, Python, CGO, sidecar or model dependency: segmentation, counts, ending buckets, LCS, canonical rule keys and tag retrieval use the Go standard library ← keeps the static SPA + distroless Go deployment and makes unit tests deterministic; `embedding_ref` is a dormant seam and `VOICE_EMBEDDING_SWITCH_POSTS` (50) selects nothing today
- VOICE-52 [o] 말투 is the directory `/voices`, a LIST: each active voice is one row and one target — a stretched link into the voice (no underline, nothing interactive nested in the anchor), its `기본` and language badges, and for a non-default voice `기본으로 설정` and `삭제` layered above the link so pressing one acts without navigating; tombstones live in a `삭제된 말투 N개` disclosure rendered only when one exists, closed on load, its rows keeping `복원`; the page's one CTA is a docked `새 말투 만들기`; renaming is not on the directory
- VOICE-53 [o] `새 말투 만들기` opens the shared `Sheet` (a bottom sheet below `md:`) with the name field and its `n / 50자` count, the source-language listbox, and an optional `말투 설명` textarea with its own count; the commit action sits in flow after the last field rather than in the pinned footer ← the panel is anchored to the layout viewport the software keyboard does not resize; with no usable analyze selection the description's message slot says so and creating without a description still works; success closes the sheet and navigates to the new voice, where the seed reports progress and failure through the analysis surface; deletion is confirmed through the sheet, which says what stays, and the default offers no delete; server refusals (duplicate name, over-long description, deleted default, busy voice, restore conflict) render under the control in the user's words
- VOICE-54 [o] one voice is `/voices/$voiceId` with five sibling tabs sharing one row of links (the matching tab carries `aria-current="page"`): 프로필 · `/versions` · `/import` (analyze-stage model selector, paste form whose first field is 제목 (선택), sample list, analysis progress) · `/rules` · `/validations`; the layout's `h1` names the voice and is where it is renamed (read-first behind a pencil; a tombstone stays renameable so a restore conflict can be resolved), badges default/deleted, shows a notice with `복원` for a tombstone and blocks the import form with the reason; an unowned id reads `없는 말투예요.`; legacy `/voice` and `/voice/<tab>` redirect to the same tab of the default voice, or to `/voices` when there is none, creating nothing; `/voices/$voiceId/rules/$id/compare` and `/voices/$voiceId/validations/$id` return to their owning tab; each tab issues only the queries its panel renders (the profile query is shared) and an in-flight list reads as loading rather than as an empty voice; the top-level destinations stay 글 / 말투 / AI 모델
- VOICE-55 [o] the learn action is disabled below 200 trimmed Unicode characters or without a usable analyze selection; an RPC rejection renders from stable `AppFailure` reason/params in the active locale, never raw transport prose; `active_job_id` resumes polling; a successful job refreshes that voice's profile query; deletion shows re-analysis progress while samples remain
- VOICE-56 [o] every voice query cache is partitioned by `(account, voice)` — `voices`, `voice-profile`, `voice-versions`, `voice-confirmations`, `voice-validations`, and the snapshot by `(account, voice, version)` — so two voices of one account and two accounts on one device never read each other's entry; directory mutations patch the cached list in the server's order (create/rename/delete/restore upsert one voice, set-default installs the returned list); rename, delete and restore also mark the voice's scope and every cached post stale; save responses patch only their owned field into the newest snapshot and delayed responses clear an input only when it still equals the submitted value; the SPA removes every account-scoped cache on logout and on a mid-session authentication failure

- VOICE-58 [o] all learning prose, diffs, feedback, comparisons, validations and versions are private account data, cascading from the owning account or post as migrations 0007 and 0009 declare; a soft-deleted voice keeps every row and only stops accepting new evidence; no private prose is logged; no cross-account or cross-voice retrieval, comparison, validation or prompt input exists

## flow
- create: 새 말투 만들기 → CreateVoice(name, source_language, description?) → voice (+ one `seed_voice`) → `/voices/$id`
- import: paste ≥ 200 chars → AddVoiceSample(model = analyze selection) → `analyze_voice` over the full corpus → ClaimCorpusVersion(ok → publish version | stale → repeat)
- learn: 확정 → 확정하고 말투 학습 | 말투 학습 → event(hash, frozen voice) → `learn_voice` → diff → rules + evidence → source + version → done | failed(retry learning only)
- delete: DeleteVoice(default | last | busy → refuse | tombstone) → posts keep `VoiceRef{deleted}` → RestoreVoice | reassign the post
