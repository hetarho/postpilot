# TEMPLATE post templates (템플릿)
> r1 | A reusable, account-owned document that decides the shape of a post — literal text, reserved positions, what repeats per photo, where prose goes — written in a small internal tag grammar, expanded and frozen at enqueue, and never learned from. Migrated from legacy policy/templates.md, tech/post-template-grammar.md, plan/11.

## decisions
- TEMPLATE-1 [o] a template decides the shape of a post; three authored axes stand beside each other and each owns one question — the voice decides how sentences sound (VOICE), the template what shape the post has, a guideline what the post must avoid (GUIDE); a post combines exactly one voice and at most one template; it replaced the retired 용도 ← prose about shape had to be re-derived by the model every run, could not require a literal line, and could not bind output to the attachments
- TEMPLATE-2 [o] a template has exactly three authored fields — `name`, `description`, `body` — plus timestamps; `body` is the single source of truth for the shape: what the database stores, what the prompt receives after expansion, and what the builder round-trips; the builder is a parser plus a renderer over that string and never a second representation
- TEMPLATE-3 [o] every store query and RPC is scoped by the authenticated user and no request carries a user id; a foreign template id is `NotFound` like an unknown one; `templates_id_user` is the composite target `posts.template_id` points at, so a post can never name another account's template; `templates_user_name` keeps display names unique per account
- TEMPLATE-4 [o] there is no tombstone: a deleted template is gone and its name is free again at once ← unlike a voice, a template is not something a post was written in, only something the next machine run is told
- TEMPLATE-5 [o] migration 0022 created `templates` and `guideline_templates`, replaced `posts.purpose_id` with `posts.template_id` under the same composite account FK and detach trigger, renamed `model_experiments.purpose_name` to `template_name` (renamed, not cleared ← a frozen comparison must keep saying what both candidates were given), and dropped `purposes` and `guideline_purposes`; destructive by the owner's decision after inspecting production (two purposes and two assigned finalized posts dropped rather than converted)
- TEMPLATE-6 [o] field rules: `name` trimmed, non-empty, ≤ `TEMPLATE_NAME_MAX_CHARS` (40), unique among the account's templates after trim (`AlreadyExists`, `TEMPLATE_NAME_TAKEN`); `description` trimmed, may be empty, ≤ `TEMPLATE_DESCRIPTION_MAX_CHARS` (200), management copy that never reaches a prompt; `body` trimmed at the edges only, non-empty, ≤ `TEMPLATE_BODY_MAX_CHARS` (4000) and it must parse; creating beyond `TEMPLATE_MAX_PER_ACCOUNT` (50) is `FailedPrecondition`, checked inside the insert transaction; limits are Unicode scalar-value counts on both sides; a bound violation is `InvalidArgument` `TEMPLATE_FIELD_TOO_LONG` with `field` `max` `actual` params; the backend is authoritative and the frontend mirrors the three ceilings only for live counters
- TEMPLATE-7 [o] parsing is part of validation: a body that does not parse has no meaning and cannot be saved; the refusal is `InvalidArgument` `TEMPLATE_PARSE_FAILED` with allowlisted `line` and `reason` params ← the editor must point at the offending line without parsing wire prose
- TEMPLATE-8 [o] UpdateTemplate is presence-based with one statement per present field inside one transaction, so an omitted field is never named by any statement and no read-modify-write can restore a stale value; a present empty `description` clears it, a present empty `name` or `body` is refused; the template screen sends all three fields in one call because they are one draft edited in one place; the `body` is never trimmed on its way to the server ← it is the canonical serialization
- TEMPLATE-9 [o] DeleteTemplate removes the template and returns `detached_posts`; the detach is the schema trigger `templates_detach_posts_on_delete` running in the delete's own transaction ← `ON DELETE SET NULL` on a composite child key would null `posts.user_id` too; the delete also cascades the template's `guideline_templates` rows while every guideline survives (one left with no links applies nowhere and lists as 적용 대상 없음); no post, content, photo, guideline or history is deleted; frozen payloads and snapshots keep the rendered body; the confirmation names detached posts only
- TEMPLATE-10 [o] assignment to a post is presence-aware with three meanings (absent preserves, present-empty clears to 없음, present value assigns), validated before anything else in the request, allowed in every status and while a job runs, and touches no content, revision, baseline, finalization or learn eligibility ← nothing is ever learned from a template; `TemplateRef {id, name}` reaches the post through the consumer-owned `TemplateDirectory` port (→POST-26)
- TEMPLATE-11 [o] the template is resolved once, at enqueue, and what gets frozen is the rendered body — expanded for the post's attached photos and turned into prompt text with copy tokens ← expansion inside the freeze is what makes "attaching a photo after the start cannot change the run" true, and it is the only place the expansion bound can refuse before a provider is called
- TEMPLATE-12 [o] one `[글 템플릿: {name}]` section enters the write and revise prompts after the complete voice profile and before the per-post material, with `[작문 지침]` after it; it carries a fixed grammar legend, the rendered body between `---` fences, then a fixed precedence sentence; absent a template the builder adds no bytes at all ← the position is load-bearing twice: the voice-profile prefix stays byte-stable across posts of different templates, and the section stays in the stable half so every revision re-injects the identical block
- TEMPLATE-13 [o] the heading, legend and precedence sentence never use the word 지침 ← the retired purpose section used it for two different things one section apart; the framing stays Korean for every target language (it frames user-authored text, not the output-language contract) and the target language outranks a conflicting language instruction inside a template (LANG)
- TEMPLATE-14 [o] handlers read the frozen copy from the payload and never the live row: editing or deleting the template after StartGeneration or StartRevision returns — including across a restart-resume or an explicit retry — cannot change the prompt; a template deleted between the save and the start is simply absent; a payload written before templates existed decodes as no template
- TEMPLATE-15 [o] a write A/B experiment freezes the same rendered body into the shared snapshot so both candidates receive byte-identical system prompts; a different template is a different input hash; `ModelExperiment.template_name` records the name, stored rather than derived, so the detail keeps reading after a rename, a delete or the retention sweep
- TEMPLATE-16 [o] nothing about a template is learned, inferred, suggested or written by a model (I4 stays entirely with voice); no template is selected from a title, memo, tags, photos or content; there is no default and no seeded library; the observe stage never sees one (I3); no template surface makes a provider call or enqueues a job (I5) — listing, selecting, creating, editing, deleting, parsing and the builder are plain CRUD and pure client work
- TEMPLATE-17 [o] the grammar is XML-tag delimited ← an LLM reads tag-delimited structure most reliably and the write prompt already asks for protojson, so a second brace language is the one thing to avoid; closing tags make nesting decidable; attributes carry the machine-readable parts; and `[사진 …]` is already the Naver export's photo marker
- TEMPLATE-18 [o] five constructs: bare text is literal (verbatim in prompt and post) · `<write>지시</write>` writes prose here per the instruction (tags intact in the prompt) · `<slot kind="…" label="…"/>` reserves a content position (a copy token in the prompt; a resolved block or an unfilled slot in the post) · `<repeat each="photo">…</repeat>` expands once per attachment · `<note>지시</note>` instructs the model only and reaches the page as nothing; `slot` is self-closing only with required `kind` ∈ `photo` · `place` · `link` and an optional `label` shown to the user and carried into the block, never an instruction; `repeat` requires `each` whose only value is `photo` and may hold literal · write · slot · note; `write` and `note` hold text only; everything else is a parse error with no lenient fallback ← a body that half-parses would silently drop the structure the user asked for
- TEMPLATE-19 [o] a body parses to an ordered node list; literal and text-holding nodes keep their raw source slice and serialization re-emits those slices, so parse → serialize is byte-exact by construction for hand-written and builder bodies alike; `<` starts a tag when followed by an identifier (or `/` plus one) and then whitespace, `>` or `/`, otherwise it is literal text (`3 < 5` needs no escape); an identifier that is not one of the five is `unknown_tag`, not literal ← a mistyped tag printing itself into every post is worse than needing `&lt;` for a rare literal tag; entities `&lt;` `&gt;` `&amp;` decode when a node's text is read, never in the stored slice
- TEMPLATE-20 [o] a body that does not parse cannot be saved and every error names a 1-based line and one reason: `unknown_tag` · `unclosed_tag` · `unexpected_close` · `malformed_tag` (unparsable attributes, or `slot` with a closing tag) · `missing_attribute` · `unknown_slot_kind` · `unknown_repeat_each` · `nested_repeat` · `empty_write`; the Go parser (`backend/internal/template`) and the TypeScript parser (`frontend/src/entities/template/lib`) are tested against one shared fixture file `backend/internal/template/testdata/grammar/cases.json` plus a committed differential corpus, and a new rule lands in the fixture first ← that file is the only mechanism keeping two implementations of one grammar honest
- TEMPLATE-21 [o] expansion at enqueue: each `<repeat each="photo">` becomes one copy of its children per attached photo, bound by filename in attachment order; zero photos drops the whole block including its literals; an expansion whose total node count would exceed `TEMPLATE_MAX_REPEAT_EXPANSION` (40) is refused at start rather than sending an unbounded prompt; rendering keeps literals and `write`/`note` tags as written and turns each slot into a copy token the model must reproduce verbatim — `photo` → `{{photo:<filename>}}` (emit an IMAGE block with exactly that file), `place` · `link` → `{{slot:<n>}}` (emit a TEXT block containing exactly that token) ← copying twelve characters exactly is something a model does reliably, reproducing a label is not; the rendered text and ordered slot specs are frozen beside `target_length`
- TEMPLATE-22 [o] a slot stays honest rather than filled: an unfilled slot is a TEXT block carrying the optional typed `slot {kind, label}`, not a sixth BlockType (→GEN-1); the template pass after validation and the attachment filter (→GEN-3) turns a TEXT block whose content is exactly `{{slot:n}}` into slot n's block, strips a token embedded in a paragraph and inserts the slot before it, and inserts a slot with no token at its template position; the slot block's content is the token, not the label ← the structured-output block object is closed and cannot carry the marker, so a token in the content survives a revision round-trip and lets the pass find the slot at its own position instead of re-appending it; the pass is idempotent and re-runs after every revision; literal fidelity and section order are not verified and no deviation fails, retries or discards a usable generation
- TEMPLATE-23 [o] unfilled slots warn, they never gate: finalization and export are not blocked; the editor states how many remain and the reading view shows where each is; the export panel states the count and the four outputs render each slot as a bracketed placeholder in marker order, distinguishable from the Naver `[사진 …]` markers by their filename suffix (EXPORT)
- TEMPLATE-24 [o] `/templates` is a top-level destination (템플릿, after 말투, lazily split) and a LIST: one-target rows carrying the name, the description and the post count, the whole row linking to the template and the delete painted above the link layer; one docked `+ 새 템플릿` is the only thing that adds; the empty state says what a template is for in plain language, shows no worked body and no marker syntax, and creates no row — there are no shipped presets
- TEMPLATE-25 [o] `/templates/$templateId` edits one template and `/templates/new` is the same component with nothing in it; the screen holds one draft (name, description, composition) and one 저장 as its only committing action, disabled while the draft equals what is stored; in-app navigation away from a dirty draft is warned about, and `beforeunload` warns only when something unsaved would be lost; the clean baseline is the mutation's own response, not the directory query ← the query lags a save by a refetch, which would leave 저장 re-enabled and the guard warning about a template just written; the create path's own post-save redirect is exempted from the guard through a ref
- TEMPLATE-26 [o] the composition is authored through one control and one mode: no source view, no mode switch, and no grammar syntax rendered to the user anywhere ← the grammar is the contract between the builder and the write prompt; one row is one block, collapsed to a kind badge and a one-line summary of its own text so the rows read as the outline of the post; a `repeat`'s children are a nested list beneath it, always visible; at most one row is expanded at a time and its fields and its delete edit in place
- TEMPLATE-27 [o] an always-visible add toolbar, sticky to the top, inserts at the current position — after the row last touched, and inside a `repeat` when that is where the position is — with that position drawn in the list before the click; an aim whose block is gone resolves to the end, where the marker is drawn too ← without the visible marker one toolbar would be worse than the two entry points it replaced
- TEMPLATE-28 [o] reordering offers both pointer drag and move buttons ← HTML5 drag events do not fire on touch and the base breakpoint is a 360 px phone; both are scoped to a sibling group (a `repeat`'s children are their own list) ← the grammar cannot express a block that left its repeat; drag events stop propagating so a nested list's drag never moves its parent; `SortableList` carries a `compact` density for the collapsed rows
- TEMPLATE-29 [o] the editor holds its rows in local state and contributes only complete blocks to the body ← a block exists as a row the moment it is added and an empty `<write></write>` does not parse; a value that is not what the editor last emitted came from outside (a refetch, a clear) and only then are the rows reseeded; a row with nothing in it makes the draft no dirtier; builder → body → builder is byte-identical for anything the builder produced
- TEMPLATE-30 [o] a body the parser cannot read (from before the builder, or edited outside the app) shows the composition as unreadable and offers exactly one action, 비우고 다시 만들기, which empties the composition in the draft while name and description stay editable and nothing is written until 저장 ← inventing a structure the author did not write would be worse than saying so, and there is no source view to repair it in
- TEMPLATE-31 [o] the directory query is re-read on every mount (`staleTime: 0`, `refetchOnMount: 'always'`) ← `post_count` is a projection over posts that no template mutation can invalidate, and it is the number the user confirms a destructive detach against; a rename also invalidates the post caches because the name is projected onto every assigned post
- TEMPLATE-32 [o] the editor and `/posts/new` show a 템플릿 picker defaulting to 없음 on ①'s dock row beside the 말투 picker (→POST-51) with an `sr-only` label, no description line and no 템플릿 관리 link; selecting writes a presence-aware patch through the draft queue; on a create 없음 sends no field at all; the select stays enabled while a job runs and says the running job keeps the template it started with; a failed directory read shows a failure with a retry, never an empty directory ← that would leave clearing as the only available action; the post list shows the template name beside the voice for an assigned post
- TEMPLATE-33 [o] the composition editor lives in `entities/template/ui` ← it performs no mutation, it is a controlled input over one of the entity's own fields, and the shape of a block is the entity's business; `features/create-template` and `features/edit-template` keep their mutation hooks and nothing else; the page owns the draft and composes the three
- TEMPLATE-34 [x] learning, inferring or model-writing a template; guessing one from post material or a default; seeded templates; filling a slot in the app (map or place lookup, URL validation, platform call); strict compliance validation; a richer grammar (other iterators, conditionals, variables, expressions, nested repeats, inheritance, includes); per-template model, target length, tags, reasoning effort or quota; version history, soft-delete, import/export, sharing; per-voice templates or a template–voice link; changing the memo's role — out of scope; the model catalog's "purposes" (MODEL) share only the English word
- TEMPLATE-35 [o] four defects are regression-pinned in the shared fixtures: a Go/JS blank-character disagreement (`U+FEFF` vs `U+0085`), slot insertion that reversed template order, a block holding two tokens leaving one behind, and a slot label containing `"` producing a body the builder's own parser refused

## flow
- author: `/templates` → `+ 새 템플릿` → `/templates/new`(rows → complete blocks → body) → 저장(parse ok → row | TEMPLATE_PARSE_FAILED line + reason)
- run: post picks template → StartGeneration / StartRevision(resolve once → expand per photo → bound check → render tokens → freeze) → prompt section after the voice profile → model output → template pass(resolve tokens → insert missing slots) → post with honest slots
- delete: DeleteTemplate → trigger detaches posts (count returned) + cascades guideline links → name free again

## constraints
- config: `TEMPLATE_NAME_MAX_CHARS` 40 · `TEMPLATE_DESCRIPTION_MAX_CHARS` 200 · `TEMPLATE_BODY_MAX_CHARS` 4000 (BE `platform/config` env; FE `shared/config` mirrors via `VITE_TEMPLATE_*` falling back to the default) · `TEMPLATE_MAX_PER_ACCOUNT` 50 · `TEMPLATE_MAX_REPEAT_EXPANSION` 40 (BE only; a non-positive or malformed value is boot-fatal); the tag names, token forms, slot kinds, section heading, legend, precedence sentence and the proto/SQL schema are code, not configuration
- schema (migration 0022): `templates(id PK, user_id FK, name, description, body, created_at, updated_at, UNIQUE(id, user_id), UNIQUE(user_id, name) …)` · `posts.template_id` composite FK + `templates_detach_posts_on_delete` trigger · `guideline_templates` composite FK · `model_experiments.template_name`
- placement BE: `backend/internal/template` (types, grammar, expand, corpus and grammar tests, `testdata/grammar/cases.json` + `corpus.json`, store, rpc; `TemplateDirectory` and the enqueue lookup consumed by post and generation through ports wired in `cmd/api`)
- placement FE: `entities/template` (`lib/grammar.ts`, `model/types.ts`, `ui` composition editor) · `features/create-template` `edit-template` `delete-template` `select-post-template` · `pages/templates` `pages/template` · `shared/ui/sortable-list`
- contract: `proto/postpilot/v1/template.proto`
