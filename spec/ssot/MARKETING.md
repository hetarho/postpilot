# MARKETING the public /about page
> r3 | The product's one public explanation surface: a localized, themed, read-only `/about` route reached from the login page, with Login as its only CTA, describing only shipped behaviour and collecting nothing. Migrated from legacy policy/public-marketing.md and plan/15 (built by job 34).

## decisions
- MARKETING-1 [o] `/about` is a direct child of the root route beside `/login` and deliberately not a child of the authenticated pathless layout ← being public is structural, not a check someone has to remember; it has no `beforeLoad`, loader, session branch or query, and mounting it issues no Connect call at all — not even GetMe — because the page exists for a visitor with no account (I5); it is refreshable and deep-linkable through the Cloudflare `single-page-application` fallback with no SSR, prerender, marketing deployment or metadata worker
- MARKETING-2 [o] `/about` carries one search param, `redirect`, which it never reads for itself and hands straight back to `/login` so a detour through the public page does not cost an expired session its destination; both ends filter it with `isInAppPath` so an off-site value cannot survive the round trip (→AUTH-27)
- MARKETING-3 [o] `/login` links to it as `Postpilot이란? / What is Postpilot?` below the credential action and outside the form; login submission, its one generic `INVALID_CREDENTIALS` failure, its pending state, its redirect validation and its signed-in guard are unchanged; a signed-in visitor who follows About's Login CTA is redirected by that guard, and About itself never special-cases session state
- MARKETING-4 [o] claim discipline: every sentence must be true of shipped behaviour as recorded in the SSOT at the time it is written; planning, in-progress or unverified behaviour is never presented as generally available — automated Naver publishing is stated as an operator-tier surface whose live verification is still in progress (PUBLISH), and softening that sentence is a policy violation, not a copy improvement; no guarantee the product does not own ("matches your voice perfectly", "never stores your data", "fully automatic publishing", any availability, security or performance superlative); no testimonial, usage metric, case study or fabricated social proof
- MARKETING-5 [o] the plans section mirrors the code-owned grant table in `backend/internal/plan` (→QUOTA-7): the monthly credit grant and the intended monthly price for `free` 50 / free · `basic` 220 / $2 · `pro` 575 / $5 · `max` 1200 / $10, model access stated as the same for every tier, and what a plan decides stated as that monthly grant alone — never as a number of jobs per day, a daily or monthly spend allowance, or a range of selectable models, none of which the product has (→QUOTA-2, →QUOTA-19); it is static localized copy, not a GetMyPlan read ← a visitor with no account has no plan to read; the values are duplicated in the page test so a drift fails a test rather than shipping, and changing the ladder means changing this copy in the same change; `master` appears only as prose describing the operator tier (unlimited, owns publishing and administration) and is never presented as an obtainable tier or a fourth row
- MARKETING-6 [o] no collection, no selling, no tracking: no signup, invitation, waitlist, contact or sales FORM on this page, no newsletter, comment field or CMS — it contains no `<form>` and no input of any kind, so the way in is always a link to a page that owns it; plans are presented, never sold — no price tag beyond the shipped figures and no purchase, upgrade or checkout affordance; the page carries exactly one filled CTA and it is the way in — 로그인 / Log in while accounts are operator-made, 시작하기 / Get started leading to signup once self-signup ships, with the other of the two beside it as a quiet link (→MARKETING-16, →THEME-18) — and the footer is product identity only; no analytics, tag manager, tracking pixel, cookie banner, advertising or marketing experiment; no screenshot, generated hero art, embedded media, remote font or any other third-party request — every asset is same-origin
- MARKETING-7 [o] all visible labels, accessible names and metadata strings live in the typed `marketing` namespace for `ko` and `en` at full parity (→LANG-7); the page composes keys and embeds no language; locale follows and persists by the browser-local rules and never changes the URL — no locale prefix, no automatic redirect; theme follows the same single browser-local preference the app uses and the public header composes the shared `widgets/interface-preferences` rather than forking either control (→THEME-6)
- MARKETING-8 [o] while `/about` is mounted it applies a localized `<title>` and `description`, `og:type=website`, localized `og:title`, `og:description` and `og:locale`, and canonical + `og:url` equal to the current origin plus the fixed `/about` path; no `og:image` is invented; the whole set is reapplied when the locale changes; leaving the route removes every tag the page created and hands the title and description back to the app default for the locale current then ← the transaction's undo restores the bytes captured at apply time, so without the second step switching to English on `/about` and navigating away put the Korean title back
- MARKETING-9 [o] exactly one module writes document head metadata: `shared/lib/document-metadata`'s transactional `applyDocumentMetadata`, which records each touched tag's prior state and returns an exact undo; the i18n provider's app-default application goes through it too, discarding the undo because a baseline has nothing above it to restore to; a second head writer is forbidden ← two of them cannot share the head safely
- MARKETING-10 [o] `index.html` keeps a product-level static title and description for clients that do not run JavaScript — neither route-specific nor localized, carrying no Open Graph promise ← it is the only metadata a crawler that refuses JavaScript will ever see, on every deep link, because this remains a CSR SPA; emptying it would have regressed every link preview, and the product does not claim localized social previews for such crawlers (→LANG-8)
- MARKETING-11 [o] the information architecture: a header (wordmark, the preferences pair, `로그인 / Log in`) · a hero with one H1 saying photos and rough notes become a publish-ready blog draft in the user's chosen voice, plus the access sentence MARKETING-16 governs · how it works as a real ordered list — choose a voice, template and target content language → add browser-converted photos and rough notes → Postpilot observes the photos first, then writes with explicit model choices and the selected voice → revise and finalize, then copy a platform format or explicitly hand an eligible Naver publication to a paired Mac · why it is different (mutually isolated voice profiles, observation separated from writing, structured canonical blocks, user-selected models and explicit A/B and revision actions) · where the result goes (Naver, Tistory, standalone-site HTML and Markdown derived from the same canonical post; Naver publication only as a separate explicit finalized-post action by a paired Mac) · the plans section (MARKETING-5) · control and privacy facts (images are converted in the browser before upload, account and voice evidence is isolated, opening pages triggers no background AI work, Naver credentials and browser state stay on the paired Mac) · a footer of concise product identity only
- MARKETING-12 [o] structure and accessibility: one H1, descriptive H2 sections, the product flow as an ordered list ← the order is semantic information, not four numerals; section separation uses spacing and semantic surface steps, never bordered card stacks; the existing `Logo`, button, link and icon primitives are reused and no About-only control is hand-rolled; the header is sticky and safe-area padded so the single Login CTA stays reachable without being repeated; controls keep the 44 px floor, focus is visible and no state is carried by colour alone; there is no horizontal page scroll at 320 px — the plans table is the one element wider than that and scrolls inside its own container while the page keeps exactly one vertical scroller; the footer's inset is a margin (`pb-8 mb-safe-b`) ← two padding utilities on one side collide (→THEME-31)
- MARKETING-13 [o] the device sweep at 360 / 390 / 430 px, 200 % zoom, keyboard and both themes was not performed on real devices when the page shipped; the structural invariants it would have protected are pinned as assertions instead — the plans table as the only wide element with its own scroller, one vertical scroller, 44 px header controls, safe-area padding, header tab order; no reusable design rule was extracted into THEME beyond the padding-plus-inset lesson already recorded there
- MARKETING-16 [o] every sentence about how a person gets an account states the path that exists at the time it is written — operator provisioning with no signup today, self-signup with email verification (→AUTH-1, →AUTH-34) once that ships — and the hero's access sentence, the header CTA and the plans assignment sentence (→MARKETING-15) all move in the change that ships it ← "there is no signup" beside a Get started button is a claim violation, not a stale string
- MARKETING-14 [x] signup or contact flows, price tags beyond the shipped figures, purchase, upgrade or checkout actions, testimonials, screenshots or generated hero art, analytics or tracking, SSR, SSG or prerendering, a blog, docs portal, changelog, legal or privacy-policy authoring, a sitemap or SEO tooling, backend, proto or database changes, a public marketing API, locale-prefixed URLs or redirects — out of scope
- MARKETING-15 [o] the sentence naming who assigns a plan states the path that actually does so — the operator today, a subscriber's own checkout once BILLING ships — and a sentence outliving its path is a MARKETING-4 violation, not stale copy; the public table may carry the same code-owned recommended rung and product-term post estimate `/plans` shows (→QUOTA-28, →QUOTA-36) and stays static copy either way, so a ladder change edits both copies together

## flow
- visit `/about` in any session state → static SPA fallback → the page renders from the `marketing` namespace with no request → Login CTA (with `redirect` handed through) → `/login`

## constraints
- placement FE: `pages/about` (ui and the route-scoped metadata lifecycle in model) · `app/providers/i18n/resources/{ko,en}/marketing.ts` · `app/routes` (public registration beside `/login`) · `pages/login` (the About link) · `shared/lib/document-metadata` · reused `features/change-locale`, `features/change-theme`, `widgets/interface-preferences`
- no environment value, tuning value, Connect contract, server package, migration or job; the canonical origin is derived from the current document origin
