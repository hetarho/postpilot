# IDEATION creation-and-comparison-ux
> st:open@261007 | A creation assistant with visible location, operational history, understandable reusable settings and actual-writing knockout tests.

## vision
- Prepare blog-ready writing and clips for manual external publication; the product is a creation assistant, not a hosted blog or a destination for browsing old articles.
- Preserve the focused two-choice home while making every subsequent location, parent and return action understandable.
- Reusable writing styles, templates, guidelines and model choices participate in one explicit actual-writing test flow.

## explored
- [o] New creation must not presume arrival from a post/clip directory; remove the editor's unconditional list-return action and retain the actual entry context through autosave address minting, reload and child settings.
- [o] Saved work is compact operational history for progress, failures, continuation and generated/exportable artifacts, rather than a large archive with a primary create button.
- [o] Desktop navigation is visible; nested settings have visible hierarchy, breadcrumbs/parent access and explicit return without requiring browser Back. Home keeps its two creation choices.
- [o] A saved reusable setting opens as the named saved item with its usable/editing/job state; AI editing and direct editing start from that same baseline and keep one working draft.
- [o] Copy identifies the setting kind, name and action. Unfinished editing, loading saved content, starting a fresh conversation and saving changes are different actions with different explanations.
- [o] Current-step controls and confirmations remain visible/reachable. A saved result is announced with its target name and creation/update outcome.
- [o] Personal learning materials can be edited. Changes are saved without AI work; the previously accepted analysis and source revisions remain in use until explicit successful reanalysis, with a clear pending-change notice.
- [o] Standalone short verification and arbitrary multiway ranking yield to one actual-writing test experience varying exactly one factor: model, writing style, post template or post guideline.
- [o] Formats are exactly two entrants (A/B), four, eight or sixteen; every match has exactly two contestants and one human-selected winner. No tie, bye, three-way match or Elo result determines the champion.
- [o] Each contestant's complete post is generated once and reused in every round. Sixteen contestants require sixteen post outputs and fifteen human decisions, not fresh generation per match.
- [o] New style/template/guideline candidates can be generated without an owned seed setting, including sixteen diverse synthetic styles; candidates remain private unsaved drafts until explicit winner adoption.
- [o] Candidate preparation and actual post generation have separate visible estimates/starts. Credit use arises from requested AI work; viewing, choosing a winner, navigation and ordinary publication do not call AI.
- [o] Existing private data, paid results, exports, provenance, owner isolation and admitted-job settlement survive the UX replacement.
- [?] Exact desktop navigation placement, history presentation/name and final visual spacing require interface review; initial implementation guidance is reversible and does not establish an approved visual design.

## shape
- Create → enter material in a roomy workspace → generate/refine → finish/export; current location and a contextual return remain visible throughout.
- Settings → named writing/video category → named saved item and state → AI editing | direct editing → shared private changes → explicit named Save → confirmed saved item.
- Personal learning → saved material → explicit Edit → Save → pending-analysis notice with prior-profile explanation → estimated explicit Reanalyze → confirmed new profile.
- Writing tests → choose one factor and2/4/8/16 format → common material and fixed settings → choose owned candidates | explicitly generate diverse drafts → check compatibility and estimate → generate one post per entrant → compare two complete posts at a time → choose winners → champion → explicitly save/apply/use.
- A model test may vary the writer or observer; observer tests use real attachments and a fixed writer to produce complete posts. Other factors share the same observations and unchanged writing options.
- Test history records context, factor, format, progress and winner; old paid comparison/verification records remain accessible as history without being converted into invented brackets.

## domains
- THEME: visible navigation, nested location/return, separate workspace/prose measures, current-step action/result clarity and desktop acceptance.
- POST CLIP: creation-origin continuity and compact operational history, with retained direct addresses, autosave, lifecycle and exports.
- EDIT TMPL GUIDE: named saved/working states, shared AI/direct draft, directory summaries, bounded candidate preparation and explicit champion publication.
- VOICE: editable learning materials, revision-aware accepted analysis/projection, dirty notices, generated-style provenance and shared-test entry.
- MODEL GEN QUOTA ARCH: single-factor complete-post experiments, binary brackets, human decisions, once-per-candidate work, receipts, admission/settlement and forward compatibility.

## open
- Final navigation layout, history naming/placement and visual dimensions remain design-review items; no mockup or final visual design is approved by this document.
- Video-render tournaments, automated judges, multi-factor optimization and statistically significant quality claims are outside this writing-test scope.
- Personal prose is never invented by synthetic winner adoption; generated winners remain explicitly AI-generated styles until actual personal learning creates a personal profile.
- Unrelated searchable-details ideation and existing browser-media tasks retain their own scope and progress.
