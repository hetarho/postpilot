## Acceptance Criteria (from plan/10.independent-voice-profiles-and-post-assi)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 Migrating an existing database creates exactly one active `기본 말투` per account, marks it default, assigns every existing post and all existing voice/profile/evidence rows to it, and preserves legacy text, snapshots, revisions, job/history status, timestamps, and prompt output byte-for-byte apart from the new ids/projections.
- [x] A2 Creating a new account establishes one active default voice before post creation. An account can create two more voices with empty independent profiles; no sample, rule, descriptor, example, or version appears in either merely because another voice has data.
- [x] A3 Active voice names are trimmed, non-empty, bounded by the owned character limit, and unique within the account. Rename affects list/post display without rewriting post content or immutable profile history.
- [x] A4 Setting an active owned voice as default atomically replaces the previous default. New-post UI initializes its required dropdown to that exact voice, and the create request always carries the id; missing, foreign, unknown, or deleted ids are rejected without silently choosing a fallback.
- [x] A5 Deleting a non-default inactive voice sets a tombstone and preserves all posts/profile history. It disappears from selectable options and existing posts show `삭제된 말투 · {name}` after reload. The default/last active voice and a voice with publishable active work cannot be deleted.
- [x] A6 Restoring a deleted voice preserves its profile/history and re-enables selection and AI work without starting a job. A conflicting active name blocks restore until the tombstone is renamed; restore does not change the default.
- [x] A7 A deleted-voice post remains readable, manually editable, copyable, and exportable. Generation, revision, save-as-rule, feedback, and finalization learning are rejected before enqueue/provider calls, with a visible action to restore or reassign the voice.
- [x] A8 Reassigning an idle post to another active owned voice preserves its slug, inputs, photos, canonical content, content revision, finalization state, and export. It clears the old machine baseline/eligibility and does not move prior evidence; active post work or an undecided write result blocks reassignment.
- [x] A9 After reassignment, a machine generation/revision freezes only the new voice profile and establishes a baseline carrying that voice id. Finalization learning rejects an old/mismatched baseline and succeeds only against a matching baseline, publishing its source/evidence exclusively to the new voice.
- [x] A10 Two voices can hold contradictory endings, manual rules, samples, and active contrast rules. Generation and five repeated AI revisions of posts assigned to each voice consistently receive only their selected voice projection; no profile fallback or cross-voice excerpt appears in prompt snapshots.
- [x] A11 Pasting a historical text sample analyzes only the selected active voice's full corpus. There is no in-app cross-voice post/sample picker or copy RPC, and deleting/reanalyzing a sample changes no other voice's corpus version or profile head.
- [x] A12 Finalize/learn events, retries, feedback, rules, confirmations, rule comparisons, validation eligibility/results, and profile restore are all voice-scoped and account-scoped. Reassigning a source post does not retarget a frozen event or completed source.
- [x] A13 Analyze-model experiments require an explicit active voice, compare one frozen corpus, and apply a winner only to that same voice. Experiment completion cannot overwrite another or a deleted voice; model Elo/selections retain their existing account-stage semantics.
- [x] A14 Voice-owned active-job guards are per voice, durable rows expose/freeze `voice_id`, and page load, directory CRUD, reassignment, delete/restore, polling, copy, and export initiate no provider call. Restart and explicit retry retain the existing personalization safety behavior.
- [x] A15 Every RPC remains authenticated with no request user id. Crafted foreign account/voice/post/sample/rule/event ids cannot read or mutate another account, and a same-account id from voice A cannot mutate voice B's aggregate.
- [x] A16 Voice directory/detail, legacy redirect, post list, new-post dropdown, editor reassignment, deleted-state warnings, mobile layout, keyboard interaction, focus restoration, pending/error states, and account-switch cache isolation are covered by frontend interaction tests using the design-system primitives and semantic tokens.
- [x] A17 Migration/store/domain/RPC/prompt/job tests cover default uniqueness, lifecycle races, table partition keys, reassign-versus-job races, baseline voice mismatch, deletion guards, soft-delete retention, restoration, and byte-preserving backfill. Proto/sql generation checks, backend vet/build/tests, frontend tests/lint/FSD/style/build, and spec lint all pass without weakening current assertions.
