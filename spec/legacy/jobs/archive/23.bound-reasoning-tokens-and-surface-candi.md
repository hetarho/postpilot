## Implementation Checklist

<!-- How to build it, top to bottom. [P] = parallel (different files, no dependency). Flag (gen)/(migrate).
     Config values are never magic literals — FE via shared/config, BE via internal/platform/config. -->

- [x] T001 [P] `internal/llm/provider.go` — add a `ReasoningEffort` string type with the OpenRouter-valid values
      plus an explicit `unset` sentinel meaning *send no reasoning key*; add `Request.Reasoning ReasoningEffort`
      (empty = unresolved) and `Response.FinishReason string`. Document on `Provider.Complete` that a returned
      `Response` may carry `Usage` even when the error is non-nil — a failed call that cost money must say so.
- [x] T002 [P] `internal/llm/errors.go` — add `ErrOutputTruncated` ("the model spent its completion budget without
      producing an answer") to the normalized set, and add `UserMessage(err) string`: the single place that unwraps
      `*ProviderError` to its provider message and maps the sentinels to what a user should read. This is the rule
      `job.failureMessage` already implements privately; T009/T010 make both callers use this one.
- [x] T003 `internal/llm/registry.go` — add `reasoning_effort` to `modelEntry` (strict yaml already rejects
      unknown keys; an unrecognized *value* must fail `Parse` with a clear message, same loud-config posture as a
      bad adapter). Carry it on the resolved entry and have `Complete` resolve effort as **model override →
      `req.Reasoning` → nothing sent**, alongside the existing `MaxTokens` default fill.
- [x] T004 `internal/llm/openaicompat/client.go` — `buildRequest` emits `reasoning: {"effort": …}` **only** when an
      effort is resolved and is not the `unset` sentinel, so today's body is byte-identical otherwise (A1). Carry
      the stream's `finish_reason` onto `Response`. On the empty-completion path, return `ErrOutputTruncated` when
      the finish reason is `length` and `ErrBadOutput` otherwise. Return the usage collected so far with **every**
      error return in `Complete`/`readStream`/`readJSON` instead of a bare `llm.Response{}`. Never send
      `reasoning.exclude` — it hides reasoning but still generates and bills it. Above the adapter, a non-empty
      partial JSON response whose finish reason is `length` must retain the same truncation classification when
      parsing proves there is no usable content.
- [x] T005 [P] `internal/platform/config/config.go` — `llmMaxTokensDefault` 4096 → **8192** (keep the comment
      accurate: reasoning tokens share this budget). Add the code-owned stage reasoning policy beside
      `VoicePersonalizationConfig` (write → low, observe → low, analyze → nothing), exposed on `Config`.
- [x] T006 `cmd/api/main.go` — pass the stage reasoning policy into `generation.NewService`, the same way
      `cfg.ObserveBatchSize` is passed today. `llm.Options` is unchanged.
- [x] T007 `internal/generation` — `NewService` takes the policy; `writeCandidate` and `observeCandidate` set
      `request.Reasoning` from it. On a failed `Complete`, return the response's usage instead of `llm.Usage{}` so
      `RunWriteCandidate`/`RunObserveCandidate` hand real numbers to the experiment context.
- [x] T008 [P] `config/providers.yaml` — document `reasoning_effort` in the header comment block, and set the
      `unset` sentinel on `anthropic/claude-sonnet-5` so today's active write model keeps its adaptive thinking (A4).
      No other model entry changes.
- [x] T009 [P] `internal/job/worker.go` — `failureMessage` delegates to `llm.UserMessage`; behavior for existing
      cases is unchanged (this is a dedupe, not a new rule).
- [x] T010 `internal/experiment/handler.go` — `userFacingError` keeps its `ErrSnapshotUnavailable` and
      `context.DeadlineExceeded` cases and otherwise delegates to `llm.UserMessage`, so the provider's own message
      and the truncation message reach the candidate row instead of one generic sentence. In `runCandidate`, log
      exactly one `slog.Error` on failure with experiment id, candidate id, model ref, and the error, and keep
      persisting `result.Usage` (now populated) on the failed candidate.
- [x] T011 Tests — adapter: no `reasoning` key when unresolved (A1), the key present with the resolved effort,
      `length` + empty content → `ErrOutputTruncated` (A5), usage returned alongside an error (A6). Registry: an
      unrecognized `reasoning_effort` fails `Parse`; model override beats the request value (A4). Config: the
      constant is 8192 and no other completion-budget literal exists (A3). Experiment: a failed candidate logs once
      and stores the provider message + usage (A6, A7). Generation: non-empty partial write and observe JSON ending
      in `length` also maps to `ErrOutputTruncated`. `cmd/api/providers_test.go` still loads the shipped yaml.
- [x] T012 Manual provider verification for **A2** — this criterion needs a real OpenRouter call and cannot be a
      unit test. Replay a production-shaped write snapshot on `z-ai/glm-5.3` through the built binary (or a small
      throwaway harness) and record `finish_reason`, reasoning tokens, completion tokens, and content length in the
      job report. Baseline to beat, measured 2026-08-30: 3,609 reasoning tokens, `length`, 0 chars.

      Verified 2026-08-30 with the production `BuildWritePrompt`/schema, eight JPEG observations, a long voice
      profile, `reasoning.effort=low`, and `max_tokens=8192`: `finish_reason=stop`, 7,196 prompt tokens, 2,487
      completion tokens, 0 reasoning tokens, and 3,964 content characters. The generated document passed
      `generation.ParseContent`; the throwaway harness was removed afterward.

## Review

- [x] `/code-review` applied (rejections noted with reason) · for non-trivial logic, `/codex:review --background`

  The first read-only review found two P2 regressions. Both were accepted and fixed: non-provider/parser failures
  retain the experiment's generic public message, and the OpenRouter reasoning wire extension now requires the
  provider-level `reasoning_format: openrouter` opt-in so other OpenAI-compatible endpoints keep their old body.
  The second review found raw parser output could reach ERROR logs; parser failures now unwrap to the normalized
  class and the logger redacts their detail while preserving provider causes. The final scoped review confirmed
  those fixes and found one remaining P2: non-empty partial JSON ending in `length` was still classified as a parser
  failure. Write, observe, and revision now preserve `ErrOutputTruncated` in that case, with regression coverage for
  write and observe. A final focused review of that fix returned no findings.
