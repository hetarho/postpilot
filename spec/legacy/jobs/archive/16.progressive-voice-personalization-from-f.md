## Acceptance Criteria (from changes/02.progressive-voice-personalization-from-f)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 An account with zero samples and zero finalized posts can generate a first post. The API/UI represents its profile as empty/unknown, makes no style claim, and neither requests nor recommends a historical-post minimum.
- [x] A2 A user can edit the generated `PostContent` in the app, including its text-bearing blocks, while the canonical value remains a validated block array and no unattached image filename can be introduced.
- [x] A3 Manual content edits autosave while the latest machine-produced baseline remains immutable. Explicit **Finalize and learn** stores a final snapshot and returns a durable learning job; opening/copying an export or loading the page does not start that job.
- [x] A4 Retrying the same finalization or its job is idempotent: it creates no duplicate finalization, sample, feedback event, profile version, or rule evidence. A later machine baseline can be finalized as a distinct event.
- [x] A5 The first finalized post becomes the first authored source and eligible few-shot excerpt. The next generation uses that one excerpt; generation with zero, one, two, or three available excerpts succeeds without duplication.
- [x] A6 A non-empty canonical profile exposes the five required layers, six bounded axes, meta/version data, contrast-rule lifecycle metadata, few-shot entries, and feedback references. Endings are analyzed and rendered as a distinct primary layer rather than folded into vocabulary.
- [x] A7 A one-source explicit learning run produces the typed profile without topic-specific preferred words; measured ending distribution and sentence-length values override conflicting model estimates, while unsupported traits remain unknown and existing manual overrides remain effective.
- [x] A8 Editing a profile descriptor, resolving a contradiction, changing a rule state, applying new evidence, or restoring a snapshot creates a new immutable whole-profile version. Reload and rollback preserve every older snapshot and identify the current head.
- [x] A9 Existing styleguide and rule content survives migration byte-for-byte as manual guidance, remains account-scoped, and continues to reach generation/revision until that account explicitly changes it.
- [x] A10 A crafted finalization diff containing factual changes and repeated ending changes ignores all factual changes and emits at most three rules only for style patterns with at least two cited edits. A diff without such a pattern returns no rules.
- [x] A11 A rule extracted from one qualifying finalization is `candidate/1`; two later independent matching evidence events produce `candidate/2` then `active/3`. Only the active rule appears in generation, ordered consistently with other active rules by evidence count.
- [x] A12 Evidence that semantically contradicts an active rule leaves the active rule and current profile unchanged and creates a visible confirmation item. Only the owning user's explicit resolution creates the replacement profile version.
- [x] A13 A rule whose last evidence is older than 180 days is excluded and retained as `retired` when the next explicit eligible request evaluates the profile. Advancing time alone runs no process and makes no provider call.
- [x] A14 Sentence feedback requires one of vocabulary, ending, length, or structure and is logged against that layer. A no-edit satisfaction response is auxiliary and cannot independently create or activate a rule.
- [x] A15 A generation prompt contains structured descriptors, bans, active evidence-ranked contrast rules, and up to three similar authored excerpts before per-post material; it contains no candidate/retired rule, carries the user's selected target length, and enforces the ending-distribution and no-three-identical-endings constraints.
- [x] A16 Candidate-rule comparison starts only after a user action and explicit model confirmation. Its candidates share one frozen input and differ in exactly the selected rule; the blind verdict affects that rule only and creates no model-leaderboard match.
- [x] A17 Profile validation is unavailable with fewer than three finalized posts. An explicit run uses three neutral summaries that reuse no author wording, presents original/regenerated pairs, and—only when explicitly enabled— stores the five-dimension judge Y ratio against the evaluated profile version.
- [x] A18 No timer, scheduler, page load, copy action, profile age, or application boot starts rule comparison, profile validation, profile extraction, embedding, or judge work. Provider calls occur only within a user-initiated operation whose model is explicit, and long operations remain restart-safe server-side jobs.
- [x] A19 Two accounts cannot read or influence each other's profiles, versions, samples, baselines, finalized snapshots, diffs, feedback, confirmation items, few-shot examples, comparisons, or validation scores.
- [x] A20 Existing observe-before-write generation, AI revision, model-stage experiments, block validation, browser image preprocessing, platform converters, and clipboard fallback retain their current behavior; postpilot still never publishes.
- [x] A21 MVP, v2, and v3 can be verified independently at their declared gates, and a failed later-stage job leaves the last valid canonical post and effective profile version unchanged.
