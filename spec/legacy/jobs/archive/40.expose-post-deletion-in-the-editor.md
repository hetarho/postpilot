## Acceptance Criteria (from changes/13.expose-post-deletion-in-the-editor)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 On `/posts/$slug`, a signed-in owner sees a danger-toned delete control in a visually separated destructive region of the editor. `/posts/new` shows no such control.
- [x] A2 Activating the control opens a confirmation dialog that names the post and states that the post, its photos, and its generation and revision history are permanently removed and cannot be restored. Dismissing the dialog deletes nothing and leaves the editor untouched.
- [x] A3 Confirming deletes the post: `GetPost` for that slug then returns `NotFound`, the slug is absent from `ListPosts`, its `images`/`uploads` rows and their R2 objects are gone, and its experiment content is purged while the `model_experiments` row survives with a null `post_slug`.
- [x] A4 After a successful delete the app is on `/posts`, the deleted post is absent from the rendered list without a manual refresh, and the post's own query no longer serves the stale post.
- [x] A5 A successful delete discards that slug's draft queue and content queue. No autosave request is sent for the deleted slug afterwards, and no save-failure notice appears.
- [x] A6 `DeletePost` on a post with a non-terminal publish job (`queued`, `running`, or `needs_attention`) fails with `FailedPrecondition` and reason `POST_PUBLISHING`, deletes nothing — no R2 object, no experiment content, no row — and the editor shows a message telling the user to cancel or finish the publication first.
- [x] A7 `DeletePost` on a post whose only publish jobs are terminal (`published`, `failed`, `outcome_unknown`, `canceled`) succeeds, and every `publish_jobs` and `publish_assets` row for that post survives unchanged. `LatestJobForDeletedPost` still returns that history for the deleted slug.
- [x] A8 `DeletePost` while a generation job is active still fails with `FailedPrecondition` and reason `POST_BUSY`, and the editor distinguishes that message from the `POST_PUBLISHING` one.
- [x] A9 Deleting another user's slug is `PermissionDenied` (`POST_FORBIDDEN`) and an unknown slug is `NotFound` (`POST_NOT_FOUND`), matching the existing ownership rules; neither destroys anything.
- [x] A10 `internal/post` contains no import of `internal/publishing`, the post store issues no query against `publish_jobs`, and the new port is declared in `post/ports.go` and satisfied by an adapter in `cmd/api/main.go`.
- [x] A11 `spec/policy/posts.md` no longer claims that post deletion does not exist and instead documents the shipped rule, including both refusal conditions and what survives a deletion. Plan 02's contract section lists `DeletePost`.
- [x] A12 The post list screen renders identically to before the change, and `pnpm build`, `pnpm lint`, `pnpm test`, and `go vet ./...` pass with no regression in the existing post, publishing, and autosave suites.

## Review

- [x] `/code-review` applied (rejections noted with reason) · for non-trivial logic, `/codex:review --background`

**Applied**

- Split the delete's failure handling from the navigation's in `DeletePostButton.confirm`, so a navigation that
  fails after a successful delete is no longer reported as a refusal (the post really is gone by then).
- Moved the `fakeBlobs` doc comment back onto `fakeBlobs`; the new `fakeLivePublish` had been inserted between them.
- `useDeletePost.test.tsx` now seeds a real stage-filtered `ListExperiments` key, so removing the experiment-list
  invalidation from the hook fails the test. It previously did not.
- Documented the check-then-delete window (below) in `post/service.go` and in `policy/publishing.md`, and the
  in-flight-request caveat of the per-slug discard in `tech/draft-autosave.md`.

**Rejected**

- *"A non-app Connect failure renders an empty alert."* Wrong: `appFailureFromConnect` falls back to
  `unknownFailure` (`UNKNOWN_FAILURE`) rather than returning undefined, so `errorMessage` is always a localized
  string.
- *"TOCTOU: a publication started between the live check and the row delete is not prevented."* Real, and both
  reviewers found it, but not fixable inside this job. The end state is one the publishing schema was built for —
  the manifest is frozen, the staged assets sit under `publish_assets.staged_key` rather than the post's `posts/`
  prefix, and `LatestJobForDeletedPost` exists to serve a publication whose post is gone — so the publication still
  completes correctly. Closing the window needs a transactional gate spanning both contexts, which would change the
  design this change specified (a plain query port) and would have to reach the post store, which A10 forbids from
  touching `publish_jobs`. Recorded in the code and in `policy/publishing.md` instead.
- *"The per-slug discard does not abort a save already in flight."* Real but bounded, and out of scope: the queue is
  marked `discarded`, so a landed response changes no local state, and the residual risk needs the request to
  outlive the delete **and** the user to mint the same freed slug within that request's lifetime. Aborting would
  mean threading an `AbortSignal` through the Connect transport and into both queues — a change to the autosave
  contract that belongs in its own change doc. Recorded in `tech/draft-autosave.md`.
- *`features/configure-model-pair/ui/CandidatePairSelect.tsx` silently dropping a cleared candidate.* Outside this
  job's blast radius — it belongs to separate uncommitted work in the tree, not to job 40. Reported to the user.

**Deviation from the checklist**

- T014/T015 specified that `DeletePostButton` call `discardDraftQueue`/`discardContentQueue` itself. FSD forbids a
  feature slice importing a sibling feature slice (`pnpm lint:fsd` fails on it), so the page passes them in through
  an `onDeleted` callback instead. The behavior and its ordering — discard before navigating — are unchanged.
