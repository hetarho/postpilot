## Acceptance Criteria (from changes/21.reuse-finished-observations-and-pick-whi)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 Starting generation on a post that has photos and a stored observation snapshot opens the picker; the desktop presentation is a dialog and the narrow-viewport presentation is a bottom sheet. A post with no photos, or with no stored snapshot, starts generation directly as it does today.
- [x] A2 Every checkbox is clear when the picker opens. Confirming without changing anything enqueues a run that makes **zero** observation calls, reports the observation stage complete immediately, proceeds to the writing stage, and leaves the stored snapshot byte-identical.
- [x] A3 Checking a subset enqueues a run that observes exactly those photos: with `OBSERVE_BATCH_SIZE = 4` and five photos selected out of fifteen, the handler makes two observation calls and the persisted snapshot afterwards still holds one entry per attached photo — the ten unselected entries unchanged, the five selected ones replaced.
- [x] A4 The snapshot never shrinks during a run: after the first batch of a partial re-observation, the persisted snapshot already contains an entry for every attached photo (carried-over plus newly observed).
- [x] A5 A photo attached after the last observation, or one whose stored entry is empty, renders checked and cannot be cleared; a picker in which those are the only photos with nothing to reuse still allows confirming.
- [x] A6 When the selected observation model differs from the model that produced the stored snapshot, the picker shows a notice naming both models, and the checkboxes still default to clear.
- [x] A7 The selection is frozen at enqueue: attaching a photo, deleting a photo, or switching the observation model after `StartGeneration` returns and before the job is dequeued does not change which photos that run observes.
- [x] A8 The A/B write comparison goes through the same picker and honors the same reuse, including the zero-observation case.
- [x] A9 Observation progress reports the count of photos actually being observed as its total, not the number attached.
- [x] A10 Regression: a first generation on a post with photos and no stored snapshot observes every photo in `ceil(N / OBSERVE_BATCH_SIZE)` calls, and the zero-photo path still makes no observation call and clears the snapshot — both exactly as plan 06 specifies today.

**Contract shape (decided here so the tasks below are unambiguous)**

The picker sends only a **set of filenames** to re-observe. The observations being carried over are
resolved and frozen **server-side at enqueue** from the post's own snapshot — the client never sends
observation text, and freezing both halves in one place is what makes A7 true.

- [x] T001 (gen) `proto/postpilot/v1/post.proto` · `model_experiment.proto`: the re-observation
  set on both start requests, and `string model` on `message Observation` — the ref that produced
  that entry. Per-entry, not per-snapshot, because this change is precisely what makes a
  mixed-model snapshot possible. Run `pnpm gen:proto`.
  **Built as a `ReobserveSelection` message (field `reobserve`), not as
  `repeated string reobserve_files` as this checklist first said.** A proto3 repeated field has NO
  presence: absent and empty arrive identically, so `reobserve_files` could not express A2 (reuse
  everything) and A10 (a client predating the picker observes everything) at the same time — the
  exact three-state distinction T004 insists on for the payload. A singular message field has
  explicit presence, so the wire carries the same three states the payload does.
- [x] T002 Observation provenance through the stack, additively (**no migration**): `model` on
  `post.Observation`, `generation.Observation`, and the store's `observationJSON`
  (`backend/internal/post/store/content.go`) — a row written before this change decodes with an
  empty model, which is "unknown", not an error. Map it in the post RPC mappers
  (`internal/post/rpc/handler.go`) and in `main.go`'s `generationPosts.SetObservations` adapter, and
  stamp it in `matchObservations` (`observe.go`) from the ref that ran the batch, including the
  empty-entry case a missing filename produces. `SetObservations`' `reflect.DeepEqual` no-op check
  keeps working unchanged.
- [x] T003 `generation.PostInput` gains `Observations []Observation`, filled by `main.go`'s
  `generationPosts.AttachedImages` adapter from `found.Observations`. This is the field whose absence
  made the persisted contact sheet write-only from this context's point of view; it is read at
  enqueue only — the handler reads the payload, never a live snapshot.
- [x] T004 `generation_payload.go`: freeze the selection. Add `ObserveFiles *[]string` and
  `Observations []Observation` to `GenerationOptions` and to `generationPayload`.
  **`ObserveFiles` must carry presence, not just emptiness**: `nil` means a job queued before this
  contract existed and keeps today's observe-everything behavior, while non-nil-but-empty means the
  frozen decision to observe nothing. A plain `[]string` with `omitempty` would encode "reuse
  everything" and decode as "re-observe everything" — the exact silent double-spend this change
  exists to stop. Extend the payload round-trip tests for all three states.
- [x] T005 `service.go` `Start`: resolve and freeze the selection.
  - Intersect the request's filenames with the attached photos (post order, duplicates collapsed,
    unknown names dropped — the same discipline `matchObservations` applies to model output).
  - **Force, server-side, every attached photo with nothing to reuse** — no stored entry, or a
    stored entry whose every field is blank. The UI states this rule (A5) but may not be the thing
    that enforces it: the run must not write from a photo it has never looked at.
  - Carry over the stored observations for every attached photo NOT in that set, and freeze both
    into the payload via `EncodeGenerationPayload`.
  - Zero photos is unchanged: `ObserveModel` cleared, `ObserveFiles` left `nil`.
  - The observation-model precondition is unchanged — an enabled, vision-capable observe model is
    still required for a post with photos even when the frozen set is empty (deliberate non-goal).
- [x] T006 `service.go` `observeCalls`: price the hold over the **frozen set**, not
  `len(post.Images)` (`request.ObserveCalls = s.observeCalls(len(selected))`). The hold and the work
  have to agree on how many calls there will be; a reuse-everything run now costs zero observation
  calls and must not be held for fifteen.
- [x] T007 `observe.go`: partial observation. Give `observeCandidate` the photos to observe and a
  seed snapshot (`targets []Image`, `seed []Observation`) instead of implicitly walking
  `post.Images` from index zero, and add `mergeObservations(attached []Image, seed, fresh []Observation)`
  returning exactly one entry per attached photo in post order — carried-over entries untouched,
  freshly observed ones replacing theirs. Every `persist` writes that merged result, so the
  persisted snapshot is complete after the FIRST batch and the contact sheet only grows (A4).
  Batching, the prompt, the schema, filename matching, the validation function and the attachment
  filter are all untouched; `observe(...)` with every photo and no seed must reproduce today's calls
  and today's snapshot byte for byte (A10).
- [x] T008 `generate_handler.go`: `GenerateJob` gains `ObserveFiles *[]string` and
  `Observations []Observation`, decoded in `main.go`'s `job.KindGenerate` registration from the
  payload. In the photo branch:
  - `ObserveFiles == nil` → today's path unchanged (observe every attached photo).
  - otherwise select the named attached photos in post order; if the selection is **empty**, make no
    provider call and no `SetObservations` call at all — `progress("observe", 0, 0)` and straight on
    to the write stage, which is what leaves the snapshot byte-identical (A2).
  - otherwise observe only the selection, seeded with the payload's carried-over observations, with
    `total` = the selected count (A9).
  The zero-photo branch (`ObserveModel == ""` → `post.Images = nil`, clear the snapshot) is
  unchanged, and so is terminal failure handling — a failed job stays failed, no resume, no requeue
  (deliberate non-goal).
- [x] T009 A/B write-comparison parity: `experiment.StartRequest` gains the same frozen set (its own
  `ObserveFiles *[]string`), threaded from `StartWriteExperimentRequest` through the experiment RPC
  handler and `experimentRunner.Snapshot` into `SnapshotWriteInput`, which resolves the forced
  photos and the carried-over observations exactly as T005 does and freezes both into
  `experimentSnapshot` — whose `Observations` field already exists and now arrives pre-seeded.
  `PrepareWriteInput` then observes only the frozen set and merges into that seed (T007's helper),
  including the make-no-call case. The observe-stage A/B (`SnapshotObserveInput` ·
  `RunObserveCandidate`) is deliberately untouched: it compares observation models, so reusing an
  observation is meaningless there, and it already runs with `persist=false`.
  `WriteExperimentPromptVersion` is NOT bumped — the prompt does not change, and observations were
  already part of the snapshot's identity.
- [x] T010 **NOT DONE — the premise was wrong, and the move was reverted.** This task assumed
  the picker needs a media query to choose between a dialog and a sheet. It does not: `Sheet` (and
  therefore `Dialog`) ALREADY is a bottom sheet on a phone and a centred dialog from `md:` up, in
  CSS, on one mount — `items-end … md:items-center`, `rounded-t-xl md:rounded-xl`,
  `animate-sheet-in md:animate-dialog-in`. The two shapes never coexist, so nothing has to pick

  `shared/ui/popover/`; its comment now records that a dialog-or-sheet surface is explicitly not
  the second primitive it was reserved for.

  - `defaultSelection(rows)` → the forced filenames only: **every other checkbox starts clear**.

## Review

- [x] `/code-review` (high) · `codex exec -m gpt-5.5` (background, read-only) — merged and deduped.
      **Six defects found and fixed:**
  1. **The credit hold overheld a reuse-everything run** (both reviewers). `CallCounts` was only
     stated when `ObserveCalls > 1`, and `NewJob.plannedCalls()` prices an unstated ref as one
     call — so a run making ZERO observation calls was still held for one, and could refuse an
     account that could afford the write-only retry this change exists to make cheap.
     `internal/job/job.go` now honors an exact stated count including zero (and its dedup keys on
     "a count was given" rather than on `stated <= 1`, which is behavior-identical for every
     previously reachable input); `EnqueueGeneration` states the count always, adding the write
     call when one model serves both stages, because the count is per model across the whole job.
  2. **The write stage could be shown a photo the run never observed** (both reviewers).
     `post.Images` is read live at dequeue, so a photo confirmed between the enqueue and the
     dequeue reached the write prompt as a bare filename with no observation beside it — the exact
     "write from a photo nothing has looked at" case. `generate_handler.go` now narrows
     `post.Images` to the photos the run holds an observation for, via `observedImages`.
  3. **A deleted photo left a reusable observation behind** (codex). Entries pair to photos by
     filename alone, and a filename is free to be taken again once its photo is gone, so a
     different photo uploaded under a freed name inherited stale eyesight — harmless while
     everything was re-observed unconditionally, silently wrong now that it can be reused.
     `post.DeleteImage` drops that photo's entry and keeps the rest.
  4. **Applying an observation A/B winner blanked provenance** (`/code-review`).
     `outputObservation` did not carry `Model`, so the winner rewrote the whole snapshot with
     unknown provenance and the next picker reported every photo as observed by an unrecorded
     model. The field is carried through both mappers.
  5. **The changed-model notice fired on every pre-existing post** (`/code-review`). An entry
     written before provenance existed reads as `''`, which was treated as "a different model".
     Only a KNOWN stored ref can differ now.
  6. **`enqueue` kept non-null assertions the picker path no longer guarded** (`/code-review`). A
     selection invalidated while the picker was open would have thrown into an empty `catch`,
     leaving a saved draft, no job and no message. The preconditions are re-checked immediately
     before the RPC.
- [x] **Out of scope, recorded rather than fixed:** the write A/B's admission prices the observe
      model exactly once regardless of how many batches it will run (`experiment/service.go` ·
      `main.go`'s `ExtraModels`, which carries no call counts). This is PRE-EXISTING and this
      change does not make it worse in magnitude: fifteen photos have always been four calls held
      as one (under-held by three), and a reuse-everything run is now zero calls held as one
      (over-held by one). Pricing the A/B's observation batches properly means threading a call
      count through the experiment enqueue seam, which belongs with plan 09/17, not here.
- [x] Design pass (design-language §10) — no hand-rolled control (`Dialog`, `Checkbox`, `Button`,
      `Notice`, `Typography` all from `shared/ui`); rows use the `divide-divider` hairline
      exception rather than a card per photo (§1.3 · §1.4); one `cta` per surface — `Dialog`'s
      confirm — with the bulk controls `secondary` and cancel `ghost`; a forced control states its
      reason (§7); registered tokens only, `pnpm lint:style` green; the phone shape is the
      unprefixed one.
