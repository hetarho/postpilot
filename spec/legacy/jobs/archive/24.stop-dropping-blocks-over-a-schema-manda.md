## Implementation Checklist

<!-- How to build it, top to bottom. [P] = parallel (different files, no dependency). Flag (gen)/(migrate).
     Config values are never magic literals — FE via shared/config, BE via internal/platform/config. -->

- [x] T001 `internal/generation/blocks.go` — stop treating a populated `level` as a drop reason for `TEXT`,
      `IMAGE`, `QUOTE`, and `LIST`. `firstPopulated` currently takes a `level bool` as its first check for exactly
      these four types; remove `level` from what it judges and normalize `block.Level = 0` on the kept block
      instead. `HEADING` keeps its own path untouched, clamp included. Every other field in `firstPopulated`
      (`file`, `alt`, `caption`, `items`) and every `content`/`items`/`file` requirement stays a drop.
- [x] T002 `internal/generation/blocks.go` — a block kept only because its `level` was normalized emits **no**
      warning; a genuinely dropped block still emits exactly one `dropping invalid generated block` line naming the
      type and the offending field. The log is the signal that surfaced this bug — keep it sharp.
- [x] T003 Comment the *why* at the normalization site: the app's own `post_content.schema.json` lists `level` in
      `required` for every block, so a schema-obedient model must send it; the value carries no meaning outside
      `HEADING` and must not cost the block. Without this note the next reader will "fix" it back.
- [x] T004 Tests in `internal/generation` — (a) a payload where every `TEXT`/`IMAGE`/`QUOTE`/`LIST` block carries a
      non-zero `level` keeps all blocks, each normalized to `level == 0` (A1, A5); (b) `HEADING` 2/3 pass, 1/4/0
      clamp to 2, empty content drops (A2); (c) `TEXT` with `items`, `IMAGE` with `content`, `IMAGE` without
      `file`, `LIST` with an empty item, and an unknown type all still drop and still log (A3 — plan 06 acceptance
      criterion 5 must keep passing); (d) a kept-by-normalization block produces no log line (A4).
- [x] T005 Confirm no caller depends on the old behavior: grep `ValidateBlocks` across `internal/generation`
      (write, revise, experiment surface) and check the existing generation/revision tests still assert the same
      persisted content for payloads that were already valid (A6).
