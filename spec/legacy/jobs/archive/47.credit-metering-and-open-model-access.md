## Acceptance Criteria (from changes/archive/19.credit-metering-and-open-model-access)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 An account's balance is the sum of `remaining` over its unexpired lots, and consumption draws from lots ordered by `expires_at` ascending with NULLs last; a monthly lot is therefore exhausted before a non-expiring bonus.
- [x] A2 A request arriving after the renewal instant closes the stale monthly lot and opens the tier's new one in the same write transaction, with no scheduled job involved, and the caller sees the renewed balance on that request.
- [x] A3 Starting an LLM-consuming job deducts a hold computed as `BASE + ceil(worst_case_cost × 100 × MULTIPLIER)`, where the worst case prices every call the work will make at its estimated input tokens plus the configured completion cap; the deduction and the job row are one `BEGIN IMMEDIATE` transaction.
- [x] A4 Reaching a terminal state settles the hold against the ledger's recorded cost for that job and returns the difference to the lots it was taken from; a job that fails after spending tokens settles at what it spent, and a job whose row failed to insert releases the whole hold on a context that outlives the caller's cancellation.
- [x] A5 **No sequence of operations leaves a balance below zero**, including two concurrent starts that each read the same balance, and including a job whose actual cost exceeds its own hold.
- [x] A6 A start whose hold exceeds the balance is refused `resource_exhausted` / `INSUFFICIENT_CREDITS` carrying `required`, `balance` and `renews_at`, writes nothing, and creates no job row.
- [x] A7 `min_plan` no longer exists in `providers.yaml`, the registry, boot validation, or any RPC; a `free` account may select and save any model, and is refused only when its balance cannot cover the hold. `MODEL_LOCKED`, `required_plan` and `ListModels.locked` are gone, and no saved selection is invalidated by a tier change.
- [x] A8 The daily start count, the daily budget and the monthly budget are gone: no code path reads them, and an account may spend its whole monthly grant within one day.
- [x] A9 `master` is held, recorded and settled like every other tier but is never refused for balance, and its usage remains readable through the same surfaces.
- [x] A10 `GetMyPlan` returns the balance, the individual lots with their expiries, and the renewal instant; the plan badge renders them, and the frontend hardcodes no credit figure.
- [x] A11 `ListModels` reports, per model and for the calling account, the credits a job with that model would require and whether the balance covers it; the picker disables what is unaffordable and states the required credits.
- [x] A12 The model picker shows an "about N posts" estimate per selectable pair, derived from the account's own recent `usage_events` history where it exists and a product default otherwise, and labelled as an estimate.
- [x] A13 A zero balance blocks every LLM-consuming action and routes to a plan comparison screen listing all four tiers with their credit grants and intended prices; writing, editing, exporting and reading posts remain fully usable at a zero balance.
- [x] A14 A post cannot exceed 30 photos: the server refuses the upload that would cross it, and the browser's selection gate reports the excess as skipped before any file is converted or sent.
- [x] A15 `adduser` opens the first monthly lot for the tier and, for `free`, an additional 50-credit signup bonus lot, in the account-creating transaction; `grantcredits <id> <amount> [--expires]` opens a bonus lot on an existing account; `setplan` re-sizes the next monthly lot without editing the current one.
- [x] A16 The migration creates `credit_lots`, admits `pro` into the plan `CHECK`, and opens an initial monthly lot for every pre-existing account; it runs embedded at boot and a failure kills the process ([I7]).
- [x] A17 No regression: the master-only procedure set and its refusals, the last-master guard, the agent bearer path, `usage_events` recording at the llm boundary with its existing cost resolution, and the job-queue contract ([I5]) all behave exactly as before.

### Schema

- [x] T001 (migrate) `0019_credit_lots.sql`: create `credit_lots(id TEXT PK, user_id TEXT NOT NULL REFERENCES users,
      kind TEXT NOT NULL CHECK(kind IN ('monthly','bonus')), granted INTEGER NOT NULL, remaining INTEGER NOT NULL
      CHECK(remaining >= 0 AND remaining <= granted), expires_at TEXT, created_at TEXT NOT NULL)` with an index on
      `(user_id, expires_at)` — the consumption order. `remaining >= 0` is the database's own half of A5: the
      no-negative-balance guarantee must not rest on Go alone.
- [x] T002 (migrate) Same migration: admit `pro` into the `users.plan` CHECK (SQLite requires the 12-step table
      rebuild), add `renews_at TEXT` to `users`, and open one `monthly` lot per existing account sized by its tier
      (every pre-existing account is `master`, whose lot is unlimited — see T005 for how that is represented).
- [x] T003 (migrate) Same migration: add `hold_credits INTEGER NOT NULL DEFAULT 0`, `settled_credits INTEGER`, and
      `settled_at TEXT` to `usage_admissions`. The admission row already exists once per job start, so the hold
      belongs on it rather than in a second table; `settled_at IS NULL` is the open-hold predicate a boot sweep and
      the settle path both read.

### Domain — `backend/internal/plan`

- [x] T004 Add `Pro` to the ladder between `Basic` and `Max`, with its `rank`, and extend `Parse`. The
      fail-closed posture on an unknown value is unchanged.
- [x] T005 Replace the `Limits` table with a **grants** table: `MonthlyCredits(Plan) int` — 50 / 200 / 500 / 1000,
      and `master` unlimited. Keep the existing "zero means unlimited, only master carries it" convention so the
      wire contract's meaning does not shift under the client. Delete `Limits`, `LimitsFor` and `Unlimited`.
- [x] T006 Add the charge formula as code-owned constants and one function:
      `const ChargeBase = 2; const ChargeMultiplier = 3` and
      `Charge(costMicrousd int64) int` = `ChargeBase + ceil(costMicrousd × Multiplier / 10_000)`. Integer math only
      — the ledger stores micro-USD and a credit is 10 000 of them, so no float enters the money path. Add the free
      signup bonus (50) beside them. **These are not config** (§ Grounding).
- [x] T007 Delete the model-floor API: `Allows` as used for floors, `EnsureAllowed`, and the `MODEL_LOCKED` error
      constructor in `errors.go`. Keep whatever `master` comparison the auth interceptor needs — verify by grep
      before deleting, since `Allows` serves both callers today.
- [x] T008 Add `ErrInsufficientCredits` carrying `required`, `balance`, `renews_at`, rendered as
      `resource_exhausted` / `INSUFFICIENT_CREDITS`. Delete the `DAILY_COUNT` / `DAILY_COST` / `MONTHLY_COST`
      reasons and their detail shapes.
- [x] T009 Keep the `Asia/Seoul` fixed zone and `MonthWindow`; delete `DayWindow` and its tests. Renewal is
      per-account (T012), so `MonthWindow` now serves the renewal instant's computation rather than a shared
      calendar window.

### Ledger and admission — `backend/internal/usage`

- [x] T010 `store/queries/*.sql` + (gen) `sqlc`: balance over unexpired lots, lots in consumption order
      (`expires_at ASC NULLS LAST, created_at ASC`), decrement a named lot, credit back a named lot, close and open
      a monthly lot, read an admission's hold, mark it settled. Every write runs on the writer handle inside the
      caller's transaction, following the existing `InWriteTx` contract.
- [x] T011 `usage.Store` port + `store.Store`: the lot operations above, in the anti-corruption style the package
      already uses (sqlc rows stop at the boundary).
- [x] T012 Renewal-on-access: a helper that, given a user and `now`, closes an elapsed monthly lot and opens the
      tier's next one inside the current write transaction, and advances `users.renews_at`. Called at the top of
      the hold path and by `GetMyPlan`, so a balance is never read stale. No ticker, no sweeper (A2).
- [x] T013 Replace `Admit` with `Hold(ctx, Start) (holdCredits int, err error)`: renew (T012), compute the worst
      case (T014), charge it against the lots in order, write the admission row with `hold_credits`. Still one
      `BEGIN IMMEDIATE` transaction — that is what makes A5 hold under concurrency. `master` skips the balance
      check but still writes the admission and its hold, so operator spend stays readable (A9).
- [x] T014 Worst-case estimator: for a `Start`, enumerate the calls the work will make and price each at
      (estimated input tokens × input price) + (`LLMMaxTokensDefault` × output price), then run the total through
      `plan.Charge`. The call count is per job kind — `generate` is `ceil(photos/4) + 1` (observe batches four,
      then write), `model_experiment` is that × the candidate width, `validate_voice_profile` is per-item × its
      stages. Keep the shape table in one place beside the estimator; an unknown kind must estimate high, not low.
- [x] T015 `Settle(ctx, jobID)`: sum `usage_events.cost_microusd` for the job, run it through `plan.Charge`, credit
      the difference back to the lots the hold came from, stamp `settled_credits` / `settled_at`. Idempotent on
      `settled_at IS NULL` so a retried terminal transition cannot refund twice. Extend `Release` to also return an
      unsettled hold when the job row failed to insert, on the context that outlives cancellation (A4).
- [x] T016 Boot sweep: settle any admission left with `settled_at IS NULL` whose job is already terminal — the
      counterpart of the existing job-queue boot sweep, so a crash between "job finished" and "hold settled" cannot
      strand credits.
- [x] T017 Delete `checkAxes` and every count/budget query behind it. `usage_events` recording, `RecordCall`, the
      metered-registry seam and cost resolution are untouched (A17).
- [x] T018 `Summary` returns balance, the lots with their expiries, and the renewal instant, replacing the
      three-axis shape.
