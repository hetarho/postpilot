## Acceptance Criteria (from changes/22.expose-the-generated-tags-as-a-copy-fiel)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 On a post whose content has tags, the export panel shows a labelled read-only tag field with a copy button on **each** of the four format tabs (naver, tistory, site, markdown).
- [x] A2 Copying it puts `#tag1 #tag2 #tag3` on the clipboard for tags `[tag1, tag2, tag3]` — each tag prefixed with a single `#`, separated by single spaces, with no trailing separator.

- [x] A4 A post whose content has an empty tag list renders no tag field and no tag label — not an empty field.

- [x] A6 A confirmation shown for one tag list does not survive a content change to a different tag list.
- [x] A7 Regression: all four outputs are byte-identical to their current values for the same content — in particular the Naver body still omits tags, the Tistory body still omits tags, the site HTML still renders its tags list, and the Markdown front matter still carries `tags`.

## Implementation Checklist

<!-- How to build it, top to bottom. [P] = parallel (different files, no dependency). Flag (gen)/(migrate).
     Config values are never magic literals — FE via shared/config, BE via internal/platform/config. -->

- [x] T001 `widgets/export-panel/lib/hashtags.ts` (new, `widgets/export-panel/lib`): `toHashtags(tags)`
  derives the ready-to-paste string from `PostContent.tags` — trim each tag, drop the ones that are
  empty after trimming, strip any leading `#` runs the model emitted and re-prefix exactly one,
  join with a single space, no trailing separator. Returns `''` for an empty/blank-only list, which
  is what the render condition in T003 keys off. Unit test the shape, the already-`#`-prefixed case,
  and the empty case.
- [x] T002 `ExportPanel.tsx` — widen the copy plumbing to a third text target: add `'tags'` to
  `CopyTarget`, to `copy()`'s `target` union and to `manualCopy.target`, and add a `tagsRef`
  (`HTMLInputElement`). Replace `isCurrent`'s two-way `target === 'output' ? outputRef… : titleRef…`
  ternary with a per-target ref lookup — with three targets the ternary would compare a tags copy
  against the TITLE field's element and report a stale copy as current. Nothing else about the
  generation counter, the `copyQueue`, the `COPY_FEEDBACK_MS` dwell or `invalidateCopyFeedback`
  changes: a tab switch keeps clearing tag feedback the same way it clears the title's.
- [x] T003 The field itself, mirroring the Naver title field exactly (`FieldLabel` + read-only
  `TextField` `min-w-0 flex-1` + `shrink-0` secondary `Button` + a `min-h-5` `role="status"` line):
  rendered OUTSIDE the `format === 'naver'` branch so it is present on all four tabs, mounted only
  when `toHashtags(content.tags)` is non-empty (A4 — no empty control), and placed after the Naver
  title block and before the copy action so the field order reads title → tags → output. The copy
  is `void copy('tags', hashtags, tagsRef.current)`: the field is always mounted when it renders,
  so `copyText` gets a real fallback element and selects it itself — no reveal effect, unlike the
  Naver body.
- [x] T004 `tagsStatus`, derived beside `titleStatus`/`outputStatus` and mounted whether or not it
  has text (a live region has to exist before its text changes): the confirmation when
  `copied.target === 'tags' && copied.value === hashtags`, the `export.manualCopy` hint when
  `manualCopy.target === 'tags' && manualCopy.value === hashtags && manualCopy.source === content`.
  Both comparisons are what makes A6 true by derivation — a confirmation for one tag list cannot
  survive a content change to a different one, and the content-identity check stops a dismissed
  fallback resurrecting when an edit is undone.
- [x] T005 [P] i18n (`app/providers/i18n/resources/ko/posts.ts` · `en/posts.ts`): `export.tags`
  (label), `export.copyTags` (button), `export.tagsCopied` (confirmation), in the same voice as
  `naverTitle`/`copyTitle`/`titleCopied`. `export.manualCopy` is reused as-is — the fallback hint is
  already target-agnostic.
- [x] T006 Tests (`ExportPanel.test.tsx`): the field renders on each of the four tabs and the copied
  string's exact shape (A1, A2); an already-`#`-prefixed tag copies with one `#` (A3); an empty tag
  list renders neither field nor label (A4); the confirmation on success and the manual-selection
  fallback on a refused clipboard write, beside the tag field (A5); a content change to a different
  tag list drops a shown confirmation (A6); the existing converter output assertions and snapshots
  still pass untouched, and the Naver title field + per-photo copy assertions still pass (A7, A8).
- [x] T007 Config: none added — `COPY_FEEDBACK_MS` in `frontend/src/shared/config` stays the owner of
  the feedback dwell and no literal timing/format value lands inline.

## Review

- [x] `/code-review` (high) · `codex exec -m gpt-5.5` (background, read-only) — merged and deduped.
  - **Applied:** `fieldOf` snapshotted `*.current` at the moment `copy()` started instead of
    reading through the ref inside `isCurrent()`. The tags field is CONDITIONALLY mounted, so a
    clipboard result settling after the tags were cleared would have compared against a detached
    input and reported a stale copy as current. It is a record of getters now. Both reviewers
    reached this line; `/code-review` judged it unreachable in practice, codex produced the
    unmount scenario, and the scenario is now a test.
  - **Rejected:** "a tag confirmation can reappear if the content changes and is undone within
    `COPY_FEEDBACK_MS`, because `copied` carries no `source` identity" (codex). This is correct
    about the mechanism and wrong about the defect. For a SUCCESS the value comparison is the
    right predicate: after the undo the clipboard genuinely does hold the tag list now on screen,
    so the confirmation is true, not stale. Identity is needed only for the manual-selection
    FALLBACK, because a failure is an event rather than a state and a dismissed one must not
    resurrect — which is exactly where the change already carries `source: content`. The title
    and output copies have behaved this way since plan 08, and this change is specified to mirror
    them.
- [x] Design pass (design-language §10) — the field mirrors the Naver title's exactly:
      `FieldLabel` + read-only `TextField` `min-w-0 flex-1` + `shrink-0` secondary `Button` +
      a `min-h-5` always-mounted `role="status"` line. No new primitive, no card, no border, one
      `cta` per view (the output copy, unchanged), registered tokens only. §7's no-empty-control
      rule is why an empty tag list renders nothing at all rather than an empty field.
- [x] Comment pass over the diff — the "why" only.
