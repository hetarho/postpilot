## Acceptance Criteria (from plan/01.accounts-and-login)

<!-- Plan 01 criteria owned by this job (plan AC numbers in parentheses); the rest are job 01's. -->

- [x] A1 (plan AC4, browser half) In browser devtools, `document.cookie` never contains `pp_session`; the session cookie is sent on every RPC as a `Cookie` header (network tab) and no `Authorization` header is used.
- [x] A2 (plan AC9) An unauthenticated visit to any route redirects to `/login`; after login the originally requested route loads.
- [x] A3 (derived) The Connect transport is created with `credentials: 'include'`; without it the same call is rejected with 401 (asserted by a unit test on the transport options).

- [x] A5 (derived) Logout calls `AuthService.Logout`, clears the session cache, and lands on `/login`; the back button does not show authenticated content.
- [x] A6 (derived) The login form shows one generic message for any failure ("아이디 또는 비밀번호가 맞지 않아요") and never reveals whether the id exists.
- [x] A7 (derived) `app/` root holds only `App.tsx` and `index.ts`; the router lives in `app/routes/`, the query client in `app/providers/` (ARCHITECTURE §3.2).

## Deviations from the checklist (as built)

Each is reflected in [plan/01](../../plan/01.accounts-and-login.md) and [policy/auth.md](../../policy/auth.md).

| Task | Wording | As built | Why |
|---|---|---|---|
| T002 | `createConnectTransport({ baseUrl, credentials: 'include' })` | `createConnectTransport({ baseUrl, fetch: credentialedFetch })` | connect-web v2's `ConnectTransportOptions` has no `credentials` — the wording does not compile. The opt-in rides on a fetch wrapper, which is also the only testable surface (a `Transport` hides its options) |
| T002 | interceptor exempts `AuthService.Login` | exempts `Login` only, by service+method name | as written. An earlier attempt exempted all of AuthService and was reverted in review: a background `GetMe` refetch that 401s must still move the app |
| T003 | `useSession`/`useLogin`/`useLogout` | plus `loadSession` returning `{status:'active'\|'signed-out'}` | the router guard runs outside React and must read the same cache entry the hooks write; and "signed out" has to be an answer, not an exception, so an outage is not mistaken for a logout |
| T005 | `queryClient.ensureQueryData(getMe)` | `queryClient.query({ ...options, staleTime })` | `ensureQueryData`/`fetchQuery`/`prefetchQuery` are all deprecated in the installed query-core |
| T007 | header in `app/routes/RootLayout.tsx`, rendered when a session exists | header in `app/routes/AuthenticatedLayout.tsx`, the guard's own component | makes "only with a session" structural instead of a conditional, and stops `/login` from issuing a `GetMe` it does not need. `RootLayout` stays bare, which is what the task asks for |
| — | (not in the checklist) | `shared/lib/redirect.ts`, `SESSION_STALE_MS` in `shared/config` | the `redirect` param needs validation the router does not do, and the guard's staleness window is a setting, not a literal |

## Review

Two reviews, merged: **7 distinct findings, all applied, 0 rejected.** Each has a regression test.

- [x] `/code-review` (high) — 4 findings:
  1. `isInAppPath` admitted `/\evil.com`, which the URL parser folds into the protocol-relative `//evil.com` — a
     real open redirect the doc comment claimed to prevent. Replaced the pattern with an origin-resolution check.
  2. `/login` was unreachable while the API was down: the reverse guard let a non-401 escape `beforeLoad`.
  3. The guard admitted a 200 `GetMe` carrying no user — every protected route open to a malformed response.
  4. The cached-answer shortcut reported *any* cached error as "signed out", including an outage.
- [x] Codex (`gpt-5.5`, xhigh) — 7 findings: 4 duplicated the above; **3 new, all applied**:
  5. `staleTime: 'static'` made a resolved session permanently valid, so a session revoked in another tab kept
     rendering signed-in screens until a full reload. Now a bounded `SESSION_STALE_MS`.
  6. A failed `Logout` cleared local state while the cookie stayed valid — `/login` then bounced the user back in
     with no way to leave. Now the cache clears and the app navigates only on success, and the failure is shown.
  7. Two tests asserted the wrong thing: one locked in the (wrong) all-AuthService exemption, and the credentials
     test would still pass if `fetch: credentialedFetch` were deleted from the transport. Both rewritten.
- [x] Comment pass — the comments that argued for the reverted behaviors (all-AuthService exemption, clear-on-failure
      logout) were rewritten to argue for what the code now does.
