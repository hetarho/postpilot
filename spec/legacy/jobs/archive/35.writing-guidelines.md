## Acceptance Criteria (from plan/16.writing-guidelines)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 An authenticated user can create, list, update, and delete guidelines. `text` is trimmed, non-empty, bounded, and unique within the account (an exact duplicate after trim is `AlreadyExists` with a Korean message). No RPC accepts a user id; a foreign guideline id is indistinguishable from an unknown one (`NotFound`). Creating beyond `GuidelineMaxPerAccount` is refused with a Korean message naming the cap.
- [x] A2 Scope is validated: `global` with purpose ids, or `purposes` with zero ids, is `InvalidArgument`; an unknown or foreign purpose id is `NotFound` and nothing is applied; duplicate ids in one request collapse to one link. The list projects each scoped guideline's purposes as `{id, name}` through the purpose directory, never a SQL join, and returns guidelines in injection order.
- [x] A3 `UpdateGuideline` changes only what the request carries: a text-only update leaves the scope intact (store test against a concurrent scope edit), and a scope patch replaces the whole scope atomically in one transaction.
- [x] A4 Generating a post whose account has applicable guidelines appends exactly one `[작문 지침]` section — after the `[글의 용도]` section when the post has a purpose, otherwise immediately after `[종결어미 제약]`, and always before `[이번 글]` — containing the texts verbatim as list lines, global group first then scoped group, each ordered by creation time, followed by the fixed precedence sentence (prompt snapshot).
- [x] A5 Scope resolution is exact: a post with purpose P receives the global guidelines plus P-linked ones; a post with no purpose receives the global ones only; guidelines linked only to other purposes never appear; a `purposes`-scoped guideline with zero remaining links appears in no prompt.
- [x] A6 With no applicable guidelines the prompt contains no `[작문 지침]` section and is byte-identical to the post-grounding baseline (golden files). The voice profile prefix and the purpose section are byte-identical with and without guidelines (prefix-comparison tests), so plan 11's acceptance criteria 4–5 keep holding.
- [x] A7 Every write and revise prompt — with or without user guidelines, with or without a purpose — contains the fixed built-in grounding constraint forbidding facts absent from the memo and photo observations. It lives in the fixed prompt text (code, not config, not a database row); the observe prompt is unchanged; golden files are regenerated exactly once for this addition.
- [x] A8 Freezing: the applicable ordered texts are resolved once at enqueue and written into the job payload beside `target_length` and the purpose brief; editing, rescoping, or deleting guidelines after `StartGeneration` / `StartRevision` returns does not change the prompt the worker builds, including after a restart-resume or an explicit retry (test edits rows between enqueue and drain). Payloads without the member decode as no guidelines.
- [x] A9 An A/B write experiment freezes the same texts into the shared snapshot: both candidates receive byte-identical system prompts including them, and changing the applicable guidelines changes the input hash.
- [x] A10 Revision injects the same section at the same relative position in the revise prompt; a revision of a post without applicable guidelines is unchanged from the baseline (snapshots).
- [x] A11 After a completed revision, `지침으로 저장` opens a dialog seeded with the revision instruction, editable before save, offering 전역 (default) and the post's current purpose as scope when one is assigned. Saving creates the guideline through the standard RPC; `AlreadyExists` is surfaced as already-saved information, not a failure; no code path lets a model or job write a guideline.
- [x] A12 Deleting a purpose removes its guideline links in the same delete (cascade), leaves every guideline row intact, keeps `DeletePurpose`'s detach behavior and response unchanged, and leaves frozen payloads/snapshots readable. An orphaned scoped guideline lists as 적용 대상 없음 and can be rescoped or deleted.
- [x] A13 The migration adds `guidelines` and `guideline_purposes` with the composite account FKs, seeds nothing, and with zero guidelines every existing prompt/job/experiment output is unchanged except the deliberate grounding-line baseline change of criterion 7.
- [x] A14 `/guidelines` supports create (live character count, scope control), read-first text edit, whole-scope edit, and delete with the stated confirmation, using design-system primitives and semantic tokens; the empty state shows the example as copy only; the nav gains 지침 after 용도 and the route is lazily split like its siblings.
- [x] A15 Guideline list/create/edit/delete, the capture save, page mount, and polling make no provider call and enqueue no job.
- [x] A16 Domain/store/RPC/prompt/payload tests cover validation limits, the cap, dedup, scope resolution, presence semantics, foreign-id rejection, freeze-after-edit, cascade-on-purpose-delete, and snapshot equality; proto/sql generation checks, backend vet/build/tests, frontend tests/lint/FSD/style/build, and spec lint pass without weakening existing assertions.

## Review

- [x] `/code-review` applied (rejections noted with reason) · for non-trivial logic, `/codex:review --background`

Findings applied while building:

- **`Service.project` mutated a slice copy**, so `Create`/`Update` returned a guideline with no purpose-name
  projection while `List` was correct. Caught by the service test; fixed with `projectOne`.
- **sqlc mis-slices a query file containing any multi-byte character** (it locates statements by byte offset and
  counts in runes), which rotated every generated query text — `CountGuidelines` shipped as `?);\n\nSELECT count(*)
  FROM guidelines WHERE user_id`. `guidelines.sql` is now ASCII-only and says why at the top. Worth knowing before the
  next context adds a query file with an em dash in a comment.
- **`isUniqueViolation` was too broad**: an id collision would have been reported to the user as "that text already
  exists". Narrowed to `isDuplicateText`, which requires the message to name `guidelines.text`.
- **`shared/ui/Dialog` stole focus out of any field inside it.** Its setup effect had `onClose` in the deps, and every
  caller passes an inline arrow, so the effect re-ran on each render and called `panel.focus()` — a text field inside
  a dialog lost focus after one keystroke. No dialog had held a field before, so nothing had noticed. Fixed in the
  primitive (handler read through a ref, deps `[open]`) rather than worked around in this slice.
- **`PURPOSE_INSTRUCTIONS_REQUIRED` read "Enter writing guidelines." in English**, which now names a different
  aggregate. Reworded to "Enter writing instructions."

Found by `/code-review` on the finished diff and fixed:

- **The agent module stopped building.** `agent/buf.gen.yaml` lists an explicit `M<file>=<import path>` mapping per
  proto file in both plugin blocks, and the new `guideline.proto` was missing from both, so the agent's generated
  connect file imported the BACKEND's package. Mapping added; `agent` builds, vets and tests clean.
- **The revise prompt's grounding line contradicted its own preservation rule.** The plan's single wording tells the
  model to omit what it cannot confirm, but the revise pass receives neither the memo nor the observations — it could
  strip real facts out of untouched blocks. Split into a shared core plus one scope clause per pass (write: omit the
  unconfirmed; revise: apply only to sentences the request touches). Goldens regenerated for the same single addition;
  each prompt still gains exactly one line.
- **`Dialog` set a ref during render**, which `react-hooks/refs` rejects. Replaced with two effects: focus and scroll
  setup keyed `[open]` alone (the actual fix), and the key listener in its own effect that may keep `onClose` in its
  deps because re-registering a listener steals no focus.
- **`지침으로 저장` appeared after a completed `generate` job**, offering to save an instruction that never ran. Now
  requires `activeJob.kind === 'revise'`, with a test for the generate case.
- **Two new files were unformatted**, failing `format:check`. Formatted.

Nothing rejected.
